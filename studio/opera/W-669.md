Gaps 60, 80 (s27: W-661 and W-488 cleanup held): the Claude sandbox bind-mounts every .git/worktrees/<id>/{config.worktree,commondir} read-only (267 mounts), so a sandboxed `git worktree remove` fails EBUSY and the Patron must rm by hand; the Patron 11-16: a blocker for the console end state too. Cleanup treats a held admin dir as non-blocking (W-227's intent: delete both branches, name the dir) and an unsandboxed host job the Patron installs (e.g. the launch service before a start) runs `git worktree prune`; next never waits on a Patron rm.
