## Decree

The Patron ruled on W-065's four open items, 2026-09-24, each taking the
architect's recommended default:

1. **Side panel**: Inbox · Board · Seats · Officina, in that order. (No
   canvas artboard draws the panel's contents; the pre-decree tab lists do
   not bind it.)
2. **The munera enumeration**: nine munera over six tiers, derived
   mechanically from D-020 and D-014 as written — doc/table work,
   mechanical audits, pre-review verification, research memos, brief
   red-team, escalation analysis, build, spec, review — over luna, terra,
   sol, astra, sonnet-build, opus-review. The exact manifest spelling is
   the W-065 brief's interface section; this decision fixes the SET, the
   brief fixes the SHAPE.
3. **Write authority**: both the Patron and the producer may write the
   munus→tier mapping; every write records the acting role. DIRECTION.md's
   decree-write rule and D-020's producer-revisable clause are BOTH
   honoured: identity is recorded, not restricted.
4. **Wire naming**: `munus` / `munera` and `tiers`, per the W-006 Latin
   contract.

## What this changes

**Amended same day (Patron, PATRON-5 — the browser write path):** the
server's write auth accepts an `Origin` equal to its own origin and
refuses every other; the write token `serve` prints is pasted once per
session and held in `sessionStorage`. Injecting the token into the served
page was considered and rejected (any local process that can `GET /`
would obtain it — the property W-016 bought). W-016's "loopback alone
never authorizes" survives intact.

`studio/bisellium.yml` gains two optional keys: `tiers` (tier id → current
holder model) and `munera` (munus id → tier id). They are configuration
read live, not evidence: no event is emitted on a munera write, and the
officina check gains `munus.tier` (a munus naming an undeclared tier is a
finding). The honest claim of any UI over these records is "recorded,
attributed and rendered" — nothing dispatches on them until the opus that
wires dispatch says so, and every screen must say that plainly.
