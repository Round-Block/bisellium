Written by the producer from the Patron's answers in the orchestrator session of 2026-10-20 ("I want to
maintain 2 engineering lanes and 1 UI lane. Is that possible?", then "Yes record the 3 lane setup"), on the producer's
assessment given in that session: the three-lane run of 2026-10-20 cost 41 lane-minutes of overlap in all
(`~/.bisellium-evidence/overrun-study-1020/report.md`), and UI files (`apps/web/`) rarely share a file with engineering
opera.

## Decree

A. **Three lanes: two engineering, one UI.** This amends D-088 D ("two lanes until the conflict check lands"). Until
   W-337 lands, the orchestrator still runs `git merge-tree --write-tree` by hand before each review (D-088 A, D).
B. **The UI lane's order.** First W-344 (UI/UX research, no build; its report goes to the Patron) and W-338 (a
   `kind: ui` opus takes the Codex spec review, without which no UI opus can reach branch); then the UI opera in the
   order the Patron rules on W-344's report. While W-338 is unbuilt, the lane carries only work that needs no UI spec
   review.
C. **Heavy jobs.** A `kind: ui` opus's post-merge `verify` (about 24 min) runs only while no engineering lane runs its
   full suite (D-075 F); the orchestrator queues it.
D. **The merge queue stays one build at a time** unless the Patron raises `max_entries_to_build` (a GitHub setting,
   the Patron's); three lanes may wait on each other there.
