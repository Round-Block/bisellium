## Ruling

**Ownership goes by time, not by field.** Each `opera/<id>.md` has exactly
one ref that may write it at any moment:

- **While `opus/<id>` exists, only a checkout on `opus/<id>` writes the
  record.** That covers gates, verdicts, handoffs, `done` and a halt of
  in-flight work. The trunk's copy stays frozen at the fork point and is
  replaced whole when the branch merges.
- **Before the branch is cut, and after it is deleted, the trunk side
  writes the record.** That means any ref that is not an opus branch,
  landing through a PR. Greenlight lives here. A trunk-side write that has
  not yet landed when the branch is cut still counts as a write during
  flight, so cut the branch after it lands.
- **An opus branch carries only its own record.** A checkout on `opus/<Y>`
  never writes `opera/<X>.md`.

The only textual conflict git can then produce on a record is between two
writers of that record. If each record has one writer, that conflict cannot
happen.

A review verdict is evidence about the branch's tree, so it goes on the
branch. The censor stays read-only. The orchestrator writes the verdict log
and runs `bisellium review` in the branch's worktree, then commits it there.
Certificates were already branch-side under W-026, and `merge` already reads
the record from the branch ref. This ruling turns that contract into a rule
that applies to every writer.

## Why not the other candidates

- **Per-field provenance.** Git merges lines, not YAML fields. `bisellium new`
  creates each record with a flow-style `probationes: {}`, and
  `editOpusFrontMatter` keeps that style, so the whole gate map sits on one line. A trunk review
  and a branch verify therefore edit the same line even though they touch
  disjoint fields. W-026 already rejected the split for `merge`.
- **Trunk-authoritative.** Under ruleset `master_protection`, every gate
  write would need its own PR through two required checks. Trunk would also
  hold certificates for a tree it does not contain, and W-026's branch-ref
  reads would have to be reversed.
- **Bookkeeping outside the work tree.** `events.jsonl` is gitignored, so
  it is per-checkout telemetry and not shared truth. Making it shared would
  mean a new storage layer and a projection engine, and every reader
  (`check`, `serve`, `context`) would have to move. That only pays off with
  concurrent writers, which the studio does not have. It stays as the
  `kill_when` successor.

## What this kills

- **The reconcile recipe:** take master's copy, then re-run
  greenlight/ready/verify/handoff on the branch. No CLI write can create
  the conflict it resolves. A conflict can still come from an out-of-band
  trunk write, such as a hand edit or a sweep script. In that case the
  resolution is fixed: during `git rebase` the branch's copy wins
  (`--theirs`), and anything legitimate the trunk wrote is re-run on the
  branch through its owning command.
- **D-016's pending clause.** Provenance is now settled, and the recipe
  D-016 would have automated no longer exists. So no `reconcile` command
  gets built, ever. If a record conflict survives W-033, that means a writer
  escaped the guard. The fix is to close that hole, not to wrap it in a
  command. The rest of D-016 stands.
- **W-034 defect 2**, as a whole. `done` run from the wrong ref is refused
  by the same guard that refuses every other writer. W-034 keeps defect 1
  only.

## Enforcement

The enforcement is a CLI refusal at the one point every record writer goes
through (W-033, `briefs/W-033.md`). `greenlight`, `ready`, `done`, `review`,
`halt`, `handoff` and `verify` refuse before they write anything when the
checkout holding `--studio` is not the record's owner. `close` and
`ci --opus` inherit the refusal through `done` and `verify`. The guard only
applies when the record is tracked in the enclosing repo. It never fires in
an officina that does not cut opus branches, which keeps it neutral to D-015
(integration strategy stays a setting).

**No check rule.** The violation is about *which ref* a write landed on,
and a tree snapshot cannot see that. The one residual, an out-of-band trunk
write, surfaces as a rebase conflict, and its resolution is now fixed. A
hook against hand edits of `opera/` would be the next rung if that residual
ever recurs. It is out of scope here.

## Consequence worth naming

In this officina the required `officina` job blocks an active opus that has
no reds or no handoff. So `ready` belongs on the branch (`branch` first,
then `ready`), and the trunk only ever shows `backlog`, `greenlit`, `halted`
or `done`. As a result, `wip.cap` and the console read in-flight work off
the trunk as `greenlit`. Teaching them to overlay live opus branches is
future work (UI is the Patron's call). This decision does not do it.
