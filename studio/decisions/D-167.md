Hand-written from the Patron's word on 2026-11-03; there is still no `decide` verb (W-157). The clerk wrote this.

W-413's build review r1 passed. The Patron then looked at the screenshots in `ci/shots/W-413/` (board-1280 and board-390) and found that the captures do not show the filter working, and that the per-column median time is not useful to them.

## Ruling

The Patron's words: "The screenshots don't show the filter working? I don't think the per column median time is useful. It would be more useful if it was per-task elapsed time, and time to completion for each task."

Asked whether "time to completion" means the actual time on done cards or an estimate on open cards, the Patron answered: "Both."

1. Drop the per-column median time.
2. Each card shows its elapsed time.
3. Done cards show the actual time to completion.
4. Open cards show an estimated time to completion, labelled as an estimate.
5. The captures show a filter applied.

This is a revise ruling, not an approval of the screens. The design lead revises the spec (revision 10), and the screens come back to the Patron for a new look.

2026-11-03, revision 14: the Patron looked at revision 13's captures and said: "I just need total items and the number of blocked items in 2 separate rows."

1. Each lifecycle column header's count block is exactly two plain rows: the column's total (for example `5 tasks`, or `Showing 2 of 5 tasks` with a filter on), then the column's blocked count (for example `1 blocked`, or `None blocked` at zero).
2. The work-in-progress limit is removed from the Board. The limit sentence, the over/under-limit wording and any combined Building+Verifying total are gone from the headers and the Board-level key. The limit is not shown anywhere on the Board in W-413.

Effect: the column headers show only those two rows.

2026-11-03, revision 15: the Patron looked at the W-413 captures and said: "for w413, i want a different color for the blocked item line, check the other screens for the latest color scheme".

1. The blocked item line on the Board (the blocked card's marker line, and the header's blocked row if it uses the same colour) takes a different colour from the one it has now.
2. The new colour is a named token from the latest colour scheme that the other screens on master use, never a new hex value. It is the existing token those screens use for a blocked or waiting state.
3. Contrast is checked in light and dark themes (WCAG AA: 3:1 for a line, 4.5:1 for text).

Effect: the blocked item line takes the existing token the latest screens use for a blocked or waiting state, not a new hex value.

2026-11-03, revision 16: the Patron clarified revision 15: "I'm talking about the blocked line in the column header."

Effect: row 2 of each column header (the blocked count) takes a colour different from the total row, from the same blocking token family, at WCAG AA 4.5:1 for text in both themes. The exact token and the zero-count colour are the design lead's to state in the brief.
