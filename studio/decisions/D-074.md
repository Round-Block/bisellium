Written by the producer at the Patron's instruction (2026-10-16: "It doesn't make sense for it to require a pr to take
effect? It should be dynamically done, like a backend db or just a config update"; then "We don't have to do the

`gpt-6-astra`, collated by Fable (`~/.bisellium-evidence/seats-live-1016/{fable-report,astra-report,collated}.md`).
The five Patron choices below were offered with recommended answers and taken as defaults, veto-able.

## Why

W-301 lands every console write as a records PR (D-071), and W-302 put `studio/bisellium.yml` under the Patron's
code-owner review, so a Seats click would wait for a second approval on GitHub. Today's `/api/delegate` rewrites the
tracked `studio/bisellium.yml` in whichever checkout `serve` runs on: in the agent clone the dirty file blocks the spec
and merge performs; in the Patron's folder agents never see the change until it is pulled. A real multi-device app keeps
settings in a store its server owns; git keeps code and certified evidence.

## Decree

A. **The line.** A setting only selects how future work runs, and every run writes the value it used into its own
   record: it is live, with no PR (seats: model, harness, tier, munus). Anything that authorizes, commits, spends or
   governs is a record, landed in git by a reviewed PR (greenlight, decline, halt, budget, petitio, answer, handoff,
   queue, lex, decisions). Pause and resume stay a local marker.
B. **One store, one reader, one writer.** `readManifest` is the only reader and folds the live overrides over
   `studio/bisellium.yml`'s defaults; `bisellium delegate` and the console's `/api/delegate` are the only writers. The
   store is an append-only `~/.bisellium/<studio>/seats.jsonl` (last line wins; each line names who, when, old and new),
   outside the agent clone, so the agent sandbox cannot write it. Moving to a database later replaces the store module
   and imports the file; readers, writers, the UI and agents do not change.
C. **`studio/bisellium.yml`** keeps the roster, defaults and policy keys; W-302's code-owner line stays.
D. **W-304** builds A-C, first in the console group, ahead of W-280. **W-301** narrows to record writes. This supersedes
   D-071's line that every console write lands as a records PR, for live settings only. W-248 keeps `delegate`.
E. **Defaults taken (veto-able):** a Seats click may not move the spec or build reviewer off `gpt-5.6-sol` (the pin stays
   in code until a later ruling); the store lives under `~/.bisellium/`; one machine now, remote agents later (W-135,
   W-284); `serve` runs from the installed `~/projects/bisellium-guard` on the agent clone's studio; `delegate` survives
   W-248 as the store's command-line writer.
