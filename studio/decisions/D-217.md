## Ruling

1. Whole themes: role tokens named by meaning are the only colours components consume; one theme file per theme sets every role; Dracula is the default. DIRECTION.md §3's "thirteen exact values" is amended to name the theme layer. Each theme owns palette values and role bindings; typography, layout and interaction semantics remain shared. Equal current colours do not imply interchangeable roles.
2. In Dracula, the existing page/section-heading roles remain #BD93F9; other themes bind their own heading colour. Normal-size heading text requires 4.5:1 on its actual surface.
3. Dracula content links, including visited links, use Classic Cyan and persistent underlines; navigation retains its separately specified treatment. Non-link facts remain non-links.
4. Preserve Dracula's W-427 severity meanings, shapes, labels and outlines. Define text and indicator colours separately; retain the existing blocking-text adjustment. Functional colours are admitted only for measured passing contexts in either variant.
5. The focus ring moves from verdigris #3FB9A3 to Classic Purple, shown on captures before merge. Apply through a dedicated focus role after migration, with Patron-reviewed captures and keyboard-state coverage.
6. Compare existing separators against Current Line in representative dense-screen captures; the Patron chooses before any border change merges. Separate decorative separators, interactive boundaries and selected fills.
7. The second theme is Alucard (light); no theme switcher until it ships. Alucard proves complete interchangeability and readable hierarchy. Its arrival does not itself authorise a switcher; placement, persistence and studio-versus-viewer ownership require a Patron ruling.
8. Order: W-674's first child is the theme layer, Dracula only, pixel-identical, old token names kept as aliases, w025.css untouched, in UI2 right after W-488. W-467 is then revised onto the roles and signed. A second child migrates w025.css consumers by a kept codemod after W-503 lands, then drops the aliases. Both extraction and consumer migration preserve pixels; implement approved visual changes in separately scoped children. The codemod maps each usage by purpose, including TSX consumers, and aliases disappear only after all consumers migrate.
9. Guards are tests in npm test: no colour literal outside themes/*.css, no palette variable outside its theme, role-set parity per theme, contrast rows per theme (text 4.5, non-text 3), served axe per theme, a colour-vision row. Guards cover all authored colour forms and derived colours, reject undeclared or missing roles, and verify browser-computed pairs and state cues per theme.
10. Named exceptions, not full Dracula compliance: muted text (--ink-2, --ink-3, off-palette; the spec's Comment fails text at 3.03:1), the derived blocking-text shade, verdigris #3FB9A3's remaining uses (brake button, Fasti marks), pink text selection, and dark shadows stay as recorded exceptions; each is decided on captures in a later W-674 child, and the console is never described as fully Dracula-compliant while one stands.
