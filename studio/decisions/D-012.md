Stated directly by the Patron for how a cascade is shaped, so the shape is
data (`cascades/sizing.json`) a decision points at rather than a number
someone has to remember to keep the orchestrator in sync with:

- One Opus Censor per opus: every opus gets exactly one qa-lead review
  pass on Opus, never split across multiple reviewers and never skipped
  to save tokens.
- Sonnet first-hour drive: the first hour of a cascade's build phase runs
  on Sonnet builders, not Opus — Opus is for review/verify and for the
  architect's spec pass, not for the bulk of the typing.
- Mutation on one opus per cascade: the Censor's mutation-testing step
  (D-010) runs against exactly one opus per cascade, not every opus every
  time — enough to keep the suite honest without doubling every
  cascade's cost.
- Two opera per cascade: a cascade carries two opera, not one and not
  four — cascade 4b's four-opus run is the counter-example this decision
  is partly reacting to (studio/acta/2026-09-18-retro-4b.md).
- One worktree/branch per builder: no shared worktree between builders —
  the root cause cascade 4b's opera halts kept citing before this pass
  found the real, committed state underneath it.
- No mid-turn relays into a running workflow: once a cascade's Workflow
  run has started, nothing gets relayed into it mid-turn — a change
  waits for the next cascade rather than mutating a run in flight.

`cascades/sizing.json` holds the numbers this decision names (one Censor,
Sonnet-first-hour, one mutation opus, two opera, one worktree per
builder) and `cascades/cascade.js` reads them from there rather than
hardcoding them a second time.
