## Why

D-071 measured "orchestrator shell calls between greenlight and done", baseline "about 25 on W-293", target under 8. The
25 was a hand tally of ladder steps, not shell calls (Fable, 2026-10-16). Counted from the main-session transcripts
(subagents not counted):

| Opus | Bash calls in the time window | Workflow calls in the window | Its own |
|---|---|---|---|
| W-293 | 231 | 112 | about 59 |
| W-243 | 117 | 75 | about 33 |

The time windows mixed in chores and a session refresh, so the window counts overstate each opus; "its own" is what the
commands attribute to the opus by id, worktree or branch. Under 8 shell calls is unreachable while git, gh and reads
exist, and a time window cannot tell an opus's work from a chore riding it, so the measure is redefined as the
record-writing actions a command attributes to the opus.

## Decree

A. **The measure is record-writing actions per opus: `next --perform`, verdict, review, red, ready, handoff, amend, run,
   an executed kept script, a `gh pr` write or a git commit/push, attributed by the opus id or worktree in the command
   (chores carry their own id).** Reads, polls and the orchestrator's own build work are reported beside it, untargeted.
B. **Calls made by a dispatched ladder-runner count once W-292 lands; builder, architect and reviewer calls do not.**
   W-292 attributes by the hook input's agent fields, not `$BISELLIUM_SELLA`, which is session-wide.
C. **Baseline: 32 (W-243, opus-attributed, counted by count.py v2; Fable's hand tally was 33).** W-293 is about 59 by
   Fable's tally and 39 by count.py v2, which counts only commands that name the opus; both are before W-214, W-274 and
   W-292.
D. **Stop rule.** The block stops early and the queue is re-ranked if record-writing actions per opus are not under 20
   after W-214, W-274 and W-292, or at two calendar weeks, whichever comes first.
E. **Block exit target: under 12 record-writing actions per opus, the runner's included, on two consecutive opera; spec
   rounds reported beside.** D-071's other trial conditions are unchanged.
F. **Counting.** `checkpoint-<id>.py` runs count.py (v2: attribution by id, execution-only scripts, read verbs excluded)
   and writes the line; no separate call. The same PR amends lex §7 and the handoff Queue paragraph. D-071 J (W-242 held
   for the measure) releases once W-292's hook counts.
