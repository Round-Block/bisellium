## Ruling

1. The credentialed `review-request` command writes a fail-closed, atomically replaced snapshot of each waiting PR's review facts under the repository's git common directory (as drafted: `bisellium/review-requests/<number>.json`). The uncredentialed console server only reads it and projects it as the optional `reviewRequests` member of `/api/inbox`; it never calls GitHub, follows the URL or takes a token. A malformed, partial or unreadable snapshot makes the member absent; retention on close/merge belongs to the foundation.
2. A new engineering opus (the foundation) owns the snapshot write, the server reader, retention and the architecture doc edge; it ranks in E1 right after W-700. The external signer is not in it (W-666's brief puts it with the Patron); W-667 pins its name or defers that row.
3. W-667 signs and builds alongside, against the optional member (absent = the absence text). Its brief drops the D-061 §4 framing and the "cannot land before that opus" line, and both briefs pin the member's type word for word.
4. The snapshot is written in the clone the server reads (ops note; W-701's wrong-checkout class).
