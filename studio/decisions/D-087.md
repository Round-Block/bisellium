Written by the producer at the Patron's instruction (2026-10-20: "adopt all the defaults, file them"), on the compiled
Fable and Astra audit of running many lanes (`~/.bisellium-evidence/lanes-leads-1020/compiled.md`, sections 3-5; the
analyses `report-fable.md` and `report-astra.md`, fact packs gathered by Haiku). The Patron's premise: bisellium must
not cap the number of lanes a user runs, especially on cloud resources, so branch orchestration matters more. Both
analyses found that a lead agent would add a model turn per opus with no decision left to make, and that the limits
today are a done-rung certificate gap, the shared `packages/cli/src/next.ts`, and W-169's one-machine claim. The gap
that bit on 2026-10-20: W-297 merged (#594), W-313 merged five minutes later (#595), and W-297's done perform refused
certify's certificate because master's source had moved, demanding a 24-minute `verify` on the host.

## Decree

A. **No lead coordinates lanes.** Lanes are coordinated by records, holds and the merge queue: the queue (W-299), the
   in-flight set and the claim (W-169), and `certify`. A lead is trialled only when it names the existing turn it
   replaces and the trial shows net cycle minutes saved after its boot, judgment and record costs; a lead gives no
   verdict and is no pass before Codex (D-066 C). W-294's title drops "owns every fix round" (D-085 A and D-086 already
   route it) and it stays in Later. The Queue's "second-lane safe" list is retired when W-169 lands; until then each
   second-lane start is the orchestrator's call under D-066 A, stated at the checkpoint.
B. **The done rung accepts a certified chain** (new opus, Now 3, after W-299 part 1): when master's source changed
   since the opus's merge commit, the done perform records certify's certificate if every first-parent commit since
   is records-only or a merge-queue merge whose `certify` run succeeded, naming master's tree with the newest such
   run's receipt; the `bisellium.yml` and opus-record refusals stand. Until it lands, each opus's done runs before the
   other lane's merge perform.
C. **W-169 is amended to r7 and its design approved (lex §7):** the per-lane handoff sections are struck (lane state is
   each opus's traditio, read by W-299's `next --all`); `next` counts `origin`'s `opus/*` refs as in flight; the claim
   is the push of the new ref; admission is re-checked on the resume path. It is re-signed and re-reviewed before
   `branch`.
D. **`packages/cli/src/next.ts` is split by region** (new opus, right after W-169): `next/derive.ts`, `perform.ts`,
   `health.ts`, `report.ts`, no behaviour change, every test row kept, as W-179 split its tests.
E. **W-308 counts before anything more is built:** two more timeline rows, a certify rebase failure and the heavy-slot
   wait. Concurrent merge groups and a shared-contract declaration wait for those numbers.
F. **Orchestration wakes on events; nothing is always-on but machinery.** W-261 is re-scoped to an event wait in the
   cascade loop (one fresh session per wake, no model polling) and moves to Next; W-231 is halted (the cascade loop
   already runs fresh sessions); W-263 is halted (absorbed by C and W-299).
G. **Cloud lanes:** nothing beyond C until a cloud lane is planned; W-160's memo is narrowed to lead with the
   cross-machine claim contract (a `refs/bisellium` ledger with expected-revision updates, an ownership generation,
   stale-owner refusal, the overlap decision inside the update). `wip_limit` in `studio/bisellium.yml` is raised with
   the lane count when lanes exceed four (the Patron's config).
