## Decree

The Patron, 2026-10-04, ruled: redo W-085 behaviours 4–6 in order on the
unpushed `opus/W-085` branch.

## What happened

The first build implemented behaviour 4 with the section already at
priority 2 and routed through `buildContext`, which every boot path calls.
The tests for behaviours 5 and 6, written after that implementation,
passed on first run, so no red could be recorded for them and
`opus.red_evidence` blocked. The builder disclosed this and did not fake a
red. No tool honours a waiver of a missing red, so a waiver was not
available.

## The rebuild

The branch was reset to behaviour 4's red-log commit. Tests 5 and 6 were
committed ahead of behaviour 4's implementation, each red recorded against
that pre-implementation tree, and behaviour 4's implementation applied on
top; behaviours 7–8 and the docs commit were replayed unchanged. The test
commits for 5 and 6 cite this decision. The first attempt is kept as the
local branch `W-085-attempt1` until W-085 is done.

## Why this is not backfill

Each red is a real run of the test against a tree without the
implementation; nothing is stubbed or edited after the fact. What the
history cannot show is that tests 5 and 6 were first written after the
code. This record says so.

## 2026-10-07: W-161's rebuild does not fire the kill clause

The Patron ruled (2026-10-07, on the producer's recommendation) that W-161's
rebuild is not "a second rebuild of this class". W-085's tests were written
after the code, so no red was possible; W-161's tests came first, but reds 4
and 5 were recorded before the preceding behaviours were built, so they
failed for the wrong reason. The remedy was the same, the cause was not.
W-161's class is L-085, fixed by W-166. This decision stands.
