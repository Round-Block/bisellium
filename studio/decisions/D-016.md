Accepted, not built: branch creation, staging, committing, pushing,
rebasing, conflict resolution and PR merging stay raw `git` and `gh` at the
orchestration layer. The line is not "git is out of scope" — `bisellium
branch`, `merge` and `close` already run git — it is **where the refusal
lives**.

**A git operation enters the CLI only when officina state decides whether
it may happen.**

- `branch` — ties a branch to an opus id, so the name is derivable and
  `merge` can find it. In.
- `merge` — compares a gate's `certifies: tree:<hash>` against the branch's
  source tree and refuses a stale certificate (D-015, corrected). In.
- `close` — refuses an opus whose gates have not passed. In.
- `pr` (W-032) — refuses an ungated opus before touching a remote, behind a
  provider adapter. In, for the refusal; the creation step is the adapter's
  and stays thin.
- `add`, `commit`, `push`, `rebase`, `checkout`, conflict resolution,
  `gh pr merge` — nothing in the officina can refuse these, so wrapping
  them buys a second, worse git with our bugs in it. Out.

### The merge-reconcile recipe is not evidence for a porcelain

Every opus branch conflicts on its own opus record, and the handoff carries
a recipe for it: take master's copy, then re-run greenlight/ready/verify/
handoff on the branch through the CLI. It has been run three times and it
works.

Automating that recipe would freeze the wrong shape. The conflict exists
because two copies of one record are both written and neither is
authoritative — **W-033's undecided provenance question**, which taxes
every merge. A `bisellium reconcile` built today would encode "both copies
are real, here is how to pick" as a supported feature, and would then have
to be unbuilt when W-033 decides that one of them is not. The recipe is
manual precisely so the tax stays visible and keeps pressure on W-033.

Note the three CLI steps in the recipe are already the right shape under
the rule above: the fix is *re-running the commands that own those fields*,
never hand-editing them. What is missing is not a git wrapper.

### What this decision is not

It does not say the orchestrator's git work is fine as it is. It says the
remedy is W-033 (which copy is authoritative) and W-032 (the gate on the
one git operation that currently escapes every refusal), not a porcelain
layer. If W-033 lands and the recipe survives it, the kill condition above
fires and exactly that recipe becomes one command — not a general git
facade, and not before.
