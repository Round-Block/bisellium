Stated directly by the Patron: a retrospectio that reports findings and
lessons but not what the cascade actually cost is missing half the
picture a sizing decision (D-012) needs. `bisellium retro`'s optional
`usage` input (`RetroInput["usage"]`, packages/cli/src/retro.ts) and its
"## Usage" section — totals, checking/building ratio, tokens per opus,
trend against the previous retro, posture from the current aerarium —
make token spend a first-class retrospectio input alongside verifier
issues, review findings and test counts, not a separate report nobody
reads before the next cascade is sized.

`bisellium emit --usage` is the matching write path: it is what turns a
cascade's real spend into `events.jsonl` evidence in the first place, so
the retro's usage section (and `burn`) have something real to read instead
of a number someone remembers. (See D-012's `cascades/sizing.json` for
where the resulting posture reads feed back into cascade shape.)
