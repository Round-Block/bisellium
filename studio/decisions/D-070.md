Written by the producer at the Patron's instruction (2026-10-16). The lesson census of D-069 showed the retro filing
197 lessons that nothing acted on: a class's recurrence check goes silent once any lesson names a done opus, and the
fixes the triage named were mostly the opus that fixed its own instance. Every review finding is already fixed inside
its own opus before merge; what the retro added was only the class, at the cost of a Codex triage, two adjust scripts
and a lessons commit per opus. Fable advised keeping a cheaper retro routed per class
(`~/.bisellium-evidence/retro-routing-fable/report.md`); the Patron chose the producer's alternative. Applied by
`~/.bisellium-evidence/audit-rulings/{apply-d070.sh,lex-d070.py,handoff-d070.py}`.

## Decree

A. **No per-opus retro.** The done rung no longer runs a Codex triage or `retro --opus`; studio/lessons/ stays as
   read-only history. Lex §9 step 7 and the QA lex §7 say so.
B. **Reviewer class tags.** The spec and build reviewers name each finding's class (`<area>×<slug>`, an existing class
   verbatim where one fits), in the finding itself.
C. **A class seen before is fixed at its cause.** When a failing verdict names a class seen in an earlier verdict log or
   lesson, the fix round also fixes the cause (a check rule, brief-admission rule, prompt template or hook in the same
   opus) or files a greenlit high opus for the class. W-297 makes `verdict` and `next` enforce B and C; until it lands
   the producer checks a failing verdict's classes with `~/.bisellium-evidence/lesson-census/census.py`.
D. **Opera.** W-297 filed greenlit (M7), ranked right after W-214. W-214 and W-251 lose their retro clauses. W-213
   (the retro reads beyond review findings) and W-287 (lesson recurrence counted truthfully) are halted: W-297 absorbs
   their escalation and counting.
