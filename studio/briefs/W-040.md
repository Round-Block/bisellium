# W-040 — gate correction: re-sign a wrongly-signed gate without erasing it

## Intent

`bisellium ready` refuses unless the opus is `greenlit` or `halted`
(`packages/commands/src/lifecycle.ts:102`). Once an opus is `building`, its
spec gate is frozen. If the gate was signed by the wrong sella, or with the
wrong spec path, the CLI offers nothing.

W-031 is the recorded case (`studio/ci/W-031-review-2.log`, FINDING 1). The
spec gate read `sella: qa-lead`; an orchestrating session overwrote it with
`eng-lead` to stop `process.cascade` firing, and the review called it what
it was: backfilled evidence, the officina's own recurrent finding class.
The review named two legitimate remedies — produce the eng-lead gate, or
restore `qa-lead` and file a petitio. **The restore had to be done by hand,
byte-for-byte**, because no command can write a gate onto a `building`
opus. CLAUDE.md forbids hand-editing front matter. Both honest paths ran
through the forbidden one.

The question this opus answers is not "should gates be rewritable" — they
already are, with a text editor. It is **whether a rewrite leaves a trace**.
Today the only available rewrite erases; that is the defect.

## The rule this encodes

A correction **appends**; it never erases. The superseded signature stays
in the record with the reason it was superseded, exactly as `D-015`'s
disproved clause is struck rather than deleted and `leges/*.md` carry an
amendment log rather than a rewritten body. That is already the officina's
house style for changing a claim; this opus gives a probatio the same
treatment.

## Interfaces

```
usage: bisellium ready <opus> [--spec <path>] [--sella <id>] [--correct --reason <text>] [--studio <dir>] [--now <iso>]
```

No new verb. `--correct` is the only path into `ready` from `building`:

- Without `--correct`, today's refusal is **unchanged**, byte for byte.
- With `--correct`, `building` is accepted and `greenlit`/`halted` are
  **refused** — a correction is not a substitute for the normal gate, and
  allowing both through one flag would let a mistyped flag silently skip
  the real path.
- `--reason` is mandatory with `--correct` and must be non-empty. A
  correction with no stated reason is the thing this opus refuses to make
  easy.
- `--correct` without a `spec` probatio recorded on the opus is refused:
  there is nothing to correct.
- The state stays `building`. No `workflow.state_changed` — nothing
  changed state. Emit the correction as its own event.

Front matter after a correction:

```yaml
probationes:
  spec:
    sella: qa-lead                 # the corrected value
    status: passed
    evidence: briefs/W-031.md
    at: 2026-09-20T12:00:00.000Z
    corrections:                   # appended, never rewritten
      - at: 2026-09-20T12:00:00.000Z
        sella: architect           # who made the correction
        reason: "restored: eng-lead signature was never produced (review-2 FINDING 1)"
        superseded:
          sella: eng-lead
          at: 2026-09-19T18:27:08.223Z
          evidence: briefs/W-031.md
```

`corrections` is a list, appended to. The `sella` on the entry is who
*corrected*; the `sella` on the gate is who the gate now claims signed it.
They are different people and the record must not conflate them.

## `probatio.corrected` (advise)

Folded into `check.ts`'s existing opera/probationes walk — no new read. One
finding per corrected gate:

```
${gate} gate corrected ${n} time(s), most recently by ${sella}: ${reason}
```

Advise, permanent, never clearable. That is the point: a corrected gate
reads differently from one that was right the first time, for as long as
the opus exists. Without this rule the correction is buried in front matter
and the feature really would be quiet gate-rewriting with extra steps.

Register the id in `packages/cli/src/rules/ids.ts` in the same commit **if
that file exists on the tree** (W-035); if it does not, W-035's harvest
picks it up. Same coupling as W-039, same one-literal cost.

## Behaviours to test

1. `ready --correct --reason "…"` on a `building` opus rewrites
   `probationes.spec.sella` and appends a `corrections` entry carrying the
   superseded sella, its `at`, and the reason
2. State stays `building`; no `workflow.state_changed` event is emitted
3. `--correct` on a `greenlit` opus is refused, and `ready` without
   `--correct` on a `building` opus is refused with today's exact message
4. `--correct` without `--reason`, or with an empty one, is refused and
   writes nothing
5. A second correction appends a second entry — the first is still readable
6. `probatio.corrected` advises once per corrected gate, naming the count,
   the correcting sella and the reason
7. `probatio.corrected` never blocks

Reds via `bisellium red W-040 --behaviour <n> --sella <id>`, one per
behaviour, assertion-level. Temp officinae only.

## Acceptance

1. `npm test` green; `typecheck`, `lint`, `format:check` clean.
2. W-031's actual case, replayed on a temp copy: a `building` opus with a
   wrong spec sella reaches the right one through the CLI alone, with the

3. No hand-edit of front matter appears anywhere in the opus's own
   evidence.

## Out of scope

- **Correcting any gate other than `spec`.** `review` already appends
  rounds, and every automated gate is re-produced by re-running `verify`.
  `spec` is the only frozen one. Generalise when a second frozen gate
  exists, not before.
- **Undoing a correction.** Append-only means append-only.
- **W-031's own record.** This opus builds the path; whether to walk it for
  W-031 is the Patron's and the Censor's, on the review's own terms.
- **Any `--force` that skips `--reason`.** The reason is the feature.
