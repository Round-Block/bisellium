# W-028 — patron-as-agent: automated merge, push and cascade orchestration

## Intent

The patron role today is a human pressing buttons — merge, push, update
handoff, rebuild dossier. Every one of those is mechanical and forgettable.
W-028 automates the patron's checkpoint responsibilities so they happen as
part of the build flow, not after it.

First deliverable: a `process.checkpoint` check rule that fires when an
opus reaches `done` but the handoff/dossier haven't been updated. This
catches the exact failure mode where code lands but checkpoint artifacts
don't follow.

Later deliverables (same opus): `bisellium close` command that runs the
full checkpoint sequence (handoff update, dossier rebuild, artifact
republish, push), and the patron sella driving cascades without a human
in the loop.

## Files owned

- `packages/cli/src/rules/process.ts` — `checkpointStale` pure function + wiring into `checkProcess`
- `packages/cli/src/rules/process.test.ts` — new behaviours for checkpoint rule
- `studio/briefs/W-028.md` — this file

## Interfaces

- `process.checkpoint` check rule (advise level) — fires when an opus
  in `done` state has no corresponding handoff update in HEAD
- `checkpointStale(changedFiles: string[]): boolean` — pure function:
  true when the commit changed opera files but not handoff/dossier

## Behaviours to test

1. `checkpointStale` returns true when opera changed but handoff didn't
2. `checkpointStale` returns false when opera and handoff both changed
3. `checkpointStale` returns false when only handoff changed
4. `checkpointStale` returns false when neither changed (docs-only commit)
5. `checkpointStale` returns false for empty file list

## Acceptance

`bisellium check` flags a commit that moves an opus forward without
updating SESSION-HANDOFF.md or the dossier progress page. The rule is
advisory, not blocking.

## Out of scope

- `bisellium close` command (later in this opus)
- Fully autonomous patron sella (later in this opus)
- Artifact republishing automation
