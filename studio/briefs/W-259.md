## Intent

Today the `done` rung names `bisellium verify <id> --studio studio --repo .` whenever an automated gate has no `tree:` certificate for master's source tree. That reruns the whole suite on this host, about 11 to 30 minutes, after the merge queue's `certify` job already ran it on the same tree: `certify` rebases the PR onto master and runs the host mint (`bisellium run … -- true`), whose `ci --offline --opus` runs typecheck, lint, the tests and both officina checks, and uploads its receipt and log as the artifact `certify-<run id>`. On W-292 the local `verify` hit the 30-minute cap twice on master 6a4ce7d3, while certify run 39012304510 had passed the merge commit 05b7ddc2 in 20 minutes (`artifact-540/`: the receipt's `finalSourceTree` is `tree:1521e1a0…`). Master had moved since by two records PRs that changed the handoff, which sits inside the source tree, so master's tree (`3872e641`, then `07316294`) was no longer the certified one (`tree-census.out`).

After this part, the `done` rung of a non-ui opus names `bisellium next <id> --perform --expect done`; the perform records the merge queue certificate or holds naming full `verify`. Records-only commits after the merge preserve this route only when they did not change `<studio>/bisellium.yml` or `<studio>/opera/<id>.md`; either policy-input change holds and names `verify`. The gates then certify the merge commit's own tree, which the done rung accepts while master changed nothing else but officina records since the merge (`recordOnly`, the list certify and `next` already share).

Cause fix (D-076 D, class `mechanism×certification-coverage-not-diff-bound`, L-160): every acceptance of a certificate for a tree other than master's goes through one diff-bound function, `mergedTree`, which both `certificate` and `recordCertify` call and `W-259-b1` pins (a gate added, or the record edited, by a records commit after the merge holds); a check rule or prompt would only restate it, so this is the smallest real fix.

Threat model: mistakes, not adversaries (D-045). The run, the job and the artifact are read with the agent's `gh` token from the repository's own Actions.

## Interfaces

**Rung 11.** When an automated gate is not certified (`certified()` false), `deriveNext` names `done`, actor `producer`, with `why: <id> is MERGED, fetched and cleaned up; no automated certificate is recorded: the perform records the merge queue's certify certificate`, `command: bisellium next <id> --perform --expect done`, `act: "certify"` and a `done` ticket (W-233). When the working record or the trunk record has `kind: ui`, it names `bisellium verify <id> --studio <rel> --repo .` with `act: "verify"`, as master does: certify's artifact cannot vouch for a `ui` opus's served-e2e gate and its screenshots.

**`certificate(…, merged?)`.** Master's source tree stays the default `want`. When `merged` (the settled PR's `mergeOid`, from the memoised `f.pr()`) is given and the first gate does not certify master's tree, `mergedTree(repo, studioRel, excludes, merged, id)` accepts the merge tree only when `diffPaths` is readable, empty or `recordOnly`, and names neither `<studio>/bisellium.yml` nor `<studio>/opera/<id>.md`; otherwise `certificate` keeps master's tree as `want`. When accepted, the merge commit's `tree:<sourceTreeHash(…, merged)>` becomes `want` if the first gate certifies it, and every gate then certifies that one tree, as before. The merge tree is read only in that case, so a world with no automated gate or a master-tree certificate makes no new git call.

**The certify perform.** W-186's `handoffHold` still runs before `performDone`, as today. `performDone`, after `dirtyHold` and before its handoff, history-row and merge refusals, calls `recordCertify(f)` when `act` is `"certify"`. Any reason it returns, or any error it throws, holds the perform with `why: refusing: the merge queue's certify certificate cannot be recorded: <reason>; run: bisellium verify <id> --studio <rel> --repo .`. `recordCertify`:

1. The settled PR's merge commit `oid` (`f.pr()`); `mergedTree` for it (a source path, `<studio>/bisellium.yml` or `<studio>/opera/<id>.md` changed on master since, or an unreadable diff, is the reason: `master changed <path> since the merge commit <12 hex>, which certify's run did not judge`).
2. `gh run list -R <slug> --workflow ci.yml --event merge_group --commit <oid> --limit 20 --json databaseId,headSha,event,status,conclusion`: exactly one entry with `headSha` = `oid` and `event` = `merge_group`, `completed` and `success`, its `databaseId` a positive safe integer. The merge queue moves master to the merge group's own commit, so the PR's `mergeCommit.oid` is that run's head (#540: run 39012304510, head 05b7ddc2).
3. `gh run view <run> -R <slug> --json jobs`: exactly one job named `certify`, conclusion `success`.
4. `gh run download <run> -R <slug> -n certify-<run> -D <dir>`, `<dir>` a fresh `mkdtempSync` under `ensureRealDirectory(repo, ".bisellium", "certify")`, removed afterwards. Every entry under it is a regular file or a directory (`artifactFiles`); exactly one file is a `.json` with a `receipts` path segment, exactly one is named `certify.log`; each is read through `readContainedRegularFile` (1 MiB and 16 MiB caps).
5. `receiptProblem`: `exitCode` 0, `harness` `run`; a `completion` with `schema` 1, `origin` `host-producer`, `completed` and `teardownComplete` true, `opus` = `<id>`, `branch` = `opus/<id>`, `gates` `ci`, `verify` and `check` true, and `finalSourceTree` equal to the merge commit's tree. `certify.log` holds the lines `certify: merge group for PR #<n>` and `certify: the mint exited 0`.
6. Then, writing: for each automated gate of the working and trunk records, `ci/<id>-<gate>-<40-hex tree>.log` (`certifies: tree:<hash>`, a `command:` line naming the run, the PR, the merge commit and the receipt's sha256, `exit code: 0`, then the receipt and the log's last 200 lines through `redact`), and on the record each gate's `status: passed`, `evidence` and `certifies` (`editOpusFrontMatter`). It prints `certificate: certify run <run>, PR #<n>, merge commit <oid12>, tree:<hash>` and one `certificate: <gate> ci/<file>` line per gate, ahead of the done lines. The 40-hex name never collides with `verify`'s 8-hex logs.

The perform then runs as today: the handoff and history-row refusals, the merge refusal, `chore/done-<id>`, `runDone`, and the commit, whose `certificate(…, mergeOf(f))` stages the new logs. A hold after the record is written (a stale handoff, say) leaves the certificate in the working tree, as a `verify` run left it, and the next perform finds it certified.

Limits, stated:

- The fallback `verify` is unchanged (`packages/pipeline` is not edited): it keeps the 30-minute `GATE_TIMEOUT_MS` per gate, which W-292's master run hit twice; the orchestrator's diagnosis of that timeout is separate.
- GitHub keeps the `certify-<run>` artifact for 90 days (#540's expires 2027-01-15); a done later than that falls back.
- A records-only change after the merge was checked by CI's records-only path (`test:record` and the studio check), not the full suite; the certificate names the merge commit's tree, not master's tip.
- The perform trusts what `gh` reports for the repository's own Actions run; it reads no signature.
- The step marker's silence limit for `done` is 120 s (`STEP_SILENCE_SECONDS.done`): a download slower than that reads stalled to a concurrent `next`; nothing kills it. Each `gh` call has `sh`'s 120 s timeout and 16 MiB buffer.
- A hold after the logs are written but before the record write (a throw in `editOpusFrontMatter`) leaves untracked logs that the next perform overwrites.
- Unchanged code keeps its behaviour: `runDone` accepts any `tree:` certificate, `check`'s `probatio.certifies.stale` judges active opera only, and `reviewFailedAtCertifiedTree` compares a failed review's tree with the gates' tree, as on master.

### Input domain

A rejection fails closed: `recordCertify` returns its reason, or its error is caught, and the perform holds with exit 1, naming `verify`, before `chore/done-<id>` is cut. A test row whose own read fails throws, which fails the row.

| Record | Valid domain | Rejected by |
|---|---|---|
| The opus's PR, through `f.pr()` | settled, with a `mergeOid` | `recordCertify` (specified): anything else is the reason |
| Master's changes since the merge commit, `diffPaths(repo, oid, master)` | readable, empty or `recordOnly`, with neither `<studio>/bisellium.yml` nor `<studio>/opera/<id>.md` changed | `mergedTree` (specified, taking `id`): a failed diff, source path or either policy-input path is the reason; `certificate` keeps master's tree as `want` |
| The record kinds, working and trunk | neither is `ui` | `deriveNext` (extended): a `ui` kind on either is named `verify`, as master names it |
| `gh run list` reply | JSON array with exactly one `merge_group` entry whose `headSha` is the merge commit, `completed`, `success`, a positive safe integer `databaseId` | `ghRead` (specified) for exit and JSON, then `recordCertify` (specified) |
| `gh run view --json jobs` reply | an object whose `jobs` holds exactly one `certify` job with conclusion `success` | `ghRead` (specified), then `recordCertify` (specified) |
| `gh run download` | exit 0 | `recordCertify` (specified): any other exit or a spawn error |
| The downloaded artifact | regular files and directories; one `receipts/…json`, one `certify.log` | `artifactFiles` (specified): a symlink or other entry; `recordCertify` (specified): any other count |
| The receipt and the log, as files | contained regular files of at most 1 MiB and 16 MiB | `readContainedRegularFile` (existing) |
| The receipt's content | JSON whose fields `receiptProblem` requires, `finalSourceTree` the merge commit's tree | `receiptProblem` (specified), after `JSON.parse` in `recordCertify` |
| `certify.log`'s content | the PR's merge-group line and `certify: the mint exited 0` | `recordCertify` (specified) |
| `ci/` and `.bisellium/certify/` | real directories | `ensureRealDirectory` (existing): it throws, which holds |
| The record write | the record parses | `editOpusFrontMatter` (existing): it throws, which holds |
| The test row's stub inputs (the scenario's replies and `files`) | data the row writes | `writeFileSync`, `JSON.parse` (in the stub and the row): a failure throws, which fails the row |
