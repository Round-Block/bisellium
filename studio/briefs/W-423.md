## Intent

The class security×symlink-parent-write-escape was filed three times (L-063, L-080, L-084) and marked addressed by W-163, which built the census of every raw file access in `packages/cli/src/containment.test.ts` (W-163-b6). It came back in W-259's build review round 1, W-274's spec round 2 and W-418's build review round 1. W-418 closed its own notice store with a per-site `lstat` check (`linked` in `packages/cli/src/review-notice.ts`), and its fix census (`~/.bisellium-evidence/W-418-review/r1/fix-census.md`, lines 10 to 11) left two sites open in `packages/cli/src/integrate.ts`: with `<git common dir>/bisellium` a symlink, the queue-mode `pr` rung writes its queue binding outside the Git common directory, and the direct-mode rung reads an outside binding as bound and deletes it after the push.

The cause is a gap in the census, not in one site. The census forces every new raw fs call to be pinned with a disposition, and it checks that a `contained` pin sits in a function that calls a containment helper. Its other dispositions are judgments. Every write under the Git common directory was pinned `outside` ("a git dir, never an officina"), so containment was never asked of it, and each new store (W-199's queue binding, W-233's step tickets, W-369's sync request, W-418's notices) followed the same pattern: `git rev-parse --git-common-dir`, then `mkdirSync(…, { recursive: true })` and a write, both of which follow a symlinked level.

The enumeration (`enumerate-master.out`) lists every direct write-capable fs call (writes, removals, renames and opens; 97 sites) in `packages/cli/src` and `packages/commands/src` as the census scans it, with its disposition, whether its function calls a containment helper, the anchor it writes under and this opus's decision. Fifteen sites write under `<git common dir>/bisellium` and none proves its directory (only `claimTicket` calls a helper at all, the contained reader, rooted at the directory itself): the queue binding (3), the sync request (2), the step-ticket store (6) and the notice store (4). The shared containment helper already exists: `ensureRealDirectory` and `requireRealDirectory` in `packages/commands/src/ids.ts`, the census's `CONTAINMENT_HELPERS` (W-099 names the same class for the officina's subdirectories and is still greenlit; this opus reuses its helper and does not close it). Twenty-five officina writes already go through it, and four sites are its own body.

So this opus does two things:

- It routes the fifteen Git-common-directory sites through the helper, anchored at the Git common directory as git prints it. A symlinked level below the anchor refuses before anything is written, read, renamed or removed through it, and the refusal surfaces through each site's existing hold or error. Behaviours 1 to 4 cover the queue binding (write, then probe and removal), the sync request and the step tickets; behaviour 5 moves W-418's notice store off its per-site check and onto the helper.
- It adds the rule the class lacked, as a row of the census (behaviour 5, `W-423-b5`): every direct `node:fs` or `node:fs/promises` call in the governed source is classified, read-only or write-capable (an unclassified function fails), and every write-capable one sits in a function that calls a containment helper, or in an approved helper's own body, or is a stated limit in a reviewed list (`WRITE_LIMITS`), each naming one of seven classes. A new direct write anywhere else fails `npm test`, and so does a limit that no longer names such a write. A stream constructed as an object and a read-only name called with a write flag are not judged: a stated limit, W-425's remainder (Limits).

The remaining forty-three direct writes that call no helper are the stated limits, by class (Limits): OS temp (9, three of them `mkdtempSync` calls the full scan of revision 2 found), repository files outside the officina (5), `<repo>/.bisellium/` (9), test seams (3), a read-only open (1), fixed-name files in the officina root, where there is no level below the anchor for the helper to prove (8), and `init` (8), which creates the officina from nothing. Every one is in `WRITE_LIMITS` by key. Out of scope proposes the follow-up filings.

Threat model: mistakes, not adversaries (D-045). The helper proves each level when it runs; a level swapped between that proof and the write (a TOCTOU window) is a stated limit (D-076 E).

**The helper's contract** (`packages/commands/src/ids.ts`; `ensureRealDirectory` and `requireRealDirectory` unchanged).

- The anchor is the `root` argument, made real with `realpathSync` first. A symlink at or above the anchor is the file system's to follow (Limits). Every caller in this opus passes the Git common directory exactly as `git rev-parse --path-format=absolute --git-common-dir` prints it.
- The walk takes each segment in turn, one plain name (not empty, `.` or `..`, and holding no `/` or `\`; any other segment throws `record directory segment must be one plain name: <json>`). For each level below the anchor it `lstat`s the entry: an absent level is made (`ensureRealDirectory`, `mkdirSync` of that one level) or ends the walk (`existingRealDirectory`, which returns undefined). A present level, or one just made, must pass `requireRealDirectory`: not a symlink, a directory, and its real path its own lexical path. Otherwise the walk throws `record directory must be a real directory, not a symbolic link: <the level's path from the real anchor>`, for a regular file at the level too.
- A refusal is a thrown `Error`. Each site catches it, writes nothing below the refused level, and surfaces the message through its existing hold or error (below).
- `requireRealDirectory(dirname(p))`, on a path `p` built from the real anchor, re-proves the whole chain in one call: its real path must equal its lexical path. A site that removes or renames a path found earlier (`unbind`, `claimTicket`, `dropClaim`) calls it first.
- **`existingRealDirectory(root, ...segments)`** (new, exported): the same walk, never creating, returning the real directory's path, or undefined when a level is absent.

**The routed sites.** Each anchors at the Git common directory of its checkout.

- **`writeBinding(repo, branch, oid)`** (new, behaviour 1): `ensureRealDirectory(<common>, "bisellium", "queue")`, then the binding `<oid>` and a newline at `<encodeURIComponent(branch)>`. It returns undefined, or why not. The queue-mode `openPr` holds before the push on why not: `why: cannot write the queue binding <common>/bisellium/queue/<branch>: <why>`.
- **`readBinding(repo, branch)`** (behaviour 2, signature unchanged): `existingRealDirectory(<common>, "bisellium", "queue")`. An absent level is `absent`, an entry in the real directory is `bound` with its real path, and a refusal is `error`. A direct-mode `openPr` holds before the rebase on `error` (`why: cannot read the queue binding: <why>`, unchanged), and so does a direct-mode merge (`readBinding` is `!== "absent"`, unchanged).
