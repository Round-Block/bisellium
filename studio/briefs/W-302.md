## Intent

`.github/CODEOWNERS` makes the Patron review any PR touching `.github/`, `scripts/ci-certify.mjs`, `.claude/`, `studio/leges/`, `studio/decisions/` and `docs/ADOPTION.md`. Two record paths that decide who reviews what are missing:

- `studio/bisellium.yml`: the seats and their models (the reviewer seat included), `source_excludes`, and the studio's settings.
- `studio/prompts/`: the review prompts the Codex gate is given (D-066 C's independence).

A records-only PR can change either with no human review: the records path needs no opus, no certificate and no code-owner approval. #512, #513 and #514 merged that way (Fable on W-243, 2026-10-16). After this opus such a PR needs the Patron's review; an agent can still open it. GitHub is the reader that decides the review, and it reads CODEOWNERS from the PR's base branch: W-302's own PR is reviewed under master's current file (it needs the Patron anyway, for `/.github/`), and the two new lines bind once master carries them. `W-197-b2` reads the file in the checkout under test and pins its bytes; it shows what the next base will say, not which review GitHub asks for.

`.github/workflows/ci.yml` also has two comments that went stale with W-243 (#516). Lines 8-10 say a head that is not `opus/W-*` "mints nothing"; the certify job's comment (lines 151-157) says certify rebases "the PR head" and mints it. Since W-243 `scripts/ci-certify.mjs` mints only a head named `opus/W-<n>`. Any other head mints nothing and passes only when `recordOnly` (`scripts/ci-scope.mjs`) holds for its merge group's diff, read through `diffPaths`; a non-record path or an empty diff exits 1, an unreadable diff exits 2. Both comments are rewritten to say so. A comment has no behaviour, so it has no red; the existing rows that read `ci.yml` keep it honest (Acceptance).
