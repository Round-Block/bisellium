## Intent

The SubagentStop guard (W-310) sends a subagent back while any of its own background work runs. A runner that started a long run (`ci --opus`, a merge perform) in the background and then ended its turn to wait was sent back, so it started a background waiter to stay in turn; every wake repeated it. Nothing refused a second background call while the first was live, and nothing refused a wait loop on `pgrep -f`, which matches the shell running the wait itself (its command line holds the pattern), so the loop never sees the run end. This opus makes one background run per subagent the rule, lets a turn that hands nothing back end while that one run is live, refuses the self-matching wait, and writes the foreground exit-file poll into the agents and the briefs.

**The probe (decided; `probe/hook-input-probe.out`).** Claude Code 2.1.314's own hook input schemas (read from the installed binary) give `background_tasks` (the session's in-flight tasks) only to Stop and SubagentStop; a PreToolUse input carries `session_id`, `transcript_path`, `cwd`, `agent_id` (present only inside a subagent), `agent_type`, `tool_name`, `tool_input` and `tool_use_id`, and no task list. The harness writes a subagent's transcript at `<session transcript without .jsonl>/subagents/agent-<agent_id>.jsonl` (this session's own files, written by 2.1.312), and records there a background start as a user record whose `toolUseResult.backgroundTaskId` names the task, an end as a `queued_command` attachment with `commandMode: "task-notification"` whose prompt holds `<task-id>…</task-id>`, and a TaskStop as a user record whose `toolUseResult` holds `task_id` and a message opening `Successfully stopped task` (no notification follows a TaskStop). A hand-back is an assistant `tool_use` named `SubagentHandback`; a reused agent's transcript holds more than one. The harness's own notes say a subagent may be "waiting on its own background work with nothing delivered yet". So the guard learns a subagent's live runs at PreToolUse from its own transcript, with no state file and no settings change.

**One background run per subagent (decided).** At PreToolUse, a Bash call with `run_in_background: true` from a subagent (an input with `agent_id`) is refused while the agent's transcript shows a background run started and not ended; the refusal names the live run and the route: wait in the foreground on the run's exit file (`timeout 540 bash -c 'until [ -f X.exit ]; do sleep 10; done'`), or stop it with TaskStop, then start the next. The main thread is not judged, nor a foreground call.

**A turn may end while the one run is live (decided).** At SubagentStop the guard still sends back an agent whose report is in (its last tool call is `SubagentHandback`) while its own work runs (W-310, unchanged text). A stop that hands nothing back is the agent waiting: it may end while one of its own runs is live, whose notice wakes it, and is sent back, once, only when two or more of its own runs are live, told to stop all but one. "The one tracked run" of the opus record is read as this one run the guard counts per agent, never a `next --track` marker (Defaults 2).

**The self-matching wait (decided).** Any Bash call, from any thread, foreground or background, whose command text holds a wait loop (`while` or `until`, or `wait-until.sh`) and a `pgrep` given `-f` or `--full` is refused, naming the exit-file poll instead.

**The guidance (decided).** The ladder-runner, builder and architect definitions and the builder and spec-draft briefs say: one background run at a time; the run writes its exit file last; wait in the foreground with the exit-file poll; never a new background waiter; never `pgrep -f`; a turn may end while the one run is live.

Threat model: mistakes, not adversaries (D-045). The guard stays deny-only and fail-open (W-310): an input or a transcript it cannot read lets the call run.
