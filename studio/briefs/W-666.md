## Intent

A Patron answer is forgeable today. `answer` is a Patron write by position alone: `main.ts` sets `BISELLIUM_ROLE=patron` before `runAnswer` (master packages/cli/src/main.ts:162-164), `appendPatronTimeline` stamps `patron` whatever the caller (master packages/commands/src/writes.ts:170), and the console's `POST /api/answer` runs it `asPatron` behind a token any same-host process can read (master apps/server/src/http.ts:332-341, :460-469, :863-877). Any agent process can therefore record an answer as the Patron.

After this opus, a Patron answer is authorized by a receipt the Patron signed, whatever the transport. A receipt binds one answer: the petitio id, the digest of the question as it stood, the named option (the reply), the mode (resolve or ask-back), the charter-gap flag, a nonce and a time. It verifies, by node:crypto alone, against a public key the officina's `bisellium.yml` names under `patron_receipts.keys`; `studio/bisellium.yml` is already code-owned (`.github/CODEOWNERS`), so adding, removing or replacing a key needs the Patron's review. The private key and the signer live with the Patron, outside the agent clone and its read set; nothing in this opus signs.

The committed record of an answer is the petitio: its stamp line `[stated] <instant> <patron>: <reply>` and, new, the receipt in its front matter under that instant (`receipts:`). The Patron timeline (`timeline/patron.jsonl`) is gitignored (`.gitignore:31`), so it carries a copy only; the check runs over the petitiones, which CI sees. Three guards, one verifier (`receiptProblem`): `answer` refuses an unsigned or invalid Patron answer before writing anything; the console's answer route carries the receipt to `answer`; and the `patron.receipt` check rule blocks a committed Patron stamp whose receipt is missing, forged, altered, replayed or agent-authored. The stamps written before receipts are fixed by one digest (`patron_receipts.floor`), so a new unsigned stamp, or an edit to an old one, blocks.

An officina whose `bisellium.yml` names no keys answers as before, and `check` says once that its Patron stamps are unsigned (advise). The real studio is enforced from the commit in which the Patron adds his key and the floor.

Threat model: an agent process on the Patron's host, with the agent clone's read and write set (D-148's sandbox: `~/.ssh` and `~/.config/gh` unreadable, `~/projects/bisellium` unwritable), that can run any bisellium verb, write any studio file and call the console with its token. It cannot read the Patron's private key or make the Patron's signer sign.

## Promises

Promise receipt: in an officina whose `bisellium.yml` names Patron keys, `answer` writes a Patron answer only with a `--receipt` that verifies for exactly that answer, and refuses by name, writing nothing (the petitio and the timeline unchanged), an answer with no receipt, a forged signature, an altered payload, an agent-authored receipt, a receipt for another reply, a stale receipt and a replayed one, and refuses the same way while any recorded-nonce source (a timeline line, a petitio entry, its front matter, its `receipts`) does not read, and while another `answer` holds the officina's answer lock (`timeline/.answer.lock`), which an answer of an officina naming `patron_receipts` holds from its petitio read through its timeline append, so two `answer` processes of one checkout never both accept one receipt; the binding is verified on the very body the edit stamps (r5, review 1 finding 1) — limit: `answer` checks what reaches it; a process that writes the petitio by hand, or deletes the lock, bypasses it, and the `patron.receipt` rule is the guard for that; the lock spans the processes of one checkout, and across checkouts the committed check (one receipt on two stamps) is the guard. Pinned by `W-666-b1` "an answer with no receipt is refused by name" and pinned by `W-666-b1` "an altered receipt is refused by name" and pinned by `W-666-b1` "a replayed receipt is refused by name" and pinned by `W-666-b4` "a malformed timeline line refuses the answer" and pinned by `W-666-b7` "an answer is refused while the answer lock is held" and pinned by `W-666-b7` "two processes replaying one receipt accept at most one".

Promise record: an accepted receipt is recorded on the petitio's front matter under the answer's stamp instant and copied to the timeline line, and an Ed25519 or an ECDSA P-256 Patron key verifies — limit: the timeline copy is local; the petitio is the committed record. Pinned by `W-666-b1` "a valid receipt is recorded on the petitio under its stamp" and pinned by `W-666-b1` "a P-256 Patron key verifies too".

Promise check: with Patron keys named, `check` blocks (`patron.receipt`) every Patron stamp in a committed petitio whose receipt is missing (beyond the floor), forged, agent-authored, bound to another reply, replayed, or keyed by no stamp, every signed stamp followed by any text other than the next Patron stamp or whitespace at the body's end (a signed stamp spans exactly its option, so a stamp marker inside a signed reply is part of that reply; r5, review 1 finding 2), blocks every petitio source it cannot read (an unlistable `petitiones/`, a symlinked, non-regular or unreadable entry, unparseable front matter, `receipts` not a mapping), and raises nothing for a valid one — limit: the mode and the charter-gap flag are bound by the signature and checked on the write path only, since a petitio's later state cannot tell them. Pinned by `W-666-b2` "a recorded answer with no receipt is blocked" and pinned by `W-666-b2` "a valid recorded receipt raises no finding" and pinned by `W-666-b5` "a symlinked petitio is blocked" and pinned by `W-666-b8` "a suffix after a signed reply is blocked" and pinned by `W-666-b8` "a signed reply holding a stamp marker raises no finding".

Promise floor: the unsigned stamps recorded before receipts pass while their digest equals `patron_receipts.floor`, and a change to any of them (any byte of an unsigned reply, which runs to the next Patron stamp or the body's end), or one more, blocks — limit: the floor is set by the Patron at install; W-666 computes no floor for him beyond printing the current digest in the block; whitespace at the very end of a petitio body is the file's and is not read. Pinned by `W-666-b2` "an unsigned stamp under the floor needs no receipt" and pinned by `W-666-b2` "an unsigned stamp that changed under the floor is blocked" and pinned by `W-666-b8` "a suffix after a floored stamp is blocked".

Promise unconfigured: an officina naming no Patron keys answers exactly as before, and `check` raises one advisory while any petitio holds a Patron stamp — limit: such an officina's answers stay forgeable; the switch is `patron_receipts.keys`. Pinned by `W-666-b1` "an officina naming no Patron keys answers as before" and pinned by `W-666-b2` "an officina naming no Patron keys is told its answers are unsigned".

Promise route: the console's `POST /api/answer` passes a body's `receipt` object to `answer` as `--receipt`, through a fresh private temp file removed when the write returns, and passes none when the body has none; a body of the wrong shape answers 400 and an `answer` refusal returns HTTP 200 `{ ok: false, exitCode: 2, output }` — limit: the route carries the receipt and verifies nothing itself; `answer` is the verifier; the refusal class is reused, unchanged code (`writeResponse` maps a non-zero `answer` exit to HTTP 200 `{ ok: false }`) over behaviour 1's refusal and behaviour 3's forwarding, so its row is a regression pin with no red of its own (D-076 E), and behaviour 6's red covers only its own change, the body-shape error code. Pinned by `W-666-b3` "the answer route passes the receipt to answer" and pinned by `W-666-b3` "an answer posted with no receipt passes none" and pinned by `W-666-b6` "a verifier refusal is HTTP 200 with ok false and exit 2".

Limits, stated:

- Reused, unchanged code these promises lean on: `readContainedRegularFile`, `splitFront`, `yaml`'s `parseDocument`, `writeResponse`, `editOpusFrontMatter` (the body travels byte-for-byte; its own read and write are one synchronous step with no lock, so a writer other than `answer` that lands between them is lost, as on master), `ensureRealDirectory`, `safeItemPath`, `parseFlags`, `checkWriteAuth` and `withWriteLock`, node:crypto's `verify` and `createPublicKey`, and node:fs's exclusive create (`wx`). None is edited.
- The verifier is agent-writable code: a PR that weakens `patron-receipt.ts` or `rules/receipts.ts` needs only the ordinary review unless the Patron code-owns them (a `Patron call` of this spec, not in its Files owned).
- `greenlight`, `budget` and `delegate` lines of the timeline are not receipt-bound; W-526 already records no Patron act for a CLI greenlight.
- The console has no way to obtain a signature yet: until W-667 gives the Inbox one, a console answer in an officina naming keys is refused by name.
- Exactly-once consumption of an answer by the boot reader is W-668's; W-666 gives it `patronStamps` and `receiptProblem`, and spends each nonce once across the officina. Revision 5 changes that seam (review 1 finding 2): `patronStamps` takes the petitio's recorded receipts and each `Stamp` carries its exact `reply`, and `stampedReply` is gone; W-668's brief names `stampedReply` among its reused helpers and is re-read against this interface before it is built. The answer lock is never taken over: a lock left by an `answer` that was killed refuses every answer of the officina, naming the path, until it is removed; `answer` cannot tell a dead owner from a live one without a race (two takers can each remove the other's lock), so it fails closed. An officina naming no `patron_receipts` takes no lock.
- A process that deletes a recorded receipt from every record (the gitignored timeline line and the petitio, restoring its question) can replay it inside the receipt's 15-minute window; `answer` reads the records as they stand, and the committed history is git's, not this opus's.
- An officina naming no keys keeps today's reading: `check` counts the stamps of the petitiones it can read for its one advisory and blocks nothing; `petitio.parse` names the rest.

## Interfaces

**Receipt wire form** (JSON): `{ "payload": { "v": 1, "petitio", "question", "option", "mode", "charter_gap", "nonce", "at" }, "key": <sha256 hex of the signing key's SPKI DER>, "sig": <base64 signature> }`. The signature is Ed25519 (`crypto.sign(null, …)`) or ECDSA P-256 over SHA-256 in IEEE P1363 form, over `receiptBytes(payload)`.

**`receiptBytes(p: ReceiptPayload): Buffer`**: `bisellium-patron-receipt/v1\n` then `JSON.stringify([v, petitio, question, option, mode, charter_gap, nonce, at])`, UTF-8.

**`questionDigest(body: string): string`**: sha256 hex of the petitio body (front matter excluded) before the answer's stamp, trimmed.

**`receiptProblem(receipt, policy, facts, now, usedNonces): string | undefined`**: the first of key, signature, nonce, binding (petitio, question, option, mode, charter_gap) and time that fails, by message, or undefined.

**`takeAnswerLock(root: string): { release: () => void } | { error: string }`** (r5): creates `timeline/.answer.lock` (`ANSWER_LOCK`) by an exclusive create holding the owner's pid, inside the timeline `ensureRealDirectory` returns; `release` removes it at the path `ensureRealDirectory` returns again, and the caller calls it in a `finally`; a lock already there, or one that cannot be created, is `{ error }`. Never a takeover.

**`patronStamps(body: string, patronId: string, receipts: ReadonlyMap<string, unknown>): Stamp[]`** (r5, a seam change for W-668): the Patron stamps of `body` in body order, each `{ at, index, line, reply, suffix }`: `index` the offset of its leading blank line, `line` its first line, `reply` its exact reply (brief:62: a signed stamp's option, else the text to the next Patron stamp or the body's end, whitespace at the body's end dropped) and `suffix` the text after a signed reply that is neither the next Patron stamp nor whitespace at the body's end (`""` when none). `stampedReply` is removed: a stamp's reply is `reply`. **`unsignedDigest(entries: readonly { where: string; at: string; reply: string }[], patronId: string): string`** (r5): sha256 hex of the brief:63 entries, sorted, joined by line feeds.

**`readPetitioReceipts(root): { records: PetitioReceipts[]; problems: SourceProblem[] }`**: every `.md` entry of `petitiones/`, sorted, as `{ where, id, body, receipts }`, and one problem per source that does not read. **`spentNonces(timeline, records): Set<string> | { error }`**: the spent nonces, or the first source error.

**`answer --receipt <path>`**: new optional flag; required when `bisellium.yml` names `patron_receipts.keys`, refused when it names none.

**`POST /api/answer`**: new optional body field `receipt` (an object).

**`bisellium.yml`**: new optional key `patron_receipts: { keys: [<base64 SPKI DER>, …], floor: <64 hex> }`.

**Petitio front matter**: new optional key `receipts: { <stamp instant>: <receipt> }`.
