## Intent

Session 58's read found the spec loop paying for its shape. After this opus:

1. **F3a, path check at sign.** The signer's spec verdict refuses a brief whose Files owned bullet's path slot (its first backticked span, `ownedPathSlots`) is not an existing file of the repository, an existing directory written with a trailing `/`, or marked `(new)` right after the span.
2. **F3b, delta rule.** Each signature log pins `# contract:`, one digest per contract section (Promise/Intent, Behaviours, Input domain, Interfaces, Limits/Defaults, the Files owned path set, and `other`), computed by the writer from the brief it pins. While `studio/bisellium.yml` says `spec: { delta_review: on }`, a re-signature whose digests equal those of the signature a passed (or design-keeping) review read stands with that review: no new review, and no reset of D-061 §4's failed-round count. Anything unclassifiable orders the review. `off`, missing or malformed is master's ladder; the check rule `spec.delta_review` makes a missing or malformed key, or an open escape while `on`, loud (D-246 item 2).
3. **F4a, `verdict --check`.** The verb runs every validator the write runs, reads the step ticket without claiming it, writes nothing and prints what it would write; the real write still validates everything. The guard lets the main thread run it.
4. **Item 5, 200k handoff.** `CONTEXT_WIND_DOWN` drops from 300k to 200k, so the dispatch hold next already has (W-430) holds at 200k, and the UserPromptSubmit hook opens its context with a `CONTEXT HANDOFF NOW` line at every prompt while a fresh status line reads 200k or more.
5. **Stale gate (b5).** A gate log admits build review only when committed strictly after the newest red (git ancestry). A red committed at the current source tree admits only full gates committed after it; before a passed review, a failed full-gate log at the tree refuses the light gates in any commit order (W-503, W-531). Only a full pass at that tree or a changed source tree cures either. `gates.ok || light.ok` no longer admits by tree alone.
6. **Measure (b6, D-246).** `retro --daily` prints the D-246 measure, the qa-lead's; it extends `reviewRounds` (retro.ts); no new script.
7. The code-owned texts ride this branch: D-245 items 2, 3 and 5 in `studio/leges/production.md` and `studio/prompts/spec-review.md`, and D-245 and D-246 themselves.

The seams this changes, each with its reason: the spec log grammar gains `contract` (`VERDICT_HEADERS`): digests are written by the tool, never claimed; `reviewedSpec` and `failedSpecReviews` read it, because that is where a re-signature is classified; the light-gate log gains line 4, `head: <oid>`, because a rerun at an unchanged tree must be a change git can commit (else the perform holds `could not commit`); admission still reads lines 1-3; `bisellium.yml` gains `spec.delta_review`, because D-246 item 2's switch-off must be one visible line, never a revert. Threat model: mistakes, not adversaries (D-045).
