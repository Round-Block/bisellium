## Intent

W-571 made `verdict` judge the Codex session behind a sessioned verdict whose `--model` the manifest seats on the codex harness. Which models are Codex's is read from `bisellium.yml#sellae` by `codexModels`, and it read every `harness` string other than exactly `codex` as "not the codex harness". So one typo in the manifest (`harness: Codex`, `harness: " codex "`, `harness: ""`, `harness: codx`) took the Codex model off the codex harness, `verdict` skipped `sessionRan`, and a blind Codex session's PASS was recorded. This opus closes that: a `harness` is absent (claude-code) or exactly one of the harness ids the registry knows (`HARNESS_PROFILES`' own keys: `claude-code`, `codex`, `fake`, `git-only`), and any other string on any row makes the manifest unable to classify, so a sessioned verdict is refused (exit 2) before anything is written.

1. **`codexModels` refuses a harness string that is not a known id (behaviour 1).** Before a row is classified, a `harness` that is present and a string must be an own key of `HARNESS_PROFILES`, matched as written: no case folding, no trimming, never an inherited property name such as `constructor` or `__proto__`. Every other string returns `{ error }`, and `runVerdict`'s existing refusal (W-571) prints it and exits 2. The rest of W-571's rule is unchanged and pinned again: `sellae` a list of mappings, a non-string `harness` refused, a `harness: codex` row's `model` a nonblank string.

**Every reader of a manifest harness or model** (`census-harness.py` at the prototype tip, `census-harness.out`, 99 read sites, none unmapped). Three decide a review record and each refuses this domain: `codexModels` (closed here; its one caller is `runVerdict`, `verdict.ts`), the UI seat gate in `verdict.ts` and the spec-reviewer gate in `next.ts` (each requires one exact harness id and model, so any other string fails closed). Ten read the harness for dispatch, probing or display and record no verdict (`talk`, `probe`, `tick`, `hooks`, `check`'s roster and liveness advisory, hook liveness in `@bisellium/shim`, `liveReplacementFor`, the serve roster and the web roster) and `spec-seats` reads a model to compare two seats: each is a stated limit (Limits). Eight read a field of the same name that is not the manifest's (a receipt, a probe record, Codex's event stream, an HTTP body).

### Input domain

**The rule (the reviewer's text): `sellae` is a list of mappings, each harness absent (meaning claude-code) or an id accepted by resolveHarness/HARNESS_PROFILES, and each `harness: codex` row has a nonblank string model; `codexModels` refuses a blank or unknown harness string before classification, exit 2 before any write.** "Accepted" is read as an own key of `HARNESS_PROFILES`: `resolveHarness(id)` is `HARNESS_PROFILES[id]`, which also returns an inherited property for `constructor` or `__proto__`, so the check is `Object.hasOwn`, not `resolveHarness(id) !== undefined` (`mutant-resolve-inherited.patch`). A rejection fails closed: the verdict is refused (exit 2) and nothing is recorded from it; the limits are exactly those the rows state.
