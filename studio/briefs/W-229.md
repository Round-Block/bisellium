## Intent

Decree family: verdict-writer-reader-parity

`parseVerdictLog` (`packages/commands/src/verdict.ts:245`) is the one parser of a verdict log, and its readers refuse the whole log on any line out of its grammar. The writer applies it only to a sessioned verdict (`sessionedProblem`, `verdict.ts:695-701`). A sessionless one passes only `findingsProblem` (`verdict.ts:67`), which accepts any numbered line carrying `check:`. Architect signatures carry no session, so on 2026-10-11 W-221, W-181 and W-169 were signed with findings like `1. Census widened … check: none: …`, written with exit 0, and refused by `next` (`readSpecSignature`, `packages/cli/src/next.ts:216`). They had to be signed again (W-221-spec-7, W-181-spec-8, W-169-spec-12).

The writer/reader pairs, from `pairs.txt`:

| Log kind | Writer's check today | Strict reader (parses with `parseVerdictLog`) | Pair |
|---|---|---|---|
| Architect spec signature, sessionless | `findingsProblem` | `next` `readSpecSignature` (`next.ts:216`, when `spec_reviewer` is set; without it `signedSpec` reads headers only); `retro --opus` `readOpusVerdicts` (`retro.ts:548`) | open: W-229 closes it |
| Configured spec review, sessionless | `findingsProblem` | `next` `readSpecReview` (`next.ts:227`); `retro --opus` | open: W-229 closes it |
| Build review, non-UI, sessionless | `findingsProblem` | `readBuildRounds` → `parseBuildReviewLog` (`verdict.ts:840`), from `next.ts:479` and `lifecycle.ts:1701`; `retro --opus` | open: W-229 closes it |
| UI spec input (`ui-lead`) | `substantiveUiTranscript` (`verdict.ts:561`) | `authoritativeUiInput` re-runs `substantiveUiTranscript` (closed); `retro --opus` parses it (open) | open: W-229 closes it |
| UI build verdict | nonblank `## UI input disposition` only | `readBuildRounds`; `retro --opus` | open: W-229 closes it |
| Any sessioned verdict | `sessionedProblem` → `parseVerdictLog` | `readSequence` (`verdict.ts:342`), `reviewRounds` (`retro.ts:674`) and the readers above | closed |
| Handoff verdict, sessionless | `findingsProblem` | none: header block only | no pair (Default 1) |
| Red log `ci/reds/<id>/NN.log` | `red` writes every header byte itself | `check` `opus.red_evidence` reads `exit`, `tree`, `sella` | not this class: no caller-written grammar |

`check` has no verdict-log reader (`pairs.txt`, last section). W-229 closes the five open pairs at the writer, with the reader's own parser.

Promise readable-at-write: every spec or build verdict `verdict` writes, sessioned or not, of any opus kind, is accepted by `parseVerdictLog` exactly as written — limit: syntax only; what a reader judges beyond the grammar stays with that reader (a signature's design magister, `passed` and no standing blocker; the reviewer's model and outcome agreement; the brief pin; the censor), so a log can parse and still not count, as today.

Promise history-readable: no committed log changes, and `readOpusVerdicts` (`retro --opus`) reads a committed spec log that `parseVerdictLog` refuses by its header block alone when it meets every `legacySignature` predicate (Interfaces); the thirteen in `history.txt` all do — limit: such a log contributes a source but no findings to the triage; `next` is unchanged: with `spec_reviewer` set, `readSpecSignature` refuses it as a signature, and without it `signedSpec` (`next.ts:280`) accepts a passing design-magister spec log by its headers, free-form or not, as today.

Promise no-new-free-form: `verdict` writes no new spec or build log `parseVerdictLog` refuses (behaviour 1, whatever its `# at:`), and `readOpusVerdicts` exempts only a refused log meeting every `legacySignature` predicate: a `<id>-spec-<n>.log` name, `# opus:` the opus, `# phase: spec`, `# sella:` the declared design magister and not `ui-lead`, no `# session:`; any other refused review or spec log still refuses the retro — limit: a committed or hand-written (never by hand) log meeting the predicates is read without findings; unchanged readers still read some logs without the parser, as today: `signedSpec` (the gate with no `spec_reviewer`) by headers, `readSequence` a sessionless last round by headers (`verdict.ts:341`), `reviewRounds` a sessionless log by headers (`retro.ts:672`), and `readOpusVerdicts` reads no handoff log (`retro.ts:548`).

The threat model is mistakes, not adversaries (D-045).

The text parsed is the text a reader decodes from the bytes written (`Buffer.concat([header + "\n\n", transcript])`, read back as UTF-8). Accepted bytes are written unchanged: no normalization. `findingsProblem`, `substantiveUiTranscript`, the UI disposition check and `sessionedProblem` run first, unchanged, so their messages win where they apply. No exported signature or flag changes.

In `packages/cli/src/retro.ts`, `readOpusVerdicts` keeps every refusal except one (behaviour 2):

```ts
/** W-229: a sessionless design-magister spec log parseVerdictLog refuses (only the pre-W-229 writer let one through) is read by its header block alone. */
function legacySignature(root: string, id: string, prefix: string, name: string): boolean {
  if (prefix !== `${id}-spec-`) return false;
  const magister = designMagister(root);
  if (isRefusal(magister) || magister.design === undefined) return false;
  const file = readContainedRegularFile(root, `ci/${name}`, "ci", LOG_MAX_BYTES);
  if ("error" in file) return false;
  const h = headerBlock(file.bytes.toString("utf8"));
  return h.get("opus") === id && h.get("phase") === "spec" && h.get("sella") === magister.design && h.get("sella") !== "ui-lead" && !h.has("session");
}
```

and in its loop: `if (isRefusal(read) && !legacySignature(root, id, prefix, name)) return read;`, then the source is pushed and `findings` gains `read.findings` only when `read` is not a refusal. `designMagister` (`retro.ts:612`) and `headerBlock` (`retro.ts:601`) are the existing readers `reviewRounds` uses; `parseVerdictLog` is not changed, and `readOpusVerdicts` bypasses it for no other log. The `ui-lead` exclusion mirrors the writer, which attributes every UI spec log to `ui-lead` (`verdict.ts:534-535`).

### Input domain

Every rejection fails closed: `verdict` exits 2 and writes nothing, and `ci/` is not created when it was absent; `retro --opus` exits 2 and writes nothing.

| Record | Valid domain | Rejected by |
|---|---|---|
| A spec or build verdict's whole log (header + blank line + transcript), any kind, sessioned or not | `parseVerdictLog` accepts it, exactly as its readers call it (`verdict.ts:245-289`; for a log with `# session:`, `readExchange` at `verdict.ts:196-236`). W-229 restates none of that grammar | `runVerdict`: prints `parseVerdictLog`'s error and returns 2 before `ensureRealDirectory` |
| A non-UI or handoff transcript | One nonempty Findings section; every numbered finding names `check: <text>` | `findingsProblem`: unchanged, before the parse |
| A UI spec transcript | Findings, Recommendation, `Verdict:` line, substance and prompt comparison; the whole log is then also accepted by `parseVerdictLog` | `substantiveUiTranscript`: unchanged, before the parse |
| A UI build transcript | A nonblank `## UI input disposition`, in a log `parseVerdictLog` accepts | `runVerdict`: the existing disposition refusal, then the parse |
| A sessioned verdict | Outcome exactly `passed` or `failed`, agreeing with what stands; the previous round's blockers accounted for | `sessionedProblem`: unchanged; the new parse then re-accepts its log |
| A sessionless handoff transcript | Passes `findingsProblem` | limit: not parsed at write; no strict reader reads it (Default 1) |
| A committed review or spec log `parseVerdictLog` refuses, read by `readOpusVerdicts` | Only a spec log meeting every `legacySignature` predicate (`<id>-spec-<n>.log`, `# opus:` the opus, `# phase: spec`, `# sella:` the design magister and not `ui-lead`, no `# session:`): read by header alone, no findings | `readOpusVerdicts`: any other refused `<id>-review-<n>.log` or `<id>-spec-<n>.log` (another sella or `ui-lead`, a `# session:`, a review name, no or a malformed design collegium, an unreadable file) refuses the retro, as today; handoff logs are not read here, as today |
| `bisellium.yml#collegia`, the design row `legacySignature` reads | Zero or one `design` row, its magister a nonempty string | `designMagister`: a duplicate or blank-magister design row is a refusal, `legacySignature` then returns false and the parser's refusal stands |
| Committed logs, read by every other reader | Unchanged bytes, unchanged readers | limit: each reads as today: `readSpecSignature`, `readSpecReview` and `readBuildRounds` refuse a log `parseVerdictLog` refuses; `signedSpec`, `readSequence` (a sessionless last round) and `reviewRounds` (a sessionless log) read headers only and never call the parser on it |
| W-229's test fixtures (fresh officinae, transcripts, seeded logs) | Present and as written by the row | `test` (node:test): a missing or malformed fixture throws in the row, which fails `npm test` |

## Out of scope

- Rewriting, normalizing or backfilling a committed log; making any reader but `readOpusVerdicts` more lenient; triaging the findings of a free-form signature.
- Moving reader semantics into the writer: who may sign, outcome agreement for sessionless logs, the brief pin, the censor.
- Requiring `--session` on signatures; a new check rule; a second grammar.
- The body cap, citation conversion, the UI digest, the review gate, retro measurements.

## Defaults for the Patron to veto

1. **Sessionless handoff verdicts are not parsed at write**, since no strict reader reads them. On a veto the condition goes and every verdict is parsed; the census shows no extra fixture breaks.
2. **Malformed input is refused, never repaired.** Whatever `parseVerdictLog` refuses, `verdict` refuses (exit 2, the parser's own message); what it accepts is written byte for byte.
3. **Syntax only.** A parseable signature that `next` still will not count (an architect `revise`, a standing blocker) is written as today.
4. **The retro exemption keys on the header, not a date.** A sessionless design-magister (not `ui-lead`) spec log the parser refuses is read without findings by `readOpusVerdicts` whenever it was written; `verdict` can no longer write one. On a veto, a cut-over is added (`# at:` before W-229's merge), which a hand-written log can still state.
