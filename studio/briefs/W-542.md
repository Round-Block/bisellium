## Intent

The W-364 guard's `writeRefusal` (`packages/cli/src/guard.ts`, the W-290 rule, called from the one Write, Edit and NotebookEdit branch of `guardRefusal`) refuses a subagent only a decision or handoff write by a non-clerk. Its source, test and dossier rules bind the main thread only. So a dispatched clerk's Write already reaches source, tests, `studio/opera/` front matter and `studio/ci/` logs, records the bisellium verbs own. The leads' meet found this gap while ruling that the clerk gets Edit: Edit opens nothing Write does not, but it makes a one-line hand edit of a record cheaper. This opus closes the gap with a guard rule and, in the same PR, gives the clerk Edit.

1. **The rule (behaviour 1).** A hook input with a string `agent_id` and `agent_type` exactly `clerk` that calls Write, Edit or NotebookEdit on a path in a git checkout is refused unless the path, relative to that checkout, is under `studio/acta/`, `studio/decisions/`, `studio/lessons/` or `docs/` (not under `docs/design/dossier/`), or is `studio/queue.yml`. A path in no checkout is not judged, as today. The main thread's and every other subagent's writes keep the rules they had (Promise others-unchanged). `CLAUDE.md` (through `instructions.ts`, which generates it) and `docs/INSTRUCTIONS.md` name the new refusal beside the guard's others.
2. **The clerk agent (behaviour 2).** `.claude/agents/clerk.md` gets Edit (no Bash), one line on Edit and Write, its roots and the CLI's records, and loses the `run:` line it cannot run (it has no Bash). Row `W-542-b2` reads the real agent file and holds its roots to the guard's `CLERK_ROOTS`, so the text and the rule cannot drift apart.

**Two roots added by name, beyond the meet's four.** The meet's roots were `studio/acta/`, `studio/decisions/`, `docs/` (not the dossier) and paths outside the repo; eng-lead's answer named its change-my-mind case: "a case where the clerk must Write a file the guard rule above would refuse". The census (`clerk-census.sh` over the 74 kept clerk briefs in `~/.bisellium-evidence/`, `clerk-census.out`) found two:

- `studio/queue.yml`: the ranked queue, edited by a clerk in at least six dispatches (`queue-1106/clerk-brief.md` and `-2`, `-3`, `-6`, `calls-meet-1107/clerk-brief-5.md`, `audit-1105/clerk-brief-d181.md`, `file-1024/clerk-d111.md`, `records-1029g/clerk-d133-brief.md`, `filings-1108/clerk-brief.md` §3). No verb writes it. One file, named exactly, so `studio/queue.yml.bak` stays refused.
- `studio/lessons/`: `addressed_by` stamps on lessons (`filings-1108/clerk-brief.md` §4, the 11-08 owed filings). `retro` writes a lesson when it is created, and no verb writes the stamp later; `check`'s `lesson.addressed_by` judges it.

**Census paths the rule refuses, on purpose (each a stated limit).**

- `studio/opera/<id>.md`, front matter or body (`W-500-spec/defer-clerk-brief.md` appended a body note): the meet ruled opera records are the CLI's. A body note goes through a verb (`amend`, `halt`, `conclude`) or a builder.
- `studio/leges/` and `studio/prompts/` (`calls-meet-1107/clerk-brief.md`, `codex-chromium-probe/clerk-d105-brief.md`, `filings-1108/clerk-brief.md` §1-§2): the lex and the prompt templates are code-owned process text, and `studio/prompts/` holds the reviewers' own instructions (W-302). An opus carries them, as W-541 carried the 11-08 draft. Default 2 asks the Patron.
- `studio/briefs/`, `studio/bisellium.yml`, `.claude/`, `CLAUDE.md`, source and tests: the census names them only as things to read.

**Where handoff records live, and whether the rule allows them.** The session handoff is `docs/SESSION-HANDOFF.md`, in the main checkout or in a records worktree (`.worktrees/records-*/docs/SESSION-HANDOFF.md`, 30 census lines). Both are under `docs/` in their own checkout, so they are allowed. The lane state and handoff notes under `~/.bisellium-evidence/` (`current-state.md`, `handoff-*/`) are in no checkout, so they are allowed. An opus's traditio (its handoff) is opus-record front matter, written by `bisellium handoff`. It stays refused to a clerk, as every opus record does.

**Facts checked, against the brief.**

- *How the guard knows the writer is a clerk*: `guardRefusal` reads `main` as "no string `agent_id`" (Claude Code sets it only in a subagent, D-073 B), and `clerk` as `!main && input["agent_type"] === "clerk"`, the subagent type Claude Code puts in the hook input. Both readings are reused unchanged. An input with `agent_type: "clerk"` and no `agent_id` is the main thread, as W-310-b3 already pins. A general-purpose or untyped subagent is not a clerk and keeps today's rules.
- *How a path outside the repo is decided*: `writeRefusal` resolves the path against the input's `cwd`, normalises `..` (`resolve`), and resolves symlinks through the longest existing prefix (`realOf`). It then judges the path relative to the nearest ancestor holding `.git/HEAD` or a `.git` file (`checkoutOf`). So a linked worktree's `studio/opera/` is an opera record in that worktree. A folder under `.worktrees/` with no `.git` file is judged in its parent checkout, where `.worktrees/...` is under no root. A symlink outside the repo that points into it is judged at its target. Any other git checkout (a scratch copy, another project) is judged by the same roots, relative to itself. "Outside the repo" therefore means outside every checkout. This is stricter than the meet's words, and it is the reading `writeRefusal` already gives the main thread.
- *Write and Edit share `writeRefusal`*: one branch (`tool === "Write" || tool === "Edit" || tool === "NotebookEdit"`) reads `file_path` or `notebook_path` and calls it. `GUARDED_TOOLS` and the repo's PreToolUse matcher cover the same four tools. NotebookEdit gets the rule with no change. The clerk's tools line does not grant it.
- *Existing rows that pin a clerk's writes as allowed*: `W-310-b3` (`packages/cli/src/guard.test.ts`) lets a clerk write `studio/decisions/D-999.md`, `docs/SESSION-HANDOFF.md` and `.worktrees/W-1/studio/decisions/D-1.md`. All three are under the roots, so the row does not flip. No other row feeds a clerk hook input (`grep -n agent_type` over every test file).
- *D-150 B* (a new process rule binds only opera started after it merges): this is a hook refusal at a tool call, not an opus gate. No opus's records, ladder or evidence are judged by it. It binds every clerk dispatch once the Patron's installed `bisellium` (the Patron's clone at master) holds it, whichever opus the dispatch serves. No opus in flight depends on a clerk writing an opus record or a ci log.
