## Intent

Decree family: dossier-pages-are-records

The Patron vetoed W-203's Default 1 (2026-10-10). A done or retro PR edits `studio/`, the handoff and dossier pages that `docs/design/dossier/build.sh` rebuilds, and today the pages send it down the full CI path (~31 min). W-209 makes the pages records.

Promise records-path: a change whose paths are all under `studio/`, are `docs/SESSION-HANDOFF.md`, or are HTML pages directly in `docs/design/dossier/` takes the records-only CI path wherever the scope step runs (a merge group, and a pull request until W-205) — limit: an empty, mixed or unreadable delta takes the full path, and so do a page in a subdirectory, a non-HTML file there (`build.sh`, `build-arch.mjs`) and every other generated page (`docs/design/queue-review/`, `docs/design/canvas/`).

Promise ci-page-readers: each page check a `ci.yml` step runs also runs on the records-only path: `checkDossierShrink`, inside `check -- studio --repo .` (in `gates` and in `officina`), and `test:record`, which holds the five test files that read them through the preload's wrapped calls (`census-w209.txt`), a list W-139's guard checks over the enlarged set — limit: the guard logs only reads by test-owned node processes during the full `npm test` through the 18 wrapped calls (`readFileSync`, `readdirSync`, `existsSync`, `statSync`, `lstatSync`, `openSync`, `opendirSync`, `createReadStream`, `cpSync`, `copyFileSync`, and `readFile`, `readdir`, `stat`, `lstat`, `open`, `opendir`, `cp`, `copyFile` in callback and `fs.promises` form). A test that reads a page only through an unwrapped call (`openAsBlob`, `access`, `exists`, `realpath`, `readlink`, `statfs`, `watch`, `watchFile` or `glob`, sync or promise form) or through a child that is not node (git, a shell) is not logged, so it could stay out of `test:record` unnoticed (`r3-preload-coverage.txt`); the full path's sample-studio check runs the same `checkDossierShrink` again, and the records-only path does not; the page generators, `build.sh` and `build-arch.mjs` (run by `bisellium close` or by hand), read the pages but run in no CI step and no test, today and under W-209 (`r2-measure.txt` F2).

Promise source-boundary: once the producer's manifest line lands, a commit that changes only `studio/` and listed pages has its parent's SOURCE identity, and a path the list does not name stays SOURCE — limit: the handoff stays SOURCE, so a checkpoint that edits it still moves the identity; a new page stays SOURCE until a records PR lists it; the list is trusted as written, since `readSourceExcludes` and `check` accept any non-empty entry, so a wrong entry such as `packages/` would exclude what it names, as on master today (`r2-measure.txt` F1, Defaults 4); landing the line moves the identity of each tree that holds a listed page (every commit since ae03d0f, 2026-09-18) and of no tree that holds none (`r2-measure.txt` F3).

No check is removed (production lex §11, D-054 §1): no workflow step, `test:record`, guard or check rule changes. The records-only path still runs the studio check and `test:record`; the full path still runs everything. The threat model is mistakes. ## Defaults for the Patron to veto

1. **The pages are listed by name; `source_excludes` gains no patterns.** No certificate code changes. A new page is CI-records at once but stays SOURCE, and so certified, until a records PR lists it. That is the safe direction. The rejected alternative is the draft's `*` matching. It changes two hash implementations, one of them the host-owned receipt hasher, and it changes the hash definition inside W-209's own source change.
2. **The producer lands the line in its own records PR on master, while no opus is between `branch` and `done`** (after W-196 is done, and before W-209 or W-205 branches). It cannot ride on `opus/W-209`, because `buildReviewDrift` holds `next` (`r2-measure.txt` F4). If the Patron vetoes the timing and the line lands at any time, an opus in flight is held by the same drift until it rebases. It then re-verifies, and its `done` certificate is judged under the new list.
3. **Only direct HTML in `docs/design/dossier/` becomes a record.** `queue-review.html` and `DIRECTION.md` each appear in one of the 40 records PRs, and canvas pages in none (`census-records-prs.txt`). They stay source until a ruling names them.
4. **The list's content is not pinned.** As on master today, `readSourceExcludes` and `check` validate only the shape, so the producer's records PR is the only guard on what the list names (`r2-measure.txt` F1). On a veto, a follow-up opus adds a narrow pin, for example a `test:record` row that compares the list with `examples/` plus the directory's pages. That row would also catch a new page left unlisted.
