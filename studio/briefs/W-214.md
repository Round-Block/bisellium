## Intent

Today each finished opus pays two records PRs: the done PR (`next <id> --perform --expect done`, twice: commit on `chore/done-<id>`, then land) and a separate checkpoint PR carrying the dossier's history row and masthead. W-302 is the latest: done #523 (the record, verify's logs, the handoff), then checkpoint #524 (`progress-body.html`, `body.html` and the rebuilt pages). Each records PR costs a merge, a CI run and an orchestrator turn, about 10 to 15 minutes (D-075 ranks this opus second for it).

The code already lets the checkpoint ride. `performDone` stages any tracked change that `recordOnly` (`scripts/ci-scope.mjs`) calls a record: the handoff and the HTML pages directly in `docs/design/dossier/` (W-209, W-243; `W-243-b2` proves a dossier page rides). The landing guard, certify and the CI scope read the same list. `verify` already ignores the dossier pages: they are in `studio/bisellium.yml`'s `source_excludes` (W-209, pinned by `W-211-b1`). What is missing is the requirement: `done` refuses without a handoff edit, but not without the history row, so the row keeps arriving in a PR of its own.

After this opus, `next --perform --expect done` (the commit perform) refuses, before it cuts `chore/done-<id>` and with no tracked file changed, while master keeps `docs/design/dossier/progress-body.html` and the working tree adds no line naming the opus id to it. The refusal reads `refusing: the checkpoint rides the done commit, and docs/design/dossier/progress-body.html adds no history row naming <id>; add it, then re-run`. With the row added, the perform commits the record, verify's logs, the handoff, the row and any other changed dossier page as one commit, which lands as one records PR. Measured as records PRs per finished opus: baseline 2, target 1, first read at W-214's own done.

W-257 and W-192 are carried. W-257 is this requirement. W-192 asked that verify run before the checkpoint's docs edits or tolerate them: verify tolerates the dossier pages already (W-209; `verify-tolerance.out`: an edited `progress-body.html`, `body.html` or `status-body.html` is not dirty to verify, an edited handoff is), so the history row and masthead may be written while verify runs; the handoff is still written after verify (Out of scope, Defaults 3).

Threat model: mistakes, not adversaries (D-045). A row is any added line naming the id; the rule does not judge what the row says.

## Interfaces

`const HISTORY = "docs/design/dossier/progress-body.html";` beside `HANDOFF`.

`historyRowRefusal(repo: string, id: string): string | undefined`, reads only:

1. `git ls-tree -z --name-only refs/heads/master -- <HISTORY>` in `repo`. A spawn error or a non-zero exit returns `master's tree cannot be read: <one line>`. Empty output (master does not keep the page) returns `undefined`: no requirement.
2. `git diff --no-ext-diff --no-textconv --no-color --unified=0 refs/heads/master -- <HISTORY>` in `repo` (the working tree, staged or not, against master). A spawn error or a non-zero exit returns `could not diff <HISTORY>: <one line>`.
3. The added lines are the lines after the first line starting `@@` that start with `+` (so the `+++ b/<path>` header is never read). If one of them matches the id as a whole token, `(?<![\w-])<id>(?![\w-])` with the id regex-escaped (`esc`), it returns `undefined`. Otherwise it returns `the checkpoint rides the done commit, and <HISTORY> adds no history row naming <id>; add it, then re-run`.

`performDone` calls it after the handoff check and, when it returns a reason, returns `heldResult` with `refusing: ` and that reason. The order of the holds before it (main checkout on master, the dirty-tree hold, the verify hold, the handoff hold) is unchanged; the branch is cut only after it.

What counts as the opus's row: `W-900 shipped` and `<strong>W-900</strong>` do; `W-9000`, `W-901` and `W-900-x` do not; a deleted page adds no line, so it is refused. A row that names the opus in another sense (a line that only mentions it) also passes: the rule checks presence, not content. The requirement follows the repository's master, as the handoff requirement does: in this repository it applies to an opus of `examples/sample-studio` too.

### Input domain

A rejection fails closed: the perform holds (`next: <id> done held`, exit 1) before `chore/done-<id>` exists, with the main checkout's HEAD, master, index, tracked files and branches unchanged (the step marker and log under the ignored `.bisellium/` are written as for any perform). A test row whose fixture write fails throws, which fails the row.

| Record | Valid domain | Rejected by |
|---|---|---|
| Master's tree entry for `docs/design/dossier/progress-body.html`, read by `git ls-tree` in the main checkout | readable; present (the rule applies) or absent (no requirement) | `historyRowRefusal`: a spawn error or non-zero exit is the reason `master's tree cannot be read`, held by `performDone` |
| The working tree's change to that page against master, read by `git diff --unified=0` when master keeps it | an added line naming the opus id as a whole token | `historyRowRefusal`: no such line (no change, other ids, a deleted page), a spawn error or a non-zero exit is a reason, held by `performDone` before the branch is cut |
| The fixture repository `W-214-b1` runs in, built by the existing helper `world()` and edited by `put`, `commit`, `appendFileSync` and `rmSync` | a git repository whose master keeps the history page and the masthead | `world()` (existing test helper): its `git`, `put` and `commit` throw on a failed write or git call, as do `appendFileSync` and `rmSync` in the row, which fails the row |
