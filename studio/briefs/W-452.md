## Intent

Today one seat signs every non-UI spec: the design collegium's magister (`architect`), with `spec_reviewer` (Codex `gpt-5.6-sol`) reviewing it; a `kind: ui` opus has the D-091 pair (`ui_spec_signer`, `ui_spec_reviewer`). D-129 A rules that the collegium lead signs its specs, and D-150 C sets the seats: engineering's specs are signed by the Opus 5.5 `architect`, which leaves design for engineering, and reviewed by Codex Sol; design's by one design lead on Codex Sol and reviewed by Claude Opus 5.5. D-129 C adds `ladder-lead` (Claude Opus 5.5) for production. D-150 B: only an opus started after the rule merges takes the new seats.

**This slice (decided).** The whole of D-129 E and D-150 C is more than one brief (`amend --collegium`, retiring `kind: ui`, routing the UI lane and its ui-lead input, the UI build reviewer, filing, the lex amendments). This opus is the first slice the dispatch names: the seat ids, the manifest's seats, and the signer and reviewer that `next` and `verdict --phase spec` name, with the old-seat carve-out. The rest is Out of scope, as named follow-ups.

**The setting (decided).** A new optional key `spec_seats: { since: <instant>, collegia: { <collegium id>: { signer: <seat>, reviewer: <seat> } } }`, read by one function, `readSpecSeats` (new `packages/commands/src/spec-seats.ts`), that `next`'s `readSpecReviewer` and `verdict` both call, so they name one signer. Absent, nothing changes: every officina without it (the sample studio, every fixture) keeps today's routing. Present, an opus is routed by its record's `collegium`: its spec is signed by the row's `signer` and reviewed by the row's `reviewer`, on the reviewer seat's own declared model. A row's seats must be two different declared, live, `kind: agent` seats, each declared once, on different models (D-150 C: one writes, another checks); the signer must be a seat of the collegium the row is keyed by (its `sellae` entry's `collegium`), while the reviewer may belong to any collegium. Every other form is an error. Every `verdict --phase spec` path, including the UI-lead input path, invokes `readSpecSeats`; when it returns an error, `next` holds at spec and `verdict` exits 2 before writing.

**The carve-out (decided, D-150 B).** An opus whose spec sequence began before `since` keeps today's seats: when any `ci/<id>-spec-<n>.log` of the checkout that owns its spec evidence carries a `# at:` earlier than `since`, the routing is today's (the design magister, `spec_reviewer`, the UI pair). An opus with no spec log yet, or whose logs are all at or after `since`, takes its collegium's seats. A spec log that cannot be read, or whose header holds no single `# at:` instant, holds (every one of the real studio's 915 spec logs carries one). So `since` needs no per-opus list and no new record field. A `kind: ui` opus keeps the UI pair whatever its logs say: the UI lane's routing is its own slice.

**The design lead's UI ruling (decided, Patron 2026-11-01).** A `kind: ui` opus's screens are ruled by a structured decision its record lists in `ui_rulings`; today `ruling` (`opus-model.ts`) accepts one only with `by: patron`, so the design lead's rulings (D-152, D-153) had to be recorded as the Patron's. A ruling now also counts with `by:` the seat `uiRulingSeat` derives from the manifest: `spec_seats.collegia.design.signer`, when it names one declared, live `kind: agent` seat of the design collegium. Every other field the reader asks of a ruling is unchanged (`provenance: stated`, `opus`, `certifies`, `design_digest`, `at`, a body). The Patron keeps control: the manifest is code-owned, so only a merge the Patron makes names the lead, and a `by: patron` ruling is judged by the same test as today, so D-152, D-153 and every existing ruling stand (Promise seats-ruling). An officina with no `spec_seats`, or one whose design signer is not such a seat, or whose manifest cannot be read, accepts only `by: patron`. The refusal message is unchanged (`<id> is not a structured Patron UI ruling for this opus`); the waiting `why` in `next` still names `by: patron` as the form the clerk writes, a limit. This is not D-150 B's carve-out: it is the Patron's delegation, so it binds every UI opus, in flight or not.

**The seats (decided).** `studio/bisellium.yml` moves `architect` to `collegium: engineering`, declares `ladder-lead` (production, `claude-opus-5-5`) and `design-lead` (design, `gpt-5.6-sol`, codex), and sets `spec_seats`: engineering `architect`/`spec-reviewer`; ops `ops-lead`/`spec-reviewer`; qa `qa-lead`/`spec-reviewer`; production `ladder-lead`/`spec-reviewer`; design `design-lead`/`ui-spec-reviewer`. Engineering's signer stays the seat id `architect` (D-150 C names the Opus 5.5 architect), so an engineering opus is signed by the same seat before and after. The design collegium's magister stays `architect`, and `ui_spec_signer`, `ui_spec_reviewer` and `spec_reviewer` stay, because the carve-out's opera are signed under them; they change in the follow-up that retires them once no opus started before `since` is open. `since` is the instant the builder commits the manifest edit (Defaults 2).
