## Intent

Two ways a failed build round sticks today, both in `deriveNext` (`packages/cli/src/next.ts`).

**An evidence-only fix is never re-reviewed (D-086 B).** Today a round failed at the current source tree and brief pin keeps returning to the builder (build, phase fix). A fix that lives outside the source tree (an acceptance script's kept outputs, a file under a `source_excludes` folder such as `examples/`) changes neither, so the order never moves. W-179's round 1 failed on missing timing evidence (`ci/W-179-review-1.log`); the builder re-measured under `~/.bisellium-evidence/W-179-build/`, and only a brief correction and a fresh signature moved the pin and reached review. After this opus, a non-merge first-parent commit on `opus/<id>` after the commit that last changed the failed round's log is a fix signal when it is empty or names at least one path that is not an officina record (`recordOnly`'s list, the one certify reads: `studio/`, `docs/SESSION-HANDOFF.md`, a page directly in `docs/design/dossier/`); next then names the next review round, the censor's order, with the why "review round <n> failed at this tree and brief; <k> commit(s) after its log are empty or change a path that is not an officina record (D-086 B)". Commits naming only record paths and merges do not count; if intervening source edits are later reverted to the reviewed tree, qualifying commits in that history still count. An empty commit counts: it is how a builder whose kept outputs live outside the repository says the fix is made. Every read this makes fails closed: a log not committed on the branch, or a git read that fails, holds the build rung with its reason, never counts as no fix or as a fix.

**A fix check's open path outside Files owned holds the suite (D-106 A).** W-309's fix check sends every open path back to the builder. W-360's round 1 check (`.bisellium/reviews/W-360/fix-1/check.json`) lists three, in `scripts/review-packet.mjs`, `packages/cli/src/next.ts` and `packages/cli/src/integrate.ts`, none in W-360's Files owned: a builder cannot fix them and must not edit them (engineering lex §2), so W-360 waits. D-106 A rules that such a path never holds that opus's suite. After this opus an open line whose lead names only paths outside the Files owned of the brief committed on `opus/<id>` is the producer's: it prints as one `evidence: <line>` on the suite order and on the review order, and never reaches the builder. With no owned open line, next orders the suite (when the automated gates are not passed at that tree) and then the re-review. With at least one, the builder gets the owned lines only. Ownership is read from the committed branch blob, the brief the spec gate judged, never from the worktree's copy: an edited worktree brief does not change it (a deleted or unreadable one already holds at the reds rung's red-evidence check, unchanged), and a committed brief that is not a readable blob holds before any open line is split.

This decides who acts, not whether (the audit's Risk 5): the evidence line stays on the review order and the reviewer may still block on the path (D-084); the producer may file it, or the architect may widen Files owned.

Promise evidence-fix: when the newest build-review round failed at the current source tree and brief pin, and `opus/<id>`'s first-parent line holds, after the commit that last changed that round's log, a commit that is not a merge and is empty or changes a path that is not an officina record, next names review, the censor's order for the next round, with the why above, and not build phase fix — limit: next cannot see the evidence itself, only a commit (an empty one serves); any such commit counts, whatever non-record path it changes, so a stray edit under a `source_excludes` folder re-orders review too; the class-loop hold (W-297) still comes first; the review round judges the fix (D-066 C).

Promise records-stay: a round failed at the current tree and brief with no such commit after its log (none, only commits of record paths, only a merge of master) keeps the builder's fix order, phase fix — limit: the records are `recordOnly`'s list, reused unchanged; a merge's own changes are never read.

Promise reads-hold: when the failed round's log is not committed on `opus/<id>`, or git cannot read the commit that last changed it or the commits after it, next holds the build rung with a why ending "so the commits after it cannot be counted (D-086 B)" (the uncommitted log's why names it and says to commit it), and orders neither the builder nor review — limit: a hold is the producer's to clear; a git read that fails for a reason outside the repository (a timeout, a spawn error) holds the same way.

Promise unowned-evidence: when the fix check at the current tree lists open lines and none is owned by the brief committed on `opus/<id>`, next names the producer's suite order while the automated gates are not passed at that tree, with "fix-check: no open path in Files owned at this tree (<census>)" and one "evidence: <line>" per open line in the check's order, and then the censor's review order with the same evidence lines; no builder is dispatched — limit: the lines are not added to the review packet; the reviewer may still block on them (D-084), and who fixes them is the producer's call.

Promise owned-builder: when at least one open line is owned, next names build, phase fix, with only the owned lines on its "open:" line, its why counting them, and no evidence line; an edited worktree brief does not change which lines are owned, and a committed brief that `git cat-file blob` cannot read holds the build rung before any line is split — limit: an unowned line on that check is shown again only by the next fix check at the fixed tree; a line whose lead names no `path:line` is the builder's, as before.

Threat model: mistakes, not adversaries (D-045).
