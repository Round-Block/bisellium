## Intent

Add one full-width `Completion` card after W-503's optional `Work in progress` card. The card keeps W-503's dark surface and white heading, shows the served overall percentage at the upper right, and groups one 6px square per planned item under each plain-English milestone title. On the next line after each title, the squares come first and the exact `N of M done` count follows immediately with an 8px gap at every ruled width. Done squares are purple and remaining squares use the neutral `ink-3` outline. With no milestone record, the card is left out and one quiet line says `No completion record is available.` A slow read says `Loading completion…`; a failed read says `Could not load completion.` Neither state hides W-503's already-loaded facts.

This is Completion only. D-234, later than D-175, records the Patron's `Completion only (Recommended)` answer, keeps W-504 as `Home's Completion row (Spend dropped)`, and defers W-439 (`/home/edckt/.bisellium-evidence/W-504-spec/clone/studio/decisions/D-234.md:12`). The old signed 3:2 composition therefore becomes one full-width outcome card; there is no empty right-hand card. Provider readings, current spend and Time do not appear. This follows D-175's no-empty-card ruling (`/home/edckt/.bisellium-evidence/W-504-spec/clone/studio/decisions/D-175.md:25`) and the later cut rather than silently preserving the superseded Spend half.

The Completion source exists on master today: `GET /api/completion` returns the milestone meter from `studio/milestones.yml` and opus records, or `{ meter: null, estimate: null }` when milestone records are absent (`/home/edckt/.bisellium-evidence/W-504-spec/clone/apps/server/src/store.ts:521`, `/home/edckt/.bisellium-evidence/W-504-spec/clone/apps/web/src/api.ts:510`). The endpoint's `overall`, milestone titles and `done` / `planned` values are retained; Home does not recalculate completion or show the endpoint's finish estimate.

The two old Spend reads also exist on master, but not the real-studio data the old composition required. `GET /api/providers` reads current observed provider rows, while this studio has no `studio/usage.yml`, so it returns no rows (`/home/edckt/.bisellium-evidence/W-504-spec/clone/apps/server/src/store.ts:480`, `/home/edckt/.bisellium-evidence/W-504-spec/clone/adapters/native/src/index.ts:588`). `GET /api/aerarium` defaults to the current ISO week; this studio records only 2026-W38 and 2026-W41, so the 2026-W47 draft date has no current spend row (`/home/edckt/.bisellium-evidence/W-504-spec/clone/apps/server/src/store.ts:468`, `/home/edckt/.bisellium-evidence/W-504-spec/clone/studio/aerarium/2026-W38.yml:1`, `/home/edckt/.bisellium-evidence/W-504-spec/clone/studio/aerarium/2026-W41.yml:1`). W-439 would add every period's budget records from usage readings (`/home/edckt/.bisellium-evidence/W-504-spec/clone/studio/opera/W-439.md:1`), but D-234 defers it and drops Spend here. W-504 should ship its honest Completion row after W-503 and should not wait for W-439.

The signed unit-chart treatment comes from the retained Home cut: one square per planned item, purple done units, neutral remaining outlines, exact labels and no angle-based chart (`/home/edckt/.bisellium-evidence/W-451-respec/old-brief.md:27`). The implementation is bounded to the tested fixtures; the real studio's larger meter and arbitrary font, zoom or browser combinations are limits, not promises.
