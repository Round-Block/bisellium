## Intent

W-276 is a delta on W-241 part 1 (`studio/briefs/W-241.md`, signed, landed #476, not built) and builds after it. W-241 part 1 creates `studio/prompts/builder-brief.md` by generalising `~/.bisellium-evidence/W-236-build/builder-brief.md`, and the `process.prompt_templates` rule that checks it. W-276 edits that one file and extends that one rule. The title's `studio/prompts/builder.md` is not created: there stays one builder template (D-042, D-066 D).

Since D-064 C (`studio/bisellium.yml`: `step_tickets: required`) every `red` needs a pending ticket that `next` wrote for that behaviour at the same HEAD. The kept brief says "do not run `bisellium next`", so a builder following it is refused at its first red. The template gains the sequence below and loses that sentence.

No code outside the rule changes. Checked against the code and by a probe on a scratch clone (`W-233-b1`'s fixture, `next` spawned with cwd in the linked worktree):

- `runNext` resolves `--repo` and `--studio` and never reads the process cwd. The linked-worktree refusal tests the `--repo` path, not the cwd.
- In report mode, `refreshTicket` writes the ticket from the ungated `deriveNext`. At `reds` its action is `red` and its round is the first missing behaviour. It is bound by `actionFacts` to the usable `.worktrees/<id>` worktree: studio `.worktrees/<id>/studio`, that HEAD, that brief blob. The ticket is written even when the order is held for a stale handover; the probe's second call printed `next: W-900 reds held` … `ticket: red round 2`.
- `runRed` calls `requireTicket` with the `--studio` it opened. From the worktree with `--studio studio --repo .`, the facts match and the red records. With the main checkout's studio it is refused: `red refused: no matching next ticket (studio is .worktrees/W-900/studio, want studio)`.

## Interfaces

`prompts/builder-brief.md` gains one slot, `<MAIN_REPO>`: the absolute path of the repository's main checkout. The lead fills it. Its per-behaviour order becomes (wording free, the three marked texts exact):

```text
For each behaviour <n>, in order, from <WORKTREE>:
1. commit the behaviour's test, its rows failing;
2. [NEXT] npm run -s bisellium -- next <ID> --studio <MAIN_REPO>/studio --repo <MAIN_REPO>
   Report mode only, never --perform. Go on only if its last line is
   [TICKET] ticket: red round <n>
   for this <n>; any other last line: stop and report the output verbatim.
3. with no commit, checkout or brief edit in between:
   [RED] npm run -s bisellium -- red <ID> --behaviour <n> --sella builder.<ID> --studio studio --repo . -- <cmd…>
   A "no matching next ticket" refusal: stop and report both lines; never retry with other --studio/--repo values.
4. commit the red log alone (studio files only), before any implementation;
5. implement behaviour <n> and commit.
```

`next` takes the main checkout's absolute paths, because `next` refuses a linked worktree as `--repo`. `red` takes the worktree's own `studio` and `.`, because the ticket is bound to the worktree's studio. The old sentence becomes "Do not push, open a PR, mint a receipt, or run `next --perform`; the orchestrator does those."

`checkPromptTemplates` keeps returning at most one `process.prompt_templates` block finding for `prompts/builder-brief.md`. Besides W-241's required texts, it now blocks that template unless all three of these hold:

- it contains NEXT, TICKET and RED exactly as above (the literal `<ID>`, `<MAIN_REPO>`, `<n>` slots; RED through its final space and two hyphens, before `<cmd…>`);
- NEXT's first occurrence comes before RED's first occurrence;
- it does not contain LEGACY: the 20 characters run, a space, a backtick, bisellium, a space, next, a backtick, matched anywhere in the file (it ends at that backtick). Both kept briefs (`~/.bisellium-evidence/W-162-build/builder-brief.md` and `W-236-build/builder-brief.md`) carry it, in the same sentence: "Do not push, open a PR, mint a receipt, or run `bisellium next`; the orchestrator does those."

Limit, stated: the rule fixes the three texts and their order only. It does not stop a second, wrong command from appearing elsewhere in the template, and it does not read the filled per-opus copies.
