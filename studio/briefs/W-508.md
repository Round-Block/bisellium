## Intent

The Patron, 2026-11-05: a reply must not reach them twice; "file it, i want a permanent solution". W-444's Stop rules judge a main-thread reply after it has been shown. A refusal (exit 2) makes the model write again, so the Patron reads and pays for the reply twice. The cause is the route, not the rules: nothing that runs at Stop can take a shown reply back. So no rule refuses at Stop any more. The Patron, 2026-11-06, ruled the length rule has no point and removed it; the usage line stays.

1. **Stop never refuses.** At a main-thread Stop `bisellium hook-event guard` exits 0 whatever the reply holds (behaviour 1).
2. **The usage line.** The hook itself shows the Patron the reading, read from the plans' own sources at the Stop, through `systemMessage`. The model no longer carries it, so W-444's rule that the reply carries a line is gone (behaviour 2).
3. **The next turn.** At the session's next UserPromptSubmit the model is handed the reading (behaviour 3).
4. **The wiring.** `.claude/settings.json` gains one UserPromptSubmit group running the same guard command, and `guardWiring` requires it (behaviour 4).
5. **The length rule is gone.** No word count, no note, no line about length to the Patron or the model, and nothing that existed only to carry them (behaviour 5).
What was probed, sandboxed, with the installed Claude Code (`sources.out`, `probe/`; haiku through `claude -p`, stream-json, two turns in one process):

- **`systemMessage` at Stop, exit 0** (`probe/twoturn-show.summary`, versions 2.1.312, 2.1.314, 2.1.317 and 2.1.318 in `probe/headless-versions.summary`): one model message, no second turn, and an informational line `Stop says: <text>`, level `notice`. Asked on the next turn to quote the text, the model says `NONE`: it never reaches the model and costs no tokens. A two-line message comes out as two `Stop says:` lines (`probe/e2e.summary`).
- **Exit 2 at Stop, master's route** (`probe/twoturn-refuse.summary`): the feedback comes back as a user message and the model writes a second reply; the defect reproduced, on every turn.
- **`additionalContext` at UserPromptSubmit** (`probe/twoturn-show.summary`): the model answers with a word only that hook held. The docs add that this hook also fires when a background subagent reports back, a session-scoped task fires or another session sends a message (`probe/hooks-docs.md`, `sources.out`).
- **The guard wired at both events** (`probe/e2e.summary`): a reply gets one model message with the reading under it, and the next prompt's context holds the reading. That run was on revision 1's prototype, which also carried the note, and is not repeated: this revision only removes lines from the same two outputs, and revision 2 refuses only inputs no probe saw, as all ten Stop inputs and all eight prompt inputs (`probe/work/`) carry no `agent_id`, a 36-character session id and, at Stop, a boolean `stop_hook_active`.
- **What was not seen.** The terminal rendering: a `tmux` probe was refused by the sandbox (a Unix socket connect, `probe/interactive-refused.out`) and not retried by another route. The desktop app's and the phone's rendering cannot be probed from here. Read from the binary, not observed: the bridge's filter forwards `hook_system_message` attachments to a remote client (function `t_e`, `sources.out`). The docs say `systemMessage` is a "warning message shown to the user". The newest 40 transcripts all say entrypoint `cli`, and the newest desktop bundle in reach is 2.1.317, a version the headless probe covers. So Acceptance ends with the Patron's own eye on their own surface (Defaults 1).

Decided here (the opus asked for each):

- **What is shown.** `readingParts(takeReading(home, now, label))`: W-444's own shape, `Claude week 19%, 5h 16% | Codex week 39% | context 208k of 300k`, read at the hook from W-430's `takeReading` (the status-line file and the newest Codex log), never `readings.jsonl` and never `usage-reading.sh`. Nothing appends a reading: the file's size and W-495's cost reading stay as they are. Running the script from the hook is ruled out: hooks run unsandboxed and `~/.bisellium-evidence/` is writable from the sandbox, so a hook must read that folder as data, not execute it (CLAUDE.md, "Never point a hook at a script in the agent clone", the same reason). Its measured cost is about 20 ms on this host's 2466 Codex logs, on a guard boot of about 0.5 s (`timing.out`, `sources.out`), inside the existing 2 s timeout.
- **W-444's freshness rule.** A reply used to be sent back when the latest reading was over 30 minutes old. The hook now reads the sources itself, so a reading is as fresh as they are; a status line older than `STALE_MS` is shown with `(Claude values seen <at>)` rather than refused.
- **What is removed with the rule.** `REPLY_WORDS`, `replyWords`, `replyLength`, `STOP_RULES`, `StopRule`, `StopContext`, the note store `reply-note.ts` and its three inventory pins exist only to carry the rule, and nothing kept reads them (`git grep`, `fix.diff`).
- **The seam change (documented reason).** W-444's `STOP_RULES` table was the seam W-436 and W-465 were to add to. The Patron's ruling leaves it empty, so it goes, rather than stand as an empty table with a store nothing writes. Reinstating a Stop rule is those opera's design to state when they resume (Out of scope).
- **The next-prompt reading stays.** Its purpose is the reading reaching the model before it writes, not the note, so it and its UserPromptSubmit wiring stay (Defaults 2). The Patron has not ruled on them.
- **The session id at a prompt.** The note store was its one reader, but the prompt's fail-closed reading of its discriminators (spec review advisory 2) keeps its rows: `promptOutput` keeps the same pattern, `PROMPT_SESSION`, as its own. An out-of-domain id still gets nothing and every probed id is inside it.
- **Main thread or subagent.** As W-444: a Stop or a UserPromptSubmit input naming an `agent_id` gets nothing. A discriminator of a wrong type fails closed and is not read as absent (Interfaces, Input domain rows 1 and 3). SubagentStop keeps W-310's and W-494's refusals: a subagent's message goes to its caller, not to the Patron. W-310's and W-418's refusals at PreToolUse stay: they refuse a call before it runs, not a shown reply.
- **`stop_hook_active`.** Nothing in this repo causes a continuation any more; another hook could, so a continuation stays not judged and shows nothing. A value that is not boolean, absent included, is not a fresh Stop either: the docs and all ten probed Stop inputs carry the boolean (`probe/hooks-docs.md`, `probe/work/stop-input-*.json`).

**When it takes effect.** Hooks run the `bisellium` on PATH, `~/.local/bin/bisellium`, a symlink into the Patron's clone `~/projects/bisellium`. The Stop half takes effect at the first Stop after that clone reaches the merged master, in a running session too, because W-444's Stop group is already wired; until then the refusals continue. The reading reaches the model only in a session whose settings hold the UserPromptSubmit group, at the latest one started after the agent clone is at the merged master. In either order nothing breaks: master's guard exits 0 at a UserPromptSubmit (its `guardRefusal` judges only PreToolUse, SubagentStop and Stop).
Threat model: mistakes, not adversaries (D-045). The reply is the session's own text and is no longer read beyond whether it is blank; the sources are written by the Patron's tools on this host and read as data. The guard writes nothing at Stop or at a prompt.
