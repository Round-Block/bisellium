## Intent

The Patron, 2026-11-05: a reply must not reach them twice; "file it, i want a permanent solution". W-444's Stop rules judge a main-thread reply after it has been shown. A refusal (exit 2) makes the model write again, so the Patron reads and pays for the reply twice. The cause is the route, not the rules: nothing that runs at Stop can take a shown reply back. So no rule refuses at Stop any more, and each rule keeps its purpose by a route with no second reply.

1. **Stop never refuses.** At a main-thread Stop `bisellium hook-event guard` exits 0 whatever the reply holds (behaviour 1).
2. **The length rule.** A reply over 200 words, counted as W-444 counts, is recorded as a note for the session's next turn, and the Patron is told in the hook's own line (behaviour 1).
3. **The usage line.** The hook itself shows the Patron the reading, read from the plans' own sources at the Stop, through `systemMessage`. The model no longer carries it, so W-444's rule that the reply carries a line is gone (behaviour 2).
4. **The next turn.** At the session's next UserPromptSubmit the model is handed the reading and, once, the note, told that the reply stands and is not to be resent (behaviour 3).
5. **The wiring.** `.claude/settings.json` gains one UserPromptSubmit group running the same guard command, and `guardWiring` requires it (behaviour 4).

What was probed, sandboxed, with the installed Claude Code (`sources.out`, `probe/`; haiku through `claude -p`, stream-json, two turns in one process):

- **`systemMessage` at Stop, exit 0** (`probe/twoturn-show.summary`, versions 2.1.312, 2.1.314, 2.1.317 and 2.1.318 in `probe/headless-versions.summary`): one model message, no second turn, and an informational line `Stop says: <text>`, level `notice`. Asked on the next turn to quote the text, the model says `NONE`: it never reaches the model and costs no tokens. A two-line message comes out as two `Stop says:` lines (`probe/e2e.summary`).
- **Exit 2 at Stop, master's route** (`probe/twoturn-refuse.summary`): the feedback comes back as a user message and the model writes a second reply; the defect reproduced, on every turn.
- **`additionalContext` at UserPromptSubmit** (`probe/twoturn-show.summary`): the model answers with a word only that hook held. The docs add that this hook also fires when a background subagent reports back, a session-scoped task fires or another session sends a message (`probe/hooks-docs.md`, `sources.out`).
- **The prototype's own guard wired at both events** (`probe/e2e.summary`): a 300-word reply gets one model message, the reading and the note's line under it; the next prompt's context holds both; the note file is gone afterwards. That run was on revision 1's prototype and is not repeated: revision 2 refuses only inputs no probe saw, as all ten Stop inputs and all eight prompt inputs (`probe/work/`) carry no `agent_id`, a 36-character session id and, at Stop, a boolean `stop_hook_active`.
- **What was not seen.** The terminal rendering: a `tmux` probe was refused by the sandbox (a Unix socket connect, `probe/interactive-refused.out`) and not retried by another route. The desktop app's and the phone's rendering cannot be probed from here. Read from the binary, not observed: the bridge's filter forwards `hook_system_message` attachments to a remote client (function `t_e`, `sources.out`). The docs say `systemMessage` is a "warning message shown to the user". The newest 40 transcripts all say entrypoint `cli`, and the newest desktop bundle in reach is 2.1.317, a version the headless probe covers. So Acceptance ends with the Patron's own eye on their own surface (Defaults 1).

Decided here (the opus asked for each):

- **What is shown.** `readingParts(takeReading(home, now, label))`: W-444's own shape, `Claude week 19%, 5h 16% | Codex week 39% | context 208k of 300k`, read at the hook from W-430's `takeReading` (the status-line file and the newest Codex log), never `readings.jsonl` and never `usage-reading.sh`. Nothing appends a reading: the file's size and W-495's cost reading stay as they are. Running the script from the hook is ruled out: hooks run unsandboxed and `~/.bisellium-evidence/` is writable from the sandbox, so a hook must read that folder as data, not execute it (CLAUDE.md, "Never point a hook at a script in the agent clone", the same reason). Its measured cost is about 20 ms on this host's 2466 Codex logs, on a guard boot of about 0.5 s (`timing.out`, `sources.out`), inside the existing 2 s timeout.
- **W-444's freshness rule.** A reply used to be sent back when the latest reading was over 30 minutes old. The hook now reads the sources itself, so a reading is as fresh as they are; a status line older than `STALE_MS` is shown with `(Claude values seen <at>)` rather than refused.
- **What is recorded where.** One small file per session, `~/.bisellium-evidence/usage/reply-notes/<session id>`, written whole by a rename (W-418's store pattern, under home because the Stop's `cwd` may be outside a checkout). It holds the rule's line. A later note replaces it; a reply in bounds leaves it, so a turn woken with no prompt does not lose it.
- **The seam change (documented reason).** W-444's `STOP_RULES` and `StopRule` stay and keep their signature, but a rule's line is now a note, not a refusal, because a refusal at Stop is the defect. `stopRefusal` becomes `stopOutput`. W-436 (halted by the freeze) was to add a refusing rule here; when it resumes its rule is a note too, and its title needs that change (Out of scope).
- **Main thread or subagent.** As W-444: a Stop or a UserPromptSubmit input naming an `agent_id` gets nothing. A discriminator of a wrong type fails closed and is not read as absent (Interfaces, Input domain rows 1 and 4). SubagentStop keeps W-310's and W-494's refusals: a subagent's message goes to its caller, not to the Patron. W-310's and W-418's refusals at PreToolUse stay: they refuse a call before it runs, not a shown reply.
- **`stop_hook_active`.** Nothing in this repo causes a continuation any more; another hook could, so a continuation stays not judged and shows nothing. A value that is not boolean, absent included, is not a fresh Stop either: the docs and all ten probed Stop inputs carry the boolean (`probe/hooks-docs.md`, `probe/work/stop-input-*.json`).

**When it takes effect.** Hooks run the `bisellium` on PATH, `~/.local/bin/bisellium`, a symlink into the Patron's clone `~/projects/bisellium`. The Stop half takes effect at the first Stop after that clone reaches the merged master, in a running session too, because W-444's Stop group is already wired; until then the refusals continue. The note and the reading reach the model only in a session whose settings hold the UserPromptSubmit group, at the latest one started after the agent clone is at the merged master. In either order nothing breaks: master's guard exits 0 at a UserPromptSubmit (its `guardRefusal` judges only PreToolUse, SubagentStop and Stop), and with the new guard and old settings the note is left and only waits.

Threat model: mistakes, not adversaries (D-045). The reply is the session's own text; the sources and the notes are written by the Patron's tools and by this hook on this host. A note is read as data: bounded, regular files only, control characters stripped, and it can only say what a sandboxed session could already say to itself. The hook runs unsandboxed and this folder is writable from the sandbox, so the store follows no symlink: the temp file is created exclusively, the rename replaces what is at the note's path, and the read goes through `readContainedRegularFile`.

### Input domain

Nothing here refuses at Stop or blocks a prompt. A rejection fails closed only where something is written or handed: a Stop or a prompt with a malformed discriminator shows, records and hands nothing, the note store writes and hands nothing out of its domain, and the wiring is one `hook.guard` block. Every other out-of-domain input is passed, shown as `?`, or told to the Patron, as the guard is fail-open. Each fail-open is stated as a limit.
