## Intent

W-523's `branch` waited on the 11-06 retro. Its spec was signed and reviewed, and two things stopped it: `next` held a new opus at `branch` until the entry existed, and once it existed the branch perform refused the entry itself, an uncommitted edit to `studio/acta/improvements.md`. `next` named `branch` both before and after the run and never named the land. After this opus: a missing retro holds only an opus with no signed spec, at the start of its spec. A failed land holds nothing. `next` names the run, the QA lead's proposals and the land, in order, on a line that holds nothing. `check` warns when the previous day's entry has nothing under its `Proposed improvements` heading. The lex says who does what.

**Decided: "no signed spec" is no `opus/<id>` branch and no `ci/<id>-spec-<n>.log` in the main checkout.** The rung already reads this as `pre && !spec.anyLog`. So a brief still being drafted holds; a signature waiting for its review, a failed review going back to its signer, and a signature over a brief edited since are all signed work and do not hold. The test sits at the head of the `!spec.ok` branch, before any spec order is named. The hold has no timer: it reads only whether the previous UTC day has an entry.

**Decided: the cascade retro stays at `branch`.** `retroHold` is split: `dailyHold` moves, and the `owed` part (D-039 section 1, a retro owed by a done opus) stays where it is. An unreadable tracker moves with the daily hold. `check`'s `retro.daily.missing` already blocks it (`process.ts`), and a signed opus is not held by it.

**Decided: the unstaged edit passes every main-checkout perform, not only `branch`.** The ops lead's `integrate.ts` pointer is the shared `dirtyReport`; the refusal W-523 printed comes from `performBranch`'s `dirtyHold` (`next.ts` near line 2525). **What happens to the edit across each perform, read and pinned.** `branch`: `git switch -c` carries it, `git commit -- <paths>` leaves it out, `switch master` carries it back, and `git worktree add` checks out the commit, so the opus worktree has the tracker as of its base. In all three it is still in the main checkout afterwards, and `land` still carries it.

**Decided: the steps are one line, not a rung.** `daily-retro: <day> step <k> of 3: <step>; then <step>` is printed by `render`, on `next <opus>`'s ordinary report, and once by `next --all`, from the first step left. Step 1 while the entry is missing, step 2 while the heading is empty, step 3 while the file differs from master, none after. An entry landed with an empty heading goes back to step 2, then 3 again, so a land before the proposals loses nothing.

**Decided at revision: the line names the role, and reads no manifest.** Round 1 read `bisellium.yml#collegia` for the QA magister's name, in `dailyLine` and `runAll`, and review found that read had no domain or rejector. So the opus adds no read of the manifest, needs no new row or rejector for it, and `runAll` gains no new way to throw. The old hold's own read of `collegia` goes too, since the hold now names the ladder-runner. The cost is a stated limit: an officina whose QA magister has another id still reads "the qa-lead". D-147 and D-188 name that seat, and this officina's is `qa-lead`.
