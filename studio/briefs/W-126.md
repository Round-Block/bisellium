# W-126 — a blocking verdict finding cites a brief line or is recorded as advisory

Status: **signed spec, revision 1** · architect sella (claude-opus-5-5) · 2026-10-05.
The spec gate is written by `bisellium verdict W-126 --phase spec`, not by this text.

## Intent

Decree family: verdict-citation

W-125's filing (`briefs/W-125.md`, "Follow-on filings", first title) asks
for four things. The verdict writer reads each finding's severity and any
citation of the opus's declared brief, and checks the cited line. A BLOCKING
finding without a valid citation is recorded as ADVISORY, with the reason.
The outcome is reconciled, so converted findings alone cannot leave a failure
behind. Raw submissions, valid blockers, historical verdicts and the censor's
sole authority (D-014) are preserved. The filing owns verdict grammar only.
`acta/2026-10-05-ranking.md` item 4 puts it after W-127, which made every
behaviour, red marker and family line one citable line. W-124's filed
follow-on (a review cites the sec-lead input it used) builds on this grammar.

**Measured at master `2526b8a`.** Script and output:
`~/.bisellium-evidence/W-126-spec/measure.mjs` → `measure.out`. The writer is
`runVerdict` (`packages/commands/src/verdict.ts:74`). It accepts a non-UI
body only when `findingsProblem` (`:56`) finds exactly one `## Findings`
section of numbered lines, each ending `check: …`. It copies the body
verbatim after a `# key: value` header, which `parseVerdictHeader`
(`opus-model.ts:452`) reads. It never writes a gate. The gate is written by
`review --pass|--fail --evidence ci/<id>-review-<n>.log`
(`lifecycle.ts:530`), which reads the log's header but not its outcome.

- 151 review logs. 12 use the writer's one-`## Findings` grammar. They hold
  28 blocking findings. Only **2** cite a line of the declared brief, and
  both cite valid lines (`studio/briefs/W-085.md:237`, `studio/briefs/W-131.md:198`).
  The other 26 cite a source `file:line`, which is what `docs/CENSOR-PROMPT.md`
  asks for (`<file:line>`).
- Of 11 failed rounds in those 12 logs, **9 rest only on uncited blockers**
  and 2 keep a valid one. W-127 round 1 is among the 9. Its five blockers
  were real defects, and each was citable: "its text names the opus", "one
  contained read".
- Citation habit: 2 of the 12 findings-grammar logs cite their brief by line
  anywhere in the body; 21 of the 139 older transcripts do. Across every log,
  11 of 65 blocking-shaped lines cite the declared brief on the same line.
  Forms in use: `studio/briefs/<id>.md:<n>` (repo-relative), `brief:<n>`
  (40 occurrences), and absolute worktree paths (40, W-087).
- Severity words in use: `BLOCKING` 63, `blocking` 22, `**BLOCKING**` /
  `**Blocking` 6; `ADVISORY` / `advisory` / `**ADVISORY**` 67.
- Outcome words in use: `failed`, `FAIL`, `VERDICT: FAIL — …`, `passed`,
  `PASS — …`.

**So the grammar cannot ship without the prompt.** Before this change, 9 of
11 failed rounds would have been recorded as passed. This opus therefore
updates `docs/CENSOR-PROMPT.md` and `.claude/agents/censor.md` in the same
cascade. The writer also prints every conversion, so the orchestrator who
records the verdict sees it before running `review`.

**A brief line**, concretely: line `n`, counting from 1, of the bytes of the
opus's `spec:` file. The writer reads that file through
`readContainedRegularFile(root, spec, "briefs")` when it records the verdict.
D-021 puts that write on the opus's own ref, so this is the brief the censor
judged. The header pins those bytes by git blob id. A later brief revision
does not silently re-aim an old citation.

**Authority.** The writer applies grammar. It does not judge. It never
promotes a finding to blocking, never turns a passed outcome into a failure,
never adds or drops a finding, and never edits the body. A failure stands
exactly when the censor cites a brief line for it. Spec-phase verdicts and
`kind: ui` verdicts are unchanged.

## Interfaces

```ts
// packages/commands/src/verdict.ts
export interface Conversion { finding: string; reason: string } // finding = the number as written
export function reconcileFindings(
  body: string,
  outcome: string,
  brief: { spec: string; repoSpec?: string; text: string } | { error: string },
): { converted: Conversion[]; outcome: string; submittedOutcome?: string };
```

**Scope.** Everything here runs only for a `--phase build` verdict on an opus
whose `kind` is not `ui`, after `findingsProblem` passes and before the
target is written. The spec phase and UI verdicts take today's path,
byte for byte.

**The brief.** `record.spec` is not a string → `{ error: "no spec" }`.
Otherwise `readContainedRegularFile(root, record.spec, "briefs")`. An error
there → `{ error: <its error> }`. On a successful read, `spec` is
`record.spec`. `repoSpec` is `<officina path relative to the git root>/<spec>`
when the officina is inside a git repository, and `text` is the bytes as
UTF-8. Its line count `L` is `text.split(/\r?\n/).length`, less one when the
text ends with a newline.

**Blocking finding.** A blocking finding is one of the numbered lines that
`findingsProblem` already selects (`contentLines`, section `Findings`,
`^[1-9]\d*\. \S`). The test is `/^[1-9]\d*\. \**blocking\b/i`, so
`blocking`, `BLOCKING`, `**BLOCKING**` and `**Blocking` all count. Every
other numbered line is left alone.

**Citation.** A citation is every match on that one line of
`/(?<![\w./-])(brief|\/?(?:[\w.-]+\/)*briefs\/[\w.-]+\.md):([1-9]\d*)(?!\d)/g`.
For a range such as `brief:169–173`, only the first number is read.

A citation is valid when all three hold:

1. Its path is `brief`, `spec`, or `repoSpec`.
2. The brief was read.
3. `1 ≤ n ≤ L`, and line `n` is not blank after `trim()`.

A finding with at least one valid citation stays blocking. Otherwise it is
converted, and its reason is the first rule below that applies:

1. the brief was not read: `the opus declares no readable brief: <error>`;
2. no citation: `cites no line of <spec>`;
3. the first citation's path is not declared: `cites <path>, not the declared brief <spec>`;
4. the first citation is past the end: `<spec> has <L> lines, no line <n>`;
5. the first citation is blank: `<spec>:<n> is blank`.

**Outcome.** A submitted outcome is failed when
`/^(?:verdict:\s*)?fail(?:ed)?\b/i` matches `outcome.trim()`. The outcome is
reconciled only when all three hold: it is failed, at least one blocking
finding was submitted, and none remains blocking. Then the recorded outcome
is `passed` and `submittedOutcome` is the raw `--outcome`. In every other
case the outcome is returned unchanged with no `submittedOutcome`. A failed
outcome with no blocking finding is left as submitted.

**Header.** The order is today's, with three additions:

- `# submitted_outcome: <raw>`, right after `# outcome:`, only when the
  outcome was reconciled;
- `# brief: <spec> blob:<40 hex>`, after `# tree:`, whenever the brief was
  read. The blob is the git blob id of the bytes read,
  sha1(`blob <byte length>\0` + bytes);
- `# converted: <finding> (<reason>); <finding> (<reason>)…`, after `# brief:`
  (or after `# tree:` when there is no brief), only when something was
  converted. Entries follow body order.

The body is still the submitted bytes, unchanged.

**stdout.** After today's success line, the writer prints one line per
conversion, `<id>: finding <finding> recorded as advisory: <reason>`. When
the outcome was reconciled, it also prints
`<id>: outcome "<raw>" recorded as passed: no blocking finding cites a line of the brief`.

**`review`.** With `--fail`, after the evidence is read through
`readContainedRegularFile` and before `readState`: when
`parseVerdictHeader(evidence)` has the key `submitted_outcome`, `review`
writes one stderr line and exits 2. It writes no record, gate or event. The
line is
`<id>: review --fail: <evidence> records outcome passed; every blocking finding was recorded as advisory (see its # converted line). Record a new verdict round whose blocking finding cites a brief line.`
`--pass` and every evidence log without the key take today's path.

**Citable shape.** Each rule above, each behaviour's first line and its
`**Genuine red:**` sit on one line, so a finding against this opus cites
`brief:<n>`.

## Behaviours to test

Rows use the officina from `verdict-findings.test.ts` (W-131's helper), with
`spec: briefs/W-300.md` on `opera/W-300.md` and a 10-line
`briefs/W-300.md`, newline-terminated, whose line 4 is blank. Each verdict is
`runVerdict(["W-300", "--round", <n>, "--sella", "qa-lead", "--outcome", <o>, "--from", <body>, "--studio", dir])`,
build phase unless stated. Rows capture stdout and stderr and read the
header with `parseVerdictHeader`. **Body exact** means the bytes after the
header's blank line equal the input bytes. Each behaviour is a `node:test`
named `W-126.behaviour.<n>: …`, selectable by name pattern.

1. **A blocking finding that cites no brief line is recorded as advisory,
   with its reason in the header.** A `--outcome passed` body has four
   findings:
   - 1: `blocking — packages/x.ts:3 … — check: none: x`
   - 2: `advisory — …`
   - 3: `BLOCKING — brief:2 …`
   - 4: `**Blocking** — briefs/W-300.md:5 …`

   Expected: exit 0; `# brief: briefs/W-300.md blob:<git blob id of the brief bytes>`;
   `# converted: 1 (cites no line of briefs/W-300.md)` exactly;
   `# outcome: passed`, with no `submitted_outcome`; body exact; and the
   stdout line for finding 1. A body with only advisory findings gets
   `# brief:` and no `# converted:`. The same four-finding body with
   `--phase spec` gets neither line. `verdict.test.ts`,
   `verdict-findings.test.ts` and `opus-model.test.ts`'s verdict rows stay
   green unchanged.
   **Genuine red:** today the log has no `# converted:` line; the row fails
   on its header assertion.

2. **A citation that is not a line of the declared brief does not keep a
   finding blocking.** Each row has one blocking finding; expected
   `# converted:` reasons:
   - `briefs/W-301.md:2` → `cites briefs/W-301.md, not the declared brief briefs/W-300.md`
   - `/home/x/studio/briefs/W-300.md:2` → the same shape, naming the absolute path
   - `brief:11` → `briefs/W-300.md has 10 lines, no line 11`
   - `brief:4` → `briefs/W-300.md:4 is blank`
   - no `spec:`, citing `brief:2` → `the opus declares no readable brief: no spec`, and no `# brief:` line
   - `spec:` naming a missing file → the same prefix
   - `brief:11` then `briefs/W-301.md:2` → the first citation's reason

   These stay blocking (no `# converted:` line): `brief:10`;
   `briefs/W-300.md:1`; `briefs/W-301.md:2` then `brief:3`; and, in an
   officina inside a git repository (`verdict.test.ts`'s `gitStudio`),
   `<officina>/briefs/W-300.md:3`.
   **Genuine red:** after behaviour 1, `briefs/W-301.md:2` keeps the finding
   blocking; the row fails on its header assertion.

3. **A failed outcome whose every blocking finding was converted is recorded
   as passed, with the submitted outcome kept.** `--outcome failed` with
   findings 1 (uncited, blocking) and 2 (advisory) gives:
   - `# outcome: passed`;
   - `# submitted_outcome: failed`;
   - the reconciliation stdout line;
   - body exact.

   `FAIL` and `VERDICT: FAIL — x` give the same, with the raw text kept.

   Unchanged rows:
   - `failed` with one uncited and one valid blocker: `# outcome: failed`,
     `# converted: 1 (…)`, and no `submitted_outcome`;
   - `failed` with only advisory findings;
   - `passed` with a valid blocker (the writer never fails a round);
   - `--phase spec --outcome failed` with an uncited blocker.

   **Genuine red:** after behaviour 2, the all-converted row records
   `# outcome: failed`; the row fails on its outcome assertion.

4. **`review --fail` refuses a verdict log whose failure was reconciled
   away.** W-300 is at `review` with no `builder_runtime`. Its
   `ci/W-300-review-1.log` comes from behaviour 3's all-converted row.
   `runReview(["W-300", "--fail", "--evidence", "ci/W-300-review-1.log", "--round", "1", "--sella", "qa-lead", "--studio", dir])`:
   - exits 2;
   - writes the stderr line;
   - leaves the opus bytes unchanged;
   - leaves `.bisellium/events.jsonl` unchanged or absent.

   Accepted:
   - `--pass` with the same log;
   - `--fail` with a log whose failure kept a valid blocker;
   - `--fail` with a pre-W-126 log written by hand: `# outcome: FAIL`, an
     uncited blocker, and no `submitted_outcome`. History is read as today.

   `lifecycle.test.ts`'s review rows stay green unchanged.
   **Genuine red:** after behaviour 3, `--fail` with the reconciled log
   exits 0 and writes a failed gate; the row fails on its exit assertion.

Each behaviour's implementation leaves the next one red (D-036):

- Behaviour 1 converts a blocking finding with no citation token, and counts
  any token as cited.
- Behaviour 2 validates each token.
- Behaviour 3 is the outcome, which neither of the first two touches.
- Behaviour 4 is the gate's consumer, in another verb, which behaviour 3's
  log does not reach.

## Out of scope

- Rewriting, re-reading or re-gating any historical verdict log.
- Spec-phase verdicts, `kind: ui` verdicts, and `next`'s spec rung.
- Judging whether a cited line is relevant to the finding. That stays the
  censor's call, and the builder may dispute it in the next round.
- Requiring `--outcome` to be exactly `passed|failed`, or refusing a
  `passed` outcome that keeps a valid blocker.
- A failed outcome with no blocking finding at all.
- Citing the sec-lead input (W-124's follow-on), brief admission (W-127),
  execution (W-125), and supplying missing tests or shrinking briefs.
- Amending `leges/qa.md`.

**Open questions for the Patron.** Each default ships as stated and can be
vetoed at the checkpoint.

1. **Reconcile by recording `passed`, or refuse the write.** Default:
   record `passed`, keep the raw outcome in `# submitted_outcome:`, and have
   `review --fail` refuse that log. This is the filing's wording ("recorded
   as ADVISORY", "cannot leave a blocking failure behind"). The risk is
   measured above: 9 of the last 11 failed rounds cited no brief line. The
   prompt change in this opus is the mitigation. The alternative is a refusal
   (exit 2, nothing written) when every blocker would convert. That keeps a
   real defect from passing, but the conversion is then never recorded.
2. **What counts as a brief line.** Default: any non-blank line of the
   declared brief, cited as `brief:<n>`, `<spec>:<n>` or `<officina>/<spec>:<n>`.
   One valid citation is enough. The alternative is to admit only lines
   inside the six sections, which would refuse the title, the status line
   and revision tables.
3. **Scope.** Default: build-phase non-UI verdicts only. Spec verdicts are
   the architect's own, and a UI verdict's `Verdict:` line must match its
   outcome header (`substantiveUiTranscript`), which reconciling would break.
4. **Leges.** `leges/qa.md` §2 could name the citation rule. Leges are
   amended by the Patron. Default: the producer proposes it at the
   checkpoint.
