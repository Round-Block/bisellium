## Intent

`scripts/ci-certify.mjs` mints only for a PR head named `opus/<id>`. Any other head prints `not an opus; nothing to mint` and passes, so source pushed on a `chore/` branch reaches master without a certificate (found landing W-240; D-039 high). D-071 B ranks this second in the CLI-first block, because the block adds more non-opus heads: `chore/done-<id>` (today's done PR; W-214 makes it the one records PR at done), plain records chores (checkpoint and decision PRs), queue commits (W-299: `studio/queue.yml`) and console writes (W-301: `chore/console-<ts>`).

After this opus certify judges a non-opus head by what its merge group changes. Officina records only: nothing to mint, as today. Any other path, an empty diff, or a diff that cannot be read: not certified, and no mint. An `opus/<id>` head mints as today, whatever it changes.

The record paths are one list, `recordOnly` in `scripts/ci-scope.mjs`, which the merge group's records-only CI path already uses (W-131, W-203, W-209): the studio directory, `docs/SESSION-HANDOFF.md`, and a page directly in `docs/design/dossier/` whose name ends `.html`. The census of the last 400 master commits titled `chore(`, `spec(` or `docs(` (`records-census.sh`, `records-census.out`) backs this list. File changes under `studio/`: 2,101. Dossier pages: 228. The handoff: 153. The rest is source and rare: `docs/research/` (458 files in two commits, #168's research salvage and #375), `.claude/` 5 (#206, #497, #498), `scripts/` 5, `docs/ARCHITECTURE.md` 3 (in the certificate's tree, read by `docs.arch.stale`), and `CLAUDE.md` with `AGENTS.md` twice each, regenerated by the decision PRs #402 and #478 (Defaults 2). `source_excludes` is not that list. It excludes `examples/` from the real studio's certificates, but the sample studio is a test fixture, so a change there needs the mint. And the handoff is a record even though the certificate hashes it.

`next` keeps its own copy of the list today, and it is wider. The done perform lets any tracked `docs/` change ride the done commit, and the landing guard passes any `docs/` path. A done PR carrying `docs/ARCHITECTURE.md` would get past both and then fail certify in the queue. Both guards now call `recordOnly`, so the CLI and certify cannot drift.

`pr` also refuses an opus branch with a merge commit since master, before it pushes. Certify rebases the head onto master commit by commit, so a merged-in master conflicts again in the queue (#489: a rebase, a re-mint, a third review round and a Patron re-approval).

How certify reads the diff. On a `merge_group` event, certify reads `git diff --name-only --no-renames -z <merge_group.base_sha>...<merge_group.head_sha>` in the candidate checkout (`fetch-depth: 0`, at `head_sha`). It reads it through `diffPaths`, a new reader in `ci-scope.mjs` that `scopeOf` (gates and web-e2e) and `next`'s done landing use too. So the three judge the same raw list with the same `recordOnly`. On a `pull_request` event the job does not run (job-level `if`; a skipped required check counts as passing), and the script refuses any other event with exit 2. So the queue is where the rule binds, which holds only while `master_protection` requires the queue (W-205's own condition).

A Patron chore that touches `scripts/`, `.github/` or `.claude/` is source. It lands as an opus on `opus/<id>` with its mint, as W-292 and W-290 will. Certify has no exemption by label, author, branch prefix or path. An exemption is the fail-open path this opus closes. The Patron's own way around a required check is GitHub's ruleset bypass, a Patron act outside certify and outside the agents' token, and this opus leaves it alone.

Threat model: mistakes, not adversaries (D-045).

## Interfaces

`certify(o)`, after `readPr` and only when `headRefName` is not `opus/W-<n>`:

- `git diff --name-only --no-renames -z <baseSha>...<headSha>`, read raw through `diffPaths(candidate, baseSha, headSha)`, which never trims before the NUL split. A failure refuses: `certify: refused: git diff of the merge group against its base failed`, exit 2. The script's own `git` helper trims, which would turn a first path ` studio/x.ts` into `studio/x.ts`; it stays for one-value reads only (`rev-parse`, `config --get`).
- `recordOnly(paths, o.studio)` true: `certify: PR #<n> head <name> is not an opus; nothing to mint (officina records only)`, exit 0. The existing W-168 row's `/not an opus; nothing to mint/` still matches.
- Otherwise: `certify: not certified: PR #<n> head <name> is not an opus and changes <up to five JSON-quoted non-record paths, or nothing> outside the officina records; source reaches master only on opus/<id> with its mint`, exit 1. No fetch, no rebase, no mint. A rename across the boundary counts as its deletion and its addition (`--no-renames`), so a source file moved into `studio/` is refused.

`diffPaths(cwd, base, head)` (new, `ci-scope.mjs`): `spawnSync` of `git diff --name-only --no-renames -z <base>...<head>` with a 120 s timeout and a 64 MiB buffer. It returns `stdout.split("\0")` without the empty pieces, never trimmed and never unquoted (`-z` prints each path verbatim), or `undefined` on a non-zero exit, a timeout or an overflow. `scopeOf(base, head)` is `diffPaths(process.cwd(), …)` and `recordOnly`, `false` on `undefined`. Its one change of output: a record whose name git quotes without `-z` (for example `studio/notes/café.md`) is now records-only, as certify judges it; today it takes the full path.

The other reads of git output, swept: `next`'s `git` (`integrate.ts`'s `sh`) never trims. `trackedChanges`, which feeds `dirtyHold` and `performDone`'s re-read, splits `git status --porcelain -z` raw and counts both sides of a rename (`touched`). `openPr`'s `rev-list` output is commit ids only, so trimming it alters nothing.

`recordOnly(paths, studio = "studio")`: true when `paths` is non-empty and every path starts with `${studio}/`, is `docs/SESSION-HANDOFF.md`, or matches `^docs/design/dossier/[^/]+\.html$`. The gates and web-e2e callers pass no `studio`, so they behave as today. Certify passes its validated `--studio`. `next` passes `f.studioRel`.

`performDone`: `rides(p)` is `p === <the record>` or (`p` is outside `${studioRel}/` and `recordOnly([p], studioRel)`): the handoff and the dossier pages. Two reads use it. Before the branch, `dirtyHold(repo, rides)` refuses a tracked change already in the checkout, such as a staged `docs/ARCHITECTURE.md`, before `chore/done-<id>` is cut. After `runDone`, which rewrites the record, `trackedChanges` is read again, and any path that does not ride unwinds with `chore/done-<id>` kept for inspection. Two reads are needed: the first cannot see what `done` itself changes, and the second runs after the branch exists.

`performLanding`: `diffPaths(repo, refs/heads/master, refs/heads/chore/done-<id>)`. `undefined` refuses (`could not read what <head> changes (git diff failed); nothing pushed`). `recordOnly(paths, studioRel)` is judged on the whole list, as certify judges it, so an empty diff is refused as well. The refusal is `refusing: <head> changes <the non-record paths, or nothing>, outside the officina records; nothing pushed`. The ladder never derives an empty done head (`choreDone` needs the done record on it); the empty case holds only so the two judges cannot disagree.

`openPr`, after the dirty check and `fetchTrunk`, before the repository slug, the mode read and any push, in both modes: `git rev-list --merges refs/heads/master..HEAD` in the worktree. A non-zero exit holds: `refusing: could not list opus/<id>'s merge commits: …`. A listed commit holds: `refusing: opus/<id> carries merge commit <12 hex>; certify replays the branch onto master, so rebase it onto master instead (no merge commits), then mint and review the rebased head`.

### Input domain

Every rejection fails closed: certify exits 1 or 2 without minting, and `next` holds before it commits or pushes.

| Record | Valid domain | Rejected by |
|---|---|---|
| A diff between two commits | `git diff --name-only --no-renames -z` exits 0 within 120 s and 64 MiB; each NUL-separated path kept verbatim | `diffPaths` (new): a failure, timeout or overflow returns `undefined`, which certify refuses (exit 2), `scopeOf` reads as not records-only, and `performLanding` holds; no output is trimmed or unquoted before it is judged |
| A non-opus head's merge group | `diffPaths` lists at least one path, every one a record | `certify` (extended): any non-record path (mixed diffs included), a rename out of a record path, or an empty diff exits 1 and names the paths; a failed diff exits 2; neither mints |
| A path as an officina record | `<studio>/…`, `docs/SESSION-HANDOFF.md`, `docs/design/dossier/<name>.html` (direct child) | `recordOnly` (extended): any other path, and an empty list, is not records-only |
| The checkout's tracked changes before `done` | the opus record, the handoff, the dossier pages (`git status --porcelain -z`, both sides of a rename) | `dirtyHold` (existing, given the narrowed `rides`): any other tracked change, `docs/ARCHITECTURE.md` included, or a failed status holds before `chore/done-<id>` is cut |
| The tracked changes after `runDone` | the same set; `runDone` rewrites only the record; verify's new certificate files are staged separately, as today | `performDone` (narrowed): any path that does not ride, or a failed status, unwinds with nothing committed and `chore/done-<id>` kept for inspection |
| A `chore/done-<id>` head's diff against master | `diffPaths` lists at least one path, every one a record | `performLanding` (narrowed): a non-record path, an empty list or a failed read holds before the push |
| The opus branch at `pr` | `git rev-list --merges master..HEAD` succeeds and lists nothing | `openPr` (extended): a merge commit, or a failed list, holds before the slug, mode read, push or PR create |
