**Definitions (settled here):**

1. **A start** is either of two rungs of an *unstarted* opus (trunk record `greenlit`, no `refs/heads/opus/<id>`): (a) its **spec rung**, meaning every order `next` makes there (the architect's draft and signature, which is the `verdict-spec` ticket; the Codex spec review; the ui-lead's input); and (b) **`branch`**, which takes a lane. A spec **draft** in a scratch worktree is not a start: it calls no verb, and no code sees it (a limit). An opus past `branch` is in flight. Order never refuses it, even after it is re-ranked down.
2. **In order** is `laneLines`' own reading of `queue.yml`, now one function, `laneTakes`. A busy lane holds its opus (any state but `done` or `halted`). An idle lane takes the highest entry of its queue that meets all three conditions: no lane holds or takes it first; its state is greenlit up to review; and it is not `next_ts` while another lane holds or takes a `next_ts` opus. A skipped entry keeps its place: nothing is reordered or written, and it is taken before every entry below it once its block clears. Each lane's **now** is the opus it holds or takes. Its **ahead** is the entry it would take if every lane's now were done: one per lane, never two, and never one entry for two lanes.
3. **The order refusals.** `branch` is named only for a lane's now. The spec rung is ordered only for a lane's now or ahead. Any other unstarted opus is held, `next: <id> <spec|branch> held`, actor `producer`, exit non-zero, with one of these whys:
   - `<id> is #<k> in queue <q>, the spec ahead of lane <L>: its spec may be signed, and it branches when the lane takes it: <lanes>; to start it now, rank it higher in queue.yml and land that edit` (an ahead opus at `branch`; behaviour 1);
   - `<id> is #<k> in queue <q> and no lane takes it: <lanes>; to start it now, rank it higher in queue.yml and land that edit` (behaviour 2, and behaviour 1 at `branch`). `<lanes>` lists each lane of that queue in the form `E1 holds W-610 (building), ahead W-512 (#2)` or `E1 takes W-512 (#2), ahead W-595 (#3)`;
   - fail closed (behaviour 1): `<id> is not ranked in queue.yml[ (it is folded into <X>)| (it is under halted|cut|deferred)]: rank it in a queue's next and land that edit before it starts`; `<studio>/queue.yml has an edit that is not committed; a start obeys the landed order: land it first`; `no start is ordered while <readQueue's why>` (a malformed or unreadable queue.yml, W-558's loader); `the queue order cannot be read: <why>` (a queued record whose state cannot be read, or git failing on queue.yml).
   The hold names `spec` while the opus's spec is owed, and `branch` once it is signed.
4. **The overlap refusal** (behaviour 3). A lane's now reaches `branch` only when its Files owned share no path with any opus **in flight**: `refs/heads/opus/<X>` exists and X's main record is open (greenlit up to review), whatever `queue.yml`'s lane field says. Every opus branch is listed (`git for-each-ref refs/heads/opus/`); a ref with no main record is not an opus and is skipped, and a done or halted one holds nothing. The lane named for X is the lane whose now it is, held or taken (an idle lane's take branched while its field is still `~` is that lane's), else `no lane`. Its own Files owned are the main checkout's signed brief (`briefs/<id>.md`, which `branch` commits). X's are the brief committed on `opus/<X>` (the blob X's spec gate judged). Both are read by master's `ownedFiles` (backticked spans on the bullet lines of `## Files owned`). Two spans overlap when they are equal, or when one ends in `/` and the other opens with it. The hold is `next: <id> branch held` with why `<id>'s Files owned overlap with an opus in flight: <X> in lane <L>|<X> in no lane: <paths>; it branches when that opus is done or halted, or when a lead ranks an entry that does not overlap above it and lands that edit (D-192, W-592)`, where `<paths>` are this opus's overlapping spans. It fails closed: an unreadable own brief, a `git for-each-ref` failure, a listed id outside the opus grammar, an unreadable X record, and an X branch with no readable brief each hold, naming what could not be read. An X with no opus branch is not in flight and is not read. It is checked against this opus when it reaches its own branch, and by then this opus's branch exists.
5. **The override** is the one way past every order refusal names (D-181 item 8): re-rank the opus in `queue.yml` and land the edit (`bisellium land <studio>/queue.yml --title … --sella producer --studio <studio>`). The landed commit records who moved it and why. There is no flag, no ticket and no new verb. Rank is the Patron's (D-194). A queue.yml edit not yet committed holds every start, so an unlanded local edit cannot bypass the order.
6. **Lanes and `next_ts`.** Lanes come from `queue.yml` `lanes:` as written, and their count stays the Patron's (D-182, W-513). `next_ts: true` is honoured as `laneLines` honours it (D-192 item 1); that skip is the order's one "blocked by another lane's opus". Class (D-193, W-595) is not read.
7. **`next --all`** prints an order hold as `next: <id> <step> queued · actor: producer · why: …`, and a `queued` line does not fail the run (exit 0 when nothing else is held; behaviour 4). An overlap hold is printed `held` and fails the run, because it is a lead's call. Every other line, the lane lines included, is unchanged.

## Promises

Promise branch-order: `next <id>` names `branch` for an unstarted opus only when a lane holds or takes it. The spec ahead and every later entry hold at `branch`, naming their rank, the lanes and the way past. An entry skipped for another lane's `next_ts` opus keeps its place and is taken before the entries below it. Pinned by `W-512-b1` "a signed spec ranked behind the lane's opus holds at branch", by `W-512-b1` "an idle lane takes the highest entry, not this one" and by `W-512-b1` "the skipped entry keeps its place: E1 takes it, not W-903" — limit: lanes are `queue.yml`'s as written; an opus branched before this lands keeps its branch.

Promise order-fails-closed: an unranked opus, an uncommitted `queue.yml` edit reported by Git and a malformed `queue.yml` each hold the start; none fails open within that domain. No `queue.yml` at all orders nothing. Pinned by `W-512-b1` "an unranked opus holds", by `W-512-b1` "an uncommitted queue.yml edit holds every start" and by `W-512-b1` "a malformed queue.yml holds the start, never fails open" — limit: a queued record whose state cannot be read holds every reached start; an ignored untracked `queue.yml` is omitted by Git status and may be obeyed by `readQueue` even though it is not committed.

Promise spec-ahead-one: the spec rung of an unstarted opus is ordered only for a lane's now or the one entry ahead of it. An opus two ahead holds at `spec`, and no architect is dispatched. Pinned by `W-512-b2` "two entries behind the lane's opus, no spec is ordered" and by `W-512-b2` "the one entry ahead of the lane's opus may take its spec" — limit: a draft in a scratch worktree is not seen.

Promise lane-overlap: a lane's now does not branch while its Files owned share a path with an opus in flight (an opus branch and an open record), whatever `queue.yml`'s lane field says. The hold names both opera, the other's lane (or no lane) and the overlapping paths, a folder span meeting a file in it. It fails closed on a brief it cannot read, and it branches once that opus is done or nothing is shared. Pinned by `W-512-b3` "E2's take overlaps W-901, in flight in E1, so it does not branch", by `W-512-b3` "E1 takes W-901, branched while its lane is still ~: E2's take does not branch", by `W-512-b3` "W-901, in flight but ranked below E1's take, is no lane's now and is still read" and by `W-512-b3` "opus/W-901 holds no brief: the overlap cannot be read, so the branch holds" — limit: only opera with an opus branch are read; a spec-ahead draft or an unbranched lane opus is not; spans are `ownedFiles`' (a glob is not expanded, a path without backticks is not seen).

Promise all-queued: `next --all` prints an order hold as `queued` and does not fail the run on it. Pinned by `W-512-b4` "an order hold alone does not fail next --all" and by `W-512-b4` "the out-of-order opus is queued, not held" — limit: the lane lines are unchanged and name no ahead.

- Unchanged code the promises lean on is a stated limit, not a guarantee (D-076 E): `readQueue` (W-558's loader), `queuedState`/`loadOpusRecord`, `laneLines`' rules as moved into `laneTakes`, `ownedFiles`, the step tickets (`requireTicket`), `meanwhile.ts`, `rules/queue.ts`, `integrate.ts`'s `git`/`sh` (its 120-second timeout), `laneRecord` and `CONFLICT_OPEN_STATES` (next.ts's, as `furtherAlongBranches` reads opus refs), and the `git status`, `git for-each-ref` and `git cat-file` calls.
- **A draft is not a start.** `next` sees a spec only when a verb runs. A draft two ahead in a scratch worktree is allowed and invisible, but it cannot be signed until it is one ahead. Per-lane draft orders and claims are W-597's.
- **The overlap reads only opera in flight.** A lane's opus with no opus branch (a spec-ahead draft, or a signed spec not yet branched) is not read. Symmetry closes it: that opus is checked against every opus in flight when it reaches its own `branch`. A ref whose id has no main record is not an opus (`opus/W-408-r3`) and is skipped. Two lanes reaching `branch` in the same moment are not serialised (a limit; `branch` itself is one ticket per opus).
- **A lane is idle by its lane field and its take.** An opus in flight that is no lane's now (a take displaced when a skipped entry's block clears, or a re-rank down) leaves its lane idle, so the lane may take and branch another entry beside it; the overlap still reads it (`in no lane`), so the two never share a file. Landing the lane field after `branch` closes it.
- **The overlap reads spans, not diffs.** Paths an opus changes outside its Files owned are W-498's boundary, at its own build. A glob is not expanded, and a path without backticks is not seen (`ownedFiles`).
- **No class, research, lane-id or rate check** (W-595, W-619, W-609). W-592 keeps the `check` rule half.
- **`meanwhile:` is unchanged** and can disagree with `lanePlan`'s ahead: it reads only a lane whose `lanes:` field names the opus, and it does not skip a `next_ts` entry (W-597).
- **The ahead releases every lane's now at once.** With two lanes, a `next_ts` entry can be one lane's ahead while another lane's `next_ts` opus is busy. It may sign, and its branch is held until a lane takes it (`W-512-b1`, the skipped-entry row).
- **The order reads the main checkout's committed `queue.yml` and the main checkout's records.** A local commit not yet landed counts as committed. A stale main checkout reads a stale order.
- **A ticket minted before a re-rank** stays valid until it is used or expires.
- **A broken record ranked above or in a lane** holds every start whose lane computation reaches it (fail closed). A lane's own opus is judged on the first pass alone, so an entry ranked below it never holds it.
- **The next-family suites that spawn `next` without a `queue.yml`** (next-world writes none) see no queue and are unordered. Their rows are unchanged, and none of them pins the order.

## Defaults for the Patron

1. **`next` refuses to start work out of the ranked order.** It starts a build only for the task a lane is due to take. It starts a spec only for that task or the one after it in each lane. Anything else is refused, and the refusal says how to get past it: change the ranking in the queue file and land that change. Default: yes.
2. **A task waiting on another lane's next.ts work keeps its place.** It is taken as soon as that work is done, before anything ranked below it. Default: yes.
3. **Two lanes never build the same files at once.** A lane's task does not start its build while any task already building owns any of the same files, whichever lane it is in, or none (a parked task with a branch counts). The refusal names both tasks and the shared files; the task starts once the other finishes, or when a lead puts a non-overlapping task first. A task whose spec is only drafted is not counted until it starts. Default: yes.
4. **There is no separate override switch.** Changing the ranking is the override, and the landed change records who made it and why. An unlanded local edit to the queue file blocks every start until it is landed. Default: yes.
5. **The full status list shows waiting tasks as "queued", not as failures.** An overlap shows as held, since a lead must pick. The lane lines stay as they are. Default: yes.
