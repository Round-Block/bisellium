## Intent

The Patron, 2026-10-22: GitHub's `ubuntu-latest` label moves to Ubuntu 26 from 2026-10-19, and Node 20 actions are deprecated and forced onto Node 24. CI's annotation report (`/home/edckt/.bisellium-evidence/ci-annotations-1022/`) shows both on today's runs: a notice that `ubuntu-latest` will migrate, on every run, and a warning that `actions/upload-artifact@v4` targets Node 20. The merge queue's one certificate is minted by the `certify` job, which runs on `ubuntu-latest` with a bubblewrap install and an AppArmor sysctl that were proved on Ubuntu 24.04 only; an image move under it changes the certificate's environment with no commit and no announcement.

Today (master aa14d5b8) `.github/workflows/ci.yml` runs `gates` (line 56), `officina` (line 118) and `certify` (line 205) on `ubuntu-latest`; `web-e2e` (line 151) already pins `ubuntu-24.04` (W-350). Both upload steps (lines 189 and 236) use `actions/upload-artifact@v4`; every checkout and setup-node step is already on `@v5`, a Node 24 major. No test reads a job's `runs-on` except W-350-b1 for `web-e2e`, and none forbids a Node 20 action.

After this opus:

1. The three jobs run on `ubuntu-24.04`, as `web-e2e` does, and both upload steps use `actions/upload-artifact@v6` (Node 24) with their inputs unchanged. The comment at line 84 stops naming `ubuntu-latest`.
2. One new row, `W-368-b1`, in the existing workflow-shape test file `scripts/ci-scope.test.mjs`, which already reads `ci.yml` through `workflow()`, fails if any job's `runs-on` is not `ubuntu-24.04` or any step's `uses:` is not a known action at or above its Node 24 major. A future image or action move is a commit that flips this row, never a silent change.

The row goes beside W-131's and W-205's whole-workflow rows rather than into a new file: the smallest check that holds is one row reading the parse those rows already read. It fails closed on any action it does not know, so adding an action means judging its runtime once, in the table.

Threat model: mistakes, not adversaries (D-045). GitHub's own image and action content is outside the repository.

Promise uploads-unchanged: both upload steps keep their `if`, `name`, `if-no-files-found` and `path` inputs, as W-168-b1 and W-350-b1 pin them — limit: upload-artifact v6 changes the runtime, not those inputs (its release notes); neither upload runs during spec prototyping (one needs a merge group, the other a master dispatch with `refresh_screenshots`).

Limits, stated:

- Unchanged code is a stated limit, not a guarantee (D-076 E): `workflow()` and the `yaml` parser it uses, every other row in the three test files, every other ci.yml line, `scripts/ci-certify.mjs` and the runner's bubblewrap and sysctl steps.
- The row reads `ci.yml` only; there is no other workflow file today. A job's `container:` or `services:` image and a job-level reusable workflow are not read (a job with no `runs-on` fails the row).
