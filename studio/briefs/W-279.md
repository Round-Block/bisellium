## Intent

`bisellium ci --opus <id>` runs the seven `CI_STEPS` in its loop (`packages/commands/src/ci.ts:53-61`, `:183-199`), then calls `runVerify` (`:201-223`). For this officina, `verify` runs `npm test -s`, `npm run -s lint` and `npm run -s typecheck` (`studio/bisellium.yml:40-42`, collected at `verify.ts:259-283`, run at `:314`). So the whole suite, lint and typecheck run twice in every host mint and every merge-queue `certify` (which reaches the same host mint, `scripts/ci-certify.mjs:195-215`).

After this opus, `ci --opus` first asks `verify` which commands it will run for the opus, and leaves those steps to `verify`. Every other step still runs in the loop. Without `--opus` nothing changes.

No applicable check is dropped while the plan's inputs stay unchanged (the Promise states the limits). A step leaves the loop only when `verify` itself says it will run that command. A waived gate, or a gate whose command differs from the step, keeps the step in the loop. The draft skipped the three steps unconditionally. That would drop the real suite whenever the opus's `tests` gate is waived, or when a candidate's manifest gives `tests` another command: the host mint reads the candidate's `studio/bisellium.yml`.

Lint today also walks `.worktrees/` (93 of 99 s, the audit), and Prettier does not ignore `.kilo/`. Both roots join both tools' ignores.

Threat model: mistakes, not adversaries (D-045).

## Interfaces

`RunVerifyOptions` gains `plan?: boolean`. Like `afterRead` (`verify.ts:47-50`), it is not a flag: no argv sets it, and only `ci.ts` passes it.

With `plan: true`, `runVerify` runs every read and refusal it runs today, through the waived/run split (`:276-283`). Then it returns `{ exitCode: 0, commands: runCommands }`. It runs no command, writes no state, gate, event or log, and calls no `afterRead`.

`RunVerifyResult` gains `commands?: Readonly<Record<string, string>>` (gate id to command). It is set only on a plan return. A plan that refuses returns today's exit code and message: an unknown opus, the record-owner refusal (`:188`), a dirty tree without `--allow-dirty` (`:231-234`), or effective-gate problems.

`handedToVerify(step, planned)`, private to `ci.ts`, returns true when some planned command equals `step` after both are split on single spaces and every `-s` token before the first `--` token is dropped. `-s` is npm's own silent flag, so `npm test -s` matches `npm test`. Any other difference fails to match, and the step stays in the loop. A mismatch can only cause a second run, never a dropped one.

The loop becomes `CI_STEPS`, minus audit under `--offline` (unchanged), minus every step `handedToVerify` accepts.

Checkout binding, not tree immutability: the loop and both `verify` calls use `execRepo` and the `HEAD` selector, but a retained step or local writer can change working files or move `HEAD` between them; `--ref` also deliberately forwards `--allow-dirty` (`ci.ts:210`, proven by `ci.test.ts` behaviour 10). `verify`'s dirty check still refuses or certifies `dirty:` under its existing rules. The binding:
- the loop runs each step with `cwd` `execRepo` (`ci.ts:184`);
- both `runVerify` calls get `--repo execRepo` (`:202`) and no `--commit`, so `HEAD` (`verify.ts:194`, `:213`);
- the local pipeline spawns every gate command with `cwd: opts.repo` (`packages/pipeline/src/index.ts:85`).

The plan and the real run select commands with the same code from the same record. Between the two reads, `ci` itself runs only the kept steps (audit, format check and the two officina checks), and none of them writes an opus record.

Records that name the moved steps stay true:
- **The probationes.** Gates `tests`, `lint` and `types` are still written only by `verify` (`verify.ts:331-337`). Each log names its command and certificate (`pipeline/src/index.ts:97-112`).
- **The host receipt.** It records only `gates: { ci: true, verify: true, check: true }`, after the one `ci --offline --opus` process exits 0 (`run-builder-host.mjs:855`, `:870`). That process still fails if any step or any gate fails. No receipt or CI step lists npm commands.
- **The workflow.** Its `gates` job runs `CI_STEPS` without `--opus`, so it is unchanged.

Execution environment: a moved step now runs under `verify`'s environment filter (`filterEnv`) with its output captured. Today's mints already run all three commands that way, inside the same `ci --opus` call, and pass.

The host mint runs `ci` from master's tooling (`run-builder-host.mjs:466`). The saving therefore starts with mints after this opus merges; this opus's own mint still runs the suite twice.

Promise each-check-once: in a successful `ci --opus` run, while the manifest and the opus's gate statuses remain unchanged between the plan and `verify`'s own read, and at most one unwaived gate normalises (`handedToVerify`) to each `CI_STEPS` command, each applicable `CI_STEPS` command (audit excepted under `--offline`) runs exactly once, either in the loop or as a `verify` gate — limit: a failing run may stop early; two unwaived gates that normalise to one step each run, so that step's check runs twice (the loop never adds a third); a nonmatching command may repeat an equivalent underlying check; `RunCiOptions.pipeline` (test-only, never set by `main.ts`) replaces the runner of the moved steps. The private host mint and `certify` checkout excludes external concurrent writers; local runs and retained commands do not guarantee this stability.

### Input domain

A rejection fails closed: `ci` exits non-zero before any step and writes nothing, or a test row fails.

| Record | Valid domain | Rejected by |
|---|---|---|
| Manifest automated probationes and the opus's gate statuses, read for the plan | what `runVerify` accepts today; a gate whose status is `waived` is not planned | `runVerify` (existing): manifest parse, `safeItemPath`/`readContainedRegularFile`, `recordOwnerRefusal`, the dirty check and `effectiveProbationes` problems end the plan non-zero, and `runCi` returns that code before the loop |
| A planned command | any string; it is matched to a step only by `handedToVerify` | `handedToVerify` (new): a command that does not match keeps its step in the loop |
| Test-only inputs of `w279.test.ts`: scratch repo and studio under `os.tmpdir()`, repo `eslint.config.mjs` and `.prettierignore` | created and removed by the test; the configs are read by ESLint and Prettier | `ESLint`/`prettier` (existing): an unreadable config throws and fails the row |

## Behaviours to test

1. **ci --opus drops no applicable CI_STEPS command and runs each once when the Promise's stability and uniqueness conditions hold.** `W-279-b1 behaviour 1: ci --opus drops no applicable CI_STEPS command and runs each once when the Promise's stability and uniqueness conditions hold` builds a scratch fixture on the `ci.test.ts` pattern:
   - a git repo whose npm scripts are `ORDER_MARKER`-style label writers appending to `order.log` (`ci.test.ts:57-82`);
   - a committed `.gitignore` naming `order.log`, so certificates read `tree:`;
   - a studio outside the repo, built with `initStudio` and `newItem`, whose automated probationes are this officina's three commands (`npm test -s`, `npm run -s lint`, `npm run -s typecheck`).

   The seam that counts runs without the real suite is `runCi`'s `--repo`: both the loop and `verify`'s pipeline run the fixture's package scripts there.
   - (a) `runCi(["--repo", repo, "--studio", studio, "--opus", id])` exits 0, and `order.log` is exactly `audit, format:check, check:studio, check:examples/sample-studio, test, lint, typecheck`. Each label appears once, and `test` appears once. The opus records `tests`, `lint` and `types` as `passed`, certifying `tree:`.
   - (b) On a fresh copy whose opus records `tests` as `status: waived`, the run exits 0. `order.log` holds `test` once, from the loop before `check:studio`, and `lint` and `typecheck` once each. `tests` stays waived.
   - (c) On a fresh copy whose manifest adds a fourth unwaived automated gate `tests-again` with command `npm test` (normalising to the same step as `npm test -s`), the run exits 0 and `order.log` is exactly `audit, format:check, check:studio, check:examples/sample-studio, test, lint, typecheck, test`: the loop runs no `test`, and the duplicate runs only as its own gate (the Promise's stated limit).

   **Genuine red:** `bisellium red W-279 --behaviour 1 --sella builder --studio studio -- node --test-reporter=tap --test-name-pattern='^W-279-b1 ' --import tsx packages/cli/src/w279.test.ts` prints `not ok 1 - W-279-b1 behaviour 1: ci --opus drops no applicable CI_STEPS command and runs each once when the Promise's stability and uniqueness conditions hold`. On master, (a)'s log holds `typecheck`, `lint` and `test` twice each.

2. **Lint and format ignore foreign worktree roots.** `W-279-b2 behaviour 2: lint and format ignore .worktrees and .kilo` uses the repo's own configuration, from the repo root.
   - `new ESLint().isPathIgnored(p)` is true for `.worktrees/W-900/source.ts` and `.kilo/worktrees/foreign/source.ts`, and false for `packages/commands/src/ci.ts`.
   - `prettier.getFileInfo(p, { ignorePath: ".prettierignore" })` gives `ignored: true` for the same two paths and `ignored: false` for `scripts/run-builder-host.mjs`.
   - Only `.prettierignore` is passed, so the row proves that file and not `.gitignore`, which already lists `.worktrees/`.

   **Genuine red:** after behaviour 1 lands, `bisellium red W-279 --behaviour 2 --sella builder --studio studio -- node --test-reporter=tap --test-name-pattern='^W-279-b2 ' --import tsx packages/cli/src/w279.test.ts` prints `not ok 1 - W-279-b2 behaviour 2: lint and format ignore .worktrees and .kilo`. ## Defaults for the Patron to veto

1. `CI_STEPS` and the GitHub workflow stay unchanged; only `ci --opus` hands steps to `verify`.
2. A step is handed over only when `verify`'s plan names its command (npm's `-s` aside). A waived or differently-commanded gate keeps its step. This replaces the draft's unconditional skip, which could drop the suite.
3. `ci --opus` now ends on a `verify` refusal (dirty tree, record owner, unknown opus) before running any step, where today it runs every step first.
4. A failing tests, lint or types gate under `ci --opus` reports its log path, not streamed output. In the host mint that log sits in a scratch checkout, and the merge group's `gates` job or a local `verify` reproduces the failure.
5. `docs/ADOPTION.md` is edited (code-owner) so the contract does not go stale. Veto it and the opus touches no code-owner path, but the ADOPTION `## Running ci` section's "in order" description becomes wrong for `--opus`.
6. Both ignore roots go into both tools, though Prettier already skips `.worktrees/` through `.gitignore`.
