## Intent

W-314 made the build-review perform read `prompts/build-review.md` and `prompts/later-round.md` from the main checkout's studio. Three reviewer-facing inputs are still the opus branch's, so an opus can still change the rules its own reviewer reads:

1. The build-review prompt names the QA charter and the lessons by relative path (`Charter: studio/leges/qa.md`, `reusing a class from studio/lessons/`), and `later-round.md` names the lessons the same way. The reviewer runs with the opus worktree as its working directory (`next.ts` `reviewSteps`, `cwd: wt.dir`), so it reads the branch's charter and lessons.
2. A spec re-review on the opus branch (an amended brief, `next.ts:846`) is ordered to hand-run the packet script with `--studio .worktrees/<id>/studio` (`packetLine`), and `buildPacket`, given no `promptStudio`, reads `prompts/later-round.md` from that studio: the branch's.
3. The same order tells the orchestrator to send `.worktrees/<id>/studio/prompts/rebuttal.md` for a dispute (`disputeLine(studioRel)`): the branch's rebuttal prompt.

After this opus each is the main checkout's. Both templates gain the slot `<STUDIO>`, filled with the main checkout's studio path (absolute), and name the charter and the lessons through it; the packet script's `promptStudio`, when not given, is the studio's place in the repository's main work tree (W-314's mechanism, extended, D-042); and the dispute line names the main checkout's studio, whichever studio the order is bound to. The opus's own evidence (its brief, spec logs, gate logs, reds and record) stays read on the branch: it is what is under review.

Cause fix: this closes W-314's two stated limits (its brief, Limits and Defaults 3) for the build and spec review paths.

Threat model: mistakes, not adversaries (D-045). The main checkout is the orchestrator's; its working copy is read as it stands.

Bootstrap: this opus is reviewed under master's ladder, never its own (Patron 2026-10-18). Its build round 1 runs master's `reviewSteps` from the main checkout, which fills master's `prompts/build-review.md` (six slots, no `<STUDIO>`) read from the main checkout's studio, which is master's text until this opus merges, not this opus's edited copy; that text names `studio/leges/qa.md` and `studio/lessons/` in the opus checkout, and this opus changes no file under `studio/leges/` or `studio/lessons/`, so those are master's copies at the branch point and the prompt's sentences hold for it. Its later build rounds take master's `buildPacket` with `promptStudio: f.studioAbs`, so master's `later-round.md` (four slots). Its spec rounds before `branch` take round 1 from the kept `fill-spec-review.sh` (the main checkout's `spec-review.md`) and later rounds from master's packet script with `--studio studio`, the main checkout. One case is a stated limit: a re-spec of this opus on its branch would run master's packet script, which reads this opus's branch `later-round.md` and leaves its `<STUDIO>` unfilled (the gap this opus closes, from the next opus). The new slot and text govern from the next opus.

## Interfaces

**`fillSlots`** (`next.ts`): the slot set is `<ID>`, `<ROUND>`, `<WORKTREE>`, `<PACKET>`, `<REVIEWED_HEAD>`, `<FOCUS>`, `<STUDIO>`, checked in that order; a template without one holds `prompts/build-review.md lacks the slot <S>`, as today. The review perform fills `<STUDIO>` with `f.studioAbs`, the `--studio` that `next` opened from the repository's main checkout, the same studio it reads `prompts/build-review.md` from (W-314).

**`fillTemplate`** (`review-packet.mjs`): the slot set is `<ID>`, `<ROUND>`, `<PREVIOUS>`, `<PACKET>`, `<STUDIO>`, checked in that order; a missing slot refuses `prompts/later-round.md lacks the slot <S>`, as today. `buildPacket` fills `<STUDIO>` with `promptStudio`, the studio the template was read from.

**`mainStudio(studio)`** (`review-packet.mjs`, not exported): `join(<main>, relative(realpath(<top>), realpath(studio)))`, where `<top>` is `git rev-parse --show-toplevel` run in `studio` and `<main>` is the path on the first `worktree ` line of `git worktree list --porcelain` run in `studio` (git lists the main work tree first). Each git call keeps `runGit`'s refusals; no `worktree ` line refuses `git worktree list names no main work tree`.

**`buildPacket(args)`**: for a later round, `promptStudio` is `args.promptStudio` when given, else `mainStudio(studio)`; it is computed only when the predecessor carries a session, so a round with no later-round prompt runs no new git call. The review perform passes `promptStudio: f.studioAbs`, unchanged. The CLI passes none, so a hand-run packet for a studio in a linked worktree reads the main checkout's `prompts/later-round.md`; for a studio in the main checkout `mainStudio` is that studio, so the read is unchanged.

**`disputeLine`** (`next.ts`): the spec-reviewer and censor orders name `<f.studioRel>/prompts/rebuttal.md`, the main checkout's studio relative to the repository root, whichever studio the rest of the order is bound to.

**`docs/ADOPTION.md`**, the `review` (W-274, part 1) paragraph:

- `fills the six slots of \`prompts/build-review.md\` read from the main checkout's studio, never the opus branch (\`<ID>\`, \`<ROUND>\`, \`<WORKTREE>\`, \`<PACKET>\`, \`<REVIEWED_HEAD>\`, \`<FOCUS>\`; a later round` becomes `fills the seven slots of \`prompts/build-review.md\` read from the main checkout's studio, never the opus branch (\`<ID>\`, \`<ROUND>\`, \`<WORKTREE>\`, \`<PACKET>\`, \`<REVIEWED_HEAD>\`, \`<FOCUS>\`, and \`<STUDIO>\`, that studio's path, where the reviewer reads the charter and the lessons; a later round`.

Promise main-rules: a build-review round's prompt names the main checkout's `leges/qa.md` and `lessons/` by absolute path, round 1 and every later round, and a template in the main checkout without `<STUDIO>` holds the perform before any Codex call — limit: the slot guarantees the path is in the prompt, not which sentence carries it; the shipped text carrying it is the code-owned prompts' (Acceptance); the main checkout's working copy is read as it stands.
