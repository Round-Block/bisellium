## Intent

The repeat S1 class `tests×one-sided-bound-assertion` came back in W-604's build review round 1 (`~/.bisellium-evidence/W-604-build/r1c/verdict.md`, finding 2): `W-604-b5` asserts each logged seconds value with `assert.ok(s >= 1.2, …)` only, so a log that also counts the reads check passes. Four cause fixes are done, each closing one syntactic form: W-334 (a digit grammar read through `Number`), W-376 (an assertion pattern anchored at one end, `startsWith`/`endsWith`), W-392 (a token boundary over part of the alphabet) and W-492 (a kill that changed the text it matched). A number compared on one side is a form none of them reads (W-376 brief:24 named it, W-317 and W-330, and left it to the reviews).

The fix extends W-376's `sidedForm` in `packages/cli/src/rules/tests.ts`: on an added or changed line of a test path, an `assert.ok(` or `assert(` whose first argument compares a number literal on one side only is a site, with its own message and the existing `// one-sided:` waiver. The form is narrow on purpose (D-085 D): it reads one comparison at the argument's top level with a literal on one side, and leaves a count, a found index, presence (0, 1, -1) and a `Math.abs` tolerance alone, because those are not measured values or are already two-sided. `studio/prompts/spec-draft.md` gains one line so the architect writes the bound into the behaviour row: a measured value states its exact value or both bounds, and the leak it must fail on, from the unpinned side.

What it would have caught (`census.out`): W-604's `w604.test.ts:170` (the reviewed b5 line, now on master). Its cost on master's existing lines, which the rule never judges (Promise old-lines): 24 lines over 227 test paths (`class-census.out`): 21 a real one-sided bound by intent (12 WCAG contrast floors, 1 contrast ceiling, 3 elapsed-time ceilings, 1 speed ceiling, 2 size caps, 1 poll cap, 1 research floor), W-604-b5's line, and W-604 fix1's pair `:180` and `:181`, which bound one value from both sides over two assertions; each of the pair is the form by design, since the message asks both bounds in one assertion, so a re-added pair is merged into one. A future opus that adds such a line again writes the exact value, both bounds, or a one-line reason.

Threat model: mistakes, not adversaries (D-045).

Promise numeric-form: with `--repo`, a line of a tracked test path added or changed since the merge-base with master whose `assert.ok(` or `assert(` first argument holds, at its top level (outside every bracket), exactly one `<`, `<=`, `>` or `>=`, a number literal on one side other than 0, 1 or -1, and on the other side no `.length` or `.size` count and no `Math.abs(` tolerance, and no annotation, is one `test.one_sided` block finding at `<name>:<line>` with the message `a number bounded on one side in an assertion: assert the exact value (assert.equal) or both bounds in one assertion (lo <= x && x <= hi), or annotate "// one-sided: <reason>"`, as pinned by `W-608-b1` "an added lower bound: one block at its line" and pinned by `W-608-b1` "W-604-b5: a measured value bounded from below" and pinned by `W-608-b1` "less than a separated literal" and pinned by `W-608-b1` "the literal on the left" and pinned by `W-608-b1` "one bound beside another condition" — limit: the rule reads one line's text through W-121's `lex`, so the forms Input row 1 names as limits are not judged and stay the reviews'.
