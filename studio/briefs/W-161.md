# W-161 — a brief names its input boundary, and admission refuses one that does not

Status: **signed spec, revision 1** · architect sella (claude-opus-5-5) · 2026-10-07.
The spec gate is written by `bisellium verdict W-161 --phase spec`, not by this text.

## Intent

Decree family: brief-admission

The decree: **every brief admitted to `building` has one Input domain
section. It is either a table that names each record the opus reads, the
valid domain of that record, and the one function that rejects anything
outside it and fails closed; or one line `None: <reason>` when the opus
reads no officina records. Brief admission refuses a brief without one.**

D-039 rates this high: the fail-open class
(`review×fail-open-on-malformed-records-patched-per-site`) is the most
recurrent open class in the design lessons, four lessons in one cascade.

- **L-069** (W-152, two failed rounds; W-153, five failed rounds and a
  sixth by exception). Each round found one more place where a damaged
  record slipped through, and each fix patched only that place. The class
  closed only when one validation at the input boundary fed every path.
  Cause named in the lesson: the briefs never named a valid input domain or
  a rejection point.
- **L-072** (W-120 r1 #2, r2 #1): malformed decision citations discarded by
  `str(...)`, then YAML `null` slipping past the fix.
- **L-074** (W-153 r1-r5): swallowed parse errors, `NaN`/`Infinity`, then
  out-of-range numbers, one per round.
- **L-077** (W-137 r1-r3): the verdict-log reader, one header form per
  round, before W-137 revision 2 named its Input domain table.

W-137 and W-163 applied this decree by hand, each with a `### Input domain`
table under Interfaces. Their review rounds then judged rows against the
table, not one site at a time. This opus makes that section an admission
rule, modelled on their shape.

**Extend, don't add (D-042).** Admission already lives in one text-only
predicate, `readBriefAdmission` in `packages/commands/src/brief-admission.ts`
(W-127, W-140). `ready` calls it before `building`, and the `brief.admission`
check rule calls it on active opera, both through `briefAdmissionProblems`.
The new clause is one more private reader in that file, behind the same
`brief_behaviour_limit` switch. No new rule id, manifest key, verb or
dependency. The receipt counters use only `countBehaviours`, which does not
change.

**How admission recognises "reads officina records": it does not guess; the
brief declares it.** Every brief carries the section, and a brief that reads
no records says so in one `None:` line. The alternative was to infer it from
the Files owned paths (non-test code outside `apps/web`). Measured below, that
trigger would demand a table from 15 of the 67 code briefs, whose owned code
calls no record reader (W-142's pipeline timeout constant is one), and it
cannot decide 2 briefs whose Files owned names no backticked path (W-089,
W-140). A trigger that cannot decide must then either refuse them, a false
positive, or admit them, which fails open: the very class this opus closes.
A declared line has no recognition step to get wrong. A docs-only or UI-only
brief is never asked for a table: it costs one line, and it is admitted. That
is 9 of 78 signed briefs. The table needs three columns because L-069's
cause had two parts, a missing domain and a missing rejection point, and the
third column names what the row is about. The rejection point must open with
one backticked function name, because "one place" is the decree: a reviewer
can then grep it, and a fix round can cite it. "Fails closed" must be stated,
because the lessons' failures were all silent skips and defaults, not
missing checks. Admission checks the shape, not the truth. Whether the named
function exists and really fails closed is the censor's judgment (default 3,
D-045).

## Interfaces

```ts
// packages/commands/src/brief-admission.ts — unchanged export, problems appended last
export function readBriefAdmission(briefText: string, limit: number): { problems: string[]; exception?: string };
function inputDomainProblems(real: string[]): string[]; // private; real = realLines(briefText)
```

**The section.** A real line (after `realLines` blanks fences and HTML
comments) that is exactly `## Input domain` or `### Input domain`, trailing
spaces aside. It runs to the next real line matching `^#{1,3} `, so a
`####` subheading stays inside. Either level is admitted: W-137 and W-163
nest it under Interfaces at `###`.

**The table form.** The table is the first run of consecutive real lines in
the section that start (after up to three spaces) with `|`. Its rules:

- Line 1 is the header. Cells split on unescaped `|` (`(?<!\\)\|`), after
  one leading and one trailing `|` are dropped, and each cell is trimmed. So
  `(blocking\|advisory)` stays one cell, as in W-137. The header must have a
  cell equal to `Valid domain` and a cell equal to `Rejected by`, ignoring
  case. The first column names what the row is about (W-137 says `Record`,
  W-163 says `Input`), and any non-empty name is admitted.
- Line 2 is a delimiter row: `|`-separated cells of `:?-{3,}:?`.
- Every later line is a data row, and there must be at least one. A data row
  has as many cells as the header, and none is empty.
- A data row's `Rejected by` cell opens with one backticked name
  (`` ^`[^`]+` ``): the one rejecting function, file or verb. Prose may
  follow it.
- Somewhere in the section, table or prose, the words `fails closed` appear,
  ignoring case.

**The `None:` form.** Exactly one real line in the section matches
`^None:\s*\S`, and the section has no table.

**Problems**, in this order, appended after every existing admission
problem. `${k}` is the 1-based data row.

| When | Problem text |
|---|---|
| no section (NO_DOMAIN) | `declares no input domain; add one "## Input domain" section: a table with "Valid domain" and "Rejected by" columns, or one line "None: <reason>" if it reads no officina records` |
| more than one heading | `has ${n} "Input domain" headings; one section only` (and nothing else from this reader) |
| a `None:` line together with a table, or two `None:` lines | `input domain mixes "None:" with a table or repeats it; one table or one "None: <reason>" line` (and nothing else from this reader) |
| no `None:` line and no admissible header or delimiter row, or no data row (NO_TABLE) | `input domain has no table with "Valid domain" and "Rejected by" columns and at least one row` |
| a data row with an empty or missing cell | `input domain row ${k} has an empty or missing cell` |
| a data row whose `Rejected by` cell does not open with a backticked name | ``input domain row ${k} names no rejecting function; its "Rejected by" cell opens with one `name` `` |
| a table section without `fails closed` | `input domain does not say that a rejection fails closed` |

A row with an empty cell reports only the empty-cell problem. The
`fails closed` problem is reported whenever NO_TABLE is not, row problems
or not.

The fixture default, under `## Input domain`:

```md
Each record has one valid domain and one rejecting function; a rejection fails closed.

| Record | Valid domain | Rejected by |
|---|---|---|
| fixture record | a string | `readFixture` |
```

### Input domain

This opus reads one officina record, the brief, and changes how its text is
judged. A rejection fails closed: a section the reader cannot place is a
problem, never skipped and never read as `None:`. The whole brief is refused,
`ready` exits 1 and writes nothing, and `check` blocks `brief.admission` on
an active opus.

| Record | Valid domain | Rejected by |
|---|---|---|
| a brief's Input domain section | The section, table form and `None:` form above, read from `realLines` (fenced blocks and HTML comments blanked). Anything else, including a heading at another level, a table with no data row, an empty cell, an unbackticked rejection point, or a second heading, is outside the domain. | `readBriefAdmission`, through `briefAdmissionProblems`, which `ready` and `check` already share. |
| the brief file itself | Unchanged: a relative path under `briefs/`, a regular file, no symlink in any component. | `readContainedRegularFile`, already called by `runReady` and by `check` before admission. |

## Behaviours to test

Every row runs in `packages/cli/src/brief-admission.test.ts`. Each is a
`node:test` named `W-161-b<n> behaviour <n>: …`, selected by
`--test-name-pattern=W-161-b<n>`. The rows drive `runReady` with the existing
`ready()` helper on a copy of `examples/sample-studio` with
`brief_behaviour_limit: 6`. They compare its stderr by `deepEqual` against
`line(problem)`, assert that the opus file is byte-identical and that the
events are unchanged on refusal, and assert exit 0 on admission. No row
writes in `studio/` or `examples/`. Each behaviour's implementation leaves
the next one red (D-036): each adds a condition the previous one did not
check.

1. **A brief with no Input domain section is refused, by `ready` and by `check`.**
   - `brief({ domain: [] })` makes `ready` exit 1 with exactly
     `[line(NO_DOMAIN)]`.
   - The default `brief()` is admitted.
   - The section heading inside a fenced block, or inside an HTML comment,
     with the real one removed, gives `[line(NO_DOMAIN)]`.
   - `#### Input domain` gives `[line(NO_DOMAIN)]`.
   - Two real `## Input domain` sections, each valid, give
     `[line('has 2 "Input domain" headings; one section only')]`.
   - `checkStudio` on the copy, with W-900 `building` (its `spec:` set and a
     passed `spec` gate) and `domain: []`, yields exactly one
     `brief.admission` block, ending in NO_DOMAIN.
   - With W-900 `done`, the same brief yields no `brief.admission` finding.
   - With no `brief_behaviour_limit` key (`ABSENT`), `ready` admits the
     brief.

   **Genuine red:** today `ready` admits `brief({ domain: [] })` with exit 0; the row fails on its exit-code `equal`.

2. **The section must hold a table with a valid domain and a rejection point, and at least one complete row.**
   - A section of prose only, or with a header and no data row, or with
     columns `Record | Domain | Checked by`, gives
     `[line(NO_TABLE)]`.
   - A row with an empty `Valid domain` cell, and a row with one cell
     fewer than the header, each give
     `[line("input domain row 1 has an empty or missing cell")]`.
   - A W-137-style cell holding `(blocking\|advisory)` stays one cell, and
     the brief is admitted.
   - Upper-case `VALID DOMAIN | REJECTED BY` headers are admitted.

   **Genuine red:** after behaviour 1, a section holding only the prose line is admitted with exit 0; the row fails on its exit-code `equal`.

3. **Every row names its one rejecting function.**
   - A second data row whose `Rejected by` cell is `the parser` gives
     ``[line('input domain row 2 names no rejecting function; its "Rejected by" cell opens with one `name`')]``.
   - `` `instant` (schema), the one parser `` is admitted, as in W-163.
   - `` see `readOpusVerdicts` `` (backtick not first) is refused as row 1.

   **Genuine red:** after behaviour 2, the `the parser` row is admitted with exit 0; the row fails on its exit-code `equal`.

4. **A table section says that a rejection fails closed.**
   - The default table with its prose line removed gives
     `[line("input domain does not say that a rejection fails closed")]`.
   - `Fails closed` inside a table cell is admitted.
   - A table with an empty cell and no `fails closed` gives the row problem,
     then this one, in that order.

   **Genuine red:** after behaviour 3, the table without the phrase is admitted with exit 0; the row fails on its exit-code `equal`.

5. **A brief that reads no records declares `None:` instead of a table, once.**
   - A section holding only `None: docs only, reads no officina records` is
     admitted.
   - `None:` with nothing after it gives `[line(NO_TABLE)]`.
   - A `None:` line plus a valid table, and two `None:` lines, each give
     `[line('input domain mixes "None:" with a table or repeats it; one table or one "None: <reason>" line')]`.
   - A `None:` line in a fenced block, with no other content, gives
     `[line(NO_TABLE)]`.

   **Genuine red:** after behaviour 4, the `None:`-only section is refused with `[line(NO_TABLE)]`; the row fails on its exit-code `equal`.

## Out of scope

- **Checking the truth of a row.** Admission does not look up the named
  function in the source, nor check that it fails closed. The censor judges
  that against the code (default 3).
- **Re-signing the 23 parked specs.** Each is re-signed when its opus goes
  to `ready`, as W-127 left them.
- **Inferring the trigger from Files owned.** Measured above and not built
  (default 1).
- **The design lex text, the architect agent file, and the brief
  template.** The rule is enforced by admission and documented in
  `docs/ADOPTION.md`. Process enforcement is a rule, not prose (default 5).
- **A second table in the section.** Only the first is read (default 6).
- **Deliberate evasion** (D-045), such as a table of placeholder rows that
  satisfies the shape. A builder or architect does not write this by
  mistake, and review reads the rows.

## Defaults for the Patron to veto

Each ships as stated and can be overturned at the checkpoint.

1. **Every new spec says what it reads, even when it reads nothing.** A
   spec that reads no studio records writes one line, `None: <reason>`. The
   tool does not guess from the spec's file list. Guessing would have
   wrongly demanded a table from 15 of 67 code specs, and could not decide
   2 at all.
2. **Old specs are left alone.** Only specs entering building, and those
   already building, are checked. Finished ones are never re-read. The 23
   parked specs already need re-signing under the earlier rule, so nothing
   breaks today.
3. **The check reads the shape, not the truth.** It checks that each row
   names a valid range and one rejecting function. Whether that function
   exists and really refuses bad input is the reviewer's call.
4. **It uses the existing on-switch.** It applies only where a studio
   already sets the behaviour limit. The sample studio is unaffected, and
   there is no new setting.
5. **The design rules text is not amended.** The admission check and the
   adoption guide carry the rule, since process rules live in checks, not
   prose.
6. **Only the first table in the section is read.** Extra tables are
   allowed as notes and are not checked.
