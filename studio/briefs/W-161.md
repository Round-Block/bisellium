# W-161 — a brief names its input boundary, and admission refuses one that does not

Status: **signed spec, revision 3** · architect sella (claude-opus-5-5) · 2026-10-07.

Revision 3 answers round 2's one finding: the Input domain also lists the

## Intent

Decree family: brief-admission

The decree: **every brief admitted to `building` has one Input domain
section. It is either a table that names each record the opus reads, the
valid domain of that record, and the one function that rejects anything
outside it and fails closed; or one line `None: <reason>` when the opus
reads no officina records. Brief admission refuses a brief without one.**

D-039 rates this high: the fail-open class
(`review×fail-open-on-malformed-records-patched-per-site`) is the most
recurrent open class in the design lessons, four lessons in one cascade.

- **L-069** (W-152, two failed rounds; W-153, five failed rounds and a
  sixth by exception). Each round found one more place where a damaged
  record slipped through, and each fix patched only that place. The class
  closed only when one validation at the input boundary fed every path.
  Cause named in the lesson: the briefs never named a valid input domain or
  a rejection point.
- **L-072** (W-120 r1 #2, r2 #1): malformed decision citations discarded by
  `str(...)`, then YAML `null` slipping past the fix.
- **L-074** (W-153 r1-r5): swallowed parse errors, `NaN`/`Infinity`, then
  out-of-range numbers, one per round.
- **L-077** (W-137 r1-r3): the verdict-log reader, one header form per
  round, before W-137 revision 2 named its Input domain table.

W-137 and W-163 applied this decree by hand, each with a `### Input domain`
table under Interfaces. Their review rounds then judged rows against the
table, not one site at a time. This opus makes that section an admission
rule, modelled on their shape.

**Extend, don't add (D-042).** Admission already lives in one text-only
predicate, `readBriefAdmission` in `packages/commands/src/brief-admission.ts`
(W-127, W-140). `ready` calls it before `building`, and the `brief.admission`
check rule calls it on active opera, both through `briefAdmissionProblems`.
The new clause is one more private reader in that file, behind the same
`brief_behaviour_limit` switch. That switch is read today in two places
(`runReady` and `checkStudio`, each inline); it moves into one exported
reader, `readBriefLimit`, in the same file. No new rule id, manifest key,
verb or dependency. The receipt counters use only `countBehaviours`, which does not
change.

**How admission recognises "reads officina records": it does not guess; the
brief declares it.** Every brief carries the section, and a brief that reads
no records says so in one `None:` line. The alternative was to infer it from
the Files owned paths (non-test code outside `apps/web`). Measured below, that
trigger would demand a table from 15 of the 67 code briefs, whose owned code
calls no record reader (W-142's pipeline timeout constant is one), and it
cannot decide 2 briefs whose Files owned names no backticked path (W-089,
W-140). A trigger that cannot decide must then either refuse them, a false
positive, or admit them, which fails open: the very class this opus closes.
A declared line has no recognition step to get wrong. A docs-only or UI-only
brief is never asked for a table: it costs one line, and it is admitted. That
is 9 of 78 signed briefs. The table has exactly three columns, in order:
`Record` (or `Input`), `Valid domain`, `Rejected by`. L-069's cause had two
parts, a missing domain and a missing rejection point, and the first column
names the record the row is about, so a table that names no record is
refused. The rejection point opens with one backticked function name
(an identifier or `module.fn`, optionally with its arguments), because "one
place" is the decree: a reviewer can then grep it, and a fix round can cite
it. A file or a verb is not a function. "Fails closed" must be stated,
because the lessons' failures were all silent skips and defaults, not
missing checks. Admission checks the shape, not the truth: it does not look
up the named function in the source. That is a stated limit. The threat model
is mistakes, not adversaries (D-045), and whether the function exists and
really fails closed is the censor's judgment (default 3).

**The section.** A real line (after `realLines` blanks fences and HTML
comments) that is exactly `## Input domain` or `### Input domain`, trailing
spaces aside. It runs to the next real line matching `^#{1,3} `, so a
`####` subheading stays inside. Either level is admitted: W-137 and W-163
nest it under Interfaces at `###`.

**The table form.** The table is the first run of consecutive real lines in
the section that start (after up to three spaces) with `|`. Its rules:

- Line 1 is the header. Cells split on unescaped `|` (`(?<!\\)\|`), after
  one leading and one trailing `|` are dropped, and each cell is trimmed. So
  `(blocking\|advisory)` stays one cell, as in W-137. The header has exactly
  three cells, in this order, ignoring case: `Record` or `Input` (W-137 says
  `Record`, W-163 says `Input`), then `Valid domain`, then `Rejected by`.
- Line 2 is a delimiter row: `|`-separated cells of `:?-{3,}:?`.
- Every later line is a data row, and there must be at least one. A data row
  has three cells, and none is empty, so every row names its record.
- A data row's `Rejected by` cell opens with one backticked function name:
  `` ^`[A-Za-z_$][\w$]*(\.[A-Za-z_$][\w$]*)?(\([^`]*\))?` ``. That is an
  identifier or `module.fn`, optionally with its arguments, such as
  `` `readOpusVerdicts(root, id)` ``. A file name (`` `containment.test.ts` ``
  has two dots) or a command line is refused. Prose may follow the name.
  Admission does not check that the function exists (Intent, default 3).
- Somewhere in the section, table or prose, the words `fails closed` appear,
  ignoring case.

**The `None:` form.** Every real line in the section that starts `None:` is
counted, empty or not. The form needs exactly one, it must match
`^None:\s*\S`, and the section has no table.

**Problems**, in this order, appended after every existing admission
problem. `${k}` is the 1-based data row.

| When | Problem text |
|---|---|
| no section (NO_DOMAIN) | `declares no input domain; add one "## Input domain" section: a table with "Record", "Valid domain" and "Rejected by" columns, or one line "None: <reason>" if it reads no officina records` |
| more than one heading | `has ${n} "Input domain" headings; one section only` (and nothing else from this reader) |
| a `None:` line together with a table, or two `None:` lines, empty or not (MIX) | `input domain mixes "None:" with a table or repeats it; one table or one "None: <reason>" line` (and nothing else from this reader) |
| one `None:` line with no reason and no table | `input domain "None:" line gives no reason` (and nothing else from this reader) |
| no `None:` line, and no admissible header or delimiter row, or no data row (NO_TABLE) | `input domain has no table with "Record", "Valid domain" and "Rejected by" columns and at least one row` |
| a data row with an empty or missing cell | `input domain row ${k} has an empty or missing cell` |
| a data row whose `Rejected by` cell does not open with a backticked function name | ``input domain row ${k} names no rejecting function; its "Rejected by" cell opens with one `function` name `` |
| a table section without `fails closed` | `input domain does not say that a rejection fails closed` |

A row with an empty cell reports only the empty-cell problem. The
`fails closed` problem is reported whenever NO_TABLE is not, row problems
or not.

### Input domain

This opus reads the manifest's admission switch, the opus record that
points at a brief, and the brief. On an over-limit brief with an exception,
the shared admission path also reads the design magister and one decision
record. Each has one valid
domain and one function that rejects anything outside it. A rejection fails
closed: it is never skipped, never read as absent, `None:` or a default.
`ready` exits non-zero and writes nothing, and `check` blocks.

| Record | Valid domain | Rejected by |
|---|---|---|
| `bisellium.yml#brief_behaviour_limit` | Absent (no admission at all), or a positive integer. `null`, `0`, a fraction, a string or any other value is outside the domain. | `readBriefLimit`. `ready` turns its error into `<id>: brief.admission: brief_behaviour_limit must be a positive integer` and exit 1; `check` turns it into a `manifest.shape` block and runs no admission. |
| the opus record, at `ready` | `state` is `greenlit` or `halted`, and the spec path (`--spec`, else `briefs/<id>.md`) is contained in the officina. Any other state, or an escaping path, is outside the domain. | `runReady`, unchanged: exit 2, nothing written. |
| the opus record, at `check` | `state` is a declared lifecycle id (else `opus.keys` or `opus.state` blocks, unchanged). ## Out of scope

- **Checking the truth of a row.** Admission checks that the rejecting place
  has the shape of one function name. It does not look up the function in
  the source, nor check that it fails closed. That is a stated limit, under
  D-045's threat model of mistakes, not adversaries. The censor judges it
  against the code (default 3).
- **Re-signing the 23 parked specs.** Each is re-signed when its opus goes
  to `ready`, as W-127 left them.
- **Inferring the trigger from Files owned.** Measured above and not built
  (default 1).
- **The design lex text, the architect agent file, and the brief
  template.** The rule is enforced by admission and documented in
  `docs/ADOPTION.md`. Process enforcement is a rule, not prose (default 5).
- **A second table in the section.** Only the first is read (default 6).
- **Deliberate evasion** (D-045), such as a table of placeholder rows that
  satisfies the shape. A builder or architect does not write this by
  mistake, and review reads the rows.

## Defaults for the Patron to veto

Each ships as stated and can be overturned at the checkpoint.

1. **Every new spec says what it reads, even when it reads nothing.** A
   spec that reads no studio records writes one line, `None: <reason>`. The
   tool does not guess from the spec's file list. Guessing would have
   wrongly demanded a table from 15 of 67 code specs, and could not decide
   2 at all.
2. **Old specs are left alone.** Only specs entering building, and those
   already building, are checked. Finished ones are never re-read. The 23
   parked specs already need re-signing under the earlier rule, so nothing
   breaks today.
3. **The check reads the shape, not the truth.** It checks that each row
   names a record, a valid range and one rejecting function by name.
   Whether that function exists and really refuses bad input is the
   reviewer's call.
4. **It uses the existing on-switch.** It applies only where a studio
   already sets the behaviour limit. The sample studio is unaffected, and
   there is no new setting.
5. **The design rules text is not amended.** The admission check and the
   adoption guide carry the rule, since process rules live in checks, not
   prose.
6. **Only the first table in the section is read.** Extra tables are
   allowed as notes and are not checked.
