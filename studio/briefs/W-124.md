## Intent

The cascade has an order (greenlit, spec signed, two-phase build with reds at
a clean tree, review rounds, a PR rebased on the fetched trunk, the merge gate,
cleanup, done, checkpoint). Today that order lives in the producer's memory, in
`docs/SESSION-HANDOFF.md` traps, and in two shell scripts. Every recurring
mistake of the last cascades was a skipped or reordered step: PR 127 closed by a
cleanup chained on the wrong step; PRs opened un-rebased; a green PR left BEHIND
and stalled; `done` run before the merge reached the local trunk; and on
2026-10-02 a dead gate chain reported healthy for four hours.

`bisellium next <opus>` derives, from the record and its evidence alone, the
one legal next step; it **names** the step (with the exact command or dispatch
order) or, with `--perform`, **performs** it, and it refuses to skip. The kept
scripts retire as their steps become verbs (Patron, 2026-10-01).

**One decree family:** the ordering and refusal verb itself, plus the three
standing rules that are properties of that same verb (stale-step health,
dispatch context caps, complete = merged + fetched). Per W-127's rule (not yet
built, honoured here) everything else is a named follow-on, never folded in:
model-tier delegation per munus (W-117), verdict grammar (W-126), recording the
sec-lead input, recording the declared dispatch budget as an event, and PR steps
for non-opus heads (`spec/<id>`, `chore/done-<id>`). See "Follow-on filings".

## Interfaces

### Grammar and result

```text
bisellium next <opus> [--perform] [--expect <step>] [--budget <tokens>]
    [--title <text> --body-file <path>] [--poll-ms <n>] [--max-polls <n>]
    [--studio <dir>] [--repo <dir>] [--now <iso>]
bisellium next <opus> --track <step> --pid <n> --output <path> [--studio <dir>] [--repo <dir>] [--now <iso>]
```

Flags parse the house way (`parseFlags`, strict allowlist, own argv in
`main.ts`). The usage text lives in `packages/commands/src/usage.ts` (the banner
lines) and is repeated, line for line, in one `NEXT_USAGE` constant in
`next.ts`; `usage.test.ts` carries the new count (see Files owned).

Argument rules (exit 2, before any derivation, nothing written):
`<opus>` goes through the shared containment helper (`safeItemPath`); `--budget`
must match `^[1-9][0-9]{0,9}$`; `--poll-ms` is an integer 1..60000 (default
20000) and `--max-polls` an integer 1..1000 (default 60); `--title` is at most
256 characters with no line break; `--body-file` must be a regular file of at
most 64 KiB whose realpath lies under the repo or `os.tmpdir()`; `--expect` and
`--track` must name a member of `STEPS`, and `--track` additionally not
`greenlight` or `checkpoint`; `--now` is accepted **only** when
`BISELLIUM_TEST_CLOCK=1` is in the environment and is otherwise a usage error
(production health uses the real clock, so a caller cannot choose the age).

Exit codes: 0 step named, performed, or a live step reported running; 1 refused,
held, dead, or a performed step failed; 2 usage, unknown opus, not a studio, not
the main checkout. Default is report-only; nothing is written without
`--perform` (or `--track`). First stdout line:
`next: <opus> <step> <named|performed|held|running|dead|complete>`, then
`key: value` lines (`command:`, `actor:`, `head:`, `health:`, `why:` naming the
evidence read). `running` is a header word, not an exit code: it exits 0, and an
orchestrator must read the word (documented in ADOPTION). A step whose rung is
now met by evidence is reported as a `health: finished <step>` line, never as a
status word. `state=<X>` lines (the scripts' vocabulary: `CONFLICT`,
`CHECKS_FAILED`, `GHAS_STOP`, `MERGE_FAILED`, `QUEUE_REJECTED`, `QUEUE_TIMEOUT`,
`MERGED`) are printed verbatim by performed `pr`/`merge`/`cleanup` steps so
parity rows can compare terminal states.

`gh` and `git` are spawned by bare name through `PATH` with argument arrays; no
shell. This is documented (tests put a stub `gh` first on `PATH`), not pinned.
In report mode there is no network except `gh` read calls for the PR rungs; the
remote-tracking ref read for `cleanup` is therefore possibly stale in report
mode and a `--perform` fetches with `--prune` first.

**Where `next` runs.** From the repository's **main checkout** (not a linked
worktree), with `--repo` naming it; otherwise exit 2 naming the main checkout.
It reads opus-branch evidence (record, `ci/`, reds, receipt) from the opus's
registered worktree `<repo>/.worktrees/<id>` when that exists, and trunk-side
evidence (brief, spec log, `done`, checkpoint) from the **committed** trunk ref
`refs/heads/master` with `git show`, never from a working tree. The verbs `next`
spawns (`ready`, `done`) run with their cwd where D-021 expects the write (the
opus worktree for `ready`, the main checkout for `done`) and any refusal is
relayed unchanged (`held`, exit 1).

**Dirty.** "Dirty" means tracked changes only: `git status --porcelain
--untracked-files=no` is non-empty (staged or unstaged). Untracked files,
including the untracked `.worktrees/` directory and the gitignored
`.bisellium/` directory, never make a tree dirty. (`open-pr.sh` is stricter;
the divergence is a named row.)

### The ladder (the single ordering; exported as `STEPS`)

The next step is the first rung whose evidence is unmet. A rung is also settled
in either of two ways, and no other: (1) the committed trunk record for the opus
already has state `done`, which settles every rung up to and including `done`
without any `gh` call; (2) the opus's PR is settled by reachability (below), so a
merged opus whose branch is gone does not walk back to `branch`. `done` still
re-checks its own gates.

**PR identity.** A candidate PR is read with one fixed call, `gh pr list -R
<slug> --head opus/<id> --state all --limit 20 --json
number,state,mergeStateStatus,headRefName,headRefOid,baseRefName,isCrossRepository,headRepositoryOwner,headRepository,mergeCommit`.
`<slug>` is `nameWithOwner` from `gh repo view`, validated against
`^[A-Za-z0-9_.-]+/[A-Za-z0-9_.-]+$` and pinned as `-R` on every later call. A
candidate counts only if `headRefName == opus/<id>`, `baseRefName == master`,
`isCrossRepository` is false, its head repository equals `<slug>`, and `number`
is a positive integer. Zero candidates: no PR. More than one OPEN candidate:
`held` (ambiguous), nothing performed. Exactly one OPEN: that PR. Otherwise the
highest-numbered MERGED candidate; CLOSED-only is no PR. The tuple (number,
headRefName, headRefOid, baseRefName, repo) is carried into every later call.

**Settlement by reachability.** A MERGED candidate settles the rungs up to
`merge` only if its `mergeCommit.oid` is contained in the local trunk by
`trunkContainsMerge` AND, when `refs/heads/opus/<id>` still exists locally, the
local tip equals `headRefOid` or is an ancestor of it (an unfetched
`headRefOid` is "unverifiable", which leaves the step at `merge`, whose perform
fetches `refs/remotes/origin/opus/<id>` and re-checks). A name match alone
never settles a rung.

**Merged-not-contained makes the step `merge`.** An identity-verified MERGED
candidate whose `mergeCommit.oid` is not yet contained in the local trunk makes
the step `merge`, whether or not `refs/heads/opus/<id>` exists locally. The
`merge` perform for a MERGED PR is a fetch of `master:master` (and of
`refs/remotes/origin/opus/<id>` when the local branch exists) followed by a
re-check of `trunkContainsMerge`: contained prints `state=MERGED` and the next
derivation moves on; still not contained is `held` naming the merge commit. It
issues no `update-branch` and no `merge` call. `branch` is never named or
performed for an opus that has an identity-verified MERGED PR: the `branch` rung
reads PR identity before it can be named, so a gone branch on a merged opus
cannot walk the ladder back. (A present local tip that is neither the
`headRefOid` nor its ancestor is a different case, unchanged: it settles nothing.)

**Performed `done` (post-merge lifecycle).** After `cleanup`, from the main
checkout on `master` at the `master` tip, tracked-clean: `next` creates
`chore/done-<id>` at that tip, runs the existing `done <id> --sella producer
--studio <studio>`, requires that the only tracked change is
`<studio>/opera/<id>.md`, stages exactly that path, and commits it with message
`chore(studio): mark <id> done` and the trailer `Co-Authored-By: producer

`done` refuses, nothing is committed and the empty branch is deleted by compare
and swap (`git update-ref -d refs/heads/chore/done-<id> <creation tip>`); if any

scripts, so a performed `done` never loops: the next call names the landing, it
does not re-perform. `next` never sets or changes `BISELLIUM_ROLE`; `done` runs
under the caller's own role environment and its refusal, if any, is relayed.

### Step health marker (behaviour 5)

`<repo>/.bisellium/steps/<opus>.json`: `{schema:1, opus, step, pid,
start_ticks, started, output, budget_seconds, writer}`, `writer` being `perform`
or `track`. The directory is already ignored by the existing `.gitignore` entry
`.bisellium/` and is in `verify`'s exclusions, so a marker perturbs neither the
dirty test nor the SOURCE tree.

- **Written by the verb.** `next --perform` writes the marker itself (pid =
  its own pid, `start_ticks` read from `/proc/self/stat` field 22, `output` =
  `steps/<opus>.log` which the verb appends one line to per action and per poll)
  before any long step, and removes it on normal exit. Crash leaves it; health
  then reads `dead`. An existing marker is handled by the same rule as
  `--track`'s: live refuses, `unknown` refuses (`held`), dead is taken over by
  the unlink-if-unchanged then exclusive-create rule below, a second `EEXIST`
  refusing.
- **`--track`** registers a step an orchestrator launched itself (`writer:
  track`, unverified, labelled so in the report). The pid must be an integer > 1,
  not `next`'s own pid or its parent's; `/proc/<pid>/stat` must exist, be readable and parse, and not be
  a zombie (an unreadable or unparseable entry is `unknown`: refused), and `next` reads `start_ticks` itself (the caller supplies none).
  `<step>` must equal the currently derived rung. `--output` must resolve, via
  `readContainedRegularFile` (`@bisellium/commands/opus-model.js`) with root
  `<repo>/.bisellium` and first component `steps`, to a regular file under
  `.bisellium/steps/`, no symlink in any component (an orchestrator's gate log
  must be written or teed there). Create is exclusive (`wx`); an existing live
  marker refuses, an existing `unknown` one refuses, and an existing dead one is
  taken over by the rule below.
- **Liveness** is `/proc/<pid>/stat` present, not state `Z`, and field 22 equal to
  the marker's `start_ticks` (a reused pid has another start time, so it reads
  dead). Field 22 is parsed from the text **after the last `)`** of the stat line
  (the `comm` field may itself contain spaces and parentheses): split that
  remainder on whitespace, whose first token is field 3 (the state), so field 22
  is the token at index 19. The per-pid read has three outcomes only: `ENOENT`
  is absent, hence `dead`; success that parses is read as above; **any other
  read failure** (`EACCES`, `EIO`, `EISDIR`, `EMFILE`, anything not `ENOENT`) **or
  a read that does not parse** (no `)`, fewer than 20 tokens after it, a state
  that is not one letter, a field 22 that is not a positive integer) yields
  `unknown`. `unknown` is `held`, never `dead`: the step line says `held`, `health:
  unknown (<code or reason>)`, exit 1, nothing performed, no marker replaced or
  unlinked; `--track` refuses on it. On a host without `/proc`, `--track` refuses
  and health reports `unknown`. Only a proven absence or a proven mismatch may
  ever read `dead`. The `/proc` root is `/proc`; a test-only
  `BISELLIUM_TEST_PROC=<dir>` replaces it, honoured **only** when
  `BISELLIUM_TEST_CLOCK=1` is also set (otherwise ignored), so rows can present an
  unreadable or unparseable `<pid>/stat` without privileges.
- **Takeover of a dead marker** (`--track` and `--perform` alike): read the
  marker, prove it `dead`, unlink it only if it is unchanged since that read
  (same inode, size and mtime), then create exclusively (`wx`); a second `EEXIST`
  refuses. The check and the unlink are two calls, so two takers can race (see
  Stated residual 10).
- **Freshness**: age = `--now` (test-guarded) or the real clock, minus the output
  file's mtime. An age more than 5 seconds negative is a clock anomaly, `held`,
  nothing performed; 0 to 5 negative counts as 0.
- **Cross-check**: a marker whose `step` is not the derived rung is never
  `running`. If the derived rung is later than the marker's step, health is
  `finished <step>`; if earlier, `stale marker (evidence regressed)`.
- **Output is data**: only the last 4096 bytes are read, the last non-empty line
  is control-character-stripped, clipped to 200 characters and printed as a
  JSON-quoted `last-output:` value, never interpreted.
- **Take, then re-derive.** `--perform` takes the marker first, then derives the
  rung again, then checks `--expect` against that second derivation, then acts.

### Dispatch order (behaviour 6)

Dispatch steps (`spec`, `reds`, `build`, `review`) print an order, not a
command to be guessed: `role:`, `sella:` (from the manifest), `budget_tokens:`,
`phase:`, `inputs:` (the brief, and the opus record's `traditio` handover block;
for `review` also the evidence logs and the ui-lead input path), `command:`.

## Stated residuals (accepted, with reason)

1. **`--track` is an attestation.** `next` cannot prove a registered pid is the
   step the caller says. It is bounded: pid > 1 and not self/parent, `/proc` start
   time bound, step equal to the derived rung, exclusive create, output contained
   and fresh. The worst effect is that `--perform` of that rung refuses until the
   pid dies or its output goes stale; `--track` never makes `next` perform or skip
   anything.
2. **Branch-gone settlement.** After cleanup, a MERGED PR for `opus/<id>` is
   settled by identity (head name, base, repo, number) plus trunk containment,
   without a local branch tip to compare. Opus ids are allocated once, so a
   recycled branch name merged by an unrelated PR is not addressed further. The
   committed trunk record `done` settles the same rungs without any `gh` call,
   but that covers **only the already-done case**; it is not evidence for an opus
   whose record is not yet `done`, so for that case identity plus containment is
   the whole of the evidence, and that is what is accepted.
3. **Linux only.** Liveness uses `/proc`; node/npm/git run in WSL only
   (`CLAUDE.md`), so no portable fallback is built. Elsewhere `--track` refuses.
4. **No check rule for the TAP red form on W-124** (`opus.red_assertion` is pinned
   to W-096); replay and the censor carry it. Generalising the rule is filed, not
   folded.
5. **Captured-fixture stubs replay, they do not prove live `gh`.** The shapes are
   real; behaviour against live GitHub is the live-proof acceptance.
6. **Trunk is the literal `master`**, as in both scripts.
7. **`running` is a header word at exit 0, not a distinct exit code.** An exit
   code would be a new orchestrator contract; the word is documented.
8. **`gh`/`git` resolve through `PATH`** (documented), because the tests rely on a
   stub first on `PATH`.
9. **`--budget` is attestation, not measurement** (documented in ADOPTION).
10. **Dead-marker takeover has a narrow two-taker race.** Unlink-if-unchanged is a
    check followed by an unlink, not one atomic step: two takers that both proved
    the same marker dead can interleave so the second unlinks the first's freshly
    created marker, and both then believe they hold the step. The window is the
    gap between two syscalls, and both takers must have read the same dead marker.
    Accepted because the marker is a health record, not a lock on the work: each
    mutating call stays separately guarded (`--match-head-commit`,
    `--force-with-lease`, the compare-and-swap `update-ref`, the `chore/done-<id>`
    exclusive create, the `branch` refusals), so a double holder cannot double-apply
    a step. `--perform` and `--track` use the same takeover rule.
