## Intent

W-209 left the list trusted as written (its Defaults 4): `readSourceExcludes` and `check` validate only its shape, so `packages/` in the list would drop real source from every certificate, and a new page stays SOURCE unnoticed. The Patron asked for the narrow pin (2026-10-10). W-211 adds one row beside W-209's and runs its file on the records-only path, where a records PR that edits the list is checked.

Promise list-pin: wherever `scripts/ci-scope.test.mjs` runs, `studio/bisellium.yml#source_excludes` must be exactly `examples/` plus each regular file directly in `docs/design/dossier/` that `recordOnly` accepts — limit: order is ignored; a duplicate, a missing or an extra entry fails; a page in a subdirectory, a non-HTML file and a symlink are not pages.

## Interfaces

```js
test("W-211-b1 behaviour 1: source_excludes is examples/ plus the dossier's direct HTML pages, and test:record runs this pin", async () => {
  const { recordOnly } = await import("./ci-scope.mjs");
  const command = "node --test-reporter=tap scripts/ci-scope.test.mjs";
  assert.ok(andSplit(pkgScripts()["test:record"]).includes(command), `test:record runs "${command}"`);
  const listed = parseYaml(readFileSync(join(REPO, "studio", "bisellium.yml"), "utf8")).source_excludes;
  const pages = readdirSync(join(REPO, "docs", "design", "dossier"), { withFileTypes: true })
    .filter((entry) => entry.isFile())
    .map((entry) => `docs/design/dossier/${entry.name}`)
    .filter((path) => recordOnly([path]));
  assert.deepEqual([...listed].sort(), ["examples/", ...pages].sort(), "source_excludes names exactly these");
});
```

It reuses the file's `REPO`, `pkgScripts`, `andSplit` and `parseYaml`, and `recordOnly` as the one definition of a page (W-209's `DOSSIER_PAGE`). No helper is added.

## Defaults for the Patron to veto

1. **A page is what `recordOnly` already calls a page**: a regular file directly in `docs/design/dossier/` ending `.html`. The pin has no second definition. Order is ignored; duplicates fail.
2. **The whole CI-scope file joins `test:record`** rather than a new test file. It adds about 14 s to the records-only path (`measure.txt`).
3. **A PR that adds, renames or deletes a dossier page fails until the same PR updates `source_excludes`.** That is the pin's purpose. The list edit moves the SOURCE identity of trees holding the page, so, as W-209 Defaults 2 says, it lands while no opus is between `branch` and `done`, or an opus in flight is held until it rebases.
