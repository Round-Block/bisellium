# W-031 — local CI: run the pipeline and record evidence without a runner

## Intent

`.github/workflows/ci.yml` runs six steps on every push and PR. It has
never once executed: GitHub Actions is blocked on billing, so every run
since the repo was created failed in ~3 seconds with an empty `steps: []`
and the annotation "The job was not started because recent account
payments have failed". The PR page shows a red check whose reason is
invisible unless you query the annotations API — worse than no CI, because
a red X that always means nothing teaches everyone to ignore red X's.

The work CI should be doing is instead being done by hand, badly. Both
round-3 QA reviews (2026-09-19) built their own scratch worktrees, relinked
`node_modules`, and re-ran the suite before they could judge anything. One
briefly misdiagnosed a symlink resolution problem as a `TS2339` type error.
That is mechanical work spending reviewer budget, and reviewer budget is
for judgement — the findings that mattered were the truncation gap between
fixture and real officina, and the scoping proof that `probatio.certifies.
stale` cannot fire for any opus `merge` accepts.

Three builders also hit a trap CI would never have: a fresh worktree has no
`node_modules`, so `@bisellium/*` resolves through the parent checkout and
edits to `packages/` are silently invisible to test runs. Tests pass
against the wrong source. A clean-checkout pipeline catches that by
construction.

## Files owned

- `packages/commands/src/ci.ts` — the pipeline runner
- `packages/cli/src/ci.ts` — re-export shim
- `packages/cli/src/ci.test.ts` — behaviours
- `packages/cli/src/main.ts` — command wiring and usage line
- `scripts/ci-workflow.test.mjs` — extend: the drift guard

## Interfaces

`bisellium ci [--ref <ref>] [--opus <id>] [--studio <dir>] [--repo <dir>]`

- Runs the same six steps as `ci.yml`, in the same order: `typecheck`,
  `lint`, `format:check`, `test`, `check studio`, `check examples/sample-studio`.
- `--ref` runs against a clean checkout of that ref in a scratch worktree,
  so uncommitted state and stale `node_modules` cannot mask a failure.
  Without it, runs in the current tree.
- Stops at the first failing step and exits non-zero, reporting which step
  failed — matching runner semantics.
- `--opus <id>` additionally records the `tests`, `lint` and `types` gate
  certificates, reusing `verify`'s existing machinery rather than
  reimplementing certificate minting.

## Behaviours to test

1. Runs all six steps in `ci.yml`'s order on a passing tree and exits 0
2. Stops at the first failing step, names it, and exits non-zero
3. `--ref` runs against a clean checkout, not the working tree — a dirty
   working tree does not change the result
4. `--ref` against a ref whose `packages/` differs from the working tree
   produces the ref's result, not the working tree's (the `node_modules`
   resolution trap: the run must not silently test the parent checkout)
5. `--opus <id>` records gate certificates identical to what `verify`
   would record for the same tree
6. Without `--opus`, no officina bookkeeping is written
7. **Drift guard**: the step list `bisellium ci` runs is asserted equal to
   the `run:` steps in `.github/workflows/ci.yml`. Adding a step to one
   without the other fails the suite.

## Acceptance

A QA agent reviewing a PR runs one command instead of building a scratch
worktree by hand, and gets the same answer the runner would give. Local
green and CI green cannot disagree, because behaviour 7 forbids the lists
from drifting.

## Out of scope

- Fixing the GitHub billing block. That is the Patron's, outside the repo.
- Removing or weakening `ci.yml`. Local CI supplements the runner; when
  billing is restored both must run the same steps, which is the point of
  behaviour 7.
- Recording CI results from a GitHub Actions run into the officina. A real
  gap — a green runner writes no certificates — but it needs the runner
  working first, so it belongs in its own opus.
