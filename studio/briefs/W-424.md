## Intent

W-350 (kind: ui, merged 2026-10-21 as PR #663, trunk state `verifying`, its UI approved by the Patron in D-124) cannot be closed. `next W-350` on the real studio names `spec held ... no passing ui-architect spec log (ci/W-350-spec-<n>.log with phase spec) names the current briefs/W-350.md`, ticket `verdict-spec round 9`, and `done W-350` refuses with `no matching next ticket (action is verdict-spec, want done)` (`done-master.out`).

The cause is in `packages/cli/src/next.ts`. `readSpecReviewer` (master :221) returns, for a kind: ui opus past ready (`PAST_READY`, :92), signer = `bisellium.yml#ui_spec_signer` (`ui-architect`) and no reviewer (:234). `signedSpec` (:434-456) then accepts only a passing spec log whose `# sella:` is that signer, pinned to the current brief before the branch. The spec rung (:1006-1089) has no skip. W-350's spec was signed as `architect` (`ci/W-350-spec-7.log`, passing, pinned to the current brief blob a6247df7), which was right then: D-098 A had removed the UI pair, and #666 restored it on 2026-10-22. Its record says so: `probationes.spec: { sella: architect, status: passed }`, written by `ready`. D-098 C names a `ci/W-350-spec-9.log` that was never written; this opus writes or backfills no W-350 spec log.

The rule: past ready, the spec gate was passed at `ready`, and the record names the seat that signed. So in `readSpecReviewer`'s kind: ui PAST_READY return, when the trunk record's `probationes.spec` has `status: passed` and its `sella` is the current UI signer or the design magister, that seat is the signer. Any other recorded seat, status or shape keeps today's signer (the UI signer). The record names who must have signed, never the evidence: `signedSpec` still requires that seat's passing log, pinned to the current brief before the branch.

Why the trunk record: the PAST_READY state that switches the reviewer off is already the trunk's, so the seat comes from the same record, not from an owner checkout's copy that a worktree edit could change. Both callers (`gather`'s pairing line, master :789, and the spec rung's gate line, :1011) pass the trunk record's `probationes` beside its `state`, so `Facts.design` (red attribution, `signedAfter`, commits) keeps naming the same seat as the spec rung, as :788's comment requires.

Why only these two seats: the design magister signed every UI spec while the pair was absent (before D-091, and under D-098 A), and the UI signer signs every one since. Any other seat in that field (a builder, the ui-lead, a guest, which the enumeration finds on older non-ui records) is not a spec signer under today's manifest, so it falls back to today's order rather than widening who may sign.

The architect's review also suggested the same change at :259 (the non-ui PAST_READY return) for symmetry. It is not made: for every other kind the only accepted seat would be the design magister, which is already that return's signer, so the change would be a no-op. Row `W-424-b1` pins that another kind keeps the design magister.

On the real records (`enumerate.out`, 424 opus records at origin/master), the prototype changes the signer of exactly two: W-350 (verifying) and W-339 (done, so its ladder stops at `afterDone` before the spec rung). The six past-ready ui records signed by `ui-architect` keep `ui-architect`, and no non-ui record changes.

Threat model: mistakes, not adversaries (D-045). The trunk record is written by the verbs and changed by PR.
