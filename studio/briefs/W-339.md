## Intent

D-088 F ordered a cheap colour check, and D-090 B widened it from today's literals to every CSS colour form. Eighteen hard-coded colours currently sit below `apps/web/src` outside `tokens.css`: twelve white surfaces, two shadows, three unauthorized amber variants and one transparent border. A future literal can silently enlarge the palette.

The rule extends `apps/web/test/tokens.test.ts`, the existing source-token mechanism, as one named node:test row. This is preferable to an officina check, which judges studio records rather than repository source, and to an ESLint plugin, which would not cover CSS without another processor. The existing root `npm test` already executes `tokens.test.ts`, so the existing `gates` job runs the rule on source-changing merge groups and master pushes. W-339 adds no package script, workflow step or workflow trigger (D-042).

The lexical rule recognises 3/4/6/8-digit hex; `rgb`, `rgba`, `hsl`, `hsla`, `hwb`, `lab`, `lch`, `oklab`, `oklch`, `color`, `color-mix`, `device-cmyk` and `light-dark` functions; all CSS named colours and `transparent`. It scans all CSS outside `tokens.css` and only direct `style={{...}}` regions in TSX. `var(...)` and `currentColor` are references, not hard-coded colours.

A fixture proves both quoted and unquoted `https://` URLs before a later colour still report that colour; CSS scanning removes block comments only, while TSX inline-style scanning handles JavaScript line comments quote-aware. This deliberately avoids treating valid unquoted CSS `url(https://cdn/x)` as a line comment.

Every other syntax is a limit: escaped identifiers, system-colour keywords, relative-colour syntax nested beyond the first closing parenthesis, JSX style objects expressed through variables or spreads, template expressions and generated source are not classified. A new colour form extends the fixture before entering the valid domain.

Today's literals are resolved exactly as the ui-lead ruled in `studio/ci/W-339-spec-3.log`: add only `--surface: #ffffff`, `--transparent: transparent` and `--shadow-drawer: rgba(22,33,30,.18)`, with the last used exclusively in the drawer shadow. Reject `--shadow-subtle`: `.seats__confirm-bar` gets `box-shadow: none` and retains its `1px solid var(--rule)` top separator. Reject the three amber variants: `.board-drawer__banner` uses surface and ink, no enclosing border, `border-left: 2px solid var(--amber)` and radius 0; its Inbox link remains verdigris and amber age numerals keep existing `--amber`. Three tokens cover fourteen replacements, one shadow is removed and three amber sites are restyled. Source-colour compliance does not by itself guarantee palette compliance.

Threat model: mistakes, not adversaries (D-045).

## Interfaces

`node --test-reporter=tap --test-name-pattern='^W-339-b1\s' --import tsx apps/web/test/tokens.test.ts` runs the focused policy row and performs no source write. Plain `node --import tsx apps/web/test/tokens.test.ts`, as root `npm test` already invokes it, runs both the existing token assertions and the new row.

The recognised CSS forms are the four hex lengths; every function named in Intent with case-insensitive optional whitespace before `(`; every case-insensitive CSS named-colour word and `transparent`. The same values are recognised inside a direct TSX inline-style region. Comments, `var(--token)`, `currentColor` and colour words joined by `-` do not report. CSS removes only quote-aware block comments; TSX inline styles additionally remove quote-aware JavaScript line comments.

`sourceColourLiterals` returns sorted `<relative-file>: <literal>` reports from the fixed root. Any non-empty report fails the row at `move every reported literal to tokens.css`.

Promise colour-source: every recognised hard-coded colour in CSS outside `tokens.css` or a direct TSX inline style fails with its relative file and literal; quoted and unquoted `https://` cannot hide a later colour — limit: the scanner is lexical and only the listed forms and direct inline-style shape are inside its domain.

Promise migration: today's eighteen literals are replaced, removed or restyled using only the three approved new tokens and existing palette roles — limit: unchanged component structure, token consumers and rendering are reused, not guaranteed (D-076 E).

Promise CI reachability: the existing root test suite runs `tokens.test.ts`, so the existing source-change `gates` path enforces the rule without workflow changes — limit: root `npm test`, `scripts/no-vendor.mjs`, the gates job and merge-queue policy are reused unchanged, not guaranteed (D-076 E).
