# W-030 — CLI discoverability: usage banner reachable from context

## Intent

`bisellium` with no arguments prints all 32 commands with their exact flag
shapes. It is the only complete reference — `docs/ADOPTION.md` mentions 16
commands, README 17, CLAUDE.md 7. Nothing pointed agents at it.

The cost, observed 2026-09-19: three reviewers had to correct CLI
invocations that an orchestrating session wrote into their briefs from
memory (`review` accepts no `--repo` and requires `--evidence`). One
reviewer, probing for the right syntax, executed a real `review` call that
wrote a genuine gate citing the brief as its "evidence" — officina
bookkeeping written by a syntax probe.

`bisellium context` is the boot command every agent definition tells its
agent to run first. A pointer there reaches every sella without any
brief-writer having to remember it.

This work was first filed under W-028 and numbered as behaviours 22-24.
That was wrong: W-028 is `patron-as-agent: automated merge, push and
cascade orchestration`, and its five behaviours are all `checkpointStale`.
The two share nothing but a number. Round-3 review of PR #1 caught it and
recommended a separate opus; this is that opus.

## Files owned

- `packages/commands/src/usage.ts` — the `USAGE` banner, single source
- `packages/cli/src/usage.ts` — re-export shim
- `packages/cli/src/main.ts` — reads `USAGE` from the shim
- `packages/commands/src/context.ts` — renders the pointer section
- `packages/cli/src/context.test.ts` — behaviours
- `packages/commands/src/usage.test.ts` — the drift guard (behaviour 5)
- `packages/cli/src/cli.test.ts` — behaviour 6 had no automated test
- `package.json` — registers the new test
- `packages/commands/src/pause.ts`, `packages/cli/src/serve.ts`,
  `packages/cli/src/tick.ts` — bare `dir`/`text` corrected to `<dir>`/`<text>`
  to match the banner (found by behaviour 5's guard, not exceeded quietly)
- `packages/commands/src/index.ts` — re-export wiring for the moved `USAGE`

## Interfaces

- `bisellium context --sella <id> <studio>` gains a section pointing at the
  usage banner. A pointer, not the banner text: the banner is ~709 tokens
  against a 4000-token default budget (17.7%), measured; the pointer is 67
  (1.7%).
- `USAGE` lives in `packages/commands` and not `packages/cli`, because
  `cli` depends on `commands` and `context.ts` lives in `commands` — the
  reverse import would be a cycle.

## Behaviours to test

1. `context` output carries the usage pointer for every declared sella
2. The pointer names no flag shapes, so it cannot drift from the banner
3. The full banner is never inlined into `context` output
4. The pointer survives truncation that drops other sections, **for the
   real officina's sellae** — not only for a small fixture lex. The
   engineering lex is ~1100 tokens against a ~200-token fixture, and at
   `--max-tokens 600` the pointer was dropped for `eng-lead`, `qa-lead`,
   `builder-a` and `builder-b` while passing its test. The test must
   exercise a lex of realistic size.
5. Every per-command `*_USAGE` constant appears verbatim in `USAGE`, so
   the banner cannot drift from the commands it documents
6. `main.ts`'s usage-error paths (no args, unknown command, unknown flag,
   `--help`) still print the banner and exit 2
7. The scan behind behaviour 5 counts every usage constant it finds and
   asserts the count, so a constant made unparseable (a template literal,
   a `: string` annotation) fails the suite by vanishing from the count —
   not only when every constant vanishes at once

## Acceptance

`bisellium context` points every sella at the banner, at every budget the
real officina uses. The banner matches the commands it documents, enforced
by a test rather than by review.

Two known drifts must be fixed as part of this: `USAGE` omits
`[--cwd <dir>]` from `red` (accepted at `lifecycle.ts:442`) and the
`context` subcommand from `hook-event` (accepted at `hooks.ts:194`).
Promoting a reference that is already wrong is worse than not promoting it.

## Out of scope

- Reconciling `USAGE` against the `parseFlags` allowlists themselves —
  `check`, `init`, `context` and `query` have no `*_USAGE` constant (their
  flags live in `main.ts`'s `FLAGS_BY_COMMAND`), so behaviour 5's guard
  covers 30 of the banner's 34 lines; those four are correct today but
  unguarded against future drift
- Any change to what the commands accept
