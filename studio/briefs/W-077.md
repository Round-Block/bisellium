## Intent

The Officina screen shows the Patron things that are stale, blank, false or
unreadable. Measured at master `f449cbc` (script
`~/.bisellium-evidence/W-077-spec/measure.mts`, output `measure.out`, run
2026-10-04T22:05Z, current period `2026-W40`):

- **Health has no time on it.** `GET /api/health` serves `<studio>/health.json`
  verbatim whenever `tick` has written one (`apps/server/src/store.ts:463-470`).
  The Patron's live file is stamped `2026-09-25T09:35:43.947Z`, so it was 5 days
  old on the day of the decree and 9 days old at measurement. Its `at` is never
  rendered: `Officina.tsx` mentions a time only in the `DEV_HEALTH` literal
  (`:38`, `:44`). The panels give no sign that they are a week old.
- **The aerarium panel is blank.** Both officinae hold only
  `aerarium/2026-W38.yml`. `/api/aerarium` filters to the current period
  (`store.ts:445-452`) and answers `[]` for `studio/` and for
  `examples/sample-studio`. "System status" then renders a heading over an
  empty grid (`Officina.tsx:83-99`). Before the fetch resolves, the panel is
  just as blank.
- **The screen shows demo numbers as if they were live.** When
  `/api/aerarium` or `/api/health` fails, the catch handlers load
  `DEV_AERARIUM` and `DEV_HEALTH` (`Officina.tsx:67-68`). A failed request
  therefore shows the Patron invented burn (`47,200 / 200,000`) and invented
  findings.
- **Engine State is filler.** The "Engine state" card (`:107-112`) shows
  `Autonomous` or `Paused` and nothing the Patron acts on. The decree removes
  it.
- **Pending actions have no names on a tick-written file.** `tick` writes
  `due` items as `{kind, sella}`, `{kind, period}`, `{kind, opus}` and
  `{kind, models}` (`packages/cli/src/tick.ts:89-93`). The served contract
  `HealthResponse.due` is `{kind, id}[]` (`apps/web/src/api.ts:150-159`), and
  the screen reads `d.id` (`:121-122`). The Patron's live file has 33 due
  items, and 0 of them have an `id`. Every row's name cell is empty, and 29 of
  the 33 React keys collide (`traditio:undefined`, …). Only the server's own
  stand-in `computeDueSummary` (`store.ts:194`) emits `{kind, id}`.
- **Contract integrity speaks rule ids.** Rows are raw `findingsByRule` keys
  (`probatio.certifies 130`, `traditio.stale 43`, …) under "Blocking issues" and
  "Advisory alerts" (`:139-153`). There are 145 rule ids in 31 families
  (`packages/cli/src/rules/ids.ts`). A fresh check of `studio/` finds 13
  distinct rules in 11 families. The Patron has no way to tell from these rows
  what is wrong, or whether anything stops work.

The fix stays inside the screen, plus one normalisation on the server's read
path:

1. The health panels carry `as of <UTC stamp>, <age>`.
2. The budget panel (renamed "Posture and burn") has three named states:
   loading, failed, and empty. Failure never shows demo data. The `?demo` path
   is unchanged.
3. The Engine state card is gone. The panel becomes "Pending actions", with its
   count beside the heading, and an empty due list says so.
4. `health()` maps a tick-written `due` onto the declared `{kind, id}` shape,
   the one place every client goes through.
5. Contract integrity opens with two plain sentences, one for what blocks
   and one for what is only a warning. Under "All findings by area", rows are
   grouped by rule family under a plain label. The exact rule ids sit in a
   native disclosure on each row, which keyboard and touch can reach, and in
   the row's `title`.

DIRECTION.md §1 applies: "if a pixel does not carry a fact from the officina's
files, it is deleted". The canvas (`docs/design/canvas/`) has no Officina
artboard (`canvas.json` lists Board, Drawer, Swimlane, Agents, Inbox and
Digest), so DIRECTION §6 "Officina" is the only design source. The Officina
keeps its screen-map touchpoint, Budget allocation (DIRECTION §8,

## Interfaces

**`apps/web/src/lib/officinaTruth.ts`**

```ts
export function healthStamp(at: string, now: Date): string;
export interface IntegrityRow { family: string; label: string; rules: string[]; count: number }
export interface IntegritySummary { stops: string; warns: string; rows: IntegrityRow[] }
export function integritySummary(h: Pick<HealthResponse, "blocks" | "advisories" | "findingsByRule">): IntegritySummary;
export const RULE_FAMILY_LABELS: Readonly<Record<string, string>>;
```

- **`healthStamp`** returns `as of YYYY-MM-DD HH:MM UTC, <age>`, built from the
  ISO string's UTC fields, with no locale.
  - `<age>` is computed from `m = floor((now - at) / 60000)`:
    - `m < 1` gives `just now`;
    - `m < 60` gives `N minute(s) ago`;
    - under 24 hours gives `N hour(s) ago`;
    - anything older gives `N day(s) ago`;
    - singular is used for 1.
  - An `at` later than `now` drops the age, giving `as of … UTC`.
  - An unparseable `at` gives `as of an unknown time`.
- **`integritySummary`.**
  - `stops` (ui-lead item 5):
    - `This check found no blocking problems.` when `blocks` is 0;
    - `This check found 1 blocking problem.` when it is 1;
    - `This check found N blocking problems.` otherwise.
  - `warns`:
    - `No warnings.` when `advisories` is 0;
    - `1 warning; it does not stop work.` when it is 1;
    - `N warnings; they do not stop work.` otherwise.
  - `rows`: one per rule family (the id up to its first `.`).
    - `count` is the sum over the family's rules, and `rules` lists those rule
      ids sorted.
    - `label` is `RULE_FAMILY_LABELS[family]`. A family with no label keeps
      its family id as the label, so a new family is shown and never
      hidden.
    - Rows are sorted by `count` descending, then by `label` ascending.
  - Numbers are formatted with the screen's existing `toLocaleString`.
- **`RULE_FAMILY_LABELS`**, the copy ui-lead blessed (item 5). It has exactly
  one entry per family in `RULE_IDS`:

  | family | label | family | label |
  |---|---|---|---|
  | acta | Daily records | opus | Work items |
  | aerarium | Budget files | path | File paths |
  | backlog | Backlog size | petitio | Questions for you |
  | brief | Specs | probatio | Gate evidence |
  | cap | Size limits | process | Process steps |
  | collegium | Team setup | receipt | Session receipts |
  | decision | Decisions | sella | Seats |
  | design | Design rules | state | Work item states |
  | doc | Docs | stray | Stray files |
  | halted | Halted work | test | Tests |
  | hook | Agent hooks | traditio | Handoff notes |
  | instructions | Agent instruction files | usage | Token usage |
  | integration | Pull request reviews | wip | Work-in-progress limits |
  | lesson | Lessons | munus | Duties |
  | lex | Team charters | manifest | Officina settings |
  | link | Broken links | | |

**`Store.api.health`** (`store.ts`). When it returns a parsed `health.json`,
`due` is replaced by a mapped copy:

- an item that already has a string `id` keeps it;
- `daily` maps `sella` to `id`;
- `aerarium` maps `period` to `id`;
- `traditio` maps `opus` to `id`;
- `probe` gets `id` = `` `${models.length} pair(s)` `` (tick's own `formatDue`
  wording);
- any other item gets `id: "unknown"`, and its `kind` is kept;
- a non-array `due` becomes `[]`.

The file on disk is never written. The fresh-summary branch is unchanged.

## Out of scope

- **Which rows stop work.** `findingsByRule` merges levels, and both writers
  (`tick.ts:274-295`, `store.ts:475-476`) emit counts only. Saying which family stops
  work needs a `blocksByRule` (or similar) in the health contract from both
  producers. That widens a seam, so it is a follow-on (see **Follow-ons**).
  The "All findings by area" label keeps readers from taking the largest row
  for the blocking one.
- **The served check runs without `--repo`.** The fresh summary's
  `checkStudio(this.studioDir, now)` has no repo context. Measured on `studio/`,
  it reports 1 block (`opus.records_unchanged`, "repository context (--repo) is
  absent") that `check --repo .` does not report. The new sentence will
  truthfully say "This check found 1 blocking problem." about an artifact of
  the call. Passing the repo through `StartServerOptions.checkStudio` is a
  CLI-side follow-on (see **Follow-ons**).
- **The period name in the empty state.** `/api/aerarium` returns no period,
  and the repo already has three `isoWeek`s (`adapters/native`,
  `packages/core`, `packages/cli/src/init.ts`). A fourth in the web, or reading
  `health.due`'s aerarium item, would duplicate or stale the server's answer.
  The copy says "this week" instead.
- **Preferring a fresh check over a stale `health.json`.** The decree is to
  show the stamp, not to change the source.
- **Tick's own `due` shape.** The server maps it on read, and `health.json`'s
  on-disk format is unchanged.
- **The discarded `/api/officina`.** That is W-110's filed follow-on.
- **The rest of DIRECTION §6.** The posture pie, which DIRECTION calls a donut
  and replaces with a 4px burn rule, the decreta-pending panel, the lex-status
  panel and the colophon on this screen are all out of scope.
