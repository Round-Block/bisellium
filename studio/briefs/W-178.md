## Intent

Decree family: test-row-floor

Speeding up or refactoring a test file must not remove rows unnoticed (production lex §11). W-178 adds the blocking rule `test.rows` to the existing test-rule module: with `--repo`, `checkTests` compares each test file's row count at the merge-base of `HEAD` and master with its count in the working tree. A lower count blocks unless the change adds a record to `test/row-drops.yml` naming the path, how many rows were dropped, the opus and a reason.

Promise per-file-floor: each file that is a test file at the base keeps at least its base row count in the candidate, or the candidate adds one record naming that path and the exact number dropped — limit: rows are counted statically by the grammar under Interfaces, so a weakened row, a row traded for another, a row inside a loop (one site) and data removed behind one registration do not lower the count; a deleted, renamed or unclassified file counts 0 under its base path.

Promise base: the base is the single merge-base of `HEAD` with `refs/heads/master`, or with `refs/remotes/origin/master` when no local master exists — limit: a stale local master gives an older base (rows added since are simply new); on master itself the base is `HEAD` and nothing is compared; the merge group, whose `HEAD` holds current master (`gates` and `officina` check out with `fetch-depth: 0`, so `origin/master` exists), compares against master as merged; the host mint's single-branch candidate clone gets `refs/remotes/origin/master` from W-323's fetch (on master, not W-178's), so it compares against the host repository's master (in `certify`, the merge group's base).

Promise fails-closed: with `--repo`, an unresolvable base, an unreadable base or candidate test file, or a malformed `test/row-drops.yml` is a `test.rows` block — limit: without `--repo` the rule does not run (as `test.sleep`); W-205's pull-request path runs no check, so the merge group is where it binds before merge.

No CI step or test command changes, and no existing test row is removed or weakened; W-178 adds rows of its own. The threat model is mistakes (D-045). A reason makes a drop visible; review still refuses a speed-only deletion.

Left out of the draft:
- The TypeScript parser as a new CLI runtime dependency (engineering lex §2 and §4 need a decision for one). The grammar is lexical, on the module's existing `lex`, measured on the repo above.
- `from`/`to` counts in a record. A record names `drop: <n>`, the rows removed, so it still matches in the merge group after other opera moved master's count.
- The append-only check on old records, and a missing file being an error. A record counts only when it is new against the base, so an old record never admits anything; an absent file is an empty list (fixture repos and adopters have none), so it can only block. W-178 does not create the file.

## Interfaces

```ts
export interface RowDrop { path: string; drop: number; opus: string; reason: string }
export function lex(text: string, opts?: { blankStrings?: boolean }): Line[]; // existing, option new
export function isTestPath(path: string, registered: ReadonlySet<string>): boolean; // new, from fileSet
export function countTestRows(text: string): number; // new, pure
export function resolveTestBase(repo: string): { base: string } | { error: string }; // new
export function readRowDrops(text: string | undefined): { drops: RowDrop[] } | { error: string }; // new, pure
export function testRowFindings(repo: string): Finding[]; // new
export function checkTests(root: string, opts: RuleOpts): Finding[]; // existing
```

**The row grammar** (`countTestRows`), lexical, on `lex(text, { blankStrings: true })` code, so comments and anything inside a string or template (a `test(` fixture, a module name) never take part. It recognises only the spellings these lines list, each wherever it matches, whatever its syntactic role:
- a registration: `test` or `it`, optionally `.skip`/`.only`/`.todo`, then `(`, on one line (spaces allowed between the tokens), not preceded by `.` or an identifier character, counted only in a file that imports `node:test` or `@playwright/test` by a listed form: a static `import <clause> from "<runner>"` (the clause identifiers, Unicode included, braces, commas, `*`, `as`, over any lines; a clause opened by the `type` keyword excluded), a side-effect `import "<runner>"`, a `require("<runner>")` or a dynamic `import("<runner>")`, where `import` and `require` are free identifiers (not a member, private member or `new`) and the module is exactly one string literal without escapes (in a call, the whole first argument, a template without substitution included);
- a reporter: a function whose body holds `PASS` and `FAIL` in its code or strings and `console.log`, `console.error`, `process.stdout.write` or `process.stderr.write` in its code, each as a substring (comments excluded); weight 1;
- a wrapper: any other function whose body calls registrations or weighted functions; its weight is their sum (resolved to a fixed point, at most four rounds); a call is the function's name then `(` on one line, not preceded by `.` or an identifier character;
- a function starts on a line that begins, after indentation and an optional `export`, with `function f(`, `async function f(` or `function* f(`, or with `const`/`let`/`var f =` then `function`, `async function`, `(…) =>` (optionally `async`, parameters on that line, an optional return type) or `x =>`; its body runs from that line to the first later line indented at or left of it (prettier-formatted source);
- the count is the registrations and weighted calls outside every weighted function's body, each call times its weight.

Limit (ADOPTION names the uncounted forms, the hand-formatted body, the escaped `require` and the local `require`): `t.test` subtests, `describe` and reflective or generated registrations are not counted, a hand-formatted body can be measured wrong, and a listed spelling counts in any role (a method named `it`, a `test.skip(` call inside a test). Every spelling brief:66-71 does not list is outside the grammar's domain and may be miscounted in either direction: an identifier spelled with a `\u` escape anywhere (a registration or call name, the identifier just before one as in `\u{61}test(`, a function or binding name, `import` or `require`); a private name (`this.#test(`); a member with a space or a line break after its dot; a registration or call split before its `(`; a function start not listed (a method, `export default function`, a generic or typed arrow, parameters holding `)` or spanning lines); a runner import not listed (a member, private-member or `new` call, a re-export, a string-named binding, a computed, concatenated or escaped module name, a template with a substitution); and source that desynchronises the lexer (a regex literal holding a quote or `//`, a backtick in `${ }`, a string continued over a line break; W-121). A local binding named `require` is taken for the module system's (scopes are not tracked). All are limits of promise per-file-floor, read alike in the base and the candidate. Ordinary edits to a listed spelling stay inside the domain: a comment, a string, whitespace, a second statement on the line, `await`, a second call argument, and a line break anywhere but inside a registration's or call's head or a function's start line.

**The record** (`test/row-drops.yml`):

```yaml
drops:
  - path: packages/cli/src/test.ts
    drop: 5
    opus: W-193
    reason: renamed to packages/cli/src/acceptance.test.ts with the same rows
```

A record is new when no deep-equal record is in the base's file. Each dropping path needs exactly one new record whose `drop` equals base minus candidate; each new record must match a dropping path. `path` is compared as a string and never opened, so no containment helper applies.

   **Genuine red:** on master the row imports `rules/tests.ts` and `assert.equal(typeof mod.countTestRows, "function")` fails. Existing rows: none flips.

2. **Each base test path is compared with the candidate, and an unobservable base blocks.** `W-178-b2` fixture repos (`git init -b master`, commit, branch): one file 3→2 blocks naming both counts; deleted and renamed files block at their base path as 0; a rise and a new file pass; local master, origin-only master, and a master moved past the branch point (base = branch point) each compare correctly; no master ref, an unborn `HEAD`, a symlinked and an unreadable candidate test file each block.

## Defaults for the Patron to veto

1. Should a branch be compared with the point where it left master, with the merge queue comparing again against master as merged?
2. Should a repository with no master branch (local or on origin) fail the check, rather than skip the comparison? Adopters on `main` would be blocked.
3. Should the reason file exist only once a drop needs it, with a record counting only for the change that adds it?
4. Should a rename count as removing the old file, so it needs a record?
5. Should rows be counted by a simple text grammar (registrations, PASS/FAIL reporters and their wrappers), without adding the TypeScript parser as a dependency?
6. Should a record name how many rows were dropped rather than the before and after counts, so it still matches when master moves under the branch?
