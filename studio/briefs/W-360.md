## Intent

W-350 built deterministic runner-owned initial-view baselines, but its verify walk still captured against the wall clock and stopped at screen mount. W-361's first build review showed both defects in real images: Board cards retained loading copy, Officina sections had not settled, and the footer/day strip moved with the date. Its third UI review found that Board could still capture before its inbox read and Seats before its independent model read. The same reviews showed Seats controls clipping and abbreviating the selected model at 390px. D-099 E requires W-360 to correct the captures before W-350 completes.

One instant, `2026-09-25T09:35:43.947Z`, governs both screenshot paths. W-350's baseline matrix retains its direct `page.clock.setFixedTime` and fixed `--now`. The verify walk gains the same server and browser time before its first navigation and seeds its actum from that instant. Playwright's fixed-time clock is the chosen mechanism: `Date` is constant while requests, animation frames and application timers continue.

Mount is no longer capture readiness. The verify walk calls one route-aware gate immediately before every `page.screenshot`: Inbox requires its focused served row and a ready shell state; Board requires the completed live shell after officina, opera and inbox reads, cards and gate ladders; Seats requires a ready shell only after officina and models reads settle, plus selected model labels matching their values; Officina requires a ready shell, all four panels and no section loader. Every route then rejects loading sentences terminated by either U+2026 or three dots anywhere in the page body. W-350's baseline matrix keeps its more specific fixture checks and adds those same Board, Seats and body-wide facts before comparison or refresh. The gate waits on observable screen evidence, never a sleep.

At phone width only, each Seats roster row becomes a compact three-column metadata line with its model control on a second full-width line. Fixed table layout, wrapping cells and border-box selects retain containment while giving the full selected model identity room beside the native arrow. The rendered row measures every Seats select at 390×900, requires readable value width, both edges inside the viewport and no document-level horizontal overflow. Desktop/tablet layout and the select's focus ring stay unchanged.

The prototype contains no PNG. W-350's ownership rule permits baseline writes only from an explicit master workflow dispatch. After the source change lands on master, the producer triggers that existing refresh with `refresh_screenshots=true`; the runner writes and uploads the eight PNGs plus `rendering-environment.json`. The producer presents the four desktop/phone screen pairs to the Patron. After approval, the builder commits those exact runner files without editing bytes, and a non-refresh runner pass compares the complete set without retries. W-350 completes only after that approval and comparison.

Threat model: timing and layout mistakes, not adversaries (D-045).
