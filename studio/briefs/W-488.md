## Intent

The console already has one authoritative capture pipeline. `scripts/served-e2e.mjs` builds the web bundle, serves the sample studio, captures the named Chromium rows and writes `studio/ci/shots/<opus>/manifest.txt` plus its PNGs. `readServedShots` is the bounded manifest/image reader used by verification and the review packet attaches those same images. A passed `served-e2e` gate names the certified source tree; `currentDesign` derives the current design digest from the opus and its brief. The reused readers and producer are enumerated in `/home/edckt/.bisellium-evidence/W-488-spec/revision-7/read-enumeration.out`.

Add the server half of capture review to the existing local `bisellium serve` process. It enumerates only existing served-e2e manifests, serves their immutable PNG bytes and accepts one bounded comment carrying the self-declared author, selector, viewport, named state, normalized pin, body, opus, source tree, design digest, manifest hash, image name and image hash. It never creates, recaptures, edits or replaces an image.

Store comments as bounded append-only `ui_capture_comment` lines in the existing local `timeline/patron.jsonl`. This is the narrowest durable local record already supported by a contained append helper; it avoids a second capture directory, database or bookkeeping file. The one build-review packet re-reads the selected set and includes only comments whose tree, design digest, manifest hash, image name and image-byte hash still match. An older capture is closed to new comments and cannot feed the current-tree review. Playwright assertions, `served-e2e`, image attachment and the single review verdict remain authoritative and unchanged.

Split out: **Capture review screen, W-488's web half** (being filed now) takes `CaptureReview.tsx`, `screens/capture-review.css`, `lib/capture-route.ts`, the `App.tsx` mount and the four served Chromium rows. The visible browser-list/current/older/loading/empty/failure parts of capture-set-identity moved; the pin-placement, `Comment as`, unverified-identity and timestamp-display parts of immutable-bound-comment moved; the whole responsive readable-capture-browser promise moved; and the on-screen “included in the one build review” part of one-review-input moved. The direct `#/captures[/<opus>]` address, shell mounting, geometry, copy and interactions are deferred unchanged: this split changes none of them.

## Interfaces

The prototype is nine commits directly after b6c6891744b05ab639138720adf45a62b75f5f42: paired `test(W-488): row b1, red` / `feat(W-488): behaviour 1` through b4, followed by the containment fix. `/home/edckt/.bisellium-evidence/W-488-spec/revision-7/stages.sh` reconstructs each exact stage; `/home/edckt/.bisellium-evidence/W-488-spec/revision-7/reds-r5.sh` proves the assertion reds and cumulative greens; `/home/edckt/.bisellium-evidence/W-488-spec/revision-7/series-builds.txt` proves every commit builds the web bundle.

`GET /api/ui-capture-sets` returns `{ sets }`, where each set has `opus`, `title`, `tree`, `current`, `capturedAt`, `designDigest`, `manifestSha256`, `shots` and `comments`. A shot has `name`, width, height, byte count and `sha256`. `GET /api/ui-capture-image/:opus/:name` returns only a PNG named by that set's existing manifest with `Cache-Control: no-store`. Both are local authenticated reads through the server's existing token seam.

`POST /api/ui-capture-comment` uses the existing origin, token and JSON checks. Its input repeats the selected set and image bindings plus `author`, `selector`, `state`, normalized `{ x, y }` pin and `body`. It returns `{ ok: true, output }` on success and `{ ok: false, exitCode: 1, output }` on a validation refusal, both with HTTP 200, and returns `{ error }` only for the 401/403/404/400 refusals. The command layer re-reads all bindings before `appendPatronTimeline`; caller data is never trusted as the binding oracle.

The durable record is version 1, kind `ui_capture_comment`, with a generated `UC-...` id and UTC timestamp. The timeline is read at at most 1 MiB; one capture set admits at most 256 valid comments; a body is 1–1000 characters, selector 1–200 and state 1–80, all nonblank and control-free. Listing admits at most 64 capture directories, manifests at most 8 KiB and PNGs through the existing 4 MiB reader. Unrelated timeline events are ignored; every line containing `"ui_capture_comment"` that cannot be parsed and validated fails the selected read closed. Set listing is deliberately all-or-nothing: one invalid admitted set refuses the list rather than returning an incomplete selection.

The build-review packet writes `ui-comments.txt` and also appends the same plain facts to `ui.txt`, which the one reviewer already receives beside the existing images. No timeline means an explicit zero-comment fact without widening old fixtures. A present timeline requires the selected set to certify the review's current source tree; otherwise packet construction refuses before writing.
