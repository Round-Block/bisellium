# W-138 — continuous improvement — every finding is captured, counted, weighted by what it cost across providers, and promoted to a fix by error type

Patron ruling (2026-10-04): file W-138 as a backlog opus with a draft brief. Not greenlit and not specced; the Patron greenlights.

Depends on: W-136 (its log reading supplies activity and usage), W-137 (lessons name their fix through `remedy`), W-085 (boot context carries open lessons).

## Intent

Improvement runs on every piece of feedback as it lands, not on a retro someone has to remember to run.

1. Capture. Every review verdict records its findings in structured form: class (the existing `family×slug` taxonomy), severity, and the check that would have caught it. Patron corrections count as findings too: for now, an interim ruling PR; later, a Board action.
2. Count. Findings are tallied by class across opera, automatically.
3. Promote by error type. Thresholds are settings in bisellium.yml, not constants:
   - security / trust boundary (path traversal, unredacted writes, injection): auto-file a fix opus on the 1st occurrence, top of the backlog
   - evidence integrity (backfilled evidence, no builder isolation): auto-file on the 2nd
   - test quality (tests agreeing with the bug, wall-clock sleeps): auto-file on the 2nd
   - workflow friction: alert only, on the 3rd, listed in the generated retro
   - architecture / UI-UX: alert only, never auto-filed (Patron authority)
   - environment / tooling noise: count only, unless it blocks work
   Auto-filing writes backlog only. Greenlighting stays the Patron's.
4. Weight by corrective cost. Every round after the first (rebuild, re-review, re-dispatch) is corrective spend, charged to the class that caused it. A class past a cost threshold (a setting) is auto-filed even below its count threshold. The backlog is ranked by corrective cost to date.
5. Verify. A class that recurs after its remedy merged reopens its lesson.
6. Generated retro. The retro becomes a report built from this data: findings by class, corrective spend, remedies landed, recurrences.

Cross-provider measurement:
- Usage is read from the harness logs (Claude: ~/.claude/projects/<clone-key>/; Codex: ~/.codex/sessions/), never self-reported by agents. Paths come from the W-136 per-project registry, not constants.
- Keep raw tokens per provider. Compare by share of each provider's usage window (the scarce resource) and by a list-price dollar figure (a common yardstick). Never add raw tokens across providers.
- One corrective round can span providers (Claude rebuilds, Codex re-reviews); a class's cost sums both.
- Report rework and cost per shipped opus by builder×reviewer provider pairing. This is the measured trigger for the provider-mapping change the Patron delegated to the orchestrator.

New providers, three tiers:
1. OpenTelemetry: if a harness exports usage and tool events as OTel (verify at spec time for Claude Code and Codex), serve accepts OTLP on localhost. No adapter. Fits the existing gen_ai.* / workflow.* wire names.
2. Harness adapter: one file in packages/shim/src/harness/ beside claude-code.ts and codex.ts, using the existing TurnUsage seam (types.ts).
3. Unknown: the git-only adapter. Activity comes from commits; usage shows "unmeasured", never 0.
Model prices and usage windows are data in the catalog (catalog.ts), not code.

Board: a "corrective spend this week" figure per provider, the top 3 costliest classes, and auto-filed fix opera flagged as such.

Trust: usage and findings are telemetry, never gate evidence. Never persist raw prompts, tool arguments or transcript text. The sandbox already blocks agents from localhost, so they cannot forge OTLP; keep it that way.
