## Intent

After a builder hands off, the orchestrator runs three steps by hand, each in its own turn: the mint (`bisellium run --sella builder --opus <id> -- true` from the worktree, about 15 to 30 minutes), the review round (W-274's `next --perform --expect review`) and the pr (`next --perform --expect pr`). The time between those turns is idle: on the three newest opera, handoff to mint was 25, 26 and 36 minutes, mint end to review 24, 3 and 7, review to pr 1 each (`minutes.md`, from `speed-1017/elapsed.json`). A hand mint also leaves the record's `run_receipt` line uncommitted (`attachReceipt`), and W-274's review perform holds on that tracked change (`dirtyHold`); hand rounds committed it with the review.

After this part, `npm run -s bisellium -- next <id> --perform --chain --budget 400000 --title <t> --body-file <f> --studio studio --repo .`, launched once in a background call, performs the mint, then the review round, then the pr, and prints one report when it ends: after the pr, after a failed review round (the builder's fix is next), or at the first hold. A re-run after a hold starts at the rung the ladder derives, so nothing is performed twice.

Threat model: mistakes, not adversaries (D-045).

## Interfaces

`next <id> --perform --chain` takes `--budget`, `--title` and `--body-file` as the rungs it performs do; `--chain` without `--perform`, or with `--expect`, is a usage error (exit 2). It performs, in turn, each rung the ladder derives while that rung is one of:

1. **the mint**: the `build` rung whose order is phase 2 (a missing or stale receipt, no failed round at this tree). `performMint` holds unless the builder's handover is current, checked as `gateDispatch` checks a resumed order (its `traditio` no older than the newest red or review log), then holds on a tracked change in the worktree (`dirtyHold`). It runs `bisellium run --sella builder --opus <id> --studio <worktree studio> --repo <worktree> -- true` from the worktree, as lex §9 step 4 does by hand, through `packages/cli/bin/bisellium.mjs`, its output appended to `.bisellium/steps/<id>.log`. A non-zero exit holds. Afterwards the only tracked change allowed is the record's `run_receipt` field (the record read again and compared with `HEAD`'s, front matter and body), which is committed alone (`chore(studio): <id> run receipt`, with a `Co-Authored-By: producer (bisellium next)` trailer); any other tracked change holds uncommitted. A receipt `f.receipt()` does not then admit holds. A thrown step error holds as `the mint failed: <message>`.
2. **review**: W-274's perform, unchanged.
3. **pr**: today's perform, unchanged; without `--title` and `--body-file` the rung is only named, as today, and the chain ends there.

Each rung runs under its own step marker, taken and released as one perform's is, and the chain moves only forward: a rung is performed at most once per call, so the call ends after pr at the latest. Output: each rung's `next: <id> <step> performed|held` line and its lines, then one `next-step:` line. Exit 0 when every rung it ran was performed, 1 at a hold, including a later rung of the three that derives held after an earlier one was performed (`gh` failing at PR discovery, say): the report then ends `next: <id> <step> held` and its `why:`. A first rung outside the three holds before anything is performed: `why: refusing: --chain performs only the mint, review and pr rungs; <the held reason, or the next step>`.

**Waiting (D-071 D).** The chain runs in the foreground of `next`, as `merge --poll-ms` does; the orchestrator launches it in its own Bash call with `run_in_background` and waits for its exit notification, never `&`, `nohup` or `setsid`. The mint and Codex are child processes of that call. Test seam: `BISELLIUM_TEST_MINT`, an absolute path run in place of the CLI with the same arguments, honoured only with `BISELLIUM_TEST_CLOCK=1`, where a relative value holds before anything is spawned; with the test clock off it is ignored.

Limits, stated:

- The handover check is the only proof the builder has finished: a builder that records `handoff` and then keeps editing is minted at the handed-off tip (a tracked change holds; a new commit does not).
- A throw outside the mint and review performs (the pr's) ends the call as `next: <id> failed`, as today, without the earlier rungs' lines; their commits stand, and a re-run resumes at the next rung.
- A mint silent for longer than 1,800 s (`STEP_SILENCE_SECONDS.build`) reads stalled to a concurrent `next`; nothing kills it.
- No test row runs the real mint: the seam replaces the spawn of `bisellium.mjs`. A wrong path there makes node exit non-zero, which holds the mint.
- The pr rung in mode direct rebases onto a moved master and holds when the source tree changes, as today; the chain then ends there and the ladder orders the build rung again.

### Input domain

A rejection fails closed: the rung holds, exit 1, its step marker is released, and no later rung runs. A test row whose own read fails throws, which fails the row.
