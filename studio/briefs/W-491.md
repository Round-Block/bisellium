## Intent

W-452's build-review round 1 failed with an S1 whose fix is one line of `studio/bisellium.yml` (`spec_seats.since` pinned), committed as ccc2c52c. The step ladder's `fixedOutside` (`packages/cli/src/next.ts`, W-328, D-086 B) counts a commit after the failed round's log as a fix only when it is empty or changes a path `recordOnly` (`scripts/ci-scope.mjs`) does not call a record, and `recordOnly` calls every path under the officina a record. The manifest lives there, but it is not bookkeeping: it decides what the ladder, the gates and the seats do. So the fix counts zero, the source tree and the brief are unchanged, `redo` stays true, and the step ladder orders a builder for a fix that is already committed, round after round. `landing.out` shows the live case: on `opus/W-452`, four commits after the round-1 log, master's count 0 (`redo: true`), the prototype's 1 (`redo: false`, ccc2c52c).

**The change (decided).** A commit on the opus branch's first-parent line after the failed round's log, merges aside, is a fix when it is empty, changes a path that is not a record (both as today), or changes the officina's manifest, the exact path `<studio>/bisellium.yml`. Everything else under the officina (opera, ci logs, receipts, reds, briefs) and the records outside it (the handoff, the dossier pages) still are not. A fix counted this way reaches the re-review exactly as a W-328 fix does: the tree is unchanged, so no fix check is due, and the review step is the censor's, with its why naming the manifest.

**One manifest path, shared (decided).** `mergedTree` (W-259) already treats the manifest as one of "the two records that decide which gates a certificate must cover: the manifest and the opus's own record". This opus gives the manifest's path one name in `next.ts`, `manifestRel(studioRel)`, read by both `mergedTree` and `fixedOutside`; `mergedTree` keeps its behaviour (W-259-b1 still pins its refusal). The opus's own record is not shared: every handoff and gates commit writes it, so counting it would make all bookkeeping a fix, which W-328-b1 and this opus's row pin against.

**`recordOnly` is unchanged (decided).** Its other callers mean "officina bookkeeping" in the sense this opus keeps: the CI merge-group short path (`scopeOf`), certify's records-only head (`scripts/ci-certify.mjs`), `mergedTree` and `sourceCommits` (whose manifest refusal sits beside them), the landing and done ride guards, and the read guard (`scripts/record-reads.mjs`). Moving the manifest out of `recordOnly` would change all seven; the fix is local to the one count that read it as "not a fix". Each is a stated limit.

Threat model: mistakes, not adversaries (D-045).

Promise fix: a commit on `opus/<id>`'s first-parent line after the commit that last changed the failed round's log, merges aside, that changes `<studio>/bisellium.yml`, alone or beside bookkeeping, is counted as a fix; with the tree and the brief unchanged the next step is the censor's review of the next round, and its why counts every such commit.
