## Intent

Decree family: test-discovery

`package.json`'s `test:suite` is one line naming 109 test programs; 13 of the last 20 merges touched it, and under W-168 a conflict there forces a local re-mint. W-193 replaces the line with `node scripts/test-suite.mjs`. The runner discovers test files, orders them by path, runs each with one invocation rule, one at a time, and stops at the first failure. Adding a test adds only its file.

Promise discovered-on-add: every regular file named `*.test.ts` or `*.test.mjs` under `packages/`, `apps/`, `adapters/` or `scripts/` (not entering `node_modules`, `dist` or dot-directories, not following symlinks) is one entry of `testPlan` with no `package.json` edit, and `npm test` runs it once when no-vendor's preflight passes and every earlier entry exits 0 — limit: a refused preflight runs nothing and the first failing entry stops the run; `*.spec.ts`, `docs/research/` tests and other names are not npm-test inputs; untracked matching files are planned too (a local run sees a builder's new file; CI and receipts run clean trees).

Promise one-rule: each entry runs as `node --test-reporter=tap --import tsx <path>` from the repo root, except a file under `apps/web/test/`, which runs from `apps/web` as `node --test-reporter=tap --import ./test/support/register-css-stub.mjs --import tsx <path below apps/web>` — limit: compared with the chain, `.` arguments are dropped, node:test files that lacked it print TAP instead of the spec format, plain `.mjs` files load `tsx`, and seven `apps/web/test/` files gain the CSS stub; none changes a program's exit on this tree (`uniform-run.txt`), and a future file needing other arguments must adapt or be changed.

Promise sequential-exit: entries run in path order, one at a time, with inherited stdio and environment; the first non-zero exit is returned unchanged and no later entry starts; a signal or spawn error returns 1 naming the path; a discovery error returns 2 before any entry starts — limit: no parallelism, timeout, retry or host slot (W-183); the order is deterministic for one tree, and adding a file can move later files by one place.

No test row or assertion is removed or weakened (production lex §11). The threat model is mistakes (D-045). `npm test` keeps running `scripts/no-vendor.mjs`, which still runs `test:suite` with `sh -c` under the shadowed PATH; `test:record` stays a hand-kept chain of the same files in the same order, each command now written exactly as the runner runs it, so the W-139 row still checks it verbatim.

## Interfaces

```js
// scripts/test-suite.mjs
export function discoverTestFiles(repoRoot) // new: string[], repo-relative, "/"-separated, sorted
export function testPlan(repoRoot)          // new: { path, cwd, argv }[], in discoverTestFiles order; cwd is "." or "apps/web"; argv excludes node
export function runTestSuite(repoRoot, options = {}) // new: number (exit code); options.spawn defaults to spawnSync
```

`runTestSuite` calls `spawn(process.execPath, entry.argv, { cwd: join(repoRoot, entry.cwd), env: process.env, stdio: "inherit" })` per entry; the `options.spawn` seam is for the `W-193-b3` rows. `runOnce({ repoRoot, suiteCommand })` in `no-vendor.mjs` (W-072, W-180's interface) is unchanged.

W-178's row census and W-121's sleep scan classify test files themselves (`TEST_NAME` in `rules/tests.ts` matches every discovered name). W-121's `fileSet` also scans paths named by a `test*` script: after W-193 those are `scripts/test-suite.mjs` (scanned for sleeps, so it has none; 0 rows under W-178) and `test:record`'s files.

## Behaviours to test

1. **Discovery selects each npm-test file once and nothing else.** `W-193-b1` rows on a temp tree: matches under each root and nested; not selected: `x.spec.ts`, `helper.ts`, a match under `docs/`, `node_modules/`, `dist/` and `.hidden/`, a symlinked file and a symlinked directory, `x.test.js`. Output is sorted and `/`-separated. A missing root throws.

   **Genuine red:** on master `scripts/test-suite.mjs` does not exist; the row imports it with `.catch(() => ({}))`, so `assert.equal(typeof mod.discoverTestFiles, "function")` fails. Existing rows: none flips.

2. **Each file gets the one rule, in path order.** `W-193-b2`: on a temp tree, `packages/a.test.ts`, `scripts/b.test.mjs` and `apps/web/test/c.test.ts` plan, in path order, the root rule for the first two and the `apps/web` rule (cwd `apps/web`, the stub before `tsx`, path `test/c.test.ts`) for the third; `apps/web/src/d.test.ts` takes the root rule.

   **Genuine red:** after behaviour 1, `testPlan` is not exported, so its `typeof` assertion fails. Existing rows: none flips.

3. **The runner is sequential and keeps the failure.** `W-193-b3`, through `options.spawn`: entries run in plan order with their cwd and the inherited environment; an exit 7 returns 7 and the next entry never runs; a signalled child and a spawn error return 1 and name the path; a discovery error returns 2 with no spawn. One row runs the real CLI on a temp repo with two passing files (exit 0) and one failing (its status).

   **Genuine red:** after behaviour 2, `runTestSuite` is not exported, so its `typeof` assertion fails. Existing rows: none flips.

4. **`npm test` uses the stable command.** `W-193-b4`: `test:suite` equals `node scripts/test-suite.mjs`; `packages/cli/src/test.ts` is absent and `packages/cli/src/acceptance.test.ts` is a plan entry; each `test:record` command is byte-equal to the rendered command of a cwd-`.` plan entry (the changed W-139 row asserts the same). That the switch kept the chain's files is the one-time `switch-parity.mjs` check (row 7), not a row: after the switch no committed chain remains.

   **Genuine red:** after behaviour 3, `package.json` still holds the chain, so the first `assert.equal` fails. Flips when the line, the `test:record` rewrite and the rename land: `W-139 behaviour 1`, whose title and membership line change in this behaviour (Files owned); `W-211-b1` if W-211 has merged, until its constant changes; `containment.test.ts`'s W-163-b6 rows until the `test.ts` pin is removed; with W-178 merged, `test.rows` blocks both officina checks until the `test/row-drops.yml` record lands. `no-vendor.test.mjs`'s two package fixtures supply their own `test:suite` and do not change.
