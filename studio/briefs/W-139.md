# W-139 — record-only CI runs the tests that read the record-only files, and a full run proves the list is exact

Status: **signed spec, revision 1** · architect sella (claude-opus-5-5) · 2026-10-05.
The spec gate is written by `bisellium verdict W-139 --phase spec`, not by this text.
Draft filed by the orchestrator, 2026-10-04, while closing cascade 43.

## Intent

W-131 gave record-only pull requests a short `gates` path: `npm ci`, the scope
step, `check -- studio`. It skips `npm test`. But some tests read the real
officina, so a studio-only change can break them. PR #218 (lessons and
petitiones only) merged on the short path and turned master red. #219 fixed
the test.

Measured at master `3dfe21c` (scripts and output under
`~/.bisellium-evidence/W-139-spec/`):

- **What the short path costs.** `ci-runs.sh` → `ci-runs.out`. The `gates` job
  took 12–16 s on six record-only PR runs, and 377–495 s on four full runs.
  Of that, `npm test` took 329–445 s.
- **Which tests read the record-only files.** The record-only set is
  `recordOnly()` in `scripts/ci-scope.mjs`: everything under `studio/`, plus
  `docs/SESSION-HANDOFF.md`. `measure.mjs` → `measure.tsv` (with `logs/*.reads`)
  runs each of the 92 `test:suite` commands on its own, in two clones:
  - **base**: unchanged, run under `fs-trace.mjs`, a `NODE_OPTIONS` preload
    that logs every fs read of the set by the process and its node children.
  - **nostudio**: `studio/` and the handoff deleted and committed. This is the
    most extreme record-only change.

  The results:
  - 8 commands read the set. All 8 pass on base.
  - 5 of the 8 fail on nostudio: `check.test.ts`, `instructions.test.ts`,
    `docs.test.ts`, `backlog-page.test.mjs` and `delegate.test.ts`.
  - The other 3 pass on nostudio, but they assert things about live content,
    so a content change can still break them:
    - `rules.test.ts`: "studio: no BLOCKING path.* finding";
    - `rules/evidence.test.ts`: "real brief corpus has no out-of-range citation";
    - `answer-carry.test.ts`: its CLI runs with cwd = repo, and
      `collectDocFiles` reads the handoff's front matter.
  - No command fails on nostudio without also showing up in the trace. So
    today, reads are a superset of dependence.
- **Nothing else on the short path can see a record file.** Prettier and
  ESLint both ignore `studio/` (`.prettierignore`, `eslint.config.mjs`). The
  served e2e only ever uses a temp copy of `examples/sample-studio`. A change
  to `examples/sample-studio` is not record-only, so it already takes the
  full path.
- **What running the 8 costs.** `time-record.sh` → `time-record.out`. The 8
  commands, chained and untraced, take 14.4–14.6 s locally (three runs).
  `answer-carry.test.ts` alone is 9.0 s of that. Locally the full suite sums
  to 516.7 s, against 329–445 s on CI, so CI runs at 0.64–0.86× local speed.
  Expected cost on CI: **+9–13 s on a record-only `gates` job, from 12–16 s to
  about 21–29 s.** The full path stays at 6–8 min.
- **Would it have caught #218?** `replay-218.sh` → `replay-218.out`. At
  `c3a8cac` (#218's merge), `check.test.ts` exits 1: two W-076 b5 rows fail.
  With #219's test file it exits 0.
- **The tracer itself can break things.** `measure.mjs`'s tracer replaced
  `fs.realpathSync` without its `.native` property. That made
  `apps/web/test/served-config.test.ts` fail when traced (vite:
  `safeRealpathSync is not a function`), though it passes untraced
  (row 89 of `measure.tsv`). The CI preload has to be transparent.
- Tracing the whole suite cost nothing measurable: 516.7 s traced against
  519.2 s untraced.

Two changes, kept narrow:

1. **The short path runs the readers.** A `test:record` script holds the 8
   commands, copied verbatim from `test:suite`. `gates` runs it on a
   record-only PR, after `check -- studio`.
2. **The full path proves the list is exact.** On the full path, `gates` runs
   `npm test` under a small read-recording preload. A guard step then fails
   the run in two cases:
   - a test file read the record-only set but `test:record` does not name it;
   - a `test:record` command's test file never read the set.

   A new reader therefore cannot land without being listed, and a stale entry
   cannot stay.

## Interfaces

**`test:record`** (`package.json`). A ` && ` chain run from the repo root. Each
command is a verbatim member of `test:suite`, where `test:suite` is split on
`&&` and each piece trimmed. Measured at `3dfe21c`, in `test:suite` order:

```
node --import tsx packages/cli/src/check.test.ts . && node --import tsx packages/cli/src/instructions.test.ts . && node --import tsx packages/cli/src/docs.test.ts . && node scripts/backlog-page.test.mjs && node --import tsx packages/cli/src/rules.test.ts . && node --import tsx packages/commands/src/delegate.test.ts . && node --import tsx packages/cli/src/rules/evidence.test.ts . && node --test-reporter=tap --import tsx packages/cli/src/answer-carry.test.ts
```

**`scripts/record-reads.mjs`** (preload, loaded with `--import <absolute path>`):

- **Inert by default.** It does nothing unless `BISELLIUM_RECORD_READS` is a
  non-empty path. It resolves that path to an absolute one once, and writes
  it back to `process.env`, so children that run in another cwd log to the
  same file.
- **The repo** is the preload's own `dirname(dirname(<this file>))`.
- **The owner.** If `basename(process.argv[1])` matches
  `/(^|\.)test\.[cm]?[jt]s$/`, the process sets
  `process.env.BISELLIUM_RECORD_OWNER` to the repo-relative,
  forward-slashed path of `argv[1]`, replacing any inherited value. Any other
  process (npm, `scripts/no-vendor.mjs`, a CLI child) keeps the inherited
  owner. With no owner at all, the owner is `?`.
- **Which calls are wrapped.** Every wrapper copies the original function's
  own property descriptors, so `realpathSync.native` and the like survive.
  `syncBuiltinESMExports()` runs once after wrapping, so named ESM imports see
  the wrappers.
  - `node:fs` sync: `readFileSync`, `readdirSync`, `existsSync`,
    `statSync`, `lstatSync`, `openSync`, `opendirSync`, `createReadStream`,
    `cpSync`, `copyFileSync`.
  - `node:fs` callback: `readFile`, `readdir`, `stat`, `lstat`, `open`,
    `opendir`, `cp`, `copyFile`.
  - `fs.promises`: the same eight.
  - `realpath*` and `access*` are not wrapped.
  - The first argument is noted when it is a string, a Buffer or a file URL.
    A file descriptor is ignored.
- **Which paths count.** `rel` is `relative(repo, resolve(path))`, with `/`
  separators. A path is in the set when `rel === "studio"` or
  `recordOnly([rel])` is true. `recordOnly` is imported from
  `./ci-scope.mjs`, so the set has one definition.
  - When `ci-scope.mjs` is itself the main module, for example W-131
    behaviour 5's spawn under CI's `NODE_OPTIONS`, the preload's import is
    the module's only evaluation, so its CLI still prints exactly once.
    Keep it that way: do not add a second load path.
- **The log.** Each in-set path appends `<owner>\t<rel>\n` with the unwrapped
  `appendFileSync`, once per (owner, rel) per process.
- **Never throws.** Noting a read swallows its own errors. The wrapped call
  returns or throws exactly as the original would.

**`checkReads`** (`scripts/ci-scope.mjs`):

```js
export function checkReads(log, commands) // log: string, commands: string[] → string[]
```

It returns the problems, sorted; an empty array means the list is exact.

- `unattributed: <rel>`: a line whose owner is `?`.
- `unlisted: <owner> (read <first rel>)`: an owner that is not a
  whitespace-separated token of any command.
- `unread: <command>`: a command none of whose tokens is an owner in the log.

**CLI**: `node scripts/ci-scope.mjs --check-reads <log>`.

- `commands` is `package.json`'s `test:record` (at the repo root), split on
  `&&` and trimmed.
- A missing log prints `missing: <log>` and exits 1. This mode fails
  closed, the opposite of the scope mode: a guard that cannot see its
  evidence must not pass.
- Problems print one per line and exit 1. Otherwise it prints
  `record_reads=ok` and exits 0.
- The `<base> <head>` mode does not change.

**`ci.yml`** (`gates` only):

- After the record-only `npm run -s check -- studio --repo .` step, add
  `- if: steps.scope.outputs.record_only == 'true'` with
  `run: npm run -s test:record`.
- The `npm test` step's `env` gains these two keys, beside
  `BISELLIUM_REQUIRE_LIVE_ROWS: "1"`:
  - `NODE_OPTIONS: --import ${{ github.workspace }}/scripts/record-reads.mjs`
  - `BISELLIUM_RECORD_READS: ${{ runner.temp }}/record-reads.log`
- Directly after `npm test`, add
  `- if: steps.scope.outputs.record_only != 'true'` with
  `run: node scripts/ci-scope.mjs --check-reads ${{ runner.temp }}/record-reads.log`.

## Behaviours to test

1. `package.json` has a `test:record` script:
   - it is non-empty;
   - its `&&`-split, trimmed commands are each a verbatim member of
     `test:suite`'s split;
   - it has no duplicates;
   - no command contains `cd` or a parenthesis.
2. `ci.yml`'s `gates` record-only steps (`if` equal to the record-only
   condition) are exactly, in order, `npm run -s check -- studio --repo .`
   and `npm run -s test:record`. `web-e2e` still has none.
3. The preload records reads of the set and nothing else, and is otherwise
   invisible. The row writes `<tmp>/probe.test.mjs`. In it:
   - `existsSync(<repo>/studio/w139-probe-absent)`;
   - a named `readFile` import from `node:fs/promises` reads
     `<repo>/docs/SESSION-HANDOFF.md`;
   - `readFileSync(<repo>/docs/ADOPTION.md)`;
   - `existsSync(<tmp>/studio/x)`;
   - it spawns a child, `node -e` an `existsSync` of
     `<repo>/studio/w139-child`, with cwd `<tmp>` and the inherited env;
   - it prints `typeof realpathSync.native`.

   The row spawns the probe with its own `NODE_OPTIONS`
   (`--import <abs preload>`) and its own `BISELLIUM_RECORD_READS` (a tmp
   log), never the inherited ones. Then:
   - the log's lines are exactly the three in-set paths
     (`studio/w139-probe-absent`, `docs/SESSION-HANDOFF.md` and
     `studio/w139-child`), each owned by the probe's repo-relative path;
   - the probe prints `function`;
   - spawned again without `BISELLIUM_RECORD_READS`, the probe creates no
     log.
4. `checkReads` and the CLI:
   - an exact log gives `[]`;
   - a `?` owner gives `unattributed:`;
   - an owner named by no command gives `unlisted:` with its first path;
   - a command whose file never appears gives `unread:`.

   The CLI exits 1 with `missing:` on an absent log, exits 1 on any problem,
   and exits 0 with `record_reads=ok` on an exact one. The CLI is checked
   against the real `test:record` with a log built from its own commands'
   test files.
5. `ci.yml`'s `gates` `npm test` step's `env` holds exactly the two lines
   above, beside `BISELLIUM_REQUIRE_LIVE_ROWS: "1"`. The step right after it
   runs `node scripts/ci-scope.mjs --check-reads ${{ runner.temp }}/record-reads.log`
   under the full-path condition. `ci-workflow.test.mjs` still passes, with
   the guard step named, not loosely matched.
