## Intent

Decree family: step-tickets

Today `next` derives the one legal step and is optional: every writer works without it, so on 2026-10-11 a builder was sent and its round recorded while `next` held W-221 for the Patron. Part 1 makes the ladder's direct writers ask `next` first, in a studio that opts in with `step_tickets: required` in `bisellium.yml` (absent: no change). A ticket names the opus, the step, the action, its round, the actor, the studio the action writes in, that checkout's HEAD, the brief's blob and the time. It is valid only for that action, round, studio, head and brief, so a covered write needs a fresh `next` at its own head, just before it. The threat model is mistakes, not adversaries (D-045): the ticket file is agent-writable; part 2 makes a missing or mismatched one fatal at merge.

Promise ticket-issue: in a studio whose `bisellium.yml` sets `step_tickets: required`, a report-mode `next <opus>` writes the ticket for the action the ladder names (the Interfaces table) to `<git common dir>/bisellium/tickets/<opus>.json`, replacing any earlier one, and deletes it when `deriveNext` holds, is complete, names the Patron, or names a rung no covered verb performs; its output ends with one `ticket:` line — limit: the file is local and agent-writable; `gateDispatch`'s dispatch preconditions (budget, stale handover) gate launching a session, not the in-session verb, so they do not withhold a ticket; a hold the records do not express (a Patron instruction in prose) withholds nothing.

Promise ticket-refuse: in such a studio `verdict` (spec and build phases), `review`, `red`, `ready`, `done`, `branch` and `merge` exit 2 with the two-line refusal, after their existing argument checks and before their first write or wrapped command, unless the pending ticket names their action and round and its studio, head and brief equal the facts the verb reads at that moment — limit: `handoff`, `verdict --phase handoff`, `verify`, `run`, `amend`, `halt`, `waive`, `greenlight`, `answer`, `emit`, `budget`, `retro` and `new` stay unticketed; `pr`, `cleanup` and the spec commit and landing run only inside `next --perform` and are not ticketed; a worktree whose own `bisellium.yml` lacks the key does not require tickets.

Promise ticket-record: a covered write claims the pending ticket immediately before its first write, by renaming it out of the pending path, and refuses (exit 2, nothing written) if the claim fails; a successful write copies the ticket line into what it writes (a `# ticket:` header in a verdict or red log; one appended `tickets:` entry on the record for `ready`, `review` and `done`) and then deletes the claimed file; a claimed ticket is never pending again, so each ticket admits at most one write, whatever fails after it — limit: a refusal before the claim (an argument check, `ticketsProblem`, a red command that exits 0) leaves the pending ticket, while a write that fails after the claim (a verdict target that exists, a front-matter write that throws, a crash) costs a fresh `next`; `branch` and `merge` record their ticket only on stdout.

Promise review-substep: in a ticketed studio, when the newest recorded build-review verdict is not the one the record's review gate cites (no gate, or a gate citing an older round), `next` names `review` for that round (actor `producer`, the exact `bisellium review` command) instead of dispatching the censor again or holding — limit: every other malformed gate state still holds as on master.

Promise perform-path: in a ticketed studio, `next --perform` issues the ticket from the derivation it performs, before acting, so `ready` and `done` consume it through the same `requireTicket` a direct call uses, and after acting it leaves the ticket the new derivation names — limit: `performBranch`, `pr`, `merge`, `cleanup` and the spec commit and landing are performed inside `next` and take no ticket.

## Interfaces

```ts
// packages/commands/src/ticket.ts
export type TicketAction = "verdict-spec" | "verdict-build" | "review" | "red" | "ready" | "done" | "branch" | "merge";
export interface StepTicket {
  opus: string;
  step: string;      // a STEPS id
  action: TicketAction;
  round: number;     // verdict round; red behaviour; review evidence round; else 0
  actor: string;     // Derived.actor
  studio: string;    // the action studio, relative to the main checkout, posix, no ".."
  head: string;      // 40-hex HEAD of the action studio's checkout
  brief: string;     // 40-hex git blob of <studio>/briefs/<opus>.md, or "none" when absent
  at: string;        // exact UTC
}
/** Absent or a non-mapping manifest: not required. "required": required. Anything else: error. */
export function readStepTickets(manifest: unknown): { required: boolean } | { error: string };
/** One line of JSON, keys in the StepTicket order above. */
export function ticketLine(t: StepTicket): string;
export function parseTicketLine(text: string): StepTicket | { error: string };
/** main = dirname of `git rev-parse --path-format=absolute --git-common-dir` run in studio. */
export function actionFacts(studio: string, opus: string): { main: string; studio: string; head: string; brief: string } | { error: string };
/** Write (replace) or, with undefined, delete <main>/.git/bisellium/tickets/<opus>.json; the error text, or undefined. */
export function setPendingTicket(studio: string, opus: string, ticket: StepTicket | undefined): string | undefined;
export function requireTicket(i: { studio: string; manifest: unknown; opus: string; verb: string; action: TicketAction; round: number }):
  { off: true } | { line: string; path: string } | { refusal: string };
/** Renames `path` to `<dir>/<opus>.claimed` (replacing any earlier claimed file), then reads it back: a failed rename, a
 *  non-regular file or bytes other than `line` + "\n" is a refusal (`unclaimable: <why>`). After a rename the pending path is
 *  empty whatever follows, and `requireTicket` never reads a `.claimed` file. */
export function claimTicket(path: string, line: string): { claimed: string } | { refusal: string };
/** Deletes the claimed file after a successful write; a failure is a warning on stderr (exit unaffected: the file is never read as a ticket). */
export function dropClaim(claimed: string): string | undefined;
/** The record's `tickets`: absent or a list of strings parseTicketLine accepts. */
export function ticketsProblem(value: unknown): string | undefined;
export function recordTicket(doc: Document, line: string): void; // appends to `tickets`

// packages/cli/src/next.ts
export interface Derived { /* existing fields */ ticket?: { action: TicketAction; round: number } }
```

`refreshTicket` writes a ticket only when the setting is required, `status` is `named`, `actor` is not `patron` and `ticket` is set; otherwise it deletes any pending one. An `actionFacts` error deletes it too. Its line, appended last to `next`'s output in a ticketed studio: `ticket: <action> round <n>` or `ticket: none`. A malformed setting prints `next: <opus> held` and `why: bisellium.yml#step_tickets is malformed (<error>)`, exit 1.

The verb's round: `verdict --round`; `red --behaviour`; `review`'s `--evidence` file name `ci/<opus>-review-<n>.log` (no such name: `none`); 0 for the rest. `verdict --phase spec` asks for `verdict-spec`, `build` for `verdict-build`.

The review substep's command: `bisellium review <opus> --pass|--fail --evidence ci/<opus>-review-<n>.log --round <n> --sella <censor> --studio <worktree studio, repository-relative>`.

A refusal is exactly these two lines on stderr, exit 2, nothing written, no event; a refusal from `requireTicket` also runs no wrapped or prerequisite command (an `unclaimable` refusal comes after `red`'s command, before its log):

```text
<opus>: <verb> refused: no matching next ticket (<reason>)
run: bisellium next <opus> --studio <main>/<studio path within its checkout> --repo <main>
```

`<reason>` is one of `absent`, `unreadable`, `action is <x>, want <y>`, `round is <x>, want <y>`, `studio is <x>, want <y>`, `head is <x>, want <y>`, `brief is <x>, want <y>` (x the ticket's, y the verb's), `facts unreadable: <why>`, or `unclaimable: <why>` (from `claimTicket`, the last check before the write). A malformed setting refuses with the one line `<opus>: <verb> refused: bisellium.yml#step_tickets is malformed (<error>)`, exit 2.
