## Intent

The class `review×shared-log-grammar-rejects-valid-records` came back twice. W-459's build review round 1 (`ci/W-459-review-1.log` #1): `retro.ts`'s `ROUND_LOG` read a round of at most 15 digits, and W-459 brief:82 admitted "a positive integer with no leading zero". W-492's build review round 1 (`ci/W-492-review-1.log` #1): `actualLines` read a block scalar's lines only two spaces past the key, and W-492 brief:60 admitted "each following line more indented than the key". Both were fixed in their own rounds, and both are on master.

The shared cause, checked against each record's writer (`class-sites.out`): each grammar was written from a domain stated in prose, not from what the record's writer prints. Neither prose domain was the writer's. The rounds' writers, `verdict --round` and `review --round`, write at most 15 digits (W-334), so no written log was ever skipped; the brief stated a wider domain than any writer writes. The TAP diagnostic's writer is Node's TAP reporter, and its grammar is not YAML. A one-line string goes through `util.inspect`: `"it's refused"` when it holds an apostrophe, backquotes when it holds both quote kinds, and `\\`, `\t` or `\x07` for a backslash, a tab or a control character. A string of lines is a `|-` block two spaces past the key (`roundtrip.out`). Master's readers know only YAML's `'…'` with `''` and the block forms. So on master, `killedPin`, `redFailsAt`, `firstFailure` and `textKilledLine` each miss six of the nine forms row `W-497-b1` prints: 24 of 36 reads (`master-readers.out`). It fails both ways:

- Closed by mistake: a kill or red whose pinned assertion holds an apostrophe, as `assert.ok(false, "it's refused")` prints it, proves no pin. The spec signature then refuses the kill (W-381), and `bisellium red` refuses the red (W-473). Six kept kill outputs already hold such an `error:` line (`kept-forms.out`: W-407, W-408, W-451, W-452, W-474, W-494).
- Open: a text kill whose changed line holds an apostrophe, a backslash or a tab is not seen. `textKilledLine` reads no `actual:` line, so W-492's refusal is skipped. Kept kill and red outputs hold twelve `actual:` lines in a form master skips: eleven double-quoted and one backquoted (`kept-forms.out`).

The record forms the officina writes itself (log names, header lines, red names) are read by grammars equal to or wider than their writers', with one bounded exception (Limits). Node's TAP reporter is the one writer whose grammar no code here owns. Four readers had each restated it by hand.

**The design: (a), one shared reader, its accepted-forms table tested against the writer itself.** `tapValue` in `brief-admission.ts` reads a diagnostic value in the grammar Node's reporter prints. The three readers of a value (`provingDiagnostic`'s `error:`, under `killedPin` and `redFailsAt`; `actualLines`'s `actual:`, under `textKilledLine`; and `firstFailure`'s `error:`) call it instead of their own regexes. The accepted-forms table is row `W-497-b1`'s `TAP_STRINGS`, and the row does not hand-write their printed forms: it has the Node running the suite print them (`nodeTap`), then asks each of the four readers to read each one back, along with every code unit U+0000 to U+00FF and lone surrogates. A Node whose reporter prints a new form fails the row, so it does not skip records silently. The table's domain is the writer's output, not a brief's sentence about it.

Why not (b), an admission rule that makes a parsed record's Input domain row name its grammar and pin each boundary form: that is lexical prose checking, and both instances were prose that named a grammar and a boundary (W-459's "no leading zero", W-492's "more indented than the key"). It was wrong about the writer. W-334's Intent 1 rejected the same kind of rule for the same reason. (b) would hold briefs to their own sentences, while (a) holds the readers to the writer.

Threat model: mistakes, not adversaries (D-045).

Promise writer-forms: each of `killedPin`, `redFailsAt`, `firstFailure` and `textKilledLine` reads a diagnostic value in each string form the Node running the suite prints through its TAP reporter: single-quoted, double-quoted when the string holds an apostrophe, backquoted when it holds both quote kinds, single-quoted with `\'` when it holds all three and a `${`, with inspect's escapes decoded, and a string of lines as a `|-` block, as pinned by `W-497-b1` "killedPin: a line holding an apostrophe, double-quoted" and pinned by `W-497-b1` "textKilledLine: a line holding an apostrophe, double-quoted" and pinned by `W-497-b1` "killedPin: a line holding both quote kinds, backquoted" and pinned by `W-497-b1` "killedPin: a line holding all three quotes and a ${, single-quoted with escapes" and pinned by `W-497-b1` "killedPin: a line holding a backslash" and pinned by `W-497-b1` "killedPin: a line holding a tab" and pinned by `W-497-b1` "killedPin: a line holding a control character" and pinned by `W-497-b1` "firstFailure: every code point of chunk 8 round-trips" and pinned by `W-497-b1` "firstFailure: every code point of chunk 1 round-trips" — limit: the forms are those of the Node that runs the suite (25.9.0 at spec, `roundtrip.out`); a string over 10000 characters, which inspect cuts (`'…'... n more characters`), and a value that is not a string are not decoded, so they are plain.

Promise kept-forms: every form master's readers read is still read as before: a single-quoted line with YAML's `''` read as one quote, a `|-`, `|` or `|+` block whose lines are one space or more past the key, and a plain value (a number, a boolean) as no line, as pinned by `W-497-b1` "killedPin: a plain line, single-quoted" and pinned by `W-497-b1` "textKilledLine: a plain line, single-quoted" and pinned by `W-497-b1` "firstFailure: a string of lines, as a block" and pinned by `W-497-b1` "textKilledLine: a number is no line" and pinned by `W-492-b1` "a doubled quote in a quoted actual" — limit: `code: 'ERR_ASSERTION'` is still compared as written, which inspect prints so always; W-492-b1's other hand-written YAML fixtures stay W-492's.

## Interfaces

- `tapValue(block: readonly string[], indent: string, key: string): TapValue | undefined` (new export, pure). It finds the first line of `block` that is `<indent><key>:` or opens with that and a space. A `|-`, `|` or `|+` value is a block: the lines after it that open with `indent` and a space, or are blank. Each has its leading spaces cut to at most two past `indent`. A value that `inspectedString` decodes is quoted. Any other value is plain, as printed. With no such line it returns undefined.
- `inspectedString(text: string): string | undefined` (new export, pure). It decodes `'…'`, `"…"` or `` `…` `` whose body holds no bare quote of its own kind, and whose every `\` opens `\\`, `\'`, `\b`, `\t`, `\n`, `\f`, `\r`, `\xHH` or `\uHHHH`. In the `'…'` form, `''` reads as one quote. Anything else gives undefined.
- `type TapValue = { form: "quoted" | "block"; lines: string[] } | { form: "plain"; text: string }`.
- Unchanged signatures: `killedPin`, `redFailsAt`, `firstFailure` and `textKilledLine` keep theirs. A message is the first line of a quoted or block value, trimmed. An `actual:` is the set of its lines, trimmed. `firstFailure` gives a quoted value decoded and untrimmed, a block's first line trimmed, or a plain value as printed.

Limits, stated:

- Unchanged code the promises lean on is a stated limit, not a guarantee (D-076 E). That covers `provingBlock`'s reading of subtests and status lines, the `code: 'ERR_ASSERTION'` compare, `textKilledLine`'s patch reading, `killProblem` and `textKillProblem` (W-381, W-492), `runRed`'s comparison (W-473), and Node's TAP reporter itself.
- The other hand-written record grammars in the census are not changed. Each is read against its writer (`class-sites.out`):
  - Round numbers in `ci/` log names: every reader is `[1-9][0-9]{0,14}`, `[1-9][0-9]*` or `\d{1,15}`, each at least the writers' `^[1-9]\d{0,14}$` (W-334).
  - Log header lines: written by the verbs as `# <key>: <value>` and read by four header readers (`parseLogHeader`, `parseVerdictHeader` and the two `headerBlock`s), with no form skipped. Folding them into one reader is follow-on work, not this class.
  - TAP status lines: `retro.ts`'s `FAILING_ROW`, `rewrite.ts`'s titles and `evidence.ts`'s W-096 check read only a row id or a title as Node prints it. A row id holds none of `#`, `\` or a newline, the characters Node escapes there.
  - The one bounded exception: red names `ci/reds/<id>/NN.log` are written as `padStart(2, "0")` and read as two digits (`retro.ts`, `rewrite.ts`, `next.ts`). They agree while `brief_behaviour_limit` is under 100; the real officina's is 6. A limit above 99 needs a follow-on opus.
- A spec or red already signed or recorded is not judged again.

## Behaviours to test

1. **Every reader of a TAP diagnostic value reads each form Node's own reporter writes.** In `W-497-b1`, appended to `verdict-citation.test.ts`, the Node running the row prints a TAP stream (`nodeTap`). For each case of `TAP_STRINGS` it fails one subtest by `assert.ok(false, value)` and one by `assert.equal(value, …)`; it also fails one on a number and one per code-unit chunk of U+0000 to U+00FF (LF aside), lone surrogates and U+2028. The cases are a plain line, an apostrophe, both quote kinds, all three quotes and a `${`, a backslash, a tab, a control character, non-ASCII text, and a string of lines. For each case: `killedPin` and `redFailsAt` read the `error:` message as the value's first line; `firstFailure` gives the value exactly (a block's first line, trimmed); and `textKilledLine` names the value's line when a patch adds it. A number's `actual:` is no line, and every chunk round-trips through `firstFailure` exactly.

   **Genuine red:** `bisellium red W-497 --behaviour 1 --sella builder --studio studio -- node --test-reporter=tap --test-name-pattern='^W-497-b1\s' --import tsx packages/cli/src/verdict-citation.test.ts`, run from the repository root on the red commit (the row over master's readers), prints `not ok 1 - W-497-b1 behaviour 1: …` and fails by `ERR_ASSERTION`, because master reads no double-quoted `error:` (`red-b1.log`, accepted, `red-accept.out`), at the declared assertion, pinned by `W-497-b1` "killedPin: a line holding an apostrophe, double-quoted". It passes on behaviour 1's commit (`green-b1.log`).
