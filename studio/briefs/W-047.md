## Interfaces

### Why the reds are mutation-record reds

The code under test is already correct, so a test written against it passes
on first run. There is no honest "write the test, watch it fail, implement"
sequence available, and manufacturing one (breaking `safeItemPath` on purpose
and committing it) would be dishonest. The house precedent is W-042's red 02,
accepted by the censor in round 2 as "an honest mutation-record red": the
recorded command applies a named mutation, runs the test, shows
assertion-level FAIL lines confined to the mutated site, and restores.

Each behaviour's sequence is: write the test → run it green → record the red
by running the mutation harness for that behaviour's group → commit test and
red together. The red proves the test *bites*, which is the property the last
two reviews found missing.

### `scripts/safe-item-path-mutants.mjs`

Plain Node ESM, no new dependency, house style of
`scripts/ci-workflow.test.mjs`.

    node scripts/safe-item-path-mutants.mjs <group>

`<group>` is `contract`, `writes`, `lifecycle`, `census`, `legacy` or `all`.

**A mutant is a record, not a string edit:**

    { label, file, fn, nth, kind, expect, kills }

`kind` is `raw-join`, `sanitize`, `body` or `insert`; `expect` is `dead` or
`alive`; `kills` is a list of **exact `check(...)` label substrings** that
must appear on `^FAIL` lines of the mutated run (empty only when
`expect: alive`). Mutants are located by `fn` + `nth`-call-in-that-function,
never by line number — W-042 round 2 had to re-map `:491/:468` to `:610/:587`
after a pure move.

**A mutant counts as dead only if** the test exited non-zero **and** every
label in its `kills` appeared on a `^FAIL` line. Exit code alone is not
accepted: an unrelated pre-existing failure would otherwise "kill" every
mutant in the run. [red-team 4]

**Run protocol, per group:**

- **Baseline first.** Run the group's test command unmutated. It must exit 0
  with zero `^FAIL` lines. Anything else is exit 3 and no mutant runs — a red
  recorded against an already-red suite proves nothing. [red-team 4]
- **Non-empty.** A group that selects zero mutants is exit 2, never "all 0
  died". [red-team 4]
- Per mutant: read the file into memory, apply exactly one replacement, run,
  restore in a `finally`, re-read and confirm byte equality (never
  `git checkout --`, per the lex). An anchor that matches zero or more than
  one call is exit 3, and so is a failed restore.
- Print, per mutant: label, resolved function, `expect`, exit code, `^FAIL`
  count, whether each `kills` label was seen, then the FAIL lines themselves.
  Those lines are the red's assertion-level content.

**Exit codes, inverted on purpose:**

- **1 — every mutant matched its `expect`, and at least one was `expect: dead`.**
  This is the success case, and it is what `bisellium red` requires: `red`
  refuses to record a command that exits 0 (`packages/commands/src/lifecycle.ts`,
  `runRed`). A red for an incomplete demonstration is therefore impossible to
  record.
- **0 — at least one mutant did not match.** `red` refuses; the builder stops
  and reports which. A mutant expected dead that survived means that call
  site's guard is not observable and its case is not real.
- **2 — usage error or empty group. 3 — baseline not green, anchor
  ambiguous, or a file did not restore byte-for-byte.**

W-042 round 2's advisory A-2 is the reason for the AND: that harness set
`overall=1` if *either* mutant died. This one requires all of them, by label.

The final line is `all <n> mutants matched (<d> dead, <a> alive)` or
`<k> of <n> mutants did NOT match: <labels>`.

**Mutation kinds.**

- `raw-join` — `safeItemPath(join(R, "D"), I)` becomes
  ``join(R, "D", `${I}.md`)``. The mutation both reviews used.
- `sanitize` — the call is kept and the id is laundered:
  `safeItemPath(join(R, "D"), I.split("/").at(-1) ?? I)`. It preserves every
  ordinary id, still appears in the census as a call site, and turns
  `../W-777` into `W-777`. Sol's finding: against an outside-only sentinel
  every assertion still passes. It is defeated by the in-directory collision
  record in the sentinel recipe below. [red-team 5]
- `body` — a replacement inside `safeItemPath` itself (behaviour 1).
- `insert` — appends a new function to a source file (behaviour 4).

**Groups.** `contract` → sites none, body mutants, runs `writes.test.ts`.
`writes` → sites 1–5, `raw-join` + `sanitize` each, runs `writes.test.ts`.
`lifecycle` → sites 6, 7, 8, 12, both kinds each, runs
`BISELLIUM_ONLY_BEHAVIOUR=45 node --import tsx packages/cli/src/lifecycle.test.ts .`.
`census` → insert mutants, runs `containment.test.ts`. `legacy` → sites 9, 10,
11 and the 13+14 pair, both kinds, runs the blocks that own them (19, 33, 44
of `lifecycle.test.ts`; `retro.test.ts` for the pair). `all` → every group,
one baseline per test command.

directory, and would false-drift on a reformat. It is redesigned around the
TypeScript compiler, which is already a devDependency
(`typescript ^5.6.0`) — no new dependency, and every one of those defects
goes away. [red-team 3]

`ts.createSourceFile(path, text, ts.ScriptTarget.Latest, true)` and walk with

### The sentinel recipe (behaviours 2 and 3)

W-042 F-1a's lesson: a traversal case whose target **does not exist** proves
nothing, because the caller's `existsSync` refuses it and masks the missing
guard. Sol's finding 5 adds the mirror: a case whose *in-directory* collision
does not exist proves nothing against a sanitizing caller. So each case builds
**both**, by copying fixture records (the shape of W-034's `../D-777`
sentinel):

    cpSync(join(dir, "opera", "W-007.md"), join(dir, "W-777.md"));            // outside target
    cpSync(join(dir, "opera", "W-007.md"), join(dir, "opera", "W-777.md"));   // collision record
    cpSync(join(dir, "petitiones", "A-1.md"), join(dir, "A-777.md"));
    cpSync(join(dir, "petitiones", "A-1.md"), join(dir, "petitiones", "A-777.md"));

Behaviour 3 uses `opera/W-002.md` (state `building`) as the source for both
opus copies; behaviour 2 uses `opera/W-007.md` (state `backlog`).

The traversal id is `../W-777` / `../A-777`. A raw join collapses it onto the
**outside** sentinel; a sanitizing caller lands on the **inside** collision
record; `safeItemPath` refuses it outright and touches neither.

Each case asserts five things. Together they kill both mutant kinds, whether
the mutant *succeeds* against its target or merely refuses it later and
differently — that second half is what W-042's `--decision ../../etc/passwd`
case lacked:

- exit code 2;
- stderr contains `unknown opus: ../W-777` (or `unknown petitio: ../A-777`) —
  the refusal came from the guard, not from a state, gate, ownership or parse
  check further down;
- the **outside** sentinel is byte-identical afterwards;
- the **inside** collision record is byte-identical afterwards;
- no event was appended (`readEventLines` before/after).

`writes.test.ts` has no stderr helper; it has the capture idiom inline near
its `answer without --opus` block. Hoist that into a sync `withStderr(fn)`
beside `readEventLines` — the shape of `lifecycle.test.ts:233` without the
`async`, since all five verbs here return synchronously. Reusing it in the
existing block is optional.

Per-verb rows. Every `check(...)` label must start with the row's `label`
string, because the harness's `kills` list matches on it:

| # | call | id | mutant dies because |
|---|---|---|---|
| 1 | `runHandoff --opus` | `../W-777` | raw: writes `traditio` into the outside sentinel · sanitize: into the collision record |
| 2 | `runEmit --usage --opus` | `../W-777` | appends a `gen_ai.usage` event either way |

## Behaviours to test

1. **`safeItemPath` has a contract.** For every id in the hostile-id table,
   `safeItemPath(base, id)` either refuses with an error naming the id, or
   returns a path whose directory is exactly `resolve(base)` and whose
   basename is exactly `id + ".md"` — a refusal is never a sanitize, and no id
   is ever rewritten. The two `base`-shape assertions ride this block. Red
   (`01.log`): `node scripts/safe-item-path-mutants.mjs contract` — `mA`, `mB`
   and `mC` each make `writes.test.ts` fail on the named table rows, `mD`
   survives as specified, and the harness exits 1 only because all four
   matched.

2. **Every `safeItemPath` call site in `writes.ts` refuses a traversal id that
   resolves onto a real file, and refuses it rather than laundering it.** Rows
   1–5 of the sentinel table: `handoff --opus`, `emit --usage --opus`,
   `answer --petitio`, `answer --opus` and `greenlight`'s positional each exit
   2, name the id as unknown on stderr, leave both the outside sentinel and
   the in-directory collision record byte-identical, and append no event. Red
