# W-265 — the host's red replay ignores an environment word inside the failing test's own assertion block, and still refuses it anywhere else

Status: **signed spec, revision 3** (design audit: rule 6 tightened to one `code:` line, `ERR_ASSERTION`, and one `error:` line, closing wrapped errors; the ladder steps corrected on which copy of the classifier each mint and certify runs; revision 2, from the round-2 review: a census of every test output that reaches the classifier, the scan guarantee as a promise line, `classifyReplay` named as the rejector; revision 1 re-cut the Codex draft under D-027 so each red fails against the code before it, and narrowed the exception to assertion failures) · written and signed by the architect (`claude-opus-5-5`) under D-027 and D-061 §6: host-security code, the Patron approves the design and Defaults before branch · 2026-10-14 · master 0526a197.

Read enumeration: none: `classifyReplay` reads only the `status` and `output` its caller passes; the tests use inline transcripts and read no record or file.

Red order: one at a time

## Intent

Decree family: host-replay-classification

`classifyReplay` (`scripts/replay-accept.mjs`) runs the `POISON` regex over the whole replay output before anything else. W-255's red 2 (`studio/ci/reds/W-255/02.log` on `opus/W-255`) is one genuine `AssertionError`, but its test name and expected message say "sandbox", so the receipt mint refused it: `red 2 did not reproduce its assertion failure at c8518b78…: the output names an environment failure (sandbox)`. The merge queue's certify reaches the same function (`scripts/ci-certify.mjs` → `bisellium run` → `scripts/run-builder-host.mjs:770`, `output` = child stdout + `"\n"` + child stderr), so certify would refuse it too.

The fix: the poison scan skips exactly one region, the failing test's own TAP block, and only when that block reports an assertion failure. Everything else is scanned as today; anything the parser does not recognise is scanned whole.

W-238 (brief admission refuses an unreplayable Genuine red) is unchanged and stays the spec-time guard. If it ever judges output, it imports `classifyReplay`, so admission and replay share one verdict. W-098's half of the 2026-10-06 triage note (the replay's whole-output poison scan) is this opus; its `rules/evidence.ts` detector stays W-098's.

## Files owned

- `scripts/replay-accept.test.mjs`: `W-265-b1` and `W-265-b2`, inside `if (only === undefined)` (W-240's pattern in `host-cells.test.mjs`), so `--behaviour 4` still selects W-130's test alone; one header line naming them.

## Interfaces

`classifyReplay({ status, output })`: signature, result shapes, reason strings, `ASSERTION`, `POISON`, `PW_*` unchanged. New order: status 0 refuses; then Playwright routing (`PW_SUMMARY` via `matchAll`, `PW_BANNER`) is decided on the full output; Playwright output gets today's full-output poison scan, count and matcher checks; any other output gets `POISON.exec(outsideOwnFailure(output))`, then today's `ASSERTION.test(output)` on the full output.

**The failing test's own block** (node `--test-reporter=tap`, root level, verified on node v25.9.0). Split `output` on `"\n"`. The block exists only when all hold:

1. Exactly one line in the whole output matches `/^not ok /` (column 0). Its index is `n`.
2. Line `n` matches `^not ok [1-9][0-9]* - (.+)$`; call the capture `name`.
3. Line `n-1` is exactly `# Subtest: ${name}` (node escapes both lines identically; a `# TODO`/`# SKIP` suffix breaks the match).
4. Line `n+1` is exactly `  ---`.
5. A later line is exactly `  ...`; the first such is the closer. Every line strictly between `  ---` and the closer begins with two spaces.
6. *(behaviour 2)* Among the between-lines, exactly one starts with `  code:` and it is exactly `  code: 'ERR_ASSERTION'`; and exactly one starts with `  error:`. Node prints the thrown error's keys at the block's two-space indent (text inside a multi-line value sits at four or more), and when an assertion wraps another error (`assert.doesNotReject`, `assert.doesNotThrow`), it prints that error's `error:` and any `code:` at two spaces too, under `actual:`. So a thrown non-assertion error, and an assertion wrapping any error (with a code, such as `'ERR_MODULE_NOT_FOUND'` or `'ENOENT'`, or without one), are scanned whole.

When all hold, `outsideOwnFailure` returns the output with lines `n-1` through the closer removed, the rest joined by `"\n"` (no `POISON` alternative spans a newline, so the join creates no match). Otherwise it returns `output` unchanged: no recognisable block means scan everything, so it fails closed. Consequences: a second root `not ok`, a nested failure (subtests or `describe`: the parent's `# Subtest:` is followed by indented lines), a line between the headings, a name mismatch, a directive, a missing delimiter or closer, an unindented body line, a non-assertion error, or an assertion wrapping a thrown error each gets no exception.

Promise scan-outside-own-block: for non-Playwright output, every line outside the one failing test's own assertion block (lines before the heading, after the closer, other tests' lines, the `# fail` summary and the appended stderr), and the whole output when no such block is recognised, goes through the `POISON` scan before a red is accepted — limit: the block's own lines (the test name and the YAML node prints for its one `AssertionError` that wraps no thrown error) are not scanned, so an assertion that quotes an environment failure as text in its message or compared values (for example a child's stderr) is accepted; a test that deliberately forges a TAP block or an `AssertionError` is out of scope (D-045).

**What a test could hide, plainly.** Only the failing test's name and the YAML node prints for its one `AssertionError`: the assertion message, `expected`/`actual`, `stack`, `location`. So an assertion whose message or compared values quote an environment failure (e.g. `assert.equal(child.status, 0, child.stderr)` where the child hit "permission denied" in the cell) is accepted as a red even if the cause was the cell. A test that itself throws ENOENT or a missing-module error is not hidden: its block carries `code: 'ENOENT'` / `'ERR_MODULE_NOT_FOUND'` and is scanned whole. Nor is one that wraps such an error in `assert.doesNotReject`/`assert.doesNotThrow`: the wrapped error adds a second `  code:` or `  error:` line (verified on node v25.9.0 for a missing module, an ENOENT, a SyntaxError and a code-less `Error`). Bounds: the exit is non-zero; the run has one root failure; poison anywhere else still refuses; the rebased-title check is unchanged; the build review reads the red; and the tip's `bisellium ci --offline` gate runs confined after the replays, so an environment failure that persists fails the green side and no receipt is minted. The residual is an environment failure that happens only at the red commit and only inside an assertion's quoted text. Under D-045 (mistakes, not adversaries) that is accepted; forging TAP on purpose is out of scope.

### Input domain

Every rejection fails closed: no receipt is minted and certification fails.

| Record | Valid domain | Rejected by |
|---|---|---|
| Replay status | non-zero or `null` continues to output classification | `classifyReplay` (existing): exit 0 is refused before any parsing |
| Playwright output (banner or line-start `N failed`) | today's full-output poison scan, one failed test, an `expect(...)` matcher | `classifyReplay` (existing): every current Playwright refusal, TAP-looking lines included |
| The failing test's own TAP block | rules 1–6 above, exactly | `classifyReplay` (existing): its fail-closed preprocessing `outsideOwnFailure` (new) removes only a block meeting rules 1–6 and otherwise returns the whole output, so poison outside the block, or anywhere in an unrecognised output, is refused |
| All other non-Playwright output | no `POISON` match outside the block; `ASSERTION` on the full output | `classifyReplay` (existing): poison or no assertion-level failure is refused |

## Plan

**The problem.** Before a feature is accepted, the host re-runs each recorded failing test ("red") in a locked-down copy to prove the failure is real. It refuses any re-run whose output mentions an environment problem such as "sandbox", "permission denied" or a missing file, because those usually mean the test broke for the wrong reason. W-255's second red is a real failure, but the test is about sandbox rules, so its own name and expected message contain "sandbox", and the host refused it. The merge queue's final certification uses the same check, so W-255 cannot land as things stand.

**The fix.** The check stops looking for those words inside the failing test's own report (its name and error details), and only when that report is a plain assertion failure. It still looks everywhere else: other tests, the summary, error output, anything before or after.

**What stays guarded.** A run that passes; a run with more than one failure; a crash on a missing file or module, even when an assertion wraps it (the report names that error); any environment word outside the one report; anything the check cannot parse with certainty (it then scans everything, as today); all browser-test rules.

**The risk, and why it is acceptable.** A test that asserts on another program's output, and quotes that output in its failure message, could hide a real environment problem inside its report. That needs a test written that way, a failure that happens only at the red and not at the final check (the final, locked-down test run would fail too), and the build reviewer missing it. Our threat model is mistakes, not attackers, so this narrow gap is acceptable.

**How it unblocks W-255.** The receipt mint runs the copy of the check in the folder the command is run from: for W-255, its own branch folder. Certification runs master's copy as it stood when the merge queue picked the change up. So W-265 lands on master first; W-255 is then rebased onto master (picking up the fixed check), its receipt re-minted from its own folder, build-reviewed, and only then queued, so certification also runs the fixed check. W-255's own code does not change.

**Rejected.** Removing "sandbox" from the word list: it would also hide real sandbox denials everywhere. A waiver plus a bypass merge for W-255: it skips the security gate once and leaves the next test like it stuck. Rewording W-255's test message: it bends the test to the checker, and the next sandbox-related test hits the same wall.
