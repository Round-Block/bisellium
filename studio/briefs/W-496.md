## Intent

Every Bash call meets two PreToolUse hooks (`.claude/settings.json`). The first is a jq one-liner, the only hook that is not `bisellium`. It replaces each quoted string with `Q`, then refuses the call when the rest holds an `&` with a blank or a line end beside it, or the word `nohup`, `setsid` or `disown`. It does not know heredocs. On 2026-11-01 a ladder-runner wrote a checkpoint script by heredoc, and the script held `&mdash;` and `&middot;`. The guard read the entities as background work and refused the call, which stopped the W-452 done run. The same pattern refuses `git grep -e nohup`, since the word is matched anywhere, as an argument too. And it lets `sleep 600&echo` run, which does background `sleep`. The pattern has no test: `instructions.test.ts` pins its text byte for byte, nothing more.

**The design: the check moves into the guard, as code with rows, and the jq hook goes.** The hook may only call the `bisellium` on PATH, never a script in the agent clone (CLAUDE.md: hooks run unsandboxed). `bisellium hook-event guard` already runs on every Bash call, from the main thread and from every subagent, and its classifiers are lexical code in `guard.ts` with rows in `guard.test.ts`. So the check becomes one more Bash rule there, `backgroundForm`, and the rows below are real tests of it. A fixed jq pattern cannot read a heredoc, which needs the delimiter word carried to later lines, so keeping jq would keep the bug.

1. **What is refused (behaviour 1).** A foreground Bash call (no `run_in_background`), from any thread, is refused when its code holds an `&` that ends or separates a command: `sleep 600 &`, `a & b`, `a&b`, `x 2>&1 &`, inside `( )`, `{ }` or `$( )`. It is also refused when `nohup`, `setsid` or `disown` is a simple command's first word. That is the word after the prefixes the guard's `strip` already drops (assignments, `env`, `timeout`, `exec`, `nice`, `command`, `xargs`, `time`, `!`, `if`/`then`/`do`), by any path (`/usr/bin/nohup`). An `&` that is part of `&&`, follows `<`, `>`, `|` or `;` (`>&2`, `2>&1`, `<&3`, `|&`, `;&`), or comes before `>` (`&>`, `&>>`) is not background, so it runs. The same holds for the word as an argument (`grep -e nohup`). The refusal names the form it found, as in the line below. The rule sits after the main thread's ladder-write refusal, so that refusal's text is unchanged.
   `` refused: `&` puts work in the background, where it dies when this Bash call returns (W-496): run the long command as its own Bash call with the run_in_background parameter set to true instead ``
2. **What is never read as code (behaviour 2).** The scan (`shellCode`) reads the command as bash does. It skips single quotes, `$'…'` and double quotes (a backslash escapes inside the last two), a backslash-escaped character, a `#` comment that opens a word, and `${…}` and `$((…))`, where an `&` is a parameter or arithmetic operator. It also skips heredoc bodies. After `<<` or `<<-` and its delimiter word (quotes removed), the body is the lines after the next newline, up to one equal to the delimiter (`<<-` drops leading tabs). Two heredocs on one line are read in turn. Code after the terminator, and the rest of the operator's own line, is judged again. The words of the `nohup` check are read from the same text with the comments and bodies taken out. So the 11-01 heredoc runs, and `cat <<'EOF' … EOF` followed by `sleep 600 &` is still refused.
3. **The wiring (behaviour 3).** `.claude/settings.json` drops the jq group, so PreToolUse holds the guard's group alone (`Bash|Write|Edit|NotebookEdit`). Both of `instructions.test.ts`'s settings rows now read that one group. The CLAUDE.md hooks line (rendered from `instructions.ts`) and `docs/INSTRUCTIONS.md` say what the guard refuses.

The guard is deny-only and fail-open (W-310). An unreadable input or a throw lets the call run, as the jq hook did when jq was missing.

Promise refuse: a foreground Bash call, any thread's, is refused with the refusal naming `&` when its code (outside quotes, escapes, comments, `${…}`, `$((…))` and heredoc bodies) holds an `&` that is not `&&`, follows none of `<`, `>`, `|`, `;` and precedes no `>`; else with the refusal naming `nohup`, `setsid` or `disown` when one is a simple command's first word after `strip`'s prefixes, by any path; a `run_in_background` call is never refused by this rule, as pinned by `W-496-b1` "a trailing & is refused" and pinned by `W-496-b1` "a separating & is refused" and pinned by `W-496-b1` "an & with no blanks is refused" and pinned by `W-496-b1` "an & in a command substitution is refused" and pinned by `W-496-b1` "a subagent's trailing & is refused" and pinned by `W-496-b1` "nohup as a command is refused" and pinned by `W-496-b1` "nohup after prefixes is refused" and pinned by `W-496-b1` "nohup by its path is refused" and pinned by `W-496-b1` "&& runs" and pinned by `W-496-b1` ">&2 runs" and pinned by `W-496-b1` "&> runs" and pinned by `W-496-b1` "nohup as an argument runs" and pinned by `W-496-b1` "a run_in_background call's & runs" — limit: a script the command runs (`bash -c '…'`, a file, a heredoc fed to a shell) is not read, as quoted text never is; a detacher behind a prefix `strip` does not drop (`sudo`, `while`) is not seen, and `command -v nohup` is refused; `simpleCommands`, `strip` and `base`, and the guard's input reading and fail-open catch (`runHookEvent`), are reused unchanged.

## Interfaces

- `backgroundForm(command: string): string | undefined` (new export of `guard.ts`): `"&"`, `"nohup"`, `"setsid"`, `"disown"`, or undefined.
- `shellCode(line: string): { code: string; amp: boolean }` (new, not exported): `code` is `line` without its comments and heredoc bodies; `amp` is true when a background `&` is found.
- The refusal: `` refused: `<form>` puts work in the background, where it dies when this Bash call returns (W-496): run the long command as its own Bash call with the run_in_background parameter set to true instead ``, on stderr with exit 2, through `handleGuard`.
- The order in `guardRefusal`'s Bash branch: the main thread's ladder write; then, unless `run_in_background` is true, this rule; then the `pgrep -f` wait, the unbounded loop and the second background run (unchanged).
- Unchanged: `simpleCommands`, `commandSeq`, `strip`, `base`, `ladderWrite`, `unboundedLoop`, `selfMatchingWait`, `callerLiveRuns`, `guardWiring`, `GUARD_COMMAND`, `runHookEvent`, `handleGuard`, every other hook in `.claude/settings.json`.

Limits, stated:

- Unchanged code the promises lean on is a stated limit, not a guarantee (D-076 E): `simpleCommands`, `strip` and `base` (the word split and the prefixes), `runHookEvent`'s input reading and fail-open catch, `handleGuard`, `guardWiring`, and Claude Code's PreToolUse hook (exit 2 refuses, the 2 s timeout).
- The check is lexical, as the guard's other Bash rules are (its header, D-045). Deliberate evasion (`eval`, an alias, a function, a variable holding `&`) is not caught.
- A script the call runs is not read: `bash -c 'sleep 600 &'` runs, as it did under jq, which also cut quoted text.
- The check is live once the Patron's clone, the `bisellium` on PATH, has the merge. Until the agent clone's settings and that install agree, either both checks run or neither.

## Out of scope

- Reading the script a call runs (`bash -c`, a file, a heredoc fed to a shell) for background syntax. The record limits the fix to quoted and heredoc text never matching; a `-c` reading as `unboundedLoop` does is its own opus.
- `sudo`, `while` and other prefixes `strip` does not drop; `command -v` as a lookup.
- Any other guard rule, the PATH install (`scripts/agent-workspace.sh`), and the other hooks.
- Architecture: unchanged. No package edge, module, seam, lifecycle state or transition changes. One hook leaves `.claude/settings.json`, and its check moves into the existing guard.

Size: three behaviours, about 110 source lines in one file and about 120 test lines in three, plus the settings, two doc lines and one paragraph: 2 points. 1. The check that stops background work in an ordinary call moves out of a one-line jq pattern into the bisellium guard, where it has tests. The jq hook leaves the settings file. Agree?
2. It now refuses only real background syntax: an `&` that ends or separates a command, or nohup, setsid or disown run as a command. Text in quotes, in a heredoc (like the 11-01 HTML file) or in a comment never counts, and neither do `&&`, `2>&1` or `&>`. Agree?
3. Some calls the old pattern let through are now refused, because they really did run work in the background: `sleep 600&echo` with no spaces, or an unquoted web address holding `&`. Agree?
4. A script a call runs (`bash -c '…'`) is still not read, as before. Agree?
5. `.claude/settings.json` is a file you own, so you merge this one. The new check is live once your clone, the bisellium on PATH, has the merge. Agree?
