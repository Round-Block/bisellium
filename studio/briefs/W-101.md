# W-101 — bisellium new allocates past every id on every branch

Status: **architect-signed** under D-027 — architect (active Codex mapping:
Astra-medium), 2026-10-01. Sol drafted; the architect amended and signed.
Revision: **3**, expands queued acceptance filings from two to five; signing
amendments below. This text signature does not
write the opus's spec gate; that remains a CLI operation on its owning ref.

## Intent

An id that is absent from the checked-out tree is not necessarily unused.
`bisellium new` currently scans only `<studio>/opera/`, so a filing from
`master` can mint an id already committed on another branch. This is the
actual shape in this repository on 2026-10-01:

- `codex/maps-lookup-experiment` contains `W-102` through `W-106`;
- `codex/public-source-canary` contains `W-107` through `W-109` as well;
- `codex/persistent-workflow` contains another `W-102`;
- `codex/read-efficiency` contains `W-102` through `W-107`, and
  `codex/source-adapter-canary` contains `W-102` through `W-108`;
- `master` contains none of those ids; and
- this worktree contains `W-101`, while the maximum `W-*` visible through
  local and remote-tracking refs is `W-109`.

The next `W-*` allocation in `studio` must therefore be `W-110`, even from a
checkout whose local `studio/opera/` ends earlier.

This is not only a `new` defect. There are five record-family/call-site rows
that mint sequential ids, implemented by four scan bodies in three modules:

| Record | Production allocator | Present behaviour |
| --- | --- | --- |
| opus `W-*` | `packages/cli/src/new.ts:53` (`newItem`) | scans local `opera/`; allocates at line 57 |
| opus `W-*` | `packages/cli/src/new.ts:170` (`runNew`) | duplicates that local scan; allocates at line 174 |
| lesson `L-*` | `packages/cli/src/retro.ts:381` (`draftRetro`, helper at line 74) | scans local `lessons/`, then carries an in-memory offset at line 383 because lessons are written later |
| petitio `P-*` | `packages/cli/src/retro.ts:430` (`draftRetro`, same helper) | scans local `petitiones/` |
| petitio `P-*` | `packages/commands/src/talk.ts:173` (`openPetitio`) | independently scans local `petitiones/`; allocates at line 177 |

`packages/commands/src/writes.ts:616` (`runAnswer`) does **not** allocate: it resolves
and edits an existing petitio. Nor is there a production `D-*` allocator.
Decision records are read and validated; `talk`'s `ACTUM:` path writes a
date-and-slug acta entry (`packages/commands/src/talk.ts:201`, with a
filename collision suffix at line 207), not `decisions/D-*.md`. That suffix
is outside the sequential record-id families. The ref-wide maxima measured
today are `P-013`, `L-038`, and `D-028`; the last is measurement, not a new
decision-writing scope.

Replace every real sequential allocator above with one shared implementation
in `@bisellium/commands`. The helper owns both discovery and the exclusive
creation attempt; callers supply the officina root, record directory, prefix,
and a renderer for the bytes. Keeping the write in the helper is necessary:
returning a supposedly free string to a later ordinary `writeFileSync` would
retain the race this opus is meant to close.

## The id universe

Ids remain separate families. A `W-*` allocation takes the maximum numeric
suffix among `W-*.md` in that officina's `opera/`; `P-*` uses its
`petitiones/`, and `L-*` its `lessons/`. A high `P-*` must not advance a
`W-*`: the prefixes name different record kinds, their directories have
different contracts, and existing ids already overlap numerically.

For one family, the candidate maximum is the union of:

1. exact matching filenames in the requested directory of the current
   working tree, including untracked and otherwise uncommitted records; and
2. exact matching paths in the same officina directory in every existing
   `refs/heads/*` and `refs/remotes/*` ref.

The implementation finds the repository containing the officina, computes
the officina's repository-relative path, obtains refs with the read-only
equivalent of:

```text
git for-each-ref --format=%(refname) refs/heads refs/remotes
```

and reads each relevant tree with `git ls-tree`, also read-only. Commands use
argument arrays, not a shell-built command line. Only a basename exactly
matching `^<prefix>-(\d+)\.md$` contributes. File contents and front matter
do not: the filename is the collision being prevented.

Canonicalize the officina root and Git worktree root with `realpath` before
computing the relative path. Discover Git from that officina, not the process
cwd; linked worktrees use their own worktree root, not the common Git directory.
This keeps symlink aliases from silently selecting a different tree path.

The repository-relative officina path is part of the lookup. For
`examples/sample-studio`, refs are inspected at
`examples/sample-studio/opera/`, never at `studio/opera/`. Its ref-wide opus
maximum is `W-007`, so it allocates `W-008` even though the same repository's
real officina reaches `W-109`. This is the necessary meaning of "same
officina on every ref", and prevents the fixture from inheriting production
bookkeeping merely because both live in one Git repository.

Tags, stash, refs outside `refs/heads/*` and `refs/remotes/*` (including
`refs/pull/*`), and an upstream server not represented locally are outside
the universe. Every ref inside the two required namespaces contributes,
including any cached queue or pull-request ref there; no name-based exclusions.

Every basename matching `^<prefix>-(\d+)\.md$` contributes its exact
nonnegative integer suffix, regardless of digit count or leading zeroes;
compare suffixes using arbitrary-precision arithmetic or an equivalent exact
decimal comparison. The maximum suffix permitted for a newly allocated record
is 999,999,999. If max-plus-one, or any candidate reached after an EEXIST
collision, exceeds that bound, refuse with a clear id-exhaustion error before
rendering or writing that candidate, leaving no newly created record or
companion file. An over-bound suffix discovered on a ref is not a Git failure
and must not trigger local-only fallback. (Architect ruling A, round 2,
2026-10-01.)

### Git degradation and stale remote state

Allocation stays usable when `git` cannot be executed or the officina is not
inside a repository. If repository discovery, ref enumeration, or tree
inspection fails, the helper falls back to the working-tree directory scan
and writes a clear warning to stderr saying that ref-wide allocation was
unavailable and local records alone were used. It does not throw merely
because Git is unavailable. The caller's existing result/exit-code contract
otherwise remains unchanged.

This chooses filing availability over ref-wide uniqueness during Git failure;
the warning must not claim that the degraded id is unused on other refs.
Discard partial ref results on any such failure so the fallback has one
testable meaning. Filesystem scan/create errors are not Git degradation.

The allocator never runs `git fetch`, implicitly or otherwise. Fetch is a
network mutation, would make an ordinary local filing depend on credentials
and availability, and still could not provide a global lock. Remote-tracking
refs are a cache: the helper uses the cache present when invoked. If it is
stale, ids known only to the server are necessarily invisible. Operators who
need fresher knowledge fetch explicitly before filing.

Every allocator Git invocation sets GIT_NO_LAZY_FETCH=1. Before inspecting
ref objects, determine the Git version and inspect effective configuration
for extensions.partialClone and any remote.<name>.promisor key. On Git older
than 2.45.0, the presence of either marker makes ref-wide discovery
unavailable: perform no ref-object inspection and use the existing warned
local-only fallback, discarding any partial ref results. An unparseable
version or failed configuration inspection takes the same fallback; a
successful inspection finding no markers does not. Test rows in
`packages/cli/src/ids.test.ts` simulate older Git with each marker
independently (asserting the warning, the local-only result, and the absence
of object-reading commands or fetch attempts), with older Git without markers
and Git 2.45+ with markers as controls, retaining the environment-propagation
assertions. (Architect ruling B, round 2, 2026-10-01.)

### Concurrent writers in one checkout

After discovering maximum `N`, the helper renders `N + 1` and creates the
record itself with `writeFileSync(target, bytes, { flag: "wx" })`, following
the non-overwrite pattern at `packages/commands/src/verdict.ts:181`. On
`EEXIST`, it increments and tries the next id; it never overwrites, truncates,
or treats the collision as success. Other I/O errors propagate to the
caller's established error handling. This closes the same-checkout race
without a stale lock file.

The guarantee is deliberately bounded: exclusive create coordinates
processes that share a filesystem checkout. Separate worktrees can still
race after observing the same ref set; Git refs are evidence, not a
distributed reservation service. Once either filing becomes a visible ref,
later allocations advance past it.

`runNew --brief` reserves the opus record exclusively before writing its
companion brief, and the brief is also a non-overwriting `wx` write. If the
brief write fails, the newly created opus record from this invocation is
removed before reporting failure, so the command does not leave a `spec:`
pointer to an absent or pre-existing brief. `newItem` has no companion file.
Retro writes each allocated lesson through the shared helper as it is
allocated; its recurrence calculation continues to use the history snapshot
taken before this retro, so its meaning does not change. Petitiones from
retro and talk use the same helper and collision retry.
Recurrence still combines that snapshot with this invocation's new lesson,
exactly as `packages/cli/src/retro.ts:402` does today; it does not reread the
newly written lessons into history. Retro is not an all-or-nothing transaction.

W-101 accepts the residual directory-replacement race between realpath/lstat
checks and path-based directory creation or exclusive file creation,
including replacement of an ancestor. Canonicalization and real-directory
checks before scanning and immediately before each exclusive create remain
required, but do not guarantee containment against concurrent hostile
directory replacement. The same-checkout exclusive-create guarantee assumes
stable directory ancestry; race-free ancestor traversal is outside this opus.
(Architect ruling C, round 2, 2026-10-01, extending W-087's accepted
limitation to this allocator.)

## Interfaces

Add one commands-package module with one production seam, named for ids rather
than for any caller. Its effective contract is:

```ts
createNextRecord(
  studioRoot: string,
  directory: "opera" | "petitiones" | "lessons",
  prefix: "W" | "P" | "L",
  render: (id: string) => string | Uint8Array,
): { id: string; path: string };
```

The exact type names may follow house style, but discovery plus exclusive
write must remain one operation and callers must not regain a scan/write
gap. The helper returns the absolute created path so `runNew --brief` can
perform its bounded rollback without reconstructing it. It may be generic
enough for a future `D-*` writer, but this opus adds no decision verb and no
unused decision-specific branch.

The helper may synchronously invoke Git because every caller is synchronous
today. It must not print in the normal Git-backed case. Its only direct user
output is the stderr degradation warning; existing caller stdout stays byte
compatible (`W-NNN`, `petitio P-NNN opened`, and existing retro results).

## Behaviours to test

1. **Every existing ref and the dirty working tree contribute to `W-*`.** In
   a temp repository, put progressively higher opus filenames on two local
   branches and one remote-tracking ref, leave a still-higher uncommitted
   opus in the tested officina, then invoke both `newItem` and `runNew` in
   independent fixtures. Each creates exactly max-plus-one with matching
   filename/front-matter id and does not alter any pre-existing record. Pin a
   repository shaped like today's gap to `W-109 -> W-110`. Genuine red: both
   current `new.ts` paths inspect only the checked-out `opera/` and one is a
   duplicate implementation.
   Use separate rows where each local branch, the remote-tracking ref, and
   the dirty tree is independently decisive; one dirty maximum must not mask
   a broken ref scan. Pin exact filename matching, nonrecursive directory
   scope, filename-over-front-matter precedence, and family independence.
2. **The shared seam covers every non-opus mint.** Temp-ref fixtures put a
   higher `L-*` on a non-checked-out branch and a higher `P-*` on a
   remote-tracking ref. `draftRetro` advances past both for its lesson and
   recurring-class petitio, and a fake-harness `talk` escalation advances
   past the same `P-*` universe. Add a source census that pins these callers
   plus both `new.ts` entry points to `packages/commands/src/ids.ts` and
   rejects the old local max scans. Genuine red: retro's private `nextId`
   and talk's private scan see only local files and no shared module exists.
3. **Git absence degrades visibly and safely.** Run rows for an officina
   outside any repository and for a process whose `git` executable cannot be
   found. In each, a local `W-004` leads to a successfully and exclusively
   created `W-005`; stderr contains both the Git/ref limitation and the
   local-only fallback, and stdout/result contracts remain intact. Genuine
   red: today's local scan happens silently, so neither row emits the
   required warning.
   Also inject failures at repository discovery, ref enumeration, and a tree
   read after a higher ref has already been read; all discard partial results
   and use the same warned local-only fallback. Pin that filesystem failures
   retain the caller's error contract instead of being swallowed as Git errors.
4. **Remote-tracking means the cache, never an implicit fetch.** Give a temp
   clone a remote-tracking `W-005`, then advance its bare origin to `W-009`
   without fetching and replace the clone's remote URL with a guaranteed
   unreachable one. Allocation still creates `W-006`: the existing
   remote-tracking-only `W-005` must affect the answer, while server-only
   `W-009` must not. A Git-command spy pins `for-each-ref` plus `ls-tree`
   while rejecting `fetch` and every network command. Restore the test
   remote URL, fetch explicitly in the test setup, and an independent
   allocation then creates `W-010`. Genuine red: the current allocator
   invokes none of the required ref-reading commands and chooses from the
   checked-out tree rather than the cached remote-tracking `W-005`.
5. **Two processes in one checkout cannot claim or overwrite one id.** This
   red is synchronized *inside* the race window, not merely before command
   start. First add a minimal test-only seam that runs once after a process
   has discovered and rendered its initial candidate but before its first
   create attempt; adding that seam must not yet change the ordinary write.
   The focused test gives two real CLI child processes a filesystem barrier
   through that seam. Each child writes a distinct ready marker containing
   the same chosen id, then blocks until the parent writes the release marker.
   The parent releases only after it has observed both ready markers and
   asserted that both chose the same candidate. Against the pre-fix ordinary
   writes, both children then report the same id and one record overwrites the
   other: the assertions for two distinct ids/files and both distinct titles
   deterministically fail. With `wx`, one child creates the candidate; the
   other receives `EEXIST`, increments, and retries without re-entering the
   one-shot barrier. Both succeed, report different consecutive ids, and both
   files retain their own title. A direct collision row also forces the first
   exclusive create to receive `EEXIST` and asserts retry rather than
   overwrite or failure. The synchronization seam is test-only, carries no
   public CLI flag, and is inert unless the focused child-process test opts
   into it. Genuine red: the barrier proves the existing ordinary write
   deterministically collapses two claims onto one file; `wx` retry does not
   exist.
6. **The fixture officina is ref-aware but isolated from the real one.** In
   one temp repository, place `studio/opera/W-999.md` and
   `examples/sample-studio/opera/W-012.md` on non-checked-out refs while the
   checked-out sample ends at `W-007`. Filing into the sample creates
   `W-013`, not `W-008` and not `W-1000`; filing into `studio` independently
   creates `W-1000`. Genuine red: today's sample allocation ignores its
   off-branch `W-012`; an implementation that scans the whole repository
   rather than the officina-relative path fails the opposite assertion.
   Repeat through a symlink alias and in a linked worktree, invoking from an
   unrelated cwd, to pin physical officina identity and worktree-relative lookup.
7. **Multi-record callers retain their consistency semantics.** A retro with
   three distinct classes creates consecutive, non-overwriting lesson ids
   and consecutive petitiones where applicable, with recurrence computed
   from pre-retro history plus the current lesson once. For `runNew --brief`, pre-create the would-be
   brief after opus-id discovery: the command refuses to overwrite it,
   removes only the opus it just reserved, and leaves the pre-existing brief
   byte-identical. Genuine red: retro's lesson offset is coupled to its local
   scanner, while `runNew --brief` currently uses ordinary writes and can
   overwrite the companion path. Keep recurrence rows as regression coverage;
   the companion collision is this behaviour's required pre-fix red.

Each numbered behaviour gets its own recorded red via `bisellium red`; the
focused test accepts a behaviour selector so no two behaviours share one
undifferentiated failure. A red is assertion-level and must fail for the
specific pre-change reason stated above, not merely because `ids.ts` has not
yet been created.

## Out of scope

- A server-backed or distributed reservation service across separate clones
  or worktrees.
- Implicit `fetch`, creation or mutation of refs, pushing, or any other
  network operation.
- A `decide` command or allocation of new `D-*` records.
- Renumbering the already-colliding `W-102`, or rewriting existing opera,
  petitiones, lessons, or decisions.
- Changing id spelling, zero-padding, record front matter, command output, or
  caller exit codes beyond the specified fallback warning.

## Signing amendments

Revision 2 resolves the draft's open design questions: reserve the opus first
because it is the shared id claim; roll back only that invocation's opus on
companion failure. Keep the one-shot test seam private and inert in ordinary
calls. Git failure uses warned local-only fallback, not silently partial ref
knowledge; physical officina identity is required. Atomicity remains limited
to one checkout, not unpublished filings in separate worktrees.

Round-2 rulings (architect, 2026-10-01, on censor round 2 and sec-lead's
re-check): A — every exact match contributes with a 999,999,999 mint bound
and refusal beyond it; B — older Git with partial-clone markers takes the
warned local-only fallback; C — the directory-replacement race is accepted.
Sec-lead's boundary rows (999,999,999 succeeds, 1,000,000,000 refuses,
including after an EEXIST collision, with no partial record or companion
file; over-bound matches local and ref-only; long leading-zero suffixes
contribute their exact value) are a test-only addition within Files owned.

The signing pass checked all five allocation rows and the excluded writers,
searched production allocation/write sites, and inspected all 170 existing
heads/remote-tracking refs with `for-each-ref` and `ls-tree`. Maxima were
`W-109`, `P-013`, `L-038`, `D-028`, and sample `W-007`. Amendments correct
the scan-body count, complete the branch snapshot, pin discriminating test
rows and recurrence semantics, and add the Patron's live acceptance filings.
The seven numbered behaviours require seven recorded reds; the live filings
are an additional completion criterion, not an eighth fabricated red.
