## Intent

Today a refresh needs the Patron: a session reaches its context limit, lands its handoff and stops, and nothing starts the next one until he types a command. Trial 3 (2026-11-08) proved the launch shape by hand: `claude -p` from the agent clone, with the agent's GitHub config and no ambient token, `--permission-mode dontAsk`, `--add-dir ~/.bisellium-evidence` and an explicit allow list with an `Edit` rule beside each `Write` rule. It booted from the landed handoff with every hook firing and no permission denial. This opus makes that shape a tested verb, `bisellium launch`, which a systemd user timer the Patron installs runs every 30 minutes at night. Each run starts at most one normal session; unless it is safe to start one, a real run may sync the agent clone, then otherwise refuses without writing launch state or starting a session.

1. **Where it runs from (behaviour 1).** The verb runs only as the Patron's clone's CLI, the installed `bisellium` (`~/.local/bin/bisellium`, the Patron's clone at master, W-379). It refuses when its own file's checkout is in the agent clone or the evidence folder, or is off master or holds a tracked change. It also refuses when it runs inside a Claude Code session (`CLAUDECODE` or `SANDBOX_RUNTIME` set) and when its state folder is in a folder an agent writes. Before its first PATH-resolved child call, it validates PATH and refuses any relative or agent-writable entry; it runs nothing an agent can write: every PATH entry and the real target of each selected executable (`git`, `bash`, `gh`, `claude`) is absolute and outside both agent-writable folders, and every link in a PATH folder, whatever its name, is judged at its real target, dangling or not; every other form is refused before execution. It then runs `git`, `bash` and `gh` by the absolute paths PATH selected, never by name. Its own interpreter is chosen before any of its code runs, so no judgement of its own can cover it: the timer's unit names `node` by absolute path under a fixed PATH (behaviour 2), and typed in the Patron's terminal, his shell's PATH selects it through the shim's `#!/usr/bin/env node`, a stated limit. It reads its allow list, its prompt and `scripts/agent-workspace.sh` from its own checkout only, and reads the agent clone without running anything there. `--dry-run` judges everything a real launch judges except the sync, and prints the exact `env … claude …` line it would run. It writes nothing and runs no sync.
2. **The allow list (behaviour 2).** `.claude/refresh/launch.json` (code-owned) holds `allow`, `disallow`, `addDirs` and the nightly `cap`. `configFaults` refuses a malformed one: a `Write(path)` rule with no `Edit(path)` beside it (trial 2's failure), a path rule that is not `~/…`, `//…`, `{agent}/…` or `{evidence}/…` (a `/path` rule is the project's), and a rule that does not parse. A path rule starting `{agent}` or `{evidence}` is passed as `//` and that folder's real path. The shipped `launch.json`, after `runLaunch` resolves its path rules, grants Edit and Write under the resolved `AGENT_DIR` and evidence folder, and the launch refuses when those resolved grants are absent. The shipped list is the working session's, read from the census of 403 session transcripts over three days (`allow-census.out`: Bash 9,335 calls, Read 1,277, Agent 401, Write 534, Edit 90, SubagentHandback 524, Grep, Glob, TaskStop, SendMessage, PushNotification, ToolSearch). It grants `Agent`, `Bash`, `Read`, `Glob`, `Grep`, `TaskStop`, `SubagentHandback`, `SendMessage`, `PushNotification` and `ToolSearch`, and `Edit` and `Write` under `{agent}`, `{evidence}` and `//tmp/claude-*/`. It denies force-push, `gh pr close`, `git stash drop`, `git worktree prune`, a nested `claude`, `scripts/cascade-loop.sh` and writes under the agent clone's `.claude/` and `~/projects/`. `.claude/refresh/prompt.md` is the fixed refresh prompt, carrying no queue state and no agent clone path (it names the session's working folder). `bisellium-launch.service` and `bisellium-launch.timer` are the units the Patron copies into `~/.config/systemd/user/`. The service runs `/home/linuxbrew/.linuxbrew/bin/node %h/.local/bin/bisellium launch` (an absolute Node 25: this host's, the Patron's own at install) under one fixed `Environment=PATH=%h/.local/bin:/home/linuxbrew/.linuxbrew/bin:/usr/local/bin:/usr/bin:/bin`, so nothing is reached through PATH before the launch judges PATH: neither names an agent-writable folder or a relative or empty entry, and the unit runs no other command and sets no other environment.
3. **Nothing runs in the agent clone (behaviour 3).** The launch refuses while its own lock names a live process (pid and start time, `/proc/<pid>/stat` field 22), or while any process other than itself and its parents has its working folder in the agent clone: a `claude` (by `comm` or argv[0]) is a live session, anything else is background work (a builder, a ci run, codex, a shell).
4. **Its own state (behaviour 4).** It refuses after a launch that did not finish (the lock names a pid that is gone or was reused), after a last result it cannot read (`session.json` not a JSON object with a `permission_denials` list), after a last session with any permission denial, and at the cap: `cap.starts` launches (shipped: 4) in the last `cap.hours` hours (shipped: 12). The state is `${XDG_STATE_HOME:-~/.local/state}/bisellium/launch/` (`lock.json`, `starts.jsonl`, `session.json`), outside every folder the sandbox lets an agent write.
5. **The workspace and the login (behaviour 5).** It refuses when the Patron's clone's `scripts/agent-workspace.sh verify` exits non-zero (naming the first `FAIL` line), and when `gh auth status --hostname github.com` fails under the session's environment (`GH_CONFIG_DIR` the agent's, no ambient token), naming the Patron's re-login command (the 401 of 11-08).
6. **A newer handoff, and the start (behaviour 6).** It refuses when the newest commit touching `docs/SESSION-HANDOFF.md` on the Patron's clone's `refs/remotes/origin/master` is absent, or is the handoff the last start launched. A real launch first runs the Patron's clone's `agent-workspace.sh sync` (W-369), which fetches origin's master into that clone and fast-forwards the agent clone, and refuses when the sync refuses. It then writes its lock and its start line, runs the session in the agent clone to its end, keeps its stdout as `session.json`, removes the lock and exits 0 only when the session did.
