# W-027 — container lifecycle: prune command and stale branch cleanup

## Intent

After cascades run with worktrees and opus branches, stale artifacts
accumulate. `bisellium run --reclaim` already cleans `.bisellium/worktrees/`
but it's buried in `run` and doesn't touch opus branches. W-027 adds a
standalone `bisellium prune` command that cleans both worktrees and stale
opus branches in one shot.

## Files owned

- `packages/cli/src/prune.ts` — `pruneStaleOpusBranches` + `runPrune` CLI wrapper
- `packages/cli/src/prune.test.ts` — behaviours for stale branch cleanup
- `studio/briefs/W-027.md` — this file

## Interfaces

- `pruneStaleOpusBranches(repo: string, studio: string): PruneResult` — pure
  function: finds `opus/*` branches whose opus is in `done` state, deletes
  them if merged into HEAD
- `runPrune(args: string[]): { exitCode: number }` — CLI wrapper: calls
  both `reclaimWorktrees` and `pruneStaleOpusBranches`, reports what was
  removed

## Behaviours to test

1. `pruneStaleOpusBranches` deletes a merged branch whose opus is `done`
2. `pruneStaleOpusBranches` keeps a branch whose opus is `building`
3. `pruneStaleOpusBranches` keeps an unmerged branch even if opus is `done`
4. `pruneStaleOpusBranches` returns empty when no opus branches exist
5. `runPrune` exits 0 and reports both worktree and branch results

## Acceptance

`bisellium prune --studio studio --repo .` removes merged opus branches
for done opera and reclaims stale worktrees. Safe: only merged+done branches
are deleted.

## Out of scope

- `.claude/worktrees/` cleanup (Workflow tool's own lifecycle)
- Disk space threshold gating cascade start (future)
- Cleanup of cascade evidence/logs
