# W-084 — the Behaviour-N citation check

Spec of record, signed by the architect, 2026-09-25. **Revision 2**, after
Sol's closure pass, which **answered this brief's own opening question — keep
the rule** — and caught one contradiction I had left in a For Sol target.

Split out of W-082 by Sol's finding 14: this rule and the `verdict` verb share
neither files nor an executable seam and are independently releasable. The
coupling was that one review found both classes, which is not a technical
coupling. Every measurement below was re-run on **this branch's tree** rather
than carried over from W-082 revision 1 — the numbers moved, and that is the
first thing this brief has to be honest about.

## Intent

The spec-revision-residue class is real and recent: four instances across
W-062 and W-072, and **nine that I produced and killed myself** in W-072
revision 5. A residue is text that describes a mechanism the same document has
already deleted or renumbered. One of the nine shipped to a reviewer as a live
defect — W-062 cited `Behaviour 13` when it declared twelve.

The mechanizable part of that class is exactly one shape. The rest is not, and
the section below says so with numbers, because the honest half of this opus is
knowing what a grep cannot see.

## The rule

**`brief.behaviour_citation`**, level **block**, over every file in
`studio/briefs/`:

```
brief cites Behaviour <n> but declares <count> behaviours
```

`<count>` is `countBehaviours(text)` — the existing function
(`packages/cli/src/rules/evidence.ts:106`), reused, never re-derived.

### Why the capitalized singular, and only it

`Behaviour N` with a capital B is how a brief refers to **its own** behaviour
in prose. Lowercase and plural forms are how it refers to other files' and
other opera's — `W-028's behaviours 22-24`, `this file's behaviour 2`,
`usage.test.ts's behaviour 17`. That distinction is not a style preference I am
imposing; it is how all 55 briefs already read, and it is the only reason a
precise rule exists at all.

**The rule is therefore deliberately incomplete, and that is not a style
mandate.** A residue written as lowercase `behaviour 7` about the brief's own
behaviour escapes it, and nothing here requires anyone to capitalise. Making
the convention mandatory would be a far more invasive claim — a rule about how
briefs must be written rather than about what they must not contradict — and
this opus does not make it. Narrow and silent beats broad and deleted.

### The three exclusions, and what they are each worth today

A match inside a **fenced code block**, an **inline code span** (backticks), or
a **double-quoted span** is not a citation — it is a fixture, a quotation, or
an example. Measured over the **44** briefs that declare at least one
behaviour, **including this one**:

| **measured at revision 2** | count |
|---|---|
| raw `Behaviour N` matches | **78** |
| live after the three exclusions | **68** |
| excluded: inline code span | **9** — every one of them in *this brief*, from behaviour 2's fixture list and the tables above |
| excluded: quoted span | **1** (W-062's amendment log, quoting the stale `"Behaviour 13"` it had already fixed) |
| excluded: fenced block | 0 |
| **out of range** | **ZERO** |

Those numbers are for the tree **with this file on it**, deliberately, because
that is the tree a reader has, and they are **stamped with the revision that
measured them** — they moved between revision 1 and revision 2 of this brief
simply because revision 2 added prose, which is the clearest possible
demonstration of why the last row is the only load-bearing one. Without this
file the corpus is 43 in scope, 66 raw, 65 live, and the inline exclusion
excludes **nothing** — which is worth stating,
because it means the inline exclusion's justification is not hypothetical and
not historical: **this brief is its largest consumer.**

The chain of events is worth recording, since it is the same class the rule
guards. The inline exclusion was discovered when W-082 revision 1 mentioned
`` `Behaviour 9` `` as one of its own false-positive fixtures and the rule
fired on its own brief during drafting. W-082 revision 2 rewrote that section
and the construct vanished, taking the exclusion's only instance with it. This
brief reinstates nine of them. A rule whose own specification trips it is a rule
that ships a false positive on day one — self-application is why the exclusion
set is three and not two.

The **fenced** exclusion still has zero instances. It is kept because
`countBehaviours` already tracks fences (`evidence.ts:112-119`) for precisely
this reason — a numbered list inside a fence is not a behaviour — and a
citation inside a fence is not a citation by the same logic. Reusing the
tracking costs nothing; For Sol target 2 asks whether that is good enough.

A reviewer re-running the table will get different raw and excluded counts as
briefs are edited. **The load-bearing number is the last row**, and it is the
one behaviour 3 asserts.

### The rule must own an all-brief crawl

No existing rule reads every brief. `opus.red_evidence` walks `opera/` and
skips any opus whose state is not ACTIVE (`rules/evidence.ts:164-165`), then
reads only the brief that opus's `spec:` points at. So it sees a handful of
briefs, never all 55. **This rule performs its own `readdirSync` over
`studio/briefs/`** — the one new directory crawl in the officina's rule set,
and worth naming as such rather than leaving a builder to assume a walk exists.

Register the id in `packages/cli/src/rules/ids.ts`. `rules/lex.test.ts`
behaviour 7 re-harvests every rule id from `check.ts` and `rules/*.ts` and
asserts set equality, so an unregistered rule fails `npm test` on its own — no
reminder needed.

### Sol's ruling on whether this rule should exist

This brief's first For Sol target asked whether a rule with zero present
findings is a rule anyone remembers. Sol answered it on the closure pass and
the answer is **keep**: *"zero present findings are normal for a regression
guard"*, and W-082's recording loop is **complementary rather than
substitutable** — *"it learns from semantic failures after review; W-084
prevents this narrow known recurrence."* Recorded here rather than left in a
review log, because it is the reason this opus exists and the next reader will
ask the same question.

### Why block, not advise

There is no legitimate reason for a brief to cite a behaviour it does not
declare, the precision is measured at zero false positives, and the class has
already shipped. An advisory would join 121 others on this officina and be read
by nobody. The escape is to fix the number.

## Four candidates that measurement rejected

This section is the other half of the opus. I tried four rules before the one
above and each is dominated by legitimate prose:

| candidate | fires on | why it is wrong |
|---|---|---|
| any `behaviour(s) N` above the brief's own count (case-insensitive, plural included) | **8 / 54** | W-030 legitimately cites "W-028's behaviours 22-24"; W-062's hit is a quoted historical mention of its own fixed residue |
| any `W-`/`P-`/`D-`/`L-nnn` id resolving to no file | **6 / 54** | briefs use fictional ids **on purpose**: `W-999` in refusal tables, `D-900`–`D-905`, `D-777`, `W-777` in worked examples |
| quoted section references (`see "X"`) matching no heading | **4 / 7** | three point at *other documents* — ADOPTION's "Running talk", the handoff's "Where things stand" — and the fourth at a bold lead-in that is not a heading |
| a brief's own `behaviours 1-N` range vs its count | **12 / 43** | `behaviours 1-5` in *Files owned* means "the subset living in this file", a per-file partition, which is correct usage |

(Rates measured over the corpus **before this brief landed** — 54 briefs, 43
declaring behaviours, 7 using quoted section references. They are indicative
rather than load-bearing: the point is that every one of the four is wrong by
whole categories, not by a few counts.)

**A grep sees syntax, and a brief's syntax is full of deliberate fiction**:
examples, refusal tables, fenced code, cross-document references, and quoted
history of its own corrections. Anyone tempted by one of these four should read
this table first; that is why it is in the brief and not in a commit message.

### And what the surviving rule still cannot see

Eight of the nine residues I killed in W-072 revision 5 are invisible to it: a
headline reading "never wedges" after the wedge became deliberate; an
exhaustive list that quietly stopped being exhaustive; a For Sol target arguing
for a deleted change; a stated count of "four rows" for five rows. Those are
prose-to-prose contradictions. **No check finds them**, and claiming otherwise
would be the process theatre this officina replaces with mechanism. Their
remedy is W-082's recording loop — once red-team rounds are evidence,
`lesson.recurrent` sees the class, and a recurring class earns a lesson and an
opus rather than a fifth reviewer noticing it.

## Behaviours to test

1. **An out-of-range self-citation blocks.** A temp officina whose brief
   declares 3 behaviours and says `Behaviour 7` in prose yields one blocking
   `brief.behaviour_citation` finding naming **both** numbers — the cited one
   and the declared count, so the message says what to fix. `Behaviour 3` in
   the same brief yields none, and neither does a brief with no numbered
   behaviours section at all.

2. **The seven false-positive constructs produce zero findings.** One block,
   one table, every row a real construct from a real brief, against a brief
   declaring 3 behaviours: `W-028's behaviours 22-24` (lowercase, plural,
   other opus); `behaviours 1-5` as a Files-owned partition; `W-999` in a
   refusal table; `see "Running talk"`; `Behaviour 9` inside a fenced block;
   `"Behaviour 13"` inside double quotes; and an **inline** `` `Behaviour 9` ``
   code span. Zero findings from all seven. This is the precision claim of both
   tables above, asserted rather than argued — and the inline row is a
   **regression pin**, not a hypothetical: it is the construct that fired on
   W-082 revision 1 during drafting and is the reason the exclusion exists.

   **Plus one robustness row:** a brief that cannot be read — permissions, or
   bytes that are not valid UTF-8 — is **skipped without aborting `check`**.
   The rest of the crawl completes and every other rule still reports. A new
   directory walk that can throw would take the whole officina's report down
   with it, which is strictly worse than missing one file.

3. **The real corpus is green, and the crawl reaches all of it.** Against
   `studio/briefs/` on this tree: `checkStudio("studio")` reports **no**
   `brief.behaviour_citation` finding, and the rule is asserted to have read
   **every** `.md` file in the directory — not only those an active opus's
   `spec:` points at, which is all `opus.red_evidence` would have covered. Both
   halves matter: green proves precision, and the file count proves the crawl.

Reds via `bisellium red W-084 --behaviour <n> --sella <id> --studio studio --
<cmd>`, one per behaviour, assertion-level, no two sharing an output
(engineering lex §2, `opus.red_evidence`). Behaviours 1 and 2 red against a
tree with no rule: 1 fails on a finding that never appears, 2 fails because the
rule id is absent from `ids.ts` and `rules/lex.test.ts`'s harvest — write 2 so
it asserts the rule **exists and is silent**, never merely that findings are
absent, or it passes vacuously before the rule is written. Behaviour 3's red is
the crawl assertion: with no rule there is no crawl, so the file-count half
fails honestly while the green half would pass vacuously — assert the count
first.

## Acceptance

1. `npm test` green; `typecheck`, `lint`, `format:check` clean.
2. `bisellium check studio --repo .` reports **no** new blocking finding, and
   the advisory count is unchanged — this rule adds nothing to the noise floor
   on a clean corpus, which is the whole claim behind blocking.
3. `rules/lex.test.ts`'s harvest passes with the new id in `ids.ts`.
4. **The census, re-run and recorded as evidence**: raw matches, live matches,
   per-exclusion attribution, and zero out of range, over whatever the brief
   count is on the day it lands. The numbers will not be 76/66/9/1/0 — briefs
   change, and they changed twice during this brief's own drafting — and the
   acceptance is the **last row**, not the first four.
5. A deliberately broken fixture fails: add `Behaviour 99` to a temp copy of
   any real brief and watch `check` block. Keep the output.

## House constraints

TypeScript strict + `noUncheckedIndexedAccess`; ESM `.js` import specifiers;
Node ≥ 25; `packages/cli/src/check.ts`'s house style. Reuse
`countBehaviours`, `safeList` and the `Finding` shape already in
`rules/evidence.ts` — no new helper for anything that file already does.

## Out of scope

- **The four rejected candidates.** Measured and documented above precisely so
  they are not re-attempted. If someone wants one, the burden is a measurement
  that beats the rates in that table.
- **Any rule for the eight semantic residues.** Named above as unreachable by
  a grep; remedied by W-082's recording loop instead.
- **Fixing briefs.** The corpus is green. This rule is a regression guard, and
  it has no backlog to burn down.
- **Lowercase and plural citation forms.** 8/54 false positives. The rule is
  deliberately blind to them, which means a residue written in lowercase
  escapes it — an accepted, named limitation.
- **Briefs outside `studio/briefs/`.** `examples/sample-studio` has no briefs
  directory; if an adopter's officina does, the same crawl covers it, but no
  fixture exercises that today.
