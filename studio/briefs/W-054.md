# W-054 — a talked session can run bisellium: PATH reaches the vendor shell snapshot

## Intent

This opus was re-cut out of W-049. See `studio/briefs/W-049.md`, "Test
hardening", the bullet "The 127 allow-half", which is where the threat
review lives.

W-044's attended smoke found the admitted `Bash(bisellium …)` rules match
on the vendor, but the command exits 127 because `bisellium` isn't found.
So every boot bundle's "run `bisellium`" instruction is broken in talked
sessions.

The fix site is unproven. The vendor Bash tool runs commands under a shell
snapshot (`~/.claude/shell-snapshots/snapshot-zsh-*.sh`) that carries its
own `export PATH=<captured value>`. A PATH set at spawn time is therefore
not shown to reach it, and a stub-based test of the spawn env would pass
vacuously.

A spawn-side fix adds reach. Any directory prepended to a session's PATH
shadows resolution for every command that session runs. In this repo that
directory would be `node_modules/.bin`, which holds every dependency's
bins. So the spec needs its own threat review of what it prepends, and an
empirical check against the real snapshot. It should also weigh the
install-side alternative first: `bisellium` on the operator's login PATH.

W-049's attended smoke records the current allow-half exit code as this
opus's baseline. W-049 guarantees `PATH` passes through verbatim, so
nothing it does makes this worse.
