# W-024 — apps/web scaffold + Inbox screen

Collegium engineering · cascade 7

## Intent

Create the `apps/web` React application and build the Inbox screen: a queue
of decisions the Patron must make, backed by GET `/api/inbox` and POST
`/api/answer`. The scaffold establishes Vite + React + TypeScript, design
tokens as CSS custom properties from DIRECTION.md §3, Google Fonts loading,
and the colophon rule (signature element 4.5). Every subsequent web opus
builds on this scaffold.

The API is complete and frozen — no endpoint changes.

### API client (api.ts)

```ts
export function fetchInbox(): Promise<InboxResponse>;
export function submitAnswer(
  petitio: string,
  reply: string,
  opts?: { askBack?: boolean; charterGap?: boolean },
): Promise<AnswerResponse>;
```

Where:

```ts
interface InboxResponse {
  opera: { id: string; title: string; collegium: string;
           sella: string; traditio: unknown }[];
  petitiones: { id: string; opus: string; from: string;
                subject: string }[];
}

interface AnswerResponse {
  ok: boolean; exitCode: number; output: string;
}
```

These types match `apps/server/src/store.ts` `needsYou()` (line 241) and
`apps/server/src/http.ts` `writeResponse()` (line 218). Every write request
includes `X-Bisellium-Token` from `import.meta.env.VITE_BISELLIUM_TOKEN`
and `Content-Type: application/json`.

### Colophon component

```ts
interface ColophonProps {
  studioPath: string;    // from /api/officina .studio
  schemaVersion?: string;
}
```

Renders one 1px `var(--rule)` hairline and one mono 11px `var(--ink-3)` line
below it: officina path, ISO generated-at timestamp, schema version. If a
tree hash is available (e.g., from the last event via `/api/events?limit=1`),
it appears first, truncated to 8 chars. Four items separated by ` · `.

### Inbox screen data flow

`/api/inbox` returns both `opera` (opera with pending human gates) and
`petitiones` (requests needing the Patron's answer). In Web I:

- **Petitiones are actionable**: the expanded item shows the subject as the
  ask, the four verb buttons (approve, defer, decline, delegate), and a
  reason input. Submitting calls POST `/api/answer` with `{ petitio, reply }`
  where `reply` is the Patron's free-text response. A keyboard shortcut of
  `1`/`2`/`3` maps to approve/defer/decline; delegate has no shortcut. The
  `askBack` flag is available as a toggle for "ask the sella to clarify".
- **Opera are display-only**: listed in the queue but not actionable via
  POST `/api/answer`. Gate approvals (POST `/api/greenlight`) are not in
  scope for W-024.

A reason is required before a decision can be submitted (DIRECTION.md §4.4:
"A decision without a reason cannot be submitted").

## Behaviours to test

1. `tokens.css` declares all nine colour custom properties (`--ink` through
   `--bad`) and all seven space properties (`--sp-1` through `--sp-12`) on
   `:root`, with exact values matching DIRECTION.md §3.
2. `fetchInbox()` sends GET to `/api/inbox` and returns the parsed JSON
   response; a non-200 status rejects the promise with the response status.
3. `submitAnswer()` sends POST to `/api/answer` with JSON body
   `{ petitio, reply }`, `Content-Type: application/json`, and
   `X-Bisellium-Token` header; returns the parsed `{ ok, exitCode, output }`
   response.
4. Inbox renders each petitio as a 40px row: subject at 13/18, sella id
   (`from`) in mono 12, with a 2px amber left rule.
5. `j` moves focus to the next item, `k` to the previous; focus does not
   leave the list boundaries (first item stays on `k`, last stays on `j`).
6. `Enter` on the focused item expands it to show the ask and verb buttons;
   `Esc` collapses the expanded item back to a row.
7. `1`/`2`/`3` on an expanded petitio trigger approve/defer/decline
   respectively, calling `submitAnswer` with the petitio's `id` and the
   constructed reply text.
8. The verb buttons are disabled until a non-empty reason is entered in the
   reason input; a submission without a reason is impossible.
9. Empty state: when `/api/inbox` returns zero petitiones and zero opera,
   the screen shows one line: "Nothing waiting on you", then the colophon,
   with no other content.
10. Colophon renders a 1px hairline then a mono 11px `ink-3` line with
    officina path and generated-at timestamp, separated by ` · `.

## Acceptance

```bash
cd apps/web && npx vite build
npm run -s typecheck
npm run -s check -- studio --repo .
```

The dev server starts without errors: `cd apps/web && npx vite`. The
production build produces `apps/web/dist/index.html` and
`apps/web/dist/assets/` entries. `bisellium serve --studio studio` serves
the built app at `http://127.0.0.1:4477/`.
