## Intent

W-299 part 1. Lex §7's trial needs "zero required handoff edits", and no opus can meet it today: making an opus done asks for a `docs/SESSION-HANDOFF.md` edit three ways. The done perform refuses without a tracked handoff change (`performDone`); the checkpoint rung stays named until the commit that made the record done also changed the handoff (`afterDone`, `checkpointed`); and W-186's rule, which the perform runs on the working-tree handoff (`handoffHold`) and the officina check runs on master, blocks a Queue that names a done or halted opus and a Resume date older than the newest done record, so each done makes the handoff stale. D-077 B rules that work state is a git record and the handoff keeps standing instructions only; W-299 absorbs W-247 (the Resume point and its required edit go) and adds a read-only `next --all`.

After this part: (1) the handoff keeps no Resume point (a `## Resume point` line blocks), and a done or halted id in the Queue is no finding, so nothing a done changes makes the handoff stale; (2) the done perform commits with no handoff change, and the checkpoint rung reads complete once the trunk record is done and its retro filed or not owed; (3) `next --all` prints, for every open opus, the step `next <opus>` derives and the opus's traditio (its handover note), one line each in id order, writing nothing: D-077 B's tracker is each record and traditio read through it, and D-087 C reads lane state there.

**What replaces the Resume point and the Queue as the boot reading: both, records first.** The Resume point's three kinds of content each already have a record: the rulings in force are `studio/decisions/`, each open opus's state and next step are its record and evidence, read by `next --all`, and the standing lines (the ladder's kept models, environment facts) are standing instructions, which stay in the handoff's Boot section. So a fresh session boots from the handoff's standing instructions, then `next --all` for where every open opus stands, then the Queue for the order. The Queue stays in the handoff in part 1, because it needs a record to move to: part 2 moves it to `studio/queue.yml` with `rank`, and drops the Queue section and `process.handoff.queue`. Part 1 only stops the Queue's done-or-halted check, the one that asked for an edit at done. Boot step 2 names `next --all` instead of a ticket-writing `next <opus>` per opus in flight.

Promise no-done-edit: making an opus done through the done perform asks no handoff edit: the perform commits the record, and what already rides it, with no handoff change; the checkpoint rung reads complete once the trunk record is done and its retro filed or not owed; and the rule the perform runs finds nothing the opus going done made stale — limit: a handoff that already blocks (a Resume point, an unqueued greenlit opus, a relative reference, over 100 lines, an unreadable record) still holds the perform, as it fails the officina check on master; the history row (W-214) is still asked for while master keeps the history page; the checkpoint rung no longer reads the done commit, so a done recorded by the `done` verb outside the perform reads complete with or without its history row.

Promise no-resume: a handoff line starting `## Resume point` blocks the officina check of the repository's own studio and the done perform (`process.handoff.resume`), whatever follows on the line, one finding per such line; no rule reads a Next field, a status claim or a date — limit: the rule is lexical (Input domain row 1): a Resume point under another heading form passes.

Promise read-only-all: `next --all` writes nothing: no ticket, no step marker, no step log, no record, no ref — limit: it reads gh for an opus whose rung reads gh (a pushed branch, an open PR) exactly as `next <opus>` does, so a gh failure shows on those lines, as it would there; it refuses a linked worktree, as `next <opus>` does.

Promise same-step: each `next --all` line names the step, status and actor `next <opus>` would derive before the dispatch gate, and the traditio of the record that gate reads (the main checkout's before `opus/<id>` exists, else the branch's or trunk's); `runAll` first applies `runNext`'s unknown-opus refusal, so a working-only id, in neither master nor `opus/<id>`, prints `failed` and makes the run exit 1, and a held derivation is printed as `next <opus>` holds it and makes the run exit 1. The open set trusts the main checkout's working-tree state while the derivation trusts the trunk and branch records `next <opus>` reads: when they disagree, inclusion follows the working record and the step follows trunk and branch — limit: no `--budget` or stale-handover hold (a dispatch rung reads named where `next <opus>` without `--budget` reads held), no step health (a running step reads as its rung) and no `command`; the open states are greenlit, building, verifying and review, so a done opus whose retro is owed is not listed (the next opus's branch rung holds on it, as today).

Threat model: mistakes, not adversaries (D-045). The handoff is a record the producer writes; `next --all` reads the repository's own records.
