## Intent

`scripts/run-builder-host.mjs` replays every recorded red at the clean committed
identity its log names, inside a bwrap cell with a fresh candidate checkout, a
private `HOME` and a private `/tmp`, no network, and a read-only system tree
(`:752-797`). A **playwright** red cannot reproduce there, for three independent
reasons measured below: the cell has no browser, it has no built `apps/web/dist`,
and the acceptance predicate at `:784-790` does not recognise playwright's
failure text. The first live W-125 builder run for W-110 stopped exactly there
(D-035). W-110's reds 2 and 3 (`apps/web/tests-serve/walk.spec.ts`) are the
blocked instances; its reds 1 and 4-8 replay correctly today.

This opus implements exactly three things.

1. **The browser cache is bound read-only** into the two cells that run candidate
   code and may need a browser — the builder cell (`:607-635`) and the replay cell
   (`:760-782`) — at the fixed cell path `/browsers`, named by one new
   environment variable `PLAYWRIGHT_BROWSERS_PATH=/browsers`. Nothing else about
   either cell's binds, namespaces or egress changes. The gate cell is out of
   scope for the structural reason in *Out of scope*.
2. **The web bundle is built during replay preparation**, by one fixed host argv,
   in a cell with the identical bwrap descriptor as the replay that follows it,
   and only when the checkout actually carries the web workspace. A build that
   fails, or that exits 0 without leaving a bundle, refuses that behaviour's
   replay with a **preparation** message that can never be read as an accepted
   red.
3. **Playwright's failure text is classified**, by a pure host-owned function in
   a new `scripts/replay-accept.mjs`, which the runner calls instead of the
   inline predicate at `:784-790`. A transcript **identified as a playwright
   run** — by its own failure summary or its own `Running N tests` banner — is
   accepted as a red only when it reports **exactly one** failed test *and* its
   failure is an `expect(…)` matcher; this routing happens **before** the
   token-based clause that today's predicate uses, so no token anywhere in the
   transcript can skip the count or the matcher check. A non-playwright run
   keeps today's path exactly. A missing browser, a module-load error, an empty
   selection, a passing run, a multi-test failure and a playwright API error are
   each refused, with a named reason.

Nothing else. The strictness is not relaxed anywhere: on the playwright path the
predicate gains *additional* required conditions, the poison list grows by four
literals, and the one transcript class whose verdict changes in the refusing
direction (a non-playwright run that prints `N failed` at line start) is named
and measured below. Measured on twenty-two transcripts — thirteen real ones, the
censor's three adversarial ones and six constructed for the routing clause — the
specified predicate flips exactly W-110's reds 2 and 3 and leaves all six of its
other reds and all five negative cases unchanged.

**What W-130 does not do, and W-110 must.** The red log's `# command:` header is
`cmd.join(" ")` (`packages/commands/src/lifecycle.ts:877`) and the replay splits
it on whitespace (`:779`), so a **quoted** argument cannot survive the round
trip. W-110's recorded reds 2 and 3 carry
`--grep W-110 behaviour 2:` as five argv words; measured on the repo's own
`layout.spec.ts`, that split broadens a one-test selection to five. Under this
brief such a replay is refused (`playwright reported N failed tests`), so W-110's
reds 2 and 3 must be recorded with a **whitespace-free** command. Measured
remedy, no code: `--grep behaviour.2:` — the regex dot matches the space, and it
selects exactly the one test. Quote-safe recording is a follow-on filing below.

## Reconciling with W-125's confinement obligations

W-125's brief requires "fixed host commands, not candidate package scripts
selected at runtime", with "immutable host tooling" pinned to the host's `master`
and resolved "never from the clone or candidate package resolution".

**That obligation governs the producer gate cell, and it is untouched.** Its
point is that a candidate must not be able to replace or skip the host's required
suite: the gate cell therefore runs `/tooling/packages/cli/src/main.ts ci` from a
separate read-only checkout of `master` (`:818-856`), and W-130 changes nothing
there. The **replay** cell has, since W-125, executed a candidate-authored
command verbatim — `commandText` out of the red log, split and spawned at `:779`
— under confinement, because that is what replaying a red *is*. Running the
candidate's build tooling in that same cell adds no capability the cell did not
already grant: same bwrap descriptor, same private `HOME`/`/tmp`, same
`--unshare-all` (no network), same read-only system tree, no host repo, no
credentials. Its product is consumed only by the candidate's own test process
inside the same cell, and the host reads nothing out of it but the cell's exit
status and output text — which the candidate could already shape.

**The stricter shape is nonetheless imposed where it costs nothing.** The build
is one hardcoded host argv (`npm --workspace @bisellium/web run build`), not a
script name the red log or the brief may choose; it is attempted only when a
fixed host path (`apps/web/package.json`) exists in the checkout, so no candidate
*selection* happens at any point; it runs through the same `sandboxArgs`
descriptor object as the replay, so the two cannot drift apart; its failure —
nonzero exit, spawn error, or exit 0 with no `apps/web/dist/index.html` — raises
a **preparation** error, which is a distinct message and a hard run failure, never
a replayed red; and behaviour 3(e) proves from inside the cell that the build saw
no credential, no host file and no egress. The residual accepted limitation is
W-125's own: the build runs candidate code, exactly as the recorded command does,
and bwrap plus the namespaces are the trusted computing base.

**The read-only browser bind grants read access and nothing else.** It adds no
write path (behaviours 1 and 2 assert `EROFS` from inside the cell), no network,
no host repository, no host home and no credential: the bind source is
`npx playwright install` output, reproducible from a public CDN, and it contains
no secret. Candidate code in that cell could already execute arbitrary native
binaries it carried itself; chromium inherits the cell's namespaces (measured:
egress stayed `ENET*` with the browser present). One accepted residual, stated
because it is real: playwright launches chromium with `--no-sandbox`
(`chromiumSandbox` defaults false), so chromium's own sandbox is off inside the
cell and bwrap's namespaces are the only boundary — the same trusted computing
base W-125 already accepted, with a larger third-party binary inside it.

## Interfaces

### The browser cache (`scripts/run-builder-host.mjs`)

One host-side resolution, computed once beside `NODE`/`NODE_BIN`:

```js
/** The host's playwright browser cache, or undefined. Host-owned: read from the
 *  host's own environment, never from the request or the candidate. */
const browserCache = () => {
  const named = process.env["PLAYWRIGHT_BROWSERS_PATH"];
  const dir = named && isAbsolute(named) ? named : join(homedir(), ".cache", "ms-playwright");
  try {
    return statSync(dir).isDirectory() ? realpathSync(dir) : undefined;
  } catch {
    return undefined;
  }
};
const BROWSERS = browserCache();
```

`node:os`'s `homedir` joins the existing `tmpdir` import. An explicitly named
`PLAYWRIGHT_BROWSERS_PATH` wins so a test — and an adopter whose browsers live
elsewhere — can point the runner at a different tree; a relative value is
ignored rather than resolved against an arbitrary cwd.

When `BROWSERS` is defined, **both** the builder cell and the replay cell gain
exactly one read-only bind and one environment name:

```js
...(BROWSERS ? [[BROWSERS, "/browsers"]] : [])        // appended to roBinds
...(BROWSERS ? { PLAYWRIGHT_BROWSERS_PATH: "/browsers" } : {})   // merged into env
```

A fixed cell path, not `/home/builder/.cache/ms-playwright`, for two reasons:
the private home stays empty and host-shaped paths stay out of the cell, and the
variable is then an assertable fact rather than an inference about `HOME`'s
layout. `roBinds` already follow `binds` in `sandboxArgs` (`:199-221`), so a
read-only bind inside a writable tree is the established shape — and
`/browsers` is not inside one anyway.

**The resolution is logged either way, once, at run start.** When `BROWSERS` is
undefined the runner binds nothing, sets nothing, and writes
`run-builder-host: no playwright browser cache found; a browser red cannot
reproduce`; it does not fail, because most reds need no browser and the
classifier names a browserless playwright failure for what it is. When
`BROWSERS` **is** defined the runner writes
`run-builder-host: browser cache bound read-only at /browsers from <resolved
path>`. Revision 2 logged only the absent case, which left the present case —
the one where a host directory becomes candidate-readable, and where the
invoker chose which — the only silent branch of the pair. A read-only bind the
run does not name is a bind nobody reviewing the log can see; both branches now
appear in the same host stderr the receipt's run is read beside. The resolved
path is a **host** path printed to **host** stderr, not into a cell and not into
a gate finding, so clause 2's token-only discipline does not reach it — the same
deliberate asymmetry the build-output dump is granted below, and for the same
reason.

The builder cell's environment allowlist therefore holds **19** names rather
than W-125's 18, and this is W-130's one deliberate extension of that contract.
The reason: a builder that cannot launch a browser cannot *record* the red the
producer must then replay, so the two cells carry the same obligation. The
variable is producer-set, a fixed literal, not credential-shaped, and present
only when the bind is.

### The classifier (`scripts/replay-accept.mjs`)

```js
/** Was a confined replay a genuine assertion-level reproduction of a red?
 *  Pure: no fs, no spawn, no environment. `status` is the child's exit code
 *  (null for a signal), `output` is stdout and stderr concatenated. */
export function classifyReplay({ status, output }) // => { accepted: boolean, reason: string }
```

Five module constants, the first two carried over from
`run-builder-host.mjs:786-789`:

```js
const ASSERTION = /(?:not ok|AssertionError|ERR_ASSERTION)/;
const POISON = /ERR_MODULE_NOT_FOUND|SyntaxError:|Cannot find module|command not found|ENOENT|not permitted|permission denied|sandbox|browserType\.launch|Executable doesn't exist|No tests found/i;
const PW_BANNER = /^[ \t]*Running \d+ tests? using \d+ workers?\b/m;
const PW_SUMMARY = /^[ \t]*(\d+) failed\b/gm;
const PW_EXPECT = /^[ \t]*(?:Error: )?expect\([a-z]+\)\.[A-Za-z]+\(/m;
```

`PW_SUMMARY` is the one global regex, and it is read **only** through
`[...output.matchAll(PW_SUMMARY)]`, never `.test()` or `.exec()`: a module-level
`/g` regex carries `lastIndex` across calls, and behaviour 4 calls
`classifyReplay` many times in one process. `matchAll` does not mutate the
source regex. Read once at the top of the playwright branch and reused, not
re-matched per clause.

**Clause ladder — the order every verdict in behaviours 4 and 5 is counted
against.** The first clause that answers stops the function:

1. `status === 0` → refused, `the command exited 0`.
2. `POISON.exec(output)` matches → refused,
   ``the output names an environment failure (${match[0]})``. The reason carries
   **the matched token only**, never the surrounding text: a real message of this
   class embeds an absolute path (measured: the missing-browser error is 112
   characters of `/home/…`), and the runner's stderr is read by a human and
   quoted into review logs.
3. **Is this a playwright run?** `const summary = [...output.matchAll(PW_SUMMARY)].at(-1)`;
   the answer is yes when `summary !== undefined || PW_BANNER.test(output)`.
   A yes routes **unconditionally** into clauses 4-6 and never reaches clause 7.
   This ordering is the whole of MUST A: revision 1 put clause 7 here, and a
   playwright transcript that merely *contained* `not ok` or `AssertionError`
   anywhere — an echoed line from a spec, an `AssertionError` out of the
   `bisellium serve` the W-110 harness spawns — was accepted as a red with its
   count and matcher unchecked. Measured, both. The union of summary and banner
   rather than either alone, because each covers the other's blind spot:
   `launch` keeps only the **last** 4 MiB of each stream, so a very long run can
   lose its banner off the head while keeping its summary at the tail, and a
   playwright run that died before summarising still printed its banner. The
   union therefore fails closed in both directions.
4. no `summary` → refused, `playwright printed no failure summary`. A playwright
   run that announced itself and then produced no failure count is not a red.
5. `summary`'s count `!== 1` → refused,
   ``playwright reported ${n} failed tests; a behaviour's red is exactly one``.
   The **last** summary, because `retries: 2` under `CI=1` can print one more
   than once. Exactly one, because a behaviour's red is one assertion-level
   failure (engineering lex §2, `opus.red_evidence`) and a behaviour in
   `walk.spec.ts` is one `test(…)` — and because this clause is what refuses a
   replay whose selection broadened, the argv-quoting hazard above.
6. `!PW_EXPECT.test(output)` → refused,
   `playwright's failure is not an expect(...) assertion`; otherwise accepted,
   `assertion-level failure`. **This clause is a discriminator against
   accidental misclassification, not a guarantee against an authored
   transcript.** What it reliably separates is the environmental near miss from
   the genuine red: a browser that would not launch, a server that would not
   answer and every other playwright API error print
   `Error: browserType.launch: …` / `Error: page.goto: net::…` and carry no
   matcher line, while a real failure prints `expect(received).toBe(expected)` or
   `Error: expect(locator).toHaveCount(expected) failed`. A **code-frame** echo
   cannot trip it — playwright's `>  4 | ` gutter defeats the line anchor, and
   `expect(page.locator('…` fails `expect\([a-z]+\)\.` on the `)` regardless —
   and that is the case behaviour 4(i) closes. A deliberate line-start
   `console.log("expect(received).toBe(expected)")` **does** forge it, measured;
   W-125's trust model already concedes that the host reads output the candidate
   shapes, so no unforgeable banner is claimed or attempted here.
7. `ASSERTION.test(output)` → accepted, `assertion-level failure`. Reached only
   when clause 3 answered no, i.e. for a non-playwright run. This is today's
   acceptance under today's conditions, which is why W-110's reds 1 and 4-8 and
   every `liveFixture` row keep their verdict byte for byte.
8. otherwise → refused, `no assertion-level failure in the output`.

Clauses 4-6 are **additional** requirements on a path that is refused outright
today; clause 2 is strictly stricter than today's. The only verdict that moves
in the refusing direction is a non-playwright transcript that prints `N failed`
at line start: clause 3 routes it to the playwright branch and clause 6 refuses
it. Measured, nothing in this repo does that — `node --test-reporter=tap`
summarises as `# fail N`, and none of W-110's six TAP reds matches the anchor —
the failure is fail-closed, the reason names it, and a refusal is recoverable by
re-recording where a false acceptance would be permanent. `browserType.launch`
and `Executable doesn't exist` join the poison list even though clause 6 would
already refuse them, so a browserless cell is a *named* refusal rather than an
accident of clause order, and so a transcript carrying both a real assertion and
a launch failure is refused.

**The 4 KiB build-output dump at step 2 of the build above is a deliberate
asymmetry with clause 2's token-only discipline.** Clause 2's reason is quoted
into review logs and gate findings, so it carries no path; the build dump is
cell-internal output from a cell with no credentials and no host paths in it,
and L-051 wants a preparation failure a human can act on without re-running the
runner. Both rules stand as written.

The runner's call site replaces `:784-791` with:

```js
const verdict = classifyReplay({ status: replay.status, output });
if (!verdict.accepted) throw new Error(`red ${behaviour} did not reproduce its assertion failure: ${verdict.reason}`);
```

`output` keeps its current construction (`${replay.stdout}\n${replay.stderr}`,
each stream already capped at 4 MiB by `launch`). The `redReplays` entry and the
`completion` receipt shape are unchanged.
