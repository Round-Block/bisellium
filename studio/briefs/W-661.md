## Intent

W-610's light-gate reader, `lightGateCommands` (master light-gates.ts:45-48), takes every backticked span on a Files owned bullet (`ownedFiles`, W-328) as a candidate test path. A bullet that names a command in a later span, as W-648's `package.json` bullet does with its `node --test-reporter=tap --import tsx …w648.test.ts` line, puts that whole command through the path check, which refuses it for its spaces, and `next` then holds a built opus with no ticket (W-648 and W-644 today).

After this opus, the light gates read one span per Files owned bullet as a test path: its path slot, the first backticked span on the bullet. A test-shaped path slot that is unsafe (a space, a `..` segment, an absolute path, a shell character) is still refused by name, as W-610 ruled. Every later span on the bullet (a command, prose, or a file named in passing) is not read by the light gates at all. `ownedFiles` keeps its W-328 meaning, every span on every bullet, for the owned-files and lane overlap checks.

The open point the call left (skip every later span, or only spaced ones) is settled as every later span. The spaced-only reading does not clear the hold it was filed for: W-648's `package.json` bullet also names `w474.test.ts`, an unspaced later span with no file at that path, so spaced-only would run `node --test-reporter=tap --import tsx w474.test.ts` from the repository root and fail W-648's light gates instead of holding them; W-644's brief (its copy in the main checkout) names `w644.test.ts` the same way. Over all 305 briefs the light gates could read, 183 later spans are unspaced test paths and 89 of them name no file at master's root, in 58 briefs (`census.out`). A later span is a reference, not the opus's own test file, so it is never a light gate. One fixture follows the other form: the next-world fixture brief (`briefText`, next-world.test.ts) names its two test files mid-bullet, in a list of the paths its rows commit, and W-610-b1 and W-610-b2 read them as light gates. The fixture is split so each test file opens its own bullet; its `ownedFiles` list is unchanged, span for span, and W-610-b2 adds its new test file as a bullet, not a span.

Threat model: mistakes, not adversaries (D-045). The path check stays the one gate between a brief's text and the shell.

## Promises

Promise slot: for a brief's committed text, `lightGateCommands` returns the manifest's `light_gates` followed by one `node --test-reporter=tap` line (with `--import tsx` for a `.test.ts` or `.test.mts` file) per Files owned bullet whose path slot is a test file, in bullet order, and a later span on any bullet adds no line and causes no refusal — limit: a bullet that names several of the opus's own test files light-gates only the first; the others run in the one full `ci --opus` only (the census lists such bullets: W-503's migration bullet loses three light lines and W-301's bullets three; a brief that wants each light-gated names it on its own bullet). Over the 305 briefs, 91 change their sequence: 69 only drop a later-span line, 22 (W-648 and W-644 among them) go from the error to a sequence, and none goes to an error. Pinned by `W-661-b1` "W-648's bullets give the manifest gates and one tap line for its test path" and pinned by `W-661-b1` "a later span shaped like a safe test path is not run" and pinned by `W-661-b1` "a later span shaped like an unsafe test path is not read" and pinned by `W-661-b1` "each bullet's path slot runs, in order" and pinned by `W-661-b1` "the slot is the first span, wherever it sits on the bullet" and pinned by `W-661-b1` "a fenced or commented bullet is not read".

Promise refusal: a test-shaped path slot that fails the safe-path form (`[A-Za-z0-9_][A-Za-z0-9_./-]*`) or holds a `..` segment is refused with the error that names it, whatever the later spans on its bullet are — limit: the form is W-610's, unchanged; a path slot that is not test-shaped (`package.json`, a source file) is not checked, since it never reaches the shell. Pinned by `W-661-b1` "an unsafe path slot is still refused, by name".

Promise unchanged: `ownedFiles` returns every backticked span of every real Files owned bullet, in order, exactly as on master, so the owned-files check of a source change, the lane overlap check and the other `next` readers are unchanged — limit: pinned on W-648's bullets by one row and by the census (`ownedFiles_differs=0` over 305 briefs), not by a row per reader. Pinned by `W-661-b1` "ownedFiles keeps its W-328 meaning".

Limits, stated:

- Reused, unchanged code these promises lean on: `realLines` (fenced and commented lines blanked), the bullet form of `ownedBullets`, `TEST_FILE`, `SAFE_PATH`, `currentLightCommands`, `admitLightGates`, `runLightGates` and `next`'s hold on a light-gate error. None is edited, and each keeps its behaviour.
- A light log written before the merge binds its command sequence; an opus whose sequence changes (a later span no longer run) needs one cheap rerun of the light gates, which `next` orders (W-610). W-648 and W-644 have no light log yet.
- The path slot is read from the brief's text only; whether the file exists is learned when its light gate runs.

## Interfaces

**`ownedPathSlots(briefText: string): string[]`** (brief-admission.ts, exported): the first backticked span of each bullet line of every real `## Files owned` section, in brief order, a leading `./` dropped; a bullet with no span gives nothing.

**`ownedFiles(briefText: string): string[]`**: unchanged signature and output.

**`lightGateCommands(manifest, studioRel, briefText)`**: unchanged signature; its test lines come from `ownedPathSlots`.
