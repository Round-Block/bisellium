# W-123 — `done` refuses unless the opus's merge is in the fetched trunk

Status: **signed spec, revision 1** · architect sella (claude-opus-5-5) · 2026-10-05.
The spec gate is written by `bisellium verdict W-123 --phase spec`, not by this text.

## Intent

The Patron's title (2026-10-01) has two halves:

- a PR opens only from a branch rebased onto the fetched trunk;
- `done` refuses unless the opus's merge is reachable from the fetched trunk.

**Scope default, veto-able by the Patron: this opus is narrowed to the `done`
half.** W-124's producer note and item 3 of `acta/2026-10-05-ranking.md` say
`next`'s `pr` step already covers the first half. The measurement below
confirms it for every path where a verb opens a PR. The title is not amended
here (`bisellium amend` is the Patron's call). If the Patron vetoes, the
PR half comes back as a second opus, not as a revision of this one.

Measured at master `659ec5a` (scripts and output under
`~/.bisellium-evidence/W-123-spec/`):

**The change.** `done` asks one question: "is this opus's PR MERGED, and is its
merge commit in the local master?" It asks only when the officina declares
`integration.pr.required: true`, and it asks after every existing refusal.
Here:

- **the opus's merge** is the `mergeCommit.oid` of the PR that `identifyPr`
  finds for head `opus/<id>` with base `master`. For a squash merge that is
  the squash commit; for a merge or rebase merge it is the commit GitHub
  reports.
- **reachable from the fetched trunk** means `settleMerged` is `settled`: the
  commit is an ancestor of `refs/heads/master`, and any local `opus/<id>` tip
  is part of the merged head.

`done` itself never fetches and never moves a ref. Fetching is the job of
`next`'s `merge` rung, which the refusal names.

`commands` cannot import `cli`, where `identifyPr` lives. So the reader is
injected, the way `runReview` already takes `runReceiptAdmission`. All three
verbs that reach `runDone` pass it. A caller that passes no reader is refused.

## Interfaces

**`mergeRefusal`** (`packages/cli/src/integrate.ts`):

```ts
/** W-123: why the opus's merge is not in the local trunk; undefined when its PR is MERGED and settled. */
export function mergeRefusal(repo: string, id: string): string | undefined
```

It is `identifyPr(repo, id)`, then `settleMerged(repo, pr, localTip(repo, id))`.
Each outcome returns exactly:

| read | returns |
| --- | --- |
| `held` | `read.reason`, unchanged |
| `none` (no PR, or CLOSED only) | `no MERGED PR from opus/<id> to master` |
| `pr`, state `OPEN` | `PR #<n> from opus/<id> is OPEN, not MERGED` |
| `pr`, MERGED, not `settled` | the `Settlement`'s `reason`, unchanged |
| `pr`, MERGED, `settled` | `undefined` |

**`runDone`** (`packages/commands/src/lifecycle.ts`):

```ts
export interface RunDoneOptions extends WriteOptions {
  /** W-123: the merge reader; the CLI passes integrate.ts's mergeRefusal. */
  mergeRefusal?: (repo: string, opusId: string) => string | undefined;
}
export function runDone(args: string[], opts: RunDoneOptions = {}): WriteResult
```

- **When it runs.** The guard runs only when
  `manifest.integration?.pr?.required === true`, and only after every
  existing refusal (usage, unknown opus, D-021, state, model, gates, sella).
  If the flag is not `true`, the reader is never called.
- **What it checks**, in order:
  1. `findGitRoot(root)` is undefined → the reason is
     `<root> is not inside a git work tree`.
  2. `opts.mergeRefusal` is absent → the reason is
     `no merge reader was supplied`.
  3. Otherwise the reason is `opts.mergeRefusal(repoRoot, opusId)`.
- **On a reason.** `runDone` prints two lines to stderr, writes nothing,
  emits no event, and returns exit 1:

  ```
  <id>: done refused: <reason>
  <id>: done needs the PR from opus/<id> merged and its merge commit in the local master; run: bisellium next <id>
  ```

**Callers.** These three are the only ones that pass the reader:

- `main.ts`: `runDone(rest, { mergeRefusal })`;
- `close.ts`: `runDone([opusId, "--studio", studio], { mergeRefusal })`. On
  failure `close` still prints `done failed (exit 1)` and exits 1;
- `next.ts` `performDone`:
  - the pre-check becomes
    `const why = mergeRefusal(repo, id); if (why !== undefined) return heldResult(\`refusing: ${why}\`);`;
  - the call becomes `runDone([...], { mergeRefusal })`.

## Behaviours to test

Every row builds its fixtures with `world(…, { prRequired: true })` and runs
the CLI under `envFor(w, …)`, which puts the stub `gh` first on PATH. A row
counts as **refused** when all of these hold:

- exit 1;
- stderr line 1 is exactly `W-900: done refused: <reason>`;
- stderr line 2 is exactly
  `W-900: done needs the PR from opus/W-900 merged and its merge commit in the local master; run: bisellium next W-900`;
- the opus record's bytes are unchanged;
- `.bisellium/events.jsonl` is byte-identical, or still absent.

1. **`done` and `close` refuse an opus whose merge is not in the local
   master, and accept one whose merge is.**

   Refused rows run `done W-900` from the opus worktree (the D-021 owner
   checkout), at stage `review`. The reason on each:

   | gh scenario | reason |
   | --- | --- |
   | `list` empty | `no MERGED PR from opus/W-900 to master` |
   | an OPEN candidate | `PR #901 from opus/W-900 is OPEN, not MERGED` |
   | a CLOSED-only candidate | `no MERGED PR from opus/W-900 to master` |
   | `list` exits 1 | starts `gh pr list exited 1` |

   Two more rows:
   - At stage `merge` with `fetched: false`, the PR is MERGED but its merge
     commit is not in the local master. The row is refused, and the reason
     contains the merge commit's first 12 hex characters.
   - `close W-900 --studio <wtStudio> --repo <wt>` with an empty `list`:
     exit 1, stderr contains the line
     `W-900: done refused: no MERGED PR from opus/W-900 to master`, and the
     record is unchanged.

   Accepted rows use stage `cleanup` (merged, fetched, branch and worktree
   gone) and `list` = `mergedList(w)`. They follow the handoff flow, from the
   main checkout on a `--no-track` branch cut from master:
   - `done W-900 --studio <studio>` exits 0, and the record reads
     `state: done`;
   - in a second such world, `close W-900` exits 0 with `state: done`.

   **Genuine red:** today the empty-`list` `done` exits 0 and writes `done`.
   The row fails on its exit assertion.

2. **The guard fails closed, and it stays silent where no PR is required.**
   - `runDone` is imported in-process with no `mergeRefusal`, on a
     `cleanup`-stage world (merged and fetched). It is refused with reason
     `no merge reader was supplied`. Capture `console.error` around the call.
   - The `cleanup` world's `studio/` is copied to a scratch directory outside
     any git work tree. CLI `done` there is refused with reason
     `<that dir> is not inside a git work tree`, and the gh call log has no
     `pr list` line.
   - A world with no `prRequired` (control) runs in-process `runDone` with a
     counting reader that always refuses. It exits 0, and the reader was
     called 0 times. The control rows pass today and must keep passing.

   **Genuine red:** today the in-process `runDone` with no reader exits 0.
   The row fails on its exit assertion.

Behaviour 1's implementation covers `mergeRefusal`, the wiring in the three
callers, and step 3 of the guard. At that point steps 1 and 2 skip: no git
root, or no reader, means no check. Behaviour 2 turns those two skips into
refusals. So behaviour 1's implementation does not already satisfy
behaviour 2 (D-036).

## Out of scope

- **The PR half of the title** (see Intent): no change to `openPr`,
  `fetchTrunk` or the `pr` rung.
- **The printed landings** for `spec/<id>` and `chore/done-<id>`
  (`next.ts:383`). They name a push and a create with no rebase (open
  question 2).
- **`bisellium merge`** (`branch.ts:420`). It refuses unless the opus is done
  on its branch. In a `pr.required` officina, that `done` is now refused
  before the merge, so `merge`'s PR path can no longer be reached
  (open question 3).
- **Officinae without `pr.required`.** There, `merge` lands with a local
  fast-forward and no PR. A "merge" check for them, for example that the
  opus tip is an ancestor of master, belongs to a later opus.
- **`done` fetching, or reading `origin/master`.** "Fetched" means the local
  `refs/heads/master` after `next`'s `merge` rung has fetched it.
- **A check rule** over `done` records already on the trunk.
- **`review --fail`** returning a done opus to `building`. It is unchanged.
