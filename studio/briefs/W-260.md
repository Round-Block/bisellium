# W-260 — a sessioned build or handoff verdict submitted `failed` whose blockers a `## Ruling` withdrew is recorded `passed`, as W-246 made spec verdicts

Status: **signed spec, revision 2** (review round 2: the downstream readers are a full census, `reviewRounds` added) · drafted by Codex under D-027, checked and signed by the architect (`claude-opus-5-5`) · 2026-10-14 · master 0526a197.

Read enumeration: none: the promotion reparses, with the existing `parseVerdictLog`, the header and body bytes `runVerdict` already holds; no file or record kind is newly read.

Red order: one at a time

## Intent

Decree family: convergent-review

W-246 made a sessioned non-UI spec verdict decide its recorded outcome after `parseVerdictLog` applies `## Ruling` (`packages/commands/src/verdict.ts`, the `phase === "spec"` test inside `if (session !== undefined)`). Build and handoff verdicts still reach `sessionedProblem` with the outcome reconciled from raw finding lines only, so a submitted `failed` whose every blocker was withdrawn exits 2: "outcome failed with no standing blocking finding". Probed on master: build (cited blocker, withdrawn), handoff (withdrawn, and `No findings`) and a `kind: ui` opus's handoff all exit 2 and write nothing.

The fix widens that one test, nothing else: every sessioned verdict whose findings `findingsProblem` checks (`!isUi || phase === "handoff"`, the predicate already used above it) is promoted the same way. UI spec and UI build verdicts are unchanged. Threat model: mistakes, not adversaries (D-045): the writer checks grammar and consistency; it does not prove a ruling, rebuttal or session id true. Sessionless and historical logs are not read differently or rewritten.

## Files owned

- `packages/commands/src/verdict.ts`: in `runVerdict`'s session branch, the W-246 condition `!isUi && phase === "spec" && recorded === "failed"` becomes `(!isUi || phase === "handoff") && recorded === "failed"`, and its comment names W-260. No other line.
- `packages/cli/src/verdict-findings.test.ts`: `W-260-b1`, and the two `W-215-b2` flips under Acceptance.

No overlap with W-255 in flight (`next.ts`, `next.test.ts`, `brief-admission*`, `docs/ADOPTION.md`, the prompt and the design lex), so this signs ahead under D-057 §2.

## Interfaces

No exported type or signature changes. The promoted log is the W-246 shape: `# outcome: passed`, then `# submitted_outcome: failed`, the header rebuilt by `headerText()`, the body byte for byte, then the unchanged `sessionedProblem` check. Promotion needs the candidate to parse, no finding blocking after rulings and conversions, and no `## Earlier findings` line `open`; otherwise today's refusal stands.

Downstream needs no change. Every reader of a build or handoff verdict log on master (census: `-review-`/`-handoff-` and `# outcome:` reads across `packages/`, `apps/`, `adapters/` and `scripts/`) reads the promoted log as the passed round it records:

- `parseBuildReviewLog` (via `readBuildRounds`, used by `next`'s `reviewGate` and `amend --round-ruling`): a passed round with no blockers, so `countedFailures` omits it and `reviewGate` accepts a `passed` gate whose status agrees with it; `review --fail` already refuses any log carrying `# submitted_outcome:` (`runReview`, W-126).
- `readSequence` (the writer's next round, and `scripts/review-packet.mjs`'s previous-round packet): no standing blocker, so the next round owes no `## Earlier findings` line for it.
- `reviewRounds` in `packages/cli/src/retro.ts` (`retro --opus` and `scripts/review-rounds.mjs`): parses the sessioned log, counts its withdrawn ruling, does not count it a failed build round, and treats its `# outcome: passed` as ending the handoff run; `readOpusVerdicts` in the same file reads its findings, the withdrawn one non-blocking.
- Header-only reads (`next`'s `reviewLogs`, `reviewSession`; `runReview`'s evidence round) never read the outcome. `authoritativeUiInput` (`opus-model.ts`) reads only UI spec logs, which this does not touch.

A log of that shape could not be written before, so no recorded history reads differently.

### Input domain

Every rejection fails closed: `verdict` exits 2 and writes nothing, `review` exits 2 without touching the gate, or `next` holds.

| Record | Valid domain | Rejected by |
|---|---|---|
| A sessioned verdict candidate (non-UI spec/build/handoff, or a UI opus's handoff) | outcome exactly `passed` or `failed`; one `## Findings` section in the existing grammar; rebuttal, ruling and earlier-findings sections in their existing grammar; promoted only when nothing stands and nothing earlier is `open` | `sessionedProblem` (unchanged): a malformed candidate, an open ruling, a `failed` beside an `open` earlier line with no standing blocker, or any other disagreement is refused before writing |
| A recorded build-review round | the existing header and outcome domain; `passed` may carry `# submitted_outcome:` and has no standing blocker | `parseBuildReviewLog` (unchanged): an out-of-domain log holds `next` |
| A build or handoff log read by `retro --opus` or `scripts/review-rounds.mjs` | the existing header and, for a sessioned log, the `parseVerdictLog` grammar; a promoted log is a passed round | `reviewRounds` (unchanged): an unparseable sessioned log refuses the retro, writing nothing |
| `review --fail` citing a promoted build log | never valid: the round passed | `runReview` (unchanged): exits 2 on `# submitted_outcome:`, gate and events untouched |
