## Intent

## Interfaces

```ts
/** 1-based line of the first `|` outside quotes and comments that is not half of `||` (D-059: no redirection is modelled), or undefined. */
export function shellPipeLine(text: string): number | undefined;
/** process.pipe_exit findings for <repo>'s scripts/*.sh, .github/workflows/*.{yml,yaml} and package.json. Never throws. */
export function repoPipeFindings(repo: string): Finding[];
/** S2: manifest automated commands for any officina; repoPipeFindings(opts.repo) only when resolve(root) === resolve(opts.repo, "studio"). */
export function checkPipeExit(root: string, opts: RuleOpts): Finding[];
```

`shellPipeLine` scans the whole text once, left to right, counting every newline it passes (in quotes, escapes and comments too). These rules are the contract; where Bash's grammar differs, the rules decide (the limits in Promise pipe-check):
- Outside single quotes `\` escapes the next character. A backslash-newline is a continuation: it is removed, so it changes no state and `|`, `\`+newline, `|` reads as `||` and `$`, `\`+newline, `(` as `$(`.
- `'…'` is opaque to the next `'`. Inside `"…"`, `\` escapes the next character, and `$(` and a backtick open a substitution that is scanned like top level, so `x="$(verdict … | tail -1)"` counts. Inside a substitution, unquoted `(` and `)` are counted, and it closes at its closing character (`)`, or a backtick) met at count zero; a backtick met at another count opens a nested substitution.
- `#` starts a comment to end of line only where a word may start: at the start of the text or a substitution, after whitespace or one of `;&()<>`, or after `||`; anywhere else it is part of a word.
- The pipe rule (D-059): an unquoted `|` outside a comment followed by `|` (continuations between them removed) is `||`, and both are consumed. Any other unquoted `|` outside a comment is a pipeline, and its line is returned. Nothing before or after it changes that. `>|`, `>>|`, `<>|`, `&>|`, `2>|`, `|&` and a lone `|` are all pipelines, and `>||` is `>` then `||`. The scanner keeps no redirection state.
- An unterminated quote or substitution returns the line it opened on.

`docs/ADOPTION.md`'s W-221 paragraph says the same in its lexical-limit sentence, which reads: "A pipeline is found lexically: every unquoted `|` outside a comment that is not half of `||` counts, so a redirection such as `>|`, `<>|` or `&>|`, a `case` pattern `a|b)`, a `[[ … =~ a|b ]]` pattern, arithmetic or a heredoc body is read as one (a false alarm: rewrite that line); a pipe inside a quoted string handed to another shell is not seen, `$'…'` is read as `'…'`, and a nested `scripts/` directory, a child shell or a sourced file is not read." The `ponytail:` comment above the scanner names the same false alarms and no redirection handling, and no longer says `$'…'` and heredocs fail closed (`census.txt` §3: each can hide a pipe). The `odd`/`clobber` state and its comment go.
