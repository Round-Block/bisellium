## Intent

A double is exact only to 2^53. A digit grammar with no upper bound (`[1-9][0-9]*`, `\d+`) admits values past it, and reading such a capture through `Number` collapses adjacent values into one. Two build reviews failed on this as an S1 today. W-317 round 1 (`ci/W-317-review-1.log`): spec-log rounds sorted through `Number`, so of `-spec-9007199254740992.log` and `-spec-9007199254740993.log` the rule could pick the older. W-330 round 1 (`ci/W-330-review-1.log`): a squash subject's PR number read through `Number`, so `(#9007199254740993)` could bind to a log for PR #9007199254740992. W-330 round 2 left an S3 advisory (`ci/W-330-review-2.log` #1): no row shows that an exactly matching unbounded PR number is accepted.

After this opus:

1. **The cause fix is a lint rule, `local/exact-digits`** (`scripts/exact-digits.mjs`, wired in `eslint.config.mjs`). In source, `npm run lint` fails on a numeric read (`Number`, `parseInt`, `parseFloat`, `Number.parseInt`, `Number.parseFloat`, unary `+`) of a regex capture whose group can hold more than 15 digits. Every integer of at most 15 digits is exact as a double (10^15 < 2^53), so a site passes by bounding its grammar to 15 digits or by comparing the capture exactly (`BigInt`, or as a string). It is mechanical and runs where every lane already runs lint, in CI's gates and in `bisellium ci`. A prompt or admission rule on the brief's grammar would be prose the reader can still get wrong (Defaults 1). The rule judges code, so a brief's unbounded grammar is safe exactly when its reader passes the rule.
2. **The census.** On master the rule reports 38 reads at 33 lines in 10 source files (`census-s1.out`, from `census.sh`). Each is fixed in this opus. Where a longer value has no meaning (rounds, PR numbers, finding and line numbers, counts), the grammar is bounded to 15 digits, and the reader then refuses or skips a longer value as it does any other malformed one. Two readers compare exactly, because a bound would change what they do. `brief.behaviour_citation` is a detector: bounded, a 16-digit citation would no longer be flagged. The admission's cited-line clamp sends any number past the brief's end to its last line. The verdict writer's `--round` gains the same 15-digit bound, so it writes no round the readers skip. `review` reads a round twice, from its evidence's name and from `--round`; it now trusts the first and refuses a second that differs. Every bound refuses a longer run rather than matching its first 15 digits (`bound-audit.out`). Interfaces 3 lists every site.
3. **Both sides are pinned.** On the bounded side, `W-334-b2` shows two adjacent rounds past the safe integers are not rounds at all (never read as one round), and a round at the bound is read exactly. On the exact side, it shows two adjacent behaviour citations past the safe integers named as written, and the clamp unchanged. W-317's `W-317-b1` already pins its adjacent pair, both accepted and the higher one chosen. W-330's advisory gets its own row, `W-330-b2 behaviour 2 review round 2`: a subject `(#9007199254740993)` and a log for PR #9007199254740993 perform. Its reader (W-330's exact string compare) is unchanged, so this row is a pin with no red; `mutants.out` shows it kills a reader that refuses every suffix past 15 digits.

Promise lint-refuses: `npm run lint` fails with `local/exact-digits` at a source file that reads, in a form the rule recognises (Interfaces 1), a regex capture whose group can hold more than 15 digits through `Number`, `parseInt`, `parseFloat`, `Number.parseInt`, `Number.parseFloat` or unary `+` — limit: only the recognised forms are judged (a capture returned from a function, held in an object, mapped with `.map(Number)` or cut with `split` or `slice` is not followed); a `${…}` in a pattern reads as empty, so a group inside one is not counted; alternatives are added, so a group that is bounded only branch by branch can be reported; test files and `scripts/ci-certify.mjs` are not linted by it (Defaults 3, 4).

Promise bounded-reads: each bounded reader reads a value of 1 to 15 digits exactly, and a longer value is refused or skipped as that reader treats any other malformed name or line (Interfaces 3) — limit: the verdict sequence, the writer, `review`, the previous retro total, the playwright count and the red header are pinned (`W-334-b2`); the other bounded sites' longer-value behaviour is reasoned in Interfaces 3 and checked by the neighbours passing, not by a row each; a JSON number from `gh` (a PR's `number`) is read by `JSON.parse` and stays a double.

Threat model: mistakes, not adversaries (D-045). The values are the officina's own names and lines and `gh`'s output. A value past 15 digits comes from a hand edit or a corrupt tool, never from a verb.
