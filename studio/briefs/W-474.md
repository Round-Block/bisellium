## Intent

The disk fills because the kept scripts of the UI seats (Codex) make a full standalone clone per stage, replay and kill, under their evidence folder, and never delete it. The repository's own code makes no copy that outlives its run. The census (`copy-sites.out`, every `git clone`, `mkdtemp`, `worktree add` and `cp -r` in the repository's source and in the kept scripts under `~/.bisellium-evidence/`):

The fixture census (`codex-passes/fixture-census.sh`) runs Codex read-only in a checkout, with no copy.
- **The kept scripts.** The UI seats' `stages.sh` (W-463: `git clone -q --no-hardlinks proto-repo stage-<stage>.XXXXXX`), `mbox-check.sh` (W-451, W-463), `reds-host.sh` and the `build-*kills*.py` and `restage-prototype.py` of W-408 clone with `--no-hardlinks` into the evidence folder and keep the clone. The engineering architect's `stages.sh`, `kills.py`, `series-builds.sh`, `red-logs.sh` and `gates-proto.sh` (W-466, W-468, this brief) work in the scratch worktree in place and make no copy. The only clean-up today is `codex-passes/ui-run.sh`'s prune after a UI run and the Patron's hand-run `prune-scratch.sh`.

**The change: one helper the kept scripts call, `bisellium run --scratch <dir> [--repo <dir>] [--base <ref>] -- <cmd…>`.** It extends `bisellium run`, which already runs a command in a disposable checkout (`--base`, released when clean, `--reclaim`), rather than adding a verb or per-script code (D-042 decree 7). It is a sella-less mode like `--reclaim`: `run --sella`'s worktree path writes in the main repository's `.git/worktrees/`, keeps a dirty worktree (every stage writes outputs) and writes a receipt into the officina, none of which a scratch copy wants. `--scratch`:

1. refuses, before any copy, a `<dir>` that is not a directory, a `--repo` not inside a git repository, a `--base` that is not a commit there, a flag other than `--repo` and `--base`, a missing command, and a `<dir>` that already holds `SCRATCH_CAP_BYTES` (3 GiB) or more;
2. makes `<dir>/scratch.XXXXXX` by `git clone --shared --no-checkout` of the repository and checks out the base commit detached, then gives the copy a `node_modules` of links to the repository's, so the copy holds a working tree and an `alternates` file and borrows every object;
3. runs the command there with `BISELLIUM_SCRATCH` naming the copy, and returns its exit status;
4. deletes the copy when the command ends, fails or cannot start, and on SIGINT, SIGTERM or SIGHUP stops the command (SIGKILL after 5 s), deletes the copy and exits 128 plus the signal.

**Why `git clone --shared`.** Measured on this repository at the base (`copy-sites.out`): a `--no-hardlinks` clone is 141 MB with a 79 MB `.git`; a `--shared` clone of the same commit is 63 MB with a 784 KB `.git`. `git worktree add --detach` would share everything too, but it writes `.git/worktrees/<name>` in the main repository's common directory: the Codex seat's workspace-write sandbox has only its scratch worktree and its evidence folder writable, so it fails there, and a killed run leaves a registered worktree behind. `clone --shared` reads the source and writes only the destination. A local clone's default hardlinks were rejected because `du` counts the hardlinked packs inside the evidence folder and they fail across file systems; a sparse or shallow checkout because the rows the scripts run read `studio/` and `docs/`, and a shallow clone of a local path copies its objects.

**Why 3 GiB, and where it is enforced.** In `runScratch`, the one place a copy is made, so every kept script that calls the helper is held to it with no code of its own. The largest evidence folders today hold 2.0 GB (W-209-review) and 1.5 GB (W-137-review), with no scratch copy in either; 3 GiB is above them and about 23 of the old full clones or 51 shared ones. The cap is per folder: it counts every regular file under `<dir>`, its subfolders included, symlinks not followed, by apparent size; it is a fixed constant with no flag, so a script cannot raise it.

**What stays a stated limit (D-076 E).** The kept scripts live outside the repository: no check rule can make a script call the helper, and a script that clones by itself is unchanged. `ui-run.sh`'s prune and `prune-scratch.sh` stay as the backstop; the copy's name `scratch.XXXXXX` is the form both already remove. The seats' prompts and kept-script templates switch to the helper after the merge (Defaults 2).

## Interfaces

**`bisellium run --scratch <dir> [--repo <dir>] [--base <ref>] -- <cmd…>`** (`runCommand` in `packages/commands/src/run.ts`), parsed by `parseScratch` in one pass over one table of the three scratch flags (`--scratch`, `--repo`, `--base`) and a seen-set; no flag is matched outside the table.

- **Scratch mode.** A run is a scratch run when, walking the tokens before the first `--` at a flag position and stepping over one value after each table flag, the exact token `--scratch` is met. Every other run is parsed by `run`'s own parse, unchanged.
- **The grammar.** `--scratch <dir>` exactly once; `--repo <v>` at most once; `--base <v>` at most once; in any order; each value is the next token taken verbatim, whatever it is (a leading `-` or `--`, and a bare `--`, included); then `--` and a non-empty command. Nothing else may stand before the separator.
- **The refusals, in the order they are checked.** Left to right, each token at a flag position is, in turn: `--`, the end of the flags; else, not one of the three, `<token> does not go with --scratch` (an unknown flag, a seat flag such as `--sella`, `--keep`, `--studio`, `--opus`, `--no-worktree` or `--reclaim`, a `--flag=value` form, and a positional alike); else, one already seen, `<flag> is given more than once`; else, with no token after it, `<flag> needs a value`. The first token that fails is the one refused, so no later token's error can stand in for it. After the walk, no `--` or nothing after it is `a command after "--" is required`. Each prints `bisellium run --scratch: <reason>` as its first stderr line and then the run usage, exit 2, before `runScratch` is called.
- Otherwise the exit is `runScratch`'s. The usage line `bisellium run --scratch <dir> [--repo <dir>] [--base <ref>] -- <cmd…>` is in `run.ts`'s `USAGE` and in the banner (`usage.ts`). No sella, officina or receipt is read or written.

**`runScratch(a: ScratchArgs): Promise<number>`** (`packages/commands/src/scratch.ts`; `ScratchArgs` is `{ dir; repo?; base?; cmd }`). Each refusal prints one line on stderr, `bisellium run --scratch: ` and its reason, and resolves 2 before any copy: `<dir> is not a directory`; `<resolved --repo, default the current directory> is not inside a git repository`; `<base> is not a commit in <repository top>`; `<real dir> holds <x.xx> GiB, at or over the 3.00 GiB cap of one opus's folder; no copy is made` (when `folderBytes(dir, SCRATCH_CAP_BYTES) >= SCRATCH_CAP_BYTES`). Then: `mkdtempSync(<real dir>/scratch.)`; `git clone -q --shared --no-checkout -- <top> <copy>`; `git -C <copy> checkout -q --detach <commit>`; the links; the command spawned in the copy, stdio inherited, the environment plus `BISELLIUM_SCRATCH=<copy>`. It resolves the command's exit code, 128 plus the signal's number when the command was killed by one, 127 when it cannot start, 1 when the clone or checkout fails (`bisellium run --scratch: git clone --shared failed: …` or `git checkout of <commit> failed: …`) or the copy cannot be removed. On SIGINT, SIGTERM or SIGHUP while it runs, it sends the signal to the command, SIGKILL after `STOP_GRACE_MS` (5,000), and when the command has exited removes the copy and exits the process with 128 plus the signal. The signal handlers are removed before it resolves.

**`folderBytes(dir: string, stop = Infinity): number`**: the sum of `lstat` sizes of every regular file under `dir`, recursing into directories, never following a symlink; it stops walking once the sum reaches `stop`. **`SCRATCH_CAP_BYTES = 3 * 1024 ** 3`**, **`SCRATCH_PREFIX = "scratch."`**.

**The copy's `node_modules`** (`linkModules`): when `<top>/node_modules` is a directory, `<copy>/node_modules` is a new directory; each entry, and each entry of a `@scope` folder (made as a directory in the copy), becomes a symlink: an entry that is itself a symlink gets the same target text (a workspace link `../../packages/x` resolves inside the copy), any other entry an absolute link to the repository's.

Promise copy: a `run --scratch` copy is made under the folder as `scratch.XXXXXX`, at the base commit (default the current directory's repository at HEAD), borrows the repository's objects through `alternates` with none of its own, names itself in `BISELLIUM_SCRATCH`, and has a `node_modules` whose workspace links resolve inside it and whose other entries are the repository's. Pinned by `W-474-b1` "the command runs in a copy under the folder" and pinned by `W-474-b1` "the copy names itself in BISELLIUM_SCRATCH" and pinned by `W-474-b1` "the copy is at the base commit" and pinned by `W-474-b1` "the copy borrows the repository's objects and holds none of its own" and pinned by `W-474-b1` "a workspace link resolves inside the copy" and pinned by `W-474-b1` "a dependency links to the repository's" and pinned by `W-474-b1` "the default is the current directory's repository at HEAD" — limit: the copy holds a full working tree (about 63 MB here); a `git gc --prune` in the source while a copy runs can drop an object the copy reads (git's documented risk of `--shared`); a nested `node_modules` inside a workspace folder, a `node_modules` that is itself a symlink, and a scoped entry more than one level down are not linked.

Promise delete: the copy is deleted when the command passes, fails or cannot start, and the run's exit is the command's. Pinned by `W-474-b1` "the copy is gone when the command passes" and pinned by `W-474-b1` "the command's exit status is the run's" and pinned by `W-474-b1` "the copy is gone when the command fails" and pinned by `W-474-b1` "a command that cannot start exits 127" and pinned by `W-474-b1` "the copy is gone when the command cannot start" — limit: files the command writes outside the copy (its evidence) are kept by design; a failed clone or checkout resolves 1 after removing the copy, unpinned here.

Promise cap: a folder holding 3 GiB or more, counted over every regular file under it with symlinks not followed, refuses the next copy with exit 2, naming its size and the cap, and makes nothing; one byte under the cap copies. Promise refusals: a folder that does not exist, a repository that is not one, a base that is not a commit, a seat flag and a missing command each refuse with exit 2 before any copy. Pinned by `W-474-b3` "a folder that does not exist refuses with exit 2" and pinned by `W-474-b3` "a repository that is not one refuses with exit 2" and pinned by `W-474-b3` "a base that is not a commit refuses with exit 2" and pinned by `W-474-b3` "--sella refuses with exit 2 and its reason first" and pinned by `W-474-b3` "--keep refuses with exit 2 and its reason first" and pinned by `W-474-b3` "no command refuses with exit 2 and its reason first" and pinned by `W-474-b3` "a repeated --scratch refuses with exit 2 and its reason first" and pinned by `W-474-b3` "a repeated --repo refuses with exit 2 and its reason first" and pinned by `W-474-b3` "a repeated --base refuses with exit 2 and its reason first" and pinned by `W-474-b3` "a positional refuses with exit 2 and its reason first" and pinned by `W-474-b3` "a flag missing its value refuses with exit 2 and its reason first" and pinned by `W-474-b3` "the first wrong token refuses with exit 2 and its reason first" — limit: `--studio`, `--opus`, `--no-worktree`, `--reclaim` and a `--flag=value` form refuse by the same table test, unpinned one by one; a run whose only `--scratch` is a `--scratch=<dir>` token, or stands where the walk takes it as a value (`--repo --scratch …`), is not a scratch run and gets `run`'s own refusal (exit 2, no copy), not the scratch reason.
