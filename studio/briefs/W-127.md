# W-127 — a brief is admitted with one decree family and a bounded set of numbered behaviours

Status: **signed spec, revision 2** · architect sella (claude-opus-5-5) · 2026-10-05.
Revision 2 applies the Patron's ruling of 2026-10-05, verbatim: "Let architect
make the exceptions". It replaces revision 1's default (a Patron decision).
The spec gate is written by `bisellium verdict W-127 --phase spec`, not by this text.

## Intent

Decree family: brief-admission

W-125's filing (`briefs/W-125.md`, "Follow-on filings") asks for brief
admission: one declared decree family per opus, its behaviours numbered, a
readiness check with a behaviour-count bound whose number and exception
authority this brief settles, a migration for signed historical briefs, and
no independent behaviour hidden in an unnumbered sublist. It leaves
execution (W-125) and verdict grammar (W-126) alone. `acta/2026-10-05-ranking.md`
item 3 puts it first because every later brief, W-126's included, takes this
shape, and W-126's blocking findings will cite its lines.

**A decree family**, operationally: the behaviours whose genuine reds all
fail at one enforcement seam (one verb, one check rule, or one predicate with
its callers) under one failure condition. Two behaviours are in different
families when either could ship, be reverted, or fail without the other.
That judgment is semantic, and no check can make it; W-125 says so too
("counting is mechanical; semantic family judgments stay with the
architect"). What a check can test, and what this opus enforces:

- the brief **declares** exactly one family, on one line
  `Decree family: <slug>`, which a reviewer can cite and dispute;
- the **count** of numbered behaviours is at most the officina's limit;
- **each numbered behaviour names exactly one genuine red**. A second red
  inside one behaviour, in a bullet, a table row or prose, is an independent
  behaviour hiding unnumbered. This is the checkable proxy for "no hiding".

The architect's spec verdict attests the family is real; the censor can
block on a mixed brief by citing the `Decree family:` line.

**The change.** When an officina's `bisellium.yml` declares
`brief_behaviour_limit`, `ready` refuses a brief that fails admission, and
`check` blocks an active opus whose brief fails it, through one shared
predicate. The real officina declares **6**. Without the key, nothing
changes; `examples/sample-studio` and every existing fixture stay as they are.

**Migration: grandfather by construction.** Admission runs where an opus
enters `building` (`ready`) and, in `check`, only on active opera
(`building`, `verifying`, `review`). Done briefs are never re-read, so no
historical brief is rewritten and no list is kept. `studio/` has no active
opus today. A halted opus is re-admitted when `ready` resumes it.

**Exception authority: a recorded architect ruling (Patron, 2026-10-05).**
A brief over the limit is admitted only with one line
`Behaviour limit exception: <decision-id>`. The line must name a decision
record, `decisions/<id>.md`, in the existing D-nnn shape (`id`, `title`,
`at`, `provenance`, `by`, `kill_when`; `decision.shape` and `decision.kill`
already enforce it). Three architect decisions use it today (D-007, D-016,
D-021). The ruling must meet two conditions:
- its `by` is the magister of the officina's `design` collegium (`architect`
  in `studio/` and in `examples/sample-studio`);
- its text names the opus.

The reader is the existing `patronDecisionProblem`, given the expected
author. No new record kind, verb or path join is added. A spec log is not
used: it signs the whole brief, and it cannot be cited apart from the brief
it signs.

## Interfaces

```ts
// packages/commands/src/brief-admission.ts — text only, no filesystem
export function countBehaviours(briefText: string): number; // moved verbatim
export function readBriefAdmission(briefText: string, limit: number): { problems: string[]; exception?: string };

// packages/commands/src/lifecycle.ts
export function patronDecisionProblem(root: string, manifest: Pick<Manifest, "patron">, decisionId: unknown, opts?: { by?: string; mustName?: string }): string | undefined;
export function briefAdmissionProblems(root: string, manifest: Pick<Manifest, "patron" | "collegia">, opusId: string, briefText: string, limit: number): string[];
```

Without `opts`, `patronDecisionProblem` returns exactly what it returns
today. With `opts.by`, the expected author is `opts.by` instead of
`manifest.patron ?? "patron"`, and a mismatch returns
`decision "<id>" is by "<actual>", not "<opts.by>"`. With `opts.mustName`,
once every other check passes, it returns
`decision "<id>" does not name <mustName>` unless the contained file's text
contains `mustName`. Both reuse its one contained read. The function keeps
its name and file, so `containment.test.ts`'s census keys and its
id-to-path joins do not move. (ponytail: the name now under-describes it;
renaming would move the census keys.)

`readBriefAdmission` returns the problems of clauses 1-3 below, and
`exception` when clause 2 found exactly one exception line on an over-limit
brief. `briefAdmissionProblems` returns those problems plus, when
`exception` is set, `behaviour limit exception: <p>` when
`patronDecisionProblem(root, manifest, exception, { by: magister, mustName: opusId })`
returns p, where `magister` is the `magister` of the `manifest.collegia`
row with `id: design`. With no such row (or an empty magister), p is
`no design collegium declares a magister`. The problem goes where clause 2's
problem would be. Every problem is returned, in this order, never the first
alone (L-054). "Outside fences" uses `countBehaviours`'s fence rule
(`^\s{0,3}` then three backticks toggles).

1. **Family.** Lines outside fences matching `^Decree family:(.*)$`; the
   value is the trimmed capture.
   - none: `declares no decree family; add one line "Decree family: <slug>"`
   - k > 1: `declares <k> decree families (<v1>, <v2>, …); one per brief, file each other family as its own opus`
   - one, not matching `^[a-z][a-z0-9]*(-[a-z0-9]+)*$`:
     `decree family "<v>" is not one slug`
2. **Count.** `n = countBehaviours(briefText)`.
   - n = 0: `numbers no behaviours under "## Behaviours to test"`
   - n > limit, with lines outside fences matching
     `^Behaviour limit exception:(.*)$`:
     - none: `numbers <n> behaviours; the limit is <limit> (brief_behaviour_limit); split it by decree family, or cite an architect ruling on a "Behaviour limit exception:" line`
     - more than one: `has <e> "Behaviour limit exception:" lines; at most one`
     - one: no problem here; `exception` = the trimmed value, which
       `briefAdmissionProblems` validates as above.
   - n ≤ limit: exception lines are not read.
3. **One red per behaviour** (only when n ≥ 1). Within `## Behaviours to
   test`, bounded as `countBehaviours` bounds it, count occurrences of the
   literal `**Genuine red:**` outside fences and not immediately preceded by
   a backtick. Each is assigned to the numbered item it follows.
   - any before item 1: `has a "**Genuine red:**" outside any numbered behaviour`
   - item i with k ≠ 1: `behaviour <i> names <k> genuine reds; each numbered behaviour names exactly one, so number every independent behaviour`

**`ready`.** When `manifest.brief_behaviour_limit` is defined, after every
existing refusal (after `refuseModel`) and before `editOpusFrontMatter`:
- not a positive integer: one line `<id>: brief.admission: brief_behaviour_limit must be a positive integer`;
- otherwise one stderr line per problem:
  `<id>: brief.admission: <specRel> <problem>`.

Either way it exits 1, writes no record and emits no event. Undefined key:
today's behaviour.

**`check`.** `brief_behaviour_limit` present and not a positive integer:
`manifest.shape` block at `bisellium.yml#brief_behaviour_limit`, message
`brief_behaviour_limit must be a positive integer`, and no `brief.admission`
finding. Valid: for each opus in `ACTIVE` with a `spec:` that
`readContainedRegularFile(root, spec, "briefs")` reads, one
`brief.admission` **block** per problem from `briefAdmissionProblems`
(imported from `@bisellium/commands/lifecycle.js`) at `opera/<id>.md`, message
`<spec> <problem>`. An unreadable spec adds nothing here;
`state.building.spec` and `opus.red_evidence` already cover it.

**Citable shape (for W-126).** The `Decree family:` line, each numbered
behaviour's first line, its single `**Genuine red:**` and any exception line
are each one line, so a finding cites `briefs/<id>.md:<line>`.

Every row copies `examples/sample-studio` to a temp dir, sets

**Accepted** means exit 0 and `state: building`. Each behaviour is a
`node:test` `describe("behaviour <n>")`, selectable by name pattern.
