## Intent

Decree family: merge-queue-binding-storage

W-168's queue binding is a key in this clone's local Git config, which no agent session can write. The sandbox mounts `.git/config` and an empty `.git/config.lock` read-only, and production lex §8 says the error is expected. So in an agent session, a queue-mode `pr` held at the binding write (`integrate.ts:607`), before its push. W-168's passing rows ran in scratch repositories without that lock. W-199 replaces only the binding's storage with a file under the repository's Git common directory, which the sandbox leaves writable. W-168's ordering is kept. The `openPr` whys name the file instead of the key. This extends `openPr` and `mergeGate` (D-042); the threat model is mistakes (D-045).

## Interfaces

```ts
/** W-199: the file whose presence binds a queue-mode PR head: `<git common dir>/bisellium/queue/<encodeURIComponent(branch)>`. */
function queueFile(repo: string, branch: string): { path: string } | { error: string };
/** W-199: `absent` only when `lstat` finds no entry; any entry is `bound`; any other failure is `error`. */
function readBinding(repo: string, branch: string): { kind: "absent" | "bound"; path: string } | { kind: "error"; reason: string };
```

Both are module-private. `queueFile` runs `git rev-parse --path-format=absolute --git-common-dir` in `repo` (`git`, `integrate.ts:46`). It makes no filesystem call of its own. For `opus/W-900` it gives `<common>/bisellium/queue/opus%2FW-900`. `readBinding` calls `lstatSync(path, { throwIfNoEntry: false })`: `undefined` is `absent`, a stat of any type is `bound`. A `queueFile` error or a throw (for example `ENOTDIR`) is `error`, its reason passed through `clean`. Every caller passes `ctx.repo`.

The call sites, checked line by line against `integrate.ts:586–688`:

- **Queue-mode `openPr`.** The on-branch, `dirtyHold`, `fetchTrunk`, `repoSlug` and `readMergeQueue` checks, and `readRef(wt, "HEAD")`, are unchanged. Then it takes `queueFile(repo, branch)`, `mkdirSync(dirname(path), { recursive: true })` and `writeFileSync(path, `${head.oid}\n`)`. A `queueFile` error holds with `why: cannot write the queue binding: <reason>`, and a throw with `why: cannot write the queue binding <path>: <reason>`. Nothing is pushed. `readBinding` only `lstat`s the path. The OID in the file is there for a person and for the tests' `bound(w)`; no production code reads it.
- **Direct-mode `openPr`.** It calls `readBinding(repo, branch)` where `git config --get` stood: after the mode read, before `sourceTreeHash` and the rebase. `error` holds with `why: cannot read the queue binding: <reason>`. `absent` takes today's path, with no further binding call. `bound` takes the same rebase and push, then `unlinkSync(path)`. If that throws, it holds with `why: pushed, but the queue binding <path> could not be removed: <reason>`, and there is no `gh pr create`.
- **Direct-mode `mergeGate`.** It calls `readBinding(ctx.repo, ctx.head)` where `git config --get` stood: right after the mode read, before `gate`. `absent` goes on to `gate`. `bound` or `error` returns W-168's lines unchanged: `mode: direct` and `why: PR #<n> was pushed for the merge queue without a rebase, …`. `mergeGate` makes no `gh` write. Limit (W-168's, kept): an `error` gets that same why. `landHead` reaches this read for `spec/<id>` and `chore/done-<id>` after its own push and PR create (row 20).
- **Queue-mode `mergeGate` and `cleanup`.** They make no binding call; neither did W-168. The file outlives `cleanup` (W-168's stated limit).

Migration: a `branch.<head>.bisellium-queue` config key is ignored. After W-199 no production code interprets it as a binding. `supportsSafeRefInspection` (`ids.ts:58`) lists every config key with `git config --null --list`, but it looks only for partial-clone markers. Git creates `.git/config.lock` exclusively before writing this clone's local config. The sandbox's lock already exists, so a local-config write in this clone fails in an agent session and none could have been written here. `reads.txt` §8 finds none (Default 4).

## Out of scope

- Merge-queue detection, rules, CI certification, rebase policy and polling.
- Removing a binding after a queued merge, or in `cleanup`.
- Migrating, reading or removing legacy Git config keys.
- A general store under `.git/`.
- Durability beyond `writeFileSync`.
- Symlinks placed on purpose (D-045).
- Overlapping runs of one opus. Limit: the step marker serialises `next --perform` runs, except that `assess` (`next.ts:1075`) judges a still-live process dead once it has been silent past its budget. A new `--perform` may then take over the marker while the old process, which is not killed, keeps running, so two `pr` or `merge` runs can overlap.

## Defaults for the Patron to veto

1. The location is `<git common dir>/bisellium/queue/<encodeURIComponent(branch)>`. It is not `.bisellium/` in the checkout: that directory is gitignored, so `git clean -fdx` would delete a binding, and a lost binding opens instead of holding.
2. Presence is the binding. The file holds the head OID and a newline, for a person and for the tests' `bound(w)`; no production code reads the bytes.
3. The write is a plain `writeFileSync`, with no temp file or rename. A partial file still holds.
4. Legacy `branch.*.bisellium-queue` keys are ignored. To check a checkout outside the sandbox: `git config --get-regexp bisellium-queue`. If it prints a line, write its OID into the new file for that branch, so direct mode still holds the PR, then unset the key.
5. In direct mode, an unreadable binding gets W-168's queue why, unchanged.
