# W-104 - Test source-diverse selection under a fixed evidence cap

## Intent

Test whether the cheapest deterministic file-diversity policy recovers evidence omitted by the frozen six-case MAPS lexical baseline under the same four-file and 6,000-character caps. These known cases are development cases, not held-out validation. W-103 and all prior pilot artifacts/scores remain unchanged.

## Interfaces

Add only experimental mode `search-diverse`. Existing `search` and `route` results remain byte-compatible for unchanged inputs; existing invalid-mode/limit rejection semantics remain, except that the new mode is accepted. Scanning, matching, manifests, order, provenance, failures and scan accounting stay unchanged.

The new mode inherits the entire W-103 search trust boundary and resource contract in `studio/briefs/W-103.md`: retrieval receives only `{id, project, question}` plus corpus bindings and budgets, never references, captured hashes/excerpts, expected outcomes, measurements, checkout snapshots or route results. Preserve lexical and canonical exclusions, oracle-copy exclusion inventory, containment, regular UTF-8 files, static cooperative corpus assumptions, read-only bounded Git allowlist/environment, no network/source execution/target writes, and all input/scan bounds and accounting. W-104 outputs and spec artifacts are excluded oracle/generated artifacts too. Poison every forbidden case field and require byte-identical new-mode output and metrics. Reference data may enter only the separate post-output evaluator.

Buffer matches during the unchanged bounded scan. Within each case, select a fixed global list of the first distinct matching `(repository ID, path)` files in existing code-unit repository-ID/path order, up to `excerptFiles`, across all repositories together. Do not refill this list when a file exhausts its ranges. Each selected file has a queue of its matching ranges in line order. Unselected files retain their existing match metadata but emit no excerpts.

At cycle start, active files are selected files with nonempty queues, in the same fixed order. Each active file gets at most one turn in that cycle. Its quota is `floor(remaining excerptCharacters / remaining turns in this cycle)`, including the current turn; decrement remaining turns after each turn. A positive quota consumes the next whole queued range and emits its nonempty prefix of at most that quota. A truncated suffix is discarded permanently, never resumed. A quota of zero emits nothing and leaves the queue unchanged for final omission accounting or a later cycle. Short ranges leave capacity available to later turns/cycles. Finish when no queued range remains or no character budget remains; every cycle with positive budget and an active queue emits at least one character, ensuring finite termination. Never emit empty excerpts.

All currently legal nonnegative integer budgets remain legal, including zero and budgets smaller than active-file count. Zero file or character caps emit no excerpts but do not suppress the bounded scan. Count characters by the existing JavaScript string-length/slice convention. Preserve every file's original `ranges` metadata and ordered prefix-correspondence: `excerpts[i]` is a prefix of `ranges[i]`, without gaps or resumed suffixes. For each discovered range, increment its owning repository's `omittedExcerpts` exactly once if truncated or wholly unserved (including unselected files and ranges left queued at termination), never twice; complete ranges add zero. Undiscovered ranges from scan exhaustion are not invented. Report scan incompleteness separately from excerpt omission.

## Behaviours to test

1. Under four files/6,000 characters, an oversized first range cannot exceed 1,500 characters in cycle one and every active selected file gets a turn. Exercise multiple repositories, fixed global selection, later cycles, short/exhausted queues, zero/low budgets and quota-zero turns. Assert finite termination, no empty excerpts, truthful prefix correspondence and per-repository omissions. Record its assertion-level red before implementation.
2. Repeated new-mode outputs are byte-identical and use only existing repository-ID/path/line order; permutation of manifest input cannot change selection. Record its distinct assertion-level red before implementation.
3. New-mode oracle isolation: poisoning all forbidden case fields leaves results and metrics byte-identical, while containment/exclusion/scan/Git contracts remain inherited. Record a distinct assertion-level red for this genuinely new mode property before implementation.

Pinned existing `search` and `route` fixtures, invalid modes and invalid limits are green regression requirements, not new red obligations. Do not manufacture a red for already-passing compatibility. Synthetic selector fixtures contain no pilot keys or keyed paths/hashes.
