## Intent

Today a milestone's percentage is the share of points done among the opera filed under it (`computeMeter`, `packages/core/src/completion.ts:69`), capped at 95 while its exit is open. It is shown by the console's Officina "Completion" panel through `/api/completion` (`apps/server/src/store.ts:513`). Filing more opera under a milestone lowers its number, and the number does not say whether the exit is met. On the real officina, master's meter reads 57.0% overall while one exit of ten is met (`meter-master.out`).

This opus adds a read-only report that counts exits instead. A milestone is met when its exit is met. The exit forms are those `milestones.yml` declares (D-038):

- An `opus:` exit is met when that opus's record is `done`.
- A `rule:` exit is met when check reports no finding of that rule. Check runs once, with `--repo`, as `check --repo` runs, and a finding of any level counts.
- A `needs:` exit names no opus and no rule, so no record can meet it. W-281 re-points those exits.
- A milestone with no exit is never met.

The weighted share is the floor of 100 × the weight of the met milestones over the weight of all of them. Filing an opus moves nothing. On the real officina the report reads `milestones: 1 of 10 exits met, 10% by weight` (`report-proto.out`): M1 is met (W-125 done), and M7's rule `lesson.recurrent` has 2 findings.

What "on its exit path" means, from the records. The records link an opus to an exit in two ways only: the exit's own `opus:`, and an opus's `parent:` (the opus it was split from, written by `new --parent`). So the path is the exit opus, then every opus whose parent chain reaches it. An opus's `milestone:` names the milestone it serves, not an exit that waits on it, so the report does not read it: counting it is the filing count this opus replaces. A `rule:`, `needs:` or absent exit has no path. On the real officina the 5 parent links reach no exit opus (`enumerate.out`), so each path is its exit opus alone. When W-118's split files its pieces with `parent: W-118`, they join M3's path. The report draws no dependency graph, since the records hold none.

The edge cases:

- No `milestones.yml`: the verb prints one line, and `next --all` prints no milestones line, as before this opus.
- A malformed `milestones.yml` (it does not parse, has no non-empty milestones list, or has an entry that is not an id, a title, a positive integer weight and at most one exit form): the report is held, naming every problem, and exits 1.
- An opus record that cannot be read: held as well, since it may be on a path.
- An opus naming an undeclared milestone: it moves nothing, since `milestone:` is not read. Check's `opus.milestone` still blocks it.

`bisellium milestones [--studio <dir>] [--repo <dir>] [--now <iso>]` prints the report. `next --all` prints it as one line before `open: <n>`, its needs text left to the verb. The code is one new module, `packages/cli/src/exits.ts`. The console panel is left as it is (Out of scope).

Threat model: mistakes, not adversaries (D-045).

## Interfaces

The prototype is `prototype.diff` over master cf96d936, built by `stages.sh` from `apply-src.py <checkout> s1|s2|b2` and `apply-test.py <checkout> b1|b2|all`. The series `prototype.mbox` carries its four commits in order.

**`bisellium milestones [--studio <dir>] [--repo <dir>] [--now <iso>]`** (`runMilestones`). `--repo` defaults to `.` and `--studio` to `<repo>/studio`, as for `next`; `--now` sets check's clock. A positional, an unknown flag, a flag without its value, a `--now` that is no ISO date, or a `--studio` that is not an officina prints `milestones: <why>` and the usage line on stderr and exits 2. Otherwise it prints, on stdout:

1. With no `milestones.yml`: `milestones: none: the officina has no milestones.yml`, exit 0.
2. Held: `milestones: held · why: <why>`, exit 1, and nothing else. `<why>` is one of these. `milestones.yml is malformed: <problem>; <problem>…`, every problem in file order. `milestones.yml cannot be read: <message>`. `opera/<id>.md cannot be read (<message>)`, each such record `;`-joined. A throw from check, as its first message line.
3. Otherwise `milestones: <k> of <n> exits met, <p>% by weight`, then one line per milestone in file order: `<id> met|open · weight <w> · <title> · exit: <status> · path: <id> <state>, … | none`. `<status>` is `opus <id> (<state>|no state|no record)`, `rule <id> (no finding|1 finding|<n> findings|not a check rule)`, `needs: <text> (no record can meet it)` or `none stated`. Exit 0. Each line's control characters print as one space.

**`next --all`** (`runAll`, W-299's lines otherwise unchanged). When `milestonesLine` returns a line, `runAll` pushes it after the opus lines and before `open: <n>`: `milestones: <k> of <n> exits met, <p>% by weight · <id> met|open: <exit>; path <id>, … | none · …`. `<exit>` is `opus <id>`, `rule <id>`, `needs` or `no exit`. A held report is `milestones: held · why: <why>`, and the run then exits 1, after every line. With no `milestones.yml` there is no line.

**`exitReport(studio, repo, now)`**: `{ kind: "absent" } | { kind: "held"; why } | { kind: "report"; rows; met; share }`. It reads `milestones.yml` through `readContainedRegularFile` (`opus-model.ts`, reused), each `opera/<id>.md` through `readFront` (adapter-native, reused), and check's findings through `checkStudio(studio, now, { repo })`. Check runs only when some exit names a rule in `RULE_IDS`. It writes nothing.

Promise exits: on a well-formed `milestones.yml` and readable records, `bisellium milestones` prints the summary and one line per milestone, each naming its exit, met or open, and its path. The share is the floor of 100 × the met weight over the whole weight. It exits 0. Pinned by `W-404-b1` "the report: a summary, then one line per milestone in file order", pinned by `W-404-b1` "the exit opus done: M1 met, 70%" and pinned by `W-404-b1` "one acta.kind finding: M2 open" — limit: a rule exit is as true as check's findings, and check, `readFront` and the YAML reader are reused unchanged. A weight total past 2^53 / 100 is summed in floating point.

Promise filings: filing an opus under a milestone, done or not, or naming a milestone that is not declared, changes no line of the report and no part of the `next --all` line. Pinned by `W-404-b1` "filing more opera, done or not, and an opus naming an undeclared milestone change no line" and pinned by `W-404-b2` "filing more opera, and an opus naming an undeclared milestone, change nothing" — limit: an opus whose `parent` chain reaches an exit opus is listed on that path, though it is never counted.

Promise held: a malformed `milestones.yml`, or an opus record that cannot be read, prints exactly one held line naming why, and no share, and exits 1. `next --all` prints that held line before `open:` and exits 1 after every line. Pinned by `W-404-b1` "four bad entries: one held line naming why, no row", pinned by `W-404-b1` "an unreadable record: held" and pinned by `W-404-b2` "a malformed milestones.yml: the held line" — limit: the why quotes the YAML reader's or the front-matter reader's own first message line (reused unchanged), and `next --all` bounds it at 1000 characters, as every line it prints.

Promise absent: with no `milestones.yml`, the verb prints one line and exits 0, and `next --all` prints no milestones line. Pinned by `W-404-b1` "no milestones.yml: one line" and pinned by `W-404-b2` "no milestones.yml: no milestones line" — limit: only a missing file is absent; any other refusal of the contained read is held.

Promise read-only: a run of the verb or of `next --all` leaves every file under the repository byte-identical, `.git` included. Pinned by `W-404-b1` "the run writes nothing: every file under the repository, .git included, is byte-identical" and pinned by `W-404-b2` "next --all writes nothing: every file under the repository, .git included, is byte-identical" — limit: check's own reads are check's (reused unchanged), and the rows prove it on their fixture repository.

Promise next-line: with a `milestones.yml`, `next --all` prints the report as one line after the opus lines and before `open: <n>`. Pinned by `W-404-b2` "the milestones line, then the open count" — limit: the line is bounded at 1000 characters by W-299's `clean`, so a long path list is cut there; the verb prints it whole. Check adds its own run time to `next --all` (about 3 s on the real officina).

Limits, stated:

- Unchanged code the promises lean on is a stated limit, not a guarantee (D-076 E): `checkStudio` and every rule it runs; `readContainedRegularFile`, `openStudio`, `parseFlags` and `resolveNow`; adapter-native's `readFront` and `listMd`; the `yaml` package; `RULE_IDS`; and in `next.ts`, `runAll`, `clean` and the linked-worktree refusal. Node and its test runner are limits too.
- A rule exit is judged with `--repo`: a rule that reads a branch's diff finds what it finds on the checked-out tree.
- `--studio` and `--repo` are resolved by node's `resolve` and opened by `openStudio`, reused. A studio outside the repository is not refused by the verb, which reads only. The rows run on fixture paths under the OS tmp dir.
