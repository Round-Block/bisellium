## Intent

A `kind: ui` opus's passed build review cites the ui-lead input it read (`# ui_input:`) and the design digest it judged (`# design_digest:`). Check's `opus.ui.design` rule compares both with the current input and digest (`reviewCitation`, `packages/commands/src/opus-model.ts:805` on master) and blocks when either differs. That is right for a review recorded after the current input. It is wrong for one recorded before it, which could not have cited it.

W-406 shows the defect. Its build review round 1 passed at 06:36 citing `ci/W-406-spec-3.log`. The Patron rejected the screens, the brief was revised and re-signed, and the ui-lead input was re-recorded as round 6 at 07:47. Check now blocks W-406 with two findings: "review evidence does not cite the current ui-lead input" and "review evidence design_digest is missing or stale" (`w406-probe.out`, master). `bisellium ci --opus` runs that check, so it fails, and `next` orders a new build review only after `ci --opus` passes at the current tree. That is a deadlock.

This opus makes such a review superseded. A superseded review counts as no review. In check, before `done`, it blocks nothing, so `ci --opus` can pass. `next`'s review rung then orders the new review, never the pr on the old one. On W-406's worktree the prototype's check has no `opus.ui.design` finding and exits 0 (`w406-probe.out`).

The enumeration (`enumerate.out`) reads every `kind: ui` record on the real officina and on W-406's worktree. W-406's review is the only superseded one. Each of the six other passed reviews (W-339, W-345, W-350, W-360, W-361 and W-366) was recorded after the input it cites, and that input is still the current one.

How "recorded before" is read. Only the two logs' headers are read, never free text. A build review is superseded by the current ui-lead input when both of these hold:

- Its `# at:` is a valid UTC instant strictly before the current input's `# at:`. The input's `at` is already validated by `authoritativeUiInput`, which picks the input as the highest-round ui-lead `ci/<id>-spec-<n>.log`.
- Its `# ui_input:` names an earlier round of this opus's spec logs: `ci/<id>-spec-<m>.log`, with `<id>` the opus and `m` below the current input's round.

For W-406, 06:36:13 is before 07:47:39, and round 3 is below round 6. A review recorded later than the input cannot have been written before it. One citing the current or a later round claims an input it did not read. Either is judged as today.

What still blocks:

- A review recorded at or after the current input that cites an older one, or the current one with a stale digest (today's two messages).
- A review recorded before the current input that cites the current input: a false claim. This is a new message, "review evidence cites the current ui-lead input but was recorded before it". Today such a review passes when its digest matches.
- A review with no `# at:` or a malformed one. This is a new message, "review evidence has a missing or malformed # at: timestamp", in every phase, even when the review cites the current input at the current digest. Such a review is never superseded. A review citing a later round, another opus's log or any other path is never superseded either, and keeps today's messages.
- Every case when no newer ui-lead input exists, as today.
- The superseded review on a `done` record, and in the `review` and `done` phases (`review --pass` and `done`). There it counts as no review and keeps today's messages, so nothing merges or closes on it.

`next` agrees with check through one shared reader. Its review rung (rung 7) asks `uiReviewSuperseded` whether the passed gate's evidence is superseded. If it is, rung 7 orders a new build review whose `why` names both logs. This matters when the brief did not change. The gate is then current at its tree and brief, and without the reader `next` would go on to the pr (`red-b2-stage1.out`). When the brief changed, as W-406's did, today's brief pin already orders the review once `ci --opus` passes.

Threat model: mistakes, not adversaries (D-045). A header is the verb's own write. A hand-edited `# at:` can make a stale review look superseded, but that only asks for a new review. It never passes one.
