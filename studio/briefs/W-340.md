## Intent

High under D-088 F. A `kind: ui` opus already requires current ui-lead input, a passed served-e2e gate and bounded screenshots under `studio/ci/shots/<id>/`. The automated build reviewer still cannot see them: the packet carries text only, `next --perform --expect review` refuses UI opera, and the prompt has no UI slot.

Revision 1 chose a text pixel-diff summary because its in-sandbox probe found `codex exec -i` but failed before reaching the model. The producer then ran `/home/edckt/.bisellium-evidence/W-340-spec/probe-images-blind.sh`: it copied one served screenshot into an otherwise empty directory, ran `codex exec -m gpt-5.6-sol -s read-only -C <empty> -i shot.png`, prohibited file reads, and asked for four visible facts. `probe-blind-answer.txt` named Inbox, Board, Seats, Officina, W-004, eng-lead, Ratio decidendi and all four action labels; the producer scored all 11 strings from the same PNG. `probe-blind-session.log` records the isolated working directory, model and answer. This proves the configured Codex review seat reads an attached image, so revision 2 replaces the fallback rather than carrying both.

Every UI review now receives exactly eight served screenshots in one fixed order: Inbox, Board, Seats and Officina at 1280×900, followed by the same four at 390×900. `ui.txt` names each attachment, viewport and screen-specific judgment. `next` gives those same absolute paths to the Codex harness as repeated `-i` pairs, for both a fresh round and a resumed round. The first-round UI slot embeds the list; the later-round prompt points to the current `ui.txt` and says the images are attached.

The served walk produces that exact desktop/phone matrix. Packet construction reuses the manifest's bounded containment read, permits the 390-wide phone form, requires the exact eight names and dimensions, and refuses before writing if any shot is missing, unreadable, non-regular, symlinked, over 4 MiB, outside `studio/ci/shots/<id>/`, extra or misdimensioned. Exact count bounds aggregate image input at 32 MiB.

The text pixel-diff summary is dropped. It would add exact change magnitude, but it would also require a base baseline and still would not convey visual meaning; attached current images let the censor judge the UI directly without blocking the first baseline-bearing opera. This opus makes no visual-regression comparison claim.

3. `uiFact(studio, opus)` (`review-packet.mjs`, internal). A UI record requires exactly the eight names above, rejects any absent or extra name, requires each named width and height 900, then returns the files in the declared desktop-then-phone order. Since each admitted file is at most 4 MiB, the fixed eight cap aggregate attachment bytes at 32 MiB. All work happens before the packet directory exists.

4. Build packet (`review-packet.mjs`). Every build packet retains `ui.txt`; its text is the ordered attachment manifest and screen-specific review instruction, not a pixel diff. The in-process result adds `images: string[]`, whose absolute paths are derived only as `<studio>/ci/shots/<id>/<fixed-name>` after contained reads. The command-line packet writer ignores that in-memory field because it does not launch a reviewer.

5. Codex harness (`harness/types.ts`, `harness/codex.ts`). `HarnessStartOpts` and `HarnessResumeOpts` gain optional readonly `images`. The Codex profile alone turns each element into one repeated `-i <path>` pair after model/reasoning flags and before stdin `-`, preserving caller order. Other harnesses ignore the optional field.

6. Automated UI review (`next.ts`). The packet's `images` list is passed unchanged on first and resumed Codex turns; `<UI>` is filled with the packet's complete attachment description. A UI review holds before Codex when packet admission fails or current ui-lead input is unavailable. Otherwise `runVerdict` receives `--ui-input`, so the design digest, source and nonblank `## UI input disposition` remain enforced. Non-UI reviews attach nothing. The row fixture asks `next` to mint the round-2 `verdict-spec` ticket before its real ui-lead writer call, declares a live design ui-lead, and deliberately leaves both W-348 pairing keys absent: that base's admitted compatibility form requires no extra signer/reviewer seats.
