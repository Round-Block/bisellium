## Intent

A recorded red is meant to prove that a behaviour's test fails for the reason the behaviour names. Today nothing compares the assertion a red failed at with the one its brief declares, so a red counts as genuine when its row failed at an earlier assertion, at a setup throw or at a precondition, and proves nothing about the behaviour. Where a red is admitted today:

- The red verb (`runRed`, `packages/commands/src/lifecycle.ts`) writes every red log. It records any non-zero exit, after W-166's tree, order and ticket checks and W-461's web build; it reads no assertion.
- The reds perform (`performReds`, `packages/cli/src/next.ts`) records each prototype red by calling `runRed`, then counts it by `usableRed` (exit, tree, module load). W-468's fix-round re-red is the red verb again, on its own ticket.
- Certify's replay (`scripts/run-builder-host.mjs`) and the pr rung's rewrite check (`packages/cli/src/rewrite.ts`) re-run a recorded red and accept it by `classifyReplay` (`scripts/replay-accept.mjs`): any `not ok`, `AssertionError` or `ERR_ASSERTION` with no environment failure. They compare nothing with the brief.
- Brief admission (`readBriefAdmission`) counts one `**Genuine red:**` marker per behaviour; the "fails at …" text after it is prose no reader holds a red to.

**The rule, at one boundary.** The red verb is the one place every red is made: a builder's own `bisellium red`, the reds perform and the fix-round re-red all call `runRed`, and the two replays only reproduce a log it wrote, at the same commit with the same words. So the comparison is made there, once, and no replay, classifier or check rule is patched: when behaviour k's genuine red declares its failing assertion, `runRed` records the red only when the command's output fails at it; otherwise it exits 1 and writes nothing, naming the declared assertion and the first `error:` the output holds. A brief that declares two exits 2 before any command runs.

**How the brief declares it: the existing pin.** No new line shape. A pin, W-322's `pinned by` form with the row in backticks and the assertion text in double quotes, already names a test row and an assertion for promises and Input domain rows, and W-381 already reads a kill's output for it. Behaviour k declares its red's failing assertion with one pin on its item's lines from its `**Genuine red:**` marker line to the item's end (`declaredReds`); a pin before the marker is part of the behaviour's text and declares nothing.

**How the red's failing assertion is read, and what counts as equal.** The output is the command's stdout and stderr as `runRed` captures them, read by W-381's kill reader (`provesPin`), without its `TAP version 13` first-line test (`redFailsAt`): the declared row's subtest (its title opening with the row name, then a space or the line's end) closes `not ok`, and one of its diagnostic blocks holds an `error:` message that is the declared text, or opens with it and `: `, beside `code: 'ERR_ASSERTION'`. Anything else is refused: a failure at another assertion, an error thrown with the declared text (its code is not `'ERR_ASSERTION'`), a message that opens with the text without `: `, the text failing in another row, and output in another form (the spec reporter, Playwright).

**Opera in flight.** No migration. A brief that declares no failing assertion for a behaviour (every brief signed before this opus) records that behaviour's red as before, so W-468, W-472, W-474, W-477 and every other opus past ready keep their briefs and their reds. New opera are held to it by ready, W-166's pattern: once admission and the red order pass, ready refuses a brief where any behaviour's genuine red declares no failing assertion or more than one (`declaredRedProblems`), in an officina that declares `brief_behaviour_limit`, unless the opus is already past ready (halted with `builder_runtime` or `start`). A Playwright red that declares none is exempt, since a pin is proved by Node's TAP output only; a Playwright red is one whose written red command opens with a closed launch form (`launchesPlaywright`: a `playwright` executable, `npx` then `playwright`, or `node` then a path ending `/node_modules/@playwright/test/cli.js`), and a later argument such as a test-name pattern `playwright` never exempts. The check rule `brief.admission` does not ask for it, so active opera's briefs stay admitted; a greenlit opus whose brief is signed but not yet ready adds one pin per behaviour before ready.

Threat model: mistakes, not adversaries (D-045). A builder who writes a log by hand, or a brief amended to drop its pins, is outside it.

Promise declared-red: after this opus the red verb records behaviour k's red, for an opus whose brief declares that behaviour's failing assertion, only when the command's output shows the declared row's subtest `not ok` with an `error:` message that is the declared text or opens with it and `: `, beside `code: 'ERR_ASSERTION'`; any other output exits 1 with nothing written, and two declared assertions exit 2 before the command runs. Pinned by `W-473-b1` "a red failing at another assertion is refused" and pinned by `W-473-b1` "a thrown error carrying the declared text is refused" and pinned by `W-473-b1` "two declared assertions exit 2" — limit: a brief that declares none records as before; the replays (`classifyReplay` in certify's host runner and the pr rung) and the check rules are unchanged and do not compare again, so a replay that fails elsewhere on a later run is not seen, and a log written by hand is not checked; the declared text holds no double quote.

Promise ready-declares: after this opus ready refuses a new opus, in an officina that declares `brief_behaviour_limit`, whose brief has a behaviour whose genuine red declares no failing assertion or more than one, unless that red's command opens with a closed Playwright-launch form and declares none, and an opus already past ready is not asked. Pinned by `W-473-b2` "ready refuses a genuine red that declares no failing assertion" and pinned by `W-473-b2` "two declared assertions are refused" and pinned by `W-473-b2` "an incidental playwright argument does not exempt a red" and pinned by `W-473-b2` "a Playwright red that declares none is admitted" and pinned by `W-473-b2` "an opus past ready resumes with no declared assertion" — limit: the spec rung of next and the check rule `brief.admission` do not ask for it, so a signed brief without pins is refused at ready, not at signing; a Playwright red is recognised by the opening words of its written red command only, so a launch through another wrapper (a shell script, `npm run`) is not exempt and must declare a pin or not be a Playwright red.

## Interfaces

In `packages/commands/src/brief-admission.ts` (`Pin` is W-322's `{ row: string; assertion: string }`):

- `declaredReds(briefText: string, k: number): Pin[]`: every pin on behaviour k's item lines (`behaviourItems`) from the line holding its `**Genuine red:**` marker to the item's end, in brief order; none when there is no marker or no item k.
- `redFailsAt(output: string, pin: Pin): boolean`: `provesPin` over the output's lines.
- `firstFailure(output: string): string | undefined`: the first diagnostic `error:` message (a quoted `'…'` with `''` read as one quote, an `error: |-` block's first line, else the value as printed), for the refusal.
- `declaredRedProblems(briefText: string, id: string): string[]`: per behaviour with other than one pin, unless it declares none and `redCommand` starts with a closed Playwright-launch form (`launchesPlaywright(words: string[]): boolean`, not exported): a `PLAYWRIGHT_WORD` executable, `npx` followed by a `PLAYWRIGHT_WORD`, or `node` followed by a path ending `/node_modules/@playwright/test/cli.js`; a matching later argument never exempts the brief. Its problem: `behaviour <k>'s genuine red declares <n> failing assertions; declare one after its marker: pinned by \`<row>\` "<assertion>" (W-473)`.

The red verb's two new refusals, on stderr, nothing written: exit 2, before any command runs, `red: <id>: behaviour <k>'s genuine red declares <n> failing assertions; one, or none — nothing run`; exit 1, after the command, `red: behaviour <k> did not fail at its declared assertion, pinned by \`<row>\` "<assertion>"; its first failure is <JSON string, or no assertion> — nothing recorded`. Ready's refusal: `<id>: brief.admission: <spec> <problem>` per problem, exit 1, the record unchanged.

Limits, stated:

- Unchanged code the promises lean on is a stated limit, not a guarantee (D-076 E): W-381's `provesPin` and `diagnosticProves` (moved to no new reader, called as they are), W-322's `PIN`, W-140's `behaviourItems`, W-443's `redCommand`, W-166's `redOrderOptIn` read of the record and brief and its `pastReady` test in ready, `runCapture`'s stdout-and-stderr capture, and `performReds`' one call of `runRed`, which this opus does not exercise by a row of its own.
- Replays are not compared again: certify's host runner and the pr rung keep `classifyReplay`. They re-run a log the red verb wrote, on the same commit with the same words, so a red that matched when recorded is replayed; a test that fails differently from run to run is not caught there.
- The pin form reads Node's TAP reporter only (the default when output is piped, and `--test-reporter=tap`); a red under the spec reporter, under Playwright or under another runner cannot declare an assertion the verb accepts.
- An assertion text holding a double quote cannot be pinned (`PIN`); such a red is declared by a shorter opening of its message.
- A message whose detail after `: ` is empty prints as an `error: |-` block whose first line, trimmed, ends at the colon, and does not match (W-381's reader, unchanged); a row's messages give a non-empty detail, as both W-473 rows do.
