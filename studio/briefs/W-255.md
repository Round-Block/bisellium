## Interfaces

`readBriefForm(briefText: string): { light: boolean } | { error: string }`, exported from `brief-admission.ts`, shaped like `readRedOrder`. An attempt is a real line (`realLines`: outside fences and HTML comments) whose trimmed text matches `/^brief[\s_-]*:/i`.

- No attempt: `{ light: false }`. Two or more: error `has <n> brief form lines; one line "Brief: light" or none`. One that is not exactly `Brief: light`: error `brief form line "<line>" is not exactly "Brief: light"`.
- One exact line: `{ light: true }`, unless excluded (D-063 §4: never for security, sandbox, branch-protection or pipeline work). Excluded, error `a light brief is not for security, sandbox, branch-protection or pipeline work (D-063 §4): <signal>; use the full template`, `<signal>` the first hit of:
  - any real `Decree family:` value, trimmed and split on `-`, holding a token of `security`, `secret`, `auth`, `sandbox`, `protection`, `pipeline`, `ci`, `certify` (signal `decree family "<slug>" names "<token>"`);
  - a backticked span on a real line of `## Files owned` (to the next real `^## `), a leading `./` dropped, under `.github/`, `.claude/` or `packages/pipeline/`, or equal to `package.json`, `scripts/agent-workspace.sh`, `scripts/ci-certify.mjs`, `scripts/ci-scope.mjs`, `scripts/run-builder-host.mjs`, `scripts/git-broker.mjs`, `scripts/git-cell-client.mjs`, `scripts/host-cells.mjs`, `packages/commands/src/ci.ts`, `packages/commands/src/verify.ts`, `packages/commands/src/builder-run.ts`, `packages/commands/src/run.ts` or `packages/cli/src/integrate.ts` (signal ``Files owned names `<span>` ``).
  - Limit: the repository has no typed work class. The list catches the ordinary mistake of marking CI, sandbox, merge or hook work light; it cannot tell that some other file has a security or pipeline effect, and a path written without backticks is not seen. Beyond the list, the signing architect decides and the build review judges (D-045: mistakes, not adversaries).

`readBriefAdmission(briefText, limit)` keeps its two parameters and `{ problems, exception? }`. With `{ light: true }` it skips `inputDomainProblems` and `readEnumerationProblems`, and each numbered behaviour's lines (bounded as `redMarkers` bounds them) hold exactly one match of `` /(?<![^\s`])bisellium red (\S+) --behaviour ([^\s`]+)/g `` (`bisellium` opens a token: at the line start or after whitespace or a backtick, so `xbisellium red …` is not one), with the second capture exactly `<i>` (so `1a`, `1.5` and `01` are refused for behaviour 1). Else `behaviour <i> names <k> red commands; a light brief gives each behaviour one "bisellium red <opus> --behaviour <i> …"`, or `behaviour <i>'s red command is not "bisellium red <opus> --behaviour <i> …"`. Limit: the opus id in the command is not compared; `next`'s red order names the id. With `{ error }` it runs every full check and appends the error last, so problem order for unmarked briefs is unchanged and the `briefAdmissionProblems` splice is unaffected.

In `next.ts`, `lightAdmission(f: Facts): (brief: string) => string[]` is built once per `deriveNext` (and in `performSpecCommit`) and passed as one new trailing parameter of `specEvidence`, `reviewedSpec` and `signedSpec`. For a brief it returns: `readBriefLimit(f.manifest.brief_behaviour_limit)`'s error, if any; with no limit declared, `"Brief: light" needs a declared brief_behaviour_limit (W-264)`; else `briefAdmissionProblems(f.studioAbs, f.manifest, f.id, brief, limit)` (the declared limit, so the exception decision is read through `patronDecisionProblem`), then `readRedOrder`'s error or `declares no red order; add the line "Red order: one at a time"`.

`specSectionsProblem(brief: string | undefined, rel: string, admit: (brief: string) => string[]): string | undefined`: undefined brief, today's message; `readBriefForm` error, `<rel> <error>`; light, `<rel> lacks the four light-brief sections` unless Intent, Files owned, Behaviours to test and Acceptance match today's heading regex, then `<rel> <admit(brief) joined by "; ">` if any; full, today's six-section check and message. `reviewedSpec` returns it with gate `signature`, `signedSpec` as its `why`: both order the architect. `readSpecSignature`, `readSpecReview`, the blob pin and the reviewer's dispatch text are unchanged.

`spec-review.md` (a) gains: "A brief marked `Brief: light` has no Input domain section by design; its absence is not a finding: judge only whether a reader the opus adds or changes accepts out-of-domain input without refusing."

### Input domain

A rejection fails closed: admission reports a problem (`ready` exits 1 writing nothing, check blocks, `specOrder` orders the architect), or `next`'s signature gate orders the architect; an invalid or excluded marker is never read as light.

| Record | Valid domain | Rejected by |
|---|---|---|
| A brief's form | no real `brief:` line (full); or one real line exactly `Brief: light`, no excluded family token or Files owned path (light) | `readBriefForm` (new): a duplicate, a variant under the prefix, or an excluded signal is an error |
| A light brief at `ready`, check and next's review gate, limit declared | one Decree family; at least one behaviour and at most the limit, or more with one `Behaviour limit exception:` line naming a decision by the design magister that names the opus; each behaviour with one genuine red and one red command whose `--behaviour` token is its ordinal; valid promise lines; at `ready`, the Red order line (`readRedOrder`, unchanged) | `briefAdmissionProblems`: `readBriefAdmission`, then `patronDecisionProblem` for the exception; an error form runs every full check, then the error |
| The brief at next's signature gates (trunk, `spec/<id>` or working tree) | full: the six headings; light: the four, a declared limit, the row above and the Red order line | `specSectionsProblem` (new) |
