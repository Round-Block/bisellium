## Intent

A red is evidence only if certify can replay it. Certify replays each recorded red in a bubblewrap cell whose HOME is a new empty directory and whose /tmp is a new writable one, and accepts it only when `classifyReplay` reads the output as an assertion-level failure. Today `red` runs the command once, on the host, with the host's HOME and TMPDIR, and records whatever fails; so a red that fails by assertion only because the host's HOME holds a file (W-562's red 3) records here and fails certify at merge. And the classifier names ENOENT as an environment failure but not a read-only mount's throw, so an EROFS red is accepted as an assertion red. This opus closes both.

1. **POISON gains a read-only mount (behaviour 1).** `classifyReplay`'s environment list (`POISON` in `scripts/replay-accept.mjs`) gains `EROFS` and `read-only file system` (case-insensitive, as the rest), so an output naming either outside the one failing assertion block is refused as an environment failure; the one failing `ERR_ASSERTION` block's own text stays exempt, as an ENOENT inside it is today. The certify runner, the pr rung's rewrite replay and `red` (behaviour 2) all read this one classifier.
2. **`red` runs the command again in certify's empty-HOME cell (behaviour 2).** For a brief that declares "Red order: one at a time" (every brief `ready` admits since W-166), after the host run fails and before the tree check, claim or any write, `red` runs the same command in the same directory once more with an environment holding only PATH (the host's), HOME (a new empty directory), TMPDIR (a new empty, writable directory), CI=1, LANG and LC_ALL C.UTF-8, TZ UTC and, when the host has a playwright browser cache, PLAYWRIGHT_BROWSERS_PATH naming it (certify's own `browserCache`); both directories are made under the host's temporary directory (its `TMPDIR`), and `runRed` attempts their recursive removal after every cell result, before any claim or write; a failure to remove is a host-filesystem limit and may leave the cell directory (Limits). It records nothing (exit 1) when the cell cannot be opened (a missing or unwritable host TMPDIR, any throw while making it), when `classifyReplay` refuses the host run, refuses the cell run (an exit 0 included), or when the two runs' root-level failing test titles (`^not ok N - <title>`, certify's own re-attestation set) differ. Otherwise it records the host run as before, with the log's header and body unchanged. The reds perform (`next --perform --expect reds`, W-326) records each red through `runRed`, so it holds the same way.

**Every path that records or replays a red** (`importers.sh` greps every reader of `ci/reds/`, `runRed` and `classifyReplay` at the tip): (a) the `red` verb, `runRed` in `packages/commands/src/lifecycle.ts`: closed here (behaviour 2); (b) the reds perform, `performReds` in `packages/cli/src/next.ts`, which calls `runRed`: closed through it, pinned by its own row; (c) a builder's red, the same verb: closed; (d) certify's replay, `scripts/run-builder-host.mjs` (also reached by `bisellium run --sella` through `packages/commands/src/builder-run.ts`): already the cell and the classifier, and gains EROFS through behaviour 1, unchanged otherwise; (e) the pr rung's rewrite replay, `packages/cli/src/rewrite.ts`: the classifier (gains EROFS) but in place with the host's environment, a stated limit with a follow-on (Limits); (f) the architects' kept spec scripts (`~/.bisellium-evidence/*/reds.sh`, `red-accept.mjs`): already `env -i` with an empty HOME and stricter text checks, outside the product, a stated limit. The rest read a recorded log and run nothing. Three of them judge whether a recorded log is a red without `classifyReplay`, each a stated limit (Limits): `usableRed` (`next.ts`, exit, tree and module-load only), `opus.red_evidence` (`rules/evidence.ts`, exit and module-load only) and W-096's `isW096AssertionRed` (`rules/evidence.ts`, its own invalid-output list, which lacks EROFS and read-only file system). The others only parse: `rules/ladder-ticket.ts`, `retro.ts`, `scripts/red-claims.mjs`, `prototype-replay.ts` (the series only); `scripts/w044-mutation-check.mjs` is mutation evidence, never a red.

**The cell from this session's sandbox.** bubblewrap runs inside the Claude Code sandbox here (`bwrap.out`: `--unshare-all`, a read-only root, HOME and /tmp bound fresh and writable), but `red` does not use it: certify's mounts are built by its runner from a fresh clone (`copyModules`, `etcFor`, `systemMounts`, `sandboxArgs`, all private to `scripts/run-builder-host.mjs`), and reusing them means a certify host-runner change, which would be split out and land first (W-323's pattern). The design is the brief's stated fallback, an environment cell (`env -i`-like), whose limit is stated (Limits).

### Input domain

**The rule (the record's text): red (and the prototype replay) runs the red's command in certify's cell (empty HOME, writable TMPDIR) and refuses to record one that classifyReplay rejects or whose result differs from the host run; POISON gains EROFS / 'read-only file system'.** "Rejects" is read for both runs: the recorded log is the host's, so it must itself be a red certify accepts. "Result differs" is read as the set of root-level failing test titles, certify's own re-attestation set. A rejection fails closed: nothing is recorded, no ticket is claimed, exit 1.
