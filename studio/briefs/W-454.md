## Intent

W-340 fixed the UI build review's screenshots to eight names: Inbox, Board, Seats and Officina at 1280×900, then at 390×900 (`UI_REVIEW_SHOTS` in `scripts/review-packet.mjs`). The packet refuses any other set (`UI review screenshots must be exactly …; unexpected …`) and its prompts say "eight". W-350's baseline list (`BASELINE_FILES` in `apps/web/tests-serve/baseline-set.ts`) is the same eight by hand. The served walk and the baseline spec already enumerate the console's navigation table (`NAV_ENTRIES`, `apps/web/src/lib/nav.ts`, W-110), so W-451, which adds Home to that table, serves `home-1280.png` and `home-390.png` and its build review packet is refused (`w451-set.out`: its branch table names exactly its ten served shots).

After this opus the table is the one list of served screens for both:

1. The review packet reads `NAV_ENTRIES` from the work tree that holds the packet's studio, the tree whose served gate wrote the shots (the opus worktree for the perform and for next's hand-run order), as text, never run, and admits exactly its routes at 1280, then at 390, in rail order. `ui.txt` and the later-round prompt name the count attached instead of "eight".
2. Each screen keeps a stated judgment by route and viewport (W-340's four, and Home's); a screen with none gets a stated default that says it is the default. The default, not a refusal: a refusal would make every new screen a second edit in this script before its own review could run, the failure this opus removes; the reviewer still inspects every image and is told which text is the default (Defaults 1).
3. The count no longer bounds the attached bytes, so the packet refuses more than 32 MiB in all (W-340's eight 4 MiB shots, its stated total).
4. The baseline list is derived: every route at 1280 and 390, then `rendering-environment.json`.

Threat model: mistakes, not adversaries (D-045). The table is the opus branch's own subject under review, read as data.

Bootstrap: this opus is `kind: feature`, so its own build review attaches no image and runs master's packet code; the prompt text it edits governs from the next opus (W-314). It lands before W-451's review: W-451's perform then runs this code from the main checkout over W-451's worktree, whose table names its ten shots.

## Interfaces

**`navRoutes(tree)`** (`review-packet.mjs`, not exported): reads `<tree>/apps/web/src/lib/nav.ts` by `readContainedRegularFile(tree, NAV_REL, "apps", 65536)`; finds the lines between `export const NAV_ENTRIES = [` and the first `] as const;` that starts a line; each nonblank line must be exactly `  { route: "<r>", href: "#/<r>", label: "<label>" },` with `<r>` matching `[a-z][a-z0-9-]{0,16}` (so `<r>-1280.png` fits the shot-name grammar's 22 characters) and `<label>` free of `"` and `\`. It returns the routes in table order. Refusals: `apps/web/src/lib/nav.ts: <read error>`, `apps/web/src/lib/nav.ts: no NAV_ENTRIES table`, `apps/web/src/lib/nav.ts: NAV_ENTRIES line "<line>" is not a { route, href, label } entry`, `apps/web/src/lib/nav.ts: NAV_ENTRIES repeats the route <r>`, `apps/web/src/lib/nav.ts: NAV_ENTRIES has no entry`.

**`uiFact(studio, opus)`**: for `kind: ui` only (the kind checks are unchanged), `tree` is `git rev-parse --show-toplevel` run in `studio` (`runGit`), and the order is every route at 1280 (`desktop`), then every route at 390 (`phone`). The served set must equal it: `UI review screenshots must be exactly <names> (apps/web/src/lib/nav.ts's routes at 1280 and 390); missing <…>; unexpected <…>`. Each shot keeps W-340's 1280x900 or 390x900 check. Their bytes summed over `UI_REVIEW_TOTAL_BYTES` (33554432) refuse `UI review screenshots total <n> bytes, over the 33554432 one review attaches`. `ui.txt` opens `Attached UI screenshots in codex -i order (<count> files, each at most 4194304 bytes):`, then one line per shot, `<k>. <name> — <viewport> <width>x900 — judge <judgment>.`, where `<judgment>` is `UI_REVIEW_JUDGMENTS[route][viewport]` when the route is an own key (`Object.hasOwn`), else `UI_REVIEW_DEFAULT[viewport]`, which begins `the default for a screen with no stated judgment:`.

Promise nav-set: a `kind: ui` build packet, performed or hand-run, attaches exactly the routes of the navigation table in the work tree holding its studio, at 1280 then 390, in table order, and refuses any other served set before the packet exists — limit: the table is read as text in the one-entry-per-line form prettier writes today; a valid TypeScript table in any other form refuses rather than guessing, and the working copy is read as it stands, not a commit.

Promise judgment: every attached shot names a judgment; a route with stated text gets it, any other route the stated default, which says it is the default — limit: the default is generic, so a new screen's specific judgment is a later edit of `UI_REVIEW_JUDGMENTS`, not a refusal.

Promise bounded: the attached set is at most 32 MiB in all, each shot at most 4 MiB (unchanged), at most 64 shots (the manifest's unchanged cap), refused before the packet exists — limit: `codex exec --help` (codex-cli 0.153.4) states no count or size limit for `-i`; the vendor's request limits are not read by code, and 32 MiB is W-340's measured-safe total, not a probed maximum.

Limits, stated:
