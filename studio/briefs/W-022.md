# W-022 — evidence content rules: assertion-level reds enforced (P-005)

## Intent

P-005 (4th recurrence of the evidence-backfilled-or-absent class): red
logs that are module-load failures rather than assertion failures, and
duplicate reds (identical bodies reused across behaviours) both need to
be caught mechanically.

## Files owned

- `packages/cli/src/rules/evidence.ts` — `isDuplicateRed`, `isModuleLoadFailure`, wired into `checkRedEvidence`
- `packages/cli/src/rules/evidence.test.ts` — pure function tests

## Interfaces

- `opus.red_content` check rule (block for duplicates, advise for module-load)
- `isDuplicateRed(a: string, b: string): boolean` — true when bodies match after header strip
- `isModuleLoadFailure(text: string): boolean` — true for ERR_MODULE_NOT_FOUND or missing-export SyntaxError

## Behaviours to test

1. Identical bodies after header strip are duplicates
2. Different bodies are not duplicates
3. ERR_MODULE_NOT_FOUND is a module load failure
4. Import SyntaxError (missing export) is a module load failure
5. Real assertion failure is not a module load failure
6. Empty body is not a module load failure

## Acceptance

`bisellium check` blocks duplicate reds and advises on module-load reds.
The engineering lex's assertion-level clause is enforced mechanically.

- Lex wording update (P-005 part 3 — already applied manually)
