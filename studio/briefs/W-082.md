## The gap: agent-verdict transcripts have no writer at all

W-062 took four revisions and W-072 five, driven by red-team rounds whose
transcripts live in the orchestrator's `$TMPDIR` scratchpad and are gone when
the session ends. The classes those rounds found — `hand-edit×absent-verb`,
`spec×written-after-the-build`, the spec-revision residue — never reach
`lesson.recurrent` (`rules/process.ts:277`), which reads `lessons/`, and never
reach a lesson at all, because `retro --from` refuses a finding whose evidence
is not under the officina:

```
retro: finding class "…" evidence "…" not found under the officina (dead link)
                                              — packages/cli/src/retro.ts:355
```

That refusal is correct. The transcript is the thing in the wrong place.

**But the gap is wider than the spec phase.** Only two things write
`studio/ci/`: `verify` (gate logs, `verify.ts:219`) and `red`
(`ci/reds/<opus>/`, `lifecycle.ts:485`). **No repository command records a
review verdict** — grep finds no producer for `ci/<opus>-review-<n>.log`, and
there are **78** such logs among `studio/ci`'s 443 top-level files (442 logs;
701 files and 700 logs recursively — measured, and revision 1's "444" was
wrong).

Revision 1 also claimed every one of them "was written by hand". That does not
follow from the absence of a producer *today* (land 12), and I cannot prove it
for 78 files. The defensible claim is the one that matters: **nothing in this
repository can write a review verdict, so every such log arrived out of band**,
against CLAUDE.md's own "Never by hand: … `ci/*.log`". The rule had no
enforcement and the practice predates the rule's own list.

So the mechanism is not a new evidence directory and not a new record kind.
It is **the missing writer**, covering both phases.

### `bisellium verdict`

```
usage: bisellium verdict <opus> --round <n> --sella <id> --outcome <text> [--phase spec|build] [--model <id>] [--from <path>] [--studio <dir>] [--now <iso>]
```

Modelled on `red`, which is the house shape for "capture evidence with
provenance into `ci/`". `red` wraps a command; a verdict cannot be re-run by
the CLI, so the transcript arrives as `--from <path>` (or stdin when
`--from` is absent).

**`--from` is deliberately NOT containment-checked, and that is land 1.**
Revision 1 refused any path outside the officina, which would have refused the
motivating case: the transcript starts life in the orchestrator's `$TMPDIR`
scratchpad. A `--from` path is a **read source**, not a write target, and
D-008's containment rule is about where the CLI *writes*. The write target is
computed by the verb from `<opus>` and `--phase`/`--round` and never taken
from the caller, so the traversal class D-008 exists for cannot arise here.
`--from` therefore accepts any readable file — including `$TMPDIR` — and the
verb copies its bytes in. That copy-in **is** the sanctioned path; there is no
separate staging step to define.

The verb writes:

```
<studio>/ci/<opus>-<phase>-<round>.log     phase "build" spells itself "review"
```

- **`--phase build` is the default and produces `ci/<opus>-review-<n>.log`** —
  the filename convention already in use for **77 of the 78** review logs. So
  existing `probationes.review.evidence` paths stay valid, nothing downstream
  moves, and the verb retro-fits the practice instead of replacing it. That
  compatibility is deliberate and is why `build` maps to `review`.

  **The 78th is `ci/W-024-review-r1.log`** (land 2), cited by W-024, whose
  round is `r1` and not an integer. It cannot round-trip through a
  positive-integer `--round`, and **that is accepted, not fixed**: `--round`
  stays a positive integer, because an alphanumeric round would weaken the
  grammar for every future log to accommodate one historical file. W-024's log
  keeps its name and its citation; the verb simply could not have produced it.
  Stated here so a builder does not "discover" it and invent `--round r1`.
- **`--phase spec` produces `ci/<opus>-spec-<n>.log`** — new, and the whole
  point: a path under the officina that `retro --from` accepts.

Header, mirroring `red`'s (`lifecycle.ts:615-622`) so one reader serves both:

```
# opus: W-072
# phase: spec
# round: 3
# sella: qa-lead
# model: gpt-5.6-sol
# outcome: AMEND-FIRST (5 lands / 4 held)
# at: 2026-09-25T…Z
# tree: tree:<hash>
```

`--outcome` is free text, mandatory and non-empty. It is not an enum: a
spec-phase verdict says `AMEND-FIRST`, `DISPATCH`, `5 lands / 4 held`, and
inventing a vocabulary for that now would be guessing at a shape three
rounds of practice have not settled.

**Header semantics, pinned (land 5)** — revision 1 left three things to the
implementer's imagination:

- **`# model:`** is written when `--model` is given and **omitted entirely**
  when it is not. Never `model: unknown`, never an empty value: absent means
  "not recorded", exactly as `harnessVersions` treats an absent vendor.
- **`# tree:`** reuses `red`'s own computation verbatim — `tree:<hash>` for a
  clean source tree, `dirty:<hash>` when `isDirtyOutside` reports changes
  outside the officina, and `unknown` when the repo cannot be resolved
  (`lifecycle.ts:575-603`). One spelling, one reader, no second convention.
- **Header values are single-line.** Any `\r` or `\n` in `--outcome`,
  `--sella` or `--model` is **refused**, not escaped or stripped: a header a
  caller can inject newlines into is a header a caller can forge a second
  record in. The transcript body below the header is exempt — it is bytes.

**`verdict` writes evidence; it does not write a gate.** `review` already
owns gates, and keeping the two apart means each verb has one job. For the
build phase the orchestrator runs `verdict` then `review --evidence <that
path>`. For the spec phase there is **no gate** — a red-team round is
evidence, not a probatio, and the `spec` gate stays `ready --spec`'s. That
choice is what keeps this arm from growing into "`review --gate spec`" and a
second signature path.

Refusals, each before any write, exit 2: unknown opus; `--round` absent or
not a positive integer; `--phase` outside `spec|build`; `--outcome` absent or
blank; `--from` absent with empty stdin; `--from` naming a path that does not
exist or escapes the officina (D-008, the shared helper); `--sella` blank
(W-039's reasoning: a verdict is permanent evidence); and D-021's ownership
refusal, placed immediately after the record-existence check like its five
siblings. **An existing log at the target path is refused, not overwritten** —
a verdict is evidence, and round 3 must not be able to erase round 2.

## Behaviours to test

All fixtures under `$TMPDIR`. Tests in `packages/cli/src/verdict.test.ts`,
registered in `package.json`'s chain.

1. **`verdict` writes the log with its provenance header.** `--phase spec
   --round 3 --from <file>` on a temp officina writes `ci/<opus>-spec-3.log`
   whose header carries opus, phase, round, sella, model, outcome, an ISO `at`
   and a `# tree:` line, followed by the transcript byte-for-byte. Stdin with
   no `--from` produces the same file. **`--from` reads from outside the
   officina** — point it at a file under `$TMPDIR`, the motivating case
   (land 1) — and the copy-in succeeds.
2. **Filename compatibility, and the default phase** (land 4). `--phase build
   --round 1` writes `ci/<opus>-review-1.log`, asserted against a literal,
   because the retro-fit rests on that spelling. **Omitting `--phase`
   entirely writes the same path** — revision 1 never tested the default it
   declared. And `--phase spec` writes `-spec-`, so the phases never collide.
3. **Header semantics** (land 5). Three rows: `--model` omitted leaves **no
   `# model:` line at all** (not an empty one); the `# tree:` line reads
   `tree:<hash>` on a clean tree and `dirty:<hash>` when the source tree is
   dirty, matching `red`'s spelling; and `--outcome`, `--sella` or `--model`
   containing `\r` or `\n` is **refused**, so a header cannot be forged into
   carrying a second record.
4. **`verdict` writes evidence and nothing else** (land 3). The assertion
   revision 1 asserted only in prose: after a successful `verdict`, the opus
   record is **byte-identical**, `probationes` and `state` deep-equal what
   they were, and the event log and `timeline/` are unchanged in length. An
   implementation that also signed a gate would pass every other behaviour
   here.
5. **Every refusal exits 2 and writes nothing.** One table, directory listing
   and bytes compared before and after: unknown opus; `--round` absent, `0`,
   `-1`, `abc`, `r1` (land 2 — the historical exception is refused, by
   design); `--phase build-ish`; `--outcome` absent and `"   "`; `--from`
   naming an unreadable path; `--from` absent with empty stdin; `--sella`
   blank; **an existing log at the target path**; and D-021 ownership from the
   wrong ref, asserted to fire before the round/outcome validation so a trunk
   caller learns about ownership first.
6. **A spec log is citable by `retro`.** The gap closing, end to end: write
   `ci/<opus>-spec-1.log` with `verdict`, then `draftRetro` with a finding
   whose `evidence` names it — the lesson is filed instead of throwing the
   dead-link error (`retro.ts:355`), and `lesson.recurrent` sees the class when
   a second cascade files it again. Without this verb the test cannot be
   written, which is the argument for the opus in one assertion.

Reds via `bisellium red W-082 --behaviour <n> --sella <id> --studio studio --
<cmd>`, one per behaviour, assertion-level, **no two sharing an output**
(engineering lex §2, `opus.red_evidence`). Revision 1 permitted behaviour 6 to
share behaviour 5's red and then demanded distinct reds two lines earlier
(land 13); every behaviour here reds on its own against an unexported-verb
skeleton. The skeleton is exported and returns `{ exitCode: 0 }` writing
nothing, so behaviours 1-4 and 6 fail their assertions and behaviour 5 fails on
`0 !== 2` — never a stub returning 2, which would green the refusal table while
nothing worked.

- **Retro-fitting the 78 existing review logs.** They are honest evidence in

  backfilling, which is worse.
- **An alphanumeric `--round`.** `W-024-review-r1.log` keeps its name and its
  citation (land 2). One historical file does not get to weaken the grammar.
- **A vocabulary for `--outcome`.** Free text until practice settles.
- **Atomicity and concurrent publication** (Sol's held 6). Two `verdict` calls
  racing on one path, and a partial write after a crash, are real omissions
  and neither is addressed here: the overwrite refusal makes the second
  publisher lose rather than corrupt, which is the safe direction. File it if a
  cascade ever runs two reviewers on one opus.
- **Making `verdict` run the reviewing agent.** The CLI does not spawn
  reviewers; D-014's gate is dispatched by the orchestrator.

## For Sol

Sol keeps the slot; not a UI opus.

**Revision 1's six targets are spent** — targets 1, 2, 3 and 6 became lands
2, 6, 5 and 1; target 4 became land 13; target 5 became land 14 and split the
opus. Revision 2's own surface:

1. **`--from` is now uncontained, which is the one place I loosened a guard.**
   I argue a read source is not a write target, and that the write path is
   computed from `<opus>` and never from the caller, so D-008's traversal class
   cannot arise. Attack that: find a way to make `--from` reach something it
   should not — a symlink, `/dev/stdin`, a FIFO that blocks forever, a file
   whose bytes are then copied into the officina and become "evidence" of
   something that never happened. If uncontained `--from` is wrong, the
   sanctioned copy-in needs defining and land 1 is only half-closed.
2. **The `# tree:` reuse.** I said "reuses `red`'s computation verbatim". `red`
   computes it against the repo containing the command's `cwd`
   (`lifecycle.ts:595-603`); `verdict` runs no command, so there is no `cwd` to
   derive from and the only candidate is `--studio`'s repo. That is a real
   difference I have papered over with the word "verbatim". What should a
   verdict's tree hash certify — the tree the reviewer read, which nothing here
   records?
3. **Whether the overwrite refusal survives a real second round.** Held 6 says
   refusal is right and `3b` is wrong, and I agree. But a reviewer that crashes
   mid-round now needs an operator to `rm` a log before retrying, which is
   W-072 finding 14's wedge in a new place. Is that acceptable for evidence, or
   does `verdict` want an explicit `--supersede` that appends rather than
   replaces?
4. **The narrowing itself.** Land 14 split this opus and I agreed immediately.
   Check that the half left behind is still worth its own opus: it is one verb,
   six behaviours, and its whole value is that `retro` can cite a spec round.
   If the citation rule was the part with teeth, say so — the Patron's
   priority is the recording loop, and I have assumed the loop is the valuable
   half.
