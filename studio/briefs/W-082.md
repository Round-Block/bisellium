# W-082 — spec-phase QA enters the record

Spec of record, signed by the architect, 2026-09-25. **Signed by the
architect alone.** No censor has read it.

Two arms. Arm (a) turned out to be larger than "give Sol's transcripts a
home" and arm (b) smaller than "sweep briefs for stale citations" — both
because of what measurement found, and both changes are the point.

## Arm (a): agent-verdict transcripts have no writer at all

W-062 took four revisions and W-072 five, driven by red-team rounds whose
transcripts live in the orchestrator's `$TMPDIR` scratchpad and are gone when
the session ends. The classes those rounds found — `hand-edit×absent-verb`,
`spec×written-after-the-build`, the spec-revision residue — never reach
`lesson.recurrent` (`rules/process.ts:277`), which reads `lessons/`, and never
reach a lesson at all, because `retro --from` refuses a finding whose evidence
is not under the officina:

```
retro: finding class "…" evidence "…" not found under the officina (dead link)
                                              — packages/cli/src/retro.ts:355
```

That refusal is correct. The transcript is the thing in the wrong place.

**But the gap is wider than the spec phase.** Only two things write
`studio/ci/`: `verify` (gate logs, `verify.ts:219`) and `red`
(`ci/reds/<opus>/`, `lifecycle.ts:485`). Nothing writes
`ci/<opus>-review-<n>.log` — grep finds no producer. Those 444 files include
every censor verdict this officina has ever recorded, and **every one was
written by hand**, against CLAUDE.md's own "Never by hand: … `ci/*.log`".
Nobody noticed because the rule had no enforcement and the practice predates
the rule's own list.

So the mechanism is not a new evidence directory and not a new record kind.
It is **the missing writer**, covering both phases.

### `bisellium verdict`

```
usage: bisellium verdict <opus> --round <n> --sella <id> --outcome <text> [--phase spec|build] [--model <id>] [--from <path>] [--studio <dir>] [--now <iso>]
```

Modelled on `red`, which is the house shape for "capture evidence with
provenance into `ci/`". `red` wraps a command; a verdict cannot be re-run by
the CLI, so the transcript arrives as `--from <path>` (or stdin when
`--from` is absent). The verb writes:

```
<studio>/ci/<opus>-<phase>-<round>.log     phase "build" spells itself "review"
```

- **`--phase build` is the default and produces `ci/<opus>-review-<n>.log`** —
  byte-for-byte the filename convention already in use. So every existing
  `probationes.review.evidence` path stays valid, nothing downstream moves,
  and the verb retro-fits the practice instead of replacing it. That
  compatibility is deliberate and is the reason `build` maps to `review`
  rather than to `build`.
- **`--phase spec` produces `ci/<opus>-spec-<n>.log`** — new, and the whole
  point: a path under the officina that `retro --from` accepts.

Header, mirroring `red`'s (`lifecycle.ts:615-622`) so one reader serves both:

```
# opus: W-072
# phase: spec
# round: 3
# sella: qa-lead
# model: gpt-5.6-sol
# outcome: AMEND-FIRST (5 lands / 4 held)
# at: 2026-09-25T…Z
# tree: tree:<hash>
```

`--outcome` is free text, mandatory and non-empty. It is not an enum: a
spec-phase verdict says `AMEND-FIRST`, `DISPATCH`, `5 lands / 4 held`, and
inventing a vocabulary for that now would be guessing at a shape three
rounds of practice have not settled.

**`verdict` writes evidence; it does not write a gate.** `review` already
owns gates, and keeping the two apart means each verb has one job. For the
build phase the orchestrator runs `verdict` then `review --evidence <that
path>`. For the spec phase there is **no gate** — a red-team round is
evidence, not a probatio, and the `spec` gate stays `ready --spec`'s. That
choice is what keeps this arm from growing into "`review --gate spec`" and a
second signature path.

Refusals, each before any write, exit 2: unknown opus; `--round` absent or
not a positive integer; `--phase` outside `spec|build`; `--outcome` absent or
blank; `--from` absent with empty stdin; `--from` naming a path that does not
exist or escapes the officina (D-008, the shared helper); `--sella` blank
(W-039's reasoning: a verdict is permanent evidence); and D-021's ownership
refusal, placed immediately after the record-existence check like its five
siblings. **An existing log at the target path is refused, not overwritten** —
a verdict is evidence, and round 3 must not be able to erase round 2.

## Arm (b): what a grep can and cannot see

The class is real — four instances across W-062 and W-072, and I produced and
killed **nine** of them myself in W-072 rev 5. So I tried to mechanize it, and
**measured four candidate rules against all 51 briefs before writing this
section.** Every one of them is dominated by legitimate prose:

| candidate rule | fires on | verdict |
|---|---|---|
| any `behaviour(s) N` citation above the brief's own count | 8 / 51 briefs | **rejected** — W-030 legitimately cites "W-028's behaviours 22-24"; W-062's is a quoted historical mention |
| any `W-`/`P-`/`D-`/`L-nnn` id that resolves to no file | 5 / 51 | **rejected** — briefs use fictional ids on purpose: `W-999` in refusal tables, `D-900`–`D-905`/`D-777` in examples |
| quoted section cross-references (`see "X"`) that match no heading | 4 of the 7 briefs that use them | **rejected** — three point at *other documents* (ADOPTION's "Running talk", the handoff's "Where things stand"); the fourth points at a bold lead-in, not a heading |
| a brief's own `behaviours 1-N` range vs its count | 11 / 40 | **rejected** — `behaviours 1-5` in *Files owned* legitimately means "the subset in this file", a per-file partition |

That table is the honest half of this arm, and it belongs in the brief so
nobody re-attempts those four. **A grep sees syntax, and a brief's syntax is
full of deliberate fiction**: examples, refusal tables, fenced code,
cross-document references, and quoted history of its own corrections.

### The one shape that survives

The **capitalized singular** `Behaviour N` is how a brief refers to *its own*
behaviour in prose; lowercase and plural forms are how it refers to other
files' and other opera's. Measured: **66 such citations across the corpus,
exactly one out of range** — and that one is inside double quotes in W-062's
amendment log, quoting the stale text it had already fixed.

Then I applied the rule to **this brief**, and it fired: behaviour 6 mentions
`` `Behaviour 9` `` as one of its own false-positive fixtures. So the
exclusion set needs a third member, and the final measurement is over all 53
briefs including the two written today: with fenced blocks, **inline code
spans** and double-quoted spans excluded, **65 live citations and zero out of
range** — while the rule still catches W-062's real residue as it stood.

Self-application is why the exclusion set is three and not two. A rule whose
own brief trips it is a rule that ships a false positive on day one.

So: **`brief.behaviour_citation`**, folded into the existing briefs walk, no
new file read:

```
brief cites Behaviour <n> but declares <count> behaviours
```

- **Level: block.** Justified by the measurement — near-perfect precision,
  zero current findings, and there is no legitimate reason for a brief to
  cite a behaviour it does not have. The class shipped four times under an
  advisory-free regime; an advisory would join 129 others and be read by
  nobody.
- **Excluded from the scan, all three**: fenced code blocks (reuse
  `countBehaviours`' own fence tracking, `rules/evidence.ts:112-119`),
  **inline code spans** (single backticks), and double-quoted spans. Every one
  is load-bearing rather than defensive, and each was added because it was
  measured to be the difference between zero findings and a false positive —
  the inline-code exclusion because this brief tripped its own rule without
  it.
- Register the id in `packages/cli/src/rules/ids.ts`; `rules/lex.test.ts`
  behaviour 7 re-harvests every rule id and asserts set equality, so an
  unregistered rule fails `npm test` on its own.

**What this rule does not see, stated plainly:** eight of the nine residues I
killed in W-072 rev 5 — a headline reading "never wedges" after the wedge
became deliberate, an exhaustive list that stopped being exhaustive, a For Sol
target arguing for a deleted change, a stated count of "four rows" for five
rows. Those are semantic contradictions between prose and prose. No check
finds them, and claiming otherwise would be the kind of process theatre this
officina replaces with mechanism. **The remedy for the other eight is arm
(a)**: once red-team rounds are recorded evidence, the class reaches
`lesson.recurrent`, and a recurring class gets a lesson and an opus rather
than a reviewer noticing it a fifth time.

## Behaviours to test

1. **`verdict` writes the log with its provenance header.** `--phase spec
   --round 3 --from <file>` on a temp officina writes
   `ci/<opus>-spec-3.log` whose header carries opus, phase, round, sella,
   model, outcome, an ISO `at` and a `# tree:` line, followed by the
   transcript byte-for-byte. Stdin with no `--from` produces the same file.
2. **Filename compatibility.** `--phase build --round 1` writes
   `ci/<opus>-review-1.log` — the existing convention, asserted against a
   literal, because the whole retro-fit rests on that spelling. And
   `--phase spec` writes `-spec-`, so the two phases never collide at one
   path.
3. **Every refusal exits 2 and writes nothing.** One table, bytes and
   directory listing compared before and after: unknown opus; `--round`
   absent, `0`, `-1`, `abc`; `--phase build-ish`; `--outcome` absent and
   `"   "`; `--from` missing, escaping the officina (`../../etc/passwd`),
   and empty; `--sella` blank; **an existing log at the target path**; and
   D-021 ownership from the wrong ref, asserted to fire before the
   round/outcome validation so a trunk caller learns about ownership first.
4. **A spec log is citable by `retro`.** The gap closing, end to end: write
   `ci/<opus>-spec-1.log` with `verdict`, then `draftRetro` with a finding
   whose `evidence` names it — the lesson is filed instead of throwing the
   dead-link error, and `lesson.recurrent` sees the class when a second
   cascade files it again. Without arm (a) this test cannot be written, which
   is the argument for arm (a) in one assertion.
5. **`brief.behaviour_citation` blocks an out-of-range self-citation.** A temp
   officina whose brief declares 3 behaviours and says `Behaviour 7` in prose
   → one blocking finding naming both numbers. `Behaviour 3` → none.
6. **The four measured false-positive shapes do not fire.** One block, one
   table, each row a real construct from a real brief: `W-028's behaviours
   22-24` (lowercase plural, other opus); `W-999` in a refusal table;
   `behaviours 1-5` in a Files-owned partition; `see "Running talk"`; a
   `Behaviour 9` inside a fenced block; and `"Behaviour 13"` inside double
   quotes; and an inline `` `Behaviour 9` `` mention. **Zero findings from all
   seven.** This behaviour is the precision claim of the table in arm (b),
   asserted rather than asserted-in-prose. The inline-code row exists because
   this brief tripped the rule on exactly that construct before the exclusion
   was added — so it is a regression pin, not a hypothetical.
7. **The real officina stays green, and the id is registered.**
   `checkStudio("studio")` reports no `brief.behaviour_citation` finding
   across all 53 briefs — including `W-076.md` and `W-082.md` themselves,
   measured — and `rules/lex.test.ts`'s harvest passes with the new id in
   `ids.ts`.

Reds via `bisellium red W-082 --behaviour <n> --sella <id> --studio studio --

## House constraints

TypeScript strict + `noUncheckedIndexedAccess`; ESM `.js` specifiers;
Node ≥ 25; match `packages/cli/src/check.ts`'s style, and `runRed` for the
verb's own shape. Any id or path reaching a write goes through the shared
containment helper.

## Out of scope

- **`review --gate spec`.** A red-team round is evidence, not a probatio. If
  the Patron ever wants a signed spec-QA gate, that is a lex question first.
- **Retro-fitting the 444 existing `ci/*.log` files.** They are honest
  evidence in the right place with the wrong provenance story; rewriting them
  now would be backfilling, which is worse.
- **A vocabulary for `--outcome`.** Free text until practice settles.
- **Any rule for the eight semantic residues.** Named in arm (b) as
  unreachable by a grep, remedied by arm (a)'s recording loop instead.
- **Making `verdict` run the reviewing agent.** The CLI does not spawn
  reviewers; D-014's gate is dispatched by the orchestrator.
