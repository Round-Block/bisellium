Changed from the draft (notes: `~/.bisellium-evidence/W-236-spec/census.txt`):
- **No `overrides` entry.** Measured on a scratch copy: with or without an override, `npm update source-map-js --package-lock-only` yields the same three-line lock diff (1.2.1 to 1.2.2) and a clean audit. With the override alone, `npm install --package-lock-only` reports "up to date" and keeps 1.2.1, so the override fixes nothing by itself. PostCSS's `^1.2.1` already resolves to the newest 1.x, so a fresh resolution picks 1.2.2 anyway; the audit gate is what stops a return. An override outlives its reason and forces every instance, so a later PostCSS on source-map-js 2.x would be pinned back silently. The Patron accepted no override (answer 1).
- **The `gates` audit step carries the full-path guard** (`if: steps.scope.outputs.record_only != 'true'`), like typecheck and lint, not unconditional. It runs on every pull request, every source-change merge group and every master push; it skips only on a merge group that `recordOnly` (`scripts/ci-scope.mjs:23`) accepts: every changed path under `studio/`, `docs/SESSION-HANDOFF.md`, or an `.html` page directly in `docs/design/dossier/`. None of those can change the lockfile. This keeps W-131 behaviour 6's rule (each `gates` step after the scope step carries a scope guard) without an exception.

## Intent

Decree family: security-review-every-change

Today `npm audit --audit-level=moderate` exits 1 on master, and its only finding at any level is this one high (measured in the Bash sandbox through its proxy; the same with the default cache and with `npm_config_cache`). The one finding is `source-map-js` 1.2.1 under `apps/web` → vite 8.3.0 → postcss 8.5.28 (`^1.2.1`). 1.2.2 is published. Bump the lockfile to 1.2.2, and add `npm audit --audit-level=moderate` as the first `CI_STEPS` entry so local `bisellium ci` and the `gates` job fail on any moderate, high or critical advisory (the Patron, 2026-10-13; D-044; D-042: extend the existing CI, no parallel mechanism).

A registry or network failure exits non-zero and fails the step: no retry, fallback or `continue-on-error`. Threat model: mistakes, not adversaries (D-045).

On `bisellium ci --ref`, `defaultInstallDeps` runs `npm ci --no-audit` (`packages/commands/src/ci.ts:95`). `--no-audit` only silences install's own report. The new first step then audits the scratch checkout's own `package-lock.json`, which is the ref's lock. No change is needed there.

### Input domain

Every rejection fails closed: the step fails, `bisellium ci` stops before later steps and before any certificate, and the `gates` job fails.

| Record | Valid domain | Rejected by |
|---|---|---|
| The exit of `npm run -s audit` under `bisellium ci` (npm judges the lockfile and the advisory response) | 0: no moderate, high or critical advisory, registry reached | `runStep`: returns the exit status (1 when the process cannot start or is signalled); `runCi` stops at any non-zero and returns 1 |
| The exit of the same command as a `gates` step | 0 | runner: `gates` fails the job on any non-zero exit; no `continue-on-error` (W-205-b1 behaviour 1 asserts none) |
| `steps.scope.outputs.record_only` | Exactly `"true"` skips the audit; every other value runs it (empty on a pull request and a push, `"false"`, anything else) | runner: `gates` evaluates `!= 'true'`, so only the exact string skips; `recordOnly` emits `true` only when every path is a record path and git succeeded |
| `package.json#scripts.audit` | Exactly `npm audit --audit-level=moderate` | exit: `node scripts/ci-workflow.test.mjs` exits 1 on a missing or different string |
| `CI_STEPS[0]` | Exactly `npm run -s audit` | exit: `node scripts/ci-workflow.test.mjs` exits 1 on any other first entry |
| `package-lock.json`, read by `scripts/source-map-js.test.mjs` | Parseable JSON whose `packages` has at least one key ending `node_modules/source-map-js`, each with a `version` string matching `/^\d+\.\d+\.\d+$/` and numerically 1.2.2 or above | exit: `node --test-reporter=tap scripts/source-map-js.test.mjs` exits 1 with `not ok` when the file is missing or unparseable, lists no source-map-js, lists one whose version does not match that pattern (`2.x`, `1.2.2-beta`, empty, missing), or lists one below 1.2.2 |
