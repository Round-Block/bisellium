## Intent

The Inbox cannot show honest pull-request review waits from master: the credentialed read lives in review-request (packages/cli/src/review-request.ts), and review-notice.ts leaves only a one-line, consumable notice. After this opus:

1. **The write.** The review-request verb, after its screen, notice and review request, reads the PR's review facts in one `gh api graphql` call and writes `<git common dir>/bisellium/review-requests/<number>.json` whole, by a rename over the old file, in a directory the shared containment helper makes or proves. It prints `review-snapshot: <state>`. A fact out of its domain, or a write that fails, holds (exit 1, `why:` and `run:`) and leaves the last snapshot byte for byte (fail closed).
2. **Retention.** A PR that is no longer open, no longer into master, or whose head touches no code-owned path loses its snapshot when review-request runs for it (`review-snapshot: removed`).
3. **The read.** The console server reads those files once per poll and adds the optional `reviewRequests` member to `GET /api/inbox`: every file whole, or the member absent with one diagnostic line; `[]` for an empty directory; absent when no snapshot was ever written in that clone. It never runs `gh`, follows a review URL or takes a token: the Git common directory is the one its branch-record probe already resolved, so it spawns nothing new.
4. **One shape.** `ReviewRequest`, the schema tag, the levels and `reviewRequestShape` live in `@bisellium/schema`, which both sides already import: the writer checks its own file with the reader's check before writing.
5. **The edge.** `docs/ARCHITECTURE.md` §4 draws the credentialed-writer, uncredentialed-reader edge; `docs/SERVE.md` and `docs/NEXT.md` name it.

The snapshot is written in the clone the server reads (D-250 ruling 4): the Git common directory is shared by every worktree of a clone, so review-request run from any of its checkouts and a server on any of its studios meet at one directory; another clone has its own. The external signer is not here (W-666). Threat model: mistakes, not adversaries (D-045).

## Promises

Promise snapshot-written: when review-request screens an open PR into master whose head touches a code-owned path, it writes that PR's snapshot whole, by rename, with its number, title, github.com review URL, reason, every code-owned path, its required checks only, its opening and observing instants, its head, its approval head and its state, as pinned by `W-702-b1` "the snapshot holds every fact of the PR and its required checks only" and pinned by `W-702-b1` "the snapshot is written: pending" — limit: the snapshot is as fresh as the last review-request run for that PR (its `observedAt`); the pr rung and land screen with review-notice and write no snapshot (reused, unchanged); a required check GitHub has not reported yet is not listed; the screen's paths and owners are review-notice's (`screenDiff`, reused).

Promise state-precedence: the state is `approved` when every owner the screen names is an `@login` whose latest opinion (APPROVED, CHANGES_REQUESTED or DISMISSED; a comment or a pending review is none) is APPROVED on the head, else `stale` when some owner's latest opinion is APPROVED on an earlier head (its oid the `approvalHead`), else `failed` when a required check failed, else `pending`, as pinned by `W-702-b1` "the owner's approval on an earlier head: stale" and pinned by `W-702-b1` "a team owner's approval is not read: pending" — limit: a team or e-mail owner never approves here (land's owner review reads the same way, integrate.ts `readOwnerReview`, reused); GitHub's own rule, not this state, holds the merge; the last 100 reviews and the first 100 check contexts are read, and more fails closed.

Promise fail-closed: a GraphQL reply that is not this PR, open, into master, at the screened head, with this repository's github.com URL, a string title, complete review and check pages, owner reviews with a commit and a time, known check kinds and statuses, and an opening instant in grammar, or a snapshot that cannot be written, holds with `why:` and `run: bisellium review-request <n> --repo <dir>` and leaves the last snapshot as it was, as pinned by `W-702-b1` "another host's URL" and pinned by `W-702-b1` "a symlinked snapshot directory holds" — limit: a held run keeps the older snapshot, whose `observedAt` shows its age; the notice and the review request before it have already run (W-418, reused).

Promise retention: review-request on a PR that is not open or not into master removes its snapshot before refusing as before, and on a PR whose head touches no code-owned path removes it and exits 0; an entry is unlinked, never followed, and another PR's snapshot is untouched, as pinned by `W-702-b2` "a merged PR" and pinned by `W-702-b2` "a merged PR: its snapshot is removed, another PR's is kept" — limit: a PR closed or merged with no later review-request run keeps its snapshot; no sweep runs.

Promise projection: each poll, the server reads every `<number>.json` under `<git common dir>/bisellium/review-requests/` and serves them in number order, the schema tag dropped, as `reviewRequests`; an empty directory is `[]`; no directory or no repository is no member; a dot name or any other name is not a snapshot; it writes and removes nothing, as pinned by `W-702-b3` "every snapshot by number, the schema tag dropped, dot and other names skipped" and pinned by `W-702-b3` "an empty snapshot directory: []" — limit: the projection is the last poll's (5 s by default; `--once` reads it once); the Git common directory is the branch-record probe's (`BranchRecordReader`, reused).

Promise all-or-nothing: one snapshot out of its domain, unreadable, or more than 256 files makes the whole member absent and writes one `bisellium serve: review requests {...}` line naming the status and file, as pinned by `W-702-b3` "a snapshot of another schema: no reviewRequests member, one diagnostic" and pinned by `W-702-b3` "more than 256 snapshots: absent" — limit: the line is written when the status changes, not every poll; one bad file hides every good one by design (W-667: absent renders the absence text).

## Defaults for the Patron

1. Recommend leaving the pr rung as it is in this opus: a PR the ladder opens shows in the Inbox once review-request has run for it, and leaves it when review-request runs after it closes. A small follow-up can have the pr and cleanup rungs write and remove the same snapshot; it changes several existing ladder test rows, so it is not folded in here.
2. Recommend "no snapshot directory" meaning "not available yet", not "nothing waits": the Inbox then shows its absence sentence in a clone where review-request never ran, instead of an empty list that could hide a waiting PR.
3. Recommend one bad file hiding the whole list, with one server log line naming the file, so the Inbox never shows a partial list as if it were complete.
4. Recommend "approved" meaning what land already reads as approved: every named owner's own approval on the current push. A team owner therefore never shows approved here; GitHub's rule still decides the merge.
