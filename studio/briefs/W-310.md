## Intent

Five rules are prose today and broke in practice. D-066 A and D-078 keep every ladder record write in the orchestrator's main thread until a hook makes the ladder-runner the only writer (W-267 part 2, then W-292's Out of scope, now this opus); the Patron ruled on 2026-10-22 that recording a build review is one of them. W-290 (D-068 A, high): the orchestrator writes source and tests by hand, and the Patron widened it on 2026-10-22: decisions and the session handoff are written only by a dispatched clerk. On 2026-10-20 two background watch loops ran on for nothing, and a dispatched agent whose report was in stayed alive while its own background work ran. D-076 E's architect line has been stated in every dispatch by hand.

After this opus one program, `bisellium hook-event guard`, runs for Claude Code's PreToolUse hook on Bash, Write, Edit and NotebookEdit and for its SubagentStop hook. It refuses (exit 2, one stderr line Claude Code shows the model):

- from the main thread, a Bash call that runs the CLI's branch, ready, done, merge or review verb, a verdict at any phase but handoff (a spec signature, a spec review or a build review), or `next --perform` on one of those rungs, with the rung unnamed or with `--chain`, directly or inside a script file the command runs: a dispatched ladder-runner runs them (a subagent's call runs);
- in any thread, a `run_in_background` Bash call whose `while`/`until` loop has no hard bound;
- in a git checkout, the main thread's Write, Edit or NotebookEdit outside `studio/` and `docs/` (source, tests, scripts, config), and anyone's write to `studio/decisions/` or `docs/SESSION-HANDOFF.md` but a dispatched clerk's (the session's shell writes are not judged here; the sandbox deny on the clone's source is W-362's);
- at SubagentStop, once, an agent whose own shell or monitor task still runs: it is sent back to stop it with TaskStop, then finishes.

**Where the code lives and how it is installed (CLAUDE.md: hooks run unsandboxed; never point a hook at a script in the agent clone).** The guard is CLI code (`packages/cli/src/guard.ts`) reached by the hook command `bisellium hook-event guard --studio studio`. `bisellium` on PATH is the Patron's existing install, `~/.local/bin/bisellium` linked into `~/projects/bisellium-guard`, a detached worktree of the Patron's clone outside the agent clone, which the sandbox does not let a session write. This opus adds no install mechanism: the Patron updates that worktree to master after the merge, as the handoff already directs, and it carries the guard until W-362 scripts the step (`scripts/agent-workspace.sh guard`, with its input checks). The probe is `hooks check --harness claude-code --repo <dir>`: one `guard:` line each for wired, installed outside `<dir>`, and live (it refuses a canned main-thread merge), exit 1 when any fails. The officina check blocks `hook.guard` when the repo's settings stop wiring it.

**Deny-only and fail-open** (W-267 part 2's gates; fail-closed vetoed): the guard never answers allow, and an unreadable input, an unknown event, its own throw, a timeout (2 s) or a missing install lets the call run; the probe reports a dead guard instead.

**The SubagentStop mechanism.** Claude Code 2.1.308 gives SubagentStop hooks `agent_transcript_path`, `stop_hook_active` and `background_tasks` (the session's in-flight tasks, each with an `id` and a `type` label such as `shell` or `monitor`), and documents exit 2 as "show stderr to subagent and continue having it run". The task list is the session's, not the agent's, so the guard counts a task as the agent's own when its id appears in the agent's transcript (Claude Code writes the id into the tool result that started it). A subagent stops a task with the TaskStop tool, so builder, architect and ladder-runner gain TaskStop in `tools:`.

Promise main-thread-ladder: with the guard wired and installed, a Bash call from the main thread (a hook input with no `agent_id`) is refused with exit 2 and a line naming the step and the ladder-runner when, in a recognised form (Input domain rows 3 and 16), it runs the CLI with the verb branch, ready, done, merge or review, the verb verdict at any phase but handoff (`--phase spec`, `--phase build`, or no `--phase`, build being the verb's default; the last `--phase` given counts, as in the CLI), or the verb next with `--perform` and either `--chain` (its review rung records a build verdict and a review) or `--expect` naming branch, ready, done, merge, spec or review, or no `--expect`, directly, in a `-c` script, or in a script file it runs (`scripts/record-review.sh` and `~/.bisellium-evidence/record-review.sh` among them); the same call from a subagent runs — limit: deliberate evasion is not judged (eval, an alias, a function, a command or a script path built from a variable, a command substitution inside double quotes); a handoff verdict, `next` without `--perform`, and a perform with `--expect` pr, cleanup or reds run; a spec reviewer's verdict is judged by its phase, never its sella, so it is refused as a spec verdict, as revision 2 already did; `env -S`'s split string and an option operand of `bash -O`/`+O` before a script file are not judged (W-362 closes both); a here-doc body line is read as a command, a false refusal; the chain's Codex round runs inside a ladder-runner's Bash call, under that call's own timeout.

Promise bounded-background: in any thread, a `run_in_background` Bash call holding a simple command that starts `while` or `until` outside a `timeout <N>` with N above zero is refused with exit 2 — limit: `for` loops, loops inside a script the command runs, eval and ssh are not judged; a `while read` over a pipe is refused though its input bounds it; a foreground loop is not judged (the Bash call's own timeout ends it).

Promise orchestrator-writes: in a git checkout (the nearest ancestor holding `.git/HEAD` or a `.git` file), the main thread's Write, Edit or NotebookEdit whose target, resolved against the input's `cwd` and through a symlinked parent, lies outside `studio/` and `docs/` is refused with exit 2 — limit: a path outside every checkout is not judged; a case-folding filesystem or a hard link is not resolved; shell writes are not judged (the sandbox deny on the clone's source is W-362's).

Promise clerk-writes: in a git checkout, a Write, Edit or NotebookEdit to `studio/decisions/` or `docs/SESSION-HANDOFF.md` is refused unless the input carries an `agent_id` and `agent_type` clerk — limit: CLI record writes through Bash stay with whoever runs them (W-290: they stay with the orchestrator, judged only by the ladder rule above); a clerk is identified by Claude Code's `agent_type`, a name any agent file could carry (D-045: mistakes, not adversaries).

Promise idle-agents: at SubagentStop with `stop_hook_active` not true, an agent with an in-flight `shell` or `monitor` task whose id its own transcript contains is refused with exit 2 and a line naming each task and TaskStop — limit: once per stop (the second stop runs, so an agent that does not stop its task ends with it still running); a task whose id is not in the transcript, and other task types, are not judged; whether Claude Code runs SubagentStop before a SubagentHandback report is delivered is not tested here (Defaults 5).

Promise wired: with `--repo`, the officina check blocks `hook.guard` once for each guarded tool (Bash, Write, Edit, NotebookEdit) no PreToolUse group covers with a guard hook, and once when no SubagentStop group with matcher `*` holds one, a guard hook being one of type `command`, timeout 2, running `bisellium hook-event guard --studio studio`, and once for a settings file it cannot read or parse — limit: a repo with no `.claude/settings.json` is not judged; a PreToolUse matcher is read as `*` or a `|` list of names, so any other regex reads as not covering; it judges the checked tree, not the Patron's installed settings or `settings.local.json`.

Promise probe: `hooks check --repo <dir>` prints `guard: wired` or `guard: not wired: …`, `guard: installed at <real path>`, `guard: installed inside …` or `guard: not installed`, and `guard: live` or `guard: dead …`, and exits 1 unless all three hold — limit: live means one canned main-thread merge was refused; the other rules are not probed; without `--repo` the report and exit code are today's.

Promise fail-open: the guard exits 0 and the call runs on an input it cannot read, an event it does not judge, or a throw of its own — limit: Claude Code's 2 s timeout and a missing or stale install also let the call run; the probe reports a missing install, but a stale install that refuses its one canned merge can pass because the other rules are not probed; `readJsonFromStream`, `runHookEvent`'s flag parsing and its catch are reused unchanged (D-076 E).

Threat model: mistakes, not adversaries (D-045). The guard catches an orchestrator or agent following an old habit, not one trying to evade it; deliberate evasion is the one limit left on the classifier.

### Input domain

The guard is deny-only and fail-open by design (W-267 part 2 vetoed fail-closed): an input it cannot read, an event it does not judge, or its own error lets the call run. Where it judges, a rejection fails closed: the refused call does not run (exit 2) and the line names the route to take. `hook.guard` and the probe fail closed: a settings file they cannot read blocks, and a probe that cannot show all three facts exits 1.
