## Interfaces

`inputDomainRows(briefText: string): number[]` (new, exported from `brief-admission.ts`): the 1-based line numbers of the Input domain table's rows, read as `inputDomainProblems` reads the table. The brief's real lines (fences and HTML comments blanked line for line, `realLines`); the one heading matching `^#{2,3} Input domain\s*$`; its section up to the next real `^#{1,3} ` line; the section's first run of lines starting `^ {0,3}\|`; the rows are that run's lines after its first two (the header and the delimiter). No section, two headings, or a run of fewer than three lines gives no rows; a "None:" line has no run. A second table in the section, and any `|` line after the section ends, are not rows.

`domainTable(real)` (new, internal) returns `{ starts, section, run, at }`: the heading indices, the section, its first run and the run's index; `inputDomainProblems` reads its heading indices, section and table run in place of its own lookup, so admission's problems and their order do not change.

`promiseLedgerProblems(brief, transcript, briefRel)` (W-306) gains the rows:

1. `rows = inputDomainRows(brief)`. With no promise line and no row it returns no problem, so no ledger is needed.
2. No citation line: the one problem is ``<briefRel> <why>; cite the promise ledger on one line above "## Findings": "Promise ledger: <absolute path>"``, `<why>` being `names a CLI verb in code on lines <n, …>`, `has Input domain rows on lines <n, …>`, or both joined by ` and `. With promise lines only it is W-306's text, unchanged.
3. The heading, citation count, path and file checks are W-306's, unchanged.
4. Coverage: after W-306's (promise line, verb) problems, each row `n` that no counting ledger line cites as `brief:<n>` is one problem, in row order: ``brief:<n> is an Input domain row, and no ledger line cites brief:<n> with a <file>:<line> and holds or scoped``. A counting line is W-306's: whole citation tokens (`CITATION_TOKEN`; no range, decimal or path past the number), a `<file>:<line>` whose name holds a letter and is not `brief`, and `holds` or `scoped` as a whole word (`STATUS`). A row whose line also names a verb in code is covered by the verb's counting line.

`runVerdict` is unchanged: each problem prints as `<id>: promise ledger: <problem>`, and the writer exits 2 with no log written and the ticket unclaimed, after the flag, findings-shape and body-cap refusals and before the session checks.

The form the architect writes, as this brief's ledger does: `brief:<n>, <the record>: <file>:<line> <rejecting function> — holds` (or `scoped`, naming the limit). A scoped row whose input no code reads (a reviewer reads it) cites the line where the input enters, a prompt or a script line.

The `docs/ADOPTION.md` paragraph (`prototype-src.diff`) states the rule and its limits: coverage only, it cannot tell whether the cited line fails closed, nor see a reader the table omits; a brief whose Input domain admission refuses has no rows here.

Promise rows-covered: a spec signature by the design magister is recorded only when every row `inputDomainRows` finds in the brief has a counting ledger line citing it — limit: the rows are those of the first table of the one Input domain section, so a brief that admission refuses for a missing or repeated section, or a second table, has fewer rows here, and the signed-brief admission in the next step (W-196, when `brief_behaviour_limit` is declared) is what sends it back; the line's reasoning is not read.

Promise promise-lines-unchanged: a brief with promise lines and no Input domain row gets W-306's problems and texts, byte for byte — limit: W-306's own reader (`usageVerbs`, `CITATION_TOKEN`, `STATUS`, `readDesignMagister`) is reused unchanged and is a stated limit here, not a guarantee (D-076 E); `W-306-b1` passing unedited on the prototype is the evidence.

Limits, stated:

Of nine kept ledgers checked against master's briefs, 60 of 96 rows are uncovered, mostly by ranges (`next.ts:1364-1369`), a bare `:111` or no line (`ledger-census.out`); each is a form slip the architect fixes when signing again.

### Input domain

A rejection fails closed: the verdict writer exits 2 with no log written and the step ticket unclaimed. A test row whose own read or write fails throws, which fails the row.

| Record | Valid domain | Rejected by |
|---|---|---|
| The brief `briefs/<id>.md`, as the spec branch of `runVerdict` reads it | a contained regular file; any text, decoded as UTF-8 | `readContainedRegularFile` (existing): an unreadable brief exits 2 before any check |
| The brief's Input domain table, as `inputDomainRows` reads it from that text (new reader) | any text; the rows are the first table run's lines after its header and delimiter, in the one Input domain section, outside fences and comments | `promiseLedgerProblems` (specified): each row no counting ledger line cites is one problem, exit 2; a brief with no row is not refused here, and admission refuses a missing, repeated or tableless section (existing) |
| The signature's citation line, before its one level-2 Findings heading | exactly one trimmed line starting `Promise ledger:` when the brief has a promise line or a row | `promiseLedgerProblems` (W-306, existing): none or several is one problem, exit 2 |
| The ledger file that line names, and each of its lines | an absolute or `~/` path to a regular file of at most 256 KiB; any lines, counting by whole tokens only | `promiseLedgerProblems` (W-306, existing): a bad path or file is one problem; each uncovered pair or row is one problem, exit 2 |
| The design magister, from the manifest's collegia | no design row (`architect`), or one design row whose magister is a nonblank string | `readDesignMagister` (W-306, existing): any other shape exits 2 before the ledger check |
| The `W-319-b1` row's fixture writes and reads (the brief, the ledgers, the transcripts, the log's presence) | files the row writes under its own temporary officina | `writeFileSync` and `readFileSync` throw on failure, which fails the row; `assert.ok` checks the brief rewrite took before the row relies on it |
