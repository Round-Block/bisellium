## Intent

The Patron, 2026-10-27 and 10-28: usage readings were lost two sessions in a row. Today a reading is a kept script nobody is made to run (`~/.bisellium-evidence/usage/usage-reading.sh <label>`): it reads Claude's 5-hour and week percentages from the status-line file the Patron's statusLine command writes (`~/.bisellium-evidence/usage/claude-latest.json`), and Codex's week percentage and reset from the newest Codex session log's last `rate_limits` (`~/.codex/sessions/**.jsonl`), and appends one JSON line to `~/.bisellium-evidence/usage/readings.jsonl` (41 lines today, one key set: `sources.out`). The rule to take readings and report them is prose, so a session that forgets it loses them.

This opus moves the reading into the verbs (D-042: no new mechanism; the script's sources, file and line shape are kept):

1. **A reading.** One new module, `packages/cli/src/usage-reading.ts`, reads both sources into one record, null where a source cannot be read, and prints it as one line. It also reads the session's context tokens from the same status-line file.
2. **A reading at every rung performed.** `next --perform` appends a reading labelled `<opus> <step>` to the readings file at every rung it performs, and prints its `usage:` line.
3. **The opus's cost.** The perform also prints the opus's cost so far, `cost: Claude week +A%, Codex week +B% over H h`, from the readings file; done refuses a checkpoint row naming the opus that does not carry that phrase, as W-214 refuses a done with no row.
4. **The context wind-down.** Past 300000 context tokens on a fresh status line, a dispatch order (new work) is held, telling the session to let running tasks finish and refresh the session handoff. A rung the verb performs (running work) still runs.
5. **The Codex burn.** `bisellium tick` and `next --all` print the week's Codex use, its reset and the burn per hour that uses the rest by then.

The reset Codex states is a record already: each reading line carries `codex_resets`, Codex's own `resets_at`. No hand-kept reset file is added (Defaults 3).

Threat model: mistakes, not adversaries (D-045). The sources are files the Patron's own tools write on this host; they are read, never trusted to name a path.

**The perform** (`next.ts`). After the rung's result, before the re-derivation, `rungUsage(id, step, nowMs)` takes a reading labelled `<id> <step>` with `{ opus: id, step }` at `nowMs`, the rung's end (the test clock's `--now` under the test clock), appends it with `appendReading` (`ensureRealDirectory(home, ".bisellium-evidence", "usage")`, then one JSON line to `readings.jsonl`), and returns the lines the perform prints at the end of its output, after the `next-step:` line (under `--chain`, every rung's, in order, after the last): the `usage:` line, a `usage-error: the reading was not recorded: <why>` line when the append failed, and the `cost:` line. A rung performed and a rung held once performing both take one; a report run, a refused `--expect`, a held marker and `--track` take none. Under `--chain` each rung performed takes its own.

**The cost.** `readReadings(home)` reads the readings file (16 MiB cap; absent is no readings; a line that does not parse or has no ISO `at` is skipped). `opusCost(readings, id)`: each interval between two consecutive readings in file order belongs to the opus whose rung reading closes it, so the opera's costs add up to the plans' whole use; an interval's use is the rise in each plan's week percentage, or the later value when it fell (the week reset); an interval where either end has no value for a plan adds nothing to that plan. Hours run from the opus's first reading to its last. Undefined when no reading names the opus. `costOf(home, id)` in `next.ts` leaves the opus's own done readings out, so a done held and run again asks the same phrase, and gives none when the cost read neither plan. `costPhrase(c)`: `Claude week +6%, Codex week +3% over 4.0 h` (one decimal of a point, dropped when whole; `unread` for a plan no interval read). The perform prints `cost: <phrase>`, or `cost: none (<why>)`.

**The checkpoint row.** `historyRowRefusal(repo, id, home = homedir())` (W-214's, now exported) keeps its refusal when the working tree adds no line naming the opus to `docs/design/dossier/progress-body.html`. Then, when the readings name the opus, it refuses unless an added line naming the opus holds the phrase: `the checkpoint row naming <id> carries no cost: add "<phrase>" beside its hours (W-430: its plan cost from the usage readings), then re-run`. No reading naming the opus before its done, a cost that read neither plan, or a readings file that cannot be read, asks nothing.

**The wind-down.** `CONTEXT_WIND_DOWN` is 300000 (the Patron's number, 2026-10-27). `windDown(r)`: when the status line is fresh and `context_tokens` is at least `CONTEXT_WIND_DOWN`, `context <n> tokens is past 300000: let running tasks finish, refresh the session handoff, and start no new work (W-430)`; otherwise undefined. `gateDispatch(d, f, budget, usage?)` holds a dispatch order with that why after its budget checks and before its handover check; `runNext` passes a reading taken once, at the verb's clock, and only when an order is gated. Report-mode lines, `extra: underlying` and the exit 1 are the gate's, as for its other holds.

**The burn.** `codexBurnLine(r, now)`: `codex: week 61% used, resets 2026-11-02T05:59:13Z (124.0 h left): 0.31%/h (7.5%/day) uses the rest`, the rest being 100 less the week's use; `codex: the week read at <seen> reset at <iso>; no reading since` once the reset has passed; `codex: unread (no session log holds a week rate_limits)` with no Codex week. `next --all` prints it on the real clock before `open:` and never fails on it. `runTick` prints it after the due lines on the dry-run path and the act path, from `opts.home ?? homedir()`; a paused tick prints none (only check runs, as before).
