# W-035 — improvement loop: lessons name what addresses them

## Intent

Retrospectives file lessons; lessons name recurring failure classes; then
nothing happens. `lesson.recurrent` has reported the same six classes for
weeks, three petitiones were opened about one of them, and all three read
`state: resolved` — where resolved means *answered in prose*. Nothing on
disk records what addresses a class, so nothing can tell "fixed" from
"accepted" from "forgotten".

This opus closes the loop with one optional front-matter key and no new
artefact type:

```yaml
addressed_by: "opus.red_content"   # a rule id — a check now catches it
addressed_by: "W-035"              # an opus — work is open or done
addressed_by: "D-016"              # a decision — formally accepted, unenforced
```

"Formally accepted" is a decision, and `decision.kill` already refuses a
decision without a `kill_when`, so an acceptance carries its own expiry for
free. **Ignored = key absent. Accepted = key resolves to a decision.**

Three mechanisms follow from it:

- `lesson.addressed_by` (block) fires only when the key is present and does
  not resolve. All 29 lessons on disk have no key, so day one is clean and
  there is no migration — the same landing `petitio.opus` (`check.ts:575`)
  already uses.
- `lesson.recurrent` (stays **advise**) becomes three-way: unaddressed,
  in-flight, or silent. One rule id, three messages — not a second
  `lesson.unaddressed` sibling. Two findings for one condition is how
  `lesson.recurrent` became noise in the first place.
- `draftRetro` stops filing a petitio for a class that already names what
  addresses it, and carries every recurrent class forward in a new
  `## Addressed` section. Today the loop files a petitio for *every*
  recurrent class *every* cascade — it manufactures part of the rot it
  reports (P-003 and P-005 are duplicates about one class).

Two prerequisites ride along because the main work cannot land without
them: `bulletClauses` drops continuation lines, so a wrapped `(check: x)`
marker is invisible — and the one real dangling marker in the tree,
`studio/leges/design.md:24`'s `(check: docs.arch.stale)`, is itself
wrapped. And `answer` gains `--opus`, so the Patron's reply to a petitio
can record the work it commissions instead of stating it in prose.

Neither new rule blocks a green tree on a calendar tick, and neither is
`--repo`-gated: both run under a bare `bisellium check studio`. Nothing in
this opus reads `opts.repo`.

### `packages/cli/src/rules/lex.ts` (Builder A)

`bulletClauses(body: string): string[]` — same signature, new semantics.
**A clause starts at a top-level bullet and runs until the next bullet, a
heading, or a blank line**, continuation lines folded in with a single
space. Export it for behaviours 1-2.

```ts
function bulletClauses(body: string): string[] {
  const out: string[] = [];
  let cur: string | undefined;
  for (const raw of body.split(/\r?\n/)) {
    const line = raw.trim();
    if (/^[-*]\s+\S/.test(line)) { if (cur !== undefined) out.push(cur); cur = line; continue; }
    if (cur === undefined) continue;
    if (line === "" || /^#{1,6}\s/.test(line)) { out.push(cur); cur = undefined; continue; }
    cur += ` ${line}`;
  }
  if (cur !== undefined) out.push(cur);
  return out;
}
```

Unchanged on purpose: an **indented** bullet still starts its own clause
(the line is trimmed before the bullet test), exactly as today. Do not add
nesting.

`CHECK_MARKER` stays anchored at end-of-clause. Add a capturing twin for
the id: `/\(check:\s*([^)]+)\)\s*$/`, trim the capture. One marker per
clause — the trailing one.

`lex.marker_unknown` (**advise**, one finding per lex, `where:
leges/<file>`): count the clauses whose captured id is not in `RULE_IDS`;
name the distinct unknown ids, sorted, comma-joined.

```
${n} clause(s) cite a rule that does not exist: ${ids.join(", ")}
```

Advise, not block: a lex clause written before its rule lands is the
correct authoring order — `engineering.md:30` cited `opus.red_evidence`
before it existed.

### `packages/cli/src/rules/process.ts` (Builder A)

Three collections, all hoisted from loops that already walk those
directories — no new directory read:

- `decisionIds: Set<string>` — filled in the existing decisions loop (~line 121)
- `operaStates: Map<string, string | undefined>` — filled in the existing
  opera loop (~line 227), value `str(data["state"])`
- `RULE_IDS` — imported from `./ids.js`

The lessons loop (~line 163) runs *before* the opera loop, so it only
**collects**; both new behaviours are evaluated after the opera loop:

- `addressedClaims: { where: string; value: unknown }[]` — one entry for
  every lesson whose front matter has `addressed_by !== undefined`
- `claimsByClass: Map<string, string[]>` — class → the non-empty string
  values, in lesson-file order

**Move the recurrence block (today at lines 207-222) to after the opera
loop**, and put the `lesson.addressed_by` validation immediately before it.
This changes emission order inside `checkProcess`; `checkStudio` does not
sort findings, so re-run `npm test` and fix any order-sensitive assertion —
and say so in the review note if one turns up.

Resolution, with **no precedence logic to invent**:

```ts
type AddressedKind = "opus" | "rule" | "decision";
function resolveAddressedBy(v: string): AddressedKind | undefined {
  if (operaStates.has(v)) return "opus";
  if (RULE_IDS.has(v)) return "rule";
  if (decisionIds.has(v)) return "decision";
  return undefined;
}
```

**First match wins, in that fixed order.** The three id spaces are disjoint
in practice — `bisellium new` and `draftRetro` allocate `W-nnn`, `D-nnn`,
`L-nnn`, `P-nnn`, and every one of the 119 rule ids contains a `.`, which
none of those do. `ID_RE` (`check.ts:37`) does not *forbid* a dotted opus
id, so the order is fixed rather than claimed impossible. Do **not** detect
or report an ambiguity: there is no such finding, and adding one would be a
second finding for one condition.

`lesson.addressed_by` (**block**, `where:` the lesson file), exactly two
messages:

```
"addressed_by" must be a non-empty string
addressed_by "${v}" names no opus, rule id, or decision
```

The first fires when the key is present but is not a non-empty string
(number, list, mapping, `null`, `""`). The second when it is a non-empty
string that `resolveAddressedBy` returns `undefined` for.

**It validates whenever the key is present, regardless of whether the
lesson's class is recurrent.** A key that does not resolve is wrong on a
one-off class too, and a rule whose firing depends on a *different* file's
cascade numbers is untestable in isolation.

`lesson.recurrent` (**advise**, unchanged threshold: ≥2 distinct cascades
across ≥2 distinct lesson entries — that threshold has four weeks of
calibration behind it, do not invent a new one). Keep the existing prefix
byte-for-byte and append one of two suffixes, or stay silent:

| state | message |
|---|---|
| silent | *some* value in `claimsByClass.get(cls)` resolves to a rule, a decision, or an opus whose state is `done` |
| in-flight | `class "${cls}" recurs across ${n} cascades (${ids}) — addressed by ${opus} (${state}), not yet done` |
| unaddressed | `class "${cls}" recurs across ${n} cascades (${ids}) — no lesson names what addresses it` |

Evaluated in that order. `${ids}` is today's `[...entries].sort().join(", ")`,
untouched. For the in-flight message, when more than one value resolves to a
non-`done` opus, name the **lexicographically smallest** such id — an
arbitrary choice made deterministic on purpose. `${state}` is
`operaStates.get(opus) ?? "unknown"`.

A value that does **not** resolve counts as addressing nothing: it blocks
under `lesson.addressed_by`, and `lesson.recurrent` still reads "no lesson
names what addresses it". A typo must not be able to buy silence.

### `packages/cli/src/retro.ts` (Builder B)

**1. Harvest `addressed_by`.** `existingLessonsByClass` (line ~92) already
regex-harvests `class`/`id`/`cascade` from the front matter. Add a fourth:
`/^addressed_by:\s*"?([^"\n]+)"?\s*$/m`, trimmed, and widen the element
type to `{ cascade: number; id: string; addressedBy?: string }`.

**2. Skip the petitio for an addressed class** (loop at line ~369). A
recurrent class is **addressed** when any existing lesson of that class has
a non-empty `addressedBy`. Addressed → no petitio, and the proposals entry
for it is dropped (it appears under `## Addressed` instead). Unaddressed →
today's behaviour unchanged. An in-flight opus still suppresses the
petitio: re-filing a petitio for work already open is the duplication this
change exists to end.

**3. Fix the petitio numbering skip.** The fix is a deletion:

```ts
const pid = nextId(petitionesDir, "P");
```

Delete `petitioSeq` and the `baseNum + petitioSeq - 1` arithmetic. Root
cause: petitiones are written *inside* the loop (line 388), so `nextId`
already sees the previous file and the offset double-counts. Lessons are
written *after* their loop, so `lessonSeq` is correct — **leave it alone**
and leave a one-line comment at each site saying why the two differ.

**4. `## Addressed`.** A new section, **between `## Recurrence` and
`## Proposals`**, listing **every** recurrent class this cascade saw:

```
## Addressed

- "<class>" → <target> (opus, <state>)
- "<class>" → <target> (rule)
- "<class>" → <target> (decision)
- "<class>" → nothing yet
```

Rules, exactly:

- One line per class in `recurrence` order (which is `classesInOrder`,
  already sorted) — this is the periodic exception review: a class accepted
  in cascade 8 is read aloud again in 9, 10, 11.
- `<target>` is the first non-empty `addressedBy` among that class's
  existing lessons, in `existingLessonsByClass` insertion order.
- Kind is decided **by what is on disk**: `opera/<target>.md` exists →
  `opus`; else `decisions/<target>.md` exists → `decision`; else `rule`.
  `retro.ts` does not import `RULE_IDS` (see Files owned).
- `<state>` for an opus is its front matter's `state:`, read with the same
  `/^state:\s*"?([^"\n]+)"?\s*$/m` style already used in this file, or
  `unknown` if absent or unreadable.
- Unaddressed recurrent class → `- "<class>" → nothing yet`.
- No recurrent class at all → the single line
  `- (none — no class recurs across two or more cascades yet)`, matching
  `## Recurrence`'s own empty-state wording.
- A blank line after the heading and after the list, like every other
  section. Never throws, never reads outside `studioRoot`.

The section is unconditional — it is emitted even when empty, so the
retro's shape does not depend on its content. `retro.test.ts`'s
byte-identical determinism goldens (behaviour 12, line 175) will churn;
that is expected, update them.

## Out of scope

Carried from the approved plan's "Explicitly not building", plus what this
brief adds.

- **A new role or collegium.** No organisation delegates improvement
  ownership to the role that found the problem. The gap is mechanism, not
  org chart.
- **`bisellium address`** — six hand edits, ever. Add it when a cascade
  actually closes with a stamp missing because nobody could make it.
