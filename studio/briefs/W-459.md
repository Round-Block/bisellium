## Intent

The daily retro (D-076 F) is a kept Python script outside the repository (`~/.bisellium-evidence/retro-daily/retro.py`) that someone has to remember to run; it was skipped 10-25 to 10-28 and 10-30, and it reads only verdict logs, so a gate failure such as W-477's census row (`ci/W-477-tests-2b4071d9.log`, row `W-163-b6`) never reached it. This opus makes it a verb, makes its absence visible to `check`, and makes `next` refuse to start new work without it.

**The verb.** `bisellium retro --daily [--studio <dir>] [--now <iso>]` extends `retro.ts` beside `--cascade` and `--opus` (one parser, `runRetro`): it drafts the previous UTC day's section and appends it to `acta/improvements.md` under that file's last section, `## Daily retro`, as `### <YYYY-MM-DD>`. The section keeps retro.py's parts: the opera done that day (cycle minutes from the first spec round to the record's `end`, failed rounds, blockers by severity), the day's spec and review rounds with minutes since the previous round, the loops whose chain touches that day (retro.py's rule: two adjacent failed rounds sharing a class under one brief, or three failed in a row; a chain may include adjacent failed rounds from another day), and the classes seen in two or more opera over the 14 calendar days from day−13 through day, inclusive. It adds two parts: `#### Gate failures`, and `#### Owed cause fixes`.

**Its input set (decided).** The officina's own records, read from the `--studio` tree, never git or GitHub, each directory enumerated by `dailyDir`: `ci/` and `opera/` must be real directories (absent, the retro would be drafted from nothing, so the run is refused), `lessons/` absent is no lesson (every recurring class then reads as owed, the cautious side), and a symlinked, non-directory or unreadable directory is refused, all before the append: the verdict logs `ci/<id>-(spec|review)-<n>.log` (header `# at:`, `# outcome:`, `# brief:` and `<n>. blocking` lines with `[class: …]` and `[severity: …]`); the gate logs `ci/<id>-(tests|lint|types)-<tree>.log` (`<tree>` 8 to 40 lowercase hexadecimal characters) of every opus done in the window (the record's `state: done` and `end`); the opus records; and the lessons (`class`, `addressed_by`). A gate log carries no time, so a gate failure is dated by its opus's `end`: the day's table lists the failing gate logs of the opera done that day, and the recurrence counts those of the opera done in the window (the 14 calendar days from day−13 through day, inclusive).

**The class key for a gate failure (decided).** `gate×<opus>`, where `<opus>` owns the failing row: a failing log's lines that open, after leading space, with `✖ ` or `not ok <n> - ` and then a row id `W-<n>-b<k>` name those rows, and each distinct owning opus is one class (`ci/W-477-tests-2b4071d9.log` fails at `W-163-b6`, so its class is `gate×W-163`, `real-probe.out`). A failing log that names no row is `gate×tests`, `gate×lint` or `gate×types`, its gate. So a row of one opus that breaks the builds of two others is one class seen in two opera, owed until a cause fix is filed.

**Owed (decided).** A class seen in two or more opera in the window is owed unless a lesson of that class names, in `addressed_by`, an opus that is greenlit or later (any state but `backlog` and `halted`), a decision on disk or a rule id, as `classifyAddressedTarget` (`retro.ts`) classifies it. The owed lines are the qa-lead's work list (D-147): file the lesson and the cause-fix opus.

**The check rule (decided).** `retro.daily.missing`, level `advise`: an officina that keeps `acta/improvements.md` and whose `## Daily retro` section holds no `### <day>` entry for the previous UTC day of `check`'s clock gets one finding on the tracker, `no daily retro for <day>: bisellium retro --daily`. Not `block` for a missing entry, because an opus branch carries the tracker as of its base: every in-flight opus's `bisellium ci --opus` runs `check -- studio` on its own tree, so a block would fail every in-flight opus's gates at each UTC midnight, the opposite of "never an opus in flight".
