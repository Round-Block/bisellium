## Intent

`sourceTreeHash`'s callers each build their exclusions as the studio dir, `.bisellium` and `source_excludes`. That list names `examples/` and the eight dossier pages but not `docs/SESSION-HANDOFF.md`, which `recordOnly` counts as a record. So every handoff PR moves every SOURCE tree and voids every finished certificate (gap 100).

After this opus, both SOURCE-tree hashers skip every path that `recordOnly` takes as a record outside the officina: the handoff and any page directly in `docs/design/dossier/` ending `.html`. They call `recordOnly` itself, so a record path added to that list later leaves every SOURCE tree with no second edit. No caller's exclusion list changes, and `source_excludes` keeps its eight dossier entries. They are now redundant, and W-211's row still pins them. The fix is in code, not a `source_excludes` line, because `studio/bisellium.yml` is code-owned and a line there only treats the symptom (Q11). `scripts/ci-scope.mjs` is only read; neither it nor `scripts/ci-certify.mjs` is touched.

The host runner changes with the shim, in this one opus, and the reason is stated here because it is a seam. The host's `finalSourceTree` must equal the shim's tree (builder-run.ts:386), and the host maps a red log's `# tree:` claim, which the shim writes, to a commit (run-builder-host.mjs:687). If either hasher lands alone, the tooling holds two disagreeing hashers. Every certify mint then refuses, including the mint that would land the other half. So D-129 B's rule that a host-runner change is "split out and lands first" (W-323) cannot apply here. That rule exists for a PR that needs the host's new behaviour at its own certify. This PR does not need it: its certify runs master's tooling, the old pair, which agrees with itself and with reds recorded at the red commit.

Threat model: mistakes, not adversaries (D-045).
