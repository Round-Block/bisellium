## Intent

`studio/prompts/builder-brief.md` tells a builder to run `ci --opus`, the full suite, after its handoff. Since W-364 the CLI refuses `ci --opus` outside a `bisellium run` session and names "a seat that is not a builder template" to run it (`packages/cli/src/guard.ts` `sessionRefusal`), so the template is broken as written, and in practice a ladder-runner already runs the suite (W-227's and W-528's `chore(studio): <id> gates` commits). The leads' speed meet named this the first cycle-time fix: a builder runs only the test files it touches and typecheck, with one test row per boundary case the spec names; a ladder-runner runs `ci --opus` once per review round, in a run session, and commits the gate logs.

**Decided: prose alone is not enough, for two reasons, so the change has two behaviours.**

1. *`next` still orders a builder after the builder's handoff.* In `packages/cli/src/next.ts`'s build rung, gates not passed at this tree go to the producer only after a full prototype replay or a clean fix check (W-326, W-309); every other case dispatches a builder (phase 2). With the new template the builder stops at its handoff, and `next` would send the same builder back, so the orchestrator would have to step past the CLI's order. Behaviour 1 makes `next` read the builder's handoff: the branch record's traditio, recorded by the build order's own builder sella (`builder.<id>`), at or after the newest red or review log, ends the build, and the gates order is the producer's, a ladder-runner's `ci --opus` in a run session. The W-364 verb refusal already stops a builder's `ci --opus`; this makes the ladder name the step instead of leaving it to memory.
2. *The template is held by a check rule, not by prose.* The standing rule is "process enforcement is a check rule or a hook, never prose". `process.prompt_templates` (`packages/cli/src/rules/prompts.ts`, block) already holds `builder-brief.md` to its slots and self-review texts. Behaviour 2 adds `PROMPT_FORBIDS`: the template must hold none of the command forms of `ci --opus` and the full suite, so a later edit that puts the instruction back blocks `check -- studio` and the build. W-364's refusal stops the run; it does not stop a template from telling every builder to try it.

**The draft was judged, not taken.** The producer's `~/.bisellium-evidence/filings-1108/brief-lex.diff` is kept in substance, with these changes: the lex step 3 replay sentence still had "the orchestrator ... runs `ci --opus`", which W-364 refuses on the main thread, so it now says a ladder-runner, inside a `bisellium run` session; the change-log row sat between 10-31 and 11-01 and now ends the table, in date order; the builder brief keeps its light gates (typecheck, format:check, lint, both officina checks, the touched files and the Acceptance rows), since they catch in seconds what would otherwise cost a suite run; its "add one test row per boundary case" became "each boundary case the brief names has its own test row; a case with none is a stop-and-report", since the builder does not add rows outside the brief; and the texts the draft did not reach are changed too (Files owned): `build-review.md`'s "the builder's bisellium ci --opus", `.claude/agents/builder.md`'s "the full `npm test`", `.claude/agents/ladder-runner.md`, which said nothing of the gates, and `next.ts`'s W-312 comment.
