# W-076 — the inbox carries a subject and a body

Spec of record, signed by the architect, 2026-09-25. **Revision 2**, after
Sol's red-team: AMEND-FIRST, 7 lands / 2 held. Every land reproduced against
the twelve petitiones on disk before it was adopted, and two of them changed
the design rather than the prose. Sol has not reviewed revision 2.

This is a **defect fix**, and the scope is smaller than the record's title
suggests, because half of it is already built.

## Intent

`adapters/native/src/index.ts:253` derives a petitio's inbox subject as
`body.split("\n")[0]` — the first *line* of a hard-wrapped markdown body.
Every petitio in this officina is wrapped at ~70 columns, so "first line" is
a **wrap artifact, not a semantic unit**. Measured across all twelve
petitiones on disk:

| | count | examples |
|---|---|---|
| cut mid-sentence by the wrap | **6 / 12** | P-001, P-004, P-008, P-009, P-011, P-012 |
| leaking raw markdown (`#`, `**`, backticks) | **7 / 12** | P-002 `# Choose a licence`, P-012 `**A check rule…`, P-013 `**W-064's red gate…` |
| 146-152 chars long | 3 / 12 | P-003 (152), P-005 (152), P-007 (146) |
| **changed by the fix** | **12 / 12** | measured by running the derivation below over all twelve |

Two concrete rows the Patron actually saw:

```
P-009  "Proposed amendment to the QA lex (`studio/leges/qa.md`), granting the"
P-012  "**A check rule for red provenance: `bisellium red` records a working"
```

Both stop mid-sentence at the wrap column, and both carry markdown syntax.
Note what the authors were doing: P-002, P-012 and P-013 all open with a
heading or a bold summary line — **the convention of writing a subject
already exists informally in the body**, which is the argument for making it
a real field rather than inventing one.

And the body never arrives at all. `store.ts:304` maps petitiones to
`{ id, opus, from, subject }`; there is no `body`. So the web Inbox shows a
truncated markdown fragment and nothing else, and P-013 — a ruling only the
Patron could make, with five numbered options in its body — had to be
handled out of band. It bit the Patron twice.

## What is already built

The client half is **done and tested**, which is why this opus is small:

- `apps/web/src/api.ts:15` already declares
  `petitiones: { …; subject: string; body?: string }[]`.
- `apps/web/src/screens/InboxView.tsx:69-70` already renders
  `selected.body`, with a `"No content provided."` placeholder branch.
- `apps/web/test/inboxview.test.ts:42,50` already asserts "detail pane shows
  body content" — against an **injected fixture**, because no server sends
  one.

So there is **no UI decision in this opus**, and that matters twice over:
UI/UX is the Patron's call, not engineering's, and this defect needs no such
call. The server is simply failing to send a field the client has been ready
to render since it was written.

## Design

### 1. Subject: a front-matter key, with a fallback good enough to never need it

`subject:` becomes a petitio front-matter key that is **required for new
petitiones and absent from all twelve existing ones**. The derivation is a
**legacy fallback**, not a correct subject — and land 6 is why that wording
matters.

**P-004 proves the fallback can mislead, not merely truncate.** Its first
paragraph ends `It fired.` — the entire point of the petitio — and a
120-character cap drops exactly that, leaving a subject that reads as a
*proposal to build two rules* when the petitio reports that **a rule already
fired and needs a ruling**. That inverts the meaning, and it is precisely the
criterion revision 1's own For Sol target 1 named. No cleverer derivation
fixes it: the information is in the second sentence.

So the honest split is:

- **`subject:`, when present, is authoritative** and must be a **non-blank
  string**. A present-but-invalid value (blank, whitespace-only, or a
  non-string — YAML will hand you a number, a date or a list) is a
  **blocking** `petitio.subject` finding and is **not** rescued by the
  derivation: a malformed key is a defect, not a fallback trigger.
- **Absent is an advisory** `petitio.subject` finding, so the twelve legacy
  files are visible without being blocking debt.
- Both levels on one rule id, which is `petitio.opened`'s exact existing
  shape: blocking when present and unparseable (`check.ts:625`), advisory
  when absent (`:628`). No new pattern.

The derivation then serves the twelve, and is labelled in code as the legacy
path:

1. take the body's **first paragraph** (up to the first blank line), not its
   first line — this is the whole fix for the 6/12 mid-sentence cuts;
2. unwrap it: newlines to spaces, collapse runs of whitespace;
3. strip inline markdown: leading `#`s, `**`/`__`, `` ` ``, `*`/`_`
   emphasis, and `[text](url)` down to `text`;
4. cap at **120 characters total, ellipsis included** — so at most 119
   characters of text plus `…`. Cut at the last space at or before that
   boundary, never mid-word; if there is no space, cut at the boundary.

Step 3's stripping is **delimiter-aware for `_` and `*`** (land 7): strip them
only where they act as emphasis — paired, and adjacent to a non-word character
on the outside — never inside a word. `snake_case_name` and `a*b` survive
intact. No petitio on disk has an identifier underscore in its first paragraph
today (measured), so this rule has no current effect and exists so the first
one does not silently corrupt.

**No sentence splitting.** That is the one temptation worth naming: a
first-sentence rule looks obviously right and breaks on this officina's own
data, because petitio bodies are full of `studio/leges/qa.md`, `W-064's` and
`D-024's` — periods and apostrophes that no `.`-split survives. Step 4's
word-boundary cap never cuts mid-word, never needs to know what a sentence
is, and is correct for every one of the twelve.

The cap can be this crude **because the body now travels with it**. A
subject is a row label, not a summary; anything it loses, the detail pane
has. That is the dependency between the two halves, and it is why they are
one opus.

No existing file is edited. The fallback repairs all twelve on its own, and
`subject:` exists for the case where a first paragraph is a bad label. When
W-038 (`petitio` through the CLI) lands, it writes the key.

### 2. Body: verbatim, untruncated

`Petitio` gains `body: string` — the markdown body as `readFront` returns
it, byte for byte. **No truncation anywhere in the payload.** Truncating the
thing the Patron has to rule on is the defect, not the remedy; if a body is
long, that is a rendering concern and the client already owns it.

`/api/inbox` is called with at most a handful of `needs_you` petitiones, so
there is no payload argument for capping.

`api.ts`'s `body` becomes **required** (land 4). Revision 1 kept the `?` to
preserve a tested branch, which Sol correctly reads as a lie in the type: a
field the server always sends is not optional, and `?` only accommodated
stale fixtures. Two consequences, both cheap:

- `apps/web/test/api.test.ts:63` and `apps/web/test/inboxview.test.ts:56-57`
  construct petitiones rows **without** `body` (measured) and gain
  `body: ""`.
- The placeholder branch stays reachable and stays tested — it now fires on
  `body: ""` rather than on `body: undefined`, which is behaviour 4's case.
  What is asserted is **the placeholder still renders**, not that a test file
  is untouched.

### 3. Rendering: nothing. The CSS line is withdrawn.

Revision 1 added `white-space: pre-wrap` to `.inbox__detail-content` and
argued it was fidelity rather than design. Sol held the justification but
noted it is **unproved**: no behaviour observes the computed style. I checked
why — **nothing in the `npm test` web suite can** (no `getComputedStyle`
anywhere in `apps/web/test` or `apps/web/src`; those tests render HTML
strings, and the only DOM harness is Playwright under `test:e2e`, outside the
chain).

So the choice is a CSS change no behaviour can pin, or no CSS change.
**Withdrawn.** This opus becomes purely server-side, which strengthens rather
than weakens it: the "no UI decision in this opus" claim is now literally
true, and a legibility improvement that needs a rendering harness is a
separate, honestly-scoped follow-on. Without it a multi-paragraph body
renders as one run-on block — legible, unstructured, and a strict improvement
on the nothing that renders today.

**No markdown renderer** either: a new runtime dependency needing a recorded
decision (engineering lex §2) to render source the Patron can already read.

## Behaviours to test

1. **The derivation, against all twelve real petitiones, pinned output by
   output** (land 7). A table over `studio/petitiones/*.md` — the real files,
   which are the honest fixture and the measurement this brief rests on. Not
   properties alone: **pin each of the twelve expected strings exactly**, so
   an ambiguity in the cap, the ellipsis or the stripping fails the test
   instead of passing two different implementations. Properties to assert
   alongside them: non-empty, no `#`/`**`/`` ` ``/`[…](…)`, length ≤120
   including any ellipsis, never ending mid-word. The reference run of the
   derivation as specified (lengths 119, 16, 115, 119, 115, 119, 116, 119,
   120, 117, 117, 68 for P-001…P-013) is in this opus's evidence; note the
   120 for P-010 is the pre-land-7 implementation and must become 119+`…`
   under the corrected cap rule.
2. **`subject:` in front matter wins**, verbatim, including when it differs
   from what the body would derive, and including when the body is empty.
3. **The body reaches `/api/inbox` untruncated.** End to end against a **temp
   officina**, and the fixture has to be built rather than borrowed (land 2):
   `needsYou()` exposes only `state: needs_you` (`store.ts:302`), P-013 is
   `resolved`, and **P-012 is the only `needs_you` petitio on disk**. So copy
   P-013's five-option body into a temp officina with `state: needs_you`, or
   assert against P-012. A multi-paragraph, 2+ KB body arrives byte-identical
   with newlines intact. Revision 1 asserted this against the real officina,
   which was impossible.
4. **Empty bodies, and `subject:`'s two failure levels.** A petitio with an
   empty or whitespace-only body yields `body: ""` and a **non-empty**
   derived subject (fall back to the petitio id rather than an empty label),
   and the client's placeholder branch still renders on `body: ""`. Then the
   rule: `subject: ""`, `subject: "   "`, `subject: 42` and `subject: [a]`
   each produce a **blocking** `petitio.subject` finding and are **not**
   rescued by the derivation; a petitio with no `subject:` key produces an
   **advisory** one; a valid non-blank string produces neither.
5. **Nothing else in the snapshot moves.** `Petitio` gaining a field leaves
   `opera`, `acta` and the `needsYou()` opera rows deep-equal to what they
   were, and `checkStudio` reports no new finding on the real officina.

Reds via `bisellium red W-076 --behaviour <n> --sella <id> --studio studio --
<cmd>`, one per behaviour, assertion-level, no two sharing an output
(engineering lex §2, `opus.red_evidence`). Temp officinae under `$TMPDIR`
for anything that writes; behaviour 1 reads the real `studio/petitiones/`
without writing.

## House constraints

TypeScript strict + `noUncheckedIndexedAccess`; ESM `.js` specifiers;
Node ≥ 25; `packages/cli/src/check.ts`'s house style. No new dependency.

## Out of scope

- **Rendering markdown as markdown.** Needs a dependency and a decision.
  `pre-wrap` preserves the author's structure, which is enough to rule on.
- **Backfilling `subject:` into the twelve existing petitiones.** The
  fallback makes it unnecessary, and there is no CLI writer for a petitio
  until W-038.
- **Subjects for opera rows.** `needsYou().opera` carries `title`, which is
  already a real field with a real writer (`amend`, W-062). Not this defect.
- **Inbox paging or search.** Three open petitiones.

## For Sol

Sol keeps the slot; not a UI opus, so D-022's `ui-lead` exception does not
apply.

**Revision 1's four targets are spent.** Target 1 (misleading truncation)
became land 6 and changed the design — P-004 is the instance, and it inverts
meaning rather than shortening it. Target 2 (stripping against real inputs)
became land 7; the twelve outputs are now pinned. Target 3 (`body?`) became
land 4 and the `?` is gone. Target 4 (the CSS line's authority) became land 9
and the line is withdrawn. Revision 2's own surface:

1. **Whether "required for new petitiones" is enforceable at all today.**
   Nothing writes a petitio — W-038 is backlog — so the requirement rests on
   an advisory finding plus whoever hand-writes the file. That is the
   injection-by-convention this officina keeps replacing with mechanism.
   Is an advisory enough until W-038, or should `petitio.subject` block on
   absence and force the twelve to be backfilled now?
2. **The legacy fallback's blast radius, given land 6.** I have labelled the
   derivation legacy and named P-004 as a known-misleading output rather than
   trying to out-clever it. Find a second one: a petitio whose derived
   subject is not merely incomplete but says something the body contradicts.
   If there are three, "legacy fallback" is too generous and the twelve need
   real subjects.
3. **The pinned twelve as a maintenance cost.** Pinning exact strings makes
   the derivation unambiguous and makes every future petitio edit a test edit.
   Is that the right trade, or should only P-004, P-010 and P-013 be pinned
   exactly (the truncation boundary, the cap boundary, the short case) with
   the rest asserted by property?
4. **`body` required versus the wire.** Making it required in `api.ts` is a
   client-side type claim about a server this repo also owns. Nothing
   validates the actual JSON. If the server regressed to omitting `body`,
   the client would read `undefined` through a required type — is a runtime
   guard warranted, or is that the kind of defensive code the type exists to
   avoid?
