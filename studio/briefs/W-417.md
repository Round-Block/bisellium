## Intent

W-403 shipped `greenlight <opus> --auto` (`packages/commands/src/auto-greenlight.ts` on master). It greenlights, with no Patron, a D-061 §4 remainder or a D-076 D cause fix. Its spec round 4 found that the cause-fix path read a mistyped parent (`W-99`, which names no record, or a parent in state `don`) as "not a remainder", and so granted the cause fix. W-403 revision 4 cut that input out, fail-closed: a cause fix that carries any `parent:` is refused, whatever the parent, with a line naming W-417. This opus closes the finding as its replacement text says, and then lifts the cut.

What master does today, form by form, for an otherwise qualifying cause fix (`master-forms.out`, each exit 2, nothing written):

- Already refused by the screen, before either kind, with this opus's line: an empty `parent:` and one that is not a string (W-403-b2 "a parent that is not an opus id: refused"), a parent record that cannot be read, a parent with no kind or a kind outside the native kinds, and a ui parent. W-403's rows pin them on a remainder (and a ui parent on a cause fix); W-417-b1 pins each on a cause fix.
- Refused only by the cut (a cause fix) or as "neither kind" (a remainder): a parent with no record (`W-99`), a string that is not an opus id (`w-6`; `../opera/W-6`, which master reads as W-6's record), the opus itself, a parent with no state, a state outside the lifecycle (`don`) and a state that is not a string. Without the cut, master would grant each of these.

So two things are open. First, the screen must refuse every invalid form itself, before either kind is read, so that no form depends on the cut (behaviour 1). Second, once it does, a cause fix whose parent passes the screen is a cause fix, and the cut is lifted (behaviour 2).

The screen (behaviour 1), for an opus whose `parent:` is present:

- `recordForm` requires an opus id: a string `OPUS_ID` (`^W-[0-9]+$`, the officina's own id form, now exported from `opus-model.ts`) matches, and that is not the opus's own id.
- `reserved` requires the id to name a record under `opera/` that exists and reads (through W-403's `readRecord`, unchanged), whose kind is native and not ui, and whose state is one of the lifecycle's seven ids (`STATES` from `@bisellium/adapter-native`: backlog, greenlit, building, verifying, review, done, halted).

Each check refuses with one line, exit 2, and writes nothing, before `remainder` and `causeFix` run. Backlog and halted are valid states: such a parent is no remainder's (W-403's `PARENT_STATES` is unchanged), but a cause fix may carry it.

Behaviour 2 removes the cut's line from `autoGrant`. The kinds are then read as W-403 reads them, unchanged: `remainder` first, so a cause fix that is also its parent's remainder is greenlit as the remainder, and a parent spec log the records cannot judge still refuses; then `causeFix`, whose census decides. The Patron's scope (`reserved`) still refuses first.

On the real officina (`real-probe.out`, every record judged as if in backlog, with the setting given in memory), the prototype differs from master on one record: W-381 (a cause fix for `tests×ruled-case-uncovered` whose parent is W-376), refused by the cut on master, is admitted. Every one of the six parent links on the real officina passes the screen (`enumerate.out`); the sample officina has none.

Threat model: mistakes, not adversaries (D-045), as in W-403.
