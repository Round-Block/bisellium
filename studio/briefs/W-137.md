# W-137 — the retro is a required step after done, and every finding leaves with a fix

Status: **signed spec, revision 1** · architect sella (claude-opus-5-5) · 2026-10-06.
The spec gate is written by `bisellium verdict W-137 --phase spec`, not by this text.
Supersedes the 2026-10-04 backlog draft, which predates D-039.

## Intent

Decree family: retro-step

The decree: **once an opus is done, its retro is the next step, and no
other opus starts until it is filed. The retro reads the opus's recorded
verdicts. It accounts for every finding once: either as a lesson with a
named fix, or as "not a lesson" with a reason. Each lesson's severity
comes from a rule over recorded facts, and a high-severity fix is filed
already greenlit.**

D-039 is the ruling (§1–§6). D-042 merged W-043 and W-060 into this opus
and asked for no new tech debt. So this brief extends `bisellium retro`,
`next`, `check`, the lesson front matter and `addressed_by`, and adds no
parallel mechanism.

  came in at 13:24Z, filed late by hand. Nothing named the retro as owed.
- **W-043** ("addressed_by is stamped through the CLI, never by hand") was
  a TODO stub. What still applies: the retro is the verb that stamps
  `addressed_by` on every lesson it files. Re-stamping old lessons stays

- **W-060** still applies at master: `classifyAddressedTarget`

- **W-161** (L-069's fix) applies to this brief. Every record the retro

## Interfaces

```
bisellium retro --opus <id> --from <triage.json> [--studio <dir>] [--now <iso>]
```

`--opus` and `--cascade` exclude each other, and `--opus` requires
`--from`. On success the retro prints the acta path and exits 0. On any
refusal it exits 2 with one line naming the record and the reason, and it
writes nothing.

```jsonc
// triage.json: one entry per recorded finding; no other keys anywhere
{ "findings": [
  { "log": "ci/W-153-review-2.log", "n": 2, "class": "review×fail-open-on-malformed-records-patched-per-site", "fix": "W-161" },
  { "log": "ci/W-153-review-1.log", "n": 1, "class": "spec×completion-counts-failed-gates", "fix": "W-153" },          // rode with the opus
  { "log": "ci/W-153-review-3.log", "n": 1, "class": "tests×…", "fix": { "title": "…", "collegium": "engineering" } }, // filed new
  { "log": "ci/W-153-review-4.log", "n": 3, "not_a_lesson": "a repeat of review-2 #2, already counted" }
] }
```

What the retro writes, in this order, so that a crash leaves the retro owed
and never falsely filed:

1. Each object `fix` becomes a new opus through `newItem` (kind `opus`,
   state `backlog`), and its id replaces the object.
2. One lesson per distinct class, through `createNextRecord`. Front matter:
   `id`, `at`, `class`, `evidence` (the class's logs, sorted and distinct),
   `opus`, `severity` and `addressed_by` (the fix id). Body: one line per
   finding, as `<log> #<n>: <the finding's first 200 chars>`.
3. For each `high` lesson whose fix is an opus in `backlog`, and only when
   `retro.high_greenlit_by` is set: `state: greenlit`, `greenlit_by: <that
   decision>`, and a `workflow.greenlight` event with `granted`. No Patron
   timeline line, because the Patron did not act. Medium and low fixes
   stay in `backlog`.
4. Last, `acta/<YYYY-MM-DD>-retro-<id>.md` with front matter `author:
   qa-lead`, `kind: decision`, `title: "Retro <id>"`, `at` and `opus: <id>`.
   Its sections are `## Sources` (every log and red read), `## Lessons`
   (id, class, severity, fix), `## Not lessons` (`<log> #<n>: <reason>`)
   and `## Fixes started` (each greenlit fix and its decision, for the
   checkpoint).

**Severity, by rule.** Area means the text of `class` before `×`.

- `high`: the area is `security` or `data-loss`, or another lesson file of
  the same class already exists.
- `medium`: otherwise, when any finding of the class is blocking.
- `low`: otherwise.

A finding is blocking when its first word is `blocking` and its number is
not listed in the log's `# converted:` header (W-126). No model judges
severity.

**A ride-along fix** names the opus itself (`"fix": "W-153"`). It is a done
opus, so it landed before done by construction.

**`owedRetros(root)`** returns `{ owed: string[] } | { error: string }`.
An opus is owed when it is `done`, its `end` is at or after `retro.since`,
and no acta file `acta/*-retro-<id>.md` carries `opus: <id>`. When `retro`
is absent, it returns `{ owed: [] }`. This is the one reader of the setting
and of retro-filed status; `next` and both check rules call it.

**`next`.**
- `afterDone`: when the opus is owed, `next` names step `retro` (actor
  `producer`) with the command `bisellium retro --opus <id> --from
  <triage.json> --studio <dir>`. The retro step comes before
  `checkpoint`.
- Wherever `deriveNext` would name `branch`, it holds at `branch` while any
  opus is owed. The hold message is `retro owed: <ids>; file them before a
  new opus starts`.
- When `owed()` returns an error, both of the above hold and name it.

**`check`.**
- `retro.overdue` (advise), at `opera/<id>.md`: `<id> is done (<end>) and
  its retro is not filed: bisellium retro --opus <id> --from <triage.json>`.
- `lesson.unfixed` (advise), at `lessons/<id>.md`: `<id> names no fix
  (addressed_by)`.
- A malformed `retro` setting is a `manifest.shape` block at
  `bisellium.yml#retro`.

### Input domain

Each record has one valid domain and one function that rejects anything
outside it. On rejection, that function refuses the whole retro (fails
closed). It never skips the bad record.

| Record | Valid domain | Rejected by |
|---|---|---|
| verdict logs | Every file in `ci/` named `<id>-review-*` or `<id>-spec-*`. The rest of the name must be `<n>.log`, where n is a positive integer with no leading zero. The header `# opus:` must equal `<id>`. There is exactly one `## Findings` heading. Under it, either the exact line `No findings`, or numbered lines `^[1-9]\d*\. \**(blocking\|advisory)\b` (case-insensitive). Any other numbered line is out of domain. If present, `# converted:` lists finding numbers that exist in that log. | `readOpusVerdicts(root, id)` |
| reds | `ci/reds/<id>/` holds only `NN.log` files (two digits). They are listed as sources and yield no findings. | `readOpusVerdicts` |
| opus record, `retro` setting, retro acta | `retro` is absent, or a mapping with exactly the keys `since` (an ISO string or YAML date) and, optionally, `high_greenlit_by`. The latter must pass `patronDecisionProblem`. A done opus with an `end` that is present but not a date counts as owed, which fails closed. A done opus with no `end` closed before W-096 and owes no retro. | `owedRetros(root)` |
| triage | Only the shape above. `log` and `n` must name a recorded finding, and every recorded finding appears exactly once. An entry has exactly one of `class` or `not_a_lesson` (a non-empty string). `class` matches `^[a-z][a-z0-9-]*×\S+$`. Every entry of one class carries the same `fix`. A string `fix` must resolve to an opus, a `RULE_IDS` id, or a decision, as `lesson.addressed_by` resolves. An object `fix` must name a declared collegium and pass `titleProblem`. Every check runs before the first write. | `draftOpusRetro` |

The opus must be `done`, and its retro must not already be filed. Otherwise
the retro refuses.

## Defaults for the Patron to veto

Each ships as stated and can be overturned at the checkpoint.

1. **When retros start being owed.** Only tasks finished after your
   retro ruling (D-039, this morning) owe one. Today that is W-120 and
   W-153. Older finished tasks are left alone.
2. **What blocks.** A missing retro stops a new task from starting its
   build branch. Tasks already under way keep going, and specs can still
   be written.
3. **Who runs it.** The producer runs the retro step. The triage, which
   sorts each finding into a lesson or "not a lesson", is the producer's
   or a dispatched agent's call. The command only checks that nothing is
   missed.
4. **What "high" means in practice.** Security and data-loss go by the
   lesson's class name. "Seen twice" means a lesson with the same class
   already exists.
5. **Automatic go-ahead for high fixes.** It is turned on by naming D-039
   in the settings, and the retro lists the fixes it started for the
   checkpoint. Without that setting, high fixes wait in the backlog like
   the rest.
6. **Test-failure records.** Reds are read and listed, but on their own
   they produce no lessons, because they carry no review findings.
7. **Old lessons with no fix.** All 61 of them get a warning now, rather
   than only new ones. The warnings stay until someone links the fixes.
8. **Tasks with no finish time.** A finished task with no finish time is
   treated as older than the retro rule. This works because `done` has
   recorded that time since 2 October.
