# W-137 — the improvement loop is check rules: a lesson names its fix, and check warns on unfixed lessons, a stale retro and untouched backlog

Draft, backlog only (Patron, 2026-10-04). Not specified; no build is
authorised. Companion: W-085 (context carries the open lessons), greenlit
the same day.

## Intent

Problem: the improvement loop stalls, and nothing makes the stall visible.

- Lessons have no link to a fix. 22 of 52 have never been cited. Recurring
  classes such as evidence-backfilled (×4), path-traversal (×3) and
  unredacted writes (×3) show that lessons are not becoming fixes.
- The last retro was cascade 35 (2026-10-01); cascades 36–43 have none.
- About 30 backlog opera have not been touched since 2026-09-20..25.

Per the standing rule, process enforcement is a check rule, never prose.
Scope (Patron):

1. A lesson must name its fix: an opus, decision or check-rule id (for
   example a `remedy:` field). Exact name and shape to be set at spec time.
2. `check` warns on a lesson that has been open too long with no fix.
3. `check` warns when the last retro is more than K cascades old.
4. `check` warns on a backlog opus untouched for more than N days.

K, N, the open-too-long threshold and the severity (warn or advise) are set
at spec time. They are settings, not constants.

## Files owned

To be set at spec time. Starts from `packages/cli/src/rules/` and the lesson
front-matter model.

## Interfaces

To be set at spec time.

## Behaviours to test

To be set at spec time: one row per rule, each with a fixture that
triggers it and one that does not.

## Acceptance

To be set at spec time. Running against the real `studio/` reports the
existing debt; how that debt is triaged is the Patron's call.

## Out of scope

- Backfilling `remedy` on existing lessons, unless the spec rules it as a
  one-off migration script.
- Feeding lessons into boot context (W-085).
- Auto-triaging backlog (greenlight and decline stay the Patron's).
