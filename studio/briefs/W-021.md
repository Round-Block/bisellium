Seam S2 holds for both: `root` is always the **officina**, `opts.repo` is the
repo root and is present only when `check` was invoked with `--repo`, neither
function ever throws, and neither returns a finding for a directory with no

absent — never `dirname(root)`, which for `examples/sample-studio` is
`examples/`, not the repo root.

### `opus.untracked` (block)

With `opts.repo`: for every opus in `building`, `verifying` or `review`,
block when `opera/<id>.md` — or the `briefs/<id>.md` its `spec:` key points
at — is untracked in that repo. One `git ls-files --others
--exclude-standard` for the whole rule, run once with `cwd: opts.repo`, a
timeout, and **untracked-only** semantics: a file that is tracked and
modified, or tracked and staged, is not this rule's business. Compare on
repo-relative POSIX paths. No git, not a repo, git failure, timeout: return
`[]` silently — a rule that cannot observe says nothing rather than
guessing.

### `opus.red_evidence` (block, with an advisory sibling)

Activated by `existsSync(<officina>/ci/reds)`: while the store does not
exist the rule emits **nothing at all**, at either level. Once it exists, for
every opus in `building`, `verifying` or `review`:

- read the brief at the opus's `spec:` path, resolved against the officina
  root and required to resolve **inside** it;
- `N = countBehaviours(brief)` — the length of the **ordered list directly
  under the `## Behaviours to test` heading**. Items are lines matching
  `^\s{0,3}\d+\.\s`; continuation lines, nested/indented items, bullet lists,
  and anything after the next `^## ` heading do not count;
- block when `ci/reds/<id>/<NN>.log` is missing for any `NN` in `1..N`
  (`padStart(2, "0")`), naming the missing numbers in the message;
- block when a present log's `# exit:` header is `0`, or absent, or not an
  integer — a log recording a command that passed is not a red;
- when `N === 0`, **advise** (rule id `opus.red_evidence`, level `advise`):
  an active opus whose brief lists no numbered behaviours has nothing to
  prove and that is itself worth saying.

The log format is W-020's contract, declared verbatim in both briefs. You
read `# behaviour:` and `# exit:` and nothing else; you never write into
`ci/reds/` by any path but `bisellium red`.

```
# behaviour: 3
# command: npm run -s typecheck
# exit: 2
# at: 2026-09-19T13:00:00Z
# sella: builder-a
# tree: dirty:0acb03d2

<the command's combined output, verbatim>
```

### D-008, blocking — `path.id.unvalidated` and `path.escapes.officina`

D-008 is about **ids and paths that reach a write**, and `check` is hermetic:
so the detection is over officina *data*, the two studios in this repo, not a
scan of source text. Both block.

- **`path.id.unvalidated`** — every id-shaped value read out of an officina
  file that is or would be joined into a path must satisfy `check.ts`'s
  `ID_RE` and contain no `..` segment: the `id` key of every opus, petitio,
  decision and lesson; front-matter `sella` and `collegium` references; every
  key under an opus's `probationes:`; and every directory name under
  `receipts/`. Same regex object as `manifest.id.format`, imported — not a
  second copy that can drift.
- **`path.escapes.officina`** — every officina-relative path read out of a
  file must resolve inside the officina root, proven by a **resolved-path
  relation** (`relative(root, resolve(root, href))` neither absolute nor
  starting `..`), never by `startsWith`: an opus's `spec:`, every gate's
  `evidence:`, every acta `evidence[].href`, every lesson `evidence[]`. The
  existing `checkLink` asks only whether the target exists, which an
  `../../etc/passwd` satisfies; you add the containment assertion beside it
  without changing it.

Your own module must not contain a single `startsWith` used as a containment
test. That is the rule dogfooding itself.

## Behaviours to test

1. `opus.untracked` blocks for an opus in `building`, `verifying` or `review`
   whose `opera/<id>.md` is untracked in `opts.repo`, and clears once that
   file is tracked.
2. `opus.untracked` blocks when the `briefs/<id>.md` the opus's `spec:` points
   at is untracked, with the brief named in the message.
3. `opus.untracked` is silent for `backlog`, `greenlit`, `done` and `halted`
   opera, and returns `[]` when `opts.repo` is absent.
4. `opus.untracked` returns `[]` and never throws when `opts.repo` is not a
   git repository, and when `git` fails outright.
5. `opus.red_evidence` emits nothing at either level while
   `<officina>/ci/reds` does not exist, even for an active opus with a brief
   full of behaviours.
6. With the store present, `opus.red_evidence` blocks for an active opus whose
   brief lists N behaviours and whose `ci/reds/<id>/NN.log` is missing for any
   of `1..N`, names the missing numbers, and clears when all N are present.
7. `opus.red_evidence` blocks for a present log whose `# exit:` header is `0`,
   absent, or not an integer.
8. `opus.red_evidence` **advises** for an active opus whose brief parses to
   zero numbered behaviours.
9. `countBehaviours` counts only the ordered list directly under
   `## Behaviours to test`: a following `##` section's list, an indented or
   nested item, a bullet list, and a numbered line inside a fenced code block
   all leave the count unchanged.
10. `path.id.unvalidated` blocks for an id containing `/`, `\`, a `..`
    segment, and an id failing `ID_RE`, in each of: an opus `id`, a
    front-matter `sella`, a `probationes:` key, a `receipts/` directory name.
11. `path.escapes.officina` blocks for a `spec:` and for a gate `evidence:`
    that resolve outside the officina root, including the absolute-path and
    the `a/../../b` forms, and passes a path that merely *looks* like an
    escape but resolves inside (`briefs/../briefs/W-021.md`) — proving the
    relation, not a string prefix.
12. `checkStudio` over `examples/sample-studio` at
    `2026-09-19T13:00:00Z` produces **zero** findings from all four rule ids,
    and over `studio` produces no `path.*` finding at all — the insurance
    clause's measurement. Assert both, in the test, against the real trees.
