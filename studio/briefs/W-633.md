## Intent

W-512 (D-192, W-592's lane-start half) holds `branch` while an opus's Files owned overlap with an opus in flight. `laneOverlap` (`next.ts`) reads the other opus's Files owned from the brief committed on `refs/heads/opus/<x>`, but its state only from the main checkout's record (`laneRecord(f.studioAbs, …)`). Once an opus has a branch, `halt` and `lift` write that branch's record alone (D-021), so an opus halted on its branch never released its files: on 2026-11-13 W-610's halt (on its branch, D-206) still held W-630 at `branch`, and the leads deleted main's local ref `opus/W-610` to let W-630 start (overlap-gap-meet-1113, item 1).

After this opus:

1. An opus whose branch record is closed releases its files: `laneOverlap` reads the state committed on `refs/heads/opus/<x>` (`<ref>:<studio>/opera/<x>.md`, the way it reads the brief) and treats `<x>` as in flight only when both that state and the main checkout's are open (greenlit, building, verifying, review). A halt on the branch releases the files; a lift there holds them again.
2. The branch record is read fail closed: an absent or unreadable blob, or a record outside the opus record loader's domain (no front matter, not a mapping, no state, a state outside the lifecycle), holds `branch` and the why names the record, the ref and the reason.

The domain check is the record loader's own (W-558): its parser is exported as `parseOpusRecord` and `loadOpusRecord` calls it, so the main and branch reads judge one domain.

Cause fix: the overlap hold read a branch-owned fact (the state, after `branch`, D-021) from the main checkout; it now reads it where `halt` writes it.

Threat model: mistakes, not adversaries (D-045). The refs and records are the repository's own, read as they stand.

## Promises

Promise release: `next <opus>` holds `branch` on an overlap with `<x>` only while `refs/heads/opus/<x>` exists, the main checkout's `opera/<x>.md` has an open state, and the record committed on that ref has an open state; a closed state on either side releases `<x>`'s files, so an opus halted on its branch (master's record still open) no longer holds an overlapping start — limit: the state is the committed blob at the ref's tip, so a halt written in the opus worktree and not yet committed releases nothing until it is committed; the main record's own read (`laneRecord`, reused) and its rule that a ref whose main record is absent is no opus are unchanged; the lane named in the why still comes from `queue.yml`. Pinned by `W-633-b1` "halted on its branch alone (master's record still building): W-901 releases its files" and pinned by `W-633-b1` "lifted on its branch: W-901 holds its files again" and pinned by `W-633-b1` "lifted: the why names the overlap" and pinned by `W-512-b3` "once W-901 is done, the lane's opus branches".

Promise closed: a branch record that cannot be judged holds `branch`, exit 1, with `opera/<x>.md is not a readable blob on refs/heads/opus/<x>, so <x>'s Files owned cannot be checked against <id>'s (W-633)` for an absent or unreadable blob, and `opera/<x>.md on refs/heads/opus/<x> <reason>, so <x>'s Files owned cannot be checked against <id>'s (W-633)` for a record outside the loader's domain, `<reason>` being the loader's own (`has no front matter`, `front matter must be a mapping`, `has no state`, `has state "<s>", not one of …`) — limit: `git cat-file` failing for any cause reads as not a readable blob (absent and unreadable are not told apart); the branch record is read only when the main record is open, so a main record that is closed or absent never reaches it. Pinned by `W-633-b1` "a branch record outside the record domain holds (fail closed)" and pinned by `W-633-b1` "malformed: the why names the record, the ref and the reason" and pinned by `W-633-b1` "no record on the branch holds (fail closed)" and pinned by `W-633-b1` "absent: the why names the record and the ref".

Promise domain: `loadOpusRecord` keeps its behaviour: it reads and judges the main record as before, through `parseOpusRecord` — limit: the reasons' text is moved, not changed; `readInput` (`@bisellium/schema`) and `walkStudio` are reused and unchanged. Pinned by `W-558-b1` "an opus record whose state is outside the lifecycle is an error" and pinned by `W-558-b1` "an opus record in a lifecycle state is valid" and pinned by `W-558-b1` "an opus record that is a directory is an error, not absent".

Limits, stated:

- Reused, unchanged code these promises lean on: `laneRecord`, `loadOpusRecord`'s reads (`walkStudio`, `readInput`, `readContainedRegularFile`), `ownedFiles`, the `meets` span rule, `CONFLICT_OPEN_STATES`, `queueOrder`, `startOrder` and the overlap why's text. None is edited beyond Files owned, and each keeps its behaviour.
- The read enumeration (`readers.out`) finds three other readers in `next.ts` that read another opus's state from the main checkout, which a halt or lift on that opus's branch does not reach. This opus does not change them; each is a stated limit:
  - `furtherAlongBranches` (the review rung's order against an opus further along): an opus halted on its branch, pushed or with a passed review at its tip, still counts as further along, and a merge-tree conflict with it holds the review rung.
  - `queuedState`, through `queueOrder` and `aheadOf` (the start order and the meanwhile line's spec ahead): a lane whose `queue.yml` opus is halted on its branch still reads busy, so the lane takes no other entry until a lead edits the lane field or the `halted:` list.
  - `runAll`'s lane lines (`next --all`, `recordOf(fsSrc(studioAbs), …)`): the same lane reads busy with the main state.
- The halt itself: `halt` writes the record and commits nothing; until that write is committed on the branch, the overlap still holds (Promise release's limit).

### Input domain

A rejection fails closed: it holds the `branch` rung of the opus being started (`next: <id> branch held`, exit 1) and writes nothing. A test row whose own fixture write fails throws, which fails the row.

| Record | Valid domain | Rejected by |
|---|---|---|
| `opera/<x>.md` committed on `refs/heads/opus/<x>` (`<x>` an id the ref listing passed through `ID_RE`) | a readable blob whose front matter is a mapping with `state` one of the lifecycle state ids | `refRecordState` (new): a `git cat-file blob` failure (the record absent on the ref, unreadable, or of the wrong type, a tree) is `not a readable blob`; `parseOpusRecord` (moved from `loadOpusRecord`) throws its reason; `laneOverlap` holds with the why under Promise closed; pinned by `W-633-b1` "malformed: the why names the record, the ref and the reason" and pinned by `W-633-b1` "absent: the why names the record and the ref" |
| `opera/<x>.md` in the main checkout | absent (no opus), or a contained regular file in the loader's domain | `laneRecord` → `loadOpusRecord` (existing): `cannot be read (…)` holds, as today; unpinned here: reused and unchanged (a stated limit) |
| The opus branch listing (`git for-each-ref refs/heads/opus/`) | refs whose id matches `ID_RE` | `laneOverlap` (existing): an id outside the grammar holds, as today; unpinned here: reused and unchanged (a stated limit) |
| The test row's fixture writes (records, `queue.yml`, briefs, the branch commits by plumbing) | files and commits the row makes | `put`, `commit` and the row's `onBranch`, each asserting git exit 0; unpinned: the row's own fixture, which fails the row (a stated limit) |

## Interfaces

**`parseOpusRecord(text: string, rel: string): Dict`** (`inputs.ts`, exported): the body `loadOpusRecord`'s parser had, on text: returns the front matter when it is a mapping whose `state` is a lifecycle state id; else throws `has no front matter`, `front matter must be a mapping`, `has no state` or `has state <json>, not one of <ids>`. `loadOpusRecord(studio, rel, base?)` keeps its signature and result.

**`refRecordState(repo, ref, studioRel, id)`** (`next.ts`, not exported): `{ state: string } | { error: string }`. Runs `git cat-file blob <ref>:<studioRel>/opera/<id>.md`; a spawn error or non-zero exit is `{ error: "opera/<id>.md is not a readable blob on <ref>" }`; a throw of `parseOpusRecord` is `{ error: "opera/<id>.md on <ref> <reason>" }`.

**`laneOverlap(f, lanes)`** (`next.ts`): after the main record's open-state check, `refRecordState(f.repo, ref, f.studioRel, x)`; an error returns `<error>, so <x>'s Files owned cannot be checked against <id>'s (W-633)`; a state outside `CONFLICT_OPEN_STATES` skips `<x>`. The overlap why and every other refusal are unchanged.
