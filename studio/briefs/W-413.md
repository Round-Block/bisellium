## Intent

At base 685a2eea the Board already groups cards by the lifecycle phases served from `/api/officina`, shows each column's raw card count, applies the manifest's one `wip_limit` to the In progress column's membership, fills a 3px rule to that ratio, and classifies a card as blocked when any recorded gate failed. `check`, however, defines the cap numerator as its exact `WIP_STATES` set (`building` plus `verifying`), so the old Board can disagree with the repository's enforcement. It also does not say that blocked work consumes WIP; there is no dwell, entry/exit rule or work filter; and a count cannot distinguish visible cards from hidden cards. Current source evidence is `/home/edckt/agents/bisellium/.worktrees/W-413-spec/apps/web/src/lib/board.ts`, `/home/edckt/agents/bisellium/.worktrees/W-413-spec/apps/web/src/screens/BoardView.tsx`, `/home/edckt/agents/bisellium/.worktrees/W-413-spec/apps/web/src/components/w025.css` and `/home/edckt/agents/bisellium/.worktrees/W-413-spec/packages/cli/src/check.ts`.

Make each lifecycle-column header a three-content-line policy block: name with the column-local `N shown` or `N of T shown`; concise membership and exit conditions; then its policy metric with the column-local median right-aligned when meaningful. The shared WIP population is exactly Building plus Verifying. A visible Board-level key says `Shared WIP = Building + Verifying; blocked work included`, and both WIP columns repeat `Shared WIP T / cap · N blocked`, even when either column's local shown count or median differs from `T`; every other column says singular `1 item · N blocked` or plural `N items · N blocked`. The key uses the standard Building and Verifying labels; renamed WIP labels are outside this copy promise. Keep the complete key visible on the unobstructed Board at 1280, 640 and 390; suppress it when an open drawer leaves only a narrow Board rail, then restore it on close. The existing 3px rule stays neutral ink and becomes full at and over cap; non-WIP columns reserve the same geometry without implying a cap. At and over cap use numerical ratio plus weight 700, never amber, as required by DIRECTION and the Patron's 2026-10-25 ruling. Evidence for the governing text and its later Board rulings is `/home/edckt/agents/bisellium/.worktrees/W-413-spec/docs/design/DIRECTION.md`, `/home/edckt/agents/bisellium/.worktrees/W-413-spec/studio/decisions/D-115.md`, `/home/edckt/agents/bisellium/.worktrees/W-413-spec/studio/decisions/D-143.md`, `/home/edckt/agents/bisellium/.worktrees/W-413-spec/studio/decisions/D-151.md` and `/home/edckt/agents/bisellium/.worktrees/W-413-spec/studio/decisions/D-161.md`.

The manifest still has one cap. The Board applies it with check's exact runtime set, not a phase-name guess: `building` and `verifying` form the one shared WIP numerator, while each column's shown count and median remain local. Dwell uses `traditio.at` only when `traditio.stage` exactly equals the opus's current lifecycle state. Unknown, malformed, or stale-stage handoffs contribute no sample. The column median is the middle recorded dwell, or the mean of the middle pair, floored only for display (`<1h`, whole hours, whole days); an empty non-terminal sample reads `median —`. Done and Halted omit median because their last-stage time is not current work. This adds no endpoint, response field or record interpretation outside data the Board already receives. Source evidence is `/home/edckt/agents/bisellium/.worktrees/W-413-spec/apps/web/src/api.ts`, `/home/edckt/agents/bisellium/.worktrees/W-413-spec/apps/server/src/store.ts` and `/home/edckt/agents/bisellium/.worktrees/W-413-spec/packages/cli/src/check.ts`.

Rule copy states membership and the condition for leaving it, not merely neighbouring state names. The standard fixture examples are `Backlog + Greenlit; approval + readiness before building`, `Building; build complete before verification`, `Verifying; passing checks before review`, `Awaiting review; approval completes work`, `Complete; no forward exit`, and `Stopped; resume when condition is met`. Membership follows served names, with Complete/Stopped overrides for Done/Halted, while exit clauses are fixed per phase id. A custom phase uses its served state names for membership and the fallback `<served membership>; recorded condition is met`. Exit copy does not read the served transition graph; alternate transition graphs remain outside this promise. The one new control is a plain `All work` / `Blocked only` select. It defaults to All work, filters lifecycle cards only, and never changes the total, cap numerator, blocked count, dwell or Waiting-on-you collection. This is deliberately a small reversible presentation policy, not a new query or record field.
