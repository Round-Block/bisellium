## Intent

W-530 (D-188) made a missing daily retro hold new work: while the previous UTC day had no entry in `<studio>/acta/improvements.md`, `next` held every opus with no `opus/<id>` branch and no spec log at `spec`, exit 1, with no time limit. On 2026-11-12 `retro --daily` refused (no measured section), so the entry could not be written and every new spec in every lane stopped; the 11-12 entry had to be written by hand (D-205). D-204 (the Patron) ends the hold: a daily retro owed is said, never enforced.

After this opus:

1. A daily retro owed holds nothing. `next <opus>` names the step it would name with the entry filed, and the existing advisory line (`daily-retro: <day> step <k> of 3: …`, W-530 behaviour 4) says the retro is owed. Only a tracker that cannot be read still holds, and only new work at the start of its spec, as today (`dailyHold` returns that reason alone).
2. When the run itself is owed (step 1) and more than 3 days are owed, the line says so loudly: `daily-retro: <day> OVERDUE <n> days (does not hold): step 1 of 3: …`. The days owed run from the day after the tracker's newest entry through the previous UTC day of `next`'s clock (`--now` under the test clock, W-547). It still holds nothing and changes no exit code.
3. That count is right for every four-digit year the tracker reads, years 0000 to 0099 included: each day is built with `setUTCFullYear`, never `Date.UTC`, which maps years 0 to 99 onto 1900 to 1999 (the hotfix review's S3 finding 2).

The per-opus retro hold (`retroHold`, D-039: a cascade retro owed holds at `branch`) is unchanged. The switch is D-204's `kill_when`; there is no config key and no check rule, as the leads accepted (unblock-meet-1113 item 6).

Cause fix: the hold W-530 added stopped all new work whenever `retro --daily` could not write its entry; this removes it at its one call site and keeps the debt visible.

Threat model: mistakes, not adversaries (D-045). The tracker is the main checkout's, read as it stands.
