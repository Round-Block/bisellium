## Intent

A plain `bisellium greenlight <opus>` appends a line to `<studio>/timeline/patron.jsonl` saying the Patron greenlit it (`packages/commands/src/writes.ts`, `runGreenlight`, near line 1026). D-186 retires greenlighting as a Patron gate, so the producer now runs the verb at an opus's turn, and each run writes a Patron act that did not happen (the QA lead, `q3-qa-lead.md`). This opus stops that line for every greenlight the CLI runs, and keeps it for the one the Patron runs from the console. It also rewords M4's exit in `studio/milestones.yml` to drop "greenlights", since `land` does not carry that file and this PR does.

**How the actor is known today, read.** It is not, from a shell. `main.ts` sets `BISELLIUM_ROLE=patron` for `answer`, `greenlight` and `budget` whoever runs them, and `appendPatronTimeline` falls back to `"patron"` when the variable is unset. `greenlight` takes no `--sella`; the other verbs' `--sella ?? $BISELLIUM_SELLA ?? "guest"` chain is unset in the producer's sessions (W-526's own amendments read `sella: guest`), so a sella would be whatever the caller typed. `--auto` already writes no line (W-403). The one path that does know is the console: `POST /api/greenlight` needs the write-auth token `serve` prints, and runs the verb inside `asPatron` (`apps/server/src/http.ts`), which sets `BISELLIUM_ROLE=patron` for that request and restores it after.

**Decided: the line is written only under the Patron role, and the CLI clears that role for `greenlight`.** `runGreenlight` appends the line when `grant === undefined` and `process.env.BISELLIUM_ROLE === "patron"`, and nowhere else; `appendPatronTimeline`'s own default no longer reaches a greenlight. `main.ts` takes `greenlight` out of its force-patron block and deletes `BISELLIUM_ROLE` before calling it, so a shell that exports the variable writes no line either. The console path is unchanged and still writes it. A decline is the same act and gets the same rule. The event `workflow.greenlight` and the record's edit are unchanged on every path.

**Rejected: a `--sella` flag, and reading `$BISELLIUM_SELLA`.** Both make the line depend on the caller naming itself: a producer that forgets the flag writes the false line this opus is for, which is a memory, not enforcement. Clearing the role in the CLI needs nobody to remember anything. The cost is a Patron running the verb from their own terminal: that act leaves no line now (Defaults 1). An omission, not a false record.
