# W-020 — lifecycle and evidence writes: `ready`, `done`, `review`, `red`

Builder A (`builder-a`) · collegium engineering · cascade 6 · pinned clock
`2026-09-19T13:00:00Z`

> Decided by the Patron on 2026-09-19 (P-001 items 3–4, P-003) and settled
> in the twelve-decision memo of this cascade's spec phase. Where this brief
> states a shape, it is decided — not a suggestion you may improve on.

## Intent

No `bisellium` command writes an opus lifecycle transition or an agent gate
result. Two stopgap scripts do it instead — `scripts/opus-ready.ts`
(greenlit → building, spec gate) and `scripts/opus-close.ts` (review gate,
→ done) — hand-rolled, emitting no event, and `opus-close`'s "are the gates
really passed" guard is a regex over raw YAML text. Cascade 5's reviewers
hit the other half of the same gap twice: there is no way to record a
**failed** review verdict at all (L-016), so a fail is either not recorded
or written by hand.

P-001 item 3 and P-003 decreed the third piece: per-behaviour reds live in
the officina at `studio/ci/reds/<opus>/`, written **only** through a new
`bisellium red` command. `opus.red_evidence` (W-021) turns blocking once
that store exists — so this opus is what activates a blocking rule in
someone else's opus. Build the store carefully.

Four named verbs, each with its guard baked in. No generic
`bisellium gate`/`bisellium state` escape hatch: a caller must say what it
means, and the command refuses what the recorded evidence does not support.
Both stopgap scripts are deleted by this opus.

## Interfaces

```ts
// packages/commands/src/lifecycle.ts
import type { WriteOptions, WriteResult } from "./writes.js";

export function runReady(args: string[], opts?: WriteOptions): WriteResult;
//   bisellium ready <opus> [--spec <path>] [--sella <id>] [--studio <dir>] [--now <iso>]

export function runDone(args: string[], opts?: WriteOptions): WriteResult;
//   bisellium done <opus> [--sella <id>] [--studio <dir>] [--now <iso>]

export function runReview(args: string[], opts?: WriteOptions): WriteResult;
//   bisellium review <opus> --pass|--fail --evidence <path> [--round <n>]
//                           [--sella <id>] [--studio <dir>] [--now <iso>]

export function runRed(args: string[], opts?: WriteOptions): Promise<WriteResult>;
//   bisellium red <opus> --behaviour <n> [--sella <id>] [--studio <dir>]
//                        [--repo <dir>] [--now <iso>] -- <cmd…>
```

`--studio` / `--now` are on all four because every write command in this
codebase has them; the rest of each surface is as decreed. Exit codes follow
the house contract: **0** the write happened · **1** a refusal the recorded
state does not support (and `red`'s "that command passed") · **2** usage,
unknown opus, not a studio. Every refusal leaves every file untouched.

Every front-matter write goes through `editOpusFrontMatter` — merge into the
yaml Document, never replace, body byte-for-byte. Every opus id goes through
`safeItemPath` before it is joined into a path (D-008, blocking as of this
cascade — W-021 ships the rule).

**`ready`** — `greenlit` or `halted` → `building`, and nothing else; any
other current state is a refusal. Sets `spec:` (default `briefs/<opus>.md`),
records the `spec` probatio `{sella, status: passed, evidence: <spec path>,
at}` **only when the manifest declares a `spec` probatio** (mirroring
`check.ts`'s `state.building.spec`, which fires only then), and deletes
`halted_at`, `reason`, `resume_when`. Refuses when the spec file does not
exist under the officina. This is `scripts/opus-ready.ts`'s behaviour exactly,
plus the event.

**`done`** — `building`, `verifying` or `review` → `done`. The two middle
states are an orchestrator-driven ceiling: nothing in this codebase moves an
opus into `verifying` or `review`, and you do not add synthetic events to
pretend otherwise; `done` simply accepts them if it finds them. The guard is
read off disk with `readFront`, never a regex over raw YAML:

- every `automated` probatio in the manifest is `passed` **with a
  `certifies:` starting `tree:`** — a `dirty:` certificate is not a close;
- every `agent` probatio is `passed` or `waived`;
- every `human` probatio **that is recorded at all** is `passed` or `waived`
  (an unrecorded human gate is not demanded — same asymmetry `check.ts`'s
  `state.done.probationes` already has).

`done` does **not** read the red store. `opus.red_evidence` is W-021's rule
and is enforced by `check`, not by this command.

**`review`** — records the manifest's review probatio (`review_probatio`,
default `review`) as `passed` or `failed` with `{sella, status, evidence, at}`,
and **updates** the evidence path when one was already recorded — that
re-recording is the L-016 wall this exists to remove. Exactly one of
`--pass`/`--fail`. `--evidence` must exist under the officina. `--round <n>`
never touches the front matter; it rides on the event as `WF.REVIEW_ROUND`.

`review` performs no forward transition — that is `done`'s job. It has one
return edge, and it is the decree's own words ("a fail is recorded honestly
and the opus stays in building"): an opus in state `review` given `--fail`
goes back to `building`, because `check.ts`'s own `state.review.failed`
message says the item belongs back in building and no other command can move
it there. An opus in `building` given `--fail` keeps its state.

**`red`** — runs `<cmd…>` after `--`, captures **combined stdout+stderr**,
and refuses with exit 1 when the command exits **0**, writing nothing and
creating no directory. That refusal is the whole point: a red you cannot
fake. There is no `--from`, no stdin, no import path — a red is produced by
running the command, never handed to the tool. The command runs with the
caller's cwd; `--studio` says where the log lands.

### The red store — the seam with W-021, declared verbatim in both briefs

Path: `<studio>/ci/reds/<opus>/<NN>.log`, where `NN` is the behaviour number
zero-padded to two digits (`String(n).padStart(2, "0")`; a behaviour past 99
is simply three digits). `<opus>` is validated and contained by resolved-path
relation before it is joined. Written **only** by `bisellium red`; read
**only** by `opus.red_evidence`. The file is:

```
# behaviour: 3
# command: npm run -s typecheck
# exit: 2
# at: 2026-09-19T13:00:00Z
# sella: builder-a
# tree: dirty:0acb03d2

<the command's combined output, verbatim>
```

Six header lines, in that order, one blank line, then the output. `# at` is
`--now`. `# sella` is `--sella`, else `$BISELLIUM_SELLA`, else `guest` (the
convention `context` and `hook-event` already follow). `# tree` is the source
tree hash of `--repo` (default: the officina's parent if it is a git repo,
else cwd) computed the way `verify.ts` computes it — `sourceTreeHash` with
the officina, `.bisellium` and `source_excludes` excluded — prefixed
`tree:` when clean and `dirty:` when `isDirtyOutside` says otherwise, or the
literal `unknown` when git is not available. `# behaviour` and `# exit` are
the only headers W-021's rule reads; do not reorder or rename any of them.

Re-running `red` for the same behaviour overwrites that behaviour's log —
the latest red for a behaviour is the one that counts, and history lives in
git.

### Events

`ready` and `done` each append one `workflow.state_changed` via `emitEvent`
with `WF.ITEM_ID`, `WF.STATE_FROM`, `WF.STATE_TO`, `WF.ACTOR_ROLE`.
`review` appends one `workflow.gate_evaluated` with `WF.ITEM_ID`,
`WF.GATE_ID`, `WF.GATE_STATUS`, `WF.GATE_EVIDENCE`, `WF.ACTOR_ROLE` and
`WF.REVIEW_ROUND` when `--round` was given. `red` emits **no** event: the
log in the store is the record, and a second copy in `events.jsonl` would be
a second source of truth for the same fact. None of these four is a Patron
write, so **none** of them appends to `timeline/patron.jsonl`.

## Behaviours to test

1. `ready` on a `greenlit` opus sets `state: building`, `spec:` and a passed
   `spec` gate, appends one `workflow.state_changed`, and leaves every other
   front-matter key and the whole body byte-identical.
2. `ready` on a `halted` opus additionally deletes `halted_at`, `reason` and
   `resume_when`; `ready` on `backlog`, `building`, `verifying`, `review` or
   `done` refuses with exit 2 and writes nothing.
3. `ready` refuses (exit 2, nothing written) when the spec file does not
   exist under the officina, and records no `spec` gate at all when the
   manifest declares no `spec` probatio.
4. `done` moves `building`, `verifying` and `review` to `done` when every
   automated gate is `passed` with a `tree:` certificate and every agent gate
   is `passed` or `waived`, and appends one `workflow.state_changed`.
5. `done` refuses with exit 1 and writes nothing for each of: an automated
   gate `failed`; an automated gate absent; an automated gate `passed` with a
   `dirty:` certificate; an agent gate not `passed`/`waived`; a **recorded**
   human gate not `passed`/`waived`. An **unrecorded** human gate does not
   block the close.
6. `review --pass --evidence <p>` records the review probatio passed with
   that evidence, sella and `at`, leaves `state` unchanged, and appends one
   `workflow.gate_evaluated` carrying `WF.REVIEW_ROUND` when `--round` was
   given.
7. `review --fail --evidence <p>` records `failed` and **overwrites** an
   evidence path recorded by an earlier round (L-016); on an opus in state
   `review` it also returns the opus to `building`, and on an opus in
   `building` it leaves the state alone.
8. `review` refuses (exit 2, nothing written) for: both `--pass` and
   `--fail`; neither; an `--evidence` path that does not exist under the
   officina.
9. `red <opus> --behaviour 3 -- <command exiting non-zero>` exits 0 and
   writes `ci/reds/<opus>/03.log` with the six headers in order, `# exit:`
   equal to the command's real exit code, `# at` equal to `--now`, and the
   command's combined stdout+stderr verbatim after one blank line.
10. `red` with a command that exits 0 refuses with exit 1, writes no file and
    creates no `ci/reds/<opus>/` directory; a second `red` for the same
    behaviour overwrites that behaviour's log and no other.
11. `red` refuses with exit 2 and writes nothing for `--behaviour 0`, a
    negative or non-integer `--behaviour`, a missing `--` separator, an empty
    command, and an opus id containing a path separator or a `..` segment
    (containment proven by resolved-path relation, never `startsWith`).
12. Each of `ready`, `done`, `review` and `red`, invoked through
    `packages/cli/src/main.ts` with no arguments, prints its own usage line
    and exits 2 — not the generic `USAGE`. (Cascade 4b shipped a command no
    dispatch line reached; this is the test that catches that.)

Record the red for each behaviour before implementing it, with
`bisellium red` itself once it exists. Bootstrap honestly: behaviours 9–11
are `red`'s own, so capture them first and use the working `red` for
1–8 and 12. The reds for 9–11 are the ones you cannot capture with the tool
— run them, keep the failing output, and write them through `bisellium red`
the moment it runs, before you implement `ready`/`done`/`review`. Nothing
here is backfilled after a test goes green: `red` will refuse it.

**Land `red` on `master` first**, as its own commit of your own files, before
you start `ready`/`done`/`review`. Builder B cannot record a single red for
W-021 until that commit exists, and `opus.red_evidence` is blocking for both
of you.
