## Intent

The class `workflow×files-owned-boundary-exceeded` came back four times: `ci/W-339-spec-5.log`, `ci/W-340-review-2.log` (`package.json` changed outside W-340's Files owned), `ci/W-408-spec-2.log` and `ci/W-487-review-2.log`. In the last, a fix after a rebase edited `apps/web/tests-serve/w411.spec.ts`, outside W-487's Files owned, and the gates passed on it. The reviewer found it a round late. Nothing refuses a changed source or test path outside the brief's Files owned before review. The census confirms the instance: at the head W-487's round 2 judged (`b7151128`), the branch's diff against origin/master holds one such path, `apps/web/tests-serve/w411.spec.ts` (`boundary-census.out`).

**The design: the ladder's build rung, before the suite.** `next` derives every step from facts. After a branch's reds are recorded and any fix order is settled, the build rung (`deriveNext`) asks for the gates (`f.gates()`), and only then does the review rung order a review. The check stands just before `f.gates()`. It takes the paths `diffPaths` lists for `origin/master...opus/<id>` and drops the officina records (`recordOnly`). Every path left must be named by the committed branch brief's Files owned (`ownedFiles`). If one is not, the rung holds, names the paths, and names the two routes: revise the brief (a spec amendment, signed again) or revert them on the branch. This point is chosen over the record's three candidates:

- `ready` runs once, before any code exists, so it sees neither the build nor a rebase.
- The `ci --opus` gates run `verify`, but `ci.ts` and `verify.ts` are pipeline files (D-063 §4's risky list). `verify` also runs on master after a merge, where no opus base exists. And the builder's own `ci --opus` is not the only route to review.
- The review perform alone comes after the full suite has run on a tree that will not be reviewed.

The build rung covers all three cases at the cost of the cheapest one. Every review order and every review perform re-derives through it (`--perform --expect review` re-derives before it acts), so a breach found there spends no round. It comes before the producer's suite order and the builder's gate dispatch, so no suite runs on a breaching tree. It runs on every derive, so a rebase is seen: the rebased tree makes the gates stale, the ladder comes back through the rung, and the merge-base diff now holds the resolution's paths. Trunk's own moves are not in that diff, since `a...b` is the diff from the merge base.

Files owned is read from the committed branch brief, the blob the spec gate judged, as W-328's fix-check split reads it, and never from the worktree. A brief revision is a committed amendment, so it counts as soon as it is committed. That is how W-412 and W-495 revised theirs this week. The census reads both in-flight branches against their committed briefs and finds no path outside (`boundary-census.out`: W-412 24 paths, W-495 28 paths, 0 outside). So the check holds neither, and it weakens neither: their revisions are exactly what it reads.

The span grammar is what briefs write. Of the spans on master, 2123 are file paths, 38 end in `/`, and the globs are old briefs or code (`owned-census.out`). The last 28 merged opera, each diffed against its own brief, have no path outside (`boundary-census.out`), so the exact-or-folder rule flips none of them.

Threat model: mistakes, not adversaries (D-045).

Promise boundary: on every derive that reaches the build rung's gates, each path `diffPaths` lists for `origin/master...opus/<id>` that is neither an officina record (`recordOnly`) nor named by the committed branch brief's Files owned holds the ladder at `build`, before the suite order and the review, naming each path and the two routes, as pinned by `W-498-b1` "an unowned test path, gates current" and pinned by `W-498-b1` "an unowned test path, gates current: why names the paths and the two routes" and pinned by `W-498-b1` "the review perform is refused" and pinned by `W-498-b1` "gates stale: held before the suite" and pinned by `W-498-b1` "gates stale: held before the suite: why names the paths and the two routes" and pinned by `W-498-b1` "a rebase resolution that changes README.md against origin/master" and pinned by `W-498-b1` "a hold over 1000 characters is printed whole" and pinned by `W-498-b1` "a hold over 1000 characters is printed whole: why names the paths and the two routes" — limit: the why is printed whole (`uncut`), but `clean` clips one rendered path at 200 characters, and a refused `--expect`'s `detail:` line and `next --all` still cut at 1000; only committed paths on `refs/heads/opus/<id>` are read against the local `refs/remotes/origin/master` (an uncommitted worktree edit is not read, and `verify` refuses to certify a dirty tree); the builder's own `ci --opus` is not refused, only the ladder's orders after it; `diffPaths`, `recordOnly`, `ownedFiles` and `git cat-file` are reused unchanged.

Promise owned: a path is owned when a span of the committed brief's Files owned (as `ownedFiles` reads it: backticked, on a bullet line, `./` dropped) equals it, or ends in `/` and opens it; the worktree's uncommitted brief does not count, and trunk's own moved paths are not the branch's, as pinned by `W-498-b1` "the committed brief revision owns the path: review round 1" and pinned by `W-498-b1` "an uncommitted brief revision does not own the path" and pinned by `W-498-b1` "a path under an owned folder span: review round 1" and pinned by `W-498-b1` "a path that only opens like the folder name is not under it" and pinned by `W-498-b1` "reverted, records only beside owned paths: review round 1" and pinned by `W-498-b1` "trunk's moved paths are not counted: review round 1" — limit: a span holding a glob (`*`, `{…}`) is not expanded, so a path it would match is outside; a path named only in prose is not read.

Promise closed: a diff git cannot read, and a committed brief git cannot read once a source path changes, each hold with its own why, as pinned by `W-498-b1` "an unreadable diff holds" and pinned by `W-498-b1` "an unreadable committed brief holds" — limit: git's own failures are read as `diffPaths` and `git` report them (reused).

## Interfaces

- `boundaryBreach(f: Facts): string | undefined` (new, not exported). It returns the hold's why, or undefined when every path the branch changes is a record or owned. The reads, in order, are: `diffPaths(f.repo, ORIGIN_TRUNK, refs/heads/opus/<id>)`; `recordOnly([path], f.studioRel)` per path; and, only when a source path is left, `git cat-file blob refs/heads/opus/<id>:<studio>/briefs/<id>.md` read by `ownedFiles`.
- The hold: `next: <id> build held`, with exit 1 and no `role` or `command`. The why is exactly `opus/<id> changes <n> path(s) outside its brief's Files owned, in its diff against origin/master (a rebase's resolutions included): <path>, …; revise the brief to own them (a spec amendment, signed again) or revert them on opus/<id> (W-498)`, each path through `clean`. The hold is emitted with `uncut: true` (W-377's whole why line), so every outside path's `clean` rendering and both routes remain present in the report, however long; limit: `clean` replaces controls with spaces and clips an individual rendered path at 200 characters, and the `detail:` line of a refused `--perform --expect` and `next --all`'s lines are still cut at 1000 characters (unchanged).
- The fail-closed whys: `could not read what opus/<id> changes against origin/master (git diff failed), so its paths cannot be checked against Files owned (W-498)` and `briefs/<id>.md is not a readable blob on refs/heads/opus/<id>, so the paths opus/<id> changes cannot be checked against Files owned (W-498)`.
- Unchanged: `diffPaths`, `recordOnly` (`scripts/ci-scope.mjs`), `ownedFiles`, the review rung's trunk-conflict check, which reads the same ref through `ORIGIN_TRUNK`, and every rung before and after.

Limits, stated:

- Unchanged code the promises lean on is a stated limit, not a guarantee (D-076 E). That covers `diffPaths`'s three-dot read and its failure as undefined, `recordOnly`'s list (the studio, the handoff and a dossier page), `ownedFiles`'s span grammar, `git`'s blob read, `verify`'s dirty-tree refusal, and every rung of `deriveNext` before the check.
- The base is the local `refs/remotes/origin/master`, the ref the review rung's rebase order names. A rebase onto a ref fetched later still diffs from the merge base it was rebased onto.
- A path named in Files owned as a glob is outside. The census finds no glob in a brief since W-339, and the refusal names the path to list.
- An opus whose diff is records-only is not read against its brief.
- A branch already past review is not judged again by any other verb: the check runs only when `next` derives.

## Defaults for the Patron

1. Before a branch is tested in full or reviewed, the studio now checks that every code or test file it changed is one its brief said it would change. If not, it stops, names the file, and offers two fixes: update the brief, or undo the change. Edits made while resolving a rebase count too. Agree?
2. The check goes in the step-by-step guide (`next`), not in the test runner, because the runner is a pipeline file and also runs on master. The trade-off is that a builder running the tests by hand is not stopped. The guide still refuses to order the review. Agree?
3. A brief must list each file, or a folder ending in `/`. Wildcards are not expanded. No brief since W-339 used one. Agree?
4. No file this opus changes is one you own, so the pull request merges through the queue without your review. Agree?
