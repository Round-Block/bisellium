## Intent

A recorded red names its pre-change state by SOURCE tree
(`# tree: tree:<sha1>`), and the runner resolves that header against the trees
of the commits on the opus branch (`scripts/run-builder-host.mjs:709–727`).
The ladder's `pr` step rebases the opus onto `master`
(`packages/cli/src/branch.ts:365` `rebaseOntoTrunk`, plain `git rebase`). When
`master` moved with any source change, every rebased commit gets a new source
tree, the header matches nothing, and the runner refuses every red with
`producer red replay refused malformed/unreachable`. No receipt can be minted,
so no marked opus can reach review. That is the live block on W-130 (seven
commits behind a `master` that carries W-132's runner) and on W-110 behind it.

Merging `master` into the branch does not help: the ladder rebases, and
`git rebase` linearizes the merge away (measured, W-125 cascade).

W-125 revision 5 (`studio/briefs/W-125.md:276–292`) already rules the answer:
the logs are **never re-recorded or edited** (evidence is produced, never
backfilled), and identity after a rebase is attested by **replay at the
post-rebase pre-change commit**. The Patron chose that design again on
2026-10-03 over re-recording. Today only the censor performs that replay, by
hand, in a review log. This opus moves it into the runner, so the attestation
is machine-produced and lands in the receipt.

This is a change to the W-125 trust boundary (D-035). The standard is W-125's
confinement obligations: nothing here relaxes export validation, the
confinement of a replay, the producer gate, the brief-derived behaviour count,
or the rule that every numbered behaviour needs a reproducing red.

**What the measurement settles.** The red log's own commit is not a heuristic
for the pre-change state — on this branch it *is* the pre-change state, because
the officina excludes the studio directory from the source tree, so a commit
that adds only a red log has its parent's source tree exactly. The alternative
candidate — matching a rebased commit by message or patch-id against the
original red commit — was discarded: after a rebase the original commits are
unreachable and the runner has nothing to match against. The red log is the
only pre-rebase artefact that survives, and it survives byte-identical.

## Interfaces

### Identification

The runner's existing path is unchanged and is tried first: a well-formed
`# tree: tree:<40 hex>` header that matches a commit's source tree on the
branch is replayed at that commit, exactly as today. A `dirty:`, `unknown`,
`none` or malformed header still refuses outright. The new path runs **only**
when a well-formed header matches no commit.

> **The rebased pre-change commit** for behaviour N is the unique commit
> reachable from `finalCommit` that *introduced* the exact bytes of the log
> being replayed at `<studioRelative>/ci/reds/<opus>/<NN>.log` — its blob at
> that path equals the log on disk, and its first parent's does not. Zero such
> commits, or more than one, is a refusal.

Two guards are part of the rule, not options:

- **Source-free.** The identified commit's SOURCE tree (same exclusion set the
  runner already computes) must equal its first parent's. A commit that carries
  source alongside the red log is refused: the state replayed must be the
  builder's own earlier committed source, not something the identifying commit
  introduced.
- **Same failure.** The replay must reproduce every `^not ok \d+ - <title>$`
  line present in the recorded log, verbatim, in addition to the existing
  assertion-level filter. Titles are the stable, path-free part of a TAP log.
  A recorded log with no `not ok` line cannot be re-attested this way and is
  refused. This check applies on this path only: it stands in for the tree
  equality that the rebase destroyed, and the direct path still has the tree.

The replay itself is unchanged — same disposable clone, same bwrap
confinement, same fixed command from the log's `# command:` header, same
rejection of `ERR_MODULE_NOT_FOUND|SyntaxError:|command not found|ENOENT|not
permitted|permission denied|sandbox`. A replay that does not reproduce
**voids that red**: the run fails, naming the behaviour and the commit tried,
and no receipt is written. Red logs are never edited, moved or re-recorded by
the runner; it only reads them.

### Why a cell-side builder cannot steer this

1. Every commit that touches `<studioRelative>/` is a host commit (M7). The
   builder's cell cannot create, modify, move or delete a red log on the
   branch at all, so it cannot plant an anchor.
2. The selector is content-addressed to bytes the host recorded and the host
   committed. A builder cannot produce a commit carrying them even if it could
   commit under `studio/`.
3. The source-free guard means the identified commit contributes no source of
   its own; whoever made it, the tree replayed is the builder's own earlier
   committed state.
4. Selection is unique or it refuses. There is no "nearest", "newest" or
   "best" tiebreak to push on.
5. Steering cannot help anyway: an implementation-present tree makes the
   command pass and the replay refuses it (M6), and a different failure fails
   the title check.

### Receipt

Each red entry gains one field:

```
{ behaviour, commit, sourceTree, replayedTree, command, assertionFailed: true }
```

`sourceTree` keeps its meaning — the identity the log **claims**. `commit` and
`replayedTree` are what was **actually** replayed. On the direct path they are
equal; after a rebase they differ, and the receipt therefore records both the
claim and the attestation, which is the thing the censor writes by hand today.
`schema` stays `1` and `replayedTree` is optional on read, so a receipt minted
before this change is admitted under today's exact rule.

`admitCurrentRunReceipt` changes in two ways and no others:

- it compares the commit's recomputed source tree to `replayedTree ?? sourceTree`
  instead of always to `sourceTree`;
- when `replayedTree` differs from `sourceTree`, it re-derives the
  identification above from the branch and refuses a receipt naming any other
  commit. The gate already recomputes every tree it is told; it must not start
  taking a commit on trust here.

Everything else at the gate is untouched: reachability, duplicate behaviours,
the brief-derived per-behaviour requirement, the dirty-tree and staleness
checks, the marker, the single censor.

### Replay-safe reds

Each red below is recorded and replayed under confinement, so each must
satisfy the producer replay's own filter:

- No whitespace inside any single command argument; select with
  `--test-name-pattern` and no `^` anchor, on a unique whitespace-free token
  (`W-134-b1` … `W-134-b4`).
- No test title, assertion message or captured output may contain the word
  `sandbox`, or a child's stderr. Assert small derived values with fixed
  messages; never interpolate a child's output into an assertion message.
- Each red is assertion-level at a clean, committed, test-only pre-change
  commit on `opus/W-134`, one log per behaviour,
  `studio/ci/reds/W-134/01..04.log` — and **each log is committed on
  `opus/W-134` in a studio-only commit sitting directly on its own pre-change
  commit**. That is this brief's own rule applied to itself; if W-134's branch
  is rebased before its receipt mints, it must re-identify by its own means.

## Behaviours to test

1. **A rebased branch mints a receipt: the runner identifies and replays the
   pre-change commit.** Live row. Extend `liveFixture` so the red logs are
   committed on `opus/<id>` in a studio-only commit on the pre-change commit,
   then advance `master` with a source change and rebase the opus branch onto
   it, so no commit's source tree matches any `# tree:` header. The runner
   completes: the replay reproduces under confinement, and the receipt's red
   entry carries `sourceTree` = the unmatched header, `commit` = the rebased
   red-log commit, and `replayedTree` = that commit's recomputed source tree,
   with `replayedTree !== sourceTree`. **Genuine red:** today the runner exits
   non-zero at `producer red replay refused malformed/unreachable`; assert the
   completed receipt's red entry, not the exit code alone.

2. **Identification is unique, source-free, or it refuses.** Four sub-rows on
   one red, over the same rebased fixture: (a) the log's bytes appear in no
   commit on the branch (recorded but never committed) — refused; (b) two
   commits introduce those exact bytes — refused; (c) the identifying commit
   also changes a source file, so its source tree differs from its parent's —
   refused; (d) a decoy later commit holds *different* bytes at the same red
   path, and the runner still selects the commit carrying the bytes it is
   replaying. Each refusal names the behaviour and the red file and writes no
   receipt. **Genuine red:** the refusals do not exist; (d) selects nothing at
   all today.

3. **Non-reproduction voids the red.** Two sub-rows on one red: (a) the red log
   is committed *after* the implementation, so the identified commit has the
   implementation present and the command passes — refused, naming the
   behaviour and the commit tried, no receipt, and the red log left byte-identical
   on disk; (b) the command fails at the identified commit but with a different
   assertion, so a `not ok` title from the recorded log is absent — refused.
   **Genuine red:** today neither case is reachable, because identification
   never happens; assert the refusal message class and the untouched log bytes.

4. **The gate admits the rebased identity and re-derives it.** Seam-level row
   on `admitCurrentRunReceipt`: a receipt whose red entry carries
   `replayedTree` matching the named commit's recomputed source tree is
   admitted though `sourceTree` matches no commit; a receipt that names a
   different commit for a rebased entry is refused; a receipt with no
   `replayedTree` is admitted or refused by exactly today's rule, with no
   behaviour change. **Genuine red:** today the first case is refused with
   "unreachable or mismatched red identity".

Each numbered behaviour has one selectable assertion-level row and its own red
log. No existing W-125 or W-132 row may be renamed, weakened or re-scoped to
make any of these pass.

## Acceptance

- Four replayable reds at clean committed pre-change identities, then the four
  focused rows and the full `run.test.ts` green, plus lint, format, typecheck
  and both officina checks at the final clean tree.
- The live rows **run, not skip**, in this sandbox. W-132 made `bisellium run`
  work here; a skipped live row is a failure, not an excuse.
- **W-134's own receipt comes from W-134's own runner**, in the sandbox,
  replaying all four reds and running the producer gate before it writes
  `run_receipt`.
- Proven against the real block, after merge and before W-130 is dispatched:
  `opus/W-130` rebased onto `master` mints a receipt whose five red entries
  name the rebased red-log commits, each with a reproducing assertion failure.
  M4 says that rebase conflicts at the implementation commit; resolving that
  conflict is W-130's own builder work and no part of W-134.
- Evidence retains the actual commands and outputs, names the pinned master
  tooling commit, and distinguishes builder from producer. Nothing is
  backfilled; no red log is edited.
- Changes stay inside Files owned. The containment census is not weakened.
  D-014's censor supplies the single independent review and judges this as a
  change to a trust boundary, with W-125's confinement obligations and D-035
  as the standard.

## Out of scope

- Re-recording, editing, moving or regenerating any red log, by hand or by
  code. W-125 revision 5 forbids it and this opus does not revisit it.
- Any change to export validation, the Git broker, `GIT_LOCKDOWN`, the
  environment allowlist, confinement, the producer gate, the `builder_runtime`
  marker, the receipt's `schema`, or review admission beyond the two changes
  named under Receipt.
- Making `rebaseOntoTrunk` preserve trees, recording a rebase mapping, teaching
  the ladder to rewrite reds, or any new on-disk bookkeeping artefact. The rule
  must work from the post-rebase branch and the logs alone, because a hand
  rebase or a GitHub rebase-merge leaves nothing else behind.
- Relaxing the assertion-level filter, the per-behaviour requirement, the
  duplicate-red rule or the dirty-tree refusal to let a red through.
- A check rule asserting that every red log sits on a source-free commit. The
  obligation is enforced where it bites — at the runner — and a rule that
  reads git history belongs to a separate opus if it is ever wanted.
- W-130's and W-110's own rebase conflicts, their implementations and their
  reviews.
- Historical logs, verdicts, lessons, opera and decisions.
