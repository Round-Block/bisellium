## Intent

Decree family: next-test-fixture-reuse

`next.test.ts` (4,642 lines, 78 `test()` rows) is the suite's slowest file: 480 s, 72% of a full run (W-142); L-127 records it timing out in W-196. Its `world(tag, stage, options)` calls (121 in the source, 332 at run time) build a repository, a bare origin, a worktree and an officina with real verbs (`verdict`, `ready`, `review`, `done`) every time, though they ask for 35 distinct (stage, options) pairs (`timing-summary.txt`).

W-179 keeps every row and every assertion and makes `world()` build each distinct pair once per process: the first request builds a seed with the current body, and every request, the first included, gets a private copy of that seed under its own scratch root, re-pointed at its own origin and worktree. Raising a timeout or trimming rows is not the remedy (production lex §11).

Promise rows-kept: every `test()` title and body on W-179's branch base is in the candidate once, unchanged, and W-179 adds one row — limit: helper code, imports and line numbers move; temporary paths and timings differ.

Promise one-build: in one `next.test.ts` process, `world()` builds a seed once per distinct stage and normalized options, and returns copies thereafter — limit: the first request per pair still pays the full build; another process builds its own; worlds built outside `world()` (`landMerge`'s side clone, `srWorld`'s edits after `world()`) are unchanged and still per call.

Promise private: a copy shares no writable path with the seed or another copy: root, repository, origin, worktree, studio, HOME, scenario, state and call log are its own, and its `origin` and worktree pointers name its own root — limit: the stub `gh` in `BIN` and the `fixtures/gh/` captures stay shared and read-only, as today.

Promise faster: on the same idle machine, the median of three runs of `node --test-reporter=tap --import tsx packages/cli/src/next.test.ts` on the candidate is at most 80% of the base's median, three alternated runs each — limit: the measured ceiling is the 31% spent on repeat builds less the copies' cost, so the draft's 70% is not promised; an acceptance measurement, not a test assertion; host load voids a measurement, and the remedy is a fresh measurement, never a rerun of a failing gate.

This is test infrastructure: `next.ts`, its ladder, receipts and the merge queue do not change. The threat model is mistakes (D-045).

Left out of the draft:

- `W-179-b2`, which could not go red after behaviour 1 (copies are already private). Its concurrent-`next` check is folded into behaviour 1.
- The `nextAsync` change to reject on a spawn error: no row depends on it.

## Interfaces

```ts
function worldKey(upTo: Stage | "backlog", o: WorldOpts): string; // new: stage + every WorldOpts field with its default, fixed order
function buildWorld(tag: string, upTo: Stage | "backlog", o: WorldOpts): World; // new: today's world() body, unchanged
function copyWorld(seed: World, tag: string): World; // new
let worldBuilds: number; // new: incremented by buildWorld
function world(tag: string, upTo: Stage | "backlog", o: WorldOpts = {}): World; // existing signature: cache lookup, then copyWorld
```

`worldKey` fills each default the body uses (`behaviours` 2, `mainOnMaster` true, `fetched` true, `sec` true, the rest absent/false), so `{}` and `{ fetched: true }` share a seed. `copyWorld` makes a new scratch root, `cpSync(seed.root, root, { recursive: true })`, re-roots every `World` path, sets `tag`, runs `git remote set-url origin <root>/origin.git` and, when the seed has a worktree, writes the copy's two pointers (`<repo>/.git/worktrees/W-900/gitdir` = `<wt>/.git`; `<wt>/.git` = `gitdir: <repo>/.git/worktrees/W-900`), never `git worktree repair` (`worktree-repair.txt`), then `scenario(w, {})` (which writes the scenario and removes state and log). `headOid` and `mergeOid` carry over: commits are identical. Seeds and copies are in `roots`, so the existing `after` hook removes them.

## Behaviours to test

1. **Equal worlds come from one build, are private, and can run `next` side by side.** `W-179-b1`: read `worldBuilds`, request two `review` worlds with equal options and different tags, and assert the counter rose by 1. Their roots, repos, origins, worktrees, studios, HOMEs, scenarios and logs differ, and each `origin` URL and `git worktree list` names only its own root, while the seed's worktree list still names only the seed's. Commit a change in the first world's worktree and push it: the second world's branch, origin and files are unchanged. Then give the two worlds different `gh` scenarios and run `nextAsync` in both under `Promise.all`: each exits as its own scenario dictates and each call log holds only its own calls.

   **Genuine red:** the red commit adds the row and `worldBuilds` counting each build, without the cache: the two calls build twice, so `assert.equal(delta, 1)` fails with 2. Existing rows: none flips; the W-124 fixtures row (`worlds agree with the real verbs and the real gh shapes`) then runs on copies and keeps every assertion.
