## Intent

`packages/cli/src/next.test.ts` is the suite's slowest step: 6,718 lines, 114 rows (W-178's count), 776 s on this host alone (the median of three idle runs, `timing-r7/summary`, master 54e18d0b), every row run one after another in one process. D-080 A rules it is split into files the runner runs side by side, every row kept; the handoff rules W-179 carries its own concurrency line rather than waiting on W-249's glob runner.

After this opus the rows live in seven files grouped by behaviour, each holding its group's rows and the helpers only it uses, over one shared fixture module that registers no row; `test:suite`'s one `next.test.ts` step becomes one `node --test --test-concurrency=7` call naming the seven files, so each runs in its own process at the same time. No row, assertion or helper body changes; the split is a kept codemod over the base file, and the count drop W-178's `test.rows` sees in `next.test.ts` is recorded once in `test/row-drops.yml`, naming where the rows went. Row `W-179-b1` pins the suite line and the seven declared file names, so a row file left out of the call, run twice, renamed or added beside them fails the suite. On the prototype the step took 242 s (median of three, alternated with the base's, every row passing, `timing-r7/summary`), 31% of the base's: about 9 minutes saved a suite run on this host, the rest of the suite unchanged.

Promise rows-kept: every `test()` call in the base `next.test.ts` is in exactly one of the seven files, its text byte for byte unchanged and under the same `if` guards, and the only new row is `W-179-b1` — limit: helpers, imports, comments' places and line numbers move; W-178's `test.rows` counts rows per file statically, so it sees the drop in `next.test.ts` and the record, not the row names; `inventory.mjs` checks names, bodies and guards at acceptance.

Promise all-run: `test:suite` runs each of the seven declared next row files exactly once, all of them in one `node --test` call whose concurrency is seven, with TAP and `--import tsx`, and no other next row file exists — limit: the row finds a next row file as a `packages/cli/src/next*.test.ts` other than `next-world.test.ts`, or a `*.test.ts` beside it importing `./next-world.test.js`; a file elsewhere, or one importing the fixture another way, is not seen; an eighth file is a deliberate edit of the row's declared list; a later runner that replaces `test:suite` (W-193, W-249) must keep the call or move the pin.

Promise isolated: no file's process writes a path, an environment variable, a working directory or a port another file's process reads while they run: each runs in its own process, which builds its own stub bin, scratch roots, HOME, worlds, scenarios and call logs under fresh `mkdtemp` directories and removes them in its own `after` hook — limit: they share the read-only `fixtures/gh/` captures and repository reads, the host's pid space and tsx's compile cache under `$TMPDIR` (Limits, stated); CPU and memory are shared, so a row's own timeouts bound it as today.

Promise faster: on this host the next step of `test:suite` on the candidate takes at most 40% of the base's, by the median of exactly three runs each, alternated base first in a fresh directory, both checkouts at one commit, the base clean and the candidate at its named tree, every run exiting 0 and starting under a one-minute load average of 2; `time-base.sh --check` exits 0 only then (measured: base 776 775 782 s, candidate 246 242 240 s, ratio 0.312, `timing-r7/summary`) — limit: the step is bounded below by its slowest file; an acceptance measurement, not a test assertion; the scripts refuse every invalid run (`time-test.out`), and the remedy for a refused or failing measurement is a fresh one in a fresh directory, never a rerun of a failing gate.

Threat model: mistakes, not adversaries (D-045). This is test infrastructure: `next.ts`, its ladder, receipts, the merge queue, CI and certify do not change.

## Interfaces

The codemod, `node ~/.bisellium-evidence/W-179-spec/split.mjs <checkout>` (kept; Defaults 2), first checks `groups.json` against the seven declared row files (every destination one of them, each reached, no key repeated, every key matching a row) and refuses, writing nothing, on any other; it then parses `packages/cli/src/next.test.ts` with the TypeScript parser already installed and places each top-level statement, with the comments above it, in one output:

- a row (a `test()` call, or an `if` block holding `test()` calls, the `if (runs(n))` and `if (only === undefined)` guards) goes to the file of the longest `groups.json` key its title starts with;
- every statement before the first row, and every statement that is neither a row nor a declaration, goes to `next-world.test.ts`;
- a later declaration stays in the one file whose chunks use it, and goes to `next-world.test.ts` when two files use it, when a shared statement uses it, or when nothing does.

Each output's imports are rebuilt from the base imports it uses, in their order, plus one `import { … } from "./next-world.test.js"` of the shared names it uses; `next-world.test.ts` gets `export ` before each declaration. Nothing else in a statement changes. `apply-test.py` appends row `W-179-b1` to the base file first (so the codemod places it), and `apply-src.py` then rewrites the suite step and writes the record, its drop computed with W-178's own `countTestRows` on the merge-base's and the working tree's `next.test.ts`. Run on master 54e18d0b, the seven files hold 10, 8, 14, 24, 27, 17 and 15 rows in the table's order (115, `inventory-proto.out`).

The row, appended to `next.test.ts` (`apply-test.py`):

```ts
test("W-179-b1 behaviour 1: test:suite runs every next row file once, side by side, in one node --test call", () => {
  const suite = (JSON.parse(readFileSync(join(REPO_ROOT, "package.json"), "utf8")) as { scripts: Record<string, string> }).scripts["test:suite"]!;
  // the seven declared row files (studio/briefs/W-179.md): a next*.test.ts beside this one, or a test file importing the shared fixture, is one of them
  const declared = ["next-branch", "next-done", "next-ladder", "next-queue", "next-review", "next-spec", "next"].map((f) => `packages/cli/src/${f}.test.ts`);
  const found = readdirSync(HERE)
    .filter((f) => f.endsWith(".test.ts") && f !== "next-world.test.ts" && (f.startsWith("next") || readFileSync(join(HERE, f), "utf8").includes('from "./next-world.test.js"')))
    .sort()
    .map((f) => `packages/cli/src/${f}`);
  assert.deepEqual(found, declared, "the next rows live in exactly the seven declared files");
  for (const f of declared) assert.ok(lstatSync(join(REPO_ROOT, f)).isFile(), `${f} is a regular file, not a link`);
  const segments = suite.split("&&").map((s) => s.trim().split(/\s+/));
  const runners = segments.filter((words) => words.some((w) => w.includes("packages/cli/src/next")));
  assert.equal(runners.length, 1, `one test:suite segment names the next files: ${JSON.stringify(runners.map((w) => w.join(" ")))}`);
  assert.deepEqual(runners[0]!.slice(0, 6), ["node", "--test", `--test-concurrency=${declared.length}`, "--test-reporter=tap", "--import", "tsx"], "it is one node --test call running every file at once, with TAP");
  assert.deepEqual(runners[0]!.slice(6), declared, "it names each next row file once, in path order, and nothing else");
});
```

It lists the next row files (each `next*.test.ts` in `packages/cli/src` but `next-world.test.ts`, and each `*.test.ts` there whose text holds `from "./next-world.test.js"`), asserts they are exactly the seven declared names and that each is a regular file by `lstatSync` (a link fails), finds the `test:suite` segments (split on `&&`) that name a `packages/cli/src/next` path, asserts there is one, and that its words are `node --test --test-concurrency=7 --test-reporter=tap --import tsx` followed by exactly the seven files in path order.

Limits, stated:

- Unchanged code the promises lean on is a stated limit, not a guarantee (D-076 E): every helper the codemod moves (`scratch`, `world`, `scenario`, `envFor`, `next()`, `nextAsync()`, the stubs) and every row body; W-178's `countTestRows`, `testRowFindings` and `readRowDrops` (`rules/tests.ts`); W-121's `test.sleep` and `scripts/no-vendor.mjs`'s static pins, which already treat `*.test.ts` as test code; and Node's test runner, which runs each named file in its own child process with `--import tsx` forwarded (probed with two files in `nt/`: `node-test-probe.out`).
- tsx's compile cache (`$TMPDIR/tsx-<uid>`) is shared by every CLI child of every file, as it already is by `nextAsync`'s concurrent children; W-311 pins that children keep the test process's `TMPDIR`. tsx reads an entry inside `try`/`catch` and recompiles on a parse failure (`node_modules/tsx/dist/index-*.mjs`, `readJsonFile`), so a half-written entry is a miss, never wrong code.
- `deadPid()` hands a row a pid that has exited; another process reusing it before the row's next call reads it would flip a health row. Linux allocates pids in sequence (`pid_max` 32768 here), so a reuse inside the row's one-call window needs that many process starts first.
- Old recorded reds name `packages/cli/src/next.test.ts` with a `--test-name-pattern` (68 logs under `studio/ci/reds/`): they are judged as text (`rules/evidence.ts`) and replayed only at their own commit (`run-builder-host.mjs` checks out the red's tree), where the file held every row; rerun on a later tree, a moved row's selector finds no test.
- `test:record` names no next file and is unchanged; certify (`scripts/ci-certify.mjs`) runs no test file by name.
