## Intent

W-339 revision 2 attempted to add screenshot baselines beside the colour rule. Its last spec review found that its browser clock advanced with real elapsed time, `apps/web/index.html` still loaded Google Fonts and its font row accepted arbitrary files. D-061 §4 moved the screenshot work intact to W-350 instead of reopening W-339. The ui-lead also required loaded fixture states, production typography rather than a universal test override, stable displayed provenance, and explicit viewport, scroll, focus and pointer state.

W-350 adds one policy row plus one served-browser spec. The policy row is cheap, runs before the browser suite and makes the wiring, exact font-to-CSS map, zero-tolerance comparison and runner-only refresh semantics reviewable without Chromium. The browser spec authenticates the committed WOFF2 family and weight from each font's own `name` and `OS/2` tables, awaits every declared face, starts a fresh fixed fixture, asserts the screen-specific loaded state, settles the initial view and compares eight PNGs. The font check does not trust a filename, CSS family declaration or a merely successful `document.fonts.load`.

The fixed instant is `2026-09-25T09:35:43.947Z`. The server receives `--now`, and the browser calls `page.clock.setFixedTime(new Date(FIXED_NOW))` before navigation, so `Date` stays constant while native timers, requests and loading continue. Playwright fixes locale `en-GB`, timezone `UTC`, device scale factor 1 and viewports 1280×900 and 390×900. Before each capture the spec resets `.shell__main` and Board's horizontal scroller, blurs focus, clears selection and parks the pointer at the bottom-right non-control pixel.

These are initial-view baselines. Desktop Inbox captures A-1/W-004 selected with its question, reason and four verbs visible. Phone Inbox captures the current loaded queue; its hidden answering pane is a known limitation owned by W-341. Board has populated columns, gate marks and the pinned Needs you column visible. Seats has manifest selections loaded and no draft confirmation. Officina receives fixed budget, health and acta records and awaits Completion's resolved fixture state. For the unchanged sample fixture, the browser asserts `No milestone records` within `.panel--completion` before capture; loading or request failure cannot satisfy readiness. The intercepted officina response displays `/fixtures/w350`, and fixed time stabilizes generated timestamps without hiding any colophon.

The five font files are absent from this no-network drafting environment, as are the eight runner-generated PNGs. The prototype therefore proves the source contract, exact CSS map and parser wiring but cannot build Vite or execute the production font assertion and browser comparison here. The builder obtains the ruled files from the exact sources below, the CI runner generates the first baseline artifact, and only those runner bytes are committed. A normal developer or CI comparison has `updateSnapshots: none`; refresh is derived from `inputs.refresh_screenshots` only on the explicit runner dispatch.

Threat model: mistakes, not adversaries (D-045).
