## Intent

Three test-only misses reached `ci --opus` on 11-09 after a signed spec (W-543's admission, W-547's W-530-b4 flip, W-558's `test.one_sided` and `scripts/status-slate.test.mjs`), and W-572's ci-opus-1 failed on a new test file that read studio records without a `test:record` entry. W-558's one class (`review×fail-open-on-malformed-records-patched-per-site`) was found one site per round across five rounds. This opus makes the signature carry proof of the cheap gates, makes a brief that answers a repeated class carry its census, and makes the round-1 reviewers ask for every site. The prototype's own first check run found two of the same misses in its own new code (four `test.one_sided` blocks, fixed before the cut) and its own first gate rows found a third on master: `packages/cli/src/w543.test.ts` is named by no `test:suite` command, so no run executes it; behaviour 1's commit adds it. Revision 3 keeps the gate cheap (ladder-time-meet-1111 call 2): only the rows a series most plausibly breaks, run at once, within ten minutes; whatever is not reached is deferred to `ci --opus`, which stays the full judge.

1. **The gate's rows (behaviour 1).** A new module, `packages/commands/src/presign-gate.ts`, computes from a git tree and its base the rows a signature owes, in this order: `check` (`npm run -s check -- studio --repo .`), `typecheck` (`npm run -s typecheck`), one `reads` row per test file the series adds, and one `test` row per test file at the tree (`*.test.ts`, `*.test.mts`, `*.test.mjs`, outside `apps/` and `docs/`; `scripts/*.test.mjs` included) that the series adds or changes or that DIRECTLY imports a touched path. A direct import is a literal static `import`/`export … from`, a side-effect `import "…"` or a literal dynamic `import("…")` in the test file itself; relative `.js` specifiers resolve to a `.ts` sibling, `@bisellium/<pkg>/<sub>.js` to `packages/<pkg>/src/<sub>.ts` (the workspace `exports` map). No transitive closure, no basename edge, no `suite` row: a test that reaches a touched path only through another module, by spawning it or by naming it is no row. Each row's command is the `package.json` `test:suite` `&&`-command whose tokens name the file, narrowed, when it names several test files (one `node --test` over a family, such as the next family's 15 files), to the owed files it names in its own order; a required file that no `test:suite` command names is a row recorded as failed, unless another test file imports it (a fixture such as `next-world.test.ts`, whose direct importers are then its rows).
2. **The gate runner and its log (behaviour 2).** `node --import tsx packages/commands/src/presign-gate.ts --opus <id> --worktree <scratch> --base <sha> --series <mbox> --out <log>` refuses (exit 2, no log) unless the scratch worktree is clean (`git status --porcelain --untracked-files=all` empty) and its `HEAD^{tree}` is the tree the series makes on the base. It then runs the rows of behaviour 1 pooled in that worktree (as many at once as the host's cores, at most 8; rows sharing one kind and command, a multi-file `test:suite` command, run it once and share its exit), each under a per-row timeout (600 s, the budget's length: a row still running is killed with its process group and recorded as failed, exit 124, and the run goes on), within a 10-minute budget for the whole run: a row not started when the budget runs out is logged `deferred` (deferred to `ci --opus`) and does not fail the gate. The log is written once rows start, whatever their exits (in a `finally`): a header (`# presign-gate: <id>`, `# base: <sha>`, `# series: sha256:<hex>`, `# tree: <sha>`, `# started: <iso>`), one line per row in owed order `<exit|deferred>\t<seconds>\t<kind>\t<file|->\t<command>`, and `# minutes: <n.n>` last (the record's measure). A `reads` row runs the file's `test:suite` command with `NODE_OPTIONS=--import <worktree>/scripts/record-reads.mjs` and a fresh `BISELLIUM_RECORD_READS` log, then `node scripts/ci-scope.mjs --check-reads <that log>`; it passes when the run exits 0 and the check prints no `unlisted:`, `failed:` or `missing:` line (W-572's ci-opus-1 shape: a new file reading studio records must be in `test:record` too). The runner exits 1 when any row failed (a timeout included), 0 otherwise (deferred rows included).
3. **`verdict --phase spec` refuses a prototyped signature without a current, passing gate log (behaviour 3).** For the signer's spec verdict (the stage `promiseLedgerProblems` runs in, so every first sign and every re-sign: a class loop, an amendment) on a brief whose `Prototype:` line `readPrototype` reads, once every earlier signer problem is none: the transcript holds exactly one `Gate log: <absolute or ~/ path>` line; the log parses (`readGateLog`); it gates this opus; its series digest is the brief's `Prototype:` digest and the series file holds that digest (`loadSeries`); its tree is the tree `verdict` itself computes by applying the series to the log's base in a temporary index (`git read-tree`, `git apply --cached`, `git write-tree`, `GIT_INDEX_FILE` under a fresh `mkdtemp` directory, removed after); its rows cover `gateRows` at that tree (same kind, file and command), each exit 0 or `deferred`; a failed row (any other exit, 124 included) refuses. Otherwise exit 2, nothing written, each problem named `<id>: pre-sign gate: <problem>`. `readPrototype`, `loadSeries` and `SERIES_MAX_BYTES` move unchanged into `packages/commands/src/prototype-line.ts` (verdict cannot import the cli), and `prototype-replay.ts` re-exports them.
4. **A brief answering a repeated class names its census (behaviour 4).** For the same signer's spec verdict, on any brief: each class tag (`CLASS_TAG`) carried by a standing `[severity: S1]` blocker of a failed (`# outcome: failed`) spec or review log of this opus under `ci/` is repeated when another failed round of this opus carries it, or a Findings line of another opus's review or spec log under `ci/` does. Every log, this opus's own included, is read through `findingLines` (its blocking S1 lines, its `# outcome: failed` line), never stricter than `next` on one record: two readers of one record disagreeing is W-558's class (producer's r3 ruling, 2026-11-11) (next's `repeatHold` reading: `findingLines`, `OTHER_LOG` and `classesIn` move from `next.ts` into `packages/commands/src/class-census.ts`, with `CLASS_TAG` from `verdict.ts`, which re-exports it; each log is read through `readContainedRegularFile`). For each repeated class the brief holds one line `Class census: <class> <script path> -> <output path> sha256:<hex>`: the script is a readable regular file, the output a readable regular file at that digest, and each non-blank output line opens `site ` or `limit `, a `limit` line holding `follow-on:`. Otherwise exit 2, `<id>: class census: <problem>`. The shape is checked, not completeness (call 2 (i)); the digest in the signed brief, which `branch` commits, is the output's commitment.
