## Intent

W-408's PR #859 was reviewed (round 1), its screens approved by the Patron (D-132) and queued, and certify refused it: six of its ten red and implementation commits did not build on their own (W-461 now refuses such a series when it is made). The builder rebuilt the series by hand (`W-408-build/rerecord/rewrite-r3.sh`): every commit builds, all five reds replay, and the new head `44d10c52` has the reviewed head `48a2484c`'s tree exactly (`git rev-parse 44d10c52^{tree} 48a2484c^{tree}`: both `7aa4d29a`). Getting it onto the PR has no ladder step, and the step that exists is the wrong one: on master `next` names `pr` for an OPEN PR "not on the local tip" (`next.ts` `classify`, `open-stale`), and its perform runs `git push -q --force-with-lease origin opus/<id>` (`integrate.ts:730`), a force push of rewritten reviewed history whose lease is only the remote-tracking ref, with no tree check, no build, no replay and no one asked. On 2026-10-29 the orchestrator dispatched a runner to run exactly that perform, and the harness refused the dispatch: `Permission for this action was denied by the Claude Code auto mode classifier. Reason: [Git Destructive]` (`harness-refusal-transcript.txt`, 11:55:40Z). The refusal was right: rewriting a reviewed PR's history is the Patron's call.

This opus makes that rewrite a reading of the `pr` rung, `act: "rewrite"`, run by `next <id> --perform --expect pr` like every other `pr` act:

- **`next` names a rewrite.** An OPEN PR whose head R is not an ancestor of the local tip N, with N's tree equal to R's (the whole tree, the record included: a rewrite changes history, never content), is named `pr` with a `rewrite:` line naming R, N and the tree. The plain `pr` perform never runs on it, so no agent's perform force-pushes a reviewed head. A tip that keeps R's source tree but changes its record tree is held (a rewrite keeps the reviewed tree; a record is committed after the push, as a descendant). A tip whose source differs from R's is a rebase onto master, which the review rung has already re-reviewed at the new source tree (W-243's advice), and is the plain `pr` as before; so is a PR head this clone does not hold, which cannot be compared (the plain push's lease, on the remote-tracking ref, refuses to replace a head this clone has not fetched).
- **The perform checks, and pushes nothing.** The worktree is on `opus/<id>` and clean: no tracked change and no untracked path (ignored paths, such as the web bundle and `node_modules`, are not looked at); origin's `opus/<id>` is R now (`ls-remote`, read just before the checks); every commit of the series builds the web bundle as certify builds it (`webBuild`, W-461's helper, reused, never a second build check); and every recorded red replays as certify replays it: certify's red-to-commit mapping (the tree lookup, then `identifyRebased`, W-134), certify's web build before the red, the red's own `# command:` split on whitespace as certify splits it, certify's classifier (`classifyReplay`, `scripts/replay-accept.mjs`, imported unchanged) on its output, and the recorded `not ok` titles re-attested after a re-identification. Builds and replays run in place in the opus worktree, each commit checked out detached, as W-461's perform builds in place; after each build and each replay the worktree must hold no path it did not hold right after that checkout, or the check fails naming the paths and the worktree is cleaned (tracked paths reset, untracked paths removed). Whatever the checks find, the worktree is then put back on `opus/<id>`, and the result counts only when the worktree is confirmed there, at N, and clean.
- **The Patron is asked once.** With every check passed and the worktree confirmed back, the perform holds and prints one `patron:` line: `git -C <worktree> push --force-with-lease=refs/heads/opus/<id>:<R> origin <N>:refs/heads/opus/<id>`. Its lease names R explicitly, so it refuses if anything moved origin off the reviewed head since the check (`../probe-lease.out`: the same command form pushes over R and is rejected, `stale info`, once origin moved). The `patron:` line is the ladder's existing way to hand the Patron one command (`integrate.ts` `patronStop`); the Patron's running it is the answer and the consent. Nothing waits on a file: until the push, origin still reads R, so the rung still names the rewrite, and rerunning the perform reruns the checks (about 43 s on W-408's 33 commits, `dry408/dry-run-w408.out`).
- **After the push, rebind and re-request.** The PR is then OPEN on the local tip, and the queue binding (`<git common dir>/bisellium/queue/opus%2F<id>`, W-199: written by the `pr` rung with the head it pushes) still names R. `next` reads the binding and, because it is neither absent nor the PR head, master's merge mode: in queue mode it names `pr`, `act: "rebind"`, with a `rebind:` line. Its perform reads the merge mode again, fetches the trunk as the `pr` rung does, screens the head as the `pr` rung screens every head it pushes (W-418's `reviewNotice`, reused: the notice, and `gh pr edit <n> --add-reviewer <owners>` for its code-owned paths; for PR #859, `studio/decisions/D-132.md`, owned by `@edckt`), and only then writes the binding for N. The next derivation is `merge`, whose perform arms the queue with `--match-head-commit N` (`mergeGate`, which in queue mode now first checks that the binding names the PR head): the requeue.

Why a reading of `pr`, not a new rung or a verb: the thirteen rungs (`STEPS`) are a contract `--chain`, step health, the silence table and the console read; a reading (`act`) is how the ladder already splits one rung (`fix-check`, `commit-opus`, `land`), the derivation decides it, and `--expect pr` refuses anything else. A verb would be a second way past the ladder's own derivation. Why the Patron runs the push and not an agent after a petitio: an answer in the Inbox is a file any session can write (`bisellium answer`), never the Patron's consent (lex: no agent message is consent), and the harness judges the push itself, not a record; a petitio would add a wait and a file and still end at the same refused push. The one command is the ask, made once per passed check.

Harness probe (revision 1's `probe-lease.sh`, run in the architect's sandbox against scratch repositories under `$TMPDIR`, the real origin only read): a `--force-with-lease=<ref>:<R>` push of a same-tree rewrite succeeds while the remote is at R (`forced update`) and is rejected once the remote moved (`stale info`); `git ls-remote origin refs/heads/opus/W-408` and `gh pr view 859` read origin (`48a2484c`, OPEN). A push to origin was not attempted: the architect's dispatch forbids it, and the 10-29 refusal shows this harness classifies an agent's rewrite of a pushed branch as destructive. So the push to origin is a Patron action (Defaults), and nothing in this opus asks for an allow rule.

This opus's own merge (W-323, D-129 B): certify's host runner is untouched. Certify's mapping lives inline in `scripts/run-builder-host.mjs`, which a change to certify's runner would have to split out and land first (D-129 B). So the mapping is copied, logic and refusal lines unchanged, into `scripts/red-claims.mjs`, a host module the runner does not yet load; the runner's switch to it is a follow-up, split out (Out of scope). A refactor of the runner onto the module was prototyped in revision 1 and certify's own W-134 rows pass on it (`../runner-refactor/census-run-w134-with-runner-refactor.out`), so the follow-up is mechanical.

Threat model: mistakes, not adversaries (D-045). The rewrite check runs the candidate's own web build and red commands in the caller's checkout, as the reds perform and `npm test` already do there.

## Interfaces

**`rewriteOf(repo, excludes, reviewed, head): Rewrite`**: a reviewed head this clone does not hold (`git cat-file -e <R>^{commit}` non-zero) is `unknown`; then `git merge-base --is-ancestor reviewed head` exit 0 is `update`; exit 1 with equal `^{tree}` oids is `rewrite` (with the tree); exit 1 with equal source trees (`sourceTreeHash` with the opus's excludes) is `recorded`; exit 1 otherwise is `rebased`; any other exit, an unreadable tree or source tree is `error` with a reason.

**`next <id>` at `pr`**, for a PR the rung reads OPEN on a head other than the local tip (`open-stale`), before the stale-handover check (a rewrite keeps the record, so a handover stale at R is stale at N too, and fixing it would change the tree): `error` holds with its reason; `recorded` holds with `opus/<id> <N12> rewrites PR #<n>'s reviewed head <R12> and changes its tree outside the source: a rewrite keeps the reviewed tree (W-462); commit the record after the Patron's push`; `rewrite` is named `pr`, `act: "rewrite"`, command `bisellium next <id> --perform --expect pr`, with `rewrite: PR #<n> <R12> -> opus/<id> <N12>, tree <T12>`; `unknown`, `update` and `rebased` are the plain `pr`, as before (for `unknown`, its push is leased on the remote-tracking ref, which refuses to replace a head this clone has not fetched).

**`next <id> --perform --expect pr`, `act: "rewrite"`** (`performRewrite`): holds, in order, on tracked changes in the worktree (`dirtyHold`, reused); a worktree not on `opus/<id>`; any untracked path (`refusing: <wt> holds untracked path(s) <paths>; the checks build and replay in place, from a clean worktree: move them aside, then rerun; nothing checked or pushed`); origin's `opus/<id>` (`remoteTip`, `ls-remote`) absent, unreadable or not R (`origin's opus/<id> is <x>, not PR #<n>'s reviewed head <R12>; nothing checked or pushed`); `rewriteOf` not `rewrite`; then `checkSeries` over `refs/remotes/origin/master..N`: a commit that cannot be checked out, or whose `webBuild` refuses (`commit <c12> does not build: <webBuildReason>; certify's replay would refuse a red on it; nothing pushed`); a build or replay after which the worktree holds a path it did not hold right after the checkout (`the build of <c12> left the worktree changed (<paths>), cleaned; certify builds and replays in a fresh clone; nothing pushed`, or `red <k>'s replay at <c12> left …`, or `…, and it could not be cleaned; …`); a behaviour 1..n (the brief's count, `countBehaviours`, certify's) with no `NN.log` at N; a claim certify would refuse (its own line, e.g. `producer red replay refused 01.log: behaviour 1: no commit on the branch introduced its recorded bytes`); a red commit whose build refuses (`webBuildFailure`, certify's line); a replay `classifyReplay` does not accept (`red <k> did not reproduce its assertion failure at <c12>: <reason>; nothing pushed`) or, after a re-identification, whose output lacks a recorded title. Whatever those find, the worktree is then checked out on `opus/<id>` (`git checkout --no-guess`) and confirmed on the branch, at N, with no changed or untracked path; if not, the result is a hold, whatever the checks found: `the worktree <wt> could not be put back on opus/<id> at <N12> clean (<git checkout failed: …, HEAD is …, opus/<id> is at …, or it holds …>): put it back by hand, then rerun; nothing pushed`, after the checks' own reason when they failed. ## Defaults for the Patron

1. **An agent never pushes a rewrite of a branch you have reviewed.** When a branch's history is rebuilt and its final code is unchanged, the agent checks it and then gives you one command to run; the push is yours. Agree?
2. **Before it asks, every step of the new history is checked**: the console builds at each one, and each recorded failing test still fails where the merge queue will look for it. The checks start only from a clean folder, a step that leaves files behind fails the check, and you are asked only once the folder is back on the branch and clean.
