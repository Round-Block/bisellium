# W-102 - Persist the Codex role workflow

## Intent

Replace the studio's active Claude-specific role assignments with the
Patron-approved Codex workflow while preserving the existing lifecycle and
single review gate. The producer remains an orchestrator; drafting,
architecture, build, red-team/security, pre-review, review and clerical work
run in explicitly separate agent contexts.

## Interfaces

- Codex project configuration is the active orchestration interface. The root
  defaults to `gpt-6-astra` at medium effort. Project agent files bind a
  separate architect to Astra medium and a separate censor to Astra high;
  builder to `gpt-5.6-sol`; security/red-team to a separate Sol context;
  prereviewer to `gpt-5.6-terra`; and clerk to `gpt-5.6-luna`. Only the
  Patron-specified Astra efforts are pinned. Drafting and building may reuse
  the builder role but must be separate dispatches; a brief's drafter and
  security red-team are never the same context.
- `.codex` role defaults govern Codex orchestration dispatch. `bisellium talk`
  remains the existing read-only conversational harness with its security
  flags; it is not a role dispatcher, and this opus adds no effort field to
  its manifest or harness contract.
- The real studio manifest remains the source of seat, harness, tier and
  munus bindings. Keep existing seat ids so W-089's separate seat-template
  work is untouched. Add only the missing Terra pre-reviewer and Luna clerk
  seats; bind the current producer/architect/censor, builders and security
  seats to their approved Codex models and harness.
- `process.review_tier` continues to inspect the model recorded on the review
  gate. Its authorized predicate accepts exact `gpt-6-astra` and historical
  model ids containing `opus`. `process.cascade` remains the existing
  same-sella advisory; it detects recorded-seat equality, not execution
  context identity.

## Behaviours to test

1. **Config and role defaults.** Project config and every role file parse,
   carry the required model, carry medium/high on the three Astra roles, and
   state the correct sella, charter and responsibility. Producer instructions
   permit orchestration only; architect alone signs `spec`; censor alone
   judges `review` and never repairs code. These tests prove declarations,
   not runtime context identity; the independent dispatch records are
   operational evidence produced when the workflow runs.
2. **Generated instructions.** Rendering is deterministic and under the
   existing cap. `AGENTS.md` names the Codex role files, separate draft/build
   and security dispatches, and the orchestration-only root. It contains no
   `Agent(... model: "sonnet")` instruction. Regeneration labels the existing
   `.claude` hooks, commands and agent definitions as legacy compatibility
   artifacts without editing them or presenting their model bindings as the
   active workflow.
3. **Review acceptance and independence.** An Astra review is silent; a
   historical Claude Opus review stays silent; Sol and a missing recorded
   model advise at the existing severity. The existing same-sella spec/review
   case still advises. Tests do not rewrite or re-sign any historical gate.
4. **Studio and cascade mapping.** The manifest and cascade sizing agree on
   Astra producer/architect/censor, Sol draft/build and separate security,
   Terra pre-review and Luna clerical work. Cascade prompts read `AGENTS.md`;
   targeted tests fail if the reviewer or first-hour builder regresses to a
   Claude model.

## Acceptance

- Record a genuine red for each behaviour before its fix.
- Pass targeted instructions, process-rule and cascade tests, then
  `npm run -s typecheck`, `npm test`, `npm run -s check -- studio --repo .`
  and `bisellium verify W-102 --studio studio --repo .` on this branch.
- Validate project and role TOML with the installed Codex CLI's strict config
  path without starting a vendor turn.
- Preserve W-089, root's untracked W-101, all historical gate records and
  review evidence byte-for-byte.

## Out of scope

- New lifecycle gates, trial or kill mechanisms, a general dispatch
  framework, or stronger review enforcement than the existing advisories.
- Extending `bisellium talk` with reasoning-effort fields or weakening its
  current sandbox, plugin, rules, configuration or feature restrictions.
- Renaming/removing builder seats ahead of W-089, deleting provider adapters,
  re-signing historical work, GitHub writes, merge or deployment.
