## Intent

W-563's pre-sign gate (`packages/commands/src/presign-gate.ts`) timed out all eight rows of the 7-file next-family `test:suite` command on W-551 (`~/.bisellium-evidence/W-551-spec/gate.log`: seven `test` rows and one `reads` row, each 124 at the flat 600 s `ROW_TIMEOUT_MS`). The runner keyed sharing on `kind + command`, so the command ran twice at once (once plain for the test rows, once traced for the reads row), both 15-wide, inside the 8-slot pool, with seven workers idle awaiting one promise; the group alone takes 582 s (W-563-build/ci7/measure.md). Two rows (`usage`, `w382`) were deferred by the 600 s start budget.

The opus changes only the runner (`runGate` and its row helpers):

1. **Once (behaviour 1).** A *shared* command is a `test` or `reads` row's command naming two or more test files (`isShared`: words matching the test-file pattern; after `rowsAt` narrows a family command to its owed files). Its rows run it once (`runShared`): under the read trace when one of them is a `reads` row, else plain. Every `test` row takes that run's exit; a `reads` row takes the run's exit, or, when the run passed, its own file's reads check.
2. **Alone, after the pool (behaviour 2).** The pool runs only the other rows; each shared command runs after the pool has drained, one at a time, so no pool worker waits on a shared run.
3. **Sized (behaviour 3).** A shared command's timeout is `sharedTimeoutMs`: its test files x `PER_FILE_MS` (120 s), at least the row timeout, at most `SHARED_MAX_MS` (1800 s). From the measure: 582 s for the 15-file family is 39 s a file; 120 s a file gives W-551's 7-file row 840 s (1.4x the whole family's time) and the whole family the 1800 s ceiling (3.1x). A run past it is killed and recorded 124, a failure.
4. **Budget-exempt (behaviour 4).** A shared command starts after the pool by design, so `BUDGET_MS` would defer it every time: it is exempt. Pooled rows keep the budget.
5. **Run time (behaviour 5).** Every row a shared command serves logs the run's own seconds (one start, one end), not the time since that row was picked up.
6. **The reads row judges only the series' files (behaviour 6).** `ci-scope.mjs --check-reads` compares a whole-suite trace to the whole `test:record` list; a gate trace holds only one command's run. `readsProblems(stdout, file)` keeps every problem line except an `unlisted:` line of another owner and an `unread:` line of a command not naming the row's file; a non-zero exit with no line at all still fails (a scalar `test:record`, a missing script).

Two faults found while tracing one run, both closed here, neither forcing eng-lead's fallback (c):

- **`node --test` gives the trace no single root.** The test runner does not run an `--import` preload in its own process, so each file's process logged `#start … root` and the check refused the trace ("2 root processes, expected 1"; reproduced in a scratch repo, 02:31 UTC). On master no reads row of a `node --test` command could pass. `traced` now runs the command under a node wrapper (`TRACE_ROOT`, preloading `record-reads.mjs`, running `sh -c <command>`) that is the run's one root; every row's trace goes through it, pooled or shared.
- **On the real repo every reads row fails on `unread:`.** Since W-563 review 1 made the check's exit the judge, a gate trace (one command) yields an `unread:` line, and exit 1, for each of the ~100 other `test:record` commands (`node scripts/ci-scope.mjs --check-reads ~/.bisellium-evidence/W-551-spec/reads-w551.log`: exit 1, 14 lines of `unread:`). Behaviour 6 closes it.

One traced run is sound: the shared run's exit serves its test rows unchanged (the trace only appends to a log), and the reads judgement reads that one trace. The cost named by qa-lead stands: a shared command's test rows now run under `record-reads.mjs` (NODE_OPTIONS), as `bisellium ci` already runs the whole suite.

The log's shape does not change: one line per row, `<exit>\t<seconds>\t<kind>\t<file|->\t<command>`, in `gateRows` order; a shared row is a row like any other.

## Promises

Promise shared-once: a `test:suite` command naming two or more test files, owed by several rows, runs once per gate run; its `test` rows take that run's exit and its `reads` row that run's exit or its own reads check. Pinned by `W-604-b1` "a shared command with a reads row runs once" — limit: a narrowed one-file family command is not shared and runs pooled under the flat row timeout; the trace's effect on a test's behaviour rests on record-reads.mjs, reused unchanged.

Promise shared-alone: a shared command starts only after every pooled row has ended, and pooled workers run only non-shared rows. Pinned by `W-604-b2` "a shared command runs after the pool" — limit: several shared commands run one after another, never in parallel with each other; the pool's size is the host's cores, at most POOL_MAX, as before.

Promise shared-sized: a shared command's timeout is `max(row timeout, min(files x per-file cap, SHARED_MAX_MS))`; a run past it is recorded 124 on every row it serves and the gate exits 1. Pinned by `W-604-b3` "a shared command's timeout is its files times the per-file cap" — limit: PER_FILE_MS rests on one measure (582 s, ci7, 15 files, one host); a shared run near its cap on a loaded host still fails 124, and per-file test timeouts stay with W-579.

Promise shared-budget: a shared command runs whatever the start budget; a pooled row not started within it stays `deferred`. Pinned by `W-604-b4` "a shared command is exempt from the start budget" — limit: BUDGET_MS bounds starts, not minutes: a gate's minutes can pass it by each shared run's time (at most SHARED_MAX_MS each); a deferred pooled row is still not a failure for verdict.

Promise shared-seconds: every row a shared command serves logs one seconds value, the run's own time. Pinned by `W-604-b5` "every row of a shared command logs its run time" — limit: a pooled row's seconds is unchanged (its own run); the seconds are wall time on a shared host, not CPU time.

Promise reads-own: a reads row fails on a problem line that judges its own file or the trace itself, and not on another owner's `unlisted:` line or an `unread:` line of a command not naming its file. Pinned by `W-604-b6` "a reads row judges only the series' files" — limit: a test file the series changes (not adds) that newly reads studio unlisted is judged by `ci --opus`, not the gate; the check's own line forms are reused unchanged from ci-scope.mjs.

## Interfaces

1. **The runner's invocation** is unchanged: `node --import tsx packages/commands/src/presign-gate.ts --opus <id> --worktree <dir> --base <sha> --series <mbox> --out <log>`.
2. **The log** is unchanged in grammar and row set. A shared row's seconds is the shared run's time; rows stay in `gateRows` order.
3. **`GateOptions.perFileMs`** (tests only; default `PER_FILE_MS`).
4. **Exports** `isShared`, `PER_FILE_MS`, `SHARED_MAX_MS`, `sharedTimeoutMs`, `readsProblems` (no CLI verb, no new dependency, no package edge).

Limits, stated:

- Unchanged code the promises lean on is a stated limit, not a guarantee (D-076 E): `rowsAt`, `gateRows`, `treeOfSeries`, `readGateLog`, `gateLogProblems`, `rowEnv`, `sh`'s kill-the-group timeout, `scripts/record-reads.mjs`, `scripts/ci-scope.mjs`'s `checkReads` and its CLI, node's `--test` runner.
- **`BUDGET_MS` bounds starts, not minutes.** A shared command runs after the pool and is exempt, so a gate's minutes can pass `BUDGET_MS` by each shared run's time (at most `SHARED_MAX_MS` each). Expected for W-551: ~6 min pool + ~10 min group, about 16-17 min (ops).
- **Several shared commands run one after another**, each alone; none in parallel with another.
- **A deferred row is still not a failure** (`W-563-b3` "a deferred row signs" unchanged): it is logged `deferred`, never 0, and left to `ci --opus`. A shared row is never deferred.
- **The reads judgement drops other owners.** A test file the series changes (not adds) that newly reads studio unlisted is judged by `ci --opus`, as on master (the gate has a reads row only for added files).
- **`PER_FILE_MS` rests on one measure** (582 s, ci7, 15 files, one host); the per-file test-timeout question stays with W-579.
- **The trace root wrapper is node's `-e`** running `sh -c`; a command's own `sh` semantics are unchanged.
- **A narrowed one-file family command** (one owed file of a family) is not shared: it is pooled under the flat row timeout.

## Defaults for the Patron

1. A shared command (one `node --test` over several owed test files) runs once, after the other rows, with a timeout of 2 minutes per file (at most 30 minutes); the gate may run past its 10-minute start budget by that much. Default: yes.
2. The gate's reads check now ignores problems about test files the series did not add; `ci --opus` still checks them all. Default: yes.
