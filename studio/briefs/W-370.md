## Intent

The done perform records the merge queue's certify certificate (W-259, W-330) by `gh run download` of the `certify-<run>` artifact (`packages/cli/src/next.ts:2609-2612` on master). An artifact download is redirected to a GitHub blob host whose name varies (`productionresultssa<N>.blob.core.windows.net`), which the agents' sandbox and the auto-mode classifier refuse, so a done needs that host named by hand (D-106 C, the stopgap) or the Patron's `!`.

This opus is the reading half. The done perform first reads the merge commit's `certify-certificate` check runs with one `gh api` GET (api.github.com). With exactly one, it takes the certificate from that check run and downloads nothing. It accepts the check run only when it was written by `github-actions`, is on that commit, names that CI run, finished with success, and carries a receipt that matches its digest. The receipt and PR checks are W-259's, unchanged. With none, it reads the artifact as W-259 does (Promise check-run-first). Anything else holds: two or more check runs, a malformed one, or a failed read. A forged or doubled check run never falls back to the artifact.

The check run's shape is written and read in one new file, `scripts/ci-certificate.mjs`: the reader (`readCertificate`, imported by `next.ts` as `ci-scope.mjs` is) and the publisher (`certificatePayload`, `readArtifact`, `publish`, and an entry point). W-396 adds the `ci.yml` job that runs the publisher, with `contents: read` and `checks: write` only and a non-skippable `base_sha` check. This opus calls the publisher from no workflow; its rows pin that what it would post is what the reader accepts.

What changes for a done, plainly. Until W-396 lands, no commit carries a check run. So every done reads zero check runs, then downloads the artifact as today, still through the blob host and the D-106 C stopgap. The only addition is one api.github.com read before the download. A `gh api` failure on that read now holds a done that would otherwise have gone straight to the download (a stated limit). After W-396 lands, a merge commit that carries certify's check run is recorded with no download. W-370 removes no artifact path the fallback needs: the download, its walk and its checks move unchanged into `artifactCertificate`.

Fails closed. A doubled, foreign, unfinished, mismatched or altered check run, a partial or unreadable reply, or a receipt that does not certify the merge commit's tree holds the perform. It writes nothing and names `bisellium verify <id>`, the full local gates, as every W-259 refusal does today.

Threat model: mistakes and a confused writer, not a hostile repository administrator (D-045). Who may write the check run (only GitHub App tokens can create one, and the reader accepts the `github-actions` app's alone) is W-396's to bound with the job's permissions.

## Interfaces

**The check run** (one, posted by `publish`; no CI job calls it until W-396): `POST repos/<GITHUB_REPOSITORY>/check-runs` through `gh api --method POST … --input -`, with the body on stdin:
`{ name: "certify-certificate", head_sha: GITHUB_SHA, external_id: GITHUB_RUN_ID, status: "completed", conclusion: "success", output: { title: "certify run <run>", summary: "receipt sha256:<hex of the receipt's UTF-8>", text } }`, where `text` is `JSON.stringify({ schema: 1, run: <run as a number>, receipt: <the receipt verbatim>, certify: <every certify.log line starting "certify: ">, tail: <its last 200 lines> })`. The tail is shortened from its oldest line until `text` fits 65535 UTF-8 bytes; the receipt and certify's lines are never shortened.

**`certificatePayload({ files, runId, sha })`**: `files` is a Map of relative path to bytes. It needs exactly one receipt (a `.json` under a `receipts` path segment, valid UTF-8 and JSON) and exactly one `certify.log`. `runId` is 1 to 15 digits with no leading zero, and `sha` is 40 lowercase hex. More than 64 certify lines, or a text the receipt and certify's lines alone overfill, is refused. Returns `{ payload }` or `{ error }`.

**`readArtifact(dir)`** recursively returns every regular file under `dir`; symlinks, other entry types and oversize files return `{ error }`, otherwise it returns `{ files }`. Limit: an `lstatSync` or `readFileSync` exception after enumeration escapes; the entry point exits non-zero before posting (under W-396's job, the job fails, and done holds).

**`publish({ env, dir, gh, log })`**: refuses (exit 2, nothing posted) a `GITHUB_EVENT_NAME` other than `merge_group`, a `GITHUB_REPOSITORY` that is not one `owner/name`, or any `readArtifact` or `certificatePayload` error. A non-zero `gh` exits 1 and logs `certificate: gh api exited <n>: <first stderr line>`. Success exits 0. The entry point accepts exactly `--dir <path>` (`readCertificateArgs`) and wires `gh` through `spawnSync` with the body as `input`.

**`readCertificate(reply, { sha, runId })`**, in this order:

1. `reply` is an object whose `check_runs` is an array of length `total_count`, else `the check-runs reply is not one complete page`.
2. Exactly one check run, else `<n> certify-certificate check runs name the commit <sha12>`.
3. Its `name` is `certify-certificate` and its `id` is a positive safe integer.
4. `app.slug` is `github-actions`, else `… written by <slug or "no app">, not github-actions`.
5. `head_sha` is `sha`, `external_id` is `String(runId)`, and `status` and `conclusion` are `completed` and `success`.
6. `output.text` is a string of at most 65535 bytes that parses to `{ schema: 1, run: runId, receipt: string, certify: ≤64 lines, tail: ≤200 lines }`, with no line holding a newline.
7. `output.summary` is `receipt sha256:<hex of receipt>`.

Returns `{ id, receipt: Buffer, certify, tail }` or `{ why }`.


**`recordCertify`** (`next.ts`). The run is found as before (`certifyRun`). Then, for the newest commit read (the merge commit, or W-330's newest chain commit), it calls `gh api --method GET repos/<slug>/commits/<sha>/check-runs -f check_name=certify-certificate -f filter=all -f per_page=100`. A `gh` failure holds `gh api --method failed: …`.
- A reply with `total_count` 0 and an empty `check_runs` reads the artifact through `artifactCertificate` (W-259's download, walk and reads, unchanged, with its refusals).
- Any other reply goes through `readCertificate`, and its refusal holds. There is no fallback.

From either source, the receipt is parsed as JSON (`certify-<run>'s receipt is not JSON`). The owners, `receiptProblem` and the PR and mint lines are then checked with W-259's wording, over the check run's `certify` lines or the artifact's whole log. The gate log body is unchanged, except that a check run's adds `, check run <id>` after the receipt digest and records the check run's `tail`. The `certificate:` output lines are unchanged.

Promise check-run-first: when the merge commit carries exactly one `certify-certificate` check run, the done perform records its certificate with `gh run list`, `gh run view` and one `gh api` GET, and never calls `gh run download`. When it carries none, it reads the artifact exactly as today, pinned by `W-370-b1` "one run list and view, no download" and `W-370-b1` "no check run: then the artifact is downloaded" — limit: which host `gh` contacts for each call is the gh CLI's and GitHub's. Until W-396's job posts check runs, every done takes the artifact path and its blob host (D-106 C).

Promise fail-closed: a doubled, foreign-app, other-commit, other-run, unfinished, malformed or digest-altered check run, a partial reply or a `gh` failure holds the perform with nothing written, names verify and never falls back to the artifact, pinned by `W-370-b1` "two check runs: no artifact is downloaded" and `W-370-b2` "another app's check run: refused" — limit: whether a check run of that name could be updated in place by another `github-actions` token is bounded by W-396's job permissions, not here.

Promise round-trip: what `publish` would post is what `readCertificate` accepts, receipt verbatim, pinned by `W-370-b3` "the reader accepts the posted check run" — limit: that GitHub returns `output.text`, `external_id` and `app.slug` in the list reply as posted is GitHub's documented shape; the rows pin the shape from a fixture written to it, not a captured reply.

Limits, stated:

- Unchanged code the promises lean on, stated and not guaranteed (D-076 E): `certifyRun`, `mergedTree` and W-330's chain, `receiptProblem`, `ghRead`, `artifactFiles` and the artifact reads now in `artifactCertificate`, the gate-log writes (O_NOFOLLOW) and the record edit in `next.ts`; `scripts/ci-certify.mjs` and the `certify` job; the `gh` CLI.
- Until W-396 lands no check run exists, so every done falls back to the artifact as today: the blob host and the D-106 C stopgap still apply. A `gh api` failure on the added read holds a done that would otherwise have gone to the download.
- The publisher is called by no workflow in this opus; its behaviour is pinned by rows only (W-370-b3).
- A re-run that posts a second check run, once W-396 lands, makes its done hold and name verify.

### Input domain
