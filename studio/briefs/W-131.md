# W-131 — evidence slims down: verdict logs carry findings not transcripts, ci/ gains a retention rule, record-only commits stop costing a CI round-trip

Status: **signed spec, revision 1** · architect sella (claude-opus-5-5) · 2026-10-04.
The spec gate is written by `bisellium verdict W-131 --phase spec`, not by this text.

## Intent

Evidence should carry findings, not narration, and studio-only commits should
stop paying for a full CI run. Measured at master `8c763b7`:

- `studio/ci/` holds 1216 files, 8980 KiB. Verdict logs are 5033 KiB of that,
  and 13 of them hold a raw Codex transcript (3281 KiB, four of them over 500
  KiB). Only 11 of 170 verdict logs have a `## Findings` heading. Script:
  `~/.bisellium-evidence/W-131-spec/measure-ci.mjs`, output `measure-ci.out`.
- Gate logs (`<id>-<probatio>-<tree8>.log`, one per `verify` per tree) are the
  part that keeps growing. 329 of them (1460 KiB) belong to a `done` opus and
  nothing outside `ci/` cites them. Nothing reads them back: `next` reads only
  reds, review logs and spec logs, and `verify` writes fresh gate logs. Reds
  (`ci/reds/`) are replayed by receipts, and review and spec logs are cited or
  read by the ladder, so neither is touched.
- CI runs on both `push` and `pull_request`, so every PR commit runs twice.
  Each run is `gates` 280–490 s, `web-e2e` ~65 s and `officina` ~15 s. In the
  last 28 measured runs, 19 were commits that only touched `studio/` (plus the
  handoff). Script: `measure-ci-runs.sh`, output `measure-ci-runs.out`.
- `run.test.ts` registers 26 live rows behind `liveSkip` (`:168`). On GitHub's
  runner every one of them skips, because AppArmor blocks unprivileged user
  namespaces.

Four changes:

1. **`verdict` stores findings.** It refuses a body over 8192 bytes, and it
   refuses a non-UI body without a `## Findings` section in which every
   numbered finding names `check:`, which is the automated check that would have
   caught it. The verb is the only writer of these logs, so the refusal itself
   is the enforcement. A Codex censor hands over its final message
   (`codex exec --output-last-message <file>`), not the session log.
2. **`prune` removes gate logs no one needs**: those of a `done` opus that
   nothing outside `ci/` cites. It covers the backlog and every future `done`
   in one idempotent sweep. Certificates are unaffected, because `studio/` is
   excluded from the source-tree hash.
3. **Record-only PRs take the cheap path.** `push` runs only on `master`. On a
   PR whose diff is record-only, `gates` runs `npm ci` and `check -- studio`
   and nothing else, and `web-e2e` skips its steps. Both required jobs still
   report success, and their names are unchanged. The post-merge `master` push
   always runs the full suite, so a record that breaks a real-studio test
   (`check.test.ts` pins petitio subjects, for example) shows up within minutes
   on master.
4. **CI runs the live rows.** On the full path, `gates` installs bubblewrap and
   lifts the AppArmor userns restriction before `npm test`. A guard row then
   fails if any live row skips while `BISELLIUM_REQUIRE_LIVE_ROWS=1`.

## Interfaces

**verdict body rules.** Both run after the existing flag checks and before the
write. On refusal: exit 2, nothing written.

- The body cap applies to every phase and every kind:
  `body.length > 8192` → `verdict body is <n> bytes; the cap is 8192 — record findings, not a transcript`.
- The findings shape applies to every non-UI verdict. UI verdicts keep their
  existing rules: the shape `substantiveUiTranscript` already enforces
  (`## Findings` + `## Recommendation`) and the disposition section. Parse the
  body with the existing `contentLines` from `opus-model.ts`, exported if needed
  (no second parser). The rules:
  - There must be exactly one level-2 heading named `Findings`.
  - Within it there is at least one numbered line `^[1-9]\d*\. \S`, or the
    exact line `No findings`.
  - Every numbered line contains `check: ` followed by non-blank text: a rule
    id, a test path, or `none: <the check that should exist>`.
  - Messages: `verdict body needs exactly one "## Findings" section holding numbered findings or the exact line "No findings"`,
    and `finding <k> names no check — end it with "check: <rule id | test path | none: <missing check>>"`.
  - Other sections may exist, and the cap bounds them.

Accepted body, for example:

    ## Findings
    1. blocking — prune.ts:41 deletes a cited log — check: packages/cli/src/prune.test.ts
    2. advisory — usage text omits the cap — check: none: a usage-string pin in verdict.test.ts

**prune.** Export `pruneCiLogs(studio: string): { removed: string[] }` from
`prune.ts`. `runPrune` calls it after the branch sweep. It prints
`ci log removed: ci/<name>` per file, and prints `nothing to prune` only when
nothing at all (worktree, branch or log) was removed. No new flag.

A file `ci/<name>` is removed only when all of these hold:

- (a) `<name>` matches `^(<opus id>)-(<probatio id>)-[0-9a-f]{8}\.log$`, where
  the probatio id is one of the manifest's `probationes[].id`;
- (b) `opera/<opus id>.md` exists and its front matter has `state: done`;
- (c) the string `ci/<name>` appears in no regular file under the officina
  outside `ci/`;
- (d) `readContainedRegularFile(root, "ci/<name>", "ci")` accepts it, so
  symlinks and escapes are refused, as the lex's containment clause requires.

Reds, verdict logs, `ci/<id>.log` and every other file are never candidates.

**ci-scope.** `scripts/ci-scope.mjs` exports `recordOnly(paths: string[]): boolean`.
It returns true only if `paths` is non-empty and every path starts with
`studio/` or equals `docs/SESSION-HANDOFF.md`. Run as
`node scripts/ci-scope.mjs <base> <head>`, it runs
`git diff --name-only <base>...<head>` and prints exactly `record_only=true` or
`record_only=false`. It always exits 0. A git failure prints
`record_only=false`, so it fails closed to the full run. Node stdlib only.

**ci.yml.**

- `on: push: branches: [master]` and `pull_request:`.
- In `gates` and `web-e2e`, a step `id: scope` appends the script's line to
  `$GITHUB_OUTPUT`, using `github.event.pull_request.base.sha` as base and
  `HEAD` as head. It runs only on `pull_request`; otherwise `record_only` is
  unset, which means the full run.
- Every full-path step carries `if: steps.scope.outputs.record_only != 'true'`.
- `gates` gets one record-only step, `npm run -s check -- studio --repo .`,
  under `if: steps.scope.outputs.record_only == 'true'`. `npm ci` runs on both
  paths.
- On the full path, before `npm test`, `gates` runs the bubblewrap install and
  `sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0`. The builder
  confirms the exact apt line against `ubuntu-latest`.
- The `npm test` step carries `env: BISELLIUM_REQUIRE_LIVE_ROWS: "1"`.
- `officina` is unchanged.
- `ci-workflow.test.mjs`'s existing parity rows keep holding: gates' full-path
  `run:` steps equal `CI_STEPS` minus the studio check, in order. Prerequisite
  steps (`npm ci`, scope, bubblewrap, sysctl) and the record-only check are
  filtered out by an explicit list, not a loose match. `CI_STEPS` and
  `bisellium ci` do not change, so local CI always runs the full list. The
  string "verify" still appears nowhere in `ci.yml`.

**run.test.ts guard.** One plain `test()` row, never `live()`, so the 26-row
count W-132 pins does not change.
When `process.env.BISELLIUM_REQUIRE_LIVE_ROWS === "1"`, it asserts
`liveRows.filter((r) => r.skipped).length === 0` with a message naming the
count and `liveSkip`. Otherwise it passes. Nothing else in the file changes.

## Behaviours to test

1. `verdict` refuses a 8193-byte body (exit 2, no log, message names the cap),
   and accepts an 8192-byte findings-shaped body.
2. `verdict` refuses a non-UI body with no `## Findings`, with two of them, or
   with an empty one. It accepts `No findings`.
3. `verdict` refuses a numbered finding without `check: <text>`, naming the
   finding's number, and accepts one with it.
4. `prune` removes exactly the files that meet (a)–(d). It keeps, each in its
   own fixture: a log cited from `lessons/`, a log of a `building` opus, a
   review log, a red, a symlinked candidate and `ci/<id>.log`. A second run
   prints `nothing to prune`.
5. `recordOnly`: true for `studio/…` and `docs/SESSION-HANDOFF.md`. False for
   an empty list, `studiox/a`, `docs/ADOPTION.md` and a mixed list. The CLI
   prints `record_only=false` when given an unknown base ref.
6. `ci.yml` parity covers the triggers and the scope gating:
   - `push` names only `master`;
   - both `gates` and `web-e2e` have an `id: scope` step;
   - every full-path step carries the `!= 'true'` guard;
   - `gates` has exactly one `== 'true'` step, and it is the studio check;
   - the existing parity rows stay green.
7. `ci.yml`'s `gates` runs a bubblewrap install and the sysctl line before
   `npm test`, and its `npm test` step sets `BISELLIUM_REQUIRE_LIVE_ROWS: "1"`.
8. The guard row, named `W-131 behaviour 8: live rows: none skip where BISELLIUM_REQUIRE_LIVE_ROWS=1`,
   fails when the env is `1` and bwrap is unusable. The red command sets the
   env with `env` and makes bwrap unusable through `PATH` alone, for example
   `PATH` set to node's own bin directory. The builder confirms that the red
   replays in the replay cell.

## Acceptance

- `npm test`, typecheck, lint and format are green. `check -- studio` and
  `check -- examples/sample-studio` report 0 blocking.
- The W-131 PR's own `gates` log shows `run.test.ts` with `# skip 0`, the 26
  live rows `ok` and the guard row `ok` under `BISELLIUM_REQUIRE_LIVE_ROWS=1`.
  If a live row cannot run on the runner, the builder stops and reports it. It
  is never skipped quietly, and the env is never dropped to get green.
- After the trigger change lands on `opus/W-131`, the branch's pushes produce
  `pull_request` runs only (`gh run list --branch opus/W-131`).
- Dry measurement: `prune` run against a scratch copy of `studio/` removes the
  set `measure-ci.mjs` reports (329 files, 1460 KiB, ±the logs added since
  `8c763b7`). The builder attaches the before/after counts. The real sweep is
  the orchestrator's: after merge it runs `bisellium prune --studio studio --repo .`
  and lands the deletion as the first record-only PR, which is also the live
  check that `gates` takes the short path. That PR must show both required jobs
  green and `gates` under 2 min.
- Every verdict recorded on W-131 itself, the censor's included, is
  findings-shaped and under 8192 bytes.

## Out of scope

- Rewriting, compacting or deleting existing verdict logs, including the 13
  historic transcripts. Evidence is not backfilled; this is a Patron call (see
  the petitio in the spec report).
- Pruning reds (receipts replay them) or verdict logs (cited as evidence and
  read by the ladder).
- A `check` rule over verdict logs. `verdict` is the sole writer, and a rule
  cannot tell legacy logs from new ones without a cutoff this opus does not
  add. Follow-on only if a hand-written log ever turns up.
- A severity field in findings, transcript-marker detection, and changes to UI
  verdict shapes beyond the cap.
- `concurrency` cancel-in-progress, branch-protection settings (the Patron's),
  `officina` job semantics, and `bisellium ci`'s `CI_STEPS`.
- The censor's dispatch prompt text. The refusal messages are the contract, and
  the orchestrator's prompt points at them.
