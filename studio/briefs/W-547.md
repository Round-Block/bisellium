## Intent

While one opus waits (the merge queue and CodeQL, its `ci --opus`, a Codex review, the Patron, a dispatched builder), nothing else runs today: the lane sat idle through most of W-542's merge. The leads' overlap meet set which work may fill each wait and which may not. This opus puts that table in code: whenever `next` names a wait, it prints a `meanwhile:` line naming the one step to run now, from a ranked table keyed by the kind of wait, filtered by locks read from live state, and a `meanwhile-locks:` line naming the locks it read. The steps a wait forbids are refused by the verbs that would run them.

1. **A meanwhile step beside every wait (behaviour 1).** `meanwhile.ts` holds the five wait kinds, the table with one row per kind and `waitOf`, which reads a derivation as one kind or as no wait. `next` prints the two lines in report mode from every health branch (running, dead, invalid, unknown, anomaly, absent, finished, stale) beside a wait.
2. **Locks from live state (behaviour 2).** `readLocks` reads, failing closed on every read or shape error (Input domain), the writer lock (a live merge or done step marker of any opus), the stash lock (a stash pushed into main after a live perform took its step), the heavy-job slots in use (open `ci --opus` and `verify` run receipts in main's studio and each opus worktree's) and, through the queue, the spec ahead (the next entry's own derivation: a spec to draft, a signed spec to review, or neither).
3. **`land` refuses while a perform writes main (behaviour 3).**
4. **`retro --daily` refuses while a perform writes main (behaviour 4).**
5. **A spec review order is held while a perform writes main or main is stashed under one (behaviour 5).**

**The waits `next` emits, enumerated from the code.** `waits.py` lists every derivation site in `next.ts` (`named(`, `hold(`, `dispatch(` and the literal `status: "held"` objects, with the step, actor, role and act each sets) and reads each as `waitOf` does (`waits.out`). The kinds:

| `merge-queue` | `merge` named (a PR open or behind), or `done` with act `land` (the done commit through the queue) | the next entry's spec draft in its own worktree, drafts in the evidence folder | the daily retro and records (the perform fast-forwards main when its PR lands; a land moves master under the queue), a spec review (main moves at the landing) |

### Input domain

**The rule, once for every lock input: every input tells a valid absence from a read or shape error.** Each input below has one valid domain, one valid absence and one rejecting function. A valid absence is no lock.
