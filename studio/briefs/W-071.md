## Dependency: W-071 builds on W-069 and does not re-specify it

**W-071 must not start before W-069 has landed on the trunk.** The opus record
carries no `depends` field (W-068 would add one), so the dependency is stated
here and is binding as spec:

> W-071 requires W-069 (*the model probe battery*) to be `done` and merged
> first. W-069 delivers `<studio>/models.json` — its schema, its
> `(model, harness)` keying, its `probes[]`/`HarnessProbe` shape including
> **`harnessVersion`**, and its atomic write discipline — together with
> **four exported functions**: `probeBattery(opts)`, `runProbe(args)`,
> **`readModelsRecord(studio)`** and **`gatherCandidates({studio, listing})`**;
> plus `packages/shim/src/harness/catalog.ts`'s `codexListModels()` and
> `harnessVersions()`, the control rule, the oldest-evidence-first ordering
> and the `bisellium probe` verb. **W-071 consumes all of them and
> re-specifies none.** A builder who finds any of them absent — in
> particular either of the two named exports — has been dispatched too early
> and should **stop**, not rebuild it here.

Sol's closure pass caught revision 1 claiming to consume a reader and a
candidate union that W-069's interface did not publish (carve findings 1 and
2). W-069 revision 4 exports both; the two names above are the fix, and they
are why this dependency block is now specific rather than gestural.

Concretely:

- `computeDue`'s probe branch reads the record through W-069's **exported
  `readModelsRecord`**. W-071 adds **no** parser of its own: the shape
  validation, the tolerance for a corrupt or absent file and the
  `(model, harness)` keying are W-069's and are reused.
- `DueProbe.models` is computed over W-069's **exported `gatherCandidates`**,
  called with the listing `runTick` already fetched. W-071 gathers no
  candidates itself, so the listing filter, the `harnessForSella` default and
  the unresolvable-tier-holder rule have exactly one implementation.
- W-071's turn cap is enforced **inside W-069's `probeBattery`**, by adding
  one optional field to `ProbeBatteryOptions` (see *Interfaces*). It does not
  fork the battery, wrap it, or reimplement candidate gathering.
- The **oldest-evidence-first ordering is W-069's** and is not re-specified.
  W-069 built it because its own stop rules (failed control, 401, usage limit)
  already create a skipped tail. W-071's cap becomes a second producer of
  skipped pairs and **inherits** the property; behaviour 3 asserts the
  inheritance, not the algorithm.
- The **signed availability limit** — `available` means a minimal
  policy-profile turn, not proof the model can carry `talk`'s ~42k boot bundle
  — is W-069's and applies unchanged to everything this opus schedules.

If the producer ever runs the two in parallel, the seam is
`ProbeBatteryOptions`' shape and `models.json`'s. Both are W-069's to define.

## Intent

W-069 delivers the Patron's decreed **manual override**: an operator runs
`bisellium probe` and the record becomes honest. It does not deliver the other
two thirds of the decreed refresh policy, and the Patron's correction of
2026-09-24 is explicit about why that is not enough:

> Wait, models.json should be dynamic right? That's my point.

Recorded in `studio/briefs/W-065.md` §"Refresh policy: dynamic, split by
cost". "Operator-triggered" makes the screen assert yesterday's truth until
someone remembers to press a button. This opus is the half that removes the
remembering.

**What it delivers:** a fourth `DueItem` kind in `bisellium tick`, fired by two
triggers (age past a configured threshold, or a vendor CLI version change), a
hard bound on what automatic spend may cost, and the manifest key that makes
the cadence an informed setting rather than a constant.

**What it does not:** it runs no turns of its own, writes no record of its own,
renders nothing, and dispatches on nothing. Every turn it causes is spent by
W-069's battery under W-069's control rule, and lands in W-069's record.

**Provenance.** The refresh policy is the Patron's decree of 2026-09-24,
recorded in `studio/briefs/W-065.md`; `tick`-as-the-runner is that brief's
§"Who runs the battery: `tick`, because the precedent is exact". D-023 decrees
the side panel, the munera set, write authority and wire naming, and is cited
nowhere here.

## Why `tick`, restated once

Confirmed in `packages/cli/src/tick.ts` before writing: it already writes a
generated record on a cadence (`health.json`, always), already computes a
typed `DueItem` union via `computeDue`, already spends harness turns for due
work (the daily acta), already skips collegia at autonomy `L0`
(`computeDue:111-112`, returning `[]` when none are active), already returns
before any cadence work while paused (`tick.ts:362`), and already carries the
idempotence-before-spend discipline with the comment explaining why
(`tick.ts:121-125`). This opus adds a branch to machinery that exists; it
introduces no new runner and no new class of spend.

**One deviation from tick.ts's existing shape, stated so it does not read as
inconsistency.** `tick` reaches `talk` through a *dynamic* import behind
`loadRealTalkOnce`, because `talk.ts` did not exist when `tick` was written.
`probe.ts` exists by the time this opus starts (it is the dependency), so
`tick` imports it **statically** from `@bisellium/commands/probe.js` — it
already statically imports `@bisellium/adapter-native` and `@bisellium/shim` —
and keeps an `opts.probe` injection seam for tests. Fewer lines, same
testability.

## Interfaces

### `packages/cli/src/tick.ts`

```ts
export interface DueProbe { kind: "probe"; models: Candidate[] }
export type DueItem = DueDaily | DueAerarium | DueTraditio | DueProbe;

/** Gathered by `runTick` (async), consumed by `computeDue` (pure, sync).
 *  Absent means "not gathered" — `computeDue` then emits NO probe item, so
 *  every existing caller and test is unaffected and no test ever depends on
 *  an installed vendor binary (Sol finding 5). */
export interface ProbeInputs {
  listing?: ListedModel[];              // undefined = the listing call failed
  versions: { claude?: string; codex?: string };
  record?: ModelsRecord;                // undefined = absent or unparseable
}

export function computeDue(
  studioRoot: string, manifest: Manifest, now: Date, probe?: ProbeInputs,
): DueItem[];

export interface RunTickOptions {
  now?: Date;
  talk?: TalkFn;
  probe?: (opts: { studio: string; now: Date; only: Candidate[]; maxTurns: number }) => Promise<unknown>;
  listModels?: () => Promise<ListedModel[]>;
  versions?: () => Promise<{ claude?: string; codex?: string }>;
}

/** The ceiling on turns one automatic run may spend. `tick` always passes it;
 *  `runProbe` (an explicit operator act) passes none. */
export const MAX_PROBE_TURNS_PER_RUN = 12;
```

`Candidate`, `ListedModel` and `ModelsRecord` are **imported from W-069**, not
redeclared. `formatDue` gains `due: probe — N pair(s)`.

**`computeDue` stays pure and synchronous.** `runTick` calls
`opts.listModels ?? codexListModels` and `opts.versions ?? harnessVersions`,
reads the record through W-069's own reader, and passes the three into
`computeDue`. A listing that rejects yields `listing: undefined`, which is
**not** an empty listing: candidates then come from the manifest alone and no
codex-only pair is dropped from the due set by a failed call.

### The two triggers

At most **one** `DueProbe` per tick, naming only the pairs that need a turn.

**Age.** A pair with no `HarnessProbe`, with an unparseable `at`, or with an
`at` older than `manifest.defaults.model_probe_stale_days`. Code default **7**,
following `handoff_stale_days`' pattern at `check.ts:76` / `tick.ts:156-157`.

```yaml
defaults:
  model_probe_stale_days: 7    # default when absent
```

**Vendor version change — compared PER PAIR, against
`probes[].harnessVersion`.** A pair is version-due when the live value for its
harness is **defined** and **differs** from the **defined** `harnessVersion`
recorded on that pair's own probe. A new vendor build can change what a model
id means, so this is the stronger trigger.

> **The record's top-level `harnessVersions` is NOT the trigger's input.** It
> is a last-observed snapshot W-069 keeps because W-065's documented record
> shape carries it. A builder who compares against it has reintroduced the
> stranding bug below, and behaviour 2 includes a case where the two disagree
> precisely so that implementation fails.

`undefined` on either side is "unknown" and **never** fires (Sol note 12). The
four combinations, stated exhaustively so none is left to inference:

| pair's `harnessVersion` | live | fires? |
|---|---|---|
| defined | defined, different | **yes** |
| defined | defined, equal | no |
| defined | `undefined` (call failed) | no — and W-069 **preserves** the recorded value, so the pair stays armed for the next run that can see a version |
| `undefined` (probed before the field existed, or never probed) | defined | no version trigger; such a pair is already **age**-due, which is what draws it in |

### The stranding invariant — why per-pair, and what it fixes

Sol's closure pass found the only defect of this round that loses **work**
rather than money (carve finding 4). Against revision 1's top-level
comparison:

> codex ships a new version → five codex pairs become version-due, all with a
> fresh `at` → the cap probes two and skips three → the partial run records
> the new codex version at the top of the file → next tick the three skipped
> pairs are neither age-due (fresh `at`) nor version-due (recorded version now
> matches). **Stranded `unverified` forever.**

No ordering fixes that, because the pairs never become due again at all — it
directly contradicts the tail rotation this opus inherits and behaviour 3
asserts.

**The invariant, enforced by W-069's record shape:** *a pair's version
evidence advances only when that pair is probed.* A skipped pair keeps its old
`harnessVersion`, stays version-due, and is drained by the next run. A probed
pair carries the new one and is not re-spent. The mark-before-spend step never
writes `harnessVersion`, because no turn ran.

So the trigger **disarms per pair, exactly once per change**, with no global
gate. The two alternatives W-069 records and refuses — advancing the recorded
version only when every version-due pair was probed (one stuck pair blocks it
forever, and every tick re-spends up to the cap), and zeroing a stranded
pair's `at` (making the record lie about when the pair was last seen) — are
not to be re-proposed here either.

A battery that fails before writing leaves every unprobed pair's
`harnessVersion` untouched and the trigger still armed. That is correct, not a
loop: the next successful battery drains it.

### The cap, and why it lives in `probeBattery`

```ts
export interface ProbeBatteryOptions {
  // … W-069's fields, unchanged …
  /** Hard ceiling on turns this run may spend. Absent means no ceiling (the
   *  operator-invoked path). `tick` always passes MAX_PROBE_TURNS_PER_RUN. */
  maxTurns?: number;
}
```

Enforced **after** W-069's oldest-evidence-first ordering and **after** its
mark-before-spend step, so pairs beyond the ceiling are already `unverified`
on disk and are returned in the `skipped` array W-069 already populates. The
cap therefore adds a second producer of `skipped` and no new concept.

Sol finding 4: "five codex turns" is a measurement, not a bound. 12 is chosen
as roughly double today's 7 pairs — enough that the present catalogue never
hits it, small enough that a vendor shipping a 40-model listing cannot spend
forty turns unattended. The starvation risk a cap would otherwise create is
already closed by W-069's ordering: what a capped run skips has the oldest
evidence next run, so it heads the queue. Behaviour 3 asserts that across two
runs rather than trusting it.

`ponytail:` one constant, no manifest key. The cadence is already configurable
through `model_probe_stale_days`; a second knob for a ceiling nothing reaches
is a setting nobody would ever move.

### Autonomy, pause and dry-run — inherited, not rebuilt

`computeDue` already returns `[]` when every collegium is `L0`
(`tick.ts:111-112`); the paused path returns before any cadence work
(`tick.ts:362`); `--dry-run` prints and spends nothing. The probe branch sits
**inside** all three gates and adds no bypass. A failing battery is reported on
stderr and never fails the tick — the same posture a failing daily takes.

Numbered 1–5. These are W-069 revision 2's behaviours 14–18, renumbered for
`countBehaviours`' contiguous 1..N read (`packages/cli/src/rules/evidence.ts`).
**No red recorded against W-069 covers any of them**, and a red naming 14–18
is void here: the mapping is `14 → 1`, `15 → 2`, `16 → 3`, `17 → 4`,
`18 → 5`, and every red for this opus is recorded fresh against this opus's
own tree.

**Reds are assertion-level only if the module loads**, so the builder lands
skeletons first — `tick.ts`'s `DueProbe`/`ProbeInputs` types and the
`maxTurns` field — then records each behaviour's red from its own
single-behaviour run. `tick.test.ts` keeps its existing shape and gains a
behaviour selector if it lacks one.

**No live vendor turn, and no dependence on an installed vendor binary, in any
unit test.** Every behaviour injects `listModels`, `versions` and `probe`
through `RunTickOptions`, or a stub profile registry through W-069's
`harnesses` seam. This is the whole point of Sol finding 5's fix.

**Every behaviour carries a positive control.** None asserts only an absence:
where the point *is* an absence, the same run proves the branch executed.

**Tree-hash ancestry.** Reds are recorded on this opus's work branch, against
a tree in which **W-069 is already merged** and the skeletons above are landed
and empty. A red recorded against a tree without W-069 certifies a tree in
which the dependency was absent, and is void.

1. **`computeDue` gains a `probe` kind: pure, synchronous, injected, and built
   on W-069's two exports — and the threshold is configurable.**
   `computeDue(root, manifest, now)` with **no** `ProbeInputs` emits no probe
   item, so every existing caller and test is unaffected. With inputs: a pair
   with no `HarnessProbe`, and one whose `at` is older than the threshold, are
   both listed in `DueProbe.models`; a fresh pair is not. The due set is
   asserted to equal a subset of W-069's **exported `gatherCandidates`**
   called with the same inputs, and the record is read through its **exported
   `readModelsRecord`** — so a builder who hand-rolls either produces a set
   that diverges on the collision fixture and fails. Default 7 with no
   manifest key; a declared
   `defaults.model_probe_stale_days` overrides it, asserted against a temp
   fixture at a value that flips a pair from fresh to due. `runTick` gathers
   through `opts.listModels` / `opts.versions` — asserted by stubs that record
   their calls, so no test touches a vendor binary. `formatDue` renders
   `due: probe — N pair(s)` and the item appears in `health.json`'s `due`
   array. Positive control: a listing that **rejects** still yields the
   manifest-derived due pairs, so a branch that silently drops the probe item
   on a failed listing fails.

2. **The version trigger is per-pair, defined-vs-defined only, and it cannot
   strand a capped run.** Parameterized over the four combinations in
   *Interfaces*, each read from `probes[].harnessVersion`: (a) a pair whose
   recorded `codex` version differs from a defined live one is due though its
   `at` is fresh — positive control: the claude pairs are **not** due in the
   same run, so a branch that marks everything due fails; (b) equal defined
   values with fresh pairs → no probe item, with the positive control that the
   age path still fires for a genuinely stale pair; (c) a live `undefined` →
   no trigger, **and** the recorded per-pair value survives the following
   battery; (d) a pair with no `harnessVersion` at all is not version-due, and
   is drawn in by the age trigger instead.

   Then the two cases Sol's closure pass required, which are the point of the
   behaviour:

   **(e) the stranding interleaving.** Five codex pairs, all with a fresh `at`
   and an old `harnessVersion`; live version changed; `maxTurns: 2`. Run one
   probes 2 and skips 3. A second `computeDue` over the resulting record
   **still reports those 3 due**, and run two probes exactly them. An
   implementation that advances a single top-level version reports **nothing**
   due here and fails. This is the discriminating case for carve finding 4 and
   must not be folded into (a).

   **(f) the top-level snapshot is not the trigger.** A record whose top-level
   `harnessVersions.codex` **equals** the live value while its pairs'
   `probes[].harnessVersion` **differs** must still report those pairs due —
   so an implementation reading the snapshot fails even when no cap is
   involved.

   Finally: after a complete battery, a second `computeDue` yields no probe
   item; after a battery that fails before writing, the pairs are still armed.
   The recorded value is the raw vendor line, compared by string equality,
   never parsed.

3. **A hard cap the automatic path cannot exceed, and the tail it skips heads
   the next run.** With 5 due pairs and `maxTurns: 2`, exactly 2 `start` calls
   happen, the other 3 come back in `skipped`, and all 5 are `unverified` on
   disk (W-069's mark-before-spend, consumed not re-specified). A second run
   against the rewritten record probes **those 3 first** — the
   oldest-evidence-first property inherited from W-069, asserted across the
   cap rather than assumed. `tick` passes `MAX_PROBE_TURNS_PER_RUN`;
   `runProbe` passes none, asserted by a stub that records the option it
   received. Positive control: the same 5 pairs with no cap yield 5 `start`
   calls and an empty `skipped`.

4. **No spend without autonomy; a failing battery never fails the tick.**
   Parameterized: (a) every collegium `L0` → no probe due item and zero
   battery calls; (b) paused → only the health step, zero battery calls,
   `models.json` untouched byte-for-byte; (c) `--dry-run` → the due line
   printed, zero battery calls, no file written; (d) an injected battery that
   throws is reported on stderr, the tick still writes its receipt, and the
   exit code still comes from the check. Positive control for (a) and (b): the
   same studio at L1 and unpaused calls the battery exactly once with the
   expected pairs, so an unimplemented branch cannot pass three absences.

5. **`model_probe_stale_days` is a declared default, not an unknown one.**
   A manifest declaring it earns **no** `manifest.defaults` advisory
   (`check.ts:251`). Positive controls, both required so the assertion cannot
   pass by the rule being disabled: an actually-unknown key still raises the
   advisory, and a non-numeric `model_probe_stale_days` still **blocks**.
   `npm run -s check -- studio --repo .` and the sample-studio check both stay
   at their pre-opus finding counts.

### The attended cadence — the censor's

W-069's attended battery proved the turns. This opus's attended run proves the
**scheduling**, and costs **one battery at most** — $0.043 on the claude half
plus 5 `codex exec` turns, W-069's measured figure, and only if a trigger
actually fires.

```sh
# 0. baseline: the record is fresh, nothing is probe-due
npm run -s bisellium -- tick --studio studio --dry-run     # expect: no probe line

# 1. the version trigger — edit the PER-PAIR evidence, not the snapshot:
#    set probes[].harnessVersion to a wrong value on every codex pair.
#    (Editing the top-level harnessVersions block instead proves nothing;
#     the trigger does not read it. That is behaviour 2(f)'s whole point.)
npm run -s bisellium -- tick --studio studio --dry-run     # expect: due: probe — 5 pair(s)
npm run -s bisellium -- tick --studio studio               # one battery, codex half only
npm run -s bisellium -- tick --studio studio --dry-run     # expect: no probe line — disarmed

# 1b. the stranding guard, attended — the round's sharpest defect.
#    restore the 5 wrong per-pair versions, then run a tick with the cap
#    lowered to 2 (a temporary constant edit, reverted after):
npm run -s bisellium -- tick --studio studio               # probes 2, skips 3
npm run -s bisellium -- tick --studio studio --dry-run     # expect: due: probe — 3 pair(s)
#    "no probe line" here is the stranding bug, NOT a pass.

# 2. the age trigger
#    edit one pair's probes[].at back beyond the threshold
npm run -s bisellium -- tick --studio studio --dry-run     # expect: due: probe — 1 pair(s)

# 3. the autonomy gate — no spend, and the record is untouched
npm run -s bisellium -- pause --studio studio --reason "cadence acceptance"
npm run -s bisellium -- tick --studio studio               # health only; models.json unchanged
npm run -s bisellium -- resume --studio studio
```

Step 1's third command is the disarm proof and is the one most likely to be
skipped; a censor that does not run it has not tested the trigger.

  gathering, the control rule, the verdict table, the atomic write, the
  oldest-evidence-first ordering, `bisellium probe`, the shim catalog module,
  the `http.ts` hoist. This opus consumes all of it.
