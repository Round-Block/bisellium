## Interfaces

```ts
export interface HandoffOpus { state: string; end?: unknown }
export type HandoffInputs = { kind: "error"; reason: string } | { kind: "absent"; opera: Map<string, HandoffOpus> } | { kind: "ok"; text: string; opera: Map<string, HandoffOpus> };
/** W-186: every <studio>/opera/*.md, then <repo>/docs/SESSION-HANDOFF.md, read fail-closed; never throws. */
export function handoffInputs(repo: string, studio: string): HandoffInputs;
/** W-186: every `block` finding for one handoff text against the opera, keyed by filename id. Pure; never throws. */
export function sessionHandoffFindings(text: string, opera: ReadonlyMap<string, HandoffOpus>): Finding[];
/** W-186: an S2 rule module: [] unless `opts.repo` is set and `resolve(root) === resolve(opts.repo, "studio")`. */
export function checkSessionHandoff(root: string, opts: RuleOpts): Finding[];
/** W-186 (next.ts, module-private): a hold when the real studio's working-tree handoff is stale with this opus done. */
function handoffHold(f: Facts): StepResult | undefined;
```

**`handoffInputs`** reads the opera first, on every path:
- `readdirSync(join(studio, "opera"))` runs inside a `try`, and a throw is `error`.
- Each name ending `.md` is read with `readContainedRegularFile(studio, "opera/<name>", "opera")` and parsed with `parseFrontMatter`. A read error, a parse throw, front matter that is not a mapping, or a `state` that is not one of `STATES` (`@bisellium/adapter-native`) is `error`, naming the file. The key is the name without `.md`, and the value is `{ state, end }`.

Only then does it read the handoff, with `readContainedRegularFile(repo, "docs/SESSION-HANDOFF.md", "docs")`. `ENOENT` gives `absent` with the opera, any other error gives `error`, and success gives `ok`.

**`checkSessionHandoff`** returns `[]` outside its officina. Otherwise it calls `handoffInputs(opts.repo, root)`. `error` gives one `process.handoff.input` finding carrying the reason. `absent` gives `[]`. `ok` gives `sessionHandoffFindings(text, opera)`.

**`handoffHold`** returns `undefined` unless `f.studioRel === "studio"`. Otherwise it calls `handoffInputs(f.repo, f.studioAbs)`:
- `error` holds as `process.handoff.input`.
- `absent` runs `git(f.repo, ["ls-tree", "-z", "--name-only", "refs/heads/master", "--", "docs/SESSION-HANDOFF.md"])`. A spawn error or a non-zero exit holds. Non-empty output, meaning master keeps the file, holds as `process.handoff.input`. Empty output returns `undefined`.
- `ok` sets `f.id` to `{ state: "done", end: new Date().toISOString() }`, and holds if `sessionHandoffFindings` returns anything.

A hold is `heldResult("refusing: docs/SESSION-HANDOFF.md is stale; fix it, then re-run", …)`, with one `handoff: <rule> <where>: <message>` line per finding. `runNext` turns it into exit 1 exactly as it does a held `performDone`.

Ids, all at level `block`: `process.handoff.input`, `process.handoff.queue`, `process.handoff.resume`, `process.handoff.reference` and `process.handoff.lines`. Each appears in `process.ts` as a literal `add("<id>", …)` argument or a `rule: "<id>"` property, the shapes `HARVEST_RE` collects. `where` is `docs/SESSION-HANDOFF.md`, plus `:<line>` when the finding has a line.

**Grammar** (lexical, line-based; a section runs from its heading to the next line starting `## `). Every id the grammar reads, in Queue, Next or a status claim, that has no record is `input`.

- Exactly one `## Queue` line and exactly one line starting `## Resume point`. That line must be `## Resume point (YYYY-MM-DD)` with a real calendar date (a `Date.UTC` round trip). Anything else is `input`.
- Queue: every whole `\bW-\d+\b` token in the section, preamble and unranked paragraph included. A `done` or `halted` one is `queue`. Every `greenlit` record that the Queue never names is `queue`.
- Next field: a Resume line matching `^(- )?(\*\*)?Next\b[^:\n]*:`, plus the following non-blank lines that start with whitespace. An id named there that is `done` or `halted`, or that the Queue does not name, is `resume`.
- Status claims: in Resume, a match of `\*\*(W-\d+)\*\*[^.\n]*\b(is building|in review|waits? to merge)` for an opus that is `done` is `resume`.
- Date: the Resume date is earlier than the UTC date of the newest `end` that `instant` parses among `done` records: `resume`. An equal date passes. With no such `end`, the comparison is skipped.
- `/\bthis (one|PR)\b|\babove\)/i` on any line: `reference`. `text.split("\n").length > 100`: `lines`.

## Defaults for the Patron to veto

1. Five rule ids, all at level `block`.
2. The rule applies only to `<repo>/studio`. An absent handoff means none is kept: no finding in `check`, and no hold at `done` unless master keeps one. The records are still loaded and checked.
3. The Next field is any Resume line opening with the word `Next` and a colon on that line, together with its continuation lines. On a veto, only an exact `Next:` label is checked (the draft's rule), and today's wording goes unchecked.
4. The Queue check reads every `W-` token in the section, and requires every greenlit opus to be named, with no number threshold.
5. The relative phrases are the kept checker's three, and the line cap is 100 split entries.
6. The Resume date is compared with the newest done `end` in UTC, the real studio's manifest timezone.
7. The done-step hold runs in `runNext`'s dispatch, before `performDone`, with the opus projected `done` at the current instant.
8. One unreadable record, or one whose `state` is not a lifecycle state, makes the handoff input `process.handoff.input`, whether or not the handoff names it. `check.ts`'s own record rules block such a record too.
