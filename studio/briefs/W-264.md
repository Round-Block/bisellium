## Intent

W-255 (D-063 §4) added the light brief: four sections instead of six, admitted only because brief admission still checks its decree family, one genuine red and one `bisellium red` command per behaviour and its promise lines, and `ready` and `next` check its Red order line. Admission runs only where `bisellium.yml` declares `brief_behaviour_limit`. With the key absent, `ready` reads a light brief but runs no admission on it and `check` does not read it, so one with no family, no reds or no Red order goes to `building`; `next`'s signature gates refuse every light brief (a form error or missing light sections first, else `"Brief: light" needs a declared brief_behaviour_limit (W-264)`). W-255's spec review failed on this twice (`studio/ci/W-255-spec-2.log` #1, `studio/ci/W-255-spec-4.log` #2) and W-303's round 2 failed on the same class (`studio/ci/W-303-spec-2.log` #1): class `spec×limit-absent-admission-skips-required-validation`, lesson L-186. D-070 C asks for a cause fix.

The cause is that every caller decides for itself whether admission runs, by whether the key is present. After this opus `admissionLimit` decides for `ready` and `check`; `next`'s light-brief gate, which only ever reads a light brief, takes the same answer as no count (Interfaces):

- **A declared limit:** unchanged. `admissionLimit` returns it as is, so `ready` and `check` admit every brief they admit today under it, and `next`'s gates are untouched.
- **No limit, an exact light brief:** every admission rule except the upper behaviour count applies; an exception line is ignored, and `ready` and `next` require Red order. `ready` and `check` also pass a refused marker through admission, while `next` rejects its form error before admission. The rules that apply are the decree family, at least one numbered behaviour, one genuine red and one red command per behaviour, promise lines, whole-diff promises (W-303) and the light-brief exclusions (D-063 §4). `ready` asks for Red order once admission passes, except for a halted opus already past ready (W-166, unchanged). `ready` and `check` read a refused marker as `readBriefAdmission` does today: a full brief plus the marker error, or, for an excluded light brief, the light rules plus the exclusion.
- **No limit, a full brief:** callers still read it where required to validate or classify the spec, but do not pass it to `briefAdmissionProblems`; full-brief admission stays opt-in through the key (Defaults 1).

`check` also fails closed on its spec input with no limit: an active opus whose `spec:` names a path that `readContainedRegularFile` cannot read blocks (`<spec> unreadable: <error>`), because `check` cannot tell whether a brief it cannot read is light. An active opus that names no `spec:` is not asked for one with no limit: no brief claims to be light, and an officina that requires specs declares the `spec` probatio, whose `state.building.spec` rule already blocks it. A malformed limit stays `manifest.shape`'s block alone, with no admission, as today.

`ready` already refuses a spec `readContainedRegularFile` cannot read (exit 2), and `next` already reports a brief its source cannot read as missing its sections (`specSectionsProblem`); neither changes.

Threat model: mistakes, not adversaries (D-045).

## Interfaces

```ts
/** W-264 (L-186): the limit admission reads a brief under. */
export function admissionLimit(declared: number | undefined, briefText: string): number | undefined;
```

`declared` is `readBriefLimit`'s `limit` (a malformed key never reaches it: `runReady` and `checkStudio`, its two callers, handle that error first, as today). A declared limit is returned as is. With none, a brief for which `readBriefForm` returns `{ light: true }` or an `{ error }` gets `Number.POSITIVE_INFINITY`, and a full brief gets `undefined`, meaning the caller does not call `briefAdmissionProblems`.

`readBriefAdmission(briefText, limit)` keeps its signed two-parameter signature (`W-140-b3`). Under an infinite limit no brief is over it, so the upper-count problem cannot occur and no exception line is read; `numbers no behaviours` and the rest run unchanged.

Callers:

- `runReady`: `if (limit.limit !== undefined)` becomes `if (admissionLimit(...) !== undefined)` around the same block (admission, then the W-166 Red order check with its halted-opus grandfathering).
- `checkStudio`, for an active opus, when the key is absent or valid: with a limit, unchanged (no `spec:` blocks `active opus names no spec: brief`). With none and a `spec:` named, the brief is read; an unreadable one blocks; a readable one goes to `briefAdmissionProblems` only when `admissionLimit` returns a limit, each problem one `brief.admission` block as today. With a malformed key, `manifest.shape` blocks and no admission runs, as today.
- `lightAdmission` (called by `next`'s `specSectionsProblem` only for an exact light brief that has the four light sections, after `readBriefForm`'s error check; `signedSpec` and `reviewedSpec` call `specSectionsProblem`): `briefAdmissionProblems` under the declared limit, else `Number.POSITIVE_INFINITY`. The no-limit refusal line is removed. A malformed key still returns its error here, so `deriveNext` derives an architect order for a light brief; `gateDispatch` emits that order only when its unchanged dispatch gates pass, and otherwise holds at `spec`.
- `specOrder`'s W-196 review gate keeps `limit.limit === undefined ? []`: with no limit it is reached only after `specSectionsProblem` has admitted a light brief, or for a full brief, which it does not pass to `briefAdmissionProblems`.
