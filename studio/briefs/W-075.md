## Intent

**The measured defect.** `App.tsx` renders `TokenPrompt` as a child of
`.shell`, and `.shell` is a CSS grid — `grid-template-columns: 220px 1fr`, one
implicit row. `.token-prompt` carried **no grid placement at all**, so while it
was mounted it became a **third grid item** and auto-placed into the first
available cell: the sidebar's column. Every following item shifted one slot.
The ui-lead measured the consequence; the mounted spec reproduces it exactly:
with the prompt open, `.sidebar`'s bounding box sits at **x = 220** instead of
**x = 0** — the rail displaced out of its own column into the second one, with
the main content pushed past it.

Since `TokenPrompt` is raised on every 401 and on any load without a token in
`sessionStorage`, the displaced state is what the operator sees **first**, on
every fresh session.

**The fix's authority is W-067's own wording.** `TokenPrompt.tsx`'s header
declares the component "screen-agnostic: mounted once in App.tsx, **above the
routed screen**, never a member of any screen." A full-width row above the
sidebar and the main area is that sentence expressed in the grid. So this is
not a new layout decision needing a ui-lead or Patron ruling — it is the
existing, documented intent, which the stylesheet never implemented. No canvas
artboard draws the prompt, and none is contradicted.

**The fix, and why it is shaped this way.** `.shell:has(.token-prompt)` gives
the shell a leading `auto` row **only while the prompt is mounted**, and
`.token-prompt { grid-column: 1 / -1 }` spans it. The common case — no prompt —
matches the previous single-row grid **exactly**, because the `:has()` rule
does not apply at all. That is the whole reason for `:has()` over an
unconditional extra row: a fix for the uncommon state must not alter the common
one. `ponytail:` CSS-only; `App.tsx` is not restructured to hoist the prompt
out of `.shell`, because a grid row is the smaller change and the component's
DOM position is already what its own docs describe.

The prompt's own visual treatment (the `.token-prompt__*` rules) comes with it,
since the component shipped in W-067 with class names and **no stylesheet at
all**. Tokens only — `--wash`, `--rule`, `--amber`, `--ink`, `--ink-2`,
`--font-body`, `--font-mono`, `--sp-*`. **No new hex literal** beyond the
`#ffffff` control fills already used elsewhere in the file.

## Behaviours to test

One behaviour, one recorded red, assertion-level (lex §2,
`check: opus.red_evidence`). The number is the `--behaviour` argument and the
`ci/reds/W-075/01.log` name.

1. **Shell geometry with the token prompt open.** Against the built
   `apps/web/dist` served by a real `bisellium serve` (W-067's `startServed`),
   at **1280×800**, on a load with no token so the prompt is visible:
   `.sidebar`'s bounding box is at **x ≈ 0** with **width ≈ 220**;
   `.shell__main`'s **x ≥ 220** and **width > 600**; and `.token-prompt`'s box
   has **no rectangular overlap** with `.sidebar`'s — asserted on both axes,
   since the prompt spans the full width and must clear the rail vertically
   rather than beside it. Then the printed token is pasted and submitted: the
   prompt is **hidden**, and the same four geometry assertions still hold, so
   the fix cannot have been a compensating shift that only looks right in one
   of the two states. (`apps/web/tests-serve/layout.spec.ts`, titled
   "shell geometry with the token prompt open (W-075 behaviour 1)")

**Scope of the claim, stated precisely.** This behaviour asserts **1280×800
only**. The three breakpoints are covered by the CSS rules and verified live in
*Acceptance*; they are **not** asserted by this spec, and the brief does not
pretend they are. W-065 behaviour 15 already asserts the rail's computed
geometry at 1280, 800 and 500 — but each of its cases **dismisses the prompt
first** (`openSeats` pastes the token before measuring), so none of them ever
observed the prompt-open state. That is precisely why this defect survived a
suite that measures the shell at three widths.

Not a behaviour, so no red: the `.token-prompt__*` visual rules. They are the
component's first stylesheet and carry no contract a test would pin; the
geometry that matters is behaviour 1's.

## Recording the red — read this before the gate

**The order is disclosed, not smoothed over.** The red was recorded with
`git stash` against the **true pre-fix tree**, *after* the fix already existed
in this worktree. That is the W-046-round-3 shape, and under D-024 the order
matters, so here is exactly what happened and exactly why it is sound here:

- the spec block was written, the fix was written, the suite went green;
- the fix was then stashed, leaving the tree at **shipped `master` plus the new
  spec file**;
- the spec was run against that tree and failed at
  `expect(sidebarBox.x).toBeCloseTo(0, 0)` — **Received: 220** — which is the
  ui-lead's measured displacement;
- the fix was restored.

**Why this is not the pattern D-024 records.** D-024's forbidden act is a red
manufactured from working code by **stubbing it back to a fabricated no-op**:
the recorded state never existed as a real product, so the artifact cannot be
reproduced and is verifiable only by candour. Here the recorded state **is
shipped `master`** — the defect is the trunk's current behaviour, not a state
invented to fail. The distinguishing property is that this red is
**independently reproducible**: check out `master`, add the spec block, run it,
and it fails at `sidebarBox.x === 220`. A censor should do that rather than
take this paragraph's word for it.

`01.log`'s header records `# tree: dirty:1b16505…`, which is honest about the
tree being dirty (the spec file was present, the fix was not) and is exactly the
ambiguity **P-012** exists to remove — a working-tree identity alongside the
commit tree would have made the stashed state mechanically self-describing.
Until P-012 lands, the reproduction instruction above is the guard, and it is a
stronger one than prescription because it can be executed.

The red was run with the Playwright title selector (`-g`), never argv, so it
covers this behaviour alone.
