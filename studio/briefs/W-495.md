## Intent

The Patron, 2026-11-01: hand-typed checkpoint figures are backfilled evidence. Today `done` refuses until the history page (`docs/design/dossier/progress-body.html`) adds a row naming the opus (W-214), and, when the usage readings name the opus, until that row carries the cost phrase the refusal itself quotes (W-430). The row is written by a per-opus script (`~/.bisellium-evidence/checkpoint-w494.py` the latest) whose cycle runs to the done time, not the land, and whose cost is the phrase done quoted. W-452's row 195 carries "Claude week +0%, Codex week +0% over 7.8 h" and "about 473 min (estimate)"; W-494's row 197 "Claude week +0%, Codex week +0% over 11.1 h" and a cycle of 706 min that holds a night's idle.

**Why the cost reads +0% (pinned by `W-495-b1`, `sources.out`, `diagnose.out`).** W-430's `opusCost` gives each interval between two consecutive readings to the opus whose rung reading closes it. The session takes a script reading (`usage-reading.sh <label>`, no `opus`) seconds before most rungs it runs, and every other lane and script reading lands between an opus's rungs. So an opus's rung readings close only intervals of seconds: W-494's seven rung readings before its done closed seven intervals of 3 to 274 seconds, all +0, while the plans moved Claude +2 and Codex +2 in its cycle; W-452 closed six, all +0, while they moved Claude +7 and Codex +14. Of the 169 readings in W-452's cycle, 4 name it and 111 are the script's (646 of the file's 1035 readings are the script's). A second fault sits under it: a fall in a plan's week is read as a reset whose later value counts whole, but ten Codex falls in the file are a stale session log (an older line, the same `resets_at`: 74, 73, 74), so a span read that way counts W-452's Codex as +88. The red of behaviour 3 shows the result at once: on master, done refuses the row and quotes "Claude week +0%, Codex week +22% over 0.0 h" to paste.

This opus replaces the attribution and the paste:

1. **The plans' use over a span.** `spanCost(readings, from, to)` reads every reading up to `to` in time order, whoever took it, from the last one at or before `from`; a rise counts, a fall counts nothing unless the plan's week reset instant moved later at it. A reading also records Claude's week reset (`claude_resets`) from the status line, so Claude's reset is read as Codex's is.
2. **The figures.** A new module, `packages/cli/src/checkpoint.ts`: `checkpointFigures` computes the cycle (first spec signature to land), the lead (greenlight to land) and the cost (`spanCost` over the cycle) into one sentence, or names what is missing; `fillFigures` writes it into a row's slot.
3. **Done writes them.** While master keeps the history page, done holds until the row naming the opus carries `{{figures}}`, fills it with the sentence and commits it; a row that already carries the sentence (done run again) passes. The W-430 phrase check and its quoted fill-in go.
4. **The rung's cost line.** Each performed rung's `cost:` line is the same span read, from the first spec signature to the rung's reading.

Rows 193 to 199 (W-491, W-489, W-452, W-411, W-494, W-492, W-487) are corrected by a kept script, `scripts/checkpoint-rows.mts`, that computes the same sentence for a row already on the page (the Patron, 2026-11-02, Defaults 3: all seven).
