# W-141 — `next` lands every record-only branch of a cascade, and never half-moves the main checkout

Status: **signed spec, revision 1** · architect sella (claude-opus-5-5) · 2026-10-06.
The spec gate is written by `bisellium verdict W-141 --phase spec`, not by this text.

## Intent

Decree family: landing

The decree: **every branch a cascade puts on master lands through `next`,
and `next` never leaves the main checkout half-moved.** Today `next` lands
only `opus/<id>`. Two other heads reach master every cascade, both by hand:

- `spec/<id>`, which carries the signed brief and its spec log;
- `chore/done-<id>`, which carries the done record, the verify certificates
  and the checkpoint docs.

The title of W-141 names more than one family. This opus keeps the landing
family, which has the highest measured payoff. The receipt and verdict
commits on the opus branch are another family; see Out of scope.

**Measured at master `ce63ecc`, cascades 44–50 (7 opera).** Script and
output: `~/.bisellium-evidence/W-141-spec/measure.sh` → `measure.out`.

- **16 record-only PRs were landed by hand:** 6 spec PRs, 7 done-plus-checkpoint
  PRs and 3 filings. Each takes about eight commands: branch, add,
  `test:record`, commit, push, `gh pr create`, `gh pr merge --auto`, switch
  back. Over the same window `next` landed the 6 opus PRs by itself.
  The hand scripts are `W-1xx-spec/commit.sh`, `W-1xx-done.sh` and
  `W-1xx-checkpoint-commit.sh`. They leave heads behind: 16 local `spec/`
  and `chore/` heads and 11 `chore/` worktrees.
- **`done` cannot be performed as the ladder stands.** It held on the first
  attempt for 6 of the 8 opera it was tried on, and 4 opera never tried it.
  All 7 done commits carry `ci/<id>-{tests,lint,types}-<hash>.log`. Only
  `verify` writes those files, and `performDone` (`next.ts:923`) commits
  exactly one path, the record.
- **The checkpoint rung never completes.** `afterDone` (`next.ts:508`) looks
  for a `Where things stand` heading in the handoff. PR 223 (`cfcfff4`)
  removed that heading, so all 7 done opera still read
  `checkpoint named`. Meanwhile all 7 done commits changed
  `docs/SESSION-HANDOFF.md`.
- **One protected path broke three rungs.** W-126 (PR 244) changed
  `.claude/agents/censor.md`. In the main checkout that path is read-only
  (EROFS; so are `.claude/commands` and `.claude/settings.json`). Because
  of it, `fetchTrunk`'s `git merge --ff-only` (`integrate.ts:228`) failed
  part-way. `done`'s clean-tree guard then held on the dirty file, and so
  did `branch` for the next opus. 14 master commits touch those paths.
- **`bisellium merge`'s `pr.required` path is dead** (`branch.ts:504-521`).
  `merge` needs `done` on the opus branch. Under W-123, `done` refuses until
  the PR is MERGED, and the ladder records `done` on the trunk. Only
  `branch.test.ts` rows 14 and 21 still reach that path.

**D-016.** This opus stays inside D-016's rule: *a git operation enters the
CLI only when officina state decides whether it may happen.* Every git
operation it adds runs only as the one rung `next` derives, after that
rung's refusal:

- the spec commit, only when the trunk lacks a signed spec and the working
  tree carries one, and only those paths;
- the landing, only of `spec/<id>` or `chore/done-<id>`, only when it
  changes officina and `docs/` paths alone, and only once the derivation
  names it;
- the done commit, only after `mergeRefusal`, and only with verify's
  outputs and the checkpoint docs.

Behaviour 1 is pure refusal. Behaviour 6 removes a git path from the CLI.
D-016's *list*, however, names `commit`, `push`, `rebase` and `gh pr merge`
as "Out". W-124 already performs push, rebase and PR merge under `next`,
and this opus adds commit. So the letter of the list no longer holds, and
an amendment is needed (Patron question 3). The build does not wait for
it, because the rule itself is met.

## Interfaces

```ts
// integrate.ts
/** Repo-relative prefixes the Patron owns: no agent writes them, so the CLI never moves them in the main checkout. */
export const PATRON_PATHS: readonly string[]; // [".claude/"]
export function identifyPr(repo: string, head: string): PrRead; // was (repo, id); callers pass `opus/${id}`
```

Other helper names are the builder's choice. **The landing heads** are
`spec/<id>` and `chore/done-<id>`. A PR counts for a landing head under the
same identity rule as `opus/<id>`: head name, base `master`, not a fork,
this repository.

**The Patron lines.** Each is printed after the `why:` line of a hold. When
a path contains a character outside `[A-Za-z0-9/._-]`, it is single-quoted.

```
why: refusing: incoming paths belong to the Patron (.claude/agents/censor.md); the main checkout is untouched
patron: git -C <repo> merge --ff-only <reviewed merge oid, 40 hex>
```

```
why: refusing: the working tree has tracked changes
dirty: M .claude/agents/censor.md
patron: git -C <repo> checkout -- .claude/agents/censor.md
```

`<repo>` is the absolute path `next` resolved for `--repo`. A Patron path
is a repo-relative path that starts with any `PATRON_PATHS` entry.

**The derivations.** Each names `bisellium next <id> --perform --expect <step>`
unless a different command is stated.

| state | step | named because |
| --- | --- | --- |
| trunk lacks a signed spec; `spec/<id>` carries one | spec | `spec signed on spec/<id>, not on master` (land it) |
| trunk lacks one, no `spec/<id>`, the main checkout's working tree carries one (`specEvidence` over the officina on disk) | spec | `spec signed in the working tree, not committed` |
| merged, fetched and cleaned up; no automated certificate on the trunk record or the main checkout's record | done | command `bisellium verify <id> --studio <rel> --repo .` |
| the same, certificates present | done | `--perform --expect done` |
| `chore/done-<id>` holds the done record | done | `done committed on chore/done-<id>, not on master` (land it) |

**The checkpoint predicate.** It replaces the heading rule. The checkpoint is
complete when two conditions hold:

- the trunk record is `done`;
- the oldest master commit in which `<studio>/opera/<id>.md` reads
  `state: done` also changed `docs/SESSION-HANDOFF.md`.

Where master has no `docs/SESSION-HANDOFF.md`, the checkpoint is complete
once the record is `done`.

## Behaviours to test

All rows live in `packages/cli/src/next.test.ts` and run against its
fixture world (stub `gh`, git shim, bare origin, real verbs), except
behaviour 6, which lives in `packages/cli/src/branch.test.ts`. Each row is
named `W-141-b<n> behaviour <n>: …` and is selected by
`--test-name-pattern=W-141-b<n>`. "Nothing mutated" means four things are
byte-identical before and after the row: `git rev-parse HEAD master`, the
index (`git ls-files -s`), `git status --porcelain` and the
`.claude/agents/censor.md` bytes.

1. **A Patron path stops `next` before the main checkout moves, and names the Patron's one command.**
   - **Merge.** The world sits at `merge` with master checked out, and the
     reviewed merge commit changes `.claude/agents/censor.md`.
     `--perform --expect merge` exits 1 and prints the merge `patron:`
     line with the reviewed oid. Nothing is mutated. After the row runs
     that exact line as a command, `next` derives `cleanup`.
   - **Dirty.** A tracked edit to `.claude/agents/censor.md` makes
     `--perform --expect branch` hold. So does the same edit at the done
     rung. Each prints the `dirty:` line and the
     `checkout -- .claude/agents/censor.md` `patron:` line, and nothing is
     mutated.

   **Genuine red:** today the merge row fast-forwards master (there is no sandbox in the fixture); the row fails on its "master unmoved" assertion.

2. **`done` composes with `verify`: the rung names verify first, then commits the record and verify's certificates.**
   The world's manifest declares an automated probatio, `tests`, whose
   command is `node -e 0`. The opus is merged, fetched and cleaned up.
   - Before verify, `next` names the `bisellium verify` command, and
     `--perform --expect done` exits 1 with that command on a `why:` line.
     No `chore/done-<id>` is created.
   - The row then runs that command and makes a tracked edit to
     `docs/SESSION-HANDOFF.md`. After that, `--perform --expect done` exits 0.
     `chore/done-<id>`'s one commit changes exactly three paths: the record,
     `ci/<id>-tests-<hex>.log` and the handoff. The commit takes tracked
     `docs/` changes along with verify's outputs; nothing else is
     committed.
   - HEAD is back on master, and `git status --porcelain` lists none of
     the three paths.

   **Genuine red:** after behaviour 1, the verified world's perform holds with `the working tree has tracked changes`; the row fails on its exit-code assertion.

3. **The checkpoint rides the done commit.**
   - `--perform --expect done` refuses when `docs/SESSION-HANDOFF.md` has no
     tracked change. Its `why:` names the checkpoint, and nothing is
     mutated.
   - Once a done commit that changed the handoff is on master, `next`
     reads `checkpoint complete`. It needs no `Where things stand` heading.
   - A world whose done commit left the handoff unchanged reads
     `checkpoint named`.

   **Genuine red:** after behaviour 2, a trunk whose done commit changed a heading-less handoff reads `checkpoint named`; the row fails on its `complete` assertion.

4. **A spec signed in the main checkout is committed onto `spec/<id>`, and nothing else moves.**
   The main checkout, on master at its tip, holds three uncommitted things:
   an untracked brief, an untracked passing spec log, and an unrelated
   tracked edit to `README.md`.
   - `next` names `spec` with `spec signed in the working tree, not committed`.
   - `--perform --expect spec` exits 0. `spec/<id>` is master plus one
     commit, whose changed paths are exactly the brief and the spec log. Its
     message carries `Co-Authored-By: <spec log sella> (bisellium next)`.
   - Afterwards HEAD is master, the brief and the log are gone from the
     working tree, the `README.md` edit is still there, and `next` names the
     landing of `spec/<id>`.

   **Genuine red:** after behaviour 3, `next` derives a `spec` dispatch to the architect for that checkout (held as `dispatch budget undeclared`); the row fails on its `why` assertion.

5. **`next` lands `spec/<id>` and `chore/done-<id>` through a PR, as it lands an opus.**
   For each head, `--perform --expect <spec|done>` does the following:
   - pushes the head with `--force-with-lease`, with no `-u`;
   - creates a PR, or reuses an OPEN one. The PR title is the head commit's
     subject and the body is its body;
   - goes through `mergeGate`'s rules: a BEHIND PR is updated, a failing
     check holds, it waits for `MIN_CHECKS`, it stops on GHAS, and it uses
     `--squash --auto`;
   - once MERGED, fast-forwards master through `fetchTrunk`, where behaviour
     1's stop applies, then deletes the head locally and on origin, leased
     to the PR head.

   Then `next` reads `branch` for a spec head, or `checkpoint complete` for
   a done head that carries the handoff. A head that changes any path
   outside the officina and `docs/` is refused before the push. No `gh`
   call is made, and the refusal names the path.

   **Genuine red:** after behaviour 4, `--perform --expect spec` on `spec/<id>` performs nothing (`spec` is not performable) and makes no `gh pr create` call; the row fails on its `ghCalls` assertion.

6. **`bisellium merge` refuses under `integration.pr.required` before any git command, and names `next`.**
   In a `pr.required` fixture with `push: true`, a bare origin and an opus
   branch that is done,
   `mergeOpusBranch` returns `ok: false`. Its error names
   `bisellium next <id>`. Nothing is pushed (the bare origin has no
   `opus/<id>`), and master and the branch tip are unchanged. Without
   `pr.required`, `merge` lands as before, and every other row is unchanged.

   **Genuine red:** today the fixture rebases, pushes and returns `ok: true` with `landed: false`; the row fails on its `ok` assertion.

Each behaviour's implementation leaves the next one red (D-036):

- Behaviour 1 touches `fetchTrunk` and the dirty helper.
- Behaviour 2 touches the done derivation and the commit set, including
  tracked `docs/` changes.
- Behaviour 3 touches `afterDone` and the handoff requirement.
- Behaviour 4 touches the spec derivation from the working tree.
- Behaviour 5 makes the landing heads performable.
- Behaviour 6 lives in `branch.ts`, which none of the others touch.

## Out of scope

- **Evidence commits on the opus branch.** These are the run-receipt
  pointer commits and the review-verdict commits: 16 of each over the 7 PRs
  measured, about 4.6 per cascade, by hand (`review-receipt.sh`,
  `W-126-review-launch*.sh`). The review packet (`review-packet.sh`) belongs
  with them. They are their own family, "evidence-commit", and should be
  filed as one follow-on opus.
- **Filing PRs** (`new` plus `greenlight` plus the handoff; 3 in the
  window). They come before the ladder, which starts at `greenlight`, so
  there is no rung to perform them. They are a follow-on that can reuse
  behaviour 5's landing for a `chore/file-<id>` head.
- **Sweeping the heads and worktrees** that the hand scripts left
  (16 heads, 11 worktrees). This is a follow-on for `prune`.
- **`next` running `verify` itself.** Verify runs `npm test`, which takes
  8–10 minutes. The rung names it, and the orchestrator runs it, under
  `--track` if it wants health reads.
- **A local `test:record` before a landing push.** CI's record-only path runs
  it (W-139), and `mergeGate` waits for that check.
- **The handoff text** that a spec PR used to carry (W-140's spec commit
  edited the handoff). Handoff edits ride the done PR.
- **`docs/SESSION-HANDOFF.md`'s "Opus ladder gotchas".** The producer trims
  them at the checkpoint after this lands.

**Open questions for the Patron.** Each default ships as stated and can be
vetoed at the checkpoint.

1. **Which paths are the Patron's.** Default: the prefix `.claude/`. It is a
   superset of your rule (`.claude/agents/*`) and of every path measured
   read-only in the main checkout (`agents`, `commands`, `settings.json`).
   The alternative is exactly `.claude/agents/`.
2. **The command printed when `merge` stops.** Default:
   `git -C <clone> merge --ff-only <reviewed oid>`. The stop comes before the
   tree moves, so `checkout -- <path>` alone would not move master.
   `git -C <clone> checkout -- <path>` is printed instead for a Patron path
   that is already dirty, for example the half-update W-126 left. The
   handoff's current `reset --hard origin/master` is dropped, because it is
   destructive.
3. **D-016 needs an amendment.** Default: amend. The architect records
   D-037 when you say yes, and the build does not wait. Drafted text: *"The
   rule of D-016 stands. Its 'Out' list is read through the rule: `add`,
   `commit`, `push`, `rebase` and `gh pr merge` stay out as verbs of their
   own. `next` performs them only as the one rung its derivation names, and
   refuses in every other state (W-124, W-141). The CLI never moves a
   Patron path in the main checkout; it stops and prints your command."*
   Kill when: `next` performs a git operation in a state its derivation did
   not name, or an adopter needs a raw git verb.
4. **The checkpoint rides the done PR.** Default: yes, and `done` refuses
   without a handoff change. This matches all 7 cascades measured. The
   alternative is a separate checkpoint PR, one more PR per cascade.
5. **Landing performs push, PR and merge in one call** (behaviour 5). An opus
   splits these into its `pr` and `merge` rungs. Default: one call, because
   a record-only head has no review gate to sit between them. A re-run
   reuses the OPEN PR.
