## Intent

The build-review perform (`next <id> --perform --expect review`, `reviewSteps`) starts and resumes the reviewer's Codex session with the opus worktree as its working directory (`const call = { cwd: wt.dir, ... }`). Codex loads `AGENTS.md` from its working directory's repository, so the reviewer reads the opus branch's `AGENTS.md` as standing instructions; `AGENTS.md` is generated, not code-owned, so an opus can rewrite its own reviewer's instructions. Measured on codex-cli 0.153.4 through the shipped shim (`probe.out`): a session started in a linked worktree loads that worktree's `AGENTS.md` and not the main checkout's; started in the main checkout it loads the main checkout's and not the worktree's; and a resume reloads `AGENTS.md` from the working directory it is resumed in.

After this opus the perform runs Codex with the main checkout (`f.repo`, the `--repo` that `runNext` has already proven is not a linked worktree) as its working directory, for a fresh round and a resumed one, so the reviewer loads master's `AGENTS.md` as the main checkout carries it. Because the reviewer's relative paths would now resolve in the main checkout, the round-1 prompt names the opus's own files by absolute path under the worktree: the two computed focus lines name `<worktree>/studio/briefs/<id>.md` and `<worktree>/studio/ci/reds/<id>/`, and the shipped template names the spec, its spec verdicts, the gate logs and the reds under `<WORKTREE>` and tells the reviewer its working directory is the main checkout.

Design. Two candidates were weighed; this opus takes (a), another working directory, with the main checkout as that directory:

- (a) moves one value in `reviewSteps`, a caller the shim already lets choose its working directory (`HarnessStartOpts.cwd`), keeps the reviewer reading the project's standing instructions (master's, which is the intended reading), and leaves every other Codex caller unchanged.
- (b) `-c project_doc_max_bytes=0` works (`probe-b.out`: no `AGENTS.md` loads in the worktree), but it goes in `CODEX_POLICY_FLAGS`, the one fixed policy every Codex caller shares and no caller may configure (W-044, W-049): `talk`'s Codex sellae would lose the project's instructions too, and the reviewer would lose master's. Rejected.
- The packet directory as the working directory was weighed and set aside: it lies under the main checkout, so Codex walks up to the same repository root and loads the same `AGENTS.md`, plus any `AGENTS.md` in the directories between, for no gain.

Cause fix: this closes W-315's stated `AGENTS.md` limit for the build-review perform. Every other path that runs a reviewer's Codex was checked (Limits): the spec-review and handoff-review paths already run outside the opus checkout, and one advisory kept script does not.

Threat model: mistakes, not adversaries (D-045). The main checkout is the orchestrator's; its working copy is read as it stands.

Bootstrap: this opus is reviewed under master's ladder, never its own (Patron 2026-10-18). Its build rounds run master's `reviewSteps` from the main checkout, which runs Codex in this opus's worktree, so its reviewer loads this branch's `AGENTS.md`; this opus does not edit `AGENTS.md`, and its edits leave the generated `AGENTS.md` unchanged (`instructions-proto.out`), so that file is master's at the branch point. Its round 1 is filled from master's `prompts/build-review.md` read from the main checkout (W-314), whose relative paths name files in the checkout master's code runs Codex in, so its sentences hold for it; its later rounds take master's `prompts/later-round.md`. Its spec rounds run from the kept scripts in the main checkout. The new working directory and text govern from the next opus.

### Input domain

A rejection fails closed: `runNext` exits 2 with a usage line before any step is derived, performed or recorded. A test row whose own read fails throws, which fails the row.

| Record | Valid domain | Rejected by |
|---|---|---|
| `f.repo`, the reviewer's working directory (new use; the `--repo` `next` runs with) | the repository's main checkout: a git repository whose git directory is its common directory | `runNext` (existing): `git rev-parse --git-dir`/`--git-common-dir` failing exits 2, `<repo> is not a git repository`; a linked worktree exits 2, `<repo> is a linked worktree; run next from the repository's main checkout` |
| The `AGENTS.md` Codex loads from that working directory | read by the reviewer (Codex), not by code | limit: no code reads it; Codex's own discovery, measured (`probe.out`) |
| `wt.studio` in the focus lines | `join(wt.dir, studioRel)`, the opus worktree's studio, already required usable before the perform reaches the prompt | `reviewSteps` (existing): an unusable worktree holds `refusing: <dir> is not a usable worktree on opus/<id>` before any read |
| The test rows' fixture writes (the stub's call log, the reply file, the advanced source and the handoff) | files the rows write | `appendFileSync` and `writeFileSync` in the stub and the rows, and the fixture `git` (which asserts exit 0): a failure throws, which fails the row |
