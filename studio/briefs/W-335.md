## Intent

D-039 high. The merge queue's `gates` job runs `npm test` with NODE_OPTIONS `--import ${{ github.workspace }}/scripts/record-reads.mjs` and BISELLIUM_RECORD_READS a log, then `node scripts/ci-scope.mjs --check-reads <log>` (W-139). The guard fails when `package.json`'s `test:record` does not name exactly the tests that read the record-only set. The builder's own gate, `bisellium ci --opus`, runs neither: CI_STEPS' `npm test` is handed to the gate runner as the `tests` gate (`npm test -s`, W-279), untraced. So a test that reads `studio/` or the handoff but is missing from `test:record` passes the builder's gates and review, and fails only in the merge queue, about an hour later: #488 (W-279) and #614 (W-288, `unlisted: packages/cli/src/rules/doc-cap.test.ts (read docs/SESSION-HANDOFF.md)`).

After this opus, a checkout whose `package.json` declares `test:record` runs CI_STEPS' `npm test` as `node scripts/test-reads.mjs`, a new script that is ci.yml's two steps as one command. Plain `bisellium ci` runs it in the step's place. `ci --opus` runs it as each gate the gate runner would have run as `npm test`. A missing or extra `test:record` entry then fails the `tests` gate, whose log names the check and its problems, and `ci --opus` exits 1 before the record can pass to review (W-312 admits only `exit code: 0` gate logs). A checkout with no `test:record` (every ci fixture today, any other repository) runs `npm test` as before.

The record leaves four questions to this brief:

1. **How ci runs the tests step with the read log and fails on the guard as ci.yml does.** `scripts/test-reads.mjs` runs `npm test` in its own checkout with NODE_OPTIONS `--import <checkout>/scripts/record-reads.mjs` and BISELLIUM_RECORD_READS a log in a fresh temp directory. Only when that exits 0 does it run `node scripts/ci-scope.mjs --check-reads <log>`, ci.yml's guard command, unchanged. It exits with the first non-zero status. The guard's own rules (`checkReads`: unlisted, unread, unattributed, malformed, root and `.fail` checks) are W-139's, reused, not copied. Plain ci runs the wrapper for the `npm test` step too, because ci.yml's full path does (Defaults 1).
2. **Whether the gate log names the check.** It does, at the log's end. `localPipeline` writes a gate's stdout, then its stderr, and keeps the last 200 lines; the real suite writes about 1271 lines to stderr (`~/.bisellium-evidence/W-335-build/accept/`), so a line the wrapper printed on stdout is cut off: revision 1 put the check on stdout, and the build's `ci/W-335-tests-3279789f.log` ends in vendor-sentinel stderr with neither line in it. Ruling (revision 2): the wrapper prints `test-reads: node scripts/ci-scope.mjs --check-reads <log>` on stderr and runs the guard with its stdout on the wrapper's stderr, so that line and the guard's problems or `record_reads=ok` come after everything npm test wrote, and are the log's last lines; `scripts/ci-scope.mjs` is unchanged. Why: the opus exists so that a missing `test:record` entry fails before review with its cause readable, and two lines in one script keep that true. Amending the promise to the `command:` line alone would leave a failing check's cause out of the log; making `localPipeline` keep the two streams in order would change every gate's log for this one gate. The log's `command:` line is `node scripts/test-reads.mjs`. Plain ci's failure line names the wrapper: `bisellium ci: step failed (exit 1): node scripts/test-reads.mjs`.
3. **How a missing preload or an unreadable log fails closed.** With `scripts/record-reads.mjs` missing, node refuses to start npm under `--import`, npm test exits non-zero, and the wrapper exits with that status before the guard. A log the guard cannot read is the guard's `missing: <path>`, exit 1, and so is a log no process wrote. A half-written log, a `.fail` marker, or a root that never ended is one of `checkReads`' problems. The wrapper starts its own trace. It drops an inherited NODE_OPTIONS and the `BISELLIUM_RECORD_*` keys, so an outer traced run (ci.yml's own `npm test` reaching a test that runs the wrapper) cannot add a second root to its log. The guard runs with no NODE_OPTIONS, as ci.yml's step does.
4. **One source, so ci.yml's steps and the local one cannot drift.** The wrapper exports `TEST` (`npm test`), `PRELOAD` (`scripts/record-reads.mjs`) and `CHECK` (`scripts/ci-scope.mjs --check-reads`) and builds what it runs from them. `W-335-b1` pins them to ci.yml: the gates step whose run is `TEST` carries NODE_OPTIONS `--import ${{ github.workspace }}/<PRELOAD>`, and the step after it is `node <CHECK> ${{ runner.temp }}/record-reads.log`. ci.yml itself does not change (it is code-owned); `scripts/ci-workflow.test.mjs` keeps CI_STEPS equal to ci.yml's run lines, and W-139's own row keeps the step's env shape.

Promise read-check: in a checkout whose package.json declares `test:record`, plain `bisellium ci` and `ci --opus` run CI_STEPS' `npm test` as `node scripts/test-reads.mjs`, which runs `npm test` under the read log and then ci.yml's `--check-reads` guard, and fails the step, or the gate and so `ci --opus`, on any problem the guard reports; the guard's own read of package.json after npm test is the authority for the list, so a test that edits package.json changes what is checked — limit: a direct `bisellium verify` runs the manifest's `npm test -s` untraced (no ci in front of it); a `tests` gate whose command does not normalise to `npm test` runs as declared; the merge queue's `certify` mint runs the wrapper only once its tooling commit holds this opus (W-335's own merge does not); ci.yml's live-row guard (BISELLIUM_REQUIRE_LIVE_ROWS) stays ci.yml's.

Promise fails-closed: a missing preload, a failing `npm test`, an absent or unreadable log, and an inherited trace each end the wrapper non-zero or are dropped before `npm test` starts, and no `record_reads=ok` is printed for a run that did not trace — limit: the guard's own rules and the preload's record-then-read invariant are W-139's code, reused unchanged, a stated limit, not a guarantee (D-076 E).

Promise names-the-cause: the `tests` gate log of `ci --opus` ends with the wrapper's `test-reads:` line and then the guard's problems or `record_reads=ok`, after every line npm test wrote to either stream — limit: `localPipeline`'s stdout-then-stderr order and its 200-line tail are unchanged code, a stated limit, not a guarantee (D-076 E); a guard that prints more than 200 lines shows its last 200.

Promise one-source: the wrapper's `TEST`, `PRELOAD` and `CHECK` are pinned equal to ci.yml's gates step and guard step by `W-335-b1`, and CI_STEPS stays pinned to ci.yml by `scripts/ci-workflow.test.mjs` — limit: ci.yml's runner-only parts (`${{ runner.temp }}` for the log, the job's other env) are read as text, not run.

Threat model: mistakes, not adversaries (D-045). A branch that deletes `test:record` from package.json turns the check off locally; ci.yml's guard then fails it with `no commands`.
