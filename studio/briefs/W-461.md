## Intent

The merge queue's `certify` replays every recorded red at the commit it was recorded on (`scripts/run-builder-host.mjs:722-735`, the tree lookup, then `identifyRebased`), and before it runs the red it builds the web bundle in the replay's cell whenever the checkout carries `apps/web/package.json` (`:747-759`: `WEB_BUILD`, then `WEB_BUNDLE` must exist, else `prepFailure`). A series that builds only at its tip is refused there, after everything else has been spent on it. W-408's PR #859 was: its reds were replayed from the signed prototype (`next W-408 --perform --expect reds`, W-326), and the perform commits a test patch, records the red, commits the implementation, and builds nothing in between. Behaviour 1's implementation imported `apps/web/src/lib/officinaWork.ts`, which only behaviour 2 added, so six of the ten commits did not build (`/home/edckt/.bisellium-evidence/W-408-build/series-fix/survey-old.txt`), and certify, after build review round 1 and the Patron's screen approval, refused:

`run-builder-host: red 2 replay preparation failed: web bundle build exited 1` (`/home/edckt/.bisellium-evidence/W-408-build/certify-859/certify-40861078866/_temp/certify.log:338`).

This opus runs that same build at the moment each commit of the series is made, so the series is refused before handoff, review and the Patron's screens:

- **`red`** builds the web bundle at the commit it is about to record on, and refuses, recording nothing, when it does not build, with certify's own line. That commit is exactly the one certify will replay the red at, so this is certify's check, run early. `red` is the one verb both makers of a series pass through: a builder records its own reds with it, and the replay perform records each red by calling it (`next.ts` `performReds`, `runRed`).
- **the reds perform** also builds each implementation commit right after it commits it, and holds at the first that does not build, before the next red is recorded on it. That names the implementation that broke the build, and covers the tip, which no red sits on.

Why these two places, and not `ready`, `ci --opus` or certify itself: certify judges red commits, and `red` is where a red commit becomes one; a check there cannot be skipped by either maker and costs nothing to a commit certify never replays. `ready` and the build gates run after the series is made, and would have to re-derive certify's red-to-commit mapping (`identifyRebased` and all), a second copy that could drift. Certify itself is not changed: the build's command, the file it must leave and the failure line are imported from `scripts/host-cells.mjs` (`WEB_BUILD`, `WEB_BUNDLE`, `prepFailure`), the module certify's runner imports them from, so the two cannot drift in what they build or how they say it failed. Only a new declaration file is added beside it (`scripts/host-cells.d.mts`, types only, no runtime code).

The cost, measured and bounded: one web bundle build is about 0.5 s on this repository (`web-build-time.out`: 0.61 s wall; `w408-demo.out`: 433 to 565 ms per commit over W-408's ten). The bound is one build per red recorded under "Red order: one at a time", plus one per implementation commit in a replay perform: at most 2n builds for n behaviours, each capped at certify's own 10 minutes (`WEB_BUILD_TIMEOUT_MS`). A checkout without `apps/web/package.json` builds nothing, as in certify. No diff-based skip ("only when the commit touches apps/web"): at 0.5 s a build is cheaper than the second rule a skip would be, and a skip is a condition certify does not have, so it would be a place for the two to drift.

This opus's own merge (W-323): nothing changes what certify runs or how. `scripts/run-builder-host.mjs`, `scripts/host-cells.mjs`, `scripts/ci-certify.mjs` and `scripts/ci-certificate.mjs` are untouched; nothing splits out to land first. The one file added under `scripts/` is a declaration file no runner loads.

Threat model: mistakes, not adversaries (D-045). The build runs the candidate's own `apps/web` build script in the caller's checkout, as the served suite and `npm test` already do there.

## Interfaces

**`webBuild(root: string): WebBuild`** (exported from `packages/commands/src/web-build.ts`): it never throws. It reads `<root>/apps/web/package.json` with `statSync`: `ENOENT` or `ENOTDIR` is `{ carried: false }` and nothing runs (certify's own condition, `run-builder-host.mjs:748`, reads the same path with `existsSync`); any other error is `ok: false`, kind `inspect`. Present, it removes `<root>/apps/web/dist/index.html` (`rmSync` with `force`, so an absent path is no error); an error there (a directory at that path, a permission) is `ok: false`, kind `cleanup`, and nothing is built. It then runs `WEB_BUILD` (`npm --workspace @bisellium/web run build`) with `cwd` `root`, a timeout of `WEB_BUILD_TIMEOUT_MS` (600 000 ms, certify's) and the caller's environment, inside a `try`, and returns `{ carried: true, ok: true }` when it exits 0 and `WEB_BUNDLE` then exists; else `{ carried: true, ok: false, kind, status, tail, detail? }`, `kind` `spawn` (a spawn error, the timeout, an output overflow or a throw), `exit` (a non-zero exit, `status` its code) or `bundle` (exit 0 and no bundle); `tail` is the last 4096 characters of its stdout and stderr (empty when it never ran) and `detail` the error code behind `inspect`, `cleanup` or `spawn`. The removal comes first so a bundle left by an earlier build never stands in for this commit's (certify's checkout is a fresh clone, which has none).

**`webBuildFailure(behaviour, failure): string`**: for `exit`, `spawn` and `bundle`, `prepFailure(behaviour, kind, status)`, certify's line, e.g. `red 2 replay preparation failed: web bundle build exited 1`; for this checkout's own two kinds, which certify's fresh clone never meets, the same prefix and `apps/web/package.json cannot be inspected (<code>)` or `the prior apps/web/dist/index.html cannot be removed (<code>)`. **`webBuildReason(failure)`**: the same without its `red <k> replay preparation failed: ` prefix, e.g. `web bundle build exited 1`, for a commit no red sits on.

**`red`**, under "Red order: one at a time", after the existing checks (clean `tree:` identity, the repository root, HEAD on `opus/<id>`, plain arguments, the prerequisite list, the ticket) and before any prerequisite or the red's command runs: `webBuild(<repository root>)`. On `ok: false` it prints `red: <webBuildFailure(behaviour)> at <short HEAD>: certify's replay builds the web bundle at this commit and would refuse this red — nothing recorded` to stderr, then the build's tail; it does not create the red log or claim its ticket, and exits 1; the attempted build may have changed ignored web artifacts (the removed prior bundle, a failed build's partial `apps/web/dist/`). A red without the opt-in builds nothing, as before.

**`next <id> --perform --expect reds`**: after each behaviour's implementation is committed (`git am`), `webBuild(<worktree>)`; on `ok: false` (any kind) the perform holds with `behaviour <k>'s implementation does not build at <short HEAD>: <webBuildReason>; certify's replay would refuse the series`, keeping every commit made so far, as its other holds do (W-326: the replay runs once; the next derivation names a builder).

Promise red: a red recorded under "Red order: one at a time" in a checkout that carries the web workspace is recorded only at a commit where certify's own build command exits 0 and leaves `apps/web/dist/index.html`; at any other commit `red` refuses with certify's preparation line and the commit, and records nothing. So a builder-made series certify would refuse at a red's preparation is refused when that red is recorded. Pinned by `W-461-b1` "a red at a commit whose web bundle does not build is refused" and pinned by `W-461-b1` "the refusal is certify's own preparation line, at the commit" — limit: the build runs in place in the caller's checkout and environment, not in certify's fresh clone and confined cell, so an ignored file the checkout holds (a stale `apps/web/node_modules`, an ignored `.env`) or a difference in installed modules can make the two disagree; `WEB_BUILD`, `WEB_BUNDLE`, `prepFailure` and the runner's replay are reused unchanged and not promised here (D-076 E).

Promise bundle: a build that exits 0 but leaves no bundle is refused the same way, and a bundle left by an earlier build does not count: it is removed first, and a prior bundle path that cannot be removed (a directory there) is itself refused, with no exception. Pinned by `W-461-b1` "a build that leaves no bundle is refused, a stale bundle notwithstanding" and pinned by `W-461-b1` "an invalid or unremovable stale bundle is refused without throwing" — limit: after the build only the existence of `apps/web/dist/index.html` is checked, as certify checks it (`existsSync`, so a directory the build itself leaves there is accepted at that commit, as certify accepts it, and the next build in the same checkout then refuses at cleanup).

Promise recorded: a red at a commit that builds is recorded as before. Pinned by `W-461-b1` "a red at a commit that builds is recorded" — limit: the rest of `red` is reused unchanged.

Promise perform: the replay perform builds each implementation commit and holds at the first that does not build, naming the behaviour and the commit, with every earlier commit kept and no red recorded on the commit that does not build; the tip is built too. So a replayed series like W-408's holds at its first implementation instead of reaching review. Pinned by `W-461-b2` "a series whose first implementation does not build holds" and pinned by `W-461-b2` "the hold names behaviour 1's implementation and certify's build failure" and pinned by `W-461-b2` "what was committed is kept, and no red is recorded on the commit that does not build" and pinned by `W-461-b2` "a series whose last implementation does not build holds" and pinned by `W-461-b2` "a bundle path the next build cannot remove holds the perform without throwing" — limit: W-408's own series is shown once through the helper, not through a perform (`w408-demo.out`: behaviour 1's implementation c80e3a71 is the first commit that does not build, as the survey and certify found); `amPatch`, the attempt marker and the perform's hold path are reused unchanged.

Promise good: a series that builds at every commit is performed as before. Pinned by `W-461-b2` "a series that builds at every commit is performed" — limit: the rest of the perform is reused unchanged.

Limits, stated:

- Unchanged code the promises lean on is a stated limit, not a guarantee (D-076 E): `scripts/host-cells.mjs` (`WEB_BUILD`, `WEB_BUNDLE`, `prepFailure`), `scripts/run-builder-host.mjs`, `scripts/replay-accept.mjs`, `scripts/ci-certify.mjs`, the rest of `bisellium red` and of the reds perform, npm and the web workspace's own `vite build`.
- A red recorded without "Red order: one at a time" builds nothing: such a red may record a `dirty:` tree, which certify refuses anyway.
- A builder-made series is checked at its red commits, the commits certify replays. An implementation the next red sits on is covered through that red; the builder's last implementation (the tip) and any commit no red sits on are not built by `red`. The tip is built by the gates' served suite, as today.
- A series rewritten after its reds are recorded (a rebase; W-462 is the reviewed-branch rewrite step) is not re-checked here; certify still is the last word.
- Certify's replay is not run: the rows build a fixture web workspace whose `build` script is a small node program, not vite; the real build is shown once on W-408's commits (`w408-demo.out`) and timed (`web-build-time.out`).
