# W-087 — the Board respects the Patron's eyes: full card titles, the drawer carries the record body, times localized DD/MM/YY HH:MM, and the drawer never covers Done and Halted — four Patron decrees from the first live reading

Draft for architect signature, 2026-09-25. This is one small Board correction:
four visible defects, four numbered behaviours, and no change to the Board's
read-only authority.

## Measured present state

### 1. Card titles are present in the DOM and hidden by CSS

`BoardView.tsx:58-63` renders the gate ladder, the complete title in one
`.board__card-title` span, then the sella/state row. The loss is entirely
layout: `w025.css:1074-1086` fixes every card at 64px, while
`w025.css:1096-1103` clamps the title to two 18px lines and hides overflow.
That is literal clipping, not missing data. It also implements the old dossier
sentence at `docs/design/DIRECTION.md:216-218`; this Patron decree supersedes
that sentence and the 64px fixed-height part of the density target.

Cards become **64px minimum, not 64px fixed**. A title uses normal wrapping,
has no line clamp, ellipsis, fixed title height, or hidden overflow, and every
character remains visible. Multi-word prose wraps at word boundaries; an
intrinsically unbreakable token may wrap inside the token to stay within the
288px column, but no character is clipped. The ladder stays first and the
sella/state row stays last. Variable card height is the necessary consequence
of showing the whole title, not a fifth design change.

### 2. The drawer's collection row drops a body the server already knows

The Board fetches `/api/opera` (`Board.tsx:16,79-85`) and constructs its drawer
from the selected `OpusEntry` in that collection (`Board.tsx:271`). Today
`Store.api.opera()` maps id, title, kind, collegium, sella, state, tokens,
probationes and traditio, but not the adapter's record body
(`apps/server/src/store.ts:260-275`). `GET /api/opera` forwards that array
without another projection (`apps/server/src/http.ts:599-603`), and the client
type correspondingly has no `body` (`apps/web/src/api.ts:149-164`). The drawer
therefore can only derive traditio and token rows (`lib/board.ts:295-322`), and
its “From the officina record” section has no body slot
(`BoardDrawer.tsx:77-97`).

The server already has two proofs that no parser or new route is needed. The
native snapshot places `readFront`'s body in `opus.meta.notes`
(`adapters/native/src/index.ts:262-288`), and the per-item endpoint already
returns `body` (`store.ts:278-293`, forwarded at `http.ts:605-611`). W-076's
petitio precedent makes the intended shape explicit: body is a **required
string**, carried untruncated, with the empty string represented honestly
(`studio/briefs/W-076.md:142-166`); the live mapping now does exactly that for
petitiones (`store.ts:308-311`).

For this opus, `/api/opera` gains required `body: string`, sourced from the
snapshot row's `meta.notes` and defaulting to `""` only when a malformed or
non-native row supplies no string. The HTTP route itself does not change. This
keeps the drawer on its existing reconciled collection instead of adding a
selection-time request and loading state. The measured cost on this branch is
5,492 UTF-8 bytes across 94 opera (19 non-empty; largest 753 bytes); the sample
studio used by the served tests is 463 bytes across seven.

`OpusEntry` and `DrawerDetail` carry the required field. The record section
renders it first as escaped plain text, untruncated, with authored newlines
preserved (`white-space: pre-wrap`); markdown source remains source, with no
renderer or dependency. An empty string renders the explicit placeholder “No
record body.”, the same honest empty-body pattern W-076 retained for the Inbox.
Tokens and traditio remain below it unchanged.

### 3. Four Board surfaces currently expose raw ISO timestamps

The required display is exactly `DD/MM/YY HH:MM`, 24-hour time, in the
**viewer's browser timezone** — not UTC and not the officina's configured
timezone. The current raw paths are:

1. `Board.tsx:70-72` records a refresh as ISO; `liveLabel` interpolates that
   string unchanged at `lib/board.ts:199-209`; `BoardView.tsx:140` renders it.
2. `drawerDetail` copies each event's `e.ts` unchanged at
   `lib/board.ts:311-323`; `BoardDrawer.tsx:69-73` renders `e.at` unchanged.
3. The Board's colophon is also a timestamp surface: `BoardView.tsx:141`
   delegates with no generated-at value, so `Colophon.tsx:16-23` creates a raw
   ISO render-time string and `Colophon.tsx:37` prints it. “Every timestamp”
   includes this third path even though the decree's two reported examples were
   liveness and event rows.
4. **Signing amendment (architect, 2026-09-25):** the drawer's record section is
   a fourth path the draft missed. `drawerDetail` pushes every non-empty string
   value in `traditio` as a record row (`lib/board.ts:295-301`), and `traditio.at`
   is an ISO instant — so an open drawer prints e.g. `2026-09-17T10:42:00Z`
   verbatim under “From the officina record”
   (`examples/sample-studio/opera/W-002.md:20`). Only the `at` key is an instant;
   `sella`, `stage`, `next` and `blocked_on` stay untouched, and `evidence`/
   `certifies` values contain no `T` or trailing `Z`. Without this path,
   behaviour 3's “no raw ISO anywhere in the Board subtree” sweep cannot pass and
   a builder would have to either weaken the assertion or localize this row
   unspecified.

One exported pure helper in `lib/board.ts` parses an ISO instant and assembles
the result from `Intl.DateTimeFormat(...).formatToParts()` with two-digit day,
month, year, hour and minute and `hourCycle: "h23"`. Production omits the
`timeZone` option so the browser supplies the viewer's zone; the helper accepts
an optional zone only to make its unit rows deterministic. Invalid input yields
`—`, never raw source text or `Invalid Date`.

`liveLabel`, drawer event view-model rows, the traditio `at` record row, and the
value BoardView passes to `Colophon` all use that helper. Event ordering, the
traditio row order and the meaning of `lastRefreshAt` do not change; seconds are
deliberately not rendered.

`Colophon.tsx`'s `generatedAt` prop is documented “ISO timestamp” and rendered
verbatim; the Board now hands it a formatted display string. That prop's doc
comment is therefore in scope as a **comment-only** edit — no behaviour, type or
markup change, and no other caller of `Colophon` is touched. A shared seam is not
silently redefined by a stale comment.

### 4. The drawer becomes a pushed panel, not an overlay

The current geometry is deterministic. On desktop the shell is a 220px rail
plus the main area (`w025.css:11-15`); the Board track is horizontally
scrollable, with 288px fixed columns, 16px gaps and 24px side padding
(`w025.css:1003-1026`; `tokens.css:22`). The native lifecycle yields seven
visible Board columns — Needs you plus Planned, In progress, Verifying,
Awaiting review, Done and Halted (`adapters/native/src/index.ts:38-45`) — a
2,160px track including six gaps and both paddings. The drawer is presently
`position: fixed; right: 0; width: 540px` (`w025.css:1133-1148`), so it paints
over the track. At a 1280px viewport the main area is 1060px and the overlay
leaves only 520px unobscured; Done and Halted together need 592px before track
padding. Tablet changes the rail to 72px and the drawer to
`min(540px, 100vw - 72px)` (`w025.css:107-113,1263-1273`); phone makes the
drawer 100vw (`w025.css:1276-1312`).

The chosen mechanism is **push layout**. `Board.tsx` gives BoardView and
BoardDrawer a single full-height `.board-workspace` grid. With no selection it
has one `minmax(0, 1fr)` Board cell. With a drawer it has
`minmax(0, 1fr) <drawer-width>`: 540px desktop, today's tablet expression, and
100vw on phone. The drawer stops being fixed and occupies the right-hand grid
cell; the Board rail remains mounted, live and independently scrollable in the
left cell. At phone width the Board cell collapses to zero while remaining
mounted and is restored on close. This preserves the current drawer widths,
the one drawer shadow, close/focus behaviour and saved Board scroll offset.

There is no drawer/Board intersection at any breakpoint. At 1440px, after the
220px rail and 540px drawer, 680px remains: enough for Done and Halted together
(592px plus the track's 48px padding). The served test scrolls the track to its
end and proves both columns' right edges are at or left of the drawer's left
edge. This opus does not also narrow the drawer or auto-scroll the Board; those
would be second mechanisms.

Push layout is **mechanics chosen to implement the decree literally**, not a new
design ruling. Its residual is look-and-feel and belongs to the Patron: at 1280px
the Board keeps 520px, at 800px a 188px sliver, and at phone width zero (mounted,
restored on close). Signed with that residual flagged, not decided — if the
Patron prefers a narrower drawer, an auto-scroll on open, or a drawer that
collapses the rail, that is a follow-on ruling and a builder must not fold it in
here.

## Behaviours to test

Each numbered behaviour gets one assertion-level recorded red. Use
`apps/web/tests-serve/board.spec.ts` for what a Patron can observe against a
built app and temp sample studio; keep deterministic formatter edge cases in
`apps/web/src/lib/board.test.ts` rather than testing `Intl` through static
markup alone.

1. **Full titles are visible and cards grow.** In a 1280px served Chromium
   viewport, replace one temp opus title before opening the Board with a
   multi-word string long enough to require at least four 18px lines. The card
   title's visible text equals the complete source string; computed line clamp
   is none and overflow is not hidden; title `scrollHeight <= clientHeight`;
   the card is taller than 64px; and the sella/state row remains below the last
   title line. Include one overlong unbroken token and assert all characters
   remain visible inside the 288px card. This row replaces W-064's old exact
   64px assertion rather than leaving contradictory tests.

2. **The served drawer carries the complete opus body.** Give W-004 in the temp
   studio a multi-paragraph body over 2KB containing newlines and literal
   markdown/HTML-like text. `GET /api/opera` returns one W-004 row whose required
   `body` exactly equals the adapter-normalized record body, with no truncation;
   opening W-004 renders the same complete text in
   `.board-drawer__record-body`, escaped, with computed `white-space: pre-wrap`.
   Opening body-less W-002 renders “No record body.” and never `undefined`.
   This single mounted row covers store → HTTP → client type/use → drawer; a
   store-only unit would not prove the Patron receives it.

3. **Every rendered Board time has the one local shape.** Pure rows pin the
   helper: `2026-09-25T11:58:00.000Z` in `Asia/Singapore` is exactly
   `25/09/26 19:58`, the same instant in `America/New_York` is exactly
   `25/09/26 07:58`, midnight uses `00` rather than `24`, and invalid input is
   `—`. A served Chromium context with `timezoneId: "Asia/Singapore"` appends a
   fixed event at that instant and asserts the drawer row is exactly
   `25/09/26 19:58`; once the initial reconciliation and drawer fetch finish,
   the liveness value, the Board colophon timestamp and the drawer's traditio
   `at` record row each match `\d{2}/\d{2}/\d{2} \d{2}:\d{2}`, and the Board
   subtree — with that drawer open — contains no ISO
   timestamp matching `\d{4}-\d{2}-\d{2}T` or a trailing `Z`.

4. **The pushed drawer has zero overlap with Done and Halted.** At 1440×900,
   open a drawer, scroll the Board track to its end, and assert Done and Halted
   are both in the viewport, each column's right edge is no greater than the
   drawer's left edge, and the Board workspace cell's right edge equals the
   drawer's left edge within one CSS pixel. Repeat the boundary assertion at
   800px and 390px; the tablet Board cell remains a narrow independently
   scrollable region and the phone Board cell is zero-width, while the Board
   DOM stays mounted and live. Close the drawer and assert the Board regains the
   full main width and its pre-open `scrollLeft`. No assertion auto-scrolls on
   open or expects a drawer narrower than today's widths.

## For Sol

These are the calls I am least confident about; the implementation above is
deliberate, but these are the useful attack surfaces for the signing pass.

1. **Collection body versus the existing item route.** I chose the W-076 shape:
   carry a required body on the collection the drawer already reconciles. It
   adds 5.5KB to today's 94-row response and avoids new fetch/loading/error
   state. `GET /api/opus/:id` already carries the same body, so Sol should
   challenge whether future payload growth outweighs that simplicity. If it
   does, this is a design change, not a mechanical substitution: selection,
   reconnect targets and drawer absence/loading semantics all need specifying.
2. **The narrow pushed Board.** At 1280px push layout leaves 520px; at 800px it
   leaves 188px; at phone width it leaves zero while remaining mounted. That is
   the strongest literal implementation of “never covers”, but whether the
   188px tablet sliver looks useful is a residual **Patron look-and-feel call**.
   The builder must not quietly combine a narrower drawer or auto-scroll to
   improve it. Sol should ensure the Patron sees that trade before signature.
3. **Plain pre-wrapped body and empty copy.** W-076 is the precedent for literal,
   untruncated source and an explicit empty placeholder, so I reused it. The
   words “No record body.” and the choice not to render markdown are still
   visible-product judgments; if the Patron wants different copy or rendered
   markdown, that ruling belongs before build.
4. **The colophon is in scope.** The request named liveness and event rows, but
   said “every timestamp the Board renders.” I included the otherwise-easy-to-
   miss render-time ISO from `Colophon`. Sol should reject that only by making
   an explicit exception to “every”, not by overlooking the third path.
