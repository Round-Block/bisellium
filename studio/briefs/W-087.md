# W-087 — the Board respects the Patron's eyes: bounded card titles with a full-title affordance, the drawer carries the record body, times localized DD/MM/YY HH:MM, and the drawer never covers Done and Halted — four Patron decrees from the first live reading

**Revision 2**, 2026-09-26, architect-signed (one signing amendment, marked in
§3, to the 390px summary allocation). It
amends revision 1's architect-signed baseline to close the ui-lead's eight
findings without adding a behaviour: four visible defects, four numbered
behaviours, four recorded reds, and no change to the Board's read-only authority.

## Measured present state

### 1. Card titles are present in the DOM and hidden by CSS

`BoardView.tsx:58-63` renders the gate ladder, the complete title in one
`.board__card-title` span, then the sella/state row. The loss is entirely
layout: `w025.css:1074-1086` fixes every card at 64px, while
`w025.css:1096-1103` clamps the title to two 18px lines and hides overflow.
That is literal clipping, not missing data. It also implements the old dossier
sentence at `docs/design/DIRECTION.md:216-218`; this Patron decree supersedes
that sentence and the 64px fixed-height part of the density target.

Cards become **64px minimum and 108px maximum**, not 64px fixed. The exact CSS
contract is `.board__card { min-height: 64px; height: auto; max-height: 108px;
flex-shrink: 0; }`,
`.board__card-title { display: -webkit-box; -webkit-box-orient: vertical;
-webkit-line-clamp: 4; overflow: hidden; overflow-wrap: anywhere; }`, and
`.board__card-meta { line-height: 14px; }`. With the existing 6px ladder, two
4px flex gaps and 8px total vertical padding, four 18px title lines plus the
14px metadata line fit exactly in the 108px border box. The ladder stays first
and the sella/state row stays last.

The full title remains the span's text and is also its native hover affordance:
the markup is exactly
`<span className="board__card-title" title={card.title}>{card.title}</span>`.
There is no drawer interaction or bespoke tooltip. Multi-word prose wraps at
word boundaries; an intrinsically unbreakable token may break inside itself to
stay within the 288px column. Text beyond four visual lines is visually
clamped, never allowed to make one 300-character title destroy column
scanability, and remains available verbatim through the native `title`
attribute. This supersedes both the old two-line truncation and revision 1's
unbounded-growth prescription.

### 2. The drawer's collection row drops a body the server already knows

The Board fetches `/api/opera` (`Board.tsx:16,79-85`) and constructs its drawer
from the selected `OpusEntry` in that collection (`Board.tsx:271`). Today
`Store.api.opera()` maps id, title, kind, collegium, sella, state, tokens,
probationes and traditio, but not the adapter's record body
(`apps/server/src/store.ts:260-275`). `GET /api/opera` forwards that array
without another projection (`apps/server/src/http.ts:599-603`), and the client
type correspondingly has no `body` (`apps/web/src/api.ts:149-164`). The drawer
therefore can only derive traditio and token rows (`lib/board.ts:295-322`), and
its “From the officina record” section has no body slot
(`BoardDrawer.tsx:77-97`).

The server already has two proofs that no parser or new route is needed. The
native snapshot places `readFront`'s body in `opus.meta.notes`
(`adapters/native/src/index.ts:262-288`), and the per-item endpoint already
returns `body` (`store.ts:278-293`, forwarded at `http.ts:605-611`). W-076's
petitio precedent makes the intended shape explicit: body is a **required
string**, carried untruncated, with the empty string represented honestly
(`studio/briefs/W-076.md:142-166`); the live mapping now does exactly that for
petitiones (`store.ts:308-311`).

For this opus, `/api/opera` gains required `body: string`, sourced from the
snapshot row's `meta.notes` and defaulting to `""` only when a malformed or
non-native row supplies no string. The HTTP route itself does not change. This
keeps the drawer on its existing reconciled collection instead of adding a
selection-time request and loading state. The measured cost on this branch is
5,492 UTF-8 bytes across 94 opera (19 non-empty; largest 753 bytes); the sample
studio used by the served tests is 463 bytes across seven.

`OpusEntry` and `DrawerDetail` carry the required field. The record section
renders it first as escaped plain text, untruncated, with authored newlines
preserved (`white-space: pre-wrap`); markdown source remains source, with no
renderer or dependency. This CSS is a W-087 decision pinned by the served
computed-style row below, **not** a shipped W-076 precedent: W-076 explicitly
withdrew its proposed `pre-wrap` (`studio/briefs/W-076.md:170-182`). An empty
string renders the explicit placeholder “No record body.”, reusing only
W-076's honest empty-body pattern. Tokens and traditio remain below it
unchanged.

### 3. Four Board surfaces currently expose raw ISO timestamps

The Patron's decree is exactly `DD/MM/YY HH:MM`, 24-hour time, in the
**viewer's browser timezone** — not UTC and not the officina's configured
timezone. The ui-lead's HELD clarification is preserved: this ordering is not
an implementation suggestion or a locale-dependent choice. Localized display
strings are never sort keys; any event ordering or later comparison continues
to use the raw machine timestamp, and formatting happens only after ordering.
The current raw paths are:

1. `Board.tsx:70-72` records a refresh as ISO; `liveLabel` interpolates that
   string unchanged at `lib/board.ts:199-209`; `BoardView.tsx:140` renders it.
2. `drawerDetail` copies each event's `e.ts` unchanged at
   `lib/board.ts:311-323`; `BoardDrawer.tsx:69-73` renders `e.at` unchanged.
3. The Board's colophon is also a timestamp surface: `BoardView.tsx:141`
   delegates with no generated-at value, so `Colophon.tsx:16-23` creates a raw
   ISO render-time string and `Colophon.tsx:37` prints it. “Every timestamp”
   includes this third path even though the decree's two reported examples were
   liveness and event rows.
4. **Signing amendment (architect, 2026-09-25):** the drawer's record section is
   a fourth path the draft missed. `drawerDetail` pushes every non-empty string
   value in `traditio` as a record row (`lib/board.ts:295-301`), and `traditio.at`
   is an ISO instant — so an open drawer prints e.g. `2026-09-17T10:42:00Z`
   verbatim under “From the officina record”
   (`examples/sample-studio/opera/W-002.md:20`). Only the `at` key is an instant;
   `sella`, `stage`, `next` and `blocked_on` stay untouched, and `evidence`/
   `certifies` values contain no `T` or trailing `Z`. This structured `at`
   field is therefore one of behaviour 3's four named timestamp surfaces; the
   negative assertion deliberately does not inspect the other verbatim record
   rows.

One exported pure helper in `lib/board.ts` parses an ISO instant and assembles
the result from `Intl.DateTimeFormat(...).formatToParts()` with two-digit day,
month, year, hour and minute and `hourCycle: "h23"`. Production omits the
`timeZone` option so the browser supplies the viewer's zone; the helper accepts
an optional zone only to make its unit rows deterministic. Invalid input yields
`—`, never raw source text or `Invalid Date`.

`liveLabel`, drawer event view-model rows, the traditio `at` record row, and the
value BoardView passes to `Colophon` all use that helper. Event ordering, the
traditio row order and the meaning of `lastRefreshAt` do not change; seconds are
deliberately not rendered.

The no-ISO assertion is scoped to **UI-produced timestamp display fields**:
`.board__liveness`, the Board colophon's generated-at value,
`.board-drawer__event-at`, and the record row whose label is exactly `at`.
It is not a text-content sweep over the Board subtree. Verbatim record content
— titles, record bodies, and traditio free-text such as `next` or `blocked_on`
— remains byte-faithful and may legitimately contain text that looks like an
ISO instant. The served fixture deliberately puts ISO-like text in those three
categories and proves it survives while the four timestamp fields contain no
raw ISO value. Other traditio keys are not guessed to be instants.

The localized event string is 14 characters, so the existing 64px allocation
at `w025.css:1246-1251` is replaced by
`.board-drawer__event-at { width: 112px; flex: 0 0 112px;
white-space: nowrap; }`; `.board-drawer__event-summary` gains `min-width: 0;
flex: 1`. The row stays one flex line, the timestamp never wraps, and even the
390px drawer leaves 218px for summary text after its 48px horizontal section
padding and 12px gap (`390 - 48 - 12 - 112 = 218`).

**Signing amendment (architect, 2026-09-26):** 218 is the arithmetic value with
no scrollbar. `.board-drawer` is itself `overflow-y: auto`, and at 390×844 the
open drawer's content is taller than the viewport, so a classic scrollbar can
take ~15px out of the section's content box. The binding property is therefore
the residual identity — the summary takes the event row's whole remaining
content width, `rowContent - 112 - 12` — with 218px as its value when the drawer
shows no scrollbar. A builder must not shrink the 112px slot or add
`scrollbar-gutter` to make a literal 218 appear.

`Colophon.tsx`'s `generatedAt` prop is documented “ISO timestamp” and rendered
verbatim; the Board now hands it a formatted display string. That prop's doc
comment is therefore in scope as a **comment-only** edit — no behaviour, type or
markup change, and no other caller of `Colophon` is touched. A shared seam is not
silently redefined by a stale comment.

### 4. The drawer becomes a pushed panel, not an overlay

The current geometry is deterministic. On desktop the shell is a 220px rail
plus the main area (`w025.css:11-15`); the Board track is horizontally
scrollable, with 288px fixed columns, 16px gaps and 24px side padding
(`w025.css:1003-1026`; `tokens.css:22`). The native lifecycle yields seven
visible Board columns — Needs you plus Planned, In progress, Verifying,
Awaiting review, Done and Halted (`adapters/native/src/index.ts:38-45`) — a
2,160px track including six gaps and both paddings. The drawer is presently
`position: fixed; right: 0; width: 540px` (`w025.css:1133-1148`), so it paints
over the track. At a 1280px viewport the main area is 1060px and the overlay
leaves only 520px unobscured; Done and Halted together need 592px before track
padding. Tablet changes the rail to 72px and the drawer to
`min(540px, 100vw - 72px)` (`w025.css:107-113,1263-1273`); phone makes the
drawer 100vw (`w025.css:1276-1312`).

The chosen mechanism is **push layout**. `Board.tsx` gives BoardView and
BoardDrawer a single full-height `.board-workspace` grid. With no selection it
has one `minmax(0, 1fr)` Board cell. With a drawer it has
`minmax(0, 1fr) <drawer-width>`: 540px desktop, today's tablet expression, and
100vw on phone. The drawer stops being fixed and occupies the right-hand grid
cell; the Board rail remains mounted, live and independently scrollable in the
left cell. At phone width the Board cell collapses to zero while remaining
mounted and is restored on close. This preserves the current drawer widths,
the one drawer shadow and saved Board scroll offset.

Opening moves DOM focus, after the drawer has mounted, to the visible
`.board-drawer__close` button. This applies at every width and is required at
widths where the Board cell collapses: focus must not remain on the now-hidden
card. Escape or activating Close restores the saved Board width and
`scrollLeft`, then restores focus to the selected card (or the existing
nearest-card/column-head fallback if reconciliation removed it). No focus
target is `document.body`.

There is no drawer/Board intersection at any breakpoint. The binding width
table leaves no builder discretion (`V` is viewport width):

| Viewport | Shell rail | Drawer grid track | Board grid track with drawer | Pinning |
|---|---:|---:|---:|---|
| `V >= 900` | 220px | 540px | `V - 760px`; exactly **140px at 900**, 520px at 1280, 680px at 1440 | Needs-you remains sticky |
| `613 <= V <= 899` | 72px | 540px | `V - 612px`; exactly 1px at 613, 188px at 800, 287px at 899 | Needs-you is static |
| `600 <= V <= 612` | 72px | `V - 72px` | exactly **0px throughout**, including 600 and 612 | Needs-you is static |
| `V <= 599` | top rail, 0px horizontal | `V` | exactly 0px | Needs-you is static |

At 1440px the prior draft's claim that 680px shows both Done and Halted was
false because it omitted W-064's sticky 288px Needs-you column
(`w025.css:1028-1033`). Needs-you plus both terminal columns, two 16px gaps and
48px track padding require 944px. The 680px residual can instead show the
pinned column plus **one** complete terminal column: `288 + 288 + 16 + 48 =
640px`, leaving 40px. The served test therefore visits Done and Halted at
separate horizontal positions. At each position it proves the terminal column
is wholly to the right of the pinned column and wholly to the left of the
drawer; both remain reachable, neither is ever covered, and the workspace-cell
boundary equals the drawer boundary. This opus does not narrow the drawer or
auto-scroll the Board.

Push layout is **mechanics chosen to implement the decree literally**, not a new
design ruling. Its residual is look-and-feel and belongs to the Patron: the
table's narrow and zero-width tracks are explicit consequences of revision 2's
proposed mechanism. If the Patron later prefers a narrower drawer, auto-scroll on open,
or a drawer that collapses the rail, that is a follow-on ruling and a builder
must not fold it in here.

## Behaviours to test

Each numbered behaviour gets one assertion-level recorded red. Use
`apps/web/tests-serve/board.spec.ts` for what a Patron can observe against a
built app and temp sample studio; keep deterministic formatter edge cases in
`apps/web/src/lib/board.test.ts` rather than testing `Intl` through static
markup alone.

1. **Titles have a four-line cap and a verbatim native affordance.** In a
   1280px served Chromium viewport, replace one temp opus title before opening
   the Board with a 300-character value containing multi-word prose and one
   overlong unbroken token. The `.board__card-title` textContent and its
   `title` attribute both equal the complete source string. Its computed
   `-webkit-line-clamp` is `4`, overflow is hidden, `overflow-wrap` is
   `anywhere`, its client height is 72px and its scroll height is greater than
   its client height. The card's computed border-box height is 108px, never
   greater; its gate ladder and sella/state row remain visible inside that box.
   A short-title card remains 64px. This row replaces W-064's old exact-64px
   assertion and revision 1's unbounded-growth assertion.

2. **The served drawer carries the complete opus body.** Give W-004 in the temp
   studio a multi-paragraph body over 2KB containing newlines and literal
   markdown/HTML-like text. `GET /api/opera` returns one W-004 row whose required
   `body` exactly equals the adapter-normalized record body, with no truncation;
   opening W-004 renders the same complete text in
   `.board-drawer__record-body`, escaped, with computed `white-space: pre-wrap`.
   Opening body-less W-002 renders “No record body.” and never `undefined`.
   This single mounted row covers store → HTTP → client type/use → drawer; a
   store-only unit would not prove the Patron receives it.

3. **Every rendered Board time has the one local shape.** Pure rows pin the
   helper: `2026-09-25T11:58:00.000Z` in `Asia/Singapore` is exactly
   `25/09/26 19:58`, the same instant in `America/New_York` is exactly
   `25/09/26 07:58`, midnight uses `00` rather than `24`, and invalid input is
   `—`. A served Chromium context with `timezoneId: "Asia/Singapore"` appends a
   fixed event at that instant and asserts the drawer row is exactly
   `25/09/26 19:58`; once the initial reconciliation and drawer fetch finish,
   the liveness value, the Board colophon timestamp and the drawer's traditio
   `at` record row each match `\d{2}/\d{2}/\d{2} \d{2}:\d{2}`. Assert those
   four timestamp fields individually contain neither
   `\d{4}-\d{2}-\d{2}T` nor a trailing `Z`; do not sweep arbitrary subtree
   text. Give a title, body and traditio `next` value ISO-like text and assert
   each is preserved and does not fail the timestamp check. Use raw event
   timestamps whose chronological order differs from lexicographic
   `DD/MM/YY` order and prove the established newest-first order is unchanged:
   no localized string becomes a sort key. Finally, the event timestamp has
   computed width and flex-basis 112px, stays on one line, shows all 14
   characters, and at 390px the summary retains its row's whole residual —
   width equal to the event row's content width minus the 112px slot and the
   12px gap, which is 218px when the drawer shows no scrollbar.

4. **The pushed drawer has zero overlap with reachable Done and Halted.** At
   1440×900, open a drawer and assert the sticky Needs-you column is visible.
   Scroll first to a position that exposes all of Done and then to the end that
   exposes all of Halted; at each position the terminal column's left edge is
   no less than the pinned column's right edge and its right edge is no greater
   than the drawer's left edge. Do not assert both terminal columns are fully
   visible at once. The Board cell is exactly 680px and its right edge equals
   the drawer's left edge within one CSS pixel. Repeat the track-width/boundary
   assertion at 800px (188px), 900px (140px), 613px (1px), 612px (0), 606px
   (0), 600px (0) and 390px (0), with the Board DOM mounted and live throughout.
   On every open, and specifically when the source card's cell becomes 0px,
   `document.activeElement` is the visible `.board-drawer__close` button. Close
   by Escape and by button; assert the Board regains full main width and its
   pre-open `scrollLeft`, and focus returns to the source card or the specified
   reconciliation fallback. No assertion auto-scrolls on open or expects a
   drawer narrower than today's widths.

## For Sol

Revision 2 closes the ui-lead pass above. These deliberate product choices
remain useful regression attack surfaces; they are not open builder choices.

1. **Collection body versus the existing item route.** I chose the W-076 shape:
   carry a required body on the collection the drawer already reconciles. It
   adds 5.5KB to today's 94-row response and avoids new fetch/loading/error
   state. `GET /api/opus/:id` already carries the same body, so Sol should
   challenge whether future payload growth outweighs that simplicity. If it
   does, this is a design change, not a mechanical substitution: selection,
   reconnect targets and drawer absence/loading semantics all need specifying.
2. **The narrow pushed Board.** At 900px push layout leaves 140px; from 600
   through 612px and at phone width it leaves zero while remaining mounted.
   Those residuals and Close-button focus are specified by this draft. A narrower drawer or
   auto-scroll is a follow-on, not a builder improvement.
3. **Plain pre-wrapped body and empty copy.** W-076 is precedent only for the
   required untruncated body and explicit empty placeholder; it withdrew its
   own `pre-wrap`. W-087 deliberately makes and tests that CSS choice itself.
   Markdown rendering or different empty copy remains outside this build.
4. **The colophon is in scope.** The request named liveness and event rows, but
   said “every timestamp the Board renders.” I included the otherwise-easy-to-
   miss render-time ISO from `Colophon`. Sol should reject that only by making
   an explicit exception to “every”, not by overlooking the third path.
