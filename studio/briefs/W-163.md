# W-163 — the build fails on a raw date parse of record data or a raw officina file access outside the approved helpers

Status: **signed spec, revision 2** · architect sella (claude-opus-5-5) · 2026-10-07.
Revision 2 (after build round 3, L-078/W-162) bounds the census's input domain
to the forms a builder writes by mistake (Input domain, Out of scope, default 8).
The spec gate is written by `bisellium verdict W-163 --phase spec`, not by this text.
Builds on W-137's tree: W-137 merges first, and this opus branches after it.

## Intent

Decree family: safe-helpers

The decree: **record dates are read by one strict parser, and officina
files are read and written only through the contained helpers. A source
scan that runs in the build lists every raw date parse and every raw file
read or write written as a direct call, and refuses any other handle on fs
or `Date` a builder could write by mistake. Each listed site is approved,
fixed, or kept with a written reason, and a new one fails the build until
someone decides which.** The scan catches mistakes, not evasion (Input
domain, default 8).

D-039 rates this high. The same three classes reached review in four opera:

- **Lenient dates.** W-120 r1 #1: `instant` accepted `2026-02-30`. W-137
  r1 #3: a regex check, then `Date.parse`, which turns `2026-02-30` into 2
  March. W-153: `completion.ts` reads dates with `new Date(v)`.
- **Uncontained reads and writes.** W-137 r1 #2 found a symlinked
  `opera/<id>.md` read outside the officina, and a symlinked `acta/` parent
  that let a write escape.
- **Per-site patching** (L-069). Each round found one more site. This brief
  names one rejection point per input (W-161) and closes each class with one
  scan, not one more patch.

**Extend, don't add (D-042).** ESLint 10 and typescript-eslint are installed,
and `npm run -s lint` runs in CI (`.github/workflows/ci.yml:37`). But the
config is deliberately untyped (`eslint.config.mjs` header). Without types,
`no-restricted-syntax` cannot tell `new Date(isoString)` from
`new Date(epochMs)`: 13 of the 42 single-argument `new Date` calls at master
take a number. It also cannot tell an officina path from any other path, so
all 294 file sites would need a per-line `eslint-disable` comment. Those
comments are self-serve: any file can excuse itself, and no list of reasons
ever gathers in one place. The W-047 census in
`packages/cli/src/containment.test.ts` already solves this shape. It does an
AST scan of the same source roots, keys each site by function name (so a
reformat does not move it), and pins a list with a disposition and a reason
for each site. It runs in `npm test`, which CI runs, and
`scripts/safe-item-path-mutants.mjs census` proves it bites. So this opus is
**an extension of that census**: inventory C for dates (typed through the
TypeScript compiler API, which is already installed) and inventory D for
file access. It adds no ESLint rule and no dependency. Default 1 lets the
Patron ask for the ESLint form instead.

**Inventory C (a raw date parse)** is either of these:
- every `Date.parse(x)`;
- every single-argument `new Date(x)` whose argument the type checker does
  not type as number-like or `Date`.

A string literal argument is not record data and is not a site.

**The `Date` member allowlist (fail closed).** On `Date` (or
`globalThis.Date`), the only member uses are the callee of a direct call
`Date.parse(…)` (a C site), `Date.UTC(…)` and `Date.now()`. Together with
`new Date(…)`, `Date(…)`, `instanceof Date`, `typeof Date` and type
positions, that is every allowed use of `Date`. Any other member access,
such as `Date.prototype`, `Date.length`, or `Date.now` not called, is an
out-of-domain finding. At `26fe11b` no non-test source uses one, so the
allowlist adds no pin.

**Inventory D (raw file access)** is every call bound from a static import
of `fs`, `node:fs`, `fs/promises` or `node:fs/promises` (a named, namespace
or default binding) to one of these:
- `readFileSync`, `readFile`, `openSync`, `open`, `createReadStream`;
- `writeFileSync`, `writeFile`, `appendFileSync`, `appendFile`,
  `createWriteStream`;
- `mkdirSync`, `mkdir`, `rmSync`, `rm`, `rmdirSync`, `unlinkSync`, `unlink`;
- `renameSync`, `rename`, `copyFileSync`, `copyFile`, `cpSync`,
  `symlinkSync`, `truncateSync`.

**Source set for C and D.** Non-test `.ts`/`.tsx` under `packages/`,
`apps/` and `adapters/`, plus `scripts/*.mjs`. Excluded: `node_modules`,
`dist`, `*.test.*`, `*.spec.ts`, `*.d.ts`, `test/` and `tests-serve/`.
Inventory C builds one `ts.createProgram` over this set to read argument
types.

**Dispositions.**

| Disposition | Meaning | How the census checks it |
|---|---|---|
| `helper` | Inside an approved helper's own body: schema `instant`, opus-model's ordering `instant`, `readContainedRegularFile`, `createNextRecord`. | Mechanical: `fn` is in that list and the file is the helper's file. |
| `contained` (D only) | The path went through a helper in the same function. | Mechanical, as a necessary condition: the enclosing function also calls `requireRealDirectory`, `readContainedRegularFile` or `createNextRecord`. The censor judges that the call covers this path. |
| `guarded` | Every caller checks the path first. | Judged. `why` names the callers. |
| `outside` | The path is never under an officina: repo files, `.bisellium/`, OS temp, `/proc`, git dirs, a template shipped in the package, a user-named `--from` file, fd 0. | Judged. `why` says which. |
| `listed` | A raw officina access, kept. | Judged. `why` gives the reason and the follow-on. |

`why` is non-empty for every entry.

**The bright line: what is fixed now, never `listed`.** In `packages/cli`
and `packages/commands`:

- (a) Every write into an officina subdirectory: write, append, mkdir,
  unlink, rm, rename or copy under `acta/`, `ci/`, `opera/`, `briefs/`,
  `petitiones/`, `decisions/`, `lessons/`, `aerarium/`, `receipts/` or
  `timeline/`. It ends `contained` through `requireRealDirectory` on the
  target's directory, or through `createNextRecord`.
- (b) Every read whose officina path is built from an id, a directory-listed
  name, a flag value or a record value. It ends `contained` through
  `readContainedRegularFile`, and the returned `bytes` are used. There is no
  second raw read of the same path.

Everything else may be `guarded`, `outside` or `listed` with a reason:

- fixed-name files at the officina root (`bisellium.yml`, `milestones.yml`,
  `health.json`);
- `init`, which creates the tree;
- core, shim, the server, adapters/native and `scripts/`.

### Input domain

Each input has one valid domain and one place that rejects anything outside
it. A rejection fails closed: the input is never skipped and never read as
a default.

| Input | Valid domain | Rejected by |
|---|---|---|
| a record date or a `--now` value | A `Date` with a finite time. Or a string `YYYY-MM-DD`, optionally followed by `T` or a space and `HH:MM[:SS[.f{1,9}]]`, then optionally `Z` or `±HH[:]MM` (hours ≤ 23, minutes ≤ 59), whose fields round-trip with no JS normalisation. No zone means UTC. Anything else, including numbers, `2026-02-30`, `24:00` and trailing text, is outside the domain. | `instant` (schema), the one parser. A caller turns `undefined` into the refusal it already has: `--now must be an ISO date` and exit 2 for a flag; the rule's own finding for a check rule; "unreadable" for a reader (completion's "No estimate", `next`'s hold). It never substitutes `now`, `0` or a lenient parse. |
| a directory an officina write lands in | A real directory whose real path equals the lexical path built from the officina's real root, with no symlink in any component. | `requireRealDirectory`, called in the writing function before the first write. The verb exits non-zero and writes nothing outside. |
| an officina file read by a derived name | `readContainedRegularFile`'s domain: a relative path under `expectedDir`, a regular file, no symlink in any component, real parent and real target inside. | `readContainedRegularFile`. The verb refuses, or the rule reports. |
| the census's input: the source set | The forms a builder writes by mistake. Every file parses (no `parseDiagnostics`). File access is bound only through the static imports above. An fs function, an fs namespace, `Date.parse` or the `Date` constructor is used only as a direct call (or `new`). `Date` is used only through its allowlist. Every scanned site has exactly one pin, every pin has a scanned site, keys are unique, dispositions come from the table, and `helper`/`contained` pass their mechanical checks. Reflection and prototype-chain routes are outside the domain (Out of scope). | `containment.test.ts`. Each of these fails the run and is never skipped: a `require("fs")`, a `createRequire`-bound `fs`, a dynamic `import("node:fs")`, an `export … from "node:fs"`, any alias, destructure, store, pass, return or export of an fs function, an fs namespace, `Date.parse` or `Date` (a reviewed escape pin aside), a `Date` member off the allowlist, a parse error, or an argument type the checker cannot resolve (that last one counts as a date site). |

- **An ESLint rule** for either class (default 1).
- **Test files**, and `readdir` listings (defaults 4 and 6).
- **Reaching fs or `Date` by reflection or the prototype chain** (not a
  follow-on, and not pinned). Examples: `someDate.constructor.parse`,
  `Object.getPrototypeOf`, `Reflect.get`, `eval`, `new Function` and
  `globalThis[expr]`. The census is an untyped syntactic scan, and no such
  scan is complete against code written to evade it. Each round of review
  found one more route: binding forms (r1), alias chains (r2), and
  `Date.prototype.constructor` (r3). The project's threat model is
  "Mistakes, not adversaries: the threat model is agents that drift, not
  agents that attack" (`docs/design/dossier/body.html`). A builder does not
  write these forms by mistake. No existing rule refuses `eval` or
  `new Function`: `eslint.config.mjs` enables neither `no-eval` nor
  `no-new-func`, and no `check` rule names them. Neither appears in the
  source set at `26fe11b`. This opus adds no such rule (default 8).

## Defaults for the Patron to veto

Each ships as stated and can be overturned at the checkpoint.

1. **A source scan, not an ESLint rule.** The guard is a scan that runs
   with the tests, which CI runs. The ESLint set-up here cannot tell a date
   string from a number. Its per-line "ignore" comments would also let any
   file excuse itself. The scan keeps every approved exception in one
   reviewed list.
2. **`--now` is read as strictly as record dates.** `--now 2026-02-30` is
   refused, where today it is silently read as 2 March.
3. **What gets fixed now.** Two kinds of file access in the command-line
   tool's own code are fixed:
   - every write into a studio folder;
   - every read of a file whose name comes from a record, an id or a flag.

   The rest stays as it is, each listed with a reason and a follow-on: the
   server, the console, the snapshot reader, the event log and session
   receipts (lower layers that cannot use these helpers yet), the helper
   scripts, and fixed-name files such as `bisellium.yml`.
4. **Tests are not scanned.** At master, tests make 2,023 raw file calls
   and 98 date calls, almost all against throwaway temp folders they create.
5. **The console keeps its own date reading.** The browser code reads
   times that the server already sent it. It does not share code with the
   server, so its 3 sites are listed with that reason.
6. **Folder listings are not counted as reads.** A listing exposes only
   names, and each listed file is then opened through the contained reader
   where the line in default 3 applies.
7. **The folder check gets stricter for everyone who uses it.** A
   symlink anywhere between the studio root and the target folder is now
   refused, not only at the last folder.
8. **The scan catches mistakes, not deliberate evasion.** It lists the
   ordinary ways code reads a date or touches a file, and it refuses
   copies or nicknames of those tools. It also refuses any use of the date
   tool beyond four plain calls (parse, UTC, now and new) and type checks.
   It does not try to catch code that digs the tools out by trickery,
   because no scan of this kind can, and the project guards against agents that drift, not
   agents that attack.
