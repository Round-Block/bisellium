## Intent

Today `next` orders the build review only after a host mint: `bisellium run --sella builder --opus <id> -- true` from the worktree (lex §9 step 4, or W-292's `next --perform --chain`, whose first rung is that mint), about 15 to 30 minutes on this host. `admitCurrentRunReceipt` then admits the record's `run_receipt` for the current source tree, both at the review rung (`deriveNext` rung 6) and in the `review` verb. The merge queue's `certify` job runs the same mint again on the merge result (`scripts/ci-certify.mjs` spawns `bisellium run --sella builder --opus <id> -- true` from master's tooling), so every opus pays for two mints.

The host mint does two things the builder's own gates do not: it replays every behaviour's red at its recorded commit (`scripts/run-builder-host.mjs`, the `redReplays` loop) and runs `bisellium ci --offline --opus` in a cell. Both already run in `certify`, because `certify` runs that very mint: red replay does not have to move, it is already in the merge queue, and lex §11 ("CI certifies at least what the local mint does") holds with `certify` as the one mint.

After this part, review's precondition is the branch record's automated gates passed at the branch's current source tree, which the builder's `bisellium ci --opus <id> --studio studio --repo .` in the worktree writes (through `verify`) and the builder commits. No host mint runs before review: the chain performs review and pr only, and lex §9 steps 3 to 5 name the builder's `ci --opus` instead of the hand mint. `certify` is unchanged and stays the one mint. W-207's remainder is none: its whole title (done records the merge queue's certificate, falling back to `verify`) shipped as W-259 part 1 (#544).

Cause fix: none is owed. No recurring S1 class drives this part; it removes a step (D-061 §5 exempts it).

Threat model: mistakes, not adversaries (D-045). The gate logs are written by `verify` in the builder's worktree; a hand-written log of the right shape is not detected, as a hand-written receipt of the right shape was not.

This opus is reviewed under master's ladder, whose perform reads `prompts/build-review.md` from the opus branch (W-274 brief:65): so this opus runs `ci --opus` and commits its gate logs before review, and the host mint and its receipt stand as history beside them; the rule applies from the next opus.

## Interfaces

**`admitCurrentGates(studioRoot, opus): GateAdmission`**, `GateAdmission = { ok: true } | { ok: false; error: string }`. It replaces `admitCurrentRunReceipt` at both of review's gates, the review rung and the `review` verb. In order:

1. `builderRuntimeObligation` of the record: invalid refuses with its error; a legacy (unmarked) record is admitted, as today.
2. The gate selectors are validated whole before any gate is selected (`gateSelectors`, private): the record's `kind` is a native opus kind (`isNativeOpusKind`) and its `probationes` absent or a mapping; the manifest is a mapping, its `probationes` absent or a list of well-formed rows (each a mapping with a nonempty string `id` unique among the rows, a string `name`, a `kind` in `PROBATIO_KINDS` and, for an `automated` row, a nonempty string `command`) and its `source_excludes` absent or a list of nonempty strings; and `effectiveProbationes` of the kind reports no problem. Any failure refuses with `<opus>: the gate configuration is malformed: <problem>`, the problem one of `kind <JSON> is not a native opus kind`, `the record's probationes is not a mapping`, `bisellium.yml is not a mapping`, `bisellium.yml probationes is not a list`, `bisellium.yml probationes[<i>] is not a well-formed gate row`, `bisellium.yml source_excludes is not a list of nonempty paths`, or the `effectiveProbationes` problems' messages joined by `; `. A malformed row never narrows the set: the automated gates are filtered from the validated set only, and an empty set is admitted only after it validates.
3. The repository is `git rev-parse --show-toplevel` from `studioRoot` (failure: `<opus>: current source tree is unavailable`); the exclusions are the studio, `.bisellium` and the validated `source_excludes`, as today; a dirty source tree (`isDirtyOutside`) refuses with `<opus>: current source tree is dirty`; the tree is `tree:<sourceTreeHash(repo, exclusions, "HEAD")>`.
4. For each automated gate of the record's kind (`effectiveProbationes`: the manifest's, plus a `ui` opus's `served-e2e`), in manifest order: `waived` is skipped, as `verify` skips it. Otherwise it must be `passed` with `certifies` equal to the tree, else `<opus>: <gate> is not passed at the current source tree tree:<12 hex>; run bisellium ci --opus <opus> in the worktree and commit the record and its gate logs`. Its `evidence` must be exactly `ci/<opus>-<gate>-<first 8 hex>.log`, the name `verify` writes for that tree, else `<opus>: <gate> records evidence <value>, not <expected>`. The log is read through `readContainedRegularFile(studioRoot, evidence, "ci")`, else `<opus>: <gate>'s log <evidence> is not a contained regular file (<reason>)`; its first line must be `certifies: <tree>` and its third `exit code: 0` (the header `localPipeline` writes), else `<opus>: <gate>'s log <evidence> does not open with certifies: <tree> and exit code: 0`.
5. When at least one log was read, each log must be tracked and unchanged from `HEAD`: `git ls-files --error-unmatch -- <log>` from the repository exits 0 for each, and `git status --porcelain --untracked-files=all -- <each log>` prints nothing (`--untracked-files=all` overrides `trackedOnly`'s `status.showUntrackedFiles=no` at the rung, which `ls-files` does not read, so the rung hides no log). An ignored or other untracked log (or a failed `ls-files`) refuses with `<opus>: a gate log is not committed (<those paths, sorted, comma-separated>)`; a changed or staged one with the same message naming the paths status prints; a failed status with `<opus>: git status of the gate logs failed`. The record's own commit state is not judged here (Limits): the record is read from the worktree's working copy, the review perform's `dirtyHold` holds on its uncommitted edits, and a `review` or `handoff` write between rounds leaves the record dirty without sending the ladder back to `build`.
6. Any throw (an unparsable record or manifest, say) refuses with `<opus>: the gate evidence cannot be read: <message>`.

**The review rung (`deriveNext` rung 6).** `f.gates()` (memoised `trackedOnly(() => admitCurrentGates(wt.studio, id))` while the worktree is usable) replaces `f.receipt()`: a refusal names `build`, phase 2, with the refusal as `why`, exactly where a missing receipt named it, and a failed round at this tree still names phase `fix`. The order's `resume` is true when a review round exists or an automated gate on the branch record carries a `certifies` (an earlier `ci --opus`), as `run_receipt` once marked an earlier mint; `resume` is a hint read loosely (a non-mapping `probationes` or gate reads as no `certifies`) on an order the admission has already refused, and admits nothing. The order's `command` line is unchanged.

**The `review` verb.** `runReview` calls `opts.gateAdmission ?? admitCurrentGates` for a marked record, before reading evidence or writing anything, and exits 2 with the refusal on stderr, as it did for the receipt.

**The chain.** `CHAIN` is `review` and `pr`; `performable` no longer admits a `build` rung; a first rung outside the two holds with `why: refusing: --chain performs only the review and pr rungs; <the held reason, or the next step for <id> is <step>>`. `performMint`, `mintSteps`, `CLI_BIN` and the `BISELLIUM_TEST_MINT` seam are deleted. Usage is unchanged (`[--perform [--chain]]`).
