## Intent

Decree family: merge-group-record-only-ci

In a merge group, `gates` and `web-e2e` run `scripts/ci-scope.mjs` on the group commit against `github.event.merge_group.base_sha`. A records-only delta takes the path a records-only pull request takes today. Any source path, an empty delta or an unreadable comparison takes the full path. The full path is unchanged on `push` and for every source change. In the workflow, only the scope step's condition and base change. The `pull_request` run is untouched; W-205 owns that (D-054 §2).

No check is removed (production lex §11, D-054 §1):
- **Steps.** For a records-only group, `gates` runs its checkout, setup-node, `npm ci` and scope steps, then `check -- studio --repo .` and `test:record`. `web-e2e` runs its checkout, setup-node, `npm ci` and scope steps, and skips its four build and browser steps (`reads.txt` §10). That is the same step set as today's records-only pull request (`reads.txt` §1). It runs on the commit master will hold, not on the PR head.
- **Full path.** The full-path steps still run once on that commit, in the post-merge `push` run. GitHub merges the group commit that passed. This is the posture W-131 settled for a records-only pull request.
- **What W-203 does not change.** `recordOnly` and `test:record` stay as they are. The path's soundness therefore stays W-131's and W-139's.
- **`officina`** is unchanged.
- **`certify`** reads no scope output. An `opus/W-*` head still gets W-168's mint, which runs the six `CI_STEPS` and `verify` from master's tooling, so CI still certifies what the local mint does. A non-opus head exits 0 with nothing to mint, as today.

The threat model is mistakes (D-045). Reused jobs are judged by their exits, one row per job (D-050). Spec review judges the lines W-203 changes (D-054 §5).

## Interfaces

The `id: scope` step in both `gates` and `web-e2e` becomes:

```yaml
- id: scope
  if: github.event_name == 'pull_request' || github.event_name == 'merge_group'
  env:
    BASE_SHA: ${{ github.event.pull_request.base.sha || github.event.merge_group.base_sha }}
  run: node scripts/ci-scope.mjs "$BASE_SHA" HEAD >> "$GITHUB_OUTPUT"
```

`HEAD` is different for each event and job:
- **`pull_request`.** `BASE_SHA` is `pull_request.base.sha`, and `HEAD` is what each job checks out today. So W-131's PR behaviour is unchanged.
- **`merge_group`.** `BASE_SHA` is `merge_group.base_sha`, the group's parent commit; with build concurrency 1 that is master's tip. `HEAD` is the group commit in both jobs:
  - `gates` checks out `github.ref_name`, the `gh-readonly-queue/…` branch, at `fetch-depth: 0`.
  - `web-e2e` checks out `github.sha`, which is `merge_group.head_sha`, at `fetch-depth: 2`.
- **`push`.** The step is skipped and its output is unset, so every `!= 'true'` step runs.

The CLI stays event-agnostic and keeps its behaviour. `node scripts/ci-scope.mjs <base> <head>` prints `record_only=${scopeOf(base, head)}`:

```js
/** W-203: true only when `git diff <base>...<head>` succeeds and recordOnly accepts its paths; any git failure is false. */
export function scopeOf(base, head) // runs `git diff --name-only --no-renames <base>...<head>` in the process cwd
```
- It prints `record_only=true` only for a non-empty delta that `recordOnly` accepts. Every path must start with `studio/` or be `docs/SESSION-HANDOFF.md`.
- Otherwise it prints `record_only=false`. That includes a failed `git diff`: `execFileSync` throws, and `scopeOf` returns `false`. The branch exits 0 in both cases.

A group commit stacks on its parent, so the delta against `base_sha` is the combined change of every PR in the group. One source path in any of them selects the full path.
