## Intent

Since about 2026-10-20 23:05Z `npm run -s audit` (W-236's gate, `npm audit --audit-level=moderate`) exits 1 on master, so the required `gates` check fails on every PR. Its one finding (`audit-master.out`): vite 8.3.0 (`apps/web`, also deduped under `@vitejs/plugin-react` 6.1.1) is inside the range 8.3.0 - 8.3.2 of three high launch-editor advisories, GHSA-698v-4r3x-3vcv, GHSA-r825-w8mm-5pxw and GHSA-587h-7wmj-h5pm. vite 8.3.3 and 8.3.4 are published; 8.3.4 is the latest and inside `apps/web`'s `^8.3.0`. A mandatory security fix (D-044), high (D-039).

The fix is the lockfile alone, by `npm update vite --package-lock-only` (W-236's route). Measured (`lock-delta-update.out`): vite goes 8.3.0 to 8.3.4, and 19 entries follow because vite 8.3.4's own ranges force them: postcss 8.5.28 to 8.5.31 (vite now asks `^8.5.29`), nanoid 3.3.19 to 3.3.20 (postcss asks `^3.3.20`), rolldown and its 15 platform bindings 1.2.9 to 1.2.14 (vite asks `~1.2.12`), and `@oxc-project/types` 0.150.0 to 0.154.0 (rolldown pins `=0.154.0`). `npm install vite@8.3.4 -w apps/web --package-lock-only` resolves the same 20 entries (`lock-install.json`, no package differs) and also raises `apps/web/package.json` to `^8.3.4`; that second file is not needed, since a fresh resolution of `^8.3.0` already picks 8.3.4, and the row below stops a return. With the prototype lock installed, `npm run -s audit` finds 0 vulnerabilities, `npm ls vite --all` shows 8.3.4 only, the web build passes and both web suites pass, `test:e2e` 7 of 7 and `test:serve` 44 of 44 (`web-proto.out`).

The audit needs the registry, so it is not a replayable red. As W-236 did, the replayable evidence is an offline node:test row on the lockfile: no vite below 8.3.3, the first version outside the advisory range. It goes in W-236's file, which is already in `test:suite`, so `package.json` is not touched; the file keeps its name (renaming it would touch `package.json` and W-236's records) and its header comment names both rows.

Threat model: mistakes, not adversaries (D-045). The upstream fix is trusted.
