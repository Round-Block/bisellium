## Intent

On 2026-11-01 records PRs #941 and #942 changed nothing outside `studio/` but the handoff, after the W-463 and W-410 master verifies. Each moved the SOURCE tree (`landing.out`: 0ebef2b1 and 4dfa47e1 MOVED under master's list, kept under master's list plus the handoff), so the done step found no automated certificate and both ~16-minute verifies ran again. The handoff is already a record everywhere else: `recordOnly` (`scripts/ci-scope.mjs`) names it, so CI takes the records-only path for it, certify passes a non-opus head that changes it, and the done and landing guards let it ride. Only the SOURCE hash still counts it.

**Every reader takes the list unchanged (decided).** `readers.out` lists them: the verify verb, the check verb's staleness compare, the verdict log's `# tree:` capture, the red verb, the step ladder's certificate, branch tree and merged tree, branch and merge (B7.1, the branch's own manifest), receipt admission (`builder-run.ts`), the done rung's tree, certify in the merge queue (`readSourceExcludes`, then the mint through `builder-run.ts`), the host replay (`scripts/run-builder-host.mjs`) and the rewrite check (`rewrite.ts`). Each spreads the manifest's list into `sourceTreeHash` or `isDirtyOutside` (`@bisellium/shim`), and an entry may name one file (`p === ex` in `isUnderExcluded`). So adding the handoff to the set is one manifest line and no reader changes. W-382's served-UI hash reads `SERVED_UI_PATHS` (`apps`, `examples/sample-studio`, `package.json`, `package-lock.json`), never the list; the handoff is none of them, so it is unchanged either way. Prettier and eslint do not read the handoff (`.prettierignore` holds `*.md` and `docs/`).

**Why the line cannot ride on this opus, and what this opus does instead (decided).** Two facts on master make each landing order fail. First, `buildReviewDrift` holds the step ladder while the main checkout's and an opus worktree's `source_excludes` differ: "land the change on master first, then rebase the branch" (`landing.out` 1; W-209 found the same, its F4). Second, W-211-b1 requires the list to be exactly `examples/` plus the dossier's direct pages, and it runs in `test:record`, so a records PR that adds the line fails its own merge group (`landing.out`: at 2a4a3e74 with the line, `not ok`). This opus breaks the tie: W-211-b1 admits the handoff at most once and stays exact otherwise. After this opus merges and is done, a one-line records PR adds the handoff to `studio/bisellium.yml` (Defaults 1) and passes the pin (`landing.out`: at the tip, with and without the line, `ok`).

**The pin (decided).** `sourceExcludesProblems(listed, pages)` in `scripts/ci-scope.mjs`, beside `recordOnly` and sharing its `HANDOFF` constant, returns the sorted problems with a list: `not a list`, `extra: <entry>`, `duplicate: <entry>`, `missing: <entry>`. W-211-b1 calls it on the real list with the pages it already derives. The handoff is admitted, not required: requiring it before the line lands would fail every branch, which is the deadlock again (Defaults 3).

**Other bookkeeping paths (decided: none added).** `studio/acta/`, and every other path under `studio/`, is already outside the SOURCE tree, because every reader excludes the officina directory. In `docs/design/dossier/`, the direct HTML pages are already listed (W-209), and the rest (`build.sh`, `build-arch.mjs`, any nested page) is the dossier's build source and stays SOURCE (W-209 Defaults 1). Other design docs (`docs/design/queue-review/`, the canvas, `DIRECTION.md`) are not records to `recordOnly`; excluding them would leave a change to them neither certified nor on the records path. After the records PR, the list is `examples/` plus `recordOnly`'s records outside the officina, and nothing else.
