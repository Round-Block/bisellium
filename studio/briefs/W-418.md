## Intent

The Patron, 2026-10-25: "I need a notification for PRs that require my review." PR #773 (W-406, opened by `next --perform --expect pr`) waited 98 minutes on their code-owner review with no signal reaching them. Since then the orchestrator has pushed one by hand, from memory (`docs/SESSION-HANDOFF.md`: "Push-notify the Patron for every PR needing their review (until W-418)").

What the probes found, before drafting (each read only):

- **The account.** The agent's `gh` acts as `bisellium-agent`, a separate GitHub user, not `edckt` (`probe-a-account.out`). So GitHub does notify `edckt` of its review requests: GitHub withholds only a user's notifications about their own actions.
- **The request lands.** On #773, #778, #781, #782 and #784 the timeline holds `review_requested` by `bisellium-agent` for `edckt`, and `edckt` approved each (`probe-a-timeline.out`, `probe-a-pr773.out`). On #773 the request came in the same second the PR was opened, by GitHub's own code-owner rule.
- **GitHub's notification did not reach the Patron.** #773 was requested at 13:15:32Z and approved at 14:53:34Z, after the Patron asked for a notification. GitHub's channel (web, email, the mobile app) is the Patron's to set up, and as set up today it is not seen away from the desk.
- **The session's push does reach them.** Claude Code's `PushNotification`, called by the orchestrator session, returned "Terminal notification sent. Mobile push requested." for #778, #781, #782 and #784. The Patron approved each between 16 seconds and 15 minutes later (`probe-b-notify.out`).

So the channel is the session's own push (Defaults 1). It needs nothing new from the Patron. But only the session can call it: `bisellium` is a CLI and cannot. This opus therefore splits the work:

- The CLI screens the PR, prints its code-owned paths, requests the code owners' review, and leaves one notice line on disk.
- The guard hook, already wired on every main-thread Bash, Write, Edit and NotebookEdit call (`.claude/settings.json`, unchanged), takes the notices at the main thread's next such call and refuses that call once with their text. The session then pushes each notice and reruns the call.

The notice reaches the session through a hook rather than through the session's memory. Pushing it is the session's own tool call (Limits).

The screen. It reads the owners file GitHub reads for a PR into master: the first of `.github/CODEOWNERS`, `CODEOWNERS` and `docs/CODEOWNERS` that master holds. It then reads the paths of `master...<head>` from the top of the tree, with `--no-renames` so that a rename out of a code-owned path counts. A pattern is matched as GitHub matches a plain one: a leading or inner `/` anchors it at the root, a trailing `/` matches a directory only, and a bare name matches at any depth. The last matching line names the owners, and a line with no owners leaves the path unowned. A line the screen does not read holds the screen, so no path passes as unowned through it. Such a line holds a glob (`*`, `?`, `[`), an escape, a `#` inside the pattern or a control or non-ASCII space, opens with `!`, or has an empty, `.` or `..` segment (a bare `/` included). Today's file has nine anchored rules and no such line (`enumerate.out`).

On master's last 40 squash merges the screen names six PRs code-owned: #784, #782, #781, #778, #773 and #743, each for a `studio/decisions/` file, owner `@edckt`. #783 and #785 are not named. That agrees with GitHub's own requests on every PR probed (`enumerate.out`, `probe-a-timeline.out`). Five of the six were records PRs opened by hand, so the screen is also a verb, `bisellium review-request <pr>`, run for a PR opened by hand. The orchestrator's kept `~/.bisellium-evidence/chore-pr.sh`, outside the repository, is to call it once this merges (Defaults 2).

Three behaviours:

1. `review-request <pr>` checks the PR on GitHub, fetches master and `refs/pull/<pr>/head`, screens, leaves the notice and requests review.
2. The `pr` rung runs the same steps on the head it has just pushed.
3. The guard hands the notices over.

Threat model: mistakes, not adversaries (D-045). The notice store sits under the Git common directory, which the agent can write, as the queue binding and the sync request already do.

## Interfaces

The prototype is `prototype.diff` over master 0e65054e, built by `stages.sh` from `apply-src.py <checkout> s1|s2|s3|b2|b3` and `apply-test.py <checkout> b1|b2|b3|rows`. The series `prototype.mbox` carries its six commits in order.

**`bisellium review-request <pr> [--repo <dir>]`** (`runReviewRequest`, new). `<pr>` must match `PR_NUMBER` (`^[1-9][0-9]{0,8}$`), and `--repo` is the only flag (`parseFlags`), given at most once and with a non-empty value: `parseFlags` keeps the last of a repeated flag, so `runReviewRequest` refuses a second `--repo` itself (`--repo is given more than once`), and an empty one (`--repo needs a non-empty value`). A usage error prints `review-request: <why>` and then `REVIEW_REQUEST_USAGE` on stderr and exits 2, before any read. Otherwise stdout opens with `review-request: PR #<pr>`, and these steps run in order:

1. `repoSlug` and one `gh pr view <pr> -R <slug> --json number,state,baseRefName,headRefOid`. A failing or non-JSON reply refuses, and so does a reply that is not an object.
2. The view must hold `number` equal to `<pr>`, `state` `OPEN` and `baseRefName` `master`, with a 40-hex `headRefOid`.
3. `git fetch -q --no-tags origin +refs/heads/master:refs/remotes/origin/master`, then `git fetch -q --no-tags origin refs/pull/<pr>/head`. `FETCH_HEAD^{commit}` must equal `headRefOid`.
4. `reviewNotice` with base `refs/remotes/origin/master`, head `headRefOid` and resume `bisellium review-request <pr> --repo <repo>`.

A refusal in steps 1 to 3 prints one `why:` line and exits 1, with nothing left or requested. Step 4 exits 0 when it runs whole and 1 at its hold. Every line passes `clean` (controls to a space, at most 1000 characters).

**`reviewNotice({ cwd, slug, pr, base, head, resume })`** (new, exported). It returns `{ ok, lines }` and runs these steps in order:

1. `screenDiff(cwd, base, head)`.
2. With no code-owned path, `code-owned: none`, or `code-owned: none (no .github/CODEOWNERS, CODEOWNERS or docs/CODEOWNERS at <base>)` when the base holds no owners file. Then `ok`, and nothing more is read, written or requested.
3. Otherwise `code-owned: <path>` per path, sorted.
4. The title, from `gh pr view <pr> -R <slug> --json title`, which must be a string.
5. `writeNotice` with `noticeText`, then `notice: <text>`.
6. When at least one owner is `@<login>` or `@<org>/<team>` (`REVIEWER`), one `gh pr edit <pr> -R <slug> --add-reviewer <a,b,…>`.
7. `review-requested: <a, b, …|none>`, and one `review-request: skipped <owner> (not an @login or @org/team)` per other owner.

The first failing step holds: `why: <why>`, then `run: <resume>`, `ok` false, and the steps after it do not run. The four holds are:

- `PR #<n>'s code-owned paths could not be screened (<why>)`, an owners line the screen does not read included: `(<file> line <n> is not a plain pattern: <pattern>[ (and <k> more)])`.
- `PR #<n> touches code-owned paths, but its title could not be read (<why>)`.
- `… its notice could not be written (<why>)`.
- `… the review request failed (<why>)`.

**`screenDiff(cwd, base, head)`** (new). It runs `git ls-tree --full-tree -z <base> -- .github/CODEOWNERS CODEOWNERS docs/CODEOWNERS` and takes the first of `OWNERS_FILES` (that order, GitHub's) with an entry. None means no owners file (`file` undefined). An entry that is not a `100644` or `100755` blob is `<file> at <base> is not a regular file`. Then it runs `git cat-file blob <oid>` and `git diff --name-only --no-renames --no-relative --ignore-submodules=none --no-ext-diff -z <base>...<head> --` (every path from the top, whatever `diff.relative`, `diff.renames` or `diff.ignoreSubmodules` say), and returns `codeOwned(text, paths)` with the file. Any git failure, and any unread line, is an `{ error }`.

**`readOwners(text)` and `codeOwned(text, paths)`** (new, pure). A `#` at a line's start or after a space or tab opens a comment. Words split at spaces and tabs; the first is the pattern and the rest are owners. The pattern rules are the Intent's, and a line it does not read is returned as `line <n> is not a plain pattern: <pattern>`. `codeOwned` returns those lines (`{ unread }`) when there is any, and otherwise the code-owned paths sorted and the owners of their last matching lines sorted.

**`noticeText(pr, title, paths)`** (new, pure): `PR #<pr> needs your review: <title> (code-owned: <p1>, …, <p5>[ and <k> more])`. The title loses its controls and is cut to 120 characters. The whole line loses its controls and is cut to 500 characters (`NOTICE_LINE`, at most 1500 bytes in UTF-8), so a notice it writes fits the guard's 4096-byte bound (`NOTICE_MAX`, Promise kept). It names the PR number, the title and the code-owned paths only.

**`writeNotice(cwd, pr, text)`** (new). It writes `<git common dir>/bisellium/notice/<pr>` whole: a temporary file `.<pr>.<pid>` beside it, then a rename, so it replaces an older notice for the same PR. It returns undefined, or why not.

**`takeNotices(cwd)`** (new, behaviour 3). It reads the notice directory of `cwd`'s Git common directory (`git rev-parse` with a 1 s timeout), in PR order. Each entry whose name matches `PR_NUMBER` and that is a regular file of at most 4096 bytes is read, loses its controls and is trimmed. It is then removed, and handed over when it is not empty. Any other entry, and one that cannot be read or removed, stays and is not handed. With no checkout or no directory the result is `[]`.

**`guardRefusal(input)`** (exported, signature unchanged). At `PreToolUse`, for the main thread (no `agent_id`) with a non-empty `cwd`, it first calls `takeNotices(cwd)`. When any notice is taken it returns `refused: a PR waits on the Patron's review (W-418): send the Patron each notice below with PushNotification, then rerun this call: 1) <notice>`. With more than one notice the sentence opens `refused: <n> PRs wait` and lists `1) … 2) …`. `hooks.ts` prints it and exits 2, as for every refusal. Every other branch is unchanged, and an input with no `cwd` (the `hooks check` probe) reads none.

**`openPr(ctx, existing, title, bodyFile)`** (`integrate.ts`, signature unchanged). After the push, and after the create when the PR is new, it prints `PR=<n> base=… head=…` and then `reviewNotice`'s lines. It uses `cwd` the opus worktree, base `TRUNK_REF` (`refs/heads/master`, which `fetchTrunk` has just made origin's) and head `HEAD`. The resume is `bisellium review-request <n> --repo <repo>`. ### Input domain

A rejection fails closed. `review-request` refuses or holds (exit 1) with a `why:` line, and the `pr` rung holds with the `run:` line. In both, nothing after the failing step runs, so an unscreened PR never reads as screened. The guard is the exception: it fails open (W-310). An entry it cannot judge is left on disk and never refuses a call. A test row whose own fixture write or git call fails throws, which fails the row.

| Record | Valid domain | Rejected by |
