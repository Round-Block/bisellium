## Intent

The Patron, 2026-10-27: "I need some autonomy from the models as well, whether it makes sense". W-407's 720px Inbox measure came from `docs/design/DIRECTION.md`, which an agent wrote almost whole (commit 5e5efd88). It passed three UI gates on conformance alone and was still wrong. On 2026-10-28 the Patron also dropped DIRECTION §4.2's fasti strip and §4.5's colophon stamp on sight. A line of DIRECTION is a Patron ruling only where it cites the Patron. The two UI judges at spec must ask of every rule a brief applies whether it makes sense on the captured screen, and who ruled it.

What exists today (the read): the UI spec reviewer (`ui-spec-reviewer`, Claude Opus 5.5, D-091 A) is dispatched with `studio/prompts/spec-review.md` filled by hand (production lex §9 step 2; for example `~/.bisellium-evidence/W-407-specreview/prep-rN.sh`), and that template has no sense clause. The ui-lead (Codex `gpt-6-astra`) has no template at all. `next`'s ui-lead order (`dispatch`, `packages/cli/src/next.ts`) says only "keep the dispatch prompt as `ci/<id>-ui-prompt-<n>.md`", and every kept fill (W-339, W-350, W-361, W-366, W-406, W-407) was written by hand. Only W-407's round-10 fill carries a sense paragraph, added by hand on 2026-10-27.

Three decisions:

1. **The clause lives in the templates, and `process.prompt_templates` enforces it.** That rule (W-241, extended by W-258) already blocks `bisellium check` when a per-opus template lacks a required text, so it is extended here rather than adding a second mechanism (D-042). `SENSE` holds three texts: `for sense, not only conformance`, `the Patron ruled it or an agent wrote it`, `what the screen should do instead`, the wording of W-407's round-10 paragraph. A new map, `SENSE_TEMPLATES`, requires them in `prompts/spec-review.md`. The Ops lex clause still names only W-241's three templates. `spec-review.md` belongs to production lex §9 step 2, not to Ops. Naming a new template in the Ops lex would be a lex amendment, which is the Patron's call (Default 4).
2. **The ui-lead gets its first template, `studio/prompts/ui-input.md`.** It is not a second mechanism. It is the template the one per-opus dispatch without one has been missing, shaped from the kept fills: five slots (`<ID>`, `<OPUS>`, `<READ>`, `<SHOTS>`, `<QUESTIONS>`), the data phrase, the sense clause and the output shape `verdict`'s UI input check reads (`## Findings`, `## Recommendation`, the `Verdict:` line, the placeholder words warning). `SENSE_TEMPLATES` requires its slots, the data phrase and `SENSE`. `next`'s ui-lead order names it as the prompt to fill: the main checkout's `<studio>/prompts/ui-input.md`, never the opus branch's, as the order's rebuttal line already reads `prompts/rebuttal.md` (W-315).
3. **Who may block on sense.** In the ui-lead's input, an agent-written rule that does not make sense on the captures is a blocking UI defect. The ui-lead holds UI design leadership within the direction (production lex §11), and its blocking line already covers a fix that contradicts DIRECTION. In the UI spec review, a sense finding is an advisory tagged `[severity: S4]`. It carries its replacement text and says whether the brief's Defaults put the rule to the Patron. The spec review's blocking scope stays as D-046 and D-076 A set it. A Patron ruling the judge thinks wrong on the screen is an advisory to the Patron in both prompts, never a blocker.

Why the check reads the templates and not the fills: a fill check would sit in `verdict --dispatch-prompt`, the ui-lead's kept prompt. It would flip the UI prompt fixture of every row that records a ui-lead input (`next-spec`, `next-review`, `next-ladder`, `next-done`, `verdict`, `verdict-citation`, `verdict-findings` tests). The spec review's fill is never kept under `ci/`, so there is nothing for a check to read. That is a stated limit and Default 2.

Threat model: mistakes, not adversaries (D-045).
