## Intent

Worktrees under `<repo>/.worktrees/` are made by every opus (its own, `-spec`, `-stage`, `-reds`, `-kills`, `-series`, `verify-<id>`) and by every records PR, and nothing removes them but the `cleanup` rung, which removes only `.worktrees/<id>`. On 11-01 there were 117 of them and 15 GB. This opus makes them go when their work ends, in two places, through one function.

**The sweep (decided).** `sweepWorktrees(repo, studio, { opus?, prs, nowMs })` in `prune.ts`. It considers only the worktrees git lists directly under `<repo>/.worktrees/`: never the main checkout, never one elsewhere, never one git marks prunable (its checkout is already gone). It keeps, each with its reason: a locked worktree; one holding the current directory; one whose age cannot be read or is under an hour (`WORKTREE_MIN_AGE_MS`), the age read from the mtime of its admin directory's `gitdir` file, which git writes once at creation (the directory's own mtime moves with later git operations; `classify-dirty.sh`'s reading); a detached one whose commit no branch, tag or remote-tracking ref holds (removing it would lose the commit); one on a branch whose PR is open, whose PR state the lookup could not read, or whose lookup failed. A branch is never deleted by the sweep, so a removed worktree loses no commit; its uncommitted changes, untracked files included, are saved first as one binary patch (`git add -A`, then `git diff --cached --binary HEAD`) in `<repo>/.bisellium/worktree-diffs/<name>-<instant>.patch`, made through `ensureRealDirectory` and written exclusively; a patch that cannot be saved keeps the worktree. A patch holds a nested repository only as a gitlink, never its files or its commits, so a dirty worktree holding one is never saved and removed: any nested `.git` (a directory or a gitfile) at a path git does not ignore, tracked (an initialized submodule, clean or not) or untracked (an embedded repository, at any depth), keeps it, its reason naming the path; a clean worktree holding an initialized submodule is kept by git itself, whose `worktree remove` without `--force` refuses it. A clean worktree is removed with `git worktree remove`, a saved dirty one with `--force`.

**The busy admin directory (decided).** When `git worktree remove` fails but the checkout is gone, the worktree counts as removed and its entry says so (`adminLeft`): the sandbox holds its admin directory. Each sweep then runs `git worktree prune` and counts, from `git worktree prune --dry-run --verbose`, the admin directories still pending (`adminLeft`); a later sweep, from a session that did not start with them, deletes them. The sweep never deletes an admin directory itself.

**The done perform (decided).** With `opus`, the sweep removes every worktree whose name or branch carries that id (`carriedOpusIds`: `<LETTERS>-<digits>` not preceded by a letter or digit and not followed by a digit, so `W-48` is not `W-489`), past the guards, dirty or clean: its opus is done. `performDone`, after the done commit and the switch back to master, runs it with the real clock (never `--now`) and a git-only PR lookup, `unpushedBranches`: a branch with no `refs/remotes/origin/<branch>` was never pushed from this clone and has no PR; a branch on origin is left unread, so its worktree is kept for `prune`, which asks GitHub. It prints `worktree removed: <path> (opus <id> done)` (with `; uncommitted changes saved to <patch>` or `; its admin directory is held busy, a later prune retries`) and `worktree kept: <path> (<reason>)` lines after its own; a sweep that throws prints `worktree sweep failed: <why>` and the perform still succeeds.

**`bisellium prune` (decided).** Without `opus`, the sweep removes a candidate when every opus id it carries that has a record in the studio's `opera/` reads `state: done` (at least one); else when its branch's PR is merged or closed; else, when it is clean, when its commit is in `refs/remotes/origin/master`. A dirty worktree is removed only for the first two reasons: a dirty worktree at master is the 11-01 trap (a fresh branch looks merged). `runPrune` runs it after `reclaimWorktrees`, before the branch prune (so an `opus/*` branch freed by a removed worktree can go in the same run), with `ghPrStates`: one `gh pr list --state all --limit 5000 --json headRefName,state`, an open PR winning over merged and merged over closed, a branch with no PR read as none. The lookup is asked at most once per sweep and only when a candidate is on a branch, so a repository with no worktree to judge never runs gh. Prune prints the removed lines and the busy count; `nothing to prune` still means nothing was removed by any part.

Threat model: mistakes, not adversaries (D-045). The worktree name reaching the patch's file name is the basename of a path git lists under `.worktrees/`, one segment.

Promise done-sweep: when the done perform succeeds it removes every worktree directly under `<repo>/.worktrees/` whose name or branch carries the opus id as a bounded token and that is at least an hour old, unlocked, outside the current directory, not detached at a commit no ref holds, and on no branch present on origin, saving each dirty one's uncommitted changes and untracked files as one patch under `<repo>/.bisellium/worktree-diffs/` before removing it, keeping a dirty one that holds a nested `.git` at a path git does not ignore (an initialized submodule, clean or not, or an untracked embedded repository or gitfile at any depth), and prints one line per worktree removed or kept; a worktree carrying another id, or outside `.worktrees/`, is untouched; a checkout removed while its admin directory is held busy counts as removed, and a later sweep prunes the admin directory. ## Out of scope

- Deleting the branches of removed worktrees (beyond `pruneStaleOpusBranches`' existing `opus/*` rule), deleting saved patches, and worktrees outside `.worktrees/` (`.bisellium/worktrees/` keeps `reclaimWorktrees`; `.claude/worktrees/` is the harness's).
- The `cleanup` rung, `bisellium done` run directly, and `bisellium close`.
- Deleting an admin directory by hand (the W-227 busy case): the sweep only runs `git worktree prune`, and a later session's sweep clears what an earlier session's sandbox held.

## Defaults for the Patron

1. When a task is marked done, its own worktrees (the task's scratch, staging and verify copies) are removed at once; any uncommitted changes in them are saved first as a patch file under `.bisellium/worktree-diffs/` in the repo, which is never deleted automatically. A worktree whose branch is on GitHub is left for `bisellium prune`, which can check its PR. Agree?
2. `bisellium prune` removes a worktree when its task is done, or its PR is merged or closed, or it has no changes and everything in it is already on master; it never removes one created less than an hour ago or one with an open PR, and it removes one with uncommitted changes only when its task or PR has ended (after saving the patch). Agree?
3. Running this sweep automatically on every `bisellium tick` is left for a follow-up task, so for now the sweep runs when a task is done and when someone runs `bisellium prune`. Agree?
4. When a session's sandbox keeps git from deleting a worktree's bookkeeping folder, the worktree itself is still removed and the leftover folder is cleared by a later `prune` from another session; nothing deletes it by force. Agree?
