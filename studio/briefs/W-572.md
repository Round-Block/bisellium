## Intent

On 11-10 the producer asked the Patron, by AskUserQuestion, to choose W-562's route when the leads' meet had already covered it. D-189 says a call goes to a leads' meet first, but nothing holds it: the PreToolUse guard (`bisellium hook-event guard`, `packages/cli/src/guard.ts`) never sees AskUserQuestion, because the repo's PreToolUse matcher is `Bash|Write|Edit|NotebookEdit`. This opus makes the guard see the tool and judge the main thread's questions.

1. **The rule (behaviour 1).** A main-thread AskUserQuestion is refused unless every question in the call either cites a leads' meet collation by its path or opens with a Patron-only tag. The refusal prints the rule and the closed tag list. A subagent's question is not judged. A malformed input is refused (fail-closed).
2. **The wiring and the texts (behaviour 2).** `GUARDED_TOOLS` gains `AskUserQuestion`, so `check --repo`'s `hook.guard` blocks a settings file whose PreToolUse matcher lacks it. The repo's `.claude/settings.json` matcher becomes `Bash|Write|Edit|NotebookEdit|AskUserQuestion`. `CLAUDE.md` (generated from `instructions.ts`) and `docs/INSTRUCTIONS.md` name the refusal. Production lex §7's D-189 line gains the rule with its `(check: hook.guard)` marker.

**Design calls (each a Default the Patron can veto).**

- *What "cites" means.* The question's `question` text holds a path written `/…` or `~/…`. The path starts the text or follows a blank, a quote, a backtick, `(`, `<` or `[`. It runs to the next blank, quote, backtick, parenthesis, angle bracket or square bracket, and trailing `.,;:!?` are dropped. `~/` is the home (`homedir()`, the hook's `HOME`), and `..` is resolved. The path is a collation when it is a regular file by `lstat` (so not a symlink itself), non-empty and readable, and its real path is `<the evidence root's real path>/<dir>/<name>`: exactly one folder under `~/.bisellium-evidence/`, `<dir>` containing `meet`, `<name>` matching `collated*.md` (`^collated[^/]*\.md$`). One such path in a question is enough; the others are not judged. A folder that is a symlink is judged where it resolves.
- *What "opens with a tag" means.* The text's first characters are `[tag]`, the tag exactly one of `ui`, `architecture`, `code-owner`, `settings`, `veto`, lower case. `[UI]`, ` [ui]` (a leading blank), `ui:` and a tag later in the text are not tags. An opening `[x]` that is not on the list is an unknown tag: the question then passes only on a citation, and the refusal names the unknown tag.
- *Every question.* Each question in the call must pass on its own. One failing question refuses the call, and the refusal names its number.
- *Who is judged.* The main thread, as `guardRefusal` already reads it (`main`: no non-empty string `agent_id` and no clerk claim, W-542). Reused, not a new test of who calls.
- *Fail-closed.* `tool_input` not an object, `questions` absent, not a list or empty, an entry not an object, or a `question` that is not a non-empty string: refused, with the rule.
- *The refusal text.* `refused: the orchestrator asks the Patron only after a leads' meet (D-189, W-572): question <n> ("<text, cut at 60>") <why>; each question cites a leads' meet collation by its path (~/.bisellium-evidence/<a folder with "meet" in its name>/collated*.md, a readable regular file, not a symlink) or opens with a Patron-only tag, [ui], [architecture], [code-owner], [settings], [veto]: run the leads' meet first, and ask the Patron only a call that is theirs alone`. `<why>` is `cites no path and opens with no Patron-only tag`, or `cites no leads' meet collation (<path>: <reason>; …)` with the reason for each path. A reason is `no such file`, `a symlink`, `not a regular file`, `empty`, `unreadable`, `not directly in a folder under ~/.bisellium-evidence/`, `its folder <dir> is not a leads' meet (no "meet" in its name)`, `not a collated*.md` or `no ~/.bisellium-evidence/`. An unknown tag adds `opens with the unknown tag [<x>] and `.
