## Intent

Today the Board's waiting strip contains Board-modeled opera, the Inbox list contains only open questions, and the shell maintains separate Inbox and Board totals. Consequently a greenlight or pending human gate can be visible on the Board while absent from Inbox, an orphan question can be counted but absent from the strip, and the two navigation badges can disagree. Current-source evidence is `/home/edckt/agents/bisellium/.worktrees/W-487-spec/apps/web/src/lib/board.ts`, `/home/edckt/agents/bisellium/.worktrees/W-487-spec/apps/web/src/screens/Inbox.tsx`, and `/home/edckt/agents/bisellium/.worktrees/W-487-spec/apps/web/src/App.tsx`.

D-151 replaces D-135's question-only Inbox membership and count while retaining its once-per-opus rule. One ordered `attentionCollection(officina, opera, inbox)` becomes the Board model's waiting strip, the Inbox list and the source of both badges. A linked opus contributes one row even when it combines Greenlight, one or many Inbox decisions, and Human gate. A question naming no Board entry remains one replyable attention row without inventing a lifecycle card. A question with no opus link remains one row under its petitio id. Ruling evidence is `/home/edckt/agents/bisellium/.worktrees/W-487-spec/studio/decisions/D-151.md`; the superseded and neighbouring rulings are `/home/edckt/agents/bisellium/.worktrees/W-487-spec/studio/decisions/D-135.md`, `/home/edckt/agents/bisellium/.worktrees/W-487-spec/studio/decisions/D-138.md`, and `/home/edckt/agents/bisellium/.worktrees/W-487-spec/studio/decisions/D-156.md`.

Inbox keeps the existing Outlook split. A pure Greenlight or Human gate row says `Opens Board drawer`; clicking it or pressing Enter opens the existing drawer. At 840px and wider, its selection fills the existing reading pane with opus id, title, ask kinds and one `Open Board drawer` control, without reply controls. A row with an Inbox decision keeps its existing detail and answer controls in Inbox, and a combined row exposes a small `Open Board actions` control. The Board strip uses the same ownership: replyable questions open their Inbox detail, while Board-only asks reuse the lifecycle-card drawer. No public deep route, second count, endpoint, write shape or drawer is added.

## Defaults for the Patron

1. Show one Inbox row per linked opus, plus one row for each standalone question. If an opus has several open questions, show the first served question and let the existing reply reconciliation advance to the next. Splitting those questions later is isolated to collection expansion.
2. Keep a mixed row replyable in Inbox and add the small `Open Board actions` control. A pure Greenlight or Human gate row states `Opens Board drawer` and opens it directly. Reversing mixed-row precedence later is isolated to `destination`.
3. Keep the shipped Outlook panes and Board waiting-strip layout. Show every ask kind in full, reserve the destination line for Board-only rows, and use the existing reading pane for Board-owned context; do not add a new panel, icon language or preview variant.
4. Give Inbox and Board the same collection count. Expanded badges show the full number; collapsed badges keep the shipped `9+` presentation. Do not retain a question-only count anywhere.
