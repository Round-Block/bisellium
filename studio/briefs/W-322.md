## Intent

Class `tests×ruled-case-uncovered` (D-076 D, high, D-039): a brief rules a case, no test pins it, and review finds it. The record names W-292 spec round 2 S1, W-293 build round 1 and W-178 build round 1 (a commented-out runner import still counted rows); W-178's rounds 2 to 4 then each found a new form of the same rule (a member call, a cross-paired line, a Unicode binding; D-085). D-085 D adds the loop's cause: a row whose valid domain is any text, for a lexical rule, that does not list the forms it recognises, so each review round may lawfully name a new one (W-178 row 4, W-221's "Any string", `review-loop-1019/compiled.md` sections 1 and 2, P2).

After this opus the W-319 ledger check reads one more thing from the brief, for the design magister's spec signature: each Input domain row holds a pin, `` pinned by `<test row>` "<assertion text>" `` (the test row's name and a text of the assertion that exercises the row), or says `unpinned`, and then its covering ledger line says `scoped` (a stated limit, D-076 E). A row whose Valid domain cell says any text or any string also holds a forms clause: "recognises", the forms (code spans, or `brief:<n>` citations of the lines that list them), then "every other form" and "limit"; each line it cites holds a pin of its own. The writer refuses the signature otherwise, one problem per row or line. The build round's packet then lists, in `facts.txt`, every ruled case none of whose pins it finds in the source diff from the merge-base with master. One reader in `brief-admission.ts` serves both; no new verb, no new file format.

What it catches, measured on master's briefs with the prototype's reader (`census.out`): 60 of 154 briefs have Input domain rows, 563 rows, none pinned, so every new signature with a table names its tests; 7 rows say any text or any string with no forms clause, W-178 row 96 (the row grammar) and W-221 row 97 (the pipefail classifier) among them, the two loops D-085 names. What it does not catch: whether the pinned assertion tests what the row rules, and whether a forms list is complete. The reviewer keeps both; the packet's list gives the build reviewer the cases with nothing in the diff to point at.

Threat model: mistakes, not adversaries (D-045).

## Interfaces

`ruledCases(briefText: string): { cases: RuledCase[]; formless: number[] }` (new, exported from `brief-admission.ts`, text only). For each row `inputDomainRows` finds, in row order: the row as a case (`line` = `row` = its line), then, when its Valid domain cell names any text or any string, each line its forms clause cites, as a case whose `row` is the citing row. Each case's `pins` are the pins its real line holds (`realLines`: fences and HTML comments blanked), `unpinned` is a row's word. `formless` holds the any-text rows with no forms clause. `RuledCase` is `{ line, row, pins: Pin[], unpinned }`, `Pin` is `{ row, assertion }`.

The forms `ruledCases` recognises, one per line (each is a grammar line of Input domain row 2):

- a pin: `pinned by` or `Pinned by` as whole words, one space, one code span holding a non-blank test row name, one space, a double-quoted non-blank assertion text holding no `"`; several on one line, anywhere on it — pinned by `W-322-b1` "no backticks round the row"
- the word `unpinned`, whole, any case, anywhere on a row's line (beside a pin it changes nothing); it does not excuse a cited grammar line — pinned by `W-322-b1` "an unpinned row covered as holds"
- the any-text trigger: `any text` or `any string`, whole words, any case, in the row's second cell (Valid domain) only — pinned by `W-322-b2` "any text in a Rejected by cell"
- the forms clause, on the row's line in this order: `recognises` or `recognizes`, at least one code span or grammar citation, `every other form`, then `limit` or `limits`; whole words, any case — pinned by `W-322-b2` "no every other form"
- a grammar citation inside the clause: the whole token `brief:<n>`, or `brief:<a>-<b>` for the lines a to b, clamped to the brief's last line (b below a cites a alone) — pinned by `W-322-b2` "the range's last line"

Every other form is a limit, read alike by the writer and the packet: a pin split over lines, a typographic quote, a row name holding a backtick, an assertion holding `"`, a pin in a fence or an HTML comment, a forms clause spread over two lines, and a row that rules text without the words any text or any string (it needs no forms clause). Ordinary edits in a listed form stay inside the domain: prose before or after a pin, a capital P, two pins on one line, a pin in any cell.

`promiseLedgerProblems(brief, transcript, briefRel)` (W-306, W-319) gains, after W-319's row problems and only once a ledger is cited:

1. For each case with no pin, in case order: a cited line gives ``brief:<m> is a grammar line brief:<n> recognises, with no pin: name its test row and assertion as pinned by `<row>` "<assertion>"``; a row that does not say unpinned gives ``brief:<n> is an Input domain row with no pin: name the test row and assertion that exercise it as pinned by `<row>` "<assertion>", or say unpinned (a stated limit, scoped in the ledger)``; an unpinned row that some counting ledger line cites, none of them with the whole word `scoped`, gives `brief:<n> says unpinned, and no ledger line cites brief:<n> as scoped` (an unpinned row with no counting line has W-319's problem only).
2. For each formless row: `brief:<n> rules any text or any string and lists no forms: say "recognises", then the forms (code spans, or brief:<line> citations of the lines that list them), then "every other form" and "limit"`.

`runVerdict` is unchanged: each problem prints as `<id>: promise ledger: <problem>`, and the writer exits 2 with no log written and the ticket unclaimed.

`pinFact(studio, repo, studioRel, id)` (new, in `review-packet.mjs`): for a build packet, after the brief admission block, the block `== ruled cases with no pinning assertion in the diff`, its source line, then one line per case none of whose pins is found, in case order, or `(none)`: `brief:<n> (Input domain row): <why>` or `brief:<m> (grammar line of brief:<n>): <why>`, `<why>` being the pins and `: not in the diff`, `unpinned`, or `no pin`. The base is `resolveTestBase(repo)` (W-178); with none, the block's third line is `no base: <its reason>` and no case is listed. The diff is `git diff --no-color --no-ext-diff --unified=0 <base> HEAD -- . :(exclude)<studioRel>` through `runGit` (the officina excluded, so the brief's own pins never match). The forms the diff reader recognises (grammar lines of Input domain row 6):

- a line starting `diff --git ` opens one file's set of added lines — pinned by `W-322-b3` "rows 6 and 10 are found; the others are listed in brief order"
- a line starting `@@` opens a hunk; a line starting `+` inside a hunk is an added line, its text after the `+` — pinned by `W-322-b3` "rows 6 and 10 are found; the others are listed in brief order"
- a pin is found when one file's added lines hold its row name and its assertion text, each as a substring of some added line — pinned by `W-322-b3` "rows 6 and 10 are found; the others are listed in brief order"

Every other form is a limit: a pin whose assertion sits in another file than its row name, a pin to a test the opus does not change, a renamed test with no added line, and text git escapes in a quoted path; each lists the case, which the reviewer reads.

The `docs/ADOPTION.md` paragraph (`prototype-src.diff`) states the rule and its limits.

Promise pins-required: a spec signature by the design magister is recorded only when each Input domain row `inputDomainRows` finds holds a pin or says unpinned with a scoped covering line, and each line an any-text row's forms clause cites holds a pin — limit: a pin is read as words; its test row and assertion are not looked up at signing, and the packet's list is where a pin with nothing behind it shows.

Promise forms-required: a row whose Valid domain cell names any text or any string is recorded only with a forms clause listing at least one form — limit: the trigger is those words in that cell, so a row that rules text in other words needs no clause; the list's completeness is the spec review's.

Promise packet-lists: a build packet's `facts.txt` names each ruled case none of whose pins its source diff holds — limit: found means two substrings in one file's added lines, not that the assertion exercises the case.

Limits, stated:

- Only new signatures are judged; recorded signatures are not re-read. Every row of master's 60 tabled briefs is unpinned (`census.out`); a brief signed again names its pins then.
- Unchanged code the promises lean on is a stated limit, not a guarantee (D-076 E): `realLines`, `inputDomainRows`, `cellsOf`, W-306's and W-319's ledger reader (`CITATION_TOKEN`, `STATUS`, the counting rule, `readDesignMagister`), `runVerdict`'s refusal order, `resolveTestBase`, `runGit`'s 4 MiB cap (an oversize diff refuses the packet, and the review perform holds) and `readContainedRegularFile`.
- The packet's list is a fact for the reviewer, not a gate; the build review prompt is unchanged (`studio/prompts/build-review.md` already hands the reviewer `facts.txt`).
