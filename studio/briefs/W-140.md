# W-140 — brief admission's parser is the only behaviour counter

The spec gate is written by `bisellium verdict W-140 --phase spec`, not by this text.

## Intent

Decree family: brief-admission

W-140's title carries five follow-ons. Three come from W-127's round-2
advisories (`ci/W-127-review-2.log` findings 1-3) and belong to one decree:
**a brief is read by one parser, `packages/commands/src/brief-admission.ts`.**
The other two come from W-123's open questions 2 and 3 (`briefs/W-123.md`,
"Out of scope"). They are about landing a branch on master, a different
family, so this opus does not carry them (see Out of scope).

This opus does three things:

- the receipt gate (`builder-run.ts` `declaredBehaviours`, line 171) and the
  host runner (`scripts/run-builder-host.mjs` `countBehaviours`, line 434)
  stop keeping private copies of the pre-W-127 section rule and call
  `countBehaviours` from `brief-admission.ts`;
- the shapes W-127's review listed (unterminated fences and comments, `~~~`
  fences, indented fences, mid-line comment openers, CRLF) get pinned rows;
- `readBriefAdmission`'s export is narrowed to the two-argument signature
  that W-127's brief signed.

**Measured at master `88035da`.** Script and output:
`~/.bisellium-evidence/W-140-spec/measure.mjs` → `measure.out`. The script
lifts both private counters verbatim out of their source files, so it
measures the code, not a copy of it.

- **On every real brief the three counters agree.** 90 briefs
  (`studio/briefs`, `examples/sample-studio/briefs`), 0 disagreements. No
  real brief has an HTML comment, a `~~~` fence, CRLF, a repeated
  `## Behaviours to test` heading or an unterminated fence. One
  (`briefs/W-085.md`) has a four-space-indented fence, and all three count
  it the same.
- **On hostile briefs they part, and only through comments.** Four shapes
  differ:
  - a numbered line inside a comment: admission 1, receipt 2, host 2;
  - a mid-line `<!--` opener: 1, 2, 2;
  - an unterminated comment: 1, 2, 2;
  - a decoy heading inside a comment: 1, 3, 3.

  In each case a receipt built to admission's count is refused by the gate,
  which asks for a red the brief does not declare. The host asks for the
  same red. `~~~` fences, indented fences, unterminated fences, CRLF and a
  repeated heading give the same count from all three.
- **The host can share the parser with no build step.** The host runs as plain
  `node` (`builder-run.ts:233` spawns `process.execPath` with no loader).
  Node 25.9 strips types natively, so a plain `node` process imports
  `packages/commands/src/brief-admission.ts`. The file imports nothing and
  uses only erasable syntax. Measured: the import works and prints nothing
  to stderr.
- `readBriefAdmission.length` is 3 today; W-127's brief signed 2.

**How the host shares it.** `run-builder-host.mjs` imports
`countBehaviours` from `../packages/commands/src/brief-admission.ts` by a
relative specifier. Its other host-owned modules (`replay-accept.mjs`,
`host-cells.mjs`) are reached the same way. The file is read from the host
checkout the runner itself is loaded from, never from candidate code.

## Interfaces

```ts
// packages/commands/src/brief-admission.ts — unchanged except the third parameter is gone
export function countBehaviours(briefText: string): number;
export function readBriefAdmission(briefText: string, limit: number): { problems: string[]; exception?: string };

// scripts/run-builder-host.mjs
import { countBehaviours } from "../packages/commands/src/brief-admission.ts";
```

**`briefAdmissionProblems`** keeps its signature and its output, byte for
byte, in the same order. It calls `readBriefAdmission(briefText, limit)`.
When `exception` is set and its check (today's callback body) returns a
problem `p`, it inserts `behaviour limit exception: <p>` into `problems` at
index 1 when `problems[0]` is a family problem, else at index 0. A family
problem is one that starts with `declares ` or `decree family `.
`exception` is set only when clause 2 found no problem, and clause 1 gives
at most one, so that index is "where clause 2's problem would be".
(ponytail: the index reads clause 1's message prefix; a reworded family
message moves it, and `W-140-b3`'s order rows fail when it does.)

**The census.** A non-test source is a `.ts`, `.tsx`, `.mjs` or `.js` file
under `packages/*/src`, `adapters/*/src`, `apps/*/src` or `scripts/`.
Excluded are names containing `.test.` and anything under `node_modules` or
`dist`. Today the literal `## Behaviours to test` occurs in three of them:
`brief-admission.ts`, `builder-run.ts` and `run-builder-host.mjs`.
`next.ts` and `new.ts` hold the bare section names, without `## `, so the
census does not count them.

**The shape table**, used by behaviour 1. Each brief is
`## Behaviours to test\n` followed by the body shown; `E` is the count the
specified rule gives:

| shape | body after the heading | E |
| --- | --- | --- |
| numbered line in a comment | `1. a\n<!--\n2. b\n-->\n` | 1 |
| mid-line comment opener | `1. a <!-- x\n2. b\n-->\n` | 1 |
| unterminated comment | `1. a\n<!--\n2. b\n` | 1 |
| decoy heading in a comment | the comment `<!--\n## Behaviours to test\n1. x\n2. y\n3. z\n-->\n` placed before the real heading; body `1. a\n` | 1 |
| unterminated backtick fence | ``1. a\n```\n2. b\n`` | 1 |
| `~~~` fence (not a fence) | `1. a\n~~~\n2. b\n~~~\n` | 2 |
| four-space-indented fence (not a fence) | ``1. a\n    ```\n2. b\n    ```\n`` | 2 |
| CRLF | `1. a\r\n2. b\r\n`, heading also `\r\n` | 2 |
| repeated heading | `1. a\n## Behaviours to test\n1. b\n` | 1 |

## Behaviours to test

Behaviour 1 runs in `packages/commands/src/run.test.ts`. It builds its
receipts the way `W-134-b4` does: `liveFixture`, then `admitCurrentRunReceipt`.
It is a plain `test`, not `live`. It writes each brief to
`briefs/W-125.md` in the fixture's officina, which is outside the source
tree. Behaviours 2 and 3 run in `packages/cli/src/brief-admission.test.ts`.
Each row is a `node:test` named `W-140-b<n> behaviour <n>: …`, selected by
`--test-name-pattern=W-140-b<n>`.

1. **The receipt gate counts behaviours with admission's parser, on every shape of the table.**
   For each row of the shape table:
   - `countBehaviours(brief)` is `E`;
   - a receipt with reds `1..E` is admitted;
   - a receipt with reds `1..E-1` plus `E+1` is refused with
     `lacks a replayed red for behaviour E`.

   W-134-b4 and every other `run.test.ts` row stay green unchanged.
   **Genuine red:** today the comment row's receipt with red 1 is refused (`lacks a replayed red for behaviour 2`); the row fails on its `ok` assertion.

2. **Admission's parser is the only behaviour counter in the tree, and the plain-node host loads it.**
   - The census lists exactly `packages/commands/src/brief-admission.ts`.
   - `scripts/run-builder-host.mjs` contains the import line from Interfaces.
   - `spawnSync(process.execPath, ["--input-type=module", "-e", <src>])`, with
     an env holding only `PATH`, imports `brief-admission.ts` by file URL and
     prints `countBehaviours` of the shape table's comment row. It exits 0,
     its stdout is `1`, and its stderr is empty.
   **Genuine red:** after behaviour 1, the census still lists `scripts/run-builder-host.mjs`; the row fails on its `deepEqual`.

3. **`readBriefAdmission`'s export is the signed two-argument signature, and exception problems keep their place.**
   - `readBriefAdmission.length` is 2.
   - A function that is never called makes a three-argument call under
     `// @ts-expect-error`, so `npm run -s typecheck` fails if the third
     parameter comes back.
   - Order rows through `runReady`, with `ready`'s stderr compared by
     `deepEqual`:
     - an invalid exception and no family → `[NO_FAMILY, behaviour limit exception: …]`;
     - an invalid exception and two `## Behaviours to test` headings →
       `[behaviour limit exception: …, has 2 "## Behaviours to test" headings; one section only]`.

   W-127's rows stay green unchanged.
   **Genuine red:** after behaviour 2, `readBriefAdmission.length` is 3; the row fails on its `equal`.

Each behaviour's implementation leaves the next one red (D-036):

- Behaviour 1 changes `builder-run.ts` only.
- Behaviour 2 changes the host, which behaviour 1 does not touch.
- Behaviour 3 is the export's signature, which neither of the first two

**Open questions for the Patron.** Each default ships as stated and can be
vetoed at the checkpoint.

1. **How the host shares the parser.** Default: a relative import of the
   `.ts` source, which Node ≥ 23.6 strips natively. Behaviour 2's plain-node
   row pins it, and `brief-admission.ts` must stay erasable syntax (no enum,
   namespace or parameter properties). The alternative is a generated `.mjs`
   copy, which needs a build step and a staleness check.
2. **Narrow, or ratify the wider export.** Default: narrow it to the signed
   signature, and have `briefAdmissionProblems` place the exception problem
   by index. The alternative is to amend W-127's interface to admit the
   callback, which keeps the code and drops behaviour 3.
3. **`~~~` fences.** CommonMark treats them as fences; W-127's rule does
   not, and no brief uses one. Default: pin today's rule. Changing it is an
   admission change for a later opus.
4. **The split.** Default: (d) and (e) are filed as one landing opus by the
   producer. The title of W-140 is not amended here.
