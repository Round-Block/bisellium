## Intent

W-328 (D-086 B) made `next` re-review a failed build round when a commit after its log changes a path that is not an officina record (`fixedOutside` in `packages/cli/src/next.ts`, filtering with `recordOnly` from `scripts/ci-scope.mjs`). Kept evidence under `studio/ci/reds/<id>/` is a record, so a fix that is only evidence does not count: `redo` stays true and `next` orders a builder fix round (build, phase fix) with nothing to change. Live case (`class-census.out`): W-425's `ci/W-425-review-2.log` failed on one blocker, "no recorded red for the fix round's regression row", tagged `[class: review×evidence-backfilled-or-absent]`; commit b5c78207 added `studio/ci/reds/W-425/fix1-b4.log`, a handoff commit followed, and `next W-425` still names the builder ("review round 2 failed at this tree").

After this opus, a round failed at this tree and brief whose standing blockers are all evidence findings, followed on `opus/<id>` by a commit that adds or changes a file under `<studio>/ci/reds/<id>/`, orders the re-review (review round n+1, the censor's order, the rung W-328 orders), never a builder fix round. Three decisions:

1. **How `next` knows a blocker is an evidence finding.** By its class tag, against a named set. The reader is the one `next` already uses for the round: `f.buildRounds()` (`readBuildRounds`, `parseBuildReviewLog`, `parseVerdictLog`), whose `blockers` are the round's standing blocking findings after `# converted:`. A new `evidenceOnly(round)` judges each blocker's text: it is an evidence finding when it does not open `blocking (security)` (D-044), carries at least one `[class:]` tag, every `[class:` in it opens a whole tag (`CLASS_TAG`, D-070 B), and every tag is in `EVIDENCE_CLASSES`, which is `review×evidence-backfilled-or-absent`, the only evidence class in the officina's logs (`class-census.out`: 18 tags, 12 of them on blocking lines, none beside another class or on a security blocker). `evidenceOnly` is the rejecting function and fails closed: an untagged, malformed, mixed or security blocker is not an evidence finding, so the round goes back to the builder as today. An unreadable log already holds at the review rung (W-167), unchanged.
2. **No fix check is ordered for such a round.** The evidence commit leaves the source tree unchanged, so the round is still current (`failedNow`); D-086 D's fix check (W-309) is ordered only for a round failed at an older tree, and reads source paths still open. The re-review judges the evidence itself (D-066 C), and its inputs already carry `ci/reds/<id>/`. A source change after the round moves the tree, and W-309's fix check runs as today.
3. **An evidence commit that touches other records counts; a commit of other records alone does not.** A commit counts when it adds or changes at least one file under `<studio>/ci/reds/<id>/`, whatever other records it also changes (the opus record, a handoff). A commit of other records only (W-425's later handoff), of another opus's reds, or that only deletes a red, does not count, and does not undo one that does. A commit that changes a path outside the records is W-328's, counted first by `fixedOutside` with W-328's why, unchanged.

Threat model: mistakes, not adversaries (D-045). W-328's behaviour stays: the W-328 rows pass at every stage (`w328-stage<k>.out`).

## Defaults for the Patron

1. **A failed review whose only problems are missing evidence goes back to review once the evidence is committed, not to a builder.** The ladder checks that every blocking problem the reviewer listed carries the "evidence missing or backfilled" class, and that a commit after the review added or changed a kept red for this opus. Then it orders the next review round. Agree?
2. **When the ladder cannot be sure a problem is only about evidence, it sends the round to the builder as today.** A problem with no class, with another class beside the evidence one, with a garbled class, or marked as a security problem counts as not evidence-only. Agree?
3. **No extra fix check runs for such a round.** The code did not change, so there is nothing for the fix check to read; the next review judges the evidence. Agree?
4. **A commit that adds a red and also edits the opus record or the handoff still counts; a commit that only edits the record or the handoff does not.** Agree?
5. **No file this opus changes is code-owned**, so its PR merges through the queue without your review. Agree?
