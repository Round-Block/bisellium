## Intent

D-088 F (3), reshaped by D-090 B and C: one states matrix (loading, empty, error, refused, stale, live, pending) on all four console screens (Inbox, Board, Seats, Officina), each served cell a served test with an `aria-live` row, and an `@axe-core/playwright` scan of every named state whose failure fails the task. A clean scan is not claimed as full conformance (D-090 C).

What master does today, measured on the served bundle (`probe-axe-master.out`, the source read whole):

- **No screen announces anything.** There is no `aria-live` or `role="status"` element in `apps/web/src`.
- **The Inbox invents petitions on a failed read**: `fetchInbox().catch(() => setData(DEV_DATA))` shows three demo petitions as if real. While loading it shows "Nothing waiting on you". An answer in flight shows nothing.
- **Seats and the Board swallow a failed read**: Seats renders empty tables forever; the Board's `Promise.all` rejects unhandled and its columns stay empty. Neither has loading or empty copy.
- **The Officina's panels** carry their own loading, failed and empty copy (W-025, W-077, W-153); the screen as a whole reports nothing.
- **axe on master's loaded screens** finds `color-contrast` (serious) on all four: the palette's `--ink-3` `#788582` is 3.83:1 on `--surface` and 3.56:1 on `--wash`, under 4.5:1. Measured from `tokens.css` (`r3/darken.out`), amber (3.64:1 and 3.38:1), ok (3.39:1 and 3.15:1) and bad on `--wash` (4.39:1) also miss the 4.5:1 text floor. With the states reachable, axe also finds `scrollable-region-focusable` (serious) on the Officina at 390: `main.shell__main` scrolls but cannot take focus (`states-proto-try1.out`).

## Interfaces

The prototype is twelve commits after master fa53e279, a test commit and then a feature commit per behaviour: `test(W-341): row b<k>, red`, then `feat(W-341): behaviour <k>`. `apply-stage.py <checkout> <k> <test|src>` writes any stage from the final snapshot (`final/`) and master. `stages.sh` rebuilds the clone's branch and the mbox, and `reds.sh` replays every red and stage. 1. `STATES_MATRIX: Record<Screen, Record<ScreenState, { copy: string } | { na: string }>>`. Served cells: Inbox loading, empty, error, refused, pending; Board loading, empty, error, stale, live; Seats loading, empty, error, refused, pending; Officina loading, empty, error. `servedCells()` lists them in matrix order (18).
2. `screenStatus(screen, input: StatusInput): ScreenStatus`, pure. `StatusInput` is `{ loaded: boolean; empty?: boolean; failed?: true | string; refused?: string; pending?: boolean; live?: boolean }`. The precedence is pending, refused, error (`failed` set), loading (`!loaded`), stale (`live === false`), empty, live (`live === true`), then "ready". "ready" is `{ state: "ready", text: "" }`. Otherwise the text is the cell's copy, with two exceptions: a string `failed` is its own copy (a write failure), and a non-empty `refused` is appended to the cell's copy after one space. A chosen state whose cell is `na` throws `<screen> cannot be <state>: <reason>`.
3. Screens: `Inbox`, `Seats`, `Board` and `Officina` each take an optional `onStatus?: (s: ScreenStatus) => void` and call it from `useEffect` keyed on `[status.state, status.text]`. The inputs are:
   - **Inbox:** `loaded` (the first read landed), `empty`, `failed` ("Could not send the answer." on a write error, else `true` on a read failure), `refused` (the server's output) and `pending` (an answer in flight).
   - **Seats:** the same, on `/api/officina` and `/api/delegate`. `/api/models` failing stays a degrade, not an error.
   - **Board:** `loaded = everLoaded`, `empty = opera.length === 0`, `failed` (the last reconciliation failed) and `live = everLoaded ? connected : undefined`.
   - **Officina:** `loaded` (aerarium, health, completion and acta all settled), `failed` (any of the first three "failed"), and `empty` (no budget, no milestone meter, no acta, nothing due).
4. Views: `InboxView`, `SeatsView` and `BoardView` gain an optional `notice?: string`, rendered as `<p class="screen-notice">` only when set:
   - **Inbox:** the notice replaces the empty copy in the empty layout, and sits first in the decision panel in the split layout.
   - **Seats:** after the honesty line.
   - **Board:** under the header, with `board__notice`.

   The containers set `notice` for loading, a read error and pending (Inbox), and for loading, empty and a read error (Seats, Board). Refused and write-error copy stays in the existing `.inbox__error` and `.seats__confirm-error`. The Board's stale and live copy stays in `.board__liveness`.
5. `App`: `useState<ScreenStatus>(READY)`. The region is `<div className="shell__status" role="status" aria-live="polite" data-state={status.state}>{status.text}</div>`, the last child of `.shell`. `main.shell__main` gets `tabIndex={0}`.
6. Served suite: `DRIVERS` maps each served cell key (`<screen>:<state>`) to a driver that steers reads or writes with `page.route` (hold, fulfil 500, fulfil fixture JSON, fulfil a refusal `{ ok: false, exitCode: 1, output }`), then asserts the visible copy. The Board's stale driver stops the real server under a connected Board. The file throws at load if the drivers and `servedCells()` differ. Each test runs `new AxeBuilder({ page }).analyze()`, with no rule, tag or region left out, and expects the mapped violations to equal `[]`.
7. Palette: the four token values of Intent 5 in `tokens.css`, the same values in DIRECTION.md §3 and in W-024's `tokens.test.ts`. Row b6 parses `--<name>: #rrggbb;` from the `:root` block and computes WCAG 2.2 relative luminance and contrast.
