## Intent

Patron, on P-015 (2026-10-01): build the check; a test that waits on wall-clock
sleep where a synchronisation seam is missing is a blocking finding. The class
`tests×wall-clock-sleep-for-a-missing-seam` was filed by retro in cascade 32
(L-035) and again in cascade 35 (L-050), and the live offender has cost at least
three PR round-trips (139, 153, and one on 2026-10-01).

**The live offender, root cause.** `scripts/no-vendor.test.mjs` behaviour 9 row 3
asserts "the lock was never free before A had already produced its (correct)
result". A is a separate process whose script is `runOnce(...)` followed by
`writeFileSync(aResultPath, ...)`. `runOnce` releases the lock in its `finally`,
which runs when it *returns*, so the lock is legitimately free for the interval
between A's `releaseLock` and A's own `writeFileSync` of the result file. The
test polls the lock with a 1 ms `setTimeout` loop and sets `racedEarly` when the
lock is free and the result file is absent. Whenever the poll lands in that
interval (a loaded CI runner makes it wide) the row fails with a correct
implementation (`attempts=NN` in the detail). The test's "result produced"
signal is, by construction, emitted *after* the event it is ordered against, so
no amount of tuning the sleep fixes it. The missing seam is a point inside A,
after adjudication and before release, where A can say "I am about to release"
and wait.

**Two halves, one decree family.** (1) the check rule; (2) the repairs that make
the tree pass it. They are one family: the rule is blocking, so merging it
without the repairs turns master red, and the repairs have no reason to exist
without the rule. Split per W-127's rule (not yet built, honoured here) is
therefore **not** warranted. What is a follow-on, not folded in, is named under
"Follow-on filings".

**Blocking at once, not advisory first.** The decree says blocking; the tree is
made to pass in this same opus, so there is no window in which master carries a
violating test; and an advisory stage is a second state with a second PR and a
second place for the class to recur (it has already recurred twice across
cascades while only a retro class existed). The ratchet is the annotation grammar
below, not a delay.

## Interfaces

### The rule: `test.sleep`, level **block**

New module `packages/cli/src/rules/tests.ts` exporting `scanTests(root, opts):
{ findings: Finding[]; sites: string[]; covered: Covered[] }` and `checkTests(root,
opts): Finding[]` (= `scanTests(...).findings`) (Seam S2: `root` the officina,
`opts.repo` the repo root). `sites` is every primitive line as `path:line`;
`covered` is one `{ where, annotation: "seam" | "waiver", kind }` per site carrying a
**valid covering annotation** (kind is the waiver kind, or `"seam"`). Wired in
`check.ts` beside `checkEvidence`. Registered in `rules/ids.ts` as `"test.sleep"`.
Never throws; reads, never writes; file contents are data.

**Observation failures are findings, not silence.** `[]` only when `opts.repo` is
absent. With `opts.repo` present, a `git ls-files` that fails, is not a repository,
or exceeds 30 s yields one block finding (`where: "git ls-files"`, message "could not
enumerate tracked files (<reason>); the sleep scan did not run"); a root
`package.json` that exists but does not parse yields one likewise ("could not parse
package.json; registered test paths unknown"); a scanned path that cannot be read
(other than ENOENT, a tracked file deleted in the working tree, which is skipped)
yields a per-path finding. This is deliberately unlike `rules/evidence.ts`: a rule
that cannot observe and says nothing would pass every sleep.

**File set.** `git ls-files -z` in `opts.repo` (tracked only; an untracked test file
is unseen until `git add`, stated residual). A path, on its repo-relative POSIX
form, is scanned when all hold:

1. its extension is one of `.ts .tsx .mts .cts .js .mjs .cjs`;
2. no segment is `node_modules` (`fixtures/` is **not** excluded: 1 tracked script,
   0 hits);
3. it is a test file by name (`\.(test|spec)\.[cm]?[tj]sx?$`), OR a directory
   segment is `test`, `tests`, `tests-serve`, `__tests__` or `e2e`, OR it is
   **registered**: it equals a whitespace-separated token (leading `./` stripped) of
   any value in the root `package.json` `scripts` whose key starts with `test`. This
   brings in files the suite runs that match no name pattern
   (`packages/cli/src/test.ts`, `scripts/no-vendor.mjs`).

Each scanned path is then `lstat`-ed: a **symlink** yields a block finding ("tests
are scanned as regular files; track the target as a regular file"), never a silent
skip; a file **over 1 MiB** yields a block finding ("not scanned: over 1 MiB"). A
path the test suite runs that is not a supported extension (`.sh`, `.py`), a nested
`package.json` (`apps/web/package.json` `test:e2e`), and non-JS/TS test sources
(`.vue`, `.svelte`) are not seen; stated residuals.

**Lexical pass.** One deterministic pass per file (no dependency, no parser) splits
each line into `code` and `comment`. State carried across lines: inside a `/* */`
block comment, inside a template literal. State reset at each newline: inside a
`'` or `"` string. Block-comment spans are blanked out of `code`; the first `//`
that is outside any string, template literal and block comment starts `comment` (the
rest of the line is not `code`); string and template **contents stay in `code`**
(builder fixtures are strings and their sleeps count). One exception, so annotations
can sit inside a multi-line fixture: in a line that *begins inside a template
literal*, a trimmed text beginning with `//` is treated as a comment line (an
embedded script's own comment). Lines whose `code` is blank are never sites. The pass
is not a JavaScript parser: a regex literal containing `//` or a quote, and a
backtick nested inside a `${ }`, can desynchronise it; stated residual, bounded by
the census (the pass must reproduce the 36-site count on this tree).

**Sleep-primitive grammar** (applied to `code`; a line yields at most one finding):

| Primitive | Match on `code` | Note |
| --- | --- | --- |
| bare timer | `(?<![.\w$])(?:setTimeout\|setInterval)(?![\w$])` | any non-member occurrence, whatever follows: a call, `?.(`, `.call(`, `.apply(`, `.bind(`, a name split from its `(` by a newline, `promisify(setTimeout)`, `{ setTimeout as delay }`, `const w = setTimeout` |
| member timer | `(\S)\s*(?:\?\.\|\.)\s*(?:setTimeout\|setInterval)(?![\w$])` | flagged **unless** the receiver is a plain identifier in the deny-list `test`, `sock`, `socket`, `req`, `res`, `server` (Playwright and `net`/`http` timeouts, not sleeps). `globalThis`, `global`, `window`, `self`, `timers`, `this`, any other identifier, and a non-identifier receiver (`)`, `]`) are flagged |
| sleep | `(?<![\w$])sleep\s*(?:\?\.\s*)?(?:\.\s*(?:call\|apply\|bind)\s*)?(?:\(\|$)` and `(?:\?\.\|\.)\s*sleep\s*(?:\?\.\s*)?(?:\(\|$)` | bare, and any-receiver member (`h.sleep(`); a `function sleep(` declaration is itself a site |
| playwright | `\bwaitForTimeout\b` | any occurrence |
| atomics | `\bAtomics\s*\.\s*wait(?:Async)?\b` | |
| timers/promises | the specifier `timers/promises` in `code` | an `import`, `require` or `import()` of it is the site (it hands out `setTimeout` and `scheduler.wait` under any local name) |
| computed | `\[\s*["'\x60](?:setTimeout\|setInterval\|sleep)["'\x60]\s*\]` | `globalThis["setTimeout"](` |

**Annotation grammar.** A site is covered by the `comment` of the site's own line
(trailing) if that begins `// sleep-`, else by the `comment` of the immediately
preceding line, which must have blank `code` (a comment-only line). Block comments
and `//` text inside a string never annotate. A single-line fixture string
(`builder("...setInterval(...)")`) is annotated on the line above or trailing
outside the string; a site inside a multi-line template fixture gets the annotation
line inside the template, which must contain no backtick, no `${` and no backslash
(it is a valid line comment in the embedded script and changes nothing it does).

```text
// sleep-seam: <name> -- <what the wait exits on>
// sleep-waiver: <kind> -- <why no seam can exist here>
```

Parsed by the literal `^\/\/\s*sleep-(seam|waiver):\s*(\S+)\s+--\s+(\S.*)$` on the
trimmed comment; a comment beginning `// sleep-` that does not match is "malformed
annotation". A site is diagnosed with the **first** failing check, in this order:
no annotation; malformed; unknown kind (waiver: not one of the four; `settle`
included); bad name (seam: not `[A-Za-z_/][A-Za-z0-9_./-]{2,}`, or a primitive's own
name); name not used (seam: the name does not occur, word-bounded as
`(?<![A-Za-z0-9_])name(?![A-Za-z0-9_])`, in the `code` of any line within 40 lines
either side of the site, the site line included); reason too short (after `-- `,
trimmed: fewer than **15 non-whitespace characters** or fewer than 3
whitespace-separated words).

- `sleep-seam` means: the wait is on a named observable (barrier, marker, event,
  predicate) and the sleep is only the poll cadence. The name check catches typos
  and names that exist nowhere near the site; **it cannot tell the observable from
  any identifier in scope** (a name like `ready` is satisfiable). Whether the named
  observable is the one the wait exits on is the censor's judgement (Acceptance), not
  the rule's.
- `<kind>` is exactly one of `guard` (a deadline that fails the test or kills a
  fixture, not what correctness waits on), `subject` (the elapsed time is the
  property under test), `fixture` (a keep-alive or injected-latency fixture),
  `no-observable` (an ordering or absence window with no observable; the reason must
  name what is missing, which the censor judges). **`settle` is deliberately not a
  kind**: "let it settle" is the class itself.

**Finding.** `rule: "test.sleep"` (written as exactly that object-literal property so
the drift guard harvests it), `level: "block"`, `where: "<path>:<line>"` for a site
(`"<path>"` for a file-level finding), message naming the primitive and either "no
annotation" or the defect. Annotations that cover no site are ignored (no finding)
and are not counted.

**Waiver caps are counted by the rule's parser, not by a regex over files.**
`tests.test.ts` behaviour 5 calls `scanTests` on the real repo and counts `covered`
entries: constants `WAIVER_CAP = 18`, `GUARD_CAP = 9`, `NO_OBSERVABLE_CAP = 5`,
`SEAM_CAP = 6` are **literals in `tests.test.ts`**, never imported from `tests.ts`.
Raising any of them needs an architect ruling recorded in this brief's revision
table; a builder or later opus cannot do it as a side effect. (Fixture annotations
inside `tests.test.ts` template literals cover no site, so they are not counted.)

### The seam for the live offender

`scripts/no-vendor.mjs`: `runOnce(opts)` gains an optional `opts.beforeRelease`.
In the `finally`, iff this call acquired the lock (not on the refused-lock path,
where the lock is another run's), the release becomes:

```js
if (lockHeld) {
  try {
    if (typeof opts.beforeRelease === "function") opts.beforeRelease();
  } finally {
    releaseLock(lockPath);
  }
}
```

So: called **once, synchronously, immediately before the guarded `releaseLock`**,
with no arguments, and changes no result; a non-function value is ignored; the
lock is released whether the hook returns, throws or is absent. **A throwing hook
propagates out of `runOnce`** after the release, replacing any pending return or
exception (JS `finally` semantics); this is accepted and asserted because the hook is
test-only. Production callers do not pass it: `main()`'s one `runOnce({ repoRoot:
REPO_ROOT, suiteCommand })` call is unchanged and behaviour 4 asserts it names no
hook. No env var, no CLI surface (unlike W-101's barrier, `runOnce` is called
in-process by the test's own script, so an option suffices).

`scripts/no-vendor.test.mjs` row 3 is rewritten with **no timer and no poll**:

- A is spawned as `spawn(process.execPath, [aScript], { stdio: ["pipe", "pipe",
  "inherit"], timeout: 30_000, killSignal: "SIGKILL" })`. **The `timeout` option is
  the row's deadline** and is not a sleep primitive: if the hook is never reached or
  never released, the kernel-level kill makes `exit` fire, so CI cannot hang on this
  row. The test reports "A was killed after the deadline" when `signalCode` is set.
- A's script passes `beforeRelease: () => { writeSync(1, "HOLD\n"); readFileSync(0); }`
  (a pipe line, then a blocking read until the test ends A's stdin; a FIFO is the
  stated fallback if the platform returns EAGAIN on fd 0). `runOnce` still returns,
  then A writes `aResultPath`, as today.
- The test awaits with events only whichever of A's stdout `HOLD` line or A's `exit`
  comes first (a crashed A is reported, never hung on). On the line it attempts
  `openSync(lockPath, "wx")`: it must throw EEXIST (the lock is held through
  adjudication, A frozen before release). It then ends A's stdin, awaits `exit`, and
  asserts A's result contains `row3-violation` and the lock file is gone. A's stdin
  is ended in a `finally` so no path leaves A blocked.
- No `racedEarly` flag, no poll loop, no `setTimeout`, no guard timer remains; the
  invariant "released last" is checked at the one instant where it can be,
  deterministically.

## Stated residuals (accepted, with reason)

1. **The rule proves declaration, not truth.** It cannot tell a real seam from a
   named one (a seam name is only checked to be a word near the site); the censor
   judges the annotations, and the pinned caps keep the count visible. The
   alternative (semantic detection of races) is not mechanical.
2. **Untracked test files are unseen** until `git add`; CI scans the committed tree.
3. **Busy-waits and elapsed-time assertions** (`Date.now()` loops with no timer,
   `performance.now()` deltas, e.g. `next.test.ts` `zombiePid`) are outside the
   grammar; a census of real cases is the follow-on.
4. **Sleeps spelled outside the grammar**: a name assembled at run time
   (`globalThis["set" + "Timeout"]`), an alias of a deny-listed receiver
   (`const sock = globalThis; sock.setTimeout(`), `eval` / `new Function`, a helper
   that sleeps under another name (its inside is a site only if it uses a primitive),
   and a shell `sleep` in a string handed to `sh` or `execSync`. The rule is a
   guard against drift and accident, not against a determined adversary.
5. **The lexical pass is not a parser**: a regex literal containing `//` or a quote
   and a backtick nested inside `${ }` can desynchronise it. Bounded by the census
   (it must reproduce 36 sites on this tree) and the fact that a mis-parse errs
   towards a spurious finding or a missed site on that one line only.
6. **Playwright specs are annotated, not rewritten**: they are not in `npm test` and
   cannot be replayed in the builder runtime.
7. **Test sources the scan cannot read**: `.sh` / `.py` / `.vue` / `.svelte` files and
   test scripts in nested `package.json` files (`apps/web/package.json`), none
   registered at `41d64dd`; a registered non-JS/TS test file is not scanned.
8. **No `opus.red_assertion` coverage of the TAP form** (pinned to W-096), as in
   W-124.
9. **Sites that move.** The line numbers above are at `41d64dd`; the rule's output,
   not the table, is the builder's work list.
10. **Cost.** Every `checkStudio` call with a `repo` now does one `git ls-files` and
    reads ~83 files; no cache is added. Accepted at this size; add a per-call memo
    if `check.test.ts` runtime visibly grows.

If, during phase 2, a REPAIR site proves to need a production observable (a change
to a module this brief does not own), the builder stops on that site and escalates
to the architect for a scope ruling; it does not reclassify it as a `settle`-style
waiver, because no such kind exists.
