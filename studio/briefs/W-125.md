# W-125 — builders finish in an isolated, executable worktree

Status: **unsigned draft** · architect sella · 2026-10-02.

## Intent

Apply W-125's decree-family rule to W-125 itself. Its title contains three
independent mechanisms: builder execution environment, verdict grammar,
and brief size. They have different enforcement seams and independent
failure conditions. **This brief implements the first family only.** The
producer receives the other two filing briefs below; this draft neither
files them nor changes W-125's opus record or spec gate.

A builder must perform its own test-first work in an isolated worktree
where Git, subprocesses, and the repository's tests actually execute.
`bisellium run` must not return successful builder completion until the
recorded reds and the final full-suite/verify gates are satisfied there.
An orchestrator running failed or omitted builder commands later and
attributing the resulting logs or commits to the builder is retired for
new runs. Historical evidence remains historical evidence.

This is an automated execution boundary, not another review gate. D-014
still gives the independent censor the sole review/QA verdict. D-022's
ui-lead authority is unchanged. D-025 was a bounded model trial, not
standing permission to change builder models or perpetuate proxy evidence.

## Measurement before design

No Git command was attempted in this drafting sandbox. CLI usage was read
with `node --import tsx packages/cli/src/main.ts`, and the architect context
was booted. Source observations below are static measurements, not claims
that a capable builder environment has already been demonstrated.

### Existing execution seam

- `packages/cli/src/run.ts` only re-exports
  `packages/commands/src/run.ts`. The latter already resolves builder seats,
  mints instances, acquires a worktree, sets Git author/committer and
  `BISELLIUM_SELLA`, spawns the supplied command, and records its exit code.
- `--no-worktree` currently permits in-place builder execution. `--base`
  selects a starting ref; `--opus` selects `opus/<id>` as that starting ref;
  they are mutually exclusive. A pre-minted instance without `--opus` does
  not currently select its opus as the base. `--keep` preserves a clean
  worktree, dirty trees are retained, but unknown Git status triggers release
  even with `--keep`. A successful child is sufficient for exit zero.
- `packages/shim/src/worktree.ts` defaults to Git, or treehouse when found
  on PATH. Git creates `bisellium/<sella>/<slot>` using `worktree add -B`.
  Neither provider establishes subprocess permissions or installs dependencies.
  Treehouse's documented/current-version base support is already called out
  as a portability limitation in that source.
- `recordOwnerRefusal` in `packages/commands/src/writes.ts:256` requires the
  tracked opus's owning `opus/<id>` branch when it exists. `verify` and
  `red` use that guard. Forking *from* that branch onto `bisellium/...` is
  therefore insufficient for a builder to record its own gates.
- `packages/commands/src/ci.ts` already owns the six CI steps and invokes
  `runVerify` for `--opus`. Its comments document a separate worktree trap:
  inherited parent `node_modules` can resolve workspace packages from the
  wrong checkout. Its scratch-ref path installs dependencies locally;
  `run` does not. Reuse these CI and verification implementations.
- `verify` writes automated gates and certificates through the existing
  writer. It refuses dirty source by default. `run` presently invokes
  neither it nor the red-evidence checks before reporting child completion.

## Interfaces

Keep the existing public `run` flag grammar and `RunResult.exitCode`.
Apply the stricter path to seats resolved by the existing builder-class
predicate, including pre-minted instances. Non-builder commands retain their
existing generic-run behavior.

For builders, require an effective opus identity from `--opus` or the
instance suffix; reject a mismatch as today. Reject `--no-worktree` and
`--base` before acquiring anything or starting a child. The effective opus
must have an existing owning branch. Acquire a fresh directory on that
actual `opus/<id>` branch, not a new branch merely based on it. If another
worktree already holds that branch, fail with its location; never force a
second checkout, detach another session, reset the branch, or silently reuse
the caller's directory. The operator must release/move the prior checkout
before dispatch. This respects the existing writer guard unchanged.

Extend `WorktreeProvider.acquire` with an optional explicit owning-branch
request. A provider must either honor it exactly or refuse before dispatch;
it cannot silently return a detached or differently named branch. Use the
Git provider for this mode when the optional pool cannot support it. Release
of an owning-branch checkout must never delete its opus branch. Validate
actual branch and physical paths after acquisition. Translate the selected
officina's repo-relative path into this checkout; the sample officina must
never resolve to the real `studio`, or either to the caller's copy.

The execution runtime must permit writes to the checkout and its Git metadata
(including linked-worktree metadata/common object storage), temporary test
directories, subprocess spawning, and loopback servers/browser execution
where required by automated gates. `run` does not grant OS permissions or
escape its enclosing sandbox. Launch it in a provisioned runtime; a denial
is a failed build-environment result with the failed operation and path.
Do not weaken the read-only `talk`/review profiles or introduce a blanket
permission-bypass flag. A successful outer-shell probe is insufficient if
the actual builder's tool runtime applies a tighter inner sandbox.

Before source work, the builder runs the retained probe in its actual tool
runtime: Node child and grandchild execution, Git read and real temporary
index write, temp-file creation, and loopback bind; for UI work also a real
browser launch. Probe scratch writes are cleaned up without altering source
or the production index. Prepare checkout-local dependencies with `npm ci`
and a writable cache, and prove workspace package resolution points into
this checkout. Never symlink the caller's entire `node_modules` or accept a
parent checkout's workspace implementation. Installation failure stops the run.

The builder uses the existing `red` verb for each numbered behaviour before
its implementation, on a committed test-only state. The runner must reject
completion with missing, malformed, duplicate, or non-assertion reds using
the existing check/evidence mechanisms. It must not manufacture reds after
the child returns. Source must be committed by the builder before final
verification; no automatic `--allow-dirty` escape.

After child exit zero, the builder execution runner executes the existing
`ci --opus <id>` path against the acquired repo and its local officina,
including `verify`, before it closes the run as successful. This is part
of the builder process tree; no subsequent orchestrator proxy command may
turn a failed result green. Use the existing CLI implementation from the
acquired checkout so changed workspace packages are actually tested. The
existing automated UI gate must build the web bundle before served tests.
Check required reds and certificates at the final source identity; a changed
tree, dirty source, failed gate, or missing evidence refuses completion.
Do not implement another tree hash, certificate writer, or CI step list.

Child nonzero/signal/spawn-error exits retain their existing meanings. A
capability, preparation, evidence, or post-child gate failure returns nonzero
and identifies the phase and command. The receipt's final exit code covers
the entire builder run, not just the model command. Preserve the worktree,
branch, commits and evidence for handoff on success or failure, even without
`--keep`; unknown status must never cause a destructive release. Print the
path and branch. Existing explicit reclaim remains the cleanup route once
work is merged and clean. Do not automatically review, merge, or mark done.

## Behaviours to test

1. **Builder admission acquires the owning isolated checkout.** In a temp
   repository with a tracked opus and free owning branch, dispatch a builder
   template and, separately, its pre-minted instance. Both run in a distinct
   directory on `opus/<id>`, with the translated local officina and builder
   identity. A real existing CLI writer can record that opus there. Refuse
   `--no-worktree`, `--base`, mismatched identities and an already-leased
   branch before child execution. Preserve non-builder flag behavior.
   **Genuine red:** today's runner accepts builder `--no-worktree` and its
   provider forks to `bisellium/...`; assertion of the owning branch fails.
   Choose one discriminating assertion for the recorded red; other rows are
   regression controls, not additional numbered behaviours.
2. **The builder environment is executable and checkout-local.** Exercise
   the probe and dependency preparation in a temp repo, with a deliberately
   wrong parent workspace package as a sentinel. The actual builder runtime
   successfully spawns a Node grandchild and Git, writes a temporary Git
   index, and uses its own package implementation. Inject subprocess denial,
   read-only Git metadata, failed install and wrong package resolution
   independently; each prevents a successful result and names the cause.
   Include loopback/browser capability when required. **Genuine red:** a
   zero-exit fake builder currently succeeds despite an unavailable Git-write
   capability or parent-resolved workspace package; assert runner failure
   for one such configured fixture. The red is that failed assertion, not
   the injected EPERM message itself. A real capable-runtime smoke run is
   additional acceptance, not a claim that injected errors prove permissions.
3. **Successful child exit cannot bypass red and final green gates.** A
   deterministic fixture builder commits tests, records its selected red via
   the real verb, implements and commits the fix, then exits zero. Before
   runner success, existing CI and verify execute in that checkout and
   certificates identify its final source. Use separate controls for a
   missing red, an executable-error pseudo-red, a failing existing-suite
   assertion, a failed automated gate and source modified after certification.
   Each returns nonzero even though the builder command returned zero; no
   parent checkout evidence is accepted. **Genuine red:** today's runner
   returns zero for the zero-exit child with a failing pre-existing fixture
   suite, without invoking CI/verify. Assert the required nonzero result.
   Keep nested fixture gates small to avoid recursively launching the host
   full suite from inside the host full suite.
4. **Results and evidence survive until explicit handoff/cleanup.** Finish
   a clean committed builder run without `--keep`, and separately force
   unknown status after source/evidence creation. Assert both worktree and
   owning branch survive, the printed location is usable, and the receipt
   reflects the final gate outcome. Pin child failure and successful gate
   controls, and verify explicit reclaim does not remove unmerged work.
   **Genuine red:** today's runner releases a clean worktree without `--keep`
   and releases unknown-status worktrees even with it. Assertion of retained
   worktree/evidence fails. No review or lifecycle advancement is produced.

Give each numbered behaviour a selectable assertion-level TAP row and its
own recorded red. Run the row against the old behavior first; missing new
imports, missing binaries, syntax failures, skips, and environmental denials
alone do not count. A minimal inert test seam may be added before recording
the red, but must not implement the behavior being demonstrated. Retain the
existing full regression suite; do not rename a builder fixture to evade
the new builder contract unless that fixture actually tests generic execution.

## Acceptance

- All four separately recorded reds are genuine, then the focused rows and
  the full CI/verify path pass in the acquired checkout with clean source.
- Perform a real builder dispatch in a runtime provisioned for Git metadata,
  children, temp files and required browser/server operations. Retain actual
  command output, execution cwd, branch, builder identity, red-state identity,
  final source identity and certificates. No live vendor call is added to
  `npm test`; this manual smoke is distinct from deterministic fixture tests.
- Demonstrate that a zero-exit builder with a deliberately failing existing
  fixture-suite assertion returns failure before a review can be dispatched
  by the orchestrating workflow. Repair it in the builder environment and
  repeat successfully. No human runs the missing gate later under the
  builder's attribution. A live runtime failure leaves this criterion unmet.
- Builder dispatch instructions consume successful `run` completion before
  invoking the censor. This opus does not attempt to prevent arbitrary manual
  invocation of the separate review verb; review grammar/admission is a
  different family. It guarantees the runner's successful return boundary.
- Probe and gate failures are actionable and preserve work. No swallowed
  EPERM, unknown-tree certificate, dirty certificate, or parent-workspace
  fallback can satisfy acceptance. Source permissions cannot be demonstrated
  from this architect sandbox; do not sign this criterion here.
- The source changes remain within Files owned. Existing non-builder runner,
  seat resolution, ownership, CI drift, evidence and containment tests remain
  effective. The Censor performs the single independent review under D-014.

## Out of scope / what must not change

- Verdict finding grammar, automatic advisory classification, behavior-count
  limits, decree-family check rules, and filing the two proposals below.
- Model assignments or tiers, D-014 role separation, D-022 design authority,
  spec signing, human UI rulings, or renewal of D-025's trial.
- `talk`/`tick` sandbox policy, general vendor permission bypasses, remote
  execution services, implicit network Git operations, or a new runtime dependency.
- Existing lifecycle ids, wire attributes, certificate hashing/exclusion
  rules, red semantics, owning-branch refusal, or officina bookkeeping writers.
- Fixing historical review findings or amending/erasing historical logs,
  lessons, verdicts, opera, proxy attribution, or decisions.
- Guaranteeing that a green full suite prevents every censor finding, or
  imposing an arbitrary maximum number of censor rounds.

## Follow-on filings for the producer

**Title: BLOCKING verdict findings cite a brief line or become advisory.**
Make the existing verdict writer parse each finding's severity and a citation
to the opus's declared brief, validate the referenced line, and record a
BLOCKING finding without a valid citation as ADVISORY with an explicit
conversion reason. Define outcome reconciliation so converted findings
alone cannot leave a blocking failure behind; preserve substantive valid
blockers and the sole censor's authority. Pin missing, malformed, wrong-brief
and valid citations with assertion-level reds, preserve the raw submitted
text as evidence, and leave historical verdicts unchanged. This filing owns
verdict grammar only; it neither supplies missing tests nor shrinks briefs.

**Title: Split briefs by decree family; check behaviours per opus.**
Have the architect declare one decree family per opus and enumerate its
independently testable behaviours, with separate filing briefs for other
families. Add a check at spec readiness for the declared family and behaviour
count, with a numeric bound and exception authority explicitly settled in
that brief before implementation; the title decrees a bound mechanism but
does not supply a number. Pin an oversized multi-family brief and a bounded
single-family brief, define migration for signed historical briefs, and
reject attempts to hide independent behaviours as unnumbered sublists.
Counting is mechanical; semantic family judgments stay with the architect.
This filing owns brief admission, without changing execution or verdict grammar.
