## Intent

Apply W-125's decree-family rule to W-125 itself. Its title contains three
independent mechanisms: builder execution environment, verdict grammar,
and brief size. They have different enforcement seams and independent
failure conditions. **This brief implements the first family only.** The
producer receives the other two filing briefs below; this draft neither
files them nor changes W-125's opus record or spec gate.

A builder performs its own test-first work in a disposable clone of the
owning branch, with working Git and subprocesses. The host producer creates
and destroys that clone. Successful `run` completion requires independent
producer recomputation and full-suite green, and the review admission seam
refuses either verdict without a successful run receipt at the current
source tree. Producer evidence is attributed to the producer, never to the
builder. Historical evidence remains unchanged.

This is the execution/admission boundary, not another review gate. D-014
keeps the independent censor as sole review/QA authority; D-022 is unchanged.
D-025 does not authorize this permission change. This brief explicitly
authorizes the bounded runtime below under the Patron's W-125 decree.

### Existing execution seam

- `packages/cli/src/run.ts` only re-exports
  `packages/commands/src/run.ts`. The latter already resolves builder seats,
  mints instances, acquires a worktree, sets Git author/committer and
  `BISELLIUM_SELLA`, spawns the supplied command, and records its exit code.
- `--no-worktree` currently permits in-place builder execution. `--base`
  selects a starting ref; `--opus` selects `opus/<id>` as that starting ref;
  they are mutually exclusive. A pre-minted instance without `--opus` does
  not currently select its opus as the base. `--keep` preserves a clean
  worktree, dirty trees are retained, but unknown Git status triggers release
  even with `--keep`. A successful child is sufficient for exit zero.
- `packages/shim/src/worktree.ts` defaults to Git, or treehouse when found
  on PATH. Git creates `bisellium/<sella>/<slot>` using `worktree add -B`.
  Neither provider establishes subprocess permissions or installs dependencies.
  Treehouse's documented/current-version base support is already called out
  as a portability limitation in that source.
- `recordOwnerRefusal` in `packages/commands/src/writes.ts:256` requires the
  tracked opus's owning `opus/<id>` branch when it exists. `verify` and
  `red` use that guard. Forking *from* that branch onto `bisellium/...` is
  therefore insufficient for a builder to record its own gates.
- `packages/commands/src/ci.ts` already owns the six CI steps and invokes
  `runVerify` for `--opus`. Its comments document a separate worktree trap:
  inherited parent `node_modules` can resolve workspace packages from the
  wrong checkout. Its scratch-ref path installs dependencies locally;
  `run` does not. Reuse these CI and verification implementations.
- `verify` writes automated gates and certificates through the existing
  writer. It refuses dirty source by default. `run` presently invokes
  neither it nor the red-evidence checks before reporting child completion.

## Interfaces

### Admission and runtime

Keep public `run` grammar and `RunResult.exitCode`; no new verb. Apply this
path to the existing builder-class predicate, including pre-minted instances.
Require an effective opus from `--opus` or the instance suffix, reject a
mismatch, `--base`, and `--no-worktree` before dispatch. Non-builder behavior
is unchanged. For builders `--keep` retains only host records/exported commits;
it never retains a live clone. Require an existing owning `opus/<id>` branch
and a host producer lease excluding concurrent publication for that opus.

The host producer pins the owning branch tip and creates a **DISPOSABLE
CLONE**, checked out on that same branch name, with its own independent Git
object store and metadata: no linked worktree, shared objects, alternates,
hardlinks, or host Git-directory mount. An existing host checkout is not a
shared clone lease; never reset or detach it. Validate real paths, branch,
and selected officina translation into the clone (sample and real officina
must remain distinct). Publish only by compare-and-swap from the pinned tip;
concurrent host movement refuses publication without overwriting work.

The builder uses Codex `danger-full-access` inside host-enforced Linux
mount, PID, user and network isolation. Only the clone directory and its
private scratch/cache/home directories are writable; no host repo, host home,
credentials, runtime sockets or host processes are exposed. Tool binaries
and Git broker policy are host-owned and read-only. `cwd` is the clone.
**Security consequence:** danger-full-access removes Codex's filesystem and
network restrictions; a clone and `cwd` alone do not confine host writes or
processes. The outer boundary is mandatory, verified before dispatch, and
fails closed if unavailable. This is this brief's W-125 authorization, not
D-025 permission, and does not change `talk` or review sandbox profiles.
See [OpenAI sandbox documentation](https://learn.chatgpt.com/docs/sandboxing).

Git is mediated by the host-owned broker, not merely a PATH wrapper. The
builder cannot write raw Git metadata or bypass the broker with another
binary/library. Allow reads and staging/commits only on the pinned opus
branch and its index; new objects needed for those commits are broker-owned
append-only writes. Deny other refs, stash, branch deletion/reset, config,
hooks, replacement refs, alternates and destructive object-store operations.
There are no remotes, fetch/push, credential helpers or hooks; broker Git
ignores global/system config, uses an empty hooks path and disables external
filters, diff/textconv and signing commands. Arbitrary `-c`, alternate Git
paths and environment overrides cannot reopen these capabilities. A real
index-write probe uses a broker-owned scratch index, not unrestricted `.git`.

Construct the child environment from empty, with exactly these names:
`PATH`, `HOME`, `TMPDIR`, `LANG`, `LC_ALL`, `TZ`, `CI`,
`GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`, `GIT_COMMITTER_NAME`,
`GIT_COMMITTER_EMAIL`, `BISELLIUM_SELLA`, `BISELLIUM_STUDIO`,
`BISELLIUM_SESSION`, `npm_config_cache`, `npm_config_userconfig`,
`npm_config_globalconfig`, `npm_config_registry`.
All values are producer-set: fixed tool PATH, clone-private home/temp/cache,
empty private npm configs, declared builder identity, `CI=1`, UTF-8 locale,
UTC and `https://registry.npmjs.org`. Inherit no other variables, credential
files, SSH agent, tokens, proxy settings, `NODE_OPTIONS` or Git config knobs.
Model authentication/transport stays in a separate host harness/control plane;
no model credential or general-purpose model-network proxy enters the tool
runtime. If a deployment cannot separate them, admission fails.

Default-deny tool-runtime network, including host/LAN access; permit private
loopback for tests. Prefer a copied dependency tree with workspace links
rebased within the clone, or a pre-populated private npm cache. Never symlink
the caller's entire node_modules or resolve packages from a parent checkout.
If `npm ci` requires network, the producer grants only HTTPS registry access
to `registry.npmjs.org` for that preparation phase, with destination/redirect
validation; other registries or Git dependencies fail closed. Disable install
scripts during network access; any required scripts run offline and confined.
Close the exception before source work. Prove local workspace resolution.

Before source edits, run the retained probe in the builder's actual tool
runtime: Node child/grandchild, Git read and real scratch index write,
private temp-file creation, loopback bind, and browser launch for UI work.
An outer-shell probe cannot stand in for this. Retain real output; any
capability/preparation denial stops the run with operation and path.

### Reds, export and producer evidence

For each numbered behaviour, the builder first commits its test-only state
on the owning branch, with a **clean, committed pre-change identity** before
that behaviour's implementation (D-028). Record commit and source-tree ids,
command, selected assertion and builder identity through the existing red
verb. Each state must remain an ancestor reachable from the exported opus
branch; no amend/squash that loses it. Dirty, missing, malformed, duplicate,
non-assertion or unreachable reds refuse completion. Builder local evidence
is diagnostic only; clean source and committed implementation are mandatory.

After the builder exits, the host freezes descendants and snapshots only the
opus branch's reachable commits since its pinned base into a quarantined
export. Validate objects, ancestry, file ownership and paths without running
clone hooks/config/code. Export no working-directory files, Git config,
extra refs, node_modules, receipts or generated evidence. Reject commits
that change protected bookkeeping, including excluded source paths used to
smuggle opus gates/receipts; those remain host-owned. The red commands and
identities are claims to recompute, not imported proof.

Then kill and reap the entire builder process group and all descendants
(including setsid/double-fork escape attempts via the PID boundary), revoke
the broker/network endpoints, and delete the clone and private runtime.
Only after teardown succeeds may the PRODUCER recompute evidence. These
steps also run for nonzero exit, signal, spawn failure and unknown status;
teardown failure prevents success and review admission. Host logs and validated
commits survive, never a directory a reviewer can accidentally execute in.
Uncommitted clone work is intentionally discarded; committed work is the
handoff unit. On export failure retain host diagnostics, not the hostile runtime.

The producer pins immutable tooling to the host's `master` commit at run
start and records that id. Resolve command/shim/adapter packages, CI step
list, certificate writer and check from that read-only host tooling, never
from the clone or candidate package resolution. Reuse existing source-tree
hash/exclusion and evidence mechanisms. Candidate source is tested in fresh
credential-free, confined host-controlled checkouts; it cannot write the
host tooling, receipt store or orchestration process. Candidate test code is
still untrusted. Do not let modified package scripts/CI definitions replace
or skip the host's required suite; test candidate implementations separately
from the immutable controller. UI gates rebuild the served web bundle first.

Re-run **each red** at its clean, committed pre-change identity on the owning
branch, requiring its actual assertion failure, then recompute full CI,
verify certificates and check at the clean final committed candidate tree.
Use the host's trusted brief/manifest/gate definitions. Record actual producer
commands, outputs, attribution and identities; do not copy clone evidence or
relabel producer runs as builder runs. Failed builder exit stays failed even
if a diagnostic host rerun passes. Missing reds cannot be backfilled after
the implementation. Pin the candidate tip through recomputation/publication;
source changes, dirty/unknown identity or any failing gate refuse completion.

### Receipt and review admission

Extend the existing receipt writer, not a parallel receipt format. The host
completion receipt binds opus, owning branch, builder instance, producer
identity, base/final commit, final source-tree id, pinned master tooling id,
red replay identities, gate results, teardown completion and final exit code.
Use the existing front-matter writer to put a `run_receipt` repo-relative
reference on the owning opus only after all required phases succeed. The
host producer alone writes it; clone-supplied references are rejected. A
receipt remains historical when stale, but cannot authorize review.

`runReview` must use the shared admission check before **either `--pass` or
`--fail`**, before reading a verdict into gates or emitting review events.
The opus must carry a contained regular-file reference to a host-produced,
completed successful `run` receipt for this opus/branch and the current clean
source tree, with successful producer gates and teardown. Refuse missing,
malformed, forged/clone-origin, wrong-opus, failed, incomplete, stale or
unknown-tree receipts; no manual, legacy, non-UI, fail-verdict or dirty bypass.
No success flag or a bare child-exit receipt suffices. Resolve source identity
with the existing source-tree mechanism, not HEAD equality alone.

Producer censor dispatch uses this same check before invoking the censor;
direct/manual `review` calls use it too. The transcript-only `verdict` verb
confers no admission and remains unchanged. Do not add a second review gate
or automatically review, merge, or mark done. Historical reviews remain
intact; any new review submission needs the current-tree receipt. Receipt
and admission writes are host trusted operations; arbitrary external edits
to host bookkeeping are outside the builder threat boundary.

## Behaviours to test

1. **Builder admission creates a confined owning-branch clone.** Template
   and pre-minted instance runs use a separate Git store on `opus/<id>`,
   correct local officina and identity. Reject invalid flags/identity or
   concurrent producer lease; preserve generic runner behavior. Prove raw
   Git metadata, other refs, hooks/config and host-path/process access are
   denied, while mediated staging/commit works. **Genuine red:** the current
   runner accepts builder `--no-worktree`; assert admission refusal. Clone
   independence and bypass attempts are regression controls for this boundary.
2. **The builder environment is executable and credential-free.** Probe
   child/grandchild, scratch index, temp, loopback and required browser;
   assert exact environment and local dependency resolution with a wrong
   parent-package sentinel. Test denied agent/token/helper access, push and
   non-registry egress, registry exception closure, failed install and
   capability denials. **Genuine red:** a zero-exit fixture with unavailable
   Git-write capability currently succeeds; assert runner failure. The red
   is the failed assertion, not injected EPERM. Add a live contained smoke.
3. **Producer gates and the current-tree receipt admit every review.** A
   fixture commits a clean test-only state, records red, commits its fix and
   exits; producer replays the red and runs full CI/verify/check before a
   receipt can admit either review outcome. Controls reject dirty/unreachable
   reds, pseudo-reds, forged clone evidence, modified gate scripts, failing
   existing-suite assertions, source drift and missing/stale/failed receipts.
   Exercise direct `runReview` pass and fail plus dispatch admission, with
   refusal leaving gates/events unchanged. **Genuine red:** today's runner
   returns zero for a zero-exit child with a failing existing fixture suite;
   assert nonzero. Keep nested gates small, not recursive host full suites.
4. **Only committed work survives mandatory runtime disposal.** Freeze and
   export validated opus commits, kill/reap descendants and remove the clone
   before producer gates; retain host records and commits for handoff. Pin
   zero/nonzero/signal/spawn-error, unknown status, `--keep`, export/cleanup
   failures, daemon escape and concurrent branch-movement controls. No other
   refs or clone evidence are imported. **Genuine red:** today's runner keeps
   a clean worktree with `--keep`; assert its runtime directory is gone after
   completion. No review or lifecycle advancement is automatic.

Each numbered behaviour has one selectable assertion-level TAP row and its
own genuine red at a clean committed pre-change owning-branch identity.
Missing imports/binaries, syntax errors, skips and environmental denials
alone do not count. An inert test seam may precede the red, not the behavior.
Keep all existing regression coverage; do not rename builder fixtures merely
to evade the contract. Security controls are cases of these four boundaries,
not an additional review round or hidden independent decree family.

  CI, verify and check pass at the final clean source tree. Evidence states
