## Intent

The repeat S1 class `tests×one-sided-bound-assertion` came back in W-487's build review round 1 (`ci/W-487-review-1.log`, commit 66fd454b): finding 2 at `InboxView.tsx:177` (a detached petition shows another opus's Board action) and finding 3 at `App.tsx:100` (both badges keep a stale nonzero count when a mounted screen's first read fails). Its three cause fixes are done: W-334 (a digit grammar read through `Number`), W-376 (`test.one_sided`: an assertion pattern anchored at one end) and W-392 (the same rule over token boundaries in any code file). All three are lexical rules on a line's text, and none of them saw W-487.

The path they miss, checked on W-487's reviewed head fa569dd5 and its spec evidence: the promises the findings break are brief:52 (one total, two badges) and brief:54 (predecessor interactions survive). Each was pinned by a Node row that reads a source file's text and matches it, `W-487-b4` "the shell owns one attention count rather than separate Inbox and Board totals" (`assert.match(app, /const \[attentionCount, setAttentionCount\] = useState\(0\)/)`, `app` read by `readFileSync` from `apps/web/src/App.tsx`) and `W-487-b2` "Inbox refresh consumes the shared attention collection instead of petition rows" (the same over `Inbox.tsx`). Such a row asserts one side only: the text is present. It cannot fail when the code holding that text also does the wrong thing, which is what both findings are. The rules miss it at both ends:

- `test.one_sided` (W-376, W-392) reads an anchor or a token boundary. These patterns are unanchored and hold no boundary, and W-376 brief:57 states an unanchored pattern as a limit.
- The spec signature's kill gate (W-381) asks each pinned line for a kill whose output shows the pinned row failing at its pinned assertion. W-487's kills did just that by changing the matched text itself: `kill-b4.patch` changes `useState(0)` to `useState(1)` on the matched line, and `kill-b4.out` fails at the pinned assertion with that changed line in its `actual:` value, the whole of `App.tsx`. A kill on a text pin passes the gate whatever the code does, so the gate proved nothing about behaviour.

So the open path is a pin on source text, admitted by a kill that changes that text. The cause fix closes it where the pin is admitted, the architect's spec signature (one rule, D-076 D). A kill whose proving failure read the source text the kill changed no longer proves its pin. The proof is lexical and needs no test source: the failing diagnostic's `actual:` value holds, as a whole line, a line the kill's patch adds. A pinned line whose every proving kill is such a text kill is refused, and the refusal names the line it found. The architect then pins the promise by a row on what the code does (a call's result, rendered markup, a served page), or says unpinned and scopes it in the ledger.

What it would have caught (`kill-census.out`, the prototype's rule over the newest kept ledger with kills of each of 44 opera): W-487's brief:52 and brief:54, the two promises its findings break, and brief:48, brief:50, brief:64 and brief:71. Also 50 lines of six earlier UI opera, W-345, W-406, W-408, W-410, W-411 and W-463, each killed by a change to CSS or JSX text that the row matched. W-345's own build review round 1 met the class at `w025.css:656`. Its cost: no engineering or CLI opus is refused (37 of the 44 opera, 351 of their killed lines). Their kills fail on results, stderr or findings, and those never hold the changed source line. 56 of the 733 proving kills are text kills.

False positives, stated: a behaviour that prints a changed line verbatim, such as a template rendered line for line or a usage string printed whole, reads as a text kill. Its way through is a kill on another line, or a pin by a different assertion. False negatives, stated: a text pin through `assert.ok(text.includes(…))` (its `actual:` is `false`), a substring or a plain scalar, and a kill that only removes lines. Each is a limit, and the spec review still reads those.

Threat model: mistakes, not adversaries (D-045).

Promise text-kill: on a brief that names a prototype, a pinned line (an Input domain row, a grammar line or a Promise line) whose every kill that shows a pinned row failing at its pinned assertion failed on the source text the kill changed is refused at the architect's spec signature with `brief:<n>'s kill \`<output>\` fails at a pinned assertion that read the source text the kill changed (its actual holds the added line "<line>")…`, exit 2 and no log written, as pinned by `W-492-b1` "a kill whose actual is the source text it changed" and pinned by `W-492-b1` "a Promise line's kill" and pinned by `W-492-b1` "both pins failing on the text" and pinned by `W-492-b1` "the reader names the added line the actual holds" — limit: the proof is lexical, an `actual:` line equal to a patch's added line, so the false positive and negative forms the Intent names are not told apart.

Promise behaviour-kill: a kill whose proving failure's `actual:` holds no added line of its patch whole still proves its pin as W-381 reads it, and one such kill on a line, or one pin it proves on what the code does, admits the line beside text kills, as pinned by `W-492-b1` "an actual holding a result" and pinned by `W-492-b1` "an actual holding the changed line inside a longer line, as rendered markup holds it" and pinned by `W-492-b1` "a text kill beside a kill on what the code does" and pinned by `W-492-b1` "one pin failing on the text and another on what the code does" — limit: whether such a kill's pinned assertion really reads behaviour stays the spec review's.
