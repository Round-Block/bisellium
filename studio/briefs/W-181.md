## Intent

Decree family: checkpoint-pages-from-records

Today every done checkpoint edits two shared sources by hand: a prose row in `docs/design/dossier/progress-body.html` and the date and status in `body.html`'s masthead. With concurrent lanes, two done heads carry competing edits of the same lines. W-181 moves the checkpoint prose into the opus record. `next --perform --expect done --checkpoint-file <path>` validates a small JSON file before anything is written. `runDone` then writes it as `checkpoint:` alongside `state: done` and `end`. A kept script, `scripts/checkpoint-pages.mjs`, regenerates the post-legacy history rows and the masthead from the records, and `build.sh` runs it before `status-page.mjs`. Done commits are refused if they touch a checkpoint-generated page.

Promise checkpoint-record: a successful `next --perform --expect done --checkpoint-file <path>` that creates `chore/done-<id>` commits the record with `state: done`, `end` and the four validated checkpoint values in one commit — limit: direct `bisellium done` neither requires nor writes a checkpoint (it stays the adopters' primitive); its record renders as `no checkpoint recorded`.

Promise generated-pages: when the generator exits 0, each done record whose `end` is strictly later than the seed boundary has exactly one escaped row, ordered by `end` then id, and the newest such record supplies the masthead date and status — limit: any row 4–6 rejection fails the whole run, so no page changes; a done record with no `end` is legacy and gets no row; the legacy rows stay frozen HTML and are never rebuilt from records; a record done at or before the boundary with no legacy row gets no row; pages lag the records until `build.sh` runs and its records PR lands; publishing the artifacts stays manual.

Promise lane-isolation: a done commit made by `next` changes none of the five checkpoint-generated pages, so concurrent lanes contribute through distinct `studio/opera/<id>.md` files that one later generation pass combines — limit: `docs/SESSION-HANDOFF.md` is still shared by every done commit (W-169 owns per-lane sections); a hand edit to a page outside `next` is not refused; one generator run at a time against a checkout is assumed (one orchestrator).

The threat model is mistakes (D-045). No test row is removed or weakened, and no CI step, receipt, certificate, merge-queue rule, `recordOnly` or `source_excludes` entry changes (production lex §11).

## Interfaces

```text
bisellium next <opus> --perform --expect done --checkpoint-file <path> [--studio <dir>] [--repo <dir>]
node scripts/checkpoint-pages.mjs [--seed] [--studio <dir>] [--body <path>] [--progress <path>]
```

The checkpoint file is one JSON object, stored as a plain mapping in the record:

```yaml
checkpoint:
  pr: 405
  summary: "Checkpoint pages count as records, so done and retro changes take the short merge-group path."
  spend: "Codex Sol draft and reviews; Opus architect; Sonnet builder; Haiku publication."
  review: "Build review passed in round 2 after correcting one stale test title."
```

`readCheckpointFile` uses `--body-file`'s containment: the realpath is a regular file under the repository or `os.tmpdir()`. The file is at most 16 KiB and holds exactly the keys `pr`, `summary`, `spend` and `review`. `pr` is a positive safe integer. Each text is non-blank, at most 2,000 characters, with no control character (so no line break). The values are stored as given and escaped only when rendered.

The generated pages are `body.html`, `progress-body.html`, `status-body.html`, `bisellium-dossier.html` and `bisellium-status.html`, all under `docs/design/dossier/`.

The seed (`--seed`, run once by the builder as the branch's last commit) refuses if any marker exists. It writes `<!-- checkpoint-rows legacy-through=<iso> -->` and `<!-- /checkpoint-rows -->` after the last legacy row in `progress-body.html`'s one `<tbody>`, and a `checkpoint-masthead` pair around the masthead's `date` and `status` spans in `body.html`. `<iso>` is the newest valid `end` among done records (W-209's `2026-10-10T19:45:19.935Z` at 580d5fd5).

The generator:
1. reads both templates and `readOfficina(studio)`;
2. requires exactly one marker pair per page, in place (the progress pair inside the one `<tbody>`; the masthead pair inside `<header class="masthead">`, enclosing exactly the `date` and `status` spans), with the same valid boundary in both;
3. refuses a done record whose `end` is present but not a strict UTC ISO instant, and selects done records whose `end` is later than the boundary;
4. sorts them by `end`, then id;
5. renders `<tr data-opus="<id>"><td><strong><id></strong> &middot; <yyyy-mm-dd></td><td><strong>shipped (PR <pr>)</strong> — <summary></td><td><spend></td><td><review></td></tr>`, every value through `esc`;
6. builds the masthead from the newest record: its `end` date and the status `<id> shipped (PR <pr>) — <summary>`;
7. computes both outputs in full before its first write, rewrites only the bytes between the markers, and writes through `writeCheckpointPages` (temporary file, then rename, per page).

A record with no `checkpoint` renders `<id>` and its date, then `done — no checkpoint recorded` and its escaped `title`, with empty spend and review cells. As the newest record, it gives the masthead status `<id> done — no checkpoint recorded`.

### Input domain

Every rejection below fails closed: `next` exits 2, or holds before `chore/done-<id>` exists with the record byte-identical, or the generator exits 2 before its first write (rows 4–6). A failed write (row 7) is not a rejection: it exits non-zero with no page partly written, and at most the first page replaced by a rename. Git shows any change.

## Defaults for the Patron to veto

1. The record keeps four plain values: PR number, what shipped, the spend line and the review line.
2. The existing history rows stay exactly as they are; only later rows are generated, labelled by opus id and finish date instead of a cascade number.
3. The masthead shows the most recently finished opus; on a tie, the higher id.
4. A finished opus with no checkpoint text still gets a row, marked "no checkpoint recorded", instead of blocking the page build.
5. A done commit never carries the generated pages; one later records PR rebuilds them, for one or several finished opera.
