# W-044 — talk profile is a permission boundary: context/query/check/providers only

Spec of record, signed by the architect, 2026-09-23. The finding is
`docs/research/mast-persistence-gaps.md` remedy 1. The threat model
`docs/research/w044-threat-model-sol.md` (gpt-5.6-sol, D-020 input, not
authority) was checked against the code before this spec relied on it. The
`ready` gate is signed on `opus/W-044` after `bisellium branch` (D-021).
Greenlight is the Patron's.

The recorded title still names `providers`. This spec removes it (see "The
ruling"). The title stays as recorded: it is bookkeeping, and no CLI verb
renames it.

## Intent

`bisellium talk` and `bisellium tick`'s unattended daily both reach the
model through `claudeCodeProfile` (`packages/shim/src/harness/claude-code.ts`).
Its tool list is `Read, Grep, Glob, WebFetch, Bash(bisellium *)`. That last
rule admits the whole CLI:

- `bisellium run … -- <cmd>` and `bisellium red … -- <cmd>` pass arbitrary
  commands through (`packages/cli/src/main.ts:84`, `:97`).
- `answer`, `greenlight` and `budget` are stamped `BISELLIUM_ROLE=patron`
  for any caller (`main.ts:109–119`).
- `talk`/`tick` reach other sellae, `verify`/`ci` run probatio commands,
  and `branch`/`merge`/`close`/`prune` move git.

A sella reads studio files as it works. Those files are data, not
instructions (CLAUDE.md). One injected line in a file therefore gets as far
as execution and a Patron signature, and `tick` does this with nobody
watching.

A second hole sits under the first. `--allowedTools` only pre-approves
tools. It does not restrict which tools exist, and the rules it grants merge
with every user, project and local settings file on the machine. So a
narrowed rule list is not a boundary by itself. The profile must also pin
which tools are available, which settings load, the permission mode and MCP.

This opus closes both holes at the profile, which is the one place every
talk path goes through. It fixes one layer and names the rest (Out of
scope).

## The ruling

**Admitted: `context`, `query`, `check`, plus the bare `bisellium` usage
banner.** Nothing else.

- `context` stays because `resume()` sends no fresh boot bundle
  (`packages/commands/src/talk.ts:317`). A resumed session, which includes
  tick's second-day daily, can only refresh its view by running
  `bisellium context`.
- `query` and `check` are the deterministic read answers.
- The bare banner stays because every boot bundle tells the sella to run
  `bisellium` for flag shapes. Denying it would make that instruction
  impossible to follow.
- **`providers` is cut from the title's list.** Its default `auto` source
  spawns `npx --yes quota-axi` (`packages/providers/src/index.ts:228`). That
  is a network fetch plus execution of third-party code, the only admitted
  verb that would start a process tree outside bisellium. Its cached half
  (`usage.yml`) is already in the context bundle ("Provider posture",
  `packages/commands/src/context.ts:191`). Neither talk nor tick needs the
  live probe. The probe stays an operator act.

**Built-in tools: exactly `Read`, `Grep`, `Glob`, `Bash`.** `WebFetch` is
dropped. It is the profile's only egress, which makes Read + WebFetch an
exfiltration channel, and nothing in talk or tick needs the web.

**tick needs no accommodation.** The daily (`packages/cli/src/tick.ts:71`)
asks for three lines. The model's first turn already has the boot bundle as
its system prompt. tick writes the acta itself from the reply text
(`tick.ts:213–260`), never through the model's shell. A resumed daily
refreshes through `context`, which is admitted. A tick-specific profile or
widening flag would reopen the hole on exactly the path that runs with
nobody watching, so there is none. Behaviour 4 proves the unattended path
carries the same policy and still writes its dailies.

**Settings isolation.** Both `start` and `resume` pass the whole policy.
Permissions are not saved with a session, so each invocation's argv is the
boundary:

- `--restricted`: ignores user/project/local settings files, refuses
  `bypassPermissions`, and confines the file tools to the working directory,
  which for talk is the studio root.
- `--strict-mcp-config` with no `--mcp-config`: no MCP servers.
- `--permission-mode dontAsk`: anything not pre-approved is denied, never
  prompted for.
- `--tools Read,Grep,Glob,Bash`: availability.
- `--allowedTools` with the rules below: approval.

The Bash rules are derived from the three verbs and nothing else:

```
Bash(bisellium)
Bash(bisellium context)  Bash(bisellium context *)
Bash(bisellium query)    Bash(bisellium query *)
Bash(bisellium check)    Bash(bisellium check *)
```

A `claude` that does not know `--restricted` or `dontAsk` exits non-zero,
and talk relays that failure. It fails closed, which is intended.

**Patron stamping is fixed here at the profile layer only.** A talked-to
sella can no longer reach `answer`/`greenlight`/`budget`. `main.ts` still
stamps any shell caller as the Patron: a builder subagent, a codex worker,
a person. That is an authority-model question (who is the caller, and how
the CLI would know), not a profile question. It goes to its own opus (Out
of scope).

## Interfaces

No exported surface changes. `claudeCodeProfile.start` and `.resume` keep
their signatures. Only the argv they hand to `claude` changes: the existing
leading flags, then the policy above. The tests are black-box over that
argv, captured by a stub `claude`, so there is no policy export to import.
That also keeps every pre-implementation red at assertion level rather than
an import failure (engineering lex §2). Keep the policy in one module-local
constant used by both `start` and `resume`. Rewrite the header comment,
which currently promises "new items, talk to other sellae".

## Behaviours to test

All four live in a new `packages/cli/src/talk-boundary.test.ts`. It uses
the `BISELLIUM_ONLY_BEHAVIOUR` harness copied from `lifecycle.test.ts:29–31`,
and its block N is behaviour N. It writes a stub `claude` (node, ESM, the
`harness.test.ts:28` pattern) to a temp bin dir prepended to `PATH`. The
stub exits 0 on `--version`. On every other call it appends its argv as one
JSON line to a log file named by an env var (pick a name `filterEnv` keeps)
and prints a normal JSON envelope. The stub never executes anything it is
handed. The expected policy is written out literally in the test: the test
is the spec, not a mirror of the code.

Assertions judge Bash rules through a **conservative matcher defined in the
test**, whose unknowns count as "admits everything":

- `Bash(P)` with no `*` admits exactly `P`.
- `Bash(P *)` admits `P` and anything starting with `P␠`.
- Anything else counts as admitting every command: bare `Bash`, a `*` in
  any other position, or a `:` form.

The verb universe is derived from the `USAGE` banner (`./usage.js`, the
first token after `bisellium` on each line), plus one synthetic verb the
CLI does not have.

1. **The argv is the policy, on both start and resume.** For
   `claudeCodeProfile.start` and `.resume` (called directly, stub on PATH):
   - The set of `--`-flags is exactly the expected set for that form. For
     start that is `-p`, `--output-format`, `--append-system-prompt-file`
     and the five policy flags. For resume it is `-p`, `--resume`,
     `--output-format` and the five policy flags.
   - `--permission-mode` is `dontAsk`.
   - The `--tools` value, split on commas, equals {Read, Grep, Glob, Bash}.
   - The `--allowedTools` values equal exactly the ten entries above:
     `Read`, `Grep`, `Glob` and the seven Bash rules.

   At HEAD this fails on the missing flags and on the `Bash(bisellium *)`
   and `WebFetch` entries.
2. **Every existing CLI verb outside {context, query, check} is denied.**
   For start and resume, over the USAGE-derived universe, the matcher runs
   against `bisellium <v>` and `bisellium <v> --probe x`. These must be
   admitted if and only if `v` is context, query or check. Bare `bisellium`
   must be admitted. A guard assertion requires the derived universe to
   contain `run`, `red`, `greenlight`, `answer`, `budget`, `talk`, `tick`
   and `providers`, so that a broken banner parse cannot pass vacuously.
   This is the guard, not a deny list: the property is set membership over
   the whole universe. At HEAD `Bash(bisellium *)` admits every verb, and
   the log lists them.
3. **A verb the CLI does not have yet is denied.** The same matcher, for
   start and resume, runs on `bisellium zz-future-verb` and
   `bisellium zz-future-verb --probe x`. Both must be denied. This is the
   deny-by-default property for verbs that do not exist yet. At HEAD the
   wildcard admits it.
4. **Both talk entry points carry the policy, and tick still writes its
   dailies.** Use a temp copy of `examples/sample-studio`, whose magistri
   default to `claude-code`, with `process.env.PATH` pointing at the stub
   and restored afterwards.
   - `runTalk --model-only` runs twice. The first call starts a session and
     the second resumes it (the second log line carries `--resume`).
   - `runTick` then runs with no `opts.talk`, so it takes the real
     `talkOnce` seam.
   - Every logged argv carries the policy from behaviour 1 for its form.
   - The tick writes one daily acta per due magister, as in
     `tick.test.ts`'s real-seam block.

   At HEAD the dailies are written but the argv fails the policy.

The existing suite passes unchanged. `harness.test.ts`'s stub ignores flags
it does not know, and `talk.test.ts`/`tick.test.ts` use the `fake` harness.
If an existing test needs editing, stop and report.

## Order of work, and where each red comes from

The hole is live at HEAD, so every red is recorded before any
implementation, from the opus worktree root, with only the test file
written:

    BISELLIUM_ONLY_BEHAVIOUR=<n> bisellium red W-044 --behaviour <n> --repo . --studio studio -- node --import tsx packages/cli/src/talk-boundary.test.ts .

Use n = 1 to 4. Confirm the four logs differ from each other. No stub phase
is needed: the test imports only exports that already exist. Before
trusting any run, check `readlink -f node_modules/@bisellium/shim` (the
worktree trap). A test that resolves the main checkout's shim is measuring
the wrong file. Then change the profile, and all four go green along with
the rest of the suite.

**Evidence of the hole is string-level, never a working exploit.** The reds
show the current rule list *matching* inert probe strings such as
`bisellium run --probe x` and `bisellium greenlight --probe x`. No process
is spawned with those arguments, the stub `claude` runs no tool, and no
model is called. Do not write, commit or run a prompt-injection fixture,
and do not demonstrate the hole live against a real model before the fix.
The code citations in Intent are the rest of the evidence.

## Out of scope

- **Patron-stamped verbs callable by any shell caller** (`main.ts:109–119`).
  W-044 only removes talk's reach to them. Whether the CLI can know its
  caller is a design question, and it overlaps W-039, which has red logs
  name their sella. **File as a new opus:** "Patron verbs refuse a caller
  that is not the Patron".
- **The codex harness.** `codex.ts` passes no sandbox or approval policy,
  so the user's `~/.codex/config.toml` decides. D-020 already puts codex
  command policy in **W-046**. Until W-046 lands, `talk --harness codex` is
  an attended, unbounded path. No sella in either manifest names `codex`
  today, so tick's unattended path is closed by this opus. W-046's brief
  should carry the condition: no L1+ magister's manifest `harness` names
  `codex` until codex runs read-only on both `exec` and `exec resume`. In
  codex-cli 0.153.4 `exec resume` has no `--sandbox` flag, so that needs
  the `-c` config override.
- **Flag-level reach inside the admitted verbs.** These are accepted
  residuals. Reopen them only if one is observed being abused.
  - `context --studio`, `query … <dir>` and `check <dir>` read other paths
    through the CLI process, which `--restricted` does not confine.
  - `query --from-index` writes the gitignored `.bisellium/` cache.
  - `check --repo <dir>` runs fixed git commands in a directory the caller
    names.
- **`PETITIO:`/`ACTUM:` lines from an injected reply.** No execution and no
  signature are involved, the Patron sees the result, and talk.ts's three
  guards stand.
- **Read/Grep/Glob disclosure within the studio root**, and the loss of
  talked sessions reading repo source outside it. The source-reading loss
  is an accepted narrowing. A `talk --repo` passing `--add-dir` is the path
  if it is missed.
- **Hooks in talked sessions.** `--restricted` drops them. talk already
  writes its own receipt and timeline.
- **Vendor-side matching** (compound commands, command substitution)
  belongs to Claude Code. The smoke checks it once on the installed version.
  Managed (policy) settings still apply and belong to the machine owner.
- **`serve`'s `POST /api/talk`** inherits this through `performTalk`. There
  is no separate work.
