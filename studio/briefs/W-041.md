# W-041 — generated backlog page: the slate rendered from the officina, never from prose

Spec of record. Signed in text: **architect, 2026-09-24**. It was filed at
cascade 22 and revalidated against the tree at cascade 26. The `spec` gate
is signed later by `bisellium ready` on `opus/W-041`, after `bisellium
branch` (D-021: `ready` belongs on the branch).

**D-020's Sol brief red-team was skipped, on stated grounds.** The opus is
not security-touching: it reads front matter and writes one HTML file, with
no execution, auth or network path. It is not cross-cutting either. It adds
one generator script, one `build.sh` line, one guard, and a prose edit to
the handoff. It touches no package, no CLI verb, and no record writer.
Terra pre-review and the censor gate apply as usual.

## Intent

`docs/SESSION-HANDOFF.md` carries the slate as hand-written prose, and that
prose has rotted. Here is what the file says on 2026-09-24, before this opus:

- **Three hand-written rankings in one file, and they disagree.** "Resume
  order" (under "Where things stand") puts W-034 first. "Resume point for
  the next funded session" and item 1 of `### Backlog` put W-033 first.
  Both W-033 and W-034 are `done`.
- **`### New opera opened, none started`** lists W-032, W-033 and W-034.
  Two of the three are finished.
- **`### Backlog` mixes filed opera with unfiled work.** Items 3, 4 and 6–9
  (the Settings screen, Web II, `bisellium ci` undocumented, the
  `branch.ts:172` "into master" string, `run --opus` → `merge`, and
  `run --reclaim`/`prune` blind to `.claude/worktrees/`) are not opera. So
  no generated view can see them.

This is the same rot class W-038 and W-039 were filed against. Every fact
the prose states about a filed opus already sits on disk in structured
form: the opus's `state`, its `traditio.blocked_on`, its halt record, the
petitiones that name it via `opus:`, and the decisions that constrain it.
The prose is a stale copy of the officina.

The dossier pipeline has already solved this problem once.
`docs/design/dossier/build-arch.mjs` renders `docs/ARCHITECTURE.md` into a
page that `build.sh` builds. This opus applies the same pattern to the
slate.

## Preconditions (not this opus's files, and not the builder's to write)

1. **Unfiled items are filed or dropped before their prose is deleted.**
   Items 3, 4 and 6–9 of `### Backlog` are unfiled. For each one, the
   orchestrator either runs `bisellium new --kind <kind> --collegium
   <collegium> --title <title>` (it lands `backlog`), or records in the PR
   description that the item is dropped and why. The builder does not
   delete a line that carries work no record holds.
2. **The ranking moves to an acta.** The page does not rank (see
   "Ordering" below). **Done:** the architect wrote the ranking as
   `studio/acta/2026-09-24-ranking.md` (`kind: daily`,
   `author: architect`). It rides the spec PR as a trunk-side record. A
   later ranking acta replaces it. The builder links to the latest one and
   never authors it.

## Interfaces

```
node scripts/backlog-page.mjs [--studio <dir>] [--out <path>] [--handoff <path>]
```

- **Defaults** are resolved against the repo root, which is the script's
  own `..` (via `import.meta.url`): `studio`,
  `docs/design/dossier/backlog-body.html` and `docs/SESSION-HANDOFF.md`.
- **Flags** resolve against the cwd.

This matters because `build.sh` `cd`s into the dossier directory. With
cwd-relative defaults, the call would read a nonexistent `studio`.

The script only reads the officina and writes one file. It never shells
out, never touches git, and never writes inside `--studio`.

For front matter, parse with the already-installed `yaml` package. Split
the front-matter block the way `scripts/sweep-traditio-stage.mjs` does.
Add no new dependency. Do not import `packages/*` TypeScript: `build.sh`
runs plain `node`, and the packages' `.js` specifiers don't resolve under
native type stripping.

`build.sh` gains two lines before the `echo`, matching the `build-arch.mjs`
calls:

```sh
node ../../../scripts/backlog-page.mjs
sed 's|<title>Bisellium Dossier</title>|<title>Bisellium Backlog</title>|' head.html | cat - backlog-body.html > bisellium-backlog.html
```

### What it reads

The generator reads front matter only.

- **`studio/bisellium.yml`:** the `probationes` list. These are the gates
  the officina declares, and the denominator for the gates cell.
- **`studio/opera/*.md`:** `id`, `title`, `state`, `collegium`,
  `probationes`, `traditio.blocked_on`. For halted opera it also reads
  `halted_by` and `resume_when`, the fields W-042's `halt` writes.
- **`studio/petitiones/*.md`:** `id`, `state`, `opus`. The `opus:` value is
  written both quoted (`"W-020"`) and bare (`W-021`). Both parse to the
  same string, so compare the parsed value, not the raw line. Many
  petitiones carry no `opus:` at all, and those name nothing. A petitio is
  open when its `state` is not `resolved` (`PETITIO_STATES`: `needs_you`,
  `awaiting_reply`, `resolved`). An open petitio that names an opus is a
  blocker on that opus. On today's tree every petitio, P-001 through
  P-011, is `resolved`. So the petitio half of the "blocked on" cell is
  exercised by fixtures only, and that is expected.
- **`studio/decisions/*.md`:** `id`, `title`, `kill_when`. All 21 records
  (D-001 through D-021) carry exactly `id title at provenance by
  kill_when`, and there is no superseded or struck field. The page lists
  every decision and does not try to judge which ones still bind.

**Do not parse brief prose, and do not parse `reason` or `resume_when` for
meaning.** Dependency sentences in briefs ("blocked on W-0xx") are real
information. They should move into `blocked_on`, not be regex-mined out
of English. A `resume_when` of "never — …" renders as written. The record
has no abandoned/halted distinction, so the page does not invent one.

### What it emits

The page has three groups, in this order. Each is a table using the
progress page's existing `.table-scroll` / `<table>` markup.

1. **In flight:** `greenlit`, `building`, `verifying` and `review`.
2. **Backlog:** `backlog`, then `halted`.
3. **Standing constraints:** decisions, with `id`, `title` and
   `kill_when`.

**Halted opera go in Backlog, not In flight.** They are out of play, and
calling them in flight would be a lie. They still render, because one of
them (W-027, "resume when the opus is resurrected") is parked future work,
not history. Within the group, halted rows come after the `backlog` rows.
The state cell reads `halted`.

**Why the In-flight group states its trunk view.** D-021's "Consequence
worth naming" says the trunk only ever shows `backlog`, `greenlit`,
`halted` or `done`. `building`, `verifying` and `review` are written on
`opus/<id>` and reach the trunk only when the branch merges. A page
generated from the trunk therefore shows an opus under active build as
`greenlit`. The page must not present that as fact. The In-flight table's
caption reads, verbatim:

> State as recorded in this checkout's officina. On the trunk, per D-021,
> an opus being built still reads `greenlit` — its live state is on
> `opus/<id>`.

The generator does not overlay branches, since it never touches git.
Teaching views to read live opus branches is the future work D-021 names,
and it belongs to the Patron.

**Columns for groups 1 and 2:** id · title · collegium · state · blocked
on · gates.

- **"Blocked on"** has two forms:
  - For a non-halted opus: `traditio.blocked_on`, joined with any open
    petitio that names it (for example `P-012 (needs_you)`). If there is
    neither, the cell is an em dash.
  - For a halted opus: `halted_by`, then `resume_when` (for example
    `D-017 — the opus is resurrected — …`). A halted opus's
    `traditio.blocked_on` predates the halt and is stale (W-023's still
    says "no per-opus halt verb exists"), so it is not shown.
- **"Gates"** is `passed/declared`. `declared` is the length of
  `bisellium.yml`'s `probationes` list. `passed` counts the entries in the
  opus's `probationes` map whose `status` is `passed`. If any gate is
  `waived`, append ` · N waived`. A waiver is a Patron decision (W-034),
  not a pass, and the page does not merge the two. On the trunk, D-021
  means a greenlit or backlog opus has `probationes: {}`, so the cell
  reads `0/5`. That is the truth, not a defect.

**A `done` opus does not appear.** The progress page is the history, and
this page is the future. Two pages that both list finished work is how the
handoff got into this state.

### Ordering: no rank key. This is the seam call.

Within each group, order by id **descending** (newest first) and nothing
else. The one exception is that halted rows follow the `backlog` rows. The
page does not rank.

The obvious alternative is a `rank:` integer in opus front matter. This
opus refuses it, for three reasons:

- **It is a second thing to maintain, and it rots silently and with
  authority.** Stale prose looks stale. `rank: 3` on an opus nobody has
  thought about since cascade 9 reads as a current judgment.
- **Front matter is written by the CLI, so a rank needs a writer.** That
  means a new `bisellium rank` verb, or a flag on `greenlight`. `greenlight`
  is the wrong command: ranking matters *before* greenlight, greenlight is
  the Patron's slate decision, and ranking is the magister's ordering
  within the slate (engineering lex §2).
- **A ranking is a dated judgment by a named sella, and the officina
  already has a shape for that: an acta entry.** Precondition 2 puts the
  current ranking there. An integer in a mutable field would be a worse
  version of it.

Instead, the page shows the inputs a ranking is made from: blockers, open
petitiones, gate counts and state. A reader ranks. The file does not
pretend to.

**Revisit trigger.** State this in the page's own footnote so the next
reader finds it:

> If a hand-written ordering of these items appears anywhere outside an
> acta twice more, `rank:` has earned its opus.

That opus would add an optional non-negative integer with one writer,
where absent means unranked, plus a rule that flags a `rank:` on a `done`
opus. Do not build it here.

### The single-source guard

The generator **exits non-zero, before writing anything**, if the handoff
(`--handoff`, default `docs/SESSION-HANDOFF.md`) matches either pattern
below. The error names each hit's line number.

1. **A slate heading.** A line matching
   `/^#+\s*(Backlog|New opera\b.*)\s*$/i`. Today this hits `### Backlog`
   and `### New opera opened, none started`.
2. **A hand-written ranking.** Three or more opus ids chained by `→` or
   `->`, matched over the whole file so that a chain wrapped across lines
   still counts: `/W-\d{3}\s*(?:→|->)\s*W-\d{3}\s*(?:→|->)\s*W-\d{3}/`.
   Today this hits three places: the "Resume order" paragraph, the
   "Resume point" list, and `### Backlog` item 1.

**Why the guard targets both patterns.** Pattern 1 on its own would pass
today's rot through untouched: two of the three stale rankings live under
non-slate headings. A two-id arrow (`W-033 → W-034`) is a dependency, not
a ranking, and stays legal. No other arrow chain in the handoff names opus
ids. The pipeline arrows ("`branch` → builder → commit") and the cost
arrows ("117k→92k→84k") do not match.

The guard is the whole point of this opus. The invariant "there is one
slate and it is generated" is enforced by the script that replaces the
prose, not by a sentence asking people to remember it. Behaviour 8 runs
the guard against the repo's real handoff, so an editor who adds a ranked
chain or a backlog heading back into the handoff breaks `npm test`.

**The handoff edit, in the same commit:**

- Delete `### Backlog` and `### New opera opened, none started` whole.
  Their unfiled items were handled under precondition 1.
- In "Resume order" and "Resume point", replace each chain with one link to
  the backlog page and one to the ranking acta. The non-slate sentences
  around them stay: mode, throttle and checkpoint notes.
- Add the page to the Artifacts list.

## Behaviours to test

Every behaviour builds its own fixture officina (and fixture handoff) under
`$TMPDIR`, except behaviour 8, which reads the real handoff. Neither
`studio/` nor `examples/sample-studio` is written.

1. **Grouping.** A fixture with one `backlog`, one `greenlit`, one
   `building`, one `halted` and one `done` opus renders:
   - `greenlit` and `building` under In flight;
   - `backlog` and then `halted` under Backlog;
   - no row at all for `done`.
2. **"Blocked on" for a non-halted opus.** `traditio.blocked_on` and an
   open petitio naming the opus (one with a quoted `opus:`, one bare) both
   appear. A `resolved` petitio does not appear. For a halted opus, the
   cell shows `halted_by` and `resume_when`, and not its stale
   `traditio.blocked_on`.
3. **Gates.** The cell counts `passed` gates against the length of
   `bisellium.yml`'s `probationes` list. A `waived` gate shows as
   `· N waived` and is not counted as passed.
4. **Ordering.** Within a group, ordering is id-descending, with halted
   rows after backlog rows. It is stable across two runs: identical input
   gives byte-identical output.
5. **Decisions.** Decisions render with `kill_when`. A decision missing
   `kill_when` still renders instead of throwing (`decision.kill` is
   `check`'s job, not this script's).
6. **Escaping.** Front-matter values are HTML-escaped. A title, `kill_when`
   or `resume_when` containing `<` or `&` cannot inject markup. The progress
   page's own rows are full of entities; this page is machine-fed and must
   not be the exception.
7. **The guard fires.** A fixture handoff with a `### Backlog` heading, and
   a separate fixture with a ranking chain wrapped across two lines, each
   make the generator exit non-zero. In both cases `--out` is not created
   or modified. These are two assertions, run as one behaviour.
8. **The real handoff passes the guard.** This behaviour is recorded red
   **before** the handoff edit, against today's heading and chains, and
   goes green in the same commit that deletes them.
9. **Write scope.** The generator writes nothing inside `--studio` and
   nothing outside `--out`.

Reds are recorded with `bisellium red W-041 --behaviour <n> --sella <id> --
node scripts/backlog-page.test.mjs <n>`, one per behaviour. They are
assertion-level, and no two share an output.

   `link.dead` for the handoff's new links.

## Out of scope

- **A `rank:` key or any ordering file.** The reasons are above, along
  with the revisit trigger.
- **Overlaying live opus branches onto In-flight state.** This is D-021's
  named future work and a UI call for the Patron. The page states its
  trunk view instead.
- **A check rule for page staleness.** The checkpoint already runs
  `build.sh`. A rule that turns the tree red because a generated artifact
  is older than its source would be the first time-based blocking rule in
  this codebase, which W-035 explicitly refused to introduce.
- **Rendering `done` opera.** That is the progress page.
- **Parsing brief prose, `reason` or `resume_when` for meaning.**
- **Touching `head.html`, `body.html` or the progress page's markup.**
- **Publishing the artifact.** That is a checkpoint action for the
  orchestrator, not a file this opus owns.
- **Migrating the handoff's non-slate sections.** Traps, environment facts
  and standing instructions are not slate state. They stay prose until
  something structured earns them.
