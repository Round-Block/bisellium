# W-041 — generated backlog page: the slate rendered from the officina, never from prose

## Intent

`docs/SESSION-HANDOFF.md` carries the backlog as a hand-numbered prose
list. It is the same rot class W-038 and W-039 were filed against, and it
is already demonstrably rotten: item 8 appears twice, item 8's second copy
contains a half-deleted sentence ("Old item, still open: … **fixed** in
W-026 … repo on `main` merges into main and reports master — same family as
reports `main`"), item 11 is a check rule that does not exist, and the
ranking produced by the architect on 2026-09-20 exists in no file at all.

Every fact the list states is already on disk in structured form: an opus's
`state`, its `traditio.blocked_on`, the petitiones that name it via `opus:`,
the decisions that constrain it. The list is a stale denormalisation of the
officina.

The dossier pipeline already solves this shape once —
`docs/design/dossier/build-arch.mjs` renders `docs/ARCHITECTURE.md` (itself
generated by `scripts/arch-graph.mjs`) into a page `build.sh` publishes.
This opus is that pattern applied to the slate.

## Files owned

- `scripts/backlog-page.mjs` — **new**, the generator
- `scripts/backlog-page.test.mjs` — **new**, behaviours (plain node, assert,
  `scripts/changelog.test.mjs` is the harness to copy)
- `docs/design/dossier/build.sh` — one line
- `docs/design/dossier/backlog-body.html` — **generated output, committed,
  never hand-edited**
- `docs/SESSION-HANDOFF.md` — the `### Backlog` section is deleted and
  replaced by a link, **in the same commit**
- `package.json` — one line wiring the test into `scripts.test`

`docs/design/dossier/head.html` is **not** owned: the page reuses the
existing styles verbatim, as the progress page does. If a style is missing,
say so in the review note rather than editing shared CSS.

## Interfaces

```
node scripts/backlog-page.mjs [--studio <dir>] [--out <path>]
```

Defaults `studio` and `docs/design/dossier/backlog-body.html`. Pure read of
the officina plus one write; it never shells out, never touches git, and
never writes inside `studio/`.

`build.sh` gains one line before the `cat`s, matching how `build-arch.mjs`
is invoked:

```sh
node ../../../scripts/backlog-page.mjs
sed 's|<title>Bisellium Dossier</title>|<title>Bisellium Backlog</title>|' head.html | cat - backlog-body.html > bisellium-backlog.html
```

### What it reads

- `studio/opera/*.md` front matter — `id`, `title`, `state`, `collegium`,
  `kind`, `spec`, `probationes`, `traditio.blocked_on`, `traditio.next`
- `studio/petitiones/*.md` — `id`, `state`, `opus`, `from`; an open petitio
  naming an opus is a blocker on that opus and a row of its own
- `studio/decisions/*.md` — `id`, `title`, `kill_when`; rendered as a short
  standing-constraints list, because two backlog items in this batch
  (W-040, D-016) are only legible next to the decision that shaped them

Front matter only. **Do not parse brief prose** — the dependency sentences
in `briefs/W-034.md` ("blocked on W-033") are real information and are
exactly the thing that must migrate into `blocked_on` rather than be
regex-mined out of English.

### What it emits

Three groups, in this order, each a table sharing the progress page's
existing `.table-scroll` / `<table>` markup:

1. **In flight** — `building`, `verifying`, `review`, `greenlit`, `halted`
2. **Backlog** — `backlog`
3. **Standing constraints** — decisions, `id` + `title` + `kill_when`

Columns for 1 and 2: id · title · collegium · state · blocked on · gates.
"Blocked on" is `traditio.blocked_on` joined with any open petitio naming
the opus (`P-009 (needs_you)`), or an em dash. "Gates" is the passed/total
count from `probationes`, not a ladder.

A `done` opus does not appear. The progress page is the history; this page
is the future. Two pages that both list finished work is how the handoff got
into this state.

### Ordering: no rank key. This is the seam call.

Within each group, order by id **descending** (newest first) and nothing
else. The page does not rank.

The obvious alternative — a `rank:` integer in opus front matter — is
refused for this opus:

- It is a second thing to maintain, and it rots **silently and with
  authority**. Stale prose is visibly stale; `rank: 3` on an opus nobody
  has thought about since cascade 9 reads as a current judgment.
- Front matter is CLI-written, so it needs a writer — a new `bisellium
  rank` verb, or a flag on `greenlight`, which is the wrong command
  (ranking matters *before* greenlight; greenlight is the Patron's slate
  decision, ranking is the magister's ordering within it, engineering lex
  §2).
- A ranking is a **dated judgment by a named sella**, which the officina
  already has a shape for. An integer in a mutable field is a worse
  version of an acta entry.

What the page shows instead are the inputs the ranking is made from —
blockers, open petitiones, gate counts, state. A reader ranks; the file
does not pretend to.

**Revisit trigger, to be stated in the page's own footnote so the next
reader finds it:** if a hand-written ordering of these items appears
anywhere outside an acta twice more, `rank:` has earned its opus — an
optional non-negative integer, one writer, absent meaning unranked, and a
rule that flags a `rank:` on a `done` opus. Do not build it here.

### The single-source guard

The generator **exits non-zero, before writing anything**, if
`docs/SESSION-HANDOFF.md` still contains a line matching `/^#+\s*Backlog\s*$/`.

Three lines, and it is the whole point of the opus: the invariant "there is
one backlog and it is generated" is enforced by the script that replaces
it, not by a sentence asking people to remember. A future editor who
re-adds the prose section breaks `npm test`.

## Behaviours to test

1. A fixture officina with one `backlog` and one `building` opus renders
   both, in the right groups, and omits a `done` one
2. `traditio.blocked_on` and an open petitio naming the opus both appear in
   the "blocked on" cell; a resolved petitio does not
3. The gates cell counts passed probationes against declared ones
4. Ordering within a group is id-descending and stable across two runs —
   byte-identical output for identical input
5. Decisions render with `kill_when`; a decision missing one still renders
   rather than throwing (`decision.kill` is `check`'s job, not this
   script's)
6. Front-matter values are HTML-escaped — a title containing `<` or `&`
   cannot inject markup (the progress page's own rows are full of entities;
   this one is machine-fed and must not be the exception)
7. The generator exits non-zero and writes nothing when the handoff still
   carries a `## Backlog` heading
8. It writes nothing inside `--studio` and never outside `--out`

Reds via `bisellium red W-041 --behaviour <n> --sella <id>`, one per
behaviour, assertion-level, no two sharing an output. Every behaviour
builds its own fixture officina under `$TMPDIR`; neither `studio/` nor
`examples/sample-studio` is written.

## Acceptance

1. `npm test` green with the 8 behaviours wired into `scripts.test`;
   `typecheck`, `lint`, `format:check` clean.
2. `bash docs/design/dossier/build.sh` regenerates all pages and produces
   `bisellium-backlog.html`; running it twice leaves the tree clean.
3. The generated page, read against `bisellium check studio --repo .`,
   names the same in-flight opera and the same open petitiones. Any
   disagreement is a defect in this script, not in `check`.
4. `docs/SESSION-HANDOFF.md`'s `### Backlog` section is **gone**, replaced
   by a one-line link, and the generator's own guard now fails if it comes
   back. Demonstrate the guard firing.
5. The page is published as its own artifact and linked from the handoff's
   Artifacts list and the dossier masthead, alongside the progress page.

## Out of scope

- **A `rank:` key or any ordering file.** Reasoned above, with its trigger.
- **A check rule for page staleness.** The checkpoint instruction already
  runs `build.sh`; a rule that turns the tree red because a generated
  artifact is older than its source would be the first time-based blocking
  rule in this codebase, which W-035 explicitly refused to introduce.
- **Rendering `done` opera.** That is the progress page.
- **Parsing brief prose for dependencies.** Those move into `blocked_on`,
  by their owning opus, when it is next touched.
- **Touching `head.html` or the progress page's markup.**
- **Migrating the handoff's non-backlog sections.** Traps, environment
  facts and standing instructions are not slate state; they stay prose
  until something structured earns them.
