## Intent

W-423 added the rule its class lacked, as row `W-423-b5` of the census in `packages/cli/src/containment.test.ts`: every direct `node:fs` or `node:fs/promises` call in `packages/cli/src` and `packages/commands/src` is classified, read-only (`W423_READ_ONLY`) or write-capable (`W423_WRITES`), and every write-capable one sits in a function that calls a containment helper, in an approved helper's own body, or in the reviewed list `WRITE_LIMITS`. Its spec review of round 4 (`studio/ci/W-423-spec-4.log`, finding 1, S1) found two write paths the rule does not see, and W-423's round 5 cut them out as a stated limit naming this opus:

- **A stream class constructed on a path.** `scanCD` follows a direct call only, and `W423_FS_VALUES` exempts `ReadStream` and `WriteStream` as values, so `new WriteStream(p)` is neither an `fs` site nor an `fsUses` finding. A `WriteStream` truncates its path when it opens, constructed or called (`streams.out`).
- **A read-only name given a write flag.** `readFileSync`, `readFile`, `createReadStream` (and `ReadStream`) take a `flag` or `flags` option; the rule judges each by its name, but `readFileSync(p, { flag: "w+" })` truncates its path, and so does a numeric `O_RDWR | O_TRUNC` (`streams.out`).

`createWriteStream` is already in `W423_WRITES` (and in W-163's `RAW_FS`), so it is judged today and is not in scope. No governed source uses a stream class, `createReadStream`, `createWriteStream` or a flagged read (`streams.out`), and every governed call of the four flag-taking names today is a `readFileSync` with no options or an encoding string (`enumerate-reads.out`, tests included: 737 calls, 51 with no options, 685 `"utf8"`, 1 `"base64"`). So this is a change of the census rule, not a site migration: no source file outside the test changes.

This opus does three things, in the census's own scan and rule (D-042: no new mechanism), each a behaviour:

1. A construction of an fs class is a direct site, as a call is, and the stream classes are classified: `WriteStream` a write, `ReadStream` a read. They leave `W423_FS_VALUES`, so any other use of one (stored, passed, exported, `instanceof`) is an `fsUses` finding and fails the row.
2. A read whose options name a literal write flag is judged a write: `w423Unrouted` refuses it outside a helper caller, as any write.
3. A read whose options the rule cannot read (a variable, a call, a spread, a shorthand or computed key, a numeric or non-literal flag) is judged a write too: the rule fails closed (D-085 D).

Threat model: mistakes, not adversaries (D-045). The rule is W-423's: lexical, function-level, the two governed packages.

  - for an object literal, true when a property is a spread or has a computed key, or when a property named `flag` or `flags` is anything but a property assignment of a string literal in `W425_READ_FLAGS` (`r`, `rs`, `sr`: `O_RDONLY`, with or without `O_SYNC`); false otherwise.
  Behaviour 2's form is the literal half only: true when an object literal's `flag` or `flags` is a string literal outside `W425_READ_FLAGS`.

**The rule** (W-423-b5's functions). `W423_READ_ONLY` gains `ReadStream` and `W423_WRITES` gains `WriteStream` (behaviour 1). `w423Unrouted` judges a governed site a write when its name is in `W423_WRITES` or it carries `writeFlag` (behaviour 2), and lists it when its function is neither a helper caller nor an approved helper and its key is not in `WRITE_LIMITS`, as before. `w423Unclassified` and `w423Stale` are unchanged; `w423Stale` reads `w423Unrouted`, so a listed limit that is a flagged read stays a live limit.

Promise streams: a governed `WriteStream` constructed on a path (`new WriteStream(p)`, by name or as a member of an fs namespace) is a write-capable direct site that must sit in a helper caller, an approved helper or `WRITE_LIMITS`; a governed `ReadStream` constructed on a path is a read-only direct site; any other use of either class outside a type position fails the row. Pinned by `W-425-b1` "a stream class constructed on a path is a direct fs site, and any other use of one fails", pinned by `W-425-b1` "both stream classes are classified", pinned by `W-425-b1` "a governed WriteStream outside the helper fails; a ReadStream with no flags and one in a helper caller do not" and pinned by `W-423-b5` "every governed direct write calls the shared containment helper or is a stated limit" (a governed source constructing one fails the real-tree row) — limit: the scan's binding analysis, `CONTAINMENT_HELPERS`' matching, `APPROVED_HELPERS` and `WRITE_LIMITS` are W-423's, reused unchanged; a use of either class as a value is refused even where it opens nothing (`x instanceof ReadStream`), and `FileReadStream`, `FileWriteStream` and `Utf8Stream` stay unclassified, so each fails the row as an unclassified site or an `fsUses` finding, unpinned here; a `WriteStream` called without construction was already a direct call site (W-423) and is now classified a write, unpinned here.

Promise flags: a governed `readFileSync`, `readFile`, `createReadStream` or `ReadStream` whose options name a literal `flag` or `flags` other than `r`, `rs` or `sr` is a write, refused outside a helper caller, an approved helper or `WRITE_LIMITS`; one with no options, an encoding string, a callback, or a literal read flag stays a read. Promise closed: a governed read of those four names whose options the rule cannot read (a variable, a call, a conditional, a spread argument or property, a shorthand, a computed key, a numeric or non-literal flag) is judged a write and refused outside the helper, so an unproven flag fails closed. Pinned by `W-425-b3` "a variable, shorthand, non-literal, spread, computed or numeric flag outside the helper fails; a callback or an encoding does not" pinned by `W-425-b3` "every read is classified" and pinned by `W-423-b5` "every governed direct write calls the shared containment helper or is a stated limit" (a governed source reading with a spread fails the real-tree row) — limit: a read flag the rule cannot prove is refused even when it is a read (`{ flag: 0 }`, `constants.O_RDONLY`, `null` or `undefined` options, a callback passed by name), an over-refusal by design, unpinned beyond the numeric case; the governed tree today passes no such form (`enumerate-reads.out`), so `W-423-b5`'s real-tree assertions stay green at every stage (`census-stage<k>.out`).

Limits, stated:

- Unchanged code the promises lean on is a stated limit, not a guarantee (D-076 E). - W-423's limits stand: the rule is lexical and function-level (a helper call anywhere in the function counts, not that the written path is the helper's result), and governs `packages/cli/src` and `packages/commands/src` only; writes by a child process are not judged.
- A use of `ReadStream` or `WriteStream` as a value fails closed, also where it opens nothing (`instanceof`). `FileReadStream`, `FileWriteStream` (node's aliases of the two) and `Utf8Stream` (which opens its `dest`) are not classified: a construction is an unclassified site and any other use an `fsUses` finding, each failing the row. A read flag it cannot prove, numeric included, is judged a write; the `fd` and `fs` options are not judged; a `FileHandle`'s methods (`handle.createWriteStream()`, `handle.writeFile`) are not fs-module calls, and the handle's own `open` is the classified write.
- Node's string flags outside `r`, `rs` and `sr` are each a write or an error (`ERR_INVALID_ARG_VALUE` for an unknown string, `streams.out`); this opus judges every one a write without listing them.
