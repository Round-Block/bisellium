## Intent

The shipped Board drawer's Evidence section currently presents each evidence path as a gate-named link, without saying which source revision was reviewed or making the recorded gate result explicit. A linked Inbox decision can then be answered after its Board evidence changes, with no warning that the Patron is deciding a different record from the one shown. Current source evidence is `/home/edckt/agents/bisellium/.worktrees/W-412-spec/apps/web/src/screens/BoardDrawer.tsx`, `/home/edckt/agents/bisellium/.worktrees/W-412-spec/apps/web/src/screens/Inbox.tsx` and `/home/edckt/agents/bisellium/.worktrees/W-412-spec/apps/web/src/lib/board.ts`.

Bind every recorded gate-evidence entry into one display record with three explicit facts: `Reviewed revision` from `evidence.certifies`, `Gate result` from the gate id and current status, and `Decision record` from `evidence.href`. Show the same binding on a linked Inbox decision. Pin the snapshot per petition when the decision is first shown. A refresh never overwrites it but marks the decision stale. Refuse if the row loses `boardEntry`. Immediately before submitting, fetch current opera and compare the full normalized gate snapshot—gate id, status, reviewed revision and decision-record path—with that pinned snapshot. If available Board evidence changed, refuse locally and instruct the Patron to review current Board evidence. If the linked Board item disappeared, retain the original binding, mark it stale and say: `The linked Board item is no longer available for this decision. Verdict not submitted. Your draft is kept.` Both refusals preserve the reason draft, name the cause and issue no answer POST. An unchanged linked question and a standalone question retain the existing answer path.

W-493's merged record-description-first move is part of the base: the whole record block remains directly below the header, then waiting facts, reasons, this bound Evidence section, named gates and events. W-412 builds on that order and does not alter W-493's card gate-progress text.

This is display and pre-submit concurrency protection. It changes no gate result, record, lifecycle state or answer vocabulary. A mutation after the final opera response but before the answer request is outside this browser-only preflight and remains a limit; an atomic server compare would be a separate interface change.

## Defaults for the Patron

The Patron agreed to Defaults 1 to 4 on 2026-11-02.

1. Use the plainest layout: one unboxed definition-list block per recorded gate inside the existing Evidence section, with quiet labels and the record path as the only link. W-493's record description stays first. A bordered or compact-table treatment would be a small CSS/rendering change.
2. Repeat that same binding inline on a linked Inbox decision, above the reason and verdict controls, so the Patron can see what the verdict binds without returning to the Board. Moving it below the controls would be a small layout change.
3. Pin each petition's evidence when its decision is first displayed. A 30 s or focus refresh keeps that binding visible, marks it stale if the Board changed, and the submit preflight compares against the pinned snapshot. For changed evidence on an available Board item, preserve the draft, refuse locally and tell the Patron to review current Board evidence. Replacing the binding on refresh would be a small state-policy change.
4. Leave standalone questions unbound. Treat a formerly linked opus that disappears or a refreshed row that loses `boardEntry` as stale, retain the original binding and say: `The linked Board item is no longer available for this decision. Verdict not submitted. Your draft is kept.` Keep the browser-only race after the final preflight response as an explicit limit rather than adding a server/API contract in this UI opus.
