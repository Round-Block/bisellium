## Intent

The record names three gaps; W-340 (merged 2026-10-22, #668) closed two of them. `next --perform --expect review` performs a `kind: ui` opus's round: `buildPacket` attaches the eight served shots from the opus worktree's `studio/ci/shots/<id>/` in the fixed desktop-then-phone order (Inbox, Board, Seats, Officina at 1280, then at 390: the order of `W-366-review/r1/prompt.md`, which is the packet's own `ui.txt`), the round passes `--ui-input` to verdict, and `studio/prompts/build-review.md` and the later-round prompt ask for `## UI input disposition` (W-340-b2, and W-274-b1's flipped UI case). W-366 went by hand on D-106 A's stopgap, not on a refusal. Three gaps remain, and D-106 names two of them.

**A stray gate log does not hold the review (D-106 A, widened).** W-360's round 1 was reviewed on a worktree still holding a failed run's gate logs: `dirtyHold` (`integrate.ts`) reads tracked changes only (`--untracked-files=no`), so an untracked `studio/ci/<id>-<gate>-<hex>.log` passes both the review perform and the fix-check perform. After this opus, a file under the worktree's `<studio>/ci/` that git neither tracks nor ignores holds both performs before any Codex call, naming up to five such paths: "refusing: <paths> untracked under <studio>/ci; commit or remove it first" ("them" for more than one). The one exception is an interrupted round's own verdict log, `ci/<id>-review-<n>.log` for the round its ticket names, which the review perform exists to finish (W-274). A listing git cannot give holds too.

**The packet's next fact is computed in the wrong checkout (D-106 A, where the packet is built).** D-106 A says a review packet is built from the main checkout until W-353 lands, because W-360's hand packet built with the worktree as `--repo` carried no source diff. The perform already builds its packet from the opus worktree (its record, brief, reds and shots live there; the main checkout has no shots) and adds the diff itself (`git diff master...HEAD`). That stays: the packet is built from the worktree. But its first fact runs `next <id> --studio <worktree>/studio --repo <worktree>`, and next refuses a linked worktree, so every performed round's `facts.txt` today records "is a linked worktree; run next from the repository's main checkout" and exit 2 (`W-366-review/packets/r1/facts.txt`). After this opus `nextFact` runs next on the main work tree (the first entry `git worktree list` gives) and its studio, the one place next runs, whichever checkout the packet reads. With both fixes the perform's packet is the one a review needs, and D-106 A's stopgap ends for the perform.

**A hand-recorded UI round cannot be recorded by `scripts/record-review.sh`.** verdict refuses a UI build verdict without `--ui-input` (`verdict.ts`, unchanged), and the script passes none, so W-366's round 1 was recorded by the Patron by hand. After this opus a fifth argument is passed to verdict as `--ui-input`, verbatim; next's review order already prints the exact `--ui-input <path>` for a UI opus. An empty fourth argument still means no session id.

Promise stray-holds: when the opus worktree holds a file under `<studio>/ci/` that git neither tracks nor ignores, the review perform (a new round, or an interrupted round beside any other such file) and the fix-check perform hold with the "untracked under <studio>/ci" why naming it, before any packet, Codex call, verdict, check or commit — limit: an ignored file and an untracked file outside `<studio>/ci/` are not read; a tracked change is `dirtyHold`'s (unchanged); the named review order a hand dispatcher follows is not held, only the performs.

Promise own-log: an interrupted round whose ticket names round n finishes beside its own untracked `ci/<id>-review-<n>.log` and nothing else — limit: the header checks, review and the commit are W-274's, reused unchanged.

Promise list-holds: when git cannot list the untracked files under `<studio>/ci/` (a non-zero exit or a spawn error), both performs hold with "refusing: git cannot list the untracked files under <studio>/ci (<reason>)" — limit: a studio at the repository root gives the pathspec `/ci/`, which git refuses, so it holds the same way (outside the stated domain, unpinned).

Promise next-fact: the review packet's `next` fact runs `next <id> --budget 400000` with `--studio` the main work tree's studio and `--repo` the main work tree, for a packet built from the opus worktree (the perform's) and from the main checkout (a hand packet) alike — limit: the fact is `next`'s output at that moment, taken while the perform holds its own step marker, so it may report the rung as running; the rest of the packet (`ui.txt`, the delta, the pin fact, the admission fact) still reads the checkout it is given.

Promise ui-input: `scripts/record-review.sh <ID> <round> <outcome> [<session>] [<ui-input>]` passes a non-empty fifth argument to verdict alone, as `--ui-input <it>`, after any `--session`; with no fifth argument, or an empty one, it passes none — limit: whether the path is the current authoritative ui-lead round is verdict's check (unchanged); the script does not read the record's kind.

Threat model: mistakes, not adversaries (D-045).
