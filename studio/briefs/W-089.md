# W-089 — seats become templates: the builder letter dies

Spec of record, **Revision 2**, 2026-09-25. Drafted by the Codex
spec-drafting lane under D-027, amended and signed by the architect the same
day. Authority: Patron decree, 2026-09-25 (recorded in the opus title), plus
the revision-1 red-team disposition recorded below.

This opus changes **the manifest shape, the sella-resolution path, and the
ADOPTION vocabulary**. It does not rebuild the Seats UI and does not touch
codex-trial mechanics (D-025 stands).

## Intent

`studio/bisellium.yml` declares five builder seats:

```
- { id: builder-a, collegium: engineering, kind: agent, model: claude-sonnet-5 }
- { id: builder-b, collegium: engineering, kind: agent, model: claude-sonnet-5 }
- { id: builder-c, collegium: engineering, kind: agent, model: claude-sonnet-5 }
- { id: builder-d, collegium: engineering, kind: agent, model: claude-sonnet-5 }
- { id: builder-sol, collegium: engineering, kind: agent, model: gpt-5.6-sol, harness: codex }
```

Four of those rows are **byte-identical apart from the letter**. The letter
encodes nothing: not a model, not a harness, not a collegium, not a
specialism, not an owner. It is a concurrency handle that the orchestrator
picks arbitrarily at dispatch and that nobody reads afterwards. Measured:
there is **no code path anywhere in the repo** that branches on which letter
a builder carries. The only builder-shaped dispatch in source is a string
prefix test (`packages/cli/src/hooks.ts:378`, `!sella.startsWith("builder")`)
which is deliberately letter-blind.

Meanwhile the thing that *is* durable — which opus the work belongs to — is
already the load-bearing identity everywhere else. D-021's one-writer
discipline proves it: `recordOwnerRefusal`
(`packages/commands/src/writes.ts:256`) refuses a write to `opera/<id>.md`
unless HEAD is on `opus/<id>`. Read the whole function — **the sella is not an
input**. Ownership is keyed on the opus branch and only on the opus branch.

So the letter is redundant with nothing and the opus id is redundant with
everything. The decree: **one builder seat per tier**, with instance identity
minted at dispatch from the seat plus the opus.

The Patron's stated scenario is 100 concurrent builders. Under today's shape
that is 100 hand-written manifest rows, and worse: the worktree slot
allocator (`packages/shim/src/worktree.ts:50`) hands out `<sella>-<n>` by
scanning for the first free `n`, so 100 builders sharing four letters
contend on a counter and produce branches like `bisellium/builder-a/37`
whose name says nothing about the work. Under seat templates the manifest
gains zero rows and each instance gets `bisellium/builder.W-137/1` — a
branch name that reads as what it is.

to do to each.

### A. Live-target membership tests — resolve, then refuse unknown or retired (3 sites)

| site | verb |
|---|---|
| `packages/commands/src/run.ts:160` | `bisellium run --sella` |
| `packages/commands/src/writes.ts:362` | `bisellium handoff --sella` |
| `packages/commands/src/writes.ts:505` | `bisellium emit --usage --sella` |

All three are the same expression, `!(manifest.sellae ?? []).some(s => s.id === sella)`,

### F. Not source: the boot line

`check` on the officina as it stands, versus the same officina with
`builder-a/b/c/d` deleted and `builder-sol` renamed. Both runs are
`npm run -s check -- <copy> --repo . --json`, on a copy so nothing real
moved:

| | findings | blocking |
|---|---|---|
| baseline (`studio/` unmodified) | 141 | **0** |
| `builder-*` rows deleted | 191 | **50** |

The 50 break down as 34 × `traditio.sella`, 15 × `opus.sella`, and one
`link.dead` that is an artifact of copying `studio/` away from its sibling
`README.md` — discount it. So the real cost is **49 blocking findings across
34 opus records**, every one of them a *true statement about the past*:

```
studio/opera/W-006.md:6:  sella: builder-c
studio/opera/W-006.md:22: traditio: { sella: builder-c, stage: done, ... }
studio/opera/W-064.md:7:  probationes: { spec: { sella: builder-a, ... } }
```

Counted across the whole officina: 296 `builder-a`, 145 `builder-b`, 46
`builder-c`, 27 `builder-d`, 71 `builder-sol`, over 359 files — most of them
in `ci/*.log`, which is evidence and is never touched.

**Records are append-only facts about the past. History does not move.** The
manifest is a statement about the present. The two blocking rules above
conflate them, and that conflation is the actual defect this opus has to
resolve.

The resolution, measured: keep the retired ids **declared**, with a
`retired: true` flag on the existing row. Same run again:

| | findings | blocking |
|---|---|---|
| templates + `retired: true` on the five old rows | 142 | **0** (the `../README.md` copy artifact only) |

Zero. `check` already tolerates an undeclared key on a sella row, so the read
rules in group E need **no change at all** for the historical ids — they stay
in `sellaIds`, they stay legal forever, and the typo-catching block they
provide stays blocking. The only new enforcement is a refusal on the
*dispatch* side.

That is also why `retired: true` on the row beats the alternatives. A
separate top-level `retired_sellae:` list would need `uniq()` run over it for
id format and uniqueness, a sibling field in
`packages/schema/src/index.ts:278`, and the union taken at six read sites. A
flag on the row is one key and six read sites unchanged. The precedent
already exists in this manifest: `probationes[].since` is the same move — a
grandfathering marker that keeps history legal.

## Measurement: the separator

The decree asks for `builder@<opus-id>`. Measured against the real rules.

`ID_RE` is `/^[A-Za-z0-9][A-Za-z0-9._-]*$/` (`packages/cli/src/check.ts:37`).
It admits `.`, `_`, `-` and rejects `@`. Four probe opera were written into a
copy of the officina, one per candidate separator, each carrying the
candidate in `sella:`, `traditio.sella` and `probationes.spec.sella`, and
`check` was run over them:

| candidate | `path.id.unvalidated` | git refname `bisellium/<id>/1` | `safeItemPath` | YAML round-trip | `receipts/<id>/` |
|---|---|---|---|---|---|
| `builder@W-089` | **3 × block** | legal | ok | ok | **block** |
| `builder.W-089` | clean | legal | ok | ok | clean |
| `builder_W-089` | clean | legal | ok | ok | clean |
| `builder-W-089` | clean | legal | ok | ok | clean |

`@` is the one candidate that fails. The table probe put the candidate in
three front-matter sella keys: top-level `sella`, `traditio.sella`, and
`probationes.spec.sella`. Only the first two have roster-membership rules,
but `path.id.unvalidated` independently walks **all** `sella` keys and
format-checks all three, so the table's `3 × block` is three format findings,
not two membership findings. The separate receipt-directory probe adds its
own `path.id.unvalidated` finding because the directory component is also an
id. The representative output below is abbreviated and does not enumerate
all three front-matter occurrences:

```
block path.id.unvalidated opera/W-901.md | front matter.sella "builder@W-089" is not a valid id
block path.id.unvalidated receipts/       | receipts directory name "builder@W-089" is not a valid id
```

Note that `@` passes `safeItemPath` and YAML and `git check-ref-format`. The
single authority that rejects it is ID_RE.

**Decision: the separator is `.`, and ID_RE is not widened.**

Why not widen ID_RE. It is the one containment invariant shared by every id
in the system — opus ids, petitio ids, decision ids, receipt directory names,
every `safeItemPath` operand, every acta filename component. ADOPTION:233
publishes it as a contract: *"each id must be alphanumeric (`.`, `_`, `-`
allowed) with no path separator or `..` segment — every id can end up as a
filename component"*. Trading that invariant for one cosmetic character is
the wrong side of the deal, and the lex is explicit that any id reaching a
filesystem write goes through the containment discipline.

Why `.` over `_` and `-`:

- `-` is the character the letters used, so `builder-W-089` reads as another
  enumerated seat, and `builder-codex.W-100` under a `-` separator would need
  longest-declared-prefix parsing to disambiguate a tier name from an
  instance. Ambiguous by construction.
- `_` is unambiguous but visually mushy against `W-089`, and appears nowhere
  else in this officina's vocabulary.
- `.` already reads as a namespace separator, no declared sella contains one,
  so "everything before the first `.`" is an unambiguous seat name even when
  the seat is itself hyphenated (`builder-codex.W-100` → `builder-codex`).
  It also keeps `run.ts:199`'s derived address valid:
  `builder.W-089@studio.bisellium` is one `@` and a real email, where
  `builder@W-089@studio.bisellium` is two.

One caution the builder must respect: `badId` (`paths.ts:44`) rejects `..`.
The minter must never produce a doubled dot, which it cannot as long as
neither operand starts or ends with one.

## Behaviours to test

Each numbered behaviour gets its own recorded red. Behaviour 1 is a manifest
edit with a check assertion, not source, and its red is the check run that
fails before the edit. There are **10 top-level behaviours and exactly 10
recorded reds**; a table-driven matrix inside one behaviour is one red, not a
reason to renumber later behaviours.

1. **The manifest declares seat templates, not enumerated seats.**
`studio/bisellium.yml`'s `sellae` gains `builder` (collegium engineering,
kind agent, model `claude-sonnet-5`) and `builder-codex` (collegium
engineering, kind agent, model `gpt-5.6-sol`, harness `codex`) — one per
D-020/D-023 build tier. `builder-a`, `builder-b`, `builder-c`, `builder-d`
and `builder-sol` keep their rows unchanged except for an added
`retired: true`, and are the only rows carrying it. `bisellium check studio
--repo .` reports zero blocking findings after the edit. `examples/sample-studio`
makes the same move: `builder-1`/`builder-2` become a single `builder` seat.

2. **`retired` is a declared, typed sella key.** `check` accepts a boolean
`retired` on a sella row. A non-boolean value is a blocking `manifest.shape`
finding at `bisellium.yml#sellae[<i>].retired`, following the
`integration.push` precedent at `check.ts:289`. `packages/schema/src/index.ts`
and `adapters/native/src/index.ts`'s `Sella` mapping carry the flag through
so a consumer can read it without re-parsing YAML.

3. **One resolver owns every class-B lookup.** A single exported helper
resolves a sella id against the manifest and is the only place the grammar
lives. Suggested shape — the builder may adjust the return type, not the
semantics:

```
resolveSeat(manifest, id): { seat: Sella; instance?: string } | undefined
```

An exact declared id resolves its row with no `instance`; exact match is
checked first. Otherwise the helper takes the substring before the **first**
`.` as the template id and the non-empty remainder as `instance`, and resolves
only when that prefix exactly names a declared row. `ghost`, `ghost.W-089`,
`builder.`, and every other unknown or empty-instance spelling return
`undefined`. A retired row resolves — reads must work forever — and the
caller sees `retired: true` and chooses the live or historical policy.
Resolution is not permission to dispatch.

Every class-B consumer named in the census calls this helper; none retains a
private `.find`, prefix test, or split:

- `context`: template and instance ids inject the same row's collegium; an
  unknown keeps the existing empty `unknown sella` bundle and CLI exit 1.
- `talk`: template and instance ids select the same harness/model; an unknown
  exits 2 before a harness starts.
- `tick`: every due-item sella resolves before `harnessForSella`; an unknown
  item is refused with the existing per-item error posture and no daily or
  probe turn is launched for it.
- `delegate`: either spelling targets the resolved template row; an unknown
  exits 2 and the manifest and timeline remain byte-identical.
- `probe`: `seatedCandidatesFor` resolves each seat id before reading model
  or harness, skips retired rows, and refuses an unresolved candidate rather
  than probing it with a default profile. Its list operation normally feeds
  exact template ids, but its test injects an instance and an unknown so the
  consumer contract cannot silently regress.
- `hooks`: receipt/status ids resolve before the row's harness is read; a
  template and any of its instance receipt directories use that row's
  harness, while an unknown directory/id is reported as unknown and is not
  given a fabricated liveness status.
- `store`: `knownParty`/`sellaExists` accept a template or its instance via
  the resolved row, preserve the patron special case, and return false so the
  HTTP route answers 404 for an unknown.

Behaviour 3's red is one table that exercises template, instance, and unknown
at all seven consumers, including the list-specific refusal postures above.

4. **Instance ids are minted here, never hand-written.** This opus implements
and exports a single minter — `seatInstance(seatId, opusId)` — as the only
producer of an instance id:
`seatInstance("builder", "W-089") === "builder.W-089"`. It refuses (returns
`undefined`, or throws — the builder's call, but it must not return a bad id)
when either operand is empty or would produce a string failing `ID_RE` or
containing `..`. `resolveSeat(manifest, seatInstance(seat, opus))` round-trips
to the seat for every declared seat and every opus id on disk. No caller may
spell `` `${seat}.${opus}` `` itself. A **builder-class seat** means exactly
either live template introduced by behaviour 1, `builder` or
`builder-codex`, after `resolveSeat`; retired lettered tombstones are not live
builder-class targets.

5. **Every builder dispatch path calls the minter and carries the instance.**
There is no orchestrator deferral in revision 2. At any boundary that launches
a process/model or records the actor for an opus, code first resolves the
seat, then calls `seatInstance(resolved.seat.id, opusId)`, and passes/writes
that canonical result. Specifically:

- `run --sella builder --opus W-089` mints `builder.W-089` before worktree
  acquisition and uses it for the worktree/branch, child
  `BISELLIUM_SELLA`, receipt, and git author. A supplied instance is
  re-minted from its prefix and suffix; if `--opus` is also supplied and
  disagrees with the suffix, the command exits 2 before dispatch. A bare
  builder template without an opus cannot be minted and is refused.
- `handoff`, `emit --usage`, and all seven lifecycle verbs already have an
  opus argument. When given a live bare builder template they call the
  helper and record its instance; when given an instance they re-mint and
  require it to match the command's opus before writing.
- `talk` and any builder-class launch reached by `tick` must already carry an
  opus-bearing instance, re-mint it through the helper, and refuse a bare
  builder template or a mismatch before starting a harness. Non-builder
  scheduled seats keep their template identities.
- `hook-event` has no opus argument, so a builder-class hook must receive the
  instance through `BISELLIUM_SELLA`; it re-mints from the suffix and refuses
  a bare builder template before a receipt or timeline write. `context` is a
  read, and `delegate` edits a template, so those two may accept the bare
  template without claiming to dispatch it.

The red spies on every downstream worktree, harness, event, receipt, and
front-matter boundary in this matrix and fails if any builder-class dispatch
passes or writes bare `builder`/`builder-codex`. It also pins that each path
called the shared helper rather than doing inline concatenation. Concretely,
the instance forms below succeed:

- `bisellium context --sella builder.W-089 studio` prints the engineering
  lex and index, byte-identical to `--sella builder`, while reporting the
  instance id.
- `bisellium run --sella builder.W-089 --opus W-089 --studio studio -- <cmd>`
  acquires a worktree and writes a receipt under the instance.
- `bisellium handoff --opus W-089 --sella builder.W-089 --next …` writes the
  instance in the handoff.
- `bisellium emit --usage 1000 --opus W-089 --sella builder.W-089 --model
  claude-sonnet-5` records usage for the instance.
- `bisellium talk --sella builder.W-089 --studio studio …` resolves the
  template's harness and model.
- `bisellium delegate --sella builder.W-089 --model X` targets the template
  row, subject to behaviour 6's retired refusal.

6. **Live dispatch rejects tombstones; lifecycle attribution rejects unknowns.**
This red is a no-write matrix over the two policies, which must not be
collapsed into “`resolveSeat` returned a row.”

At the three group-A membership sites — `run.ts:160`,
`writes.ts:362` (`handoff`), and `writes.ts:505` (`emit --usage`) — an exact
retired name such as `builder-a` and an instance such as
`builder-a.W-200` both exit 2 with:

```
sella "builder-a" is retired — dispatch "builder" instead
```

`run` acquires no worktree, spawns no child, and writes no receipt; `handoff`
does not alter front matter or the timeline; `emit --usage` appends no event.
`context`, `talk`, and `delegate` also refuse a retired live target (using
their existing exit 1/2 posture), `probe` skips it, and its model is never
re-decreed. Historical readers, hook receipt status, and check rules may still
resolve the tombstone. The letter dies at dispatch and lives in history.

Separately, `resolveSella` (`lifecycle.ts:43`) and `namedSella`
(`lifecycle.ts:57`) become roster-aware and are the gates for all their
callers: `ready`, `done`, `review`, `halt`, `waive`, `red`, and `amend`.
After the existing flag/env/default selection, they use `resolveSeat` against
the opened manifest. An unresolved id exits 2, writes/spawns nothing, and
prints exactly:

```
<verb>: unknown sella "<id>" — not declared in bisellium.yml
```

`namedSella` keeps W-039's distinct no-name refusal before this membership
check. `guest`, a live template, and a valid instance resolve. A retired id
also passes this *attribution* membership check because its tombstone row is
the grandfathering record; that does not make it dispatchable at any live
gate above. The red covers all five `resolveSella` verbs and both
`namedSella` verbs, flag and environment sources, unknown exit 2/no-write,
and a tombstoned historical id.

7. **`traditio.sella` and `opus.sella` accept an instance id whose seat is
declared.** Both rules route their membership test through `resolveSeat` and
therefore accept `builder.W-089`. They keep blocking an id that resolves to
nothing: `bulider.W-089` (misspelled seat), `ghost.W-089` (no such seat),
`builder.` (empty instance), and a bare unknown id such as `builder-e`. The
34 historical `traditio.sella: builder-*` records and 15 `sella: builder-*`
records stay clean via their declared retired rows, with no edit to any
record. `check studio --repo .` stays at zero blocking findings throughout.

8. **The `process.cascade` hook warning stops guessing from a prefix.**
`packages/cli/src/hooks.ts:378`'s `!sella.startsWith("builder")` becomes a
`resolveSeat` lookup. The warning is suppressed only when the resolved row is
one of the two exact live builder-class templates defined in behaviour 4,
and emitted for retired, unknown, or non-builder seats. `builder.W-089` and
`builder-codex.W-100` write source silently; `builderish`, other unresolved
`builder`-prefixed strings, retired `builder-a`, and `eng-lead` all warn.

9. **An instance id survives the filesystem and git surfaces.** With
`builder.W-089` as the sella: `receipts/builder.W-089/<session>.json` is
written and `check` reports no `path.id.unvalidated` for the directory name;
the worktree branch `bisellium/builder.W-089/1` passes
`git check-ref-format`; `GIT_AUTHOR_EMAIL` is
`builder.W-089@<slug>.bisellium` — exactly one `@`. A test pins all three,
including a negative case proving an id containing `..` never reaches a join.

10. **ADOPTION records the vocabulary, and the boot line uses the live sella.**
`docs/ADOPTION.md`'s `sellae` example block documents `retired`, and a short
"Seats and instances" passage states the contract: a **seat** is a template,
one per tier, declared in `sellae`; an **instance** is `<seat>.<opus-id>`,
minted at dispatch, carrying no state of its own; **the opus id is the
identity**, and D-021's one-writer discipline is already keyed on the opus
branch, so the instance name and ownership rule agree by construction; a
**retired** seat stays declared so records naming it remain readable forever
and is refused as a live dispatch target. `GLOSSARY.md` gains the two terms.
`.claude/agents/builder.md:14` becomes exactly
`run: bisellium context studio` — no `--sella` at all, the same shape
`.claude/settings.json`'s hook commands use, so `main.ts:188`'s
`--sella ?? $BISELLIUM_SELLA ?? "guest"` chain supplies the dispatched
instance and no literal or shell expansion can strand a booting builder with
an empty bundle (census F). A doc test pins that the line names no `--sella`,

## Seams

Two new seams and one changed one. All three are contracts.

**S1 (new) — `resolveSeat`.** The single authority on what a sella id means.
Every membership test and row lookup goes through it; no caller re-implements
`id.split(".")` or `sellae.find`. It lives in the lowest package that all
seven class-B consumers and the checker can import without a cycle. If a
lower-level shim cannot import that package, its caller passes the already
resolved result; the grammar is never copied into the shim.

**S2 (new) — `seatInstance`.** The single authority that joins a resolved
live builder template to an opus id. Every builder dispatch boundary invokes
it, including the branch that receives an already-instanced id; callers
compare the result rather than trusting or reassembling input. The helper
owns `ID_RE`/`..` validation and the tests own the no-bare-builder invariant.

**S3 (changed) — the manifest's `sellae` roster.** It no longer means
"everyone who may be dispatched". It means "every seat template, plus every
seat that ever existed". Membership is the read/historical contract;
`retired: false` (absent) is the live-dispatch contract. Any future reader of
`sellae` must explicitly choose which policy it needs.

`ID_RE` is explicitly **unchanged**. Any diff touching `check.ts:37` fails
review.
