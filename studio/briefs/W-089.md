# W-089 — seats become templates: the builder letter dies

Spec of record, signed by the architect, 2026-09-25. **Revision 1**, no Sol
pass yet. Authority: Patron decree, 2026-09-25 (recorded in the opus title).

This opus changes **the manifest shape, the sella-resolution path, and the
ADOPTION vocabulary**. It does not rebuild the Seats UI and does not touch
codex-trial mechanics (D-025 stands).

## Intent

`studio/bisellium.yml` declares five builder seats:

```
- { id: builder-a, collegium: engineering, kind: agent, model: claude-sonnet-5 }
- { id: builder-b, collegium: engineering, kind: agent, model: claude-sonnet-5 }
- { id: builder-c, collegium: engineering, kind: agent, model: claude-sonnet-5 }
- { id: builder-d, collegium: engineering, kind: agent, model: claude-sonnet-5 }
- { id: builder-sol, collegium: engineering, kind: agent, model: gpt-5.6-sol, harness: codex }
```

Four of those rows are **byte-identical apart from the letter**. The letter
encodes nothing: not a model, not a harness, not a collegium, not a
specialism, not an owner. It is a concurrency handle that the orchestrator
picks arbitrarily at dispatch and that nobody reads afterwards. Measured:
there is **no code path anywhere in the repo** that branches on which letter
a builder carries. The only builder-shaped dispatch in source is a string
prefix test (`packages/cli/src/hooks.ts:378`, `!sella.startsWith("builder")`)
which is deliberately letter-blind.

Meanwhile the thing that *is* durable — which opus the work belongs to — is
already the load-bearing identity everywhere else. D-021's one-writer
discipline proves it: `recordOwnerRefusal`
(`packages/commands/src/writes.ts:256`) refuses a write to `opera/<id>.md`
unless HEAD is on `opus/<id>`. Read the whole function — **the sella is not an
input**. Ownership is keyed on the opus branch and only on the opus branch.

So the letter is redundant with nothing and the opus id is redundant with
everything. The decree: **one builder seat per tier**, with instance identity
minted at dispatch from the seat plus the opus.

The Patron's stated scenario is 100 concurrent builders. Under today's shape
that is 100 hand-written manifest rows, and worse: the worktree slot
allocator (`packages/shim/src/worktree.ts:50`) hands out `<sella>-<n>` by
scanning for the first free `n`, so 100 builders sharing four letters
contend on a counter and produce branches like `bisellium/builder-a/37`
whose name says nothing about the work. Under seat templates the manifest
gains zero rows and each instance gets `bisellium/builder.W-137/1` — a
branch name that reads as what it is.

## Measurement: what the migration costs

`check` on the officina as it stands, versus the same officina with
`builder-a/b/c/d` deleted and `builder-sol` renamed. Both runs are
`npm run -s check -- <copy> --repo . --json`, on a copy so nothing real
moved:

| | findings | blocking |
|---|---|---|
| baseline (`studio/` unmodified) | 141 | **0** |
| `builder-*` rows deleted | 191 | **50** |

The 50 break down as 34 × `traditio.sella`, 15 × `opus.sella`, and one
`link.dead` that is an artifact of copying `studio/` away from its sibling
`README.md` — discount it. So the real cost is **49 blocking findings across
34 opus records**, every one of them a *true statement about the past*:

```
studio/opera/W-006.md:6:  sella: builder-c
studio/opera/W-006.md:22: traditio: { sella: builder-c, stage: done, ... }
studio/opera/W-064.md:7:  probationes: { spec: { sella: builder-a, ... } }
```

Counted across the whole officina: 296 `builder-a`, 145 `builder-b`, 46
`builder-c`, 27 `builder-d`, 71 `builder-sol`, over 359 files — most of them
in `ci/*.log`, which is evidence and is never touched.

**Records are append-only facts about the past. History does not move.** The
manifest is a statement about the present. The two blocking rules above
conflate them, and that conflation is the actual defect this opus has to
resolve.

The resolution, measured: keep the retired ids **declared**, with a
`retired: true` flag on the existing row. Same run again:

| | findings | blocking |
|---|---|---|
| templates + `retired: true` on the five old rows | 142 | **0** (the `../README.md` copy artifact only) |

Zero. `check` already tolerates an undeclared key on a sella row, so the read
rules in group E need **no change at all** for the historical ids — they stay
in `sellaIds`, they stay legal forever, and the typo-catching block they
provide stays blocking. The only new enforcement is a refusal on the
*dispatch* side.

That is also why `retired: true` on the row beats the alternatives. A
separate top-level `retired_sellae:` list would need `uniq()` run over it for
id format and uniqueness, a sibling field in
`packages/schema/src/index.ts:278`, and the union taken at six read sites. A
flag on the row is one key and six read sites unchanged. The precedent
already exists in this manifest: `probationes[].since` is the same move — a
grandfathering marker that keeps history legal.

## Measurement: the separator

The decree asks for `builder@<opus-id>`. Measured against the real rules.

`ID_RE` is `/^[A-Za-z0-9][A-Za-z0-9._-]*$/` (`packages/cli/src/check.ts:37`).
It admits `.`, `_`, `-` and rejects `@`. Four probe opera were written into a
copy of the officina, one per candidate separator, each carrying the
candidate in `sella:`, `traditio.sella` and `probationes.spec.sella`, and
`check` was run over them:

| candidate | `path.id.unvalidated` | git refname `bisellium/<id>/1` | `safeItemPath` | YAML round-trip | `receipts/<id>/` |
|---|---|---|---|---|---|
| `builder@W-089` | **3 × block** | legal | ok | ok | **block** |
| `builder.W-089` | clean | legal | ok | ok | clean |
| `builder_W-089` | clean | legal | ok | ok | clean |
| `builder-W-089` | clean | legal | ok | ok | clean |

`@` is the one candidate that fails, and it fails in three places at once —
the two front-matter refs and the receipt directory name:

```
block path.id.unvalidated opera/W-901.md | front matter.sella "builder@W-089" is not a valid id
block path.id.unvalidated receipts/       | receipts directory name "builder@W-089" is not a valid id
```

Note that `@` passes `safeItemPath` and YAML and `git check-ref-format`. The
single authority that rejects it is ID_RE.

**Decision: the separator is `.`, and ID_RE is not widened.**

Why not widen ID_RE. It is the one containment invariant shared by every id
in the system — opus ids, petitio ids, decision ids, receipt directory names,
every `safeItemPath` operand, every acta filename component. ADOPTION:233
publishes it as a contract: *"each id must be alphanumeric (`.`, `_`, `-`
allowed) with no path separator or `..` segment — every id can end up as a
filename component"*. Trading that invariant for one cosmetic character is
the wrong side of the deal, and the lex is explicit that any id reaching a
filesystem write goes through the containment discipline.

Why `.` over `_` and `-`:

- `-` is the character the letters used, so `builder-W-089` reads as another
  enumerated seat, and `builder-codex.W-100` under a `-` separator would need
  longest-declared-prefix parsing to disambiguate a tier name from an
  instance. Ambiguous by construction.
- `_` is unambiguous but visually mushy against `W-089`, and appears nowhere
  else in this officina's vocabulary.
- `.` already reads as a namespace separator, no declared sella contains one,
  so "everything before the first `.`" is an unambiguous seat name even when
  the seat is itself hyphenated (`builder-codex.W-100` → `builder-codex`).
  It also keeps `run.ts:199`'s derived address valid:
  `builder.W-089@studio.bisellium` is one `@` and a real email, where
  `builder@W-089@studio.bisellium` is two.

One caution the builder must respect: `badId` (`paths.ts:44`) rejects `..`.
The minter must never produce a doubled dot, which it cannot as long as
neither operand starts or ends with one.

## Behaviours

Each numbered behaviour gets its own recorded red. Behaviour 1 is a manifest
edit with a check assertion, not source, and its red is the check run that
fails before the edit.

**1. The manifest declares seat templates, not enumerated seats.**
`studio/bisellium.yml`'s `sellae` gains `builder` (collegium engineering,
kind agent, model `claude-sonnet-5`) and `builder-codex` (collegium
engineering, kind agent, model `gpt-5.6-sol`, harness `codex`) — one per
D-020/D-023 build tier. `builder-a`, `builder-b`, `builder-c`, `builder-d`
and `builder-sol` keep their rows unchanged except for an added
`retired: true`, and are the only rows carrying it. `bisellium check studio
--repo .` reports zero blocking findings after the edit. `examples/sample-studio`
makes the same move: `builder-1`/`builder-2` become a single `builder` seat.

**2. `retired` is a declared, typed sella key.** `check` accepts a boolean
`retired` on a sella row. A non-boolean value is a blocking `manifest.shape`
finding at `bisellium.yml#sellae[<i>].retired`, following the
`integration.push` precedent at `check.ts:289`. `packages/schema/src/index.ts`
and `adapters/native/src/index.ts`'s `Sella` mapping carry the flag through
so a consumer can read it without re-parsing YAML.

**3. One resolver owns seat lookup.** A single exported helper resolves a
sella id against the manifest and is the only place the grammar lives.
Suggested shape — the builder may adjust the return type, not the semantics:

```
resolveSeat(manifest, id): { seat: Sella; instance?: string } | undefined
```

Contract: an id that exactly matches a declared row resolves to that row with
no `instance` (this is checked **first**, so a hyphenated seat name can never
be mis-parsed as an instance of a shorter one); otherwise, an id of the form
`<prefix>.<rest>` where `<prefix>` exactly matches a declared row resolves to
that row with `instance: <rest>`; anything else returns `undefined`. A
retired row resolves — reads must work forever — and the caller sees
`retired: true` on the seat and decides. Empty `<rest>` (a trailing dot) does
not resolve.

**4. Instance ids are minted, never hand-written.** A single minter —
`seatInstance(seatId, opusId)` — is the only producer of an instance id:
`seatInstance("builder", "W-089") === "builder.W-089"`. It refuses (returns
`undefined`, or throws — the builder's call, but it must not return a bad id)
when either operand is empty or would produce a string failing `ID_RE` or
containing `..`. `resolveSeat(manifest, seatInstance(seat, opus))` round-trips
to the seat for every declared seat and every opus id on disk.

**5. Every dispatch verb accepts an instance id.** The three membership tests
(group A) and the seven row lookups (group B) route through `resolveSeat`.
Concretely, all of these succeed where they exit 2 or return an empty bundle
today:

- `bisellium context --sella builder.W-089 studio` prints the engineering
  lex and the engineering index, byte-identical to
  `--sella builder studio`, and reports `builder.W-089` as the sella.
- `bisellium run --sella builder.W-089 --studio studio -- <cmd>` acquires a
  worktree and writes a receipt.
- `bisellium handoff --opus W-089 --sella builder.W-089 --next …` writes the
  handoff.
- `bisellium emit --usage 1000 --opus W-089 --sella builder.W-089 --model
  claude-sonnet-5` records the usage.
- `bisellium talk --sella builder.W-089 --studio studio …` resolves the
  seat's harness and model.
- `bisellium delegate --sella builder.W-089 --model X` — see behaviour 6.

The orchestrator's own dispatch is out of scope: nothing in this opus makes
`tick` mint instance ids. This opus makes the ids *legal and resolvable*; who
mints them at dispatch is the orchestrator's business and stays prose for now
(named in For Sol).

**6. A dispatch verb refuses a retired seat, by name.** `run`, `talk`,
`context` and `delegate` given a retired seat id — `builder-a`, or an
instance of one such as `builder-a.W-200` — exit 2 (for `context`, exit 1,
its existing refusal code) with a message naming a live seat:

```
sella "builder-a" is retired — dispatch "builder" instead
```

`delegate --sella builder-a --model X` refuses for the same reason and does
**not** write `sellae[i].model`: a retired row's model is a historical fact,
never re-decreed. `probe` skips retired rows when gathering candidates — a
retired seat's model is not a model this officina is asking about.

**7. `traditio.sella` and `opus.sella` accept an instance id whose seat is
declared.** Both rules route their membership test through `resolveSeat` and
therefore accept `builder.W-089`. They keep blocking an id that resolves to
nothing: `bulider.W-089` (misspelled seat), `ghost.W-089` (no such seat),
`builder.` (empty instance), and a bare unknown id such as `builder-e`. The
34 historical `traditio.sella: builder-*` records and 15 `sella: builder-*`
records stay clean via their declared retired rows, with no edit to any
record. `check studio --repo .` stays at zero blocking findings throughout.

**8. The `process.cascade` hook warning stops guessing from a prefix.**
`packages/cli/src/hooks.ts:378`'s `!sella.startsWith("builder")` becomes a
`resolveSeat` lookup: the warning is suppressed when the resolved seat is a
declared build seat, and emitted otherwise. `builder.W-089` and
`builder-codex.W-100` write source silently; `builderish`, `builder`-prefixed
strings that resolve to nothing, and `eng-lead` all warn. This is process
enforcement in a hook, where the standing rule puts it, rather than in a
string prefix that any similarly-spelled sella defeats.

**9. An instance id survives the filesystem and git surfaces.** With
`builder.W-089` as the sella: `receipts/builder.W-089/<session>.json` is
written and `check` reports no `path.id.unvalidated` for the directory name;
the worktree branch `bisellium/builder.W-089/1` passes
`git check-ref-format`; `GIT_AUTHOR_EMAIL` is
`builder.W-089@<slug>.bisellium` — exactly one `@`. A test pins all three,
including a negative case proving an id containing `..` never reaches a join.

**10. ADOPTION records the vocabulary, and the boot line stops lying.**
`docs/ADOPTION.md`'s `sellae` example block documents `retired`, and a short
"Seats and instances" passage states the contract: a **seat** is a template,
one per tier, declared in `sellae`; an **instance** is `<seat>.<opus-id>`,
minted at dispatch, carrying no state of its own; **the opus id is the
identity**, and D-021's one-writer discipline is already keyed on the opus
branch, so the instance name and the ownership rule agree by construction; a
**retired** seat stays declared so that records naming it stay readable
forever, and is refused as a dispatch target. `GLOSSARY.md` gains the two
terms. `.claude/agents/builder.md:14`'s boot line becomes
`bisellium context --sella builder studio` — the seat, since a subagent brief
cannot know its own instance id. `bisellium docs registry` stays green.

## Non-goals

- **The Seats UI is not rebuilt.** Measured: `seatRows` and
  `availableModels` (`apps/web/src/lib/delegation.ts:47,101`) render whatever
  `sellae` holds, so nothing breaks. What they *will* do is render the five
  retired rows as ordinary seats, model dropdown and all, with only
  behaviour 6's CLI-side refusal behind them. That is a cosmetic gap, not a
  correctness one. **File a follow-on** to grey out or fold away a retired
  seat in the Seats surface — UI/UX is the Patron's call and not
  engineering's to decide inside this opus.
- **Codex-trial mechanics are untouched.** D-025 stands. `builder-codex` is
  a rename of the seat `builder-sol` occupied, at the same model and harness;
  the trial's rules, its censor gate and its red-team carve-out are not this
  opus's business.
- **No record is rewritten.** Not one byte under `studio/opera/`,
  `studio/ci/`, `studio/acta/`, `studio/petitiones/` or `studio/decisions/`
  changes. `ci/*.log` in particular is evidence.
- **The gate-sella membership hole stays open.** `probationes.<id>.sella` is
  format-checked and not roster-checked (group E). Closing it would convert
  20 historical records into blocking debt for no gain here.
- **The orchestrator is not taught to mint.** No change to `tick`'s dispatch
  or to the cascade scripts.
- **`resolveSella`/`namedSella` keep their "guest" and no-roster-check
  behaviour.** They are W-039's deliberate design and out of scope; adding a
  roster check there is a separate opus with its own migration question.

## Seams

One new seam and one changed one. Both are contracts.

**S1 (new) — `resolveSeat`.** The single authority on what a sella id means.
Every membership test and row lookup goes through it; no caller re-implements
`id.split(".")` or `sellae.find`. Live in `@bisellium/commands` beside
`safeItemPath` if the import graph allows, so `packages/cli`, `apps/server`
and `packages/shim` can all reach it; if `packages/shim` cannot import
`commands`, the shim's own two sites (`receiptPath`, `worktree`) take the
already-resolved string from their caller rather than getting a duplicated
copy of the grammar.

**S2 (changed) — the manifest's `sellae` roster.** It no longer means
"everyone who may be dispatched". It means "every seat template, plus every
seat that ever existed". Membership is the read contract; `retired: false`
(absent) is the dispatch contract. Documented in behaviour 10; any future
reader of `sellae` must pick which of the two it wants.

`ID_RE` is explicitly **unchanged**. Any diff touching `check.ts:37` fails
review.

## For Sol

My least-confident calls, in order.

1. **`retired: true` may not be what the Patron meant by "the letter dies".**
   The decree says the enumerated seats die. My migration keeps their rows in
   the manifest as tombstones, because measurement says deleting them turns
   49 true historical statements into blocking findings, and the brief's own
   constraint is that old ids read forever. I believe a tombstone is the
   honest shape — the manifest becomes "seats, plus seats that were" — but a
   reader could reasonably say the rows should be gone and the two rules
   should learn a `retired_sellae` list, or (worse) be downgraded to advise.
   Attack the tombstone: is a retired row still a *seat* in a way that
   pollutes the roster's meaning past repair? S2 is where the damage would
   show.

2. **The separator is `.` and the decree said `@`.** I have the measurement
   (three blocking findings for `@`, none for `.`) and I refuse to widen
   ID_RE for it. But `.` inside a sella id has a cost I may be
   under-counting: it reads as a file extension in a directory listing
   (`receipts/builder.W-089/`), and anything that ever does `basename(x,
   ext)` or splits an id on `.` would mis-parse it. Measured: `split(".")`
   has **zero** occurrences in non-test source across `packages`, `apps`,
   `adapters` and `scripts` (the only splits nearby are `init.ts:43` on a
   date's `-`, `rules/docs.ts:72` on `#`, `ci.ts:116` on a space). If Sol
   finds a surface I missed — a template string, a regex, a `basename` call
   with an extension argument — `_` is the fallback and the measurement table
   already clears it.

3. **`resolveSeat`'s exact-match-first rule may be too clever or not clever
   enough.** With two declared builder seats, one of which is hyphenated
   (`builder-codex`), the grammar must never read `builder-codex` as an
   instance `codex` of seat `builder`. Exact-match-first plus a `.`
   separator makes that impossible, and I chose the separator partly for it.
   But I have not thought hard about a seat id that itself contains a `.` —
   ID_RE permits it. Should `resolveSeat` refuse to resolve when a *declared
   seat id* contains the separator, as a check rule rather than a runtime
   surprise? I lean yes and left it out to keep the diff honest.

4. **Behaviour 5 makes instance ids legal but nothing mints them.** The
   orchestrator still dispatches by hand-picking a seat, and after this opus
   it can hand-write `builder.W-089` into every `--sella`. That is a prose
   convention, and the standing rule says process enforcement is a check
   rule or a hook, never prose. I judged "teach `tick` to mint" to be a
   second opus, but the consequence is that W-089 ships a capability with no
   enforcement that it is used. Is that acceptable, or does the opus owe at
   least an advisory rule — *an active opus whose `sella` names a bare build
   seat rather than an instance* — so the gap is visible in `check` output
   instead of being remembered?

5. **Behaviour 8 changes a live process guard.** `startsWith("builder")` is
   crude but it currently fires for every non-builder sella, which is
   fail-safe: an unknown id warns. Routing it through `resolveSeat` keeps
   that (unresolvable → warn), but it now depends on "is this seat a build
   seat", and I have not specified how that is determined — by `munera`'s
   `build` munus and its tier's model, or by the seat's own model matching
   the build tier's, or by a new key. I named none of the three deliberately,
   because each is a different amount of new shape. Pick one, or tell me the
   guard should keep its prefix test and this behaviour should be dropped.

6. **`packages/shim/src/receipts.ts:39` is a raw join of a sella into a
   path**, and the engineering lex §2 says any id reaching a filesystem write
