# W-062 — amend: retitle or re-scope an opus record through the CLI, never by hand

Spec of record, signed by the architect, 2026-09-25. Revision 2, amended
after Sol's red-team pass: **AMEND-FIRST, 7 lands / 3 held.** Sol has read
revision 1 and attacked it; it has not reviewed the amendments below, and
this is still the architect's document alone. The amendment log is at the
end; every land is marked at the place it changed the spec.

## Intent

An opus record carries two kinds of field. Some are *evidence*: a gate's
verdict, a state transition, a handoff — each produced by exactly one verb
that refuses to write it dishonestly. Some are *description*: the title, and
the `spec:` pointer that names which document the opus is built against.
Every evidence field has a writer. **Neither descriptive field has one once
it is set.**

Precisely (Sol land 7 — revision 1 claimed "`new` writes both, once", which
is false): `new` always writes `title` and nothing ever writes it again.
`new` writes `spec:` **only** with `--spec` or `--brief`, and `ready` writes
it on the `greenlit|halted → building` transition. W-062's own record is the
proof — `studio/opera/W-062.md` has no `spec:` key at all, because it was
filed without either flag. So the pointer has two writers for its *initial*
value and none for any later one.

Two live instances this week, both disclosed, both forced:

1. **W-046's title went stale.** The Patron's decrees narrowed its scope
   mid-flight. `studio/opera/W-046.md` still reads *"provider portability:
   one opus end-to-end on both harnesses, model and policy passed"*. The
   honest title — *"the decreed model and a command policy reach both
   harnesses"* — exists only in the brief's own first paragraph, which says
   in as many words: *"The title above is the honest one; the record is the
   orchestrator's to change through the CLI."* There was no such CLI. The
   record still lies, and `context`, `query`, the server's `/api/opera` and
   the generated backlog page all read that lying field
   (`packages/commands/src/context.ts:148`, `query.ts:81`,
   `apps/server/src/store.ts:261`).

2. **W-075's spec pointer was re-pointed by hand.** It was dispatched with
   its own record as the spec; a brief was written afterwards, and the
   pointer had to move `opera/W-075.md` → `briefs/W-075.md`. `ready` is the
   only writer of that field (`packages/commands/src/lifecycle.ts:148`,
   `doc.setIn(["spec"], specRel)`) and it refuses any opus that is not
   `greenlit` or `halted` (`:129`). The opus was `building`. Every honest
   path ran through the forbidden one.

The censor named the class and set the trigger: **`hand-edit×absent-verb`**,
retro class C7 in `studio/ci/W-075-review-1.log:351` — *"second live
instance this week (A5). Tracked, disclosed, forced. Target: W-062
(`amend`). Escalate on a third."* Advisory A5 in the same log: *"Two is a
tracked exception; a third makes it a habit."*

CLAUDE.md's "Never by hand" list names `opera/` front matter first. A
prohibition with no permitted alternative is not enforcement; it is a
standing invitation to disclose a violation and carry on. This opus supplies
the alternative, and — the more important half — supplies a **refusal** for
everything that must not travel the same road.

## The rule this encodes

**A record's description is amendable; its evidence is not.** The split is
not a matter of taste, and drawing it is this opus's actual deliverable:

| Field | Amendable | Why |
|---|---|---|
| `title` | **yes** | A claim about scope. When the scope moves, the honest act is to move the claim. Nothing certifies a title. |
| `spec:` | **yes, if it already exists** | A pointer to the document of record. Which document that *is* can legitimately change (W-075). Creating it from absent is not an amendment — `new --spec/--brief` and `ready` own the first value (land 7). |
| `state` | **never** | A lifecycle position. `greenlight`, `ready`, `done`, `halt`, `review --fail` each own one edge and refuse the others. |
| `probationes.*` | **never** | Evidence. Produced by `verify`, `review`, `waive`; corrected — append-only — by W-040's `ready --correct`. |
| `traditio` | **never** | A record of what happened at a moment. `handoff` writes it. |
| `id` | **never** | It must equal the filename. Changing it is a rename, not an amendment. |

Per **D-016**, a command earns its place in this CLI when *refusing* is the
point. `amend --title` on its own would be a text editor with extra steps.
`amend` refusing `--state` **by name**, with a message saying which verb
owns that field, is the feature: it is the first thing an agent reaching for
a hand edit will run into, and it has to send them somewhere real.

Per **W-040**'s already-accepted house rule, *a correction appends; it never
erases* — the same style `leges/*.md` use for their amendment logs and
`D-015` uses for its struck clause. An amendment leaves the superseded value
in the record forever. W-040 gives that treatment to a gate signature; this
gives it to a descriptive field. The two never touch the same key (see
Sequence).

## Interfaces

```
usage: bisellium amend <opus> [--title <text>] [--spec <path>] --reason <text> [--sella <id>] [--studio <dir>] [--now <iso>]
```

`amend` is a new verb rather than a flag on an existing one. It cannot be
`ready --retitle`: `ready` is a state transition (`greenlit|halted →
building`) and every one of its refusals exists to protect that transition.
`amend` deliberately has **no state gate at all** — W-046 is `done` and its
title is wrong, which is precisely the case that must work. Hanging a
stateless write off a stateful verb would mean either weakening `ready`'s
guard or bolting a second, contradictory guard beside it.

- **At least one of `--title` / `--spec`.** Both in one call is allowed and
  appends one entry per changed field, `title` first, then `spec`, so the
  record is deterministic regardless of flag order.
- **`--reason` is mandatory** and must be non-empty after trim. W-040's
  rule, verbatim: the reason is the feature. An amendment with no stated
  reason is the thing this opus refuses to make easy.
- **`--sella`** composes the two helpers that already exist rather than
  taking either whole (land 8). `resolveSella` returns `--sella ""` and a
  whitespace `$BISELLIUM_SELLA` verbatim, and `amendments[].sella` is
  collected by `collectIdRefs` (`rules/paths.ts:58`, which recurses arrays
  and pushes every `sella` key) and run through `badId` against
  `ID_RE = /^[A-Za-z0-9][A-Za-z0-9._-]*$/` — so a blank writes front matter
  that `path.id.unvalidated` **blocks**. Therefore: an explicit `--sella`
  that is empty or whitespace is **refused** (it is an assertion of
  anonymity, not an omission); a blank `$BISELLIUM_SELLA` is treated as
  unset, which is exactly `namedSella`'s existing semantics; and the
  fallback is still `guest`. In code that is `namedSella(flag) ?? "guest"`
  after the explicit-blank refusal — no third helper. `namedSella`'s
  docstring says "Not exported: `runRed` is the only caller"; it gains a
  second in-module caller and the docstring must say so.
- **Works in any state**, `done` and `halted` included. Stated positively
  because every sibling verb in `lifecycle.ts` has a state gate and a
  reviewer will otherwise read its absence as an omission.
- **`--spec` is an officina-relative path, and only that** (land 10).
  `isContained` alone is not the documented contract: `resolve(root, "/abs")`
  returns the absolute path unchanged, so an absolute path that happens to
  sit inside the officina passes it, while `docs/ADOPTION.md` defines
  `spec:` as officina-relative and every reader resolves it with
  `resolve(root, spec)`. An absolute value would therefore travel into the
  record and break in any clone at a different path. Lexical containment
  also follows no symlink. One small amend-only helper does all four checks
  in order — reject absolute, `isContained`, `existsSync`, then
  `realpathSync` on the target re-checked for containment — and it *calls*
  `isContained` rather than re-deriving containment (there stays one
  spelling of the resolved-path relation).

Front matter after one amendment of W-046:

```yaml
title: "provider portability: the decreed model and a command policy reach both harnesses"
amendments:
  - at: 2026-09-25T10:00:00.000Z
    sella: architect
    field: title
    reason: "the Patron's decrees narrowed the scope mid-flight; the record claimed an opus crossed both harnesses, a talk-shaped dispatch did (W-046 brief ¶1, Sol round-1 finding 1)"
    superseded: "provider portability: one opus end-to-end on both harnesses, model and policy passed"
```

`superseded` carries the **old** value only. The new value is the live field;
storing it twice creates two places that can disagree. Key names
(`at`, `sella`, `reason`, and a list appended to) are W-040's `corrections`
shape on purpose — a reader who has seen one can read the other.

The write goes through `editOpusFrontMatter` (merge into the yaml Document,
body byte-for-byte) like every other tool-written record change. Two traps
the builder owns:

- `amendments` will not exist on the first amendment. `doc.addIn` needs the
  sequence to be there; create it through the Document API, never by
  string-splicing the front matter.
- Records are created with a flow-style `probationes: {}` and
  `editOpusFrontMatter` preserves per-node style (see D-021's "Why not the
  other candidates"). A new top-level block sequence must not reflow
  anything else — behaviour 1 asserts the untouched keys and the body
  survive.

### Refusals

Never-amendable fields, refused **by name, before argv is even parsed**:

```ts
// ponytail: an exact-arg scan, so `--title "--state"` is also refused.
// Harmless — refusing a title that is literally a flag name costs nothing.
const NOT_AMENDABLE: [string, string][] = [
  ["--state", "state is lifecycle, not description — use greenlight/ready/done/halt, or review --fail to reopen"],
  ["--probationes", "a gate is evidence — it is produced by verify/review/waive, never amended"],
  ["--traditio", "a handoff records what happened at a moment — use handoff"],
  ["--id", "an id must equal its filename — that is a rename, not an amendment"],
];
```

Each exits 2, writes nothing, and prints `amend: <flag> is not
amendable — <why>`. This scan runs **before** `parseFlags` and therefore
before the D-021 ownership guard, which is a deliberate departure from the
five siblings' ordering: those place `recordOwnerRefusal` immediately after
the record-existence check so a trunk caller is told about ownership rather
than about state. That reasoning does not reach here, because a
never-amendable flag is wrong on **every** ref — telling a caller to move
checkouts before telling them the flag does not exist would send them to do
work that changes nothing. Sol attacked this ordering and **held** it, on a
sharper ground than revision 1's: D-021 governs *write* ownership, and this
refusal can never write. Every verb the message redirects to — `greenlight`,
`ready`, `done`, `halt`, `review`, `waive`, `handoff`, `verify` — carries
its own ownership guard, so a caller sent to the right verb on the wrong ref
is still refused by that verb.

Every other refusal, each before anything is written, exit 2:

- no opus id; neither `--title` nor `--spec`; `--reason` absent, empty or
  whitespace-only; any undeclared flag (`parseFlags`' own error)
- `--title` empty or whitespace-only — `check.ts:432` requires a non-empty
  `title`, so this refuses at the source what `opus.keys` would block later
- `--spec` resolving outside the officina, via `lifecycle.ts`'s existing
  `isContained` (D-008's resolved-path relation, never `startsWith`) — the
  message names D-008, the shape `ready --spec` and `review --evidence`
  already use. This is `path.escapes.officina` (`rules/paths.ts:131`) read
  backwards: a record this command writes cannot trip it.
- `--spec` given as an **absolute** path, even one inside the officina, and
  `--spec` whose target's **real path** escapes the officina through a
  symlink (land 10)
- `--spec` naming a path that does not exist under the officina, in
  `ready`'s own wording
- **`--spec` when the record has no string-valued `spec:` key** (land 7):
  `amend: <id> has no spec: to amend — the first pointer is written by
  "new --spec"/"new --brief" or by "ready"`. This keeps `superseded`
  meaningful on every entry: there is no amendment from nothing.
- an unknown opus id (`safeItemPath` + `existsSync`)
- **a value identical to the current one**, per field — but the comparison
  differs per field (land 3). `title` is compared as an **exact scalar**:
  leading or trailing whitespace is a real change to a displayed field and
  amending it is legitimate. `spec` is compared by **canonical resolved
  target**, because `briefs/W-1.md` and `./briefs/W-1.md` name one
  document, and recording an amendment between them would fabricate a
  change that did not happen. A path alias is a no-op and is refused as
  one.
- **a pre-existing `amendments:` key that is not a YAML sequence** (land
  9). A scalar or mapping there makes `doc.addIn` throw, which would leave
  `runAmend` exiting on an uncaught exception rather than a refusal. Read
  the record with `readFront` and refuse — exit 2 — **before**
  `editOpusFrontMatter` is called at all. Two mechanisms then guarantee the
  bytes: the pre-check means the callback is never entered, and
  `editOpusFrontMatter` writes only after its callback returns
  (`frontmatter.ts:52-53`), so even a throw inside it leaves the file
  untouched. The message names the key and its actual shape.
- D-021's ownership refusal via `recordOwnerRefusal`, after the
  record-existence check

### One event, no timeline line

`amend` emits a single `workflow.item_amended` per amended field —
`WF.ITEM_ID`, `WF.ACTOR_ROLE`, plus bare `field` and `reason` keys (the
precedent is `greenlight`'s bare `attrs["reason"]`, `writes.ts:808`). No new
`workflow.*` attribute name is minted; the event name joins
`WorkflowEventName` in `packages/schema/src/index.ts:245`, one literal. No
`workflow.state_changed`: nothing changed state.

**It does not append to the Patron timeline**, and that was a real choice
against the brief's own suggestion. Two reasons, both checkable:
`appendPatronTimeline` (`writes.ts:170`) is the Patron's own record —
`answer`, `greenlight`, `budget`, `delegate` — and an architect retitling an
opus is not a Patron act; and `.gitignore` carries `studio/timeline/`, so a
line written there is invisible in every clone and in the PR diff. The
amendment's permanent, shared home is the record's own front matter, which
travels with the opus, shows up in review, and survives `git clone`. The
event is local telemetry for the console feed; the `amendments` list is the
record.

### The guard: an active opus's pointer and its spec gate must agree

Revision 1 called this consequence "deliberately unguarded" and invited Sol
to break it. **Sol broke it (land 1), and the call was wrong.** The attack,
verified in source:

- `opus.red_evidence` (`rules/evidence.ts:167`) counts declared behaviours
  by resolving the **live** `spec:` pointer and parsing that document.
- `state.building.spec` (`check.ts:544-547`) requires only that `spec:` is
  non-empty and that the `spec` gate is `passed`. **It never compares the
  gate's `evidence` to the pointer.**

So re-pointing a `building` opus from a ten-behaviour brief to a
five-behaviour brief, with five reds on disk, **erases** the missing-red
block while the old passed gate — which certifies a document the opus is no
longer built against — survives untouched. That is not "making the officina
honest"; it is a laundering path, and it is exactly the erasure my own
attack target said would invalidate the design.

**The fix is a check rule, not a refusal in `amend`.** One condition folded
into `state.building.spec`'s existing walk: for an opus in an ACTIVE state,
when both `spec:` and `probationes.spec.evidence` are present, block unless
they resolve to the same document (`resolve(root, …)` on both, the same
canonicalization land 3 requires of the no-op comparison — never string
equality). The rule id is unchanged, so nothing new needs registering in
`rules/ids.ts`; it is the same clause of the same contract ("an active
opus's spec is real and certified"), with a second message.

Why the rule and not a refusal: a pointer that disagrees with its gate is a
defect **however it arose** — and W-075's record arrived in that state by
hand edit, with no `amend` in the tree at all. A refusal inside `amend`
would close the path for one writer; the rule closes it for every writer and
every hand edit, which is CLAUDE.md's standing rule (process enforcement is
a check rule or a hook, never a memory or prose). It also makes the erasure
structurally impossible rather than merely discouraged: the `red_evidence`
finding may disappear, but a `state.building.spec` block appears in its
place, so **the blocking set cannot shrink** across a `--spec` amendment.
Behaviour 13 asserts precisely that.

Consequences to accept, not soften:

- After amending an active opus's `spec:`, the officina is **red until the
  spec gate is re-signed against the new document**. Today that path is
  `halt` then `ready --spec <new>` (`ready` accepts `halted`); W-040's
  `ready --correct` is the direct one. That is correct discipline: whoever
  re-points an active opus's spec owes the re-signature in the same commit,
  and the required `officina` CI job will insist on it.
- `opus.untracked` (`evidence.ts:87`) still blocks when the new brief is not
  yet committed. Correct, and no guard: commit the brief.
- **The ACTIVE boundary is not a laundering path**, checked: `halt`,
  `amend --spec`, then `ready` does not smuggle a mismatch back into
  `building`, because `ready` rewrites `spec:` *and*
  `probationes.spec.evidence` from the same `specRel`
  (`lifecycle.ts:148-152`) — they agree by construction on the way through.
  But that same line exposes a wart worth stating: `ready`'s `--spec`
  **defaults to `briefs/<id>.md`**, so a `ready` run without `--spec` after
  an amendment that pointed somewhere else silently moves the pointer back,
  leaving an `amendments` entry describing a field that has since returned.
  That is `ready`'s existing default, not something `amend` introduces, and
  it is not in scope to change. The operational rule is: after amending a
  pointer away from the default, every later `ready` passes `--spec`
  explicitly. Say it in the ADOPTION paragraph.
- The rule is **green on the real officina today**, verified: on trunk
  nothing is active (D-021's own noted consequence), and `ready` writes
  `spec:` and `probationes.spec.evidence` from the same `specRel`
  (`lifecycle.ts:148-152`), so anything `ready` produced agrees by
  construction. The one mismatch on disk is W-075, which is `done` and
  therefore outside ACTIVE — behaviour 12 pins that exemption against
  W-075's exact shape, because a rule that fired there would retroactively
  block a shipped opus.

## Behaviours to test

All against temp copies of `examples/sample-studio` under `$TMPDIR` via the
file's existing `freshStudio` / `tmpGitStudioRepo` helpers; `NOW` is the
file's pinned clock. Neither `studio/` nor `examples/sample-studio` is
written.

1. **A `done` opus is retitled.** `runAmend` with `--title` and `--reason`
   on an opus in `done` exits 0; `title` is the new value; `amendments` is a
   one-element list whose entry carries `at` = `NOW.toISOString()`, the
   `--sella` value, `field: title`, the reason, and `superseded` = the old
   title. `state`, `probationes` and `traditio` deep-equal what they were,
   and the body after the front matter is byte-for-byte unchanged (assert
   via `splitFront`, as the existing blocks do). W-046's real case, and the
   proof there is no state gate.
2. **`--spec` re-points the pointer and leaves the gate alone.** On a
   `building` opus whose `probationes.spec.evidence` is `opera/<id>.md`,
   `--spec briefs/<id>.md` moves the top-level `spec:` and leaves
   `probationes.spec` deep-equal — sella, status, evidence, at. W-075's
   case, and the load-bearing half of the amend/refuse split: the gate goes
   on recording what was actually reviewed. **And the record is now blocked
   by `state.building.spec`** for exactly that disagreement — assert the
   block here as part of this behaviour's outcome, so the test can never be
   read as "re-pointing an active spec is quietly fine" (land 1). This
   fixture needs the declared `spec` probatio too, for the same reason
   behaviours 11-12 do (see the fixture trap in Files owned) — without it
   the block-assertion half of this behaviour silently tests nothing.
3. **Both flags in one call** append two entries, `title` then `spec`
   regardless of flag order, each with its own `field` and `superseded`.
4. **A second amendment appends.** Amend twice; `amendments` has length 2,
   the first entry is byte-identical to what it was, and both `superseded`
   values are readable. Append, never rewrite.
5. **One `workflow.item_amended` per amended field**, carrying `ITEM_ID`,
   `ACTOR_ROLE` = the resolved sella, and the field name; and **no**
   `workflow.state_changed` line is appended by any amend call in this file.
6. **Every refusal exits 2 and writes nothing.** One block, one table — the
   shape this file's behaviour 2 already uses: read the record's bytes and

   already `briefs/<id>.md`, the path-alias no-op (land 3); `--sella ""`
   and `--sella "  "` (land 8); and a record whose `amendments:` is already
   a scalar, and one where it is a mapping (land 9). For the whitespace

### Reds

One red per behaviour, assertion-level, no two sharing an output
(engineering lex §2, `opus.red_evidence`, P-005). The skeleton that produces
them is exact:

```ts
export function runAmend(_args: string[], _opts: WriteOptions = {}): WriteResult {
  return { exitCode: 0 };
}
```

Exported (so an import mistake is a module-load failure, not a silently
passing red), no output, no write, exit 0. Against it, behaviours 1-5 and

because 0 ≠ 2. Note what the skeleton must *not* be: a stub returning 2
would make behaviours 6-8 pass green while nothing worked — the refusals
are the majority of this opus's surface, and a skeleton that fakes them
fabricates the reds.

## Out of scope

- **Amending `kind` or `collegium`.** Descriptive in principle, so the
  refusal table does not name them — they simply have no flag. Add one the
  first time either is hand-edited; that is the same trigger that produced
  this opus, and it has not fired.
- **Renaming an opus id.** Refused by name. It is a file rename plus every
  inbound reference (`addressed_by`, `ci/reds/<id>/`, branch names, the
  reds store, acta prose) — a migration, not an amendment.
- **Setting `spec:` for the first time.** Refused (land 7); `new
  --spec`/`--brief` and `ready` own the initial value. Note the live
  consequence: `studio/opera/W-062.md` has no `spec:` key today, so this
  opus's own record gets its pointer from `ready`, not from `amend`.
- **Fixing the same two path holes in `ready --spec` and `review
  --evidence`** (land 10). Both accept an absolute-inside path and neither
  follows a symlink, because `isContained` is all they call. The amend-only
  helper does not change their behaviour, deliberately: they are not this
  opus's files and tightening a path contract under two existing callers is
  its own opus with its own reds. File it the first time either is fed an
  absolute path, or fold it into W-059's containment sweep — whose brief is
  the natural home, since this is the same class at two more sites.
- **Amending anything but an opus.** A decision, a lex and a petitio all
  have amendment needs and all lack a writer (D-021's own front matter was
  hand-written, and says so). One artifact at a time; the sibling opens
  when a second artifact class is hand-amended.
- **Fixing W-046's and W-075's records.** This opus builds the road.
  Walking it for those two is the orchestrator's next act, in its own

- **A check rule on amendment count.** W-040 pairs its append-only

  same suspicion, and the `amendments` list is already in the committed
  record where a reviewer reads it. Add a rule if an opus is ever amended
  enough times that the list stops being read.
- **Undoing an amendment.** Append-only means append-only. The remedy for a
