# W-042 — halt and abandon: take an opus out of play without completing it

## Intent

The officina has three blocking findings and all three belong to two opera
nobody intends to finish:

```
$ npm run -s check -- studio --repo . --level block
  traditio.present    opera/W-028.md  active item (building) has no handoff
  opus.red_evidence   opera/W-027.md  missing red log(s) for behaviour(s) 1, 2, 4, 5
  opus.red_evidence   opera/W-028.md  missing red log(s) for behaviour(s) 1, 2, 3, 4, 5
FAIL — 3 blocking, 80 advisory
```

D-017 accepted that evidence debt as historical. It could not move either
opus's `state`, because no verb does:

- `close` (`packages/cli/src/close.ts`) calls `executeClose` → `runDone`,
  which refuses on unpassed gates. It is a FINISH verb. It refused W-028
  with `gates not passed: review`, correctly.
- `pause`/`resume` (`packages/commands/src/pause.ts`) write a studio-wide
  `<studio>/PAUSED` marker. There is no `--opus`, and there never was.
- `halted` is a first-class state that every **reader** already honours —
  `packages/schema/src/index.ts:21` (phase), `adapters/native/src/index.ts:45`
  (state id) and `:162` (a declared transition from every state but `done`),
  `check.ts:536-540` (`halted.exit`, `halted.at`, `halted.stale`),
  `lifecycle.ts:102` (`ready` admits `greenlit|halted` → `building`). No
  **writer** anywhere sets it. The four `halted` blocks in `studio/opera/`
  were typed by hand, before any of this.

So the state exists, the rules that read it exist, the way back out exists.
The single missing piece is the verb that writes it. That is this opus, and
it is deliberately nothing more: the Patron's goal — officina green, then
the `officina` job promoted to required in `.github/workflows/ci.yml:34` —
is blocked on exactly one `state:` write.

### Why one verb and not two

`halt` (resumable) and `abandon` (terminal) would need two state ids, and
the second id is not free. `halted` is load-bearing in six places: schema
`PHASES`, the native adapter's `STATES`/`ORDER`/transition table, epoch0's
phase mapping (`adapters/epoch0/src/lifecycles.ts:60`), `check`'s `stateIds`
and its `ACTIVE`/`WIP_STATES` reasoning, `ready`'s admission edge, and the
web board. A second terminal id changes all six to encode what one prose
field already says — and it would still not *enforce* terminality, since a
Patron who decides to resurrect an abandoned opus types `ready` either way.

Terminality is therefore a property of the exit condition, not of the state.
`resume_when` is the field that already asks "what would bring this back",
`halted.exit` already blocks a halted opus that omits it, and *"nothing
would — abandoned, see D-017"* is a valid, honest, human-written answer to
that question. One verb, `halt`. Abandonment is a halt whose exit condition
is `never`.

### Why `--decision` is mandatory

Halting writes off greenlit work, and the obvious abuse is halting to dodge
a failing review. The guard is not a refusal — refusing while a review round
is open would refuse both W-027 and W-028, the two opera this verb exists to
move. The guard is twofold and cheaper:

1. **A mandatory `--decision <id>` that must resolve to a real file at
   `<studio>/decisions/<id>.md`.** You cannot halt quietly; you must point
   at a decision someone recorded, with the `kill_when` `decision.kill`
   already demands of it. D-017 is exactly that decision for W-027/W-028.
2. **`halt` never touches `probationes`.** W-028's
   `review: { status: failed, evidence: ci/W-028-review-3.log, … }` survives
   the halt verbatim. A halted opus carrying a failed review gate documents
   the dodge by itself, and `ready`-ing it back to `building` restores that
   verdict into an active state where `state.review.failed` and
   `state.done.probationes` apply again in full — which is D-017's own
   `kill_when`, made mechanical.

### Is the silence honest?

Halting W-027 and W-028 makes `opus.red_evidence`, `traditio.present` and
`wip.cap` stop reporting them. That is not this opus suppressing a rule: all
three already filter on `ACTIVE = {building, verifying, review}`
(`check.ts:68-70`, `rules/evidence.ts:25,81,165`), the same asymmetry
`probatio.certifies.stale`, `state.building.spec` and
`probatio.certifies.mismatch` have had since they were written. The rules
ask "is this *active* work missing its evidence". Halted work is not active
work, the debt stays written in the front matter, and it is reported again
the moment the opus is resurrected. Nothing is deleted and nothing is
backfilled.

## Interfaces

```
bisellium halt <opus> --reason <text> --resume-when <text> --decision <id>
                      [--sella <id>] [--studio <dir>] [--now <iso>]
```

All four flags valued; `--reason`, `--resume-when` and `--decision` are
required, and their absence is a usage error (exit 2) with the banner, not a
default. `--sella` follows the existing `resolveSella` chain
(`--sella` → `$BISELLIUM_SELLA` → `guest`). Signature and plumbing mirror
`runReady` exactly — `parseFlags`, `openStudio`, `safeItemPath`, `readState`,
`resolveNow`, `editOpusFrontMatter`, `emitEvent` — and `runHalt` is
synchronous, like its three neighbours. Do not invent a second idiom.

Front matter written, all **top-level**:

| key | value |
|---|---|
| `state` | `halted` |
| `halted_at` | `now.toISOString()` — the key `check.ts:538` reads |
| `reason` | `--reason` — read by `halted.exit` |
| `resume_when` | `--resume-when` — read by `halted.exit` |
| `halted_by` | `--decision` — the authority trail; new, read by no rule yet |

Top-level is the contract: `check.ts:537-538` reads `d["reason"]`,
`d["resume_when"]`, `d["halted_at"]` off the root, and `runReady:130` deletes
them from the root. The nested `halted: { … }` maps in `studio/opera/W-011`,
`W-012`, `W-013`, `W-015` are hand-typed prose on `done` opera, read by
nothing. Do not imitate them.

`runReady`'s cleanup loop gains `"halted_by"`, so a resurrected opus does not
keep a stale authority stamp for a decision whose `kill_when` has just fired.

Refusals, each exit 2, each writing nothing:

- state `done` or `halted` — mirrors `describeLifecycle`'s own transition
  table (`for (const s of ORDER) if (s !== "done")`), plus re-halting, which
  would silently overwrite a recorded reason and decision with a new one.
- unknown opus id, or one `safeItemPath` rejects.
- a `--decision` that does not exist at `<studio>/decisions/<id>.md`, or that
  `safeItemPath(join(root, "decisions"), id)` rejects (D-008 containment —
  the same helper, not a fresh `join`, and not `ready`'s `isContained`, which
  is for caller-supplied *paths*; `--decision` is an *id*).

Event: one `workflow.state_changed` through `emitEvent`, attributes
`ITEM_ID`, `STATE_FROM`, `STATE_TO: "halted"`, `ACTOR_ROLE` — the existing
four, exactly as `runReady` emits them. **No new `workflow.*` attribute** for
the reason or the decision: those names are a schema contract and this opus
has no authority over them. The reason lives in the front matter, where the
rule that cares about it already reads.

Success line, in `runReady`'s shape: `${opusId}: state=halted by=${decision}`.

## Behaviours to test

1. **`halt` moves a `building` opus to `halted` and writes all five keys.**
   Against a temp copy of `examples/sample-studio`, `runHalt` on an opus in
   `building` exits 0; its front matter afterwards has `state: halted`,
   `halted_at` equal to the pinned `NOW.toISOString()`, `reason`,
   `resume_when` and `halted_by` equal to the flags passed; and the markdown
   body after the front matter is byte-for-byte what it was before (the
   `editOpusFrontMatter` discipline — assert on `splitFront`, as the existing
   blocks do). One `workflow.state_changed` line is appended with
   `STATE_FROM: "building"`, `STATE_TO: "halted"` and the `--sella` value in
   `ACTOR_ROLE`.

2. **Every refusal exits 2 and writes nothing.** One block, one table, the
   shape behaviour 2 of this file already uses (read the file contents
   before and compare after): `done` and `halted` source states; an unknown
   opus id; each of `--reason`, `--resume-when`, `--decision` omitted in
   turn; a `--decision` naming a file that does not exist under
   `decisions/`; and a `--decision` of `../../etc/passwd`. In every case the
   opus file is unchanged and no event line is appended.

3. **A failed review gate survives the halt untouched.** An opus in
   `building` whose `probationes.review` is `failed` with evidence — W-028's
   exact shape — is halted successfully, and its `probationes` mapping
   afterwards deep-equals what it was before. This is the anti-dodge guard
   asserted directly: halting hides the opus from the active-state rules, it
   never edits the verdict that would embarrass it.

4. **`check` reports a halted opus's active-state debt only while it is
   active.** Build a studio whose opus is in `building`, with a spec
   declaring N behaviours and no red logs, and no `traditio`. `check` blocks
   on `opus.red_evidence` and `traditio.present`, and the opus counts toward
   `wip.cap`. Run `runHalt`. All three go silent, `halted.exit`/`halted.at`
   do **not** fire (the verb wrote what they read), and the whole run is free
   of blocking findings for that opus. Then `runReady` it back and assert
   `opus.red_evidence` fires again. This is the opus's whole purpose, and it
   is the regression guard for the day someone adds `halted` to `ACTIVE`.

5. **`ready` clears `halted_by` with the rest of the halt entry.** A halted
   opus with all five keys, run through `runReady`, comes back with
   `halted_at`, `reason`, `resume_when` **and `halted_by`** all `undefined`.

## Order of work, and where each red comes from

Five behaviours, five assertion-level reds, no two sharing a body — `red`'s
own `opus.red_content` rule will check the last part, and an import failure
counts as one red, not five (P-005), so the export must exist before any red
is recorded.

`packages/cli/src/lifecycle.test.ts` already carries the harness for this:
`BISELLIUM_ONLY_BEHAVIOUR` (a comma-separated list, read at the top of the
file) restricts a run to the listed blocks, and `bisellium red` inherits the
environment into the command it wraps. W-020 built it for exactly this job.

1. **Behaviour 5 first, at HEAD, with no new code at all.** Write block 5;
   `runReady` today deletes three keys, not four, so it fails on the
   `halted_by === undefined` assertion. Record it:
   `BISELLIUM_ONLY_BEHAVIOUR=5 bisellium red W-042 --behaviour 5 --repo . --studio studio -- node --import tsx packages/cli/src/lifecycle.test.ts .`
   Then add `"halted_by"` to line 130's loop; block 5 goes green.
2. **Land a stub `runHalt`** — the signature, `export`ed, and a body that
   returns `{ exitCode: 2 }` after printing usage. Wire `main.ts` and the
   banner now too, so nothing later is untested-but-shipped.
3. Write blocks 1–4. Record each red on its own, with
   `BISELLIUM_ONLY_BEHAVIOUR=<n>`, so each log contains that behaviour's
   assertions and no others. Against the stub: 1 fails on `exitCode !== 0`,
   2 fails on the *usage-error* cases passing for the wrong reason (the stub
   refuses everything, so assert the source-state and bad-`--decision` cases
   leave the file unchanged **and** that the `building` case in block 1 is
   the one that must succeed — check the recorded logs actually differ before
   moving on), 3 fails on the halt not happening, 4 fails on the check
   findings not moving.
4. Write the real body. All five green, and the rest of the suite with them.

The stub state is never committed.

## Out of scope

- A second, terminal state id (`abandoned`, `killed`). See Intent. If one is
  ever wanted, it is an opus that changes `@bisellium/schema`, both adapters,
  `check` and the board together — not a flag smuggled in here.
- Relaxing `halted.exit` so an abandonment may omit `resume_when`. The field
  is answerable by an abandonment; requiring an answer is the point.
- The `halted.stale` advisory, which will fire on a deliberately abandoned
  opus every day after the seventh, forever. It is advisory, the officina
  goes green at block level regardless, and teaching the rule about permanent
  halts is a check-rule opus with its own brief.
- Worktree and branch cleanup for a halted opus. `halt` writes state and
  nothing else — `prune` already reclaims worktrees, and `close`'s
  conflation of finish-merge-cleanup is precisely why it could not do this.
- Enforcing *who* may halt. `describeLifecycle` names the production magister
  as the actor for `→ halted`, but no other lifecycle verb enforces its
  declared actor either (`done` does not), and inventing an authority
  mechanism for one verb is a platform. `--decision` carries the authority.
- A new `workflow.*` attribute for the reason or the decision.
- `pause`/`resume` and the `PAUSED` marker: untouched. Studio-wide brake and
  per-opus halt are different instruments and stay that way.
- Re-halting, amending a halt in place, or an `unhalt` distinct from `ready`.
  `ready` is already the way back and is already tested.
