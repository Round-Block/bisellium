## Intent

W-125's Git broker binds a unix socket (`scripts/run-builder-host.mjs:556–575`)
and the cell's `git` connects to `/control/git.sock`. Every session now runs
inside the Claude Code bubblewrap sandbox, which denies a unix-socket
`listen()`; there is no unsandboxed path any more (Patron, 2026-10-03). So
`bisellium run`, its red replays and the eleven W-125 acceptance live rows
cannot run at all.

Replace that transport with host-created **named pipes** in the same
host-owned, read-only `/control` mount. One mechanism, one decree family.
W-125's trust map is carried over unchanged and is the standard the censor
judges against (D-035): broker policy stays host-owned, there is no raw `.git`
write, the host parses only channels the host created, and teardown still
kills and deletes everything. No lifecycle id, wire attribute, receipt field,
marker or review-admission rule moves.

**Is the socket the only blocker?** Yes. M2, M4, M5 and M6 found no other
denial on the runner's path: the nested namespaces, every Git operation, the
lease directory, the dependency copy and the cell's loopback bind all work
confined. The only measured denial is `listen()` on a unix socket, and it is
inherited into the cell as well as the host (M1, M4).

**The replacement cannot be inherited stdio fds alone.** M8 is decisive: the
builder command is an arbitrary agent, and every `git` it runs is spawned by a
process it created without mapping fd 3, so the channel is severed before
`git` ever sees it. A named pipe is reached by path, like the socket was
(M9), is a pipe, and needs no `listen()`. That is the transport this brief
specifies. An inherited duplex fd works (M7) and may be used **in addition**
only if a behaviour below needs it; it may not be the only path.

Two implementation hazards were measured and must be handled, not rediscovered:

- A host-side blocking `openSync(fifo, "r")` on the event loop **deadlocks the
  runner before it spawns the cell** (observed: `m9-fifo.mjs` hung until
  rewritten). Open both pipes `O_RDWR` and read through a stream, so the read
  end never sees EOF and never blocks.
- An open pipe handle is a live libuv handle. Unless it is closed (or
  `unref`ed) at teardown, the runner never exits and every live row times out.
- A host **write** to `git-reply` is the symmetric hazard, and the one the
  phase-1 builder found missing: a cell that never drains fills the pipe at
  65536 bytes, after which a blocking write hangs the runner and a queued
  write grows it without bound (M11). The discipline below is mandatory, not
  the builder's choice.

## Interfaces

### The control channel

`scripts/git-broker.mjs` exports one function:

`openCellChannel(controlDir, serve) -> { close() }`

It creates two named pipes in `controlDir` — `git-request` and `git-reply` —
with mode 0600, opens both `O_RDWR` on the host, reads newline-delimited JSON
frames `{ id, args }` off the request pipe, calls
`serve(args) -> { status, stdout, stderr }`, and writes
`{ id, status, stdout, stderr }\n` to the reply pipe. `close()` closes both
handles so the runner's event loop can drain.

**Policy does not move into this module.** The runner keeps `validateGitArgs`,
`GIT_LOCKDOWN`, `brokerEnv`, the `bisellium-probe-index` branch and the
`/workspace` path mask, and passes them in as `serve`. The transport is dumb
by design: a reviewer reads one allowlist, in the same file as before.

#### Reply writes: non-blocking, one frame, no queue

The cell is untrusted and may never drain `git-reply`. Once the pipe's 65536
bytes are full (M11) a host write has to do something, and both obvious
choices are defects. A blocking `writeSync` stops the runner's event loop, so
its deadlines and teardown never fire — measured: a 1 MiB blocking write into
the full pipe never returned (M11). A stream write queues replies in host
memory without bound. A cell that spams small requests, each earning an error
frame, reaches one or the other. The discipline is therefore specified, not
left to the builder:

- `git-reply` is opened `O_RDWR | O_NONBLOCK`. `git-request` is unchanged:
  `O_RDWR`, read through a stream.
- A reply is written with `writeSync` from an offset, repeatedly while the
  call makes progress. **A short write is normal, not an error:** a 256 KiB
  write into 16384 free bytes returns 16384 (M12), and a legitimate reply can
  be far larger than the pipe, because the broker already caps a `git` stdout
  at 4 MiB (`run-builder-host.mjs:298`). A frame is never torn; the remainder
  resumes from its offset.
- On `EAGAIN`, or a write returning zero, the unwritten remainder is kept and
  **the host pauses the request stream** until it is delivered, resuming the
  stream only then. Delivery is retried from a `setTimeout` that is
  `unref`ed — never from a blocking write, and never from an asynchronous
  `fs.write`, whose pending threadpool request is itself a live handle that
  would keep the runner from exiting.
- **The bound is one reply frame**, at most the 4 MiB stdout cap. The host
  reads no request while a remainder is pending, so it can never hold a
  second, and nothing is queued. A cell that floods requests only fills
  `git-request` — a kernel buffer, not host memory — and its own writes block
  or are refused there, which is the correct backpressure and the cell's own
  problem. No reply is dropped, no run is ended and no new deadline is added:
  the stall surfaces to the cell as its own client deadline, exactly as a
  crashed client already does.
- `close()` discards the pending remainder, clears the retry timer and closes
  both handles. Measured on both paths — drained and never drained — the host
  process then exits `0` (M13).

This is the one place the transport makes a policy-shaped choice, and it is a
containment choice, not a Git one: it buys bounded host memory and a live
event loop at the price of a reply a non-draining cell was never going to
read. Say so in the code.

Framing is the new untrusted input and is bounded here: a frame over 128 KiB
(the cap the socket path already used), a frame that is not JSON, a frame
whose `args` is not an array of strings, or a missing `id` is answered with a
`status: 2` error frame and never reaches `serve`. A request that is never
terminated by a newline is discarded at the cap; it cannot grow the host's
buffer without limit.

### The cell's `git`

`scripts/git-cell-client.mjs` replaces the inline socket client. It is copied
into `/tools/git` exactly as `probe-builder-runtime.mjs` is already copied
into `/tools`, keeps mode 0555 in the read-only `/tools` bind, and uses no
`node:net`. It resolves its control directory from
`process.env.BISELLIUM_GIT_CONTROL ?? "/control"`; the variable is never set
inside the cell, so the probe's exact 18-name environment allowlist is
unchanged. A cell that sets it for its own children only redirects its own
`git` at its own fake broker and loses Git entirely — `/usr/bin/git` stays
bound to `/dev/null`. It cannot reach the host that way, and the host never
reads anything the cell wrote outside the request pipe.

Each call: take a mutex, write one `{ id, args }` frame to `git-request`,
read reply frames from `git-reply` until one carries its own `id` or a
deadline passes, then release. Synchronous `writeSync`/`readSync` (M7, M9) —
the client is a short-lived process with no event loop to keep alive. The
mutex is an atomic `mkdirSync` in the cell's private `/tmp`, the same
primitive the runner already uses for the producer lease, with a bounded
spin and a deadline so a crashed client cannot wedge the cell forever.

**The mutex and the `id` are cell-side correctness, not host security.** A
builder that breaks its own mutex, drains the reply pipe or forges reply
frames confuses only its own processes: the host never reads the reply pipe
and never acts on anything but an allowlisted request. State this in the
code, so a later reader does not mistake it for a trust boundary.

### What does not change

The `/control` directory keeps its existing read-only bind — measured
sufficient: the cell cannot unlink, rename, chmod or plant there (M10), and
a read-only mount still permits opening a FIFO, because the kernel's
read-only check covers regular files, directories and symlinks only. Raw
`.git` stays read-only. The probe's `bisellium-probe-index` scratch index
still lives in `runtime/probe`, which is never bound into the cell. Export
validation, compare-and-swap publication, red replay, the pinned-master
producer gate, the receipt schema and review admission are untouched.

Teardown gains one step: `close()` the channel where `broker.close()` is
called today, including in `teardownAll()` and the signal handlers. The pipes
live under `runtime/control`, so the existing `rmSync(runtime)` already
removes them; nothing new to delete.

### Replay-safe reds

Every red below is recorded and replayed under confinement, so each one must
satisfy the producer replay's filter in `scripts/run-builder-host.mjs`:

- No whitespace inside any single command argument; select with `--grep` and
  no `^` anchor. Give each row a unique whitespace-free token (`W-132-b1` …
  `W-132-b4`) and grep that.
- The replay rejects output matching
  `ERR_MODULE_NOT_FOUND|SyntaxError:|command not found|ENOENT|not permitted|permission denied|sandbox`.
  **No test title, assertion message or captured output in a red may contain
  the word `sandbox`, or a child's stderr.** Assert on a small derived value
  with a fixed message; never interpolate a child's output into an assertion
  message on a red row.
- Each red is assertion-level at a clean, committed, test-only pre-change
  commit on `opus/W-132`, one log per behaviour, `studio/ci/reds/W-132/01..04.log`.

## Behaviours to test

1. **The live rows are not gated on a socket.** `run.test.ts` drops
   `socketUsable`; `liveSkip` is false whenever `bwrap` is usable, and all
   eleven W-125 live rows execute rather than skip under this sandbox. Assert
   the gate's own value and that the suite reports zero skipped live rows.
   **Genuine red:** today `liveSkip` is the socket refusal string, so the
   assertion fails. Compare a sanitised token (for example `gated` versus
   `ungated`), never the string itself — it contains a word the replay filter
   rejects.

2. **No socket primitive survives, and the channel is a host-created pipe
   pair the cell cannot subvert.** A source invariant over the three owned
   scripts: no `node:net`, no `createServer`, no `createConnection`, no
   `.sock` name. A live row then asserts, from inside the cell, that
   `/control` lists exactly the host-created names, that each is a FIFO, and
   that `unlink`, `rename`, `chmod` and planting a symlink there all fail.
   **Genuine red:** the invariant fails today on `run-builder-host.mjs`.
   Report the matched token names, not the matching source lines.

3. **A `git` call reaches the host broker from any process depth.** Drive the
   committed cell client from a grandchild with no inherited fd
   (node → shell → client, as a real agent shells out) against a host channel
   created by `openCellChannel`, and assert an allowlisted verb is served and
   a denied verb is refused with the broker's message. One live row then
   proves the same depth inside a real dispatch: the builder command shells
   out to commit, and the exported commit is the evidence. **Genuine red:**
   `scripts/git-cell-client.mjs` does not exist, so the row's first assertion
   — that the runner installs a standalone cell client — fails. Assert its
   absence explicitly; do not let a module load or `ENOENT` stand in for it.

4. **A hostile cell cannot make the host misbehave through the request
   pipe.** Drive `openCellChannel` directly with an oversize frame, a
   non-JSON frame, `args` that is not an array of strings, a frame with no
   `id`, interleaved frames from two writers, and a forged reply written into
   the reply pipe. Assert the host answers each with an error frame, calls
   `serve` only for well-formed allowlisted requests, bounds its buffer at
   128 KiB, writes only into the pipe it created, and that `close()` lets the
   process exit. **Genuine red:** `scripts/git-broker.mjs` does not exist, so
   the row's first assertion — that the transport module is importable and
   exports `openCellChannel` — fails. Assert its absence explicitly.

   **4a — a deaf, flooding cell.** Same row, same red log: 4a is a sub-row of
   behaviour 4, not a fifth behaviour, because the absent module is already
   its red. Add a `deaf` scenario to the row's cell script: it opens
   `git-reply` read-write and never reads it, opens `git-request`
   `O_WRONLY | O_NONBLOCK`, writes well-formed `status` frames in a loop until
   a write throws `EAGAIN` or a 5000-frame cap is reached, reports the count
   it got in, and exits without reading one reply. Non-blocking is what makes
   the scenario terminate: the cell is refused rather than parked, which is
   itself the backpressure the discipline claims. Then assert, in this order:

   - **The host is alive and its event loop is free.** After the flood, the
     harness's `sample` command on stdin is still answered. This is the
     assertion that fails if a host reply write blocks.
   - **The host stopped reading requests rather than queueing replies.**
     `host.served().length` is strictly less than the frames the cell got in,
     and is unchanged across two samples taken a short wait apart.
   - **Memory is bounded.** The gc'd retained growth over a baseline sampled
     just before the flood stays under the 8 MiB bound the row already uses —
     above one 4 MiB frame, far below a queued flood. No new bound is
     introduced.
   - **The stall is a pause, not a death.** The test itself drains
     `git-reply`; afterwards a fresh well-formed sentinel is answered with its
     own `id`, and `host.served()` grows again.
   - **Teardown is still live with a remainder pending.** Run `deaf` once
     more, so the host is holding an undelivered frame, and let the row's
     existing `close()` assertion run from there: the host process still
     exits `{code: 0, signal: null}`.

   Place 4a after the existing `flood` and `resume` scenarios and before
   `close`. Fixed assertion messages only, as everywhere in this row: the
   frame count and the served count are small derived numbers, and no cell
   output is interpolated into a message.

Each numbered behaviour has one selectable assertion-level row and its own red
log. Behaviours 3 and 4 both begin with an existence assertion on a declared
new module; the substance of each row is what follows it, and the two reds are
distinct files with distinct assertions. Do not rename or weaken an existing
W-125 row to make it pass; the eleven live rows keep every assertion they have
today, apart from `/control`'s contents in behaviour 2.

## Acceptance

- Four replayable reds at clean committed pre-change identities, then the four
  focused rows and the full `run.test.ts` green, plus lint, format, typecheck
  and both officina checks at the final clean tree.
- The eleven W-125 live rows **run, not skip,** inside this sandbox, and the
  suite output shows no live row skipped. A skipped live row is a failure.
- A real `bisellium run` dispatch completes confined: the cell's `git` works
  through the pipes, the commit exports, the red replays reproduce their
  assertion failures, the producer gate runs, and teardown removes the runtime
  and the lease. The runner process exits on its own; a hang is a failure.
- **W-132's own receipt comes from W-132's own runner, in the sandbox.** The
  fix cannot be built inside the W-125 cell, because the pre-fix runner cannot
  start there; the build happens the legacy way on `opus/W-132`, and the
  receipt is minted afterwards by a `bisellium run` for W-132 executed from a
  checkout that already carries the fix. That run replays all four reds and
  runs the producer gate before it writes `run_receipt`.
- Evidence retains the actual commands and outputs, names the pinned master
  tooling commit, and distinguishes builder from producer. Nothing is
  backfilled.
- Changes stay inside Files owned. The containment census is not weakened.
  D-014's censor supplies the single independent review and judges this as a
  change to a trust boundary, with W-125's confinement obligations and D-035
  as the standard.

## Out of scope

- Any change to the broker's Git allowlist, `GIT_LOCKDOWN`, the environment
  allowlist, the clone/export/publication rules, red semantics, the producer
  gate, the receipt schema, the `builder_runtime` marker or review admission.
  Only the transport under them moves.
- Weakening the outer confinement, the read-only `/control` or `/tools` binds,
  the read-only raw `.git`, or the default-deny egress to make something pass.
- Reintroducing any socket, including TCP loopback, as the control channel —
  loopback is measured to work (M1, M4) and is still refused here: it is a
  listening port in a shared process namespace, where the pipes are not.
- Adding a runtime dependency, a new CLI verb or flag, a new environment name
  visible inside the cell, or a second review gate.
- W-130 and W-110. W-132 lands first, because both are blocked on a receipt
  that no runner can currently mint; W-130 rebases onto it and re-attests its
  reds by replay, exactly as W-125 revision 5 prescribes.
- Historical logs, verdicts, lessons, opera and decisions.
