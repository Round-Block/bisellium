# W-135 — containment setup becomes part of init/adopt: the agent clone, sandbox settings, reviewed folder, restart loop and hook rule are set up per project and verify themselves

## Intent

Problem: bisellium is meant to be plug-and-play: `bisellium init` for a new
project, and adoption of an existing repo. But the safety layer that makes
agent work safe on this machine was built by hand and is tied to this
machine:

- the separate agent clone (`scripts/agent-workspace.sh`, `~/agents/<repo>`,
  a repo-scoped non-admin token via `GH_CONFIG_DIR`);
- the Bash sandbox settings in `.claude/settings.local.json`;
- the owner-only reviewed folder that agents cannot write;
- the restart loop `scripts/cascade-loop.sh` (a restricted claude, its
  settings and state in `<reviewed folder>/.cascade-loop`, and it refuses to
  run from the agent clone);
- the rule that hooks never point at code an agent can write.

A new user would have to rebuild all of it.

Goal: `init` and adopt set up that layer for the target project, with the
project as a parameter, give the same guarantees, and check themselves the
way `scripts/agent-workspace.sh verify --inside` does today.

Link (Patron, 2026-10-04): W-136 step 1 adds a per-project registry that
lives outside every repo, is owner-only, and holds no tokens. In W-136,
`agent-workspace.sh setup` writes it. Once this opus moves setup into
init/adopt, those write it instead, with the same fields and the same
owner-only rule.
