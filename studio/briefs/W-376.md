## Intent

The repeat S1 class `tests×one-sided-bound-assertion` (D-076 D, high; L-066, L-115): a test of an output the brief spells out (a hold reason, a message, a `why:` line) asserts one end of it, so a wrong other end ships. Its live case is W-328 review 1 (`ci/W-328-review-1.log` #1, S1): its brief's lines 27 and 47 spelled the uncommitted log's hold reason, its row asserted `new RegExp(`^ci/${OPUS}-review-1\\.log is not committed …`)` with no end anchor, and the build appended `; commit it, then rerun` past the promised ending. W-310 review 1 #3 (S1, the same class) is a `guard:` status line whose rows assert `/^guard: live/m` and the like.

The cause fix is a check rule over test files (form (a)): `test.one_sided`, block, beside W-121's `test.sleep` and W-178's `test.rows` in `rules/tests.ts`. With `--repo`, each line of a tracked test file added or changed in the working tree since the merge-base with master is read; a line holding a one-sided assertion of a string is one block finding at `<name>:<line>`, unless it carries a `// one-sided: <reason>` annotation. Two forms are one-sided (behaviour 1, behaviour 2):

- an `assert.match` whose pattern (a regex literal, or `new RegExp` of a string or template literal) is anchored at one end only: it opens with `^` and has no closing `$`, or the reverse;
- an `assert.ok(` or `assert(` whose first argument calls `startsWith` or `endsWith`.

Why this and not the other forms. A brief-admission rule (b) reads the brief's words: W-328's brief already spelled the whole reason, so such a rule admits it and the test still asserts a prefix. A prompt line (c, `studio/prompts/`, code-owned) is prose the reviewer already applies; review is where the class was found, after the build. The check rule reads the test line itself and fails mechanically before review: `bisellium ci` runs `npm run -s check -- studio --repo .`, so the opus branch's gates, which next orders before the build review, block on it, and the pull request's CI does too. It reads only the lines a branch adds, so the 111 one-sided assertions on master (`tree-census.out`) stay as they are and master gains no finding.

What it would have caught (`would-catch.out`, the prototype's rule on each reviewed head against its merge-base): W-328 review 1's head, `next-review.test.ts:1393` (finding #1) and `:1383` (the shared why's end-only pattern); W-310 review 1's head, six `guard:` prefixes in `guard.test.ts`. It would not have caught W-317 or W-330 review 1 (a numeric bound that collapses past `Number.MAX_SAFE_INTEGER`, not a string assertion), nor the class's coverage findings (W-179 spec 8, W-275, W-330 review 2, W-339, W-340, W-351, W-354: a case or a field never exercised), nor an unanchored pattern or `includes` (the includes form): the rule cannot tell an output the brief spells out from a fragment the test means to find, and most `assert.match` lines added over master's last 40 feature merges are unanchored by intent. Those stay the reviews'.

Its cost (`feats-census.out`): over master's last 40 feature merges, 86 lines would have been flagged in 20 merges; 37 of them are W-179's split of `next.test.ts` (a moved line is an added line), so about one line per opus outside a split, each rewritten to the whole string or annotated.

Threat model: mistakes, not adversaries (D-045).

The forms `oneSidedSites` recognises, one per line (each a grammar line of Input domain row 6):

- an `assert.match` site: `assert`, `.`, `match`, `(`, spaces allowed between, with no word character, `$` or `.` before `assert`, found in the string-blanked code (so never inside a string, a template or a comment) — pinned by `W-376-b1` "spaces around the call" and pinned by `W-376-b1` "inside a string" and pinned by `W-376-b1` "inside a comment" and pinned by `W-376-b1` "a member assert is not read, a limit"

- one end only: the pattern's source starts with `^` and does not end with a `$` that follows no backslash, or ends with such a `$` and does not start with `^`; flags such as `m` change nothing — pinned by `W-376-b1` "a regex literal anchored at its end" and pinned by `W-376-b1` "a new RegExp string anchored at its end" and pinned by `W-376-b1` "a line prefix under the m flag" and pinned by `W-376-b1` "an escaped dollar is no end anchor" and pinned by `W-376-b1` "a dollar in a character class is no end anchor" and pinned by `W-376-b1` "a template ending in a substitution has no end anchor" and pinned by `W-376-b1` "anchored at both ends" and pinned by `W-376-b1` "both ends under the m flag" and pinned by `W-376-b1` "a new RegExp anchored at both ends"

- one site per line, the `assert.match` form read first — pinned by `W-376-b1` "a second assertion on the line" and pinned by `W-376-b2` "one site per line"

Every other form is a limit: an unanchored pattern and `includes` (the includes form), a pattern held in a name, an `assert.match` call whose pattern is on a later line, `assert.doesNotMatch`, a member assert (`t.assert.match`), `assert.equal(x.startsWith(…), true)` and any assertion other than the three named, a Playwright `expect(…)` matcher, a `$` after two backslashes (read as escaped), a regex literal holding a quote or an unbalanced bracket in the first argument (W-121's lexical pass, `lex`), and an annotation written any other way.

Promise added-line: with `--repo`, a line of a tracked test file added or changed in the working tree since the merge-base with master that holds a one-sided assertion of the forms above and no annotation is one `test.one_sided` block finding at `<name>:<line>`, and the officina check exits 1 — limit: the rule reads one line's text, so the forms brief:57 names are not judged, and whether an output the brief spells out is asserted whole stays the reviews' (D-085 E); the lexical pass is W-121's `lex`, reused unchanged.

Promise old-lines: a line present at the merge-base is not judged, so master, and a branch that adds no such line, gain no finding — limit: a moved, renamed or split test file's lines are added lines and are judged anew (W-179's split would have flagged 37); an untracked test file is not read, as for `test.sleep`; a checkout with no master ref is held by `test.rows`' block alone.

Limits, stated:

- Only added and changed lines are judged; the 111 one-sided assertions on master (`tree-census.out`) are not, and a later edit of such a line judges it then.
- The rule does not read the brief, so an assertion of an output the brief never spells out is judged the same; the annotation is that case's way through, and its reason is read for length only.
- An in-flight branch that merges master after this opus lands is judged on its own added lines: `opus/W-360`, `opus/W-366` and `opus/W-373` add none (`inflight-census.out`).
- Unchanged code the promises lean on is a stated limit, not a guarantee (D-076 E): `lex` and its string blanking, `isTestPath`, `registeredPaths`, `resolveTestBase`, `readCandidate`, `gitOut`, `reasonOf`, `checkStudio`'s call of `checkTests` and the check CLI's printing and exit.

## Behaviours to test

1. **An added `assert.match` whose pattern is anchored at one end only is a `test.one_sided` block, unless annotated.** In `W-376-b1` (`rules/tests.test.ts`, W-178's `branched` repositories and `checkStudio`): a branch that adds `assert.match(why, /^ready/, …)` at line 3 of a test file whose line 2 already held a prefix assertion gives exactly one block, `a.test.ts:3`, its whole message asserted. Only listed lines are judged. The annotation on the line or the line above waives a site; a short or two-word reason, another prefix, no colon, two lines above, after code on the line above, or inside a string does not.
