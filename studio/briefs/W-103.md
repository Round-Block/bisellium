# W-103 — Investigate bounded multi-project source lookup

## Intent

Build a read-only, executable Node.js-stdlib research harness inside Bisellium.
Run the existing 15 exploratory cases through two explicitly distinct retrieval
paths: deterministic repository search and curated routes from the captured
dataset. The experiment measures source discovery and retrieval mechanics; it
does not score answer quality.

## Files owned

- `docs/research/bisellium-maps-harness.mjs`
- `docs/research/bisellium-maps-harness.test.mjs`

`docs/research/bisellium-maps-exploratory-cases.json` is an unchanged input.
Resulting research report outputs may be captured under
`docs/research/W-103/` (bindings, mode-result JSON and a concise report).
These are experiment artifacts, not additional implementation files. No new
dependencies, helper modules, production integration or policy rewrites.

## Interfaces

The executable accepts the dataset, an explicit JSON binding, retrieval mode
(`search` or `route`), and integer budgets. It emits deterministic JSON only.
Bindings map each project ID to repositories with unique, stable, explicitly
supplied repository IDs, roots and a fixed `corpusFiles` list of relative file
paths. Search visits every repository bound to the case's project, in repository
ID order; paths use code-unit lexical order, without locale dependence.
Never infer repository identity from root basename, matching paths or ordering.
Route bindings map each `(project ID, case ID, reference index)` explicitly to
exactly one repository ID within that project. Reject duplicate, ambiguous or
unmapped entries; there is no implicit single-root shortcut or search fallback.

Search retrieval receives only `{id, project, question}` from each case,
plus corpus bindings and budgets. It cannot inspect curated references,
captured hashes, expected outcomes, excerpts, measurements, checkout snapshots
or route results. Corpus manifests are fixed independently of case answers and
references. Tokenize the question into unique lowercase ASCII alphanumeric
tokens of length at least three; select lines containing any token, in path
then line-number order, merging adjacent selected lines. Route reads current
source for the explicitly bound references; captured excerpts are never source.
Captured-hash comparisons belong only to route results.

The searchable corpus is an explicit manifest, never a recursive discovery
scan. Reject absolute paths (including Windows forms), empty/dot/traversal
components and backslashes. Accept only regular UTF-8 text files with extensions
`.ts`, `.tsx`, `.js`, `.mjs`, `.cjs`, `.json`, `.md`, `.toml`, `.yaml`, `.yml`,
`.txt`, `.py`, `.rs`, `.go`, `.cs`, `.gd`, `.sh`, `.css`, `.html`, `.svelte`,
`.vue`; reject invalid UTF-8 or NUL bytes as binary. Exclude directory components
`.git`, `node_modules`, `vendor`, `assets`, `.worktrees`, `worktrees`, `dist`,
`build`, `coverage`, `research`, `briefs`, `reports`, `test`, `tests`, `__tests__`,
and filenames containing `.test.` or `.spec.`. Additionally exclude the dataset,
binding input, W-103 brief, harness, harness test, report destinations and all
generated research artifacts (including copies designated by the binding's
exclusion inventory). Apply exclusions to lexical and canonical paths so
symlink aliases cannot reintroduce oracle artifacts. The static cooperative
corpus contract requires its manifest/exclusion inventory to omit any other
copies of oracle data. Route may access curated briefs/research references,
subject to the same containment, regular-file and resource limits; its content
never enters search. No scan of asset, dependency or worktree trees is permitted.

Bounds are per case/repository and independent of excerpt/output caps. Defaults
and hard maxima are: 128 distinct directories visited, 512 candidate files
examined, 128 source-file opens, 8 MiB actual source bytes read, and 256 KiB per
source file. A visit means checking/resolving the root or a unique lexical parent
directory on a manifest/reference path; count every such directory before its
operation. A candidate is counted before metadata lookup; count opens before
opening, and cap each read by the remaining byte allowance. Oversized files are
skipped by metadata, never partially hashed or called complete. Count failed
attempts; no hidden rereads for hashing, excerpts or encoding checks. Hash the
fully read bytes once. Do not enumerate directories: check only explicit paths
and their parents, in stable order. Stop before an operation would exceed a
limit, recording the exact limit and unexamined candidates as incomplete.
Lower integer budgets are allowed; invalid or above-maximum values fail before
source access. Each JSON input is capped at 1 MiB before parsing; permit at most
15 cases, 16 projects, 8 repositories per project, 512 corpus paths per repository,
128 references per case, and 1,024 characters/32 components per relative path.

Output defaults/hard maxima per case are 16 excerpt-bearing files and 16,384
excerpt characters, counted separately from scan work. Continue the bounded
scan even after excerpts fill, reporting omitted excerpts. Emit compact metadata
and aggregate rejection counts, with at most 32 failure samples per repository.
Never hide scan exhaustion behind excerpt truncation. Include configured limits,
actual counters, output truncation and coverage status for every repository.
Results retain project ID and binding-supplied repository ID, question, exact
relative paths/ranges, observed SHA-256 and identity, plus explicit failures.
Any unavailable repository remains visible while others stay usable.

Canonicalize each root once. Before opening a candidate, resolve its parents
and final path with `realpath`; require each to equal the canonical root or
start with root plus separator. Reject dangling links, escapes through any
intermediate/final symlink, and non-regular files. Cache only within a run.
The corpus is static and cooperative during a run: hostile concurrent mutation
and descriptor-based race resistance are explicitly outside this experiment.
The harness executes no source, makes no network calls and writes nothing to
bound target repositories. Tests use temporary fixtures; report capture is
external stdout redirection into the authorized research output directory.

Git observation uses argument arrays, no shell, with cwd at the canonical root
and common flags `--no-optional-locks -c core.fsmonitor=false
-c core.hooksPath=/dev/null -c core.untrackedCache=false`. Set
`GIT_OPTIONAL_LOCKS=0`, `GIT_TERMINAL_PROMPT=0`, `GIT_CONFIG_NOSYSTEM=1` and
`GIT_CONFIG_GLOBAL=/dev/null`; discard inherited `GIT_*` overrides first.
The complete command allowlist is `rev-parse --verify HEAD`,
`symbolic-ref --short -q HEAD`, and `status --porcelain=v1 -z
--untracked-files=no --ignore-submodules=all -- <literal selected paths>`.
Encode pathspecs as `:(literal)<repo-relative-path>`; omit status when no files
were selected, and never permit an empty status scope. At most three Git calls
per repository/case, each with a 2-second timeout, 64 KiB stdout and 16 KiB stderr
limits; terminate on overflow/timeout and discard partial identity fields.
No fetch, checkout, reset, clean, update-index, config writes or fallback Git
commands. Failure yields partial/unknown identity, never a broader query.
Dirty state covers only selected tracked paths; it is not a whole-tree clean
claim. Current content hashes remain authoritative for retrieved bytes.

## Behaviours to test

1. **Scoped identity and retrieval:** duplicate local ids and cross-project
   requests retain their explicit project/repository attribution; search and
   curated-route modes are deterministic and never fall back across bindings;
   multi-root projects search every bound repository, and unmapped/ambiguous
   route references fail explicitly.
2. **Honest degradation:** an unavailable repository, missing/moved reference,
   non-Git checkout, or unsupported binding yields an explicit partial/unknown
   result while successful repositories remain usable. Assert Git allowlist,
   literal scopes, environment controls, timeout/output bounds and no fallback.
3. **Freshness and provenance:** a content change causes a captured-hash
   mismatch and reports the newly observed file hash and dirty/content scope;
   HEAD alone never describes changed working-tree content.
4. **Containment and budgets:** traversal, absolute paths, and symlinks escaping
   a selected root are rejected without reading them; file and character limits
   are enforced with stable truncation and incomplete-coverage disclosure.
   Exercise each scan budget independently, binary/oversized inputs and parent
   symlink escapes. Assert excluded oracle/generated artifacts cannot match,
   including via symlink aliases; no directory enumeration is used.
5. **Reproducible metrics:** repeated runs over fixed fixtures produce identical
   ordered retrieval results and instrumented counts, while setup/maintenance
   measures remain separate from repeated lookup cost. Poison references,
   captured hashes/excerpts, expected outcomes, measurements, checkout snapshots
   and route results and assert byte-identical search output and metrics.

## Acceptance

- Record one assertion-level red per behaviour before its fix; no two
  behaviours share red evidence.
- `node --test docs/research/bisellium-maps-harness.test.mjs` passes.
- Both modes execute all 15 existing cases with explicit bindings and bounded
  output; the report labels them exploratory, previously inspected, and not a
  held-out evaluation.
- Publish the effective corpus manifest, exclusions, limits, deterministic
  ordering, incomplete coverage and counters with the resulting research report.
  Baseline comparison means deterministic lexical retrieval versus curated
  retrieval only. No model answers are generated or scored; no answer-quality
  or usage-savings conclusions follow. Input preparation and maintenance costs
  stay separate; timing, if captured externally, is not a deterministic metric.
- `npm run -s typecheck` and `npm test` pass as proportional regression checks.

## Out of scope

Production CLI or schema changes; changes to Snapshot or the epoch0 adapter;
project registry persistence; workflow ingestion, orchestration, schedules,
UI, embeddings, or game adapters; target-project writes; network calls;
independent answer scoring; semantic-correctness, billed-token, subscription,
or usage-savings claims.
