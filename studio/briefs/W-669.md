## Intent

The Claude sandbox bind-mounts each `.git/worktrees/<name>/commondir` and `config.worktree` read-only into every sandboxed command, so a sandboxed `git worktree remove` deletes the checkout and the admin directory's other files (its `gitdir` among them), then fails `Device or resource busy` on the admin directory itself. `next`'s cleanup perform (`cleanup`, master integrate.ts:1248-1251) stops at that failure: the local and remote-tracking branches are kept, `next` names cleanup again, and done waits on the Patron's `rm` outside the sandbox (gap 80, W-661; gap 60, W-610). W-227 meant the held directory to be named and the branches still deleted; that held only for the `.worktrees/<id>` leftover, not for the admin directory.

After this opus, a failed `git worktree remove` whose result is the sandbox's (the checkout truly absent, git's listing succeeding and listing no worktree there, and the admin directory the checkout's `.git` file named still a real folder) is not a hold: cleanup prints a `worktree: ran (…)` line naming the held directory and git's refusal, deletes the local branch and the remote branch as before, and `next` names done. Every other failed removal holds, with the line and exit code it has today. A held admin directory is a named note, never a wait on the Patron.

The unsandboxed prune is the one already installed: W-369's sync (`scripts/agent-workspace.sh sync`, run from the installed guard's copy in the Patron's clone, never the agent clone's) runs `git worktree prune -v` outside the sandbox before every launch (`bisellium launch`, launch.ts:409), at every SessionStart (`hook-event sync`) and, when `<git common dir>/bisellium/sync` exists, after the Bash call that wrote it returns (the PostToolUse hook). Git prunes an admin directory with no `gitdir` file, so the held one goes at the first of those. Cleanup now writes that request file when it names a held directory, so the prune follows in the same session. Trigger chosen: the existing request-file hook, because it adds no host job, no new unsandboxed code and no new install, and it fires when the cleanup's own call returns; the launch and SessionStart syncs are the fallbacks for a run no Claude Code hook sees. No Patron call is needed for it: the hook commands and the sync are the Patron's already (W-369, W-543). A dedicated host timer would be a new architecture choice, and this opus makes none.

Threat model: mistakes, not adversaries (D-045). The removal is never `--force`; git deletes a checkout only after its own clean check, so a checkout with changes is never removed and its branch is never deleted.

## Out of scope

- A new host job (a timer, a launch step or a Patron verb) for the prune: the installed W-369 sync already runs it unsandboxed at launch, at SessionStart and on request.
- Changing `scripts/agent-workspace.sh`, the hook commands, `bisellium prune` or W-227's `.worktrees/<id>` leftover handling.
- Removing the empty stubs a live session's sandbox remakes: they are unlisted and read by nothing, and the next sync after that session clears them.
- `--force` on any removal.
- Architecture: unchanged — no package edge, seam between packages, lifecycle transition or serve route changes.
