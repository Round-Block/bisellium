# W-033 — officina bookkeeping provenance: one writer per opus record

Spec of record, signed by the architect. The decision behind it is
**D-021**. Read that first. This brief builds its enforcement and nothing
else.

## Intent

Right now every copy of `opera/<id>.md` can be written from any checkout,
and nothing says which copy is authoritative. This caused three blocking
findings in one day: W-026 round 5, W-030 round 2 and W-031 round 1. The
orchestrator has also run a hand reconcile recipe about six times, and
W-034's defect 2 is the same class. The original question, and the three
instances in detail, are in this file's git history (`git log -p --
studio/briefs/W-033.md`).

D-021 answers it. **While `opus/<id>` exists, only a checkout on
`opus/<id>` writes `opera/<id>.md`. Otherwise the trunk side writes it. An
opus branch never writes another opus's record.** This opus makes the CLI
refuse every write that breaks that rule, before anything is written.

Every command that writes an opus record already routes through
`openStudio`/`safeItemPath` (`verify` resolves its own path). So one helper,
called at the same point in each of those commands, covers the whole class.
The W-026 lesson applies: the class gets enumerated up front, not one
instance per review round.

## The ownership function

Add one helper to `packages/commands/src/writes.ts`:

```ts
export function recordOwnerRefusal(studioRoot: string, opusId: string): string | undefined
```

It returns `undefined` to allow the write, or a refusal message. It checks
the following in order:

1. `studioRoot` is not inside a git work tree, or `opera/<id>.md` is not
   tracked there (`git ls-files --error-unmatch`) → **allow**. Git refs
   cannot own an untracked file. This keeps every temp-copy fixture, and
   every officina that lives outside its repo, exactly as it is today.
2. HEAD of **the checkout containing `studioRoot`** (`git -C studioRoot
   symbolic-ref -q HEAD`) is `refs/heads/opus/<id>` → **allow**.
3. That HEAD is `refs/heads/opus/<other>` → **refuse**. An opus branch
   carries only its own record.
4. `refs/heads/opus/<id>` exists (`git show-ref --verify --quiet`) →
   **refuse**. This also covers a detached HEAD at the branch's own tip.
5. Otherwise → **allow**. This is a trunk-side write with no branch cut yet.

Only local refs count. Remote-tracking refs do not. Linked worktrees share
refs, so a reviewer's scratch worktree sees the branch.

The git calls use `execFileSync` with `GIT_TIMEOUT_MS`, the same way
`lifecycle.ts` already does. If git is missing or fails in steps 2–4, the
helper **refuses** and says so. It never silently allows, because a guard
that fails open is how W-026 round 5 happened. Step 1's "not a repo" is
the one place where allowing is correct.

The refusal names the record, the owning branch, what this checkout is on
(the branch short name, or `detached HEAD at <sha7>`), D-021 and the
remedy. For example:

```
W-030: opera/W-030.md is owned by opus/W-030 while that branch exists (D-021);
this checkout is on master — run it in the worktree that has opus/W-030 checked
out (git worktree list), or delete opus/W-030 if it has already merged
```

For step 3, the message says that `opus/<other>` carries only `<other>`'s
record.

**One definition of the branch name.** Move `opusBranchName` from
`packages/cli/src/branch.ts` into `writes.ts` and have `branch.ts` import it
from `@bisellium/commands/writes.js`. Keep the `export` in `branch.ts`
(re-export it) so `branch.test.ts:14` still works. If the guard and `merge`
spelled the prefix differently, the guard would never fire.

## Callers

Each call goes right after the command has resolved and existence-checked
the opus path, and before any read-modify-write, event, timeline append or
gate run. On refusal: `console.error(msg)`, return `{ exitCode: 2 }`
(the same code as the existing state-precondition refusals in these files),
and write nothing.

| command | file | note |
|---|---|---|
| `greenlight` | `writes.ts` | before the rollback snapshot |
| `handoff` | `writes.ts` | |
| `ready` | `lifecycle.ts` | |
| `done` | `lifecycle.ts` | `close` inherits via `executeClose` → `runDone` |
| `review` | `lifecycle.ts` | before the `--evidence` checks, so the refusal names ownership, not a missing file |
| `halt` | `lifecycle.ts` | before the `--decision` lookup |
| `verify` | `verify.ts` | **before the pipeline runs**. `ci --opus` inherits it. |

Not guarded: `red` (it writes `ci/reds/<id>/NN.log`, per-behaviour files
that no trunk-side writer touches), `emit` (`events.jsonl` is gitignored)
and `answer --opus` (it writes the petitio, not the opus).

## Behaviours to test

All fixtures build a **real git repo with the studio committed inside it**,
and the relevant `opus/<id>` branch where one is needed. That means
`git init -b master`, copy `examples/sample-studio` to `<repo>/studio`, then
commit. This is the W-026 blind spot: a studio outside the repo collapses
both copies into one file, and the bug disappears from the test. Worktrees
come from `git worktree add`. A test never switches a branch by rewriting
files.

1. **`done` from a trunk checkout is refused while `opus/<id>` exists**
   (W-034 defect 2). The repo is on `master`, `opus/<id>` exists, and the
   record is in `building` with passing gates, so without the guard `done`
   would succeed. `runDone` exits 2. The message contains `opus/<id>` and
   `D-021`. The record's bytes and the events log's bytes are unchanged
   (the log's absence counts as unchanged), and `git status --porcelain` is
   empty.
2. **`review` from a detached worktree at the branch tip is refused**
   (W-030/W-031). Take a `git worktree add --detach <p> opus/<id>` with the
   evidence file present under `<p>/studio/ci/`. `runReview --pass` exits
   2 with the ownership message and writes nothing. It must be refused even
   though HEAD's commit **equals** the branch tip.
3. **Every other record writer refuses the same way from the trunk.** One
   table: `ready` (record `greenlit`), `halt` (record `building`, a real
   `--decision`), `handoff` and `greenlight` (record `backlog`). Each exits
   2 with the ownership message, the record is byte-identical and no event
   is appended. Pick every fixture state so the command **would succeed**
   without the guard, so the red fails on the missing refusal and not on
   some other precondition.
4. **`verify` refuses before running anything.** Pass a stub
   `MergePipeline` whose `run` records that it was called. From the trunk
   with `opus/<id>` present: exit 2, the stub was never called, no new
   file under `studio/ci/`, and the record is byte-identical.
5. **An opus branch cannot write another opus's record.** From a checkout
   on `opus/<Y>`, where no `opus/<X>` exists, `runHandoff --opus <X>`
   exits 2, the message names `opus/<Y>`, and `<X>`'s record is unchanged.
6. **Ownership is decided by the checkout that holds `--studio`, not by
   `process.cwd()`.** With `process.cwd()` in the trunk checkout, `runDone`
   with `--studio <worktree-on-opus/<id>>/studio` exits 0. The worktree's
   record now reads `state: done`, and the trunk checkout's record is
   byte-identical. The mirror case, cwd inside that worktree and `--studio`
   naming the trunk checkout's studio, exits 2.
7. **An untracked record is left alone.** In a repo where `opus/<id>`
   exists and HEAD is `master`, put the studio in a directory the repo
   ignores (add it to `.gitignore` and commit), so its record is untracked.
   `runDone` there exits 0 and writes `state: done`.

The existing suite must pass unchanged, and that is part of the
acceptance: every current lifecycle/writes/close/ci test uses a studio that
is outside any repo, or inside one with no `opus/*` branch. If an existing
test needs editing, stop and report. Do not edit it.

## Out of scope

- **A reconcile command, or any porcelain over rebase conflicts.** D-016
  still applies, and D-021 has removed the recipe it would have automated.
- **Moving bookkeeping out of the work tree** (a separate ref, or front
  matter projected from the event log). That is D-021's `kill_when`
  successor.
- **A check rule.** A tree snapshot cannot see which ref a write landed on
  (D-021, Enforcement).
- **A hook against hand edits of `opera/`**, and sweep scripts that write
  front matter. Both are out-of-band writers. Their residual shows up as a
  rebase conflict, and D-021 fixes how that conflict is resolved.
- **Remote-tracking refs** (`origin/opus/<id>`), and deleting stale merged
  opus branches (`prune`'s territory).
- **`wip.cap`, `serve` or the board reading live opus branches.** The trunk
  shows in-flight work as `greenlit` (D-021, Consequence). UI is the
  Patron's call.
- **`merge`'s reads** (W-026), `verify`'s raw `join` for the opus path
  (W-047), and the per-worktree `events.jsonl` that dies with its
  worktree.
- **W-034 defect 1** (waived gates in `done`).
