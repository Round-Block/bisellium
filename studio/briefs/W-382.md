## Intent

A `kind: ui` opus needs, at done, a Patron ruling whose `certifies` is the served-e2e gate's tree (`opus-model.ts` `ruling`, read by `validateUiPolicy` at phase `done`). The Patron rules on the branch's screens before the PR opens (W-377), but the merge queue squashes the branch onto a moved master, and the done step re-runs `verify` on master, so the served tree is master's, never the branch's. The ruled tree is not even on master's history: the squash commit's SOURCE tree differs from the branch head's in all three past cases (`treeof.out`: W-345's ruled 5e60e8c2 vs merge 6908987d, W-406's b5cef85e vs 1eafe007, W-463's a4e8a7b0 vs 381ca0f3). So every ui opus has needed a second ruling on the same screens (D-113, D-116, D-145, D-146).

**When a ruling carries.** A ruling given on tree B counts at done on master's tree M when the served UI is the same at both: the paths the screens are built from and captured against have the same bytes and modes. Those paths are `SERVED_UI_PATHS`: `apps` (the web app, its served suite and its server), `examples/sample-studio` (the fixture officina every served spec copies; outside the SOURCE tree, so it moves the served UI and not `tree:`), `package.json` and `package-lock.json` (the bundle's dependencies). A master move that touches only CLI code, docs or officina records carries the ruling, which is the D-113 case ("nothing under `apps/` changed").

**How it is known without the branch.** The branch head is gone after the squash and cleanup, so B's paths cannot be read at done. Instead `verify` records them when it runs: a clean run's served-e2e log gains two header lines, `served-ui: sha256:<hash of git ls-tree -r of SERVED_UI_PATHS at the certified commit>` and `served-at: <the run time, the gate's at>`, written by the pipeline before the blank line that opens the command's output, so the command cannot forge them. Every served-e2e log stays in `ci/` by tree (`ci/<id>-served-e2e-<tree8>.log`) and lands on master with the merge. At done, a ruling on B carries when B's log is B's passing served run naming `served-ui` X, the current run's log names the same X, the ruling's design digest is the current one, and the ruling is dated at or after B's `served-at` and the ui-lead input (the same order today's rule keeps: the ruling follows the capture it rules on).

**What done records.** Nothing new on the record: the carried ruling stays in `ui_rulings`, and the evidence is the ruling and the two logs, all on master, from which `check` recomputes the carry on the done record each time (no stored copy of a fact the logs already hold, lesson class `design×indirection-duplicates-source-of-truth`). `done` prints one line after its done line, `<id>: ui ruling <D> carried from tree:<B> to tree:<M>: served UI sha256:<X> unchanged`, which the done perform relays as `done: …`. A ruling at the served tree is current as before and prints nothing.

Threat model: mistakes, not adversaries (D-045). The ruling's own grammar, the served-e2e gate's policy and `verify` are unchanged.

## Interfaces

**`SERVED_UI_PATHS: readonly string[]`** = `["apps", "examples/sample-studio", "package.json", "package-lock.json"]` and **`servedUiHash(repo: string, ref = "HEAD"): string`** (`@bisellium/shim`): `sha256:` and the hex sha256 of the stdout of `git ls-tree -r --full-tree <ref> -- <SERVED_UI_PATHS>` run in `repo` (mode, type, blob id and path per entry, path-sorted). Throws when git cannot read `ref`.

**`PipelineRunOpts.commandHeaders?: Readonly<Record<string, readonly string[]>>`** (`@bisellium/pipeline`): per probatio id, lines `localPipeline` writes after `exit code: …` and before the blank line; a line not matching `^[a-z][a-z-]*: [\x21-\x7e]+$` is dropped. A gate not named gets today's log.

**`verify`** passes, for the reserved served-e2e gate only and only when the run is clean (`dirty` false) and `servedUiHash(repo, commit)` does not throw, `served-ui: <servedUiHash(repo, commit)>` and `served-at: <now, as the gate's at>`. A dirty run, a throw and every other gate get no header line.

**`uiRulingCarry(root, record, id): { ruling; from; to; servedUi } | undefined`** (`@bisellium/commands/opus-model.js`): for a `kind: ui` record, undefined when any `ui_rulings` entry is current at the served tree (today's rule), else the first entry that carries, else undefined.
