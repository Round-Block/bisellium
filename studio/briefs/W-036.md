# W-036 — CI parity: the suite passes on a fresh public runner

## Intent

The repo went public on 2026-09-20 and GitHub Actions stopped failing on
billing. `.github/workflows/ci.yml` has executed fifteen times since. The
`master_protection` ruleset names the `build` job as a required check, so
until that job can reach a green, no PR can merge through the intended
flow and every red X is again a red X that means nothing.

The diagnosis against the real logs (run ids below) is narrower than the
brief that commissioned this opus assumed, and the difference matters:

**`npm test` has no runner delta.** Six runs — 35491232821, 35491318422,
35491437774, 35491595745, 35491610207, 35491737170 — ran `npm test` to
completion on a fresh `ubuntu-24.04` runner and recorded
`Run npm test: success`. In the nine later runs the step's conclusion is
`skipped`, not `failure`: `format:check` exited first under `bash -e {0}`
and GitHub skipped the rest of the job. Read as a job-level red, that
looks like a test failure; read as a step conclusion, it never was one.
The suite is already runner-hardened — every git-using test sets its own
`user.name`/`user.email` on the repo it creates
(`packages/cli/src/branch.test.ts:29`, `prune.test.ts:17`,
`rules.test.ts:106`, `lifecycle.test.ts:474`,
`packages/pipeline/test/pipeline.test.ts:83`,
`packages/commands/src/run.test.ts:58`) rather than inheriting a
developer's global identity. A local run under the runner-equivalent
condition (`HOME` a fresh empty directory, `GIT_CONFIG_GLOBAL` and
`GIT_CONFIG_SYSTEM` pointed at files that do not exist) is green at
current `HEAD`: 1173 PASS, 0 FAIL, exit 0.

**`format:check` has no runner delta either.** It fails on the runner for
the same reason it fails on this checkout: one tracked file was committed
unformatted.

```
2026-09-20T05:53:02.8623686Z [warn] scripts/w030-usage-guard-mutation.mjs
2026-09-20T05:53:02.8769059Z [warn] Code style issues found in the above file.
2026-09-20T05:53:02.8914391Z ##[error]Process completed with exit code 1.
```

`npm run -s format:check` at `HEAD` on this machine prints the same two
warnings and exits 1. The file arrived with W-030 (commit `9e3e533`,
`3e21140`); the first run to fail this way, 35491794386, is W-030's own
branch push. Prettier wants two wrappings in it — a long array literal at
line 46 and a long template literal at line 96 — and nothing else.

So there is no local-green/runner-red delta to close. There is one
unformatted file standing between the required check and its first green,
and that is the whole of this opus.

## Files owned

- `scripts/w030-usage-guard-mutation.mjs` — reformat only, no behaviour
  change. W-030 is `done`, so the file is not in another opus's hands; no
  other in-flight brief names it (`W-022`, `W-023`, `W-027`, `W-028`,
  `W-035` are the open ones).

Nothing else. No workflow change, no test-script change, no
`.prettierignore` change.

## Interfaces

None. No command, no flag, no exported symbol. The mechanical pass already
exists and is the one to use — `node scripts/format-all.mjs`, which is
`prettier --write .` honouring `.prettierignore` (W-019). Do not hand-edit
the two sites; the lex requires mechanical work to go through a committed
script, and this one is already committed.

## Behaviours to test

1. **`npm run -s format:check` exits 0 against the tracked tree.** Today
   it exits 1 naming `scripts/w030-usage-guard-mutation.mjs`. The red is
   the step itself, recorded with `bisellium red W-036 --behaviour 1 …
   -- npm run -s format:check`; no new assertion is needed, because
   `format:check` *is* the assertion and CI already runs it on every push.
   After `node scripts/format-all.mjs`, the same command exits 0 and lists
   nothing.

2. **`node scripts/w030-usage-guard-mutation.mjs` still does its job after
   the reformat.** The file is not a static asset — it mutates real source
   on disk, runs `packages/commands/src/usage.test.ts` against the mutated
   tree, reverts in a `finally`, and exits with the test's own code. A
   reformat that broke its array literal or its revert path would be
   invisible to `format:check` and to `npm test` (the script is in neither).
   Run it and assert two things: it exits non-zero (the M13 mutation makes
   `usage.test.ts` fail, which is the point of the script), and
   `git status --porcelain` is empty afterwards — the revert restored every
   byte. The red for this behaviour is the same command run against a
   deliberately broken copy of the script under `$TMPDIR` (delete the
   `finally` block), which leaves the tree dirty; keep that output as the
   recorded red, and do not let the broken copy near the checkout.

## Acceptance

- `npm run -s format:check` exits 0 on this branch.
- `npm test` exits 0 on this branch under the runner-equivalent
  environment — `HOME` a fresh empty directory under `$TMPDIR`,
  `GIT_CONFIG_GLOBAL` and `GIT_CONFIG_SYSTEM` set to paths that do not
  exist — with no `FAIL` lines. This is a pinned observation, not a fix;
  it is here so the opus closes on evidence that the second half of its
  title is true rather than on an assumption.
- On a runner re-run of `ci.yml` against this branch, the `build` job
  reaches `Run npm run -s check -- studio --repo .` — that is, `typecheck`,
  `lint`, `format:check` and `test` all report `success` in the job's step
  conclusions.

The commissioning acceptance was "the `build` job passes". It cannot be,
and W-036 must not be judged on it: the job's fifth step is
`check -- studio`, which fails on officina debt this opus is forbidden to
touch. Reaching that step green is the strongest true statement available,
and it is exactly the delta W-036 owns.

## Out of scope

- **`npm run -s check -- studio --repo .`.** Honest officina debt —
  missing reds on W-028, W-035 awaiting build, `wip.cap` exceeded. It
  burns down through opera already in flight. Do not touch `studio/`
  bookkeeping to make a check pass.
- **Anything about what CI enforces.** No step added, removed or
  reordered; `scripts/ci-workflow.test.mjs` guards that list and must stay
  green untouched.
- **The `lint` step's two warnings** (`close.test.ts:5` unused `execSync`,
  `tick.test.ts:203` unused `opts`). `eslint .` exits 0 on warnings; the
  step is green. Cleaning them is someone's tidy-up, not this opus's.
- **A pre-push or pre-commit format gate.** W-031 (`bisellium ci`) is the
  designed vehicle for running the pipeline before a push and is still in
  `backlog`. Building a second gate here would duplicate it. Raising
  W-031's rank is a producer's call, not a builder's.
- **The stale `.prettierignore` exclusions.** `packages/`, `apps/`,
  `adapters/`, `.claude/` and `cascades/` are ignored with in-file comments
  calling each a temporary measure for cascade 5 and 6 — cascades long
  closed. With them dropped, `prettier --check .` reports 88 files. The
  format gate therefore guards `scripts/`, `.github/` and root config and
  almost nothing else. Widening it is a real and worthwhile opus; it is
  also a diff across every other opus's declared files, which the
  engineering lex forbids a single builder to take. File it, rank it,
  schedule it between cascades. It is not W-036.
