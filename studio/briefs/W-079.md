behaviour of `runAmend` changes.** Written for builder-sol's first build
under D-025; every line number, message string and command below was run on

No *For Sol* section: D-025 puts builder-sol in the builder's seat, and a

## Intent

W-062's censor round-1 advisory A1: two refusals in `runAmend` are real and
correct, and **no test would notice if they were deleted**. Verified here by
mutation — each guard removed, block 51 still **67 PASS / 0 FAIL**.

## Guard 1 — the absolute-path refusal

Source, `packages/commands/src/lifecycle.ts:1013-1016`:

```ts
    if (isAbsolute(specFlag)) {
      console.error(`${opusId}: --spec "${specFlag}" must be officina-relative, not absolute`);
      return { exitCode: 2 };
    }
```

The row that should pin it, `packages/cli/src/lifecycle.test.ts:2437-2441`:

```ts
    await assertRefusal(
      "--spec absolute inside the officina (land 10)",
      opusPathFor("W-500"),
      ["W-500", "--spec", join(dir, "briefs", "W-500.md"), "--reason", "r", "--studio", dir],
    );
```

It passes **no `tokens` argument**. `assertRefusal`'s signature is
`(label, opusPath, args, tokens: string[] = [])` (`:2396`) and its stderr
check is guarded by `if (tokens.length)` (`:2403`) — so with `tokens`
defaulted the message is never inspected. Delete the guard and an absolute
`--spec` still exits 2, just further down: `isContained` passes for a path
inside the officina (that is exactly why the guard exists), then
`join(root, specFlag)` produces `<root><abs>`, which does not exist, so the
refusal becomes `no spec at … — not ready`. Exit 2 either way, so the row
stays green.

**The fix: pass the token.** One argument on one call:

```ts
      ["must be officina-relative, not absolute"],
```

## Guard 2 — the narrowed catch

Source, `packages/commands/src/lifecycle.ts:1097-1103`:

```ts
  } catch (e) {
    if (e instanceof AmendShapeError) {
      console.error(e.message);
      return { exitCode: 2 };
    }
    throw e;
  }
```

`AmendShapeError` (`:909`) is thrown for a malformed `amendments:` node. Any
*other* error must propagate, so a real defect surfaces as a crash instead
of a quiet `exit 2` that reads like a refusal. Widen this to a blanket catch
and nothing fails — measured across **all twelve** amend blocks (46-57), zero
failures.

**The fix: one new assertion in block 51**, inducing a non-`AmendShapeError`
by making the record read-only so `editOpusFrontMatter`'s `writeFileSync`
fails. Measured on this tree, unmutated:

```
unmutated runAmend under a read-only record -> THREW: Error / EACCES: permission denied, open '…'
```

So the assertion is that `runAmend` **throws**, not that it returns 2:

```ts
    // W-079: pins lifecycle.ts's narrowed catch. A non-AmendShapeError must
    // propagate; a blanket catch would turn this into exit 2.
    {
      const p = opusPathFor("W-001");
      chmodSync(p, 0o444);
      let threw = false;
      try {
        await withStderr(() => runAmend(["W-001", "--title", "readonly probe", "--reason", "r", "--sella", "architect", "--studio", dir]));
      } catch {
        threw = true;
      } finally {
        chmodSync(p, 0o644);
      }
      check("amend b6: a non-AmendShapeError propagates (not swallowed as exit 2)", threw);
    }
```

`chmodSync` joins the `node:fs` import at `lifecycle.test.ts:13`. Restore the
mode in `finally`, or every later row in block 51 inherits a read-only
record.

## Reds — read this before recording anything

This is a **test-strengthening** opus, so the honest red is *not* a failing
assertion in the new tests. It is the transcript of **the mutation surviving
the unstrengthened suite**: that survival is the defect.

`bisellium red` refuses a command that exits 0 (`lifecycle.ts`'s
`runCapture` guard: *"command exited 0 — that command passed, nothing
recorded"*). So the red command must be a script that **asserts the
behaviour and fails when it does not hold**. Write
`scripts/w079-mutation-check.mjs` to take a behaviour number and, for that
behaviour's guard:

1. copy `packages/commands/src/lifecycle.ts` aside;
2. apply the mutation by exact-string replacement — **assert the target
   string was found**, so a silent no-op cannot masquerade as a result;
3. run `BISELLIUM_ONLY_BEHAVIOUR=51 node --import tsx packages/cli/src/lifecycle.test.ts .`;
4. restore the file from the copy, **in a `finally`**;
5. exit **0** if the suite failed (the guard is pinned) and **non-zero** if
   the suite passed (the guard is not pinned).

Run before the test edits, it exits non-zero and that is the red. Run after,
it exits 0. Same script, same command, both phases — which is what makes the
evidence checkable by a third party.

```
bisellium red W-079 --behaviour 1 --sella builder-sol --studio studio --repo . -- node scripts/w079-mutation-check.mjs 1
bisellium red W-079 --behaviour 2 --sella builder-sol --studio studio --repo . -- node scripts/w079-mutation-check.mjs 2
```

Two reds, one per behaviour, no shared output (engineering lex §2,
`opus.red_evidence`). The script is committed and **not** registered in
`npm test` — it mutates tracked source, exactly like its four siblings
(`scripts/w041-mutation-check.mjs`, `w044-`, `w049-`,
`w030-usage-guard-mutation.mjs`), none of which is in the chain.

**Verify `git status` is clean after each red.** A mutation left on disk
would be certified into the next gate.
