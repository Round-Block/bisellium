## Intent

The Patron, 2026-10-28 and 10-30: a reply to the Patron answers each asked point in one or two lines, and carries the latest usage reading. Both are prose today (the session's memory), so a long session forgets them. This opus makes them a hook (process enforcement is a check rule or a hook, never prose).

What landed of W-430's seam: nothing yet. W-430 (done) shipped the usage half only; no source names `STOP_RULES` or reads `last_assistant_message`, the guard judges only PreToolUse and SubagentStop, and the repo wires no Stop hook (`sources.out`). This opus builds the seam as W-430's Out of scope drew it, with one documented change (Interfaces, the rule's second argument).

1. **The seam.** `guardRefusal` (packages/cli/src/guard.ts), which `bisellium hook-event guard --studio studio` already runs, gains a Stop branch: the main thread's final reply, the payload's `last_assistant_message`, is judged by each rule of an exported table, `STOP_RULES`, and their refusals are joined. W-436 adds its rule as one more entry.
2. **The length rule.** A reply of more than 200 words is sent back, code blocks counted.
3. **The usage rule.** A reply with no line carrying the latest usage reading is sent back, with that reading's line to carry.
4. **The wiring.** `.claude/settings.json` gains one Stop group running the same guard command, and `guardWiring` (the `hook.guard` check) requires it.

Decided here (the opus asked for each):

- **Main thread or subagent.** Claude Code fires Stop for the main thread and SubagentStop for a subagent, and its hook input carries `agent_id` only inside a subagent, "even in --agent sessions" absent for the main thread (the installed Claude Code 2.1.314's own schema, `sources.out`). The rules run at Stop only, and a Stop input that names an `agent_id` is not judged (D-073 B, as the guard's other branches tell them apart). SubagentStop keeps its one W-310 rule.
- **What counts as the usage reading.** The line `~/.bisellium-evidence/usage/usage-reading.sh <label>` prints holds four parts: `Claude week N%`, `5h N%`, `Codex week N%` and `context Nk` (`of 300k` after it). A reply carries the latest reading when one of its lines holds all four with the values of the readings file's last reading (`~/.bisellium-evidence/usage/readings.jsonl`, the file the script and every `next --perform` rung append to, W-430), and that reading was taken within 30 minutes of the Stop. The script's own printed line passes as it is; so does the short form the refusal names, `Claude week 19%, 5h 16% | Codex week 39% | context 208k of 300k`.
- **How a refusal reaches the model.** As every guard refusal: the line on stderr and exit 2. At Stop, Claude Code then does not end the turn and shows the model that text, so the model writes a short reply (and takes a reading, if it needs one).
- **How a loop is avoided.** Claude Code sets `stop_hook_active` on a continuation a Stop hook caused; such a Stop is not judged, as SubagentStop already does it. A reply is sent back at most once.
- **The settings change.** No hook installed today runs at the main thread's final reply: PreToolUse and PostToolUse run at tool calls, SubagentStop only for a subagent. So one Stop group is needed in `.claude/settings.json`, which is code-owned: the Patron merges this opus's PR (Defaults 4). It runs the guard command the repo already runs, so no new command or script is installed. A `bisellium` on PATH older than this opus's merge exits 0 at Stop (its guard judges only PreToolUse and SubagentStop), so the entry is harmless in either order of merge and install.

Threat model: mistakes, not adversaries (D-045). The reply is the session's own text; the readings file is written by the Patron's tools on this host.

**The seam** (`guard.ts`).

- `interface StopContext { input: Dict; home: string; now: Date }` and `type StopRule = (reply: string, ctx: StopContext) => string | undefined`: a refusal line, or undefined when the reply keeps the rule. W-430's spec drew the rule as `(reply, input)`; it takes `ctx` instead (the documented seam change) because the usage rule reads the readings file under a home, at a clock, that the rows set; `ctx.input` is that input.
- `STOP_RULES: readonly StopRule[]`: the length rule, then the usage rule. W-436 appends its rule.
- `stopRefusal(input, home = homedir(), now = new Date(), rules = STOP_RULES)`: undefined when the input names an `agent_id`, when `stop_hook_active` is true, or when `last_assistant_message` is not a string holding a non-space; otherwise each rule's refusal, in table order, joined by a newline (each is one line), or undefined when none refuses.
- `guardRefusal(input)`: at `hook_event_name` `Stop`, `stopRefusal(input)`. Its other branches are unchanged; `handleGuard` prints the refusal on stderr and exits 2, as for PreToolUse and SubagentStop.

**The length rule.** `REPLY_WORDS` is 200 (the Patron's number, W-430 Defaults 2). `replyWords(reply)`: the reply's whitespace-separated runs that hold a letter or a digit (`\p{L}` or `\p{N}`), code blocks included, so a bare `-`, `|`, `>` or fence is not a word. Over 200: `refused: this reply is <n> words, over 200 (W-444): reply again in at most 200 words, code blocks counted, each asked point in one or two lines`.

**The usage rule.** `readReadings(home)` (W-430's, unchanged) reads the readings file; the latest reading is its last. `readingParts(r)`: `Claude week <claude_week_used>%, 5h <claude_5h_used>% | Codex week <codex_week_used>% | context <floor(context_tokens / 1000)>k of 300k`, a value the reading lacks as `?`. `carriesReading(reply, r)`: one line of the reply holds `Claude week <v>%`, `5h <v>%`, `Codex week <v>%` and `context <v>k`, each `v` a number (or `?`) equal to the reading's (the context in thousands, rounded down, as the script prints it); a value the reading lacks is not compared. With no readings file (`readReadings` maps its ENOENT to no reading) or no reading in it, nothing is asked. Any other read error (`readReadings`'s `{ error }`: a permission or file-type mistake, a symlink on the path, a file over its 16 MiB bound) is refused: `refused: the usage readings file ~/.bisellium-evidence/usage/readings.jsonl cannot be read (W-444): <error>; fix it, then run ~/.bisellium-evidence/usage/usage-reading.sh <label> and carry its line`. A latest reading whose `at` (parsed by `instant`, so no raw date parse is added) is more than 30 minutes (`STALE_MS`) from the Stop, either side, or does not parse: `refused: this reply carries no usage reading taken in the last 30 minutes (W-444): the latest is from <at>; run ~/.bisellium-evidence/usage/usage-reading.sh <label> and carry its line`. A fresh one the reply does not carry: `refused: this reply carries no line with the latest usage reading (W-444): carry "<readingParts>" (the reading at <at>), or run ~/.bisellium-evidence/usage/usage-reading.sh <label> and carry its line`.
