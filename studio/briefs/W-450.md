## Intent

The merge queue's `certify` job mints with master's `bisellium run`, whose host runner (`scripts/run-builder-host.mjs`) replays each recorded red. When the queue rebased the opus onto a master that moved, the tree a red log claims is no longer on the branch, so the runner identifies the red's pre-change commit from the log's bytes and re-attests it by its failing titles: the `not ok <n> - <title>` lines of the recorded log (`run-builder-host.mjs:716`), each of which the replay must print again (`:770-774`). A Node TAP red prints that line. A served Playwright red printed only the `list` report, so certify refused W-442's PR #835 twice, at the same line:

`run-builder-host: producer red replay refused 01.log: behaviour 1: its recorded log has no not-ok title to re-attest` (`certify-835-run1.log:592`, `certify-835-run2.log:592`; `:717`).

The Patron merged it by hand (dossier row 167). The filed design closes it, and this opus does it: the served config (`apps/web/playwright.serve.config.ts`) gains a second reporter beside `list`, which prints one TAP 13 stream when the run ends, `not ok <n> - <title>` for each test whose final outcome is a failure and `ok` for every other. A served red's log then carries the title the host's grammar reads, and the replay prints it again.

Why this design and not a host change: the alternative, teaching the host runner to read Playwright's `list` lines (`✘ 1 [chromium] › file:line:col › title (4.4s)`), changes the code certify runs, so by the W-323 trap it is judged by the old runner at its own merge and must land first in its own opus; and the `list` line carries a duration, a source position and a ` (retry #n)` suffix, so the recorded and replayed lines differ by run. The reporter changes no host code: the replay runs the red commit's own served config, and `classifyReplay` still routes the output through its Playwright clause (the `list` banner, exactly one failed, an `expect(…)` failure), unchanged. Its title is the test's title path without the empty root (project, file relative to the test directory, describes, title), one line, `\` and `#` escaped as TAP 13 asks, with no path, port, duration or attempt; and it is read from the final outcome, so the recording (no `CI`, no retries) and the replay (the replay cell sets `CI=1`, so the served config retries twice) print the same single line.

This opus's own merge (W-323): nothing changes what certify runs or how; `scripts/ci-certify.mjs`, `scripts/ci-certificate.mjs` and the host runner are untouched. Its one red is a Node TAP red, which master's runner already re-attests after a rebase. A served red recorded before this lands (none is open: W-442 is done) is not helped; every served red recorded after it is.

Threat model: mistakes, not adversaries (D-045). The reporter is candidate code, as every test's own output already is; the host trusts no more of it than before: the titles it matches are read from the log bytes the branch committed, and the classifier still requires `list`'s single expect failure.

## Interfaces

**`tapTitle(test: TestCase): string`** (exported): `test.titlePath()` without its empty parts, joined by ` › `; each run of `\r` or `\n` becomes one space; then `\` becomes `\\` and `#` becomes `\#`. For W-442's row it is `chromium › w442.spec.ts › W-442-b1 Officina today rule clears every weekday letter at 1280 and 390`.

**`tapLines(tests: readonly TestCase[]): string[]`** (exported): `TAP version 13`, `1..<count>`, then per test in order `<status> <k> - <tapTitle>`, where `<status>` is `not ok` when `test.outcome()` is `unexpected` and `ok` otherwise (`expected`, `flaky`, `skipped`), with ` # SKIP` appended when it is `skipped`.

**`TapReporter`** (default export, Playwright `Reporter`): `onBegin` keeps the root suite; `onEnd` writes `\n` + `tapLines(root.allTests()).join("\n")` + `\n` to stdout in one write, so every stream line starts at column 0 after whatever `list` wrote; `printsToStdio()` is true.

**`TAP_REPORTER`** (exported from the served config): `fileURLToPath(new URL("./tests-serve/tap-reporter.ts", import.meta.url))`, absolute so a config that spreads the served one (the row) keeps the reporter. The served config's other fields are unchanged.

Promise reattest: a served Playwright red recorded after this opus carries one `not ok <k> - <title>` line per finally failing test, which `run-builder-host.mjs`'s title grammar reads, and a replay of the same commit under the replay cell's `CI=1` prints the same line once, so certify re-attests a rebased served red instead of refusing it with "no not-ok title". Pinned by `W-450-b1` "the served run prints the failing row's not-ok title, once though it ran twice, with no path or attempt" — limit: the host's rebased identification and printed-title check (`run-builder-host.mjs:705-735`, `:770-774`), `classifyReplay` and the replay cell are reused unchanged and not promised here; the row copies the host's title pattern rather than running the host, so the end-to-end path is shown once on W-442's own served row (`served-demo.out`), not pinned; a red recorded before this opus lands is not helped.

Promise outcome: every other test prints `ok` by its final outcome: a pass, a pass on retry and a skip (with ` # SKIP`). Pinned by `W-450-b1` "every other row prints ok, by its final outcome: a pass, a retried pass and a skip" — limit: `TestCase.outcome()` and `titlePath()` are Playwright 1.63's, reused unchanged.

Promise classifier: the served output still carries `list`'s report, so `classifyReplay` reads it through its Playwright clause as before. Pinned by `W-450-b1` "the replay classifier still reads the list report: one expect failure" — limit: `classifyReplay` is reused unchanged.
