## Intent

Every test that starts the CLI (`node --import tsx packages/cli/src/main.ts …`) pays tsx's compile of the whole TypeScript graph, about 96 repository modules, on every start: about 650 to 800 ms cold against 300 to 400 ms with a written cache. `next.test.ts`'s rows start the CLI dozens of times each (86 times in `W-124 behaviour 1`, the diagnosis), so the suite takes about 39 minutes on this host, over the 30-minute gate cap of the host mint and the done rung's full local verify. Two causes, both measured:

1. `packages/cli/src/main.ts:240-246` ends the process with `process.exit(code)` as soon as `main()` settles. tsx writes each compiled module to its cache with an asynchronous `fs.promises.writeFile` while the graph loads; the main thread then runs the verb without turning the event loop, and `process.exit` ends the process before those writes land, leaving each entry created and empty. tsx reads an empty entry as a miss, so the next start compiles again and truncates again. One start on a fresh cache directory leaves 104 of 104 entries empty on master and 0 of 104 when the process ends by `process.exitCode`; the next start takes 881 ms against 344 to 413 ms (`exit-variants.out`). The sandbox's live cache holds 9,265 empty entries of 23,019 (Fable). CI's children hit the same truncation.
2. `next.test.ts` builds every git and CLI child's env by hand (`SETUP_ENV`, line 102, which `envFor` spreads) and leaves out `TMPDIR`, so a child's `os.tmpdir()` falls back to `/tmp`, which the Claude sandbox mounts read-only: tsx cannot write its cache there at all (one W-124 row fell from 72 to 49 s with TMPDIR passed, the diagnosis). `scripts/ci-certify.test.mjs`'s `spawnScript` (line 52) is the one other hand-built env that starts tsx. The census (`env-census.out`) finds every other hand-built env either merged into `process.env` (`Object.assign`, so TMPDIR stays), spread from it, carrying TMPDIR already, or starting no tsx child (git only, or plain `node`).

After this opus the CLI ends by setting `process.exitCode` and letting the event loop drain, so tsx's writes land, and the two envs carry the test process's `tmpdir()`. On a fresh cache directory `W-123 behaviour 1` takes 35.8 s, then 32.5 s, with master's exit, and 19.4 s, then 18.5 s, on the prototype (`time-fresh.out`; with master's exit 68 of its 105 entries stay empty, the rest written by the long-lived test process). Fable projects the suite here at about 22 minutes and CI's 13 lower. Every existing test row is kept unchanged; one row is added.

Open handles. With `process.exitCode` the process ends only when nothing keeps the loop alive, and a verb can leave something open: `hook-event`'s payload reader (`packages/shim/src/hooks/stdin.ts:14`) leaves its listeners on a stdin that never ends after its 2-second timeout, and with `process.exitCode` alone the CLI then never exits (`open-stdin.out`: killed at 10 s). Others the census of `main()`'s callees names: a timed-out quota-axi probe's pipes (`packages/providers/src/index.ts:181`, ended by its own SIGTERM, then SIGKILL within 5 s) and `serve`'s models listing timer (`apps/server/src/http.ts:358`, 3 s). One backstop handles them all: when `main()` settles, an unref'd timer calls `process.exit(code)` after `EXIT_GRACE_MS` (1000 ms). Unref'd, it never keeps the loop alive itself, so a verb with nothing open ends as soon as its writes land (79 of 79 CLI starts in the W-123 row ended on their own, 5.6 ms after `main()` on average, `w123-exitlog.tsv`), and a verb with a handle open ends at most 1 s later than on master, with the code `main()` returned. A shorter delay is a race, not a fix: `setTimeout(exit, 0)` left 104 entries empty on one run and none on the next, and a 0 ms backstop left 104 empty (`exit-variants.out`).

The `serve` shutdown path (`main.ts:56-83`, `runServeUntilStopped`) is unchanged: it resolves 0 only after the server's `close()`, and `finish(0)` then ends the process; the listing timer above is its one known straggler.

Threat model: mistakes, not adversaries (D-045). The change touches no input boundary.

## Interfaces

`main.ts`, module-private:

```ts
/** How long a verb's process may outlive `main()` when a handle it left
 *  open (a stdin a hook payload never closed, a timer) keeps the loop alive. */
const EXIT_GRACE_MS = 1000;

function finish(code: number): void {
  process.exitCode = code;
  setTimeout(() => process.exit(code), EXIT_GRACE_MS).unref();
}

main(process.argv.slice(2)).then(finish, (err) => {
  console.error(err instanceof Error ? err.stack ?? err.message : String(err));
  finish(1);
});
```

`finish` carries a doc comment naming W-311 and why `process.exit` is not called at once. Exit codes do not change: each verb's code reaches the parent as on master, and a rejection prints its stack and exits 1. No verb, no `serve` code, no stdin reader and no provider code changes.

Limits (D-076 E), stated, not guaranteed:

- A verb that leaves a handle open ends up to `EXIT_GRACE_MS` later than on master; its cache writes then land only if the loop turned meanwhile. Only `hook-event` on a stdin that never ends is measured (`open-stdin.out`: 2.4 s on master, 3.7 s on the prototype); the others above are read from the code, not run.
- A verb whose open handle does work after `main()` settles (a timer callback, a child's `exit` handler) now runs that work for up to 1 s before the hard exit; on master it was cut at once. The census found none that writes a record.
- A later hand-built child env that drops TMPDIR again costs only time: tsx catches a failed cache write, so no row fails for it. No check rule pins the other test files.
- On this host the main checkout's `/tmp/tsx-1000` was warmed outside the sandbox (diagnosis and handoff), so master's rows there already run warm for unchanged files; the gain shows on a cold or changed tree, a fresh worktree and CI (`time-fresh.out`).

### Input domain

A rejection fails closed: a failed read, write or spawn in the row throws or fails its assertion, which fails the row; `main.ts` refuses nothing.

| Record | Valid domain | Rejected by |
|---|---|---|
| `main()`'s settled outcome, a verb's exit code or a rejection | a number, or any thrown value | `finish` (specified): sets the number as `process.exitCode`; a rejection prints the stack, as on master, and finishes with 1; nothing is refused |
| A handle a verb leaves open after `main()` settles (a stdin never ended, a child's pipe, a timer) | none expected; any | limit: `finish`'s unref'd timer ends the process with `main()`'s code `EXIT_GRACE_MS` after it settles |
| The test process's temp directory copied into `SETUP_ENV` and `spawnScript`'s env | a path string, `TMPDIR` or else `/tmp` | `tmpdir` (`node:os`): returns a string; an unwritable directory makes tsx skip its cache writes (it catches them), slower, never a failure |
| The tsx cache directory under the row's fresh TMPDIR, and its entries | one `tsx-*` directory holding at least one entry, each non-empty | `readdirSync`, `statSync` (in `W-311-b1`): a missing directory throws; no directory, several, no entry or an empty entry fails its assertion |
| The FIFO `W-311-b1` makes for `hook-event`'s stdin | a FIFO the row creates under its scratch directory and opens read-write | `execFileSync` (`mkfifo`), `openSync` (in `W-311-b1`): a failure throws, which fails the row |

## Behaviours to test

1. **One CLI start leaves tsx's compile cache entries written, the env `next.test.ts` builds for its children keeps the test's TMPDIR, and a verb that leaves a handle open still exits.** In `W-311-b1` (`next.test.ts`, the file's `scratch`, `SETUP_ENV`, `TSX` and `MAIN`): the bare CLI started once with `{ ...SETUP_ENV, TMPDIR: <fresh scratch dir> }` exits 2 (its usage); under that directory there is exactly one `tsx-*` directory, it holds at least one entry (dot-files aside), and none of them is empty. `SETUP_ENV["TMPDIR"]` equals `tmpdir()`. Then `hook-event tool --sella guest --studio <scratch dir>` started with a stdin that never ends (a FIFO the row holds open read-write) and a 30 s spawn timeout ends with no signal, exits 0, and prints `hook-event tool: timed out after 2000ms reading hook payload from stdin` on stderr.

   **Genuine red:** `bisellium red W-311 --behaviour 1 --sella builder --studio studio -- node --test-reporter=tap --test-name-pattern='^W-311-b1\s' --import tsx packages/cli/src/next.test.ts` prints `not ok 1 - W-311-b1 behaviour 1: …`, failing at `every cache entry the start wrote is non-empty: 104 of 104 are empty` on master d78ffa00 (`red-b1-master.out`). With the exit fix alone it fails at `SETUP_ENV carries the test process's TMPDIR` (`red-b1-exitonly.out`), and with both fixes but no backstop it fails at `hook-event on a stdin that never ends exits on its own`, the spawn killed at its timeout (`red-b1-nobackstop.out`).
