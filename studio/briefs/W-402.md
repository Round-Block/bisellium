## Intent

W-398 made `scripts/agent-workspace.sh verify` read-only. Its settings line runs `node scripts/agent-settings-merge.mjs --check <file> …` through `check_shown`, which prints `FAIL user settings hold every isolation entry` and each line the check printed, indented. W-398 named one wrong type in `--check`, after `merge()` has run (`agent-settings-merge.mjs:116` to `:127` on master): an array at `permissions` or `env`, or a string at `sandbox.filesystem.denyRead` or `permissions.deny`. Every other wrong type at the fields `merge()` reads makes `merge()` throw first (`:106` to `:111`), and the CLI prints Node's message: `Cannot create property 'GH_CONFIG_DIR' on string 'bad'` for `env: "bad"`, `Cannot create property 'deny' on number '5'` for `permissions: 5`, `(existing ?? []) is not iterable` for `denyRead: 7` or `permissions.deny: {}`. With several wrong types at once the throw on one hides the rest. `{"permissions": [], "env": "bad"}` prints only Node's message for `env`. `{"permissions": [], "env": []}` prints only `permissions`. `denyWrite: "/k"` with `denyRead: 7`, `permissions.deny: {}` and `env: "bad"` prints only `denyWrite`. Reproduced on master 10f9a4f0 (`repro-master.out`).

The fix is one classifier, `wrongTypes`, in the merge script. `merge()` reads seven fields by name, and each needs one type. `sandbox` and `sandbox.filesystem` need an object and `sandbox.filesystem.denyWrite` an array of strings (`checkShape`, `:31`). `sandbox.filesystem.denyRead` and `permissions.deny` need an array (`union`, `:23`). `permissions` and `env` need an object (a property is set on each). `wrongTypes` returns one `<key> is not <type>` for each field of the wrong type, in the order `merge()` reads them: `sandbox`, `sandbox.filesystem`, `sandbox.filesystem.denyWrite`, `sandbox.filesystem.denyRead`, `permissions`, `permissions.deny`, `env`. That order is the declared precedence. `--check` runs it on the parsed file before `merge()` runs. When it returns any line, `--check` prints each as `<file>: <key> is not <type>; left untouched` on stdout, prints nothing else, and exits 1. A child field is read only under a parent that is an object; any other JSON parent holds no child fields, so no field goes unread. `null` is a wrong type where `checkShape` refuses it (the three sandbox fields) and absent where `merge()` reads it through `??` (the other four), as `merge()` itself treats them. W-398's four-field block after `merge()` is removed; `wrongTypes` covers its fields with the same text.

A single wrong type keeps W-398's line text. The three sandbox lines are `checkShape`'s messages, and the four others are W-398's `--check` lines. The forms that printed Node's message now print the line for their field. The write mode (no `--check`, run by `setup` and `guard`) is unchanged: `merge()` still throws or reshapes there as on master.

## Interfaces

**`node scripts/agent-settings-merge.mjs --check <settings.json> <patronDir> <agentGh> [<agentDir>]`** (W-398's mode; items 1 to 3 and 5 to 6 of W-398's Interfaces are unchanged):

1. The argument checks, the read, the absent file (`{}`) and the not-a-JSON-object line are W-398's, and come first.
2. Then `wrongTypes(before)`. Each field it names prints `<file>: <key> is not <type>; left untouched` on stdout, one line per field in the order of Intent, with `<type>` one of `an object`, `an array`, `an array of strings`. When any is printed, `--check` exits 1 and prints nothing more: no `missing`, `does not exist` or repeated-entry line.
3. When `wrongTypes` names none, `--check` runs `merge()` and goes on as W-398's items 3 and 5. On a JSON object `wrongTypes` passes, `merge()` neither throws nor reshapes, by its code: its throws are `checkShape`'s three, the spread of a non-iterable in `union` (`denyRead`, `deny`), and a property set on a primitive (`permissions`, `env`). The `catch` around `merge()` stays (`<file>: <message>; left untouched`).
4. No branch of `--check` calls `copyFileSync`, `mkdirSync` or `writeFileSync` (W-398's item 6, unchanged).

**`wrongTypes(settings)`** (module-local, not exported): `string[]`, empty when no field holds a wrong type. Valid per field: `sandbox`, `sandbox.filesystem`: absent or an object. `sandbox.filesystem.denyWrite`: absent or an array of strings. `sandbox.filesystem.denyRead`, `permissions.deny`: absent, `null` or an array. `permissions`, `env`: absent, `null` or an object.
