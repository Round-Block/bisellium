## Intent

D-088 A and B replace declared-file overlap with the conflict git itself would encounter. Today `deriveNext` reaches the review dispatch as soon as the branch gates are current. It does not ask whether that tree conflicts with `origin/master` or with another lane whose tree is already reviewed or pushed toward the merge queue. A later rebase can therefore invalidate the tree a reviewer signed.

After this opus, immediately before `deriveNext` would order build review, `next` runs `git merge-tree --write-tree` between `refs/remotes/origin/master` and `refs/heads/opus/<id>`. Exit 1 names a producer rebase at the opus worktree instead of a reviewer. Exit 0 continues to the other-lane checks. Every other local `opus/<id>` branch whose main-checkout record is open and which is either pushed or has a passed build review at its current tree is checked in numeric id order. Exit 1 there holds review and names the opus to wait for. No stdout or stderr text decides conflict; any exit other than 0 or 1, or a failed branch listing, holds review.

This is placed after current build gates are established and before the existing UI-review problems and review dispatch. Earlier rungs do no conflict work. A passed current review proceeds to PR without being checked again: the purpose is to prevent the first review of a tree that already needs rebasing, not to replace the PR and merge guards.

Threat model: mistakes, not adversaries (D-045).

## Interfaces

The prototype is staged by behavior: `apply-test.py <checkout>` adds both rows; `apply-src.py <checkout> 1` adds the master comparison and `apply-src.py <checkout> 2` adds strict other-lane enumeration, qualification and comparisons. `stages.sh <master|s1|proto>` prepares a disposable clone. The four commits in `prototype.mbox` are, in order, `test(W-337): row b1, red`, `feat(W-337): behaviour 1`, `test(W-337): row b2, red`, and `feat(W-337): behaviour 2`, each based on master 33da750d.

1. `mergeTreeConflict(repo, left, right): { conflict: boolean } | { error: string }` (new, private). It invokes `git(repo, ["merge-tree", "--write-tree", left, right])` once. Status 0 is `{ conflict: false }`; status 1 is `{ conflict: true }`; a spawn error, null status, or every other status is an error naming the two literal refs and numeric status. It never reads stdout or stderr to decide the result.

2. `reviewedAtTip(f: Facts): { reviewed: boolean } | { error: string }` (new, private), with `laneRecord` and `refPresence` as its strict readers. No usable registered worktree and an absent, failed or stale valid gate are definite `{ reviewed: false }`. An unreadable or malformed worktree record, manifest, build-review sequence, ticket setting, ref source tree or current brief is an error. Only a passed gate whose log certifies `refs/heads/opus/<id>` at the current worktree brief pin is `{ reviewed: true }`. A successfully checked pushed ref bypasses local qualification because the unchanged PR path only pushes the reviewed head.

3. `furtherAlongBranches(f: Facts): { refs: string[] } | { error: string }` (new, private). It runs `git for-each-ref --format=%(refname) refs/heads/opus/`, sorts its nonblank lines by numeric id, and accepts only exact `refs/heads/opus/<ID_RE>` refs. It excludes the current id. For each other id, `laneRecord` strictly reads the main-checkout record: absence and a valid closed state are noncandidates, an invalid record or state is an error, and `greenlit`, `building`, `verifying` or `review` is open. An open ref is included when `refPresence` proves its remote-tracking ref exists or `reviewedAtTip` proves current local review. Every reader error returns an error instead of omission.

4. `deriveNext`, just before the existing `// 7 review` body. First it compares `refs/remotes/origin/master` with `refs/heads/opus/<id>`. A conflict returns `build named`, actor `producer`, command `from .worktrees/<id>: git rebase origin/master`. Then it compares each `furtherAlongBranches` ref with the current branch. The first conflict returns `review held`, actor `producer`, and `wait for <other> to land before review`. A comparison or enumeration error returns `review held` and orders no reviewer. Only all status-0 comparisons reach the existing UI check and review dispatch.

Promise master-before-review: a current branch that conflicts with `origin/master` names a rebase instead of build review — limit: `next` does not fetch here; it judges the local `refs/remotes/origin/master` the caller has refreshed, and performing the printed rebase stays an operator action.

Promise later-lane-before-review: a current branch that conflicts with an open pushed or current-reviewed local opus branch holds review and names the first such opus in numeric id order to wait for. The compared and certified source is refs/heads/opus/<id>; the worktree record, manifest, review logs and brief qualify local review, so uncommitted or ignored worktree source entries are outside the comparison and unreadable qualification inputs hold under Input-domain row 6 — limit: branches absent locally are invisible, and a pushed branch is trusted to have crossed the unchanged review-before-PR path.

Promise exit-code-only: every merge-tree decision uses status 0 for clean and status 1 for conflict, never command text — limit: this requires git 2.38 or later, where `git merge-tree --write-tree` supplies this contract; older git is unsupported.

Promise fail-closed: a merge-tree status outside 0 and 1, a spawn error, a failed ref listing, a malformed listed ref, an unreadable or unclassifiable listed record, or an error qualifying an open unpushed lane's local review holds review and orders no reviewer — limit: a successfully checked pushed branch is compared without consulting its local worktree evidence.

Limits, stated:

- Unchanged code the promises lean on is a stated limit, not a guarantee (D-076 E): `git` and its 120-second bound, `ID_RE`, `gather`, `reviewGate`, `readStepTickets`, `readContainedRegularFile`, `sourceTreeHash`, `blobOf`, `dispatch`, `render`, and the PR/merge guards.
- The check reads local refs only and performs no fetch. A remote branch not represented by a local `opus/*` ref, or a newly moved `origin/master` not fetched into its remote-tracking ref, is outside the decision.
- Merge-tree may write unreachable tree objects in the object database. It moves no ref, index or worktree file; garbage collection remains Git's.
- The first conflicting further-along branch is named. Later candidates are not compared in that invocation; after the named branch lands, rerunning checks the new master first and then the remaining lanes.
- Closed branches, an unpushed branch without a current passed review, and changes made after a review (so its gate no longer matches the source tree) are not further along.
