# W-039 — red logs must name the sella that recorded them

## Intent

Six red logs on the real officina carry `# sella: guest`:
`ci/reds/W-028/{17,18,19,21}.log` and `ci/reds/W-036/{01,02}.log`. The
dispatches that produced them never set `$BISELLIUM_SELLA`, and
`resolveSella` (`packages/commands/src/lifecycle.ts:40`) falls back to
`guest` silently. The evidence exists; nobody knows who made it.

Nothing catches this, and the handoff has carried it as a prose bullet for
a cascade. "Process enforcement is a check rule or a hook, never a memory
or prose."

The six cannot be fixed. `bisellium red` refuses to record when the command
exits 0, so once a behaviour is implemented its red can never be
re-produced — and rewriting the header by hand is forging evidence, the
officina's own recurrent finding class. **The six are permanent history.**
That fact decides every level choice below.

## Two pieces, in this order

### 1. `red` refuses an unattributed recording (the root cause)

`runRed` exits 2, writing nothing, when the sella resolved by **fallback** —
neither `--sella` nor `$BISELLIUM_SELLA` was given:

```
red: no sella — pass --sella <id> or set $BISELLIUM_SELLA (use --sella guest to record as guest deliberately)
```

An explicit `--sella guest` or `BISELLIUM_SELLA=guest` is **accepted**. The
refusal is about anonymity, not about guest: a single-sella officina whose
only sella is `guest` states so and proceeds. The check happens before the
command runs, so nothing is executed and nothing is written.

**Only `red`.** `ready`, `done` and `review` share `resolveSella` and have
the same anonymity hole, and widening the refusal to them would be the
smaller diff — but a red log is permanent and unrepeatable, while a gate is
re-signable (W-040), and refusing the four common lifecycle commands in a
fresh officina is an adopter-facing regression bought for an internal
process problem. The narrowing is deliberate. Widen it when a `guest` gate
shows up on a real officina; do not widen it in this opus.

Implement by giving `resolveSella` a way to report that it fell back —
returning `undefined` rather than `"guest"` for a caller that asks, or a
sibling helper next to it. Do not read `process.env` a second time at the
call site.

### 2. `opus.red_sella` (advise) — the logs already on disk

Folded into `checkEvidence`'s existing reds walk
(`packages/cli/src/rules/evidence.ts:157`). No new directory read.

- Scope: the `<NN>.log` files `opus.red_evidence` already resolves, not
  every `*.log` in the directory. `W-028/close-bugs-*.log` and friends are
  off-contract artifacts; "no sella header" is not a finding about a file
  that was never a red log.
- Fires when a log's header has no `# sella:` line, or one whose value is
  `guest`.
- **One finding per opus**, `where: ci/reds/<id>/`, naming the count and
  the log basenames sorted and comma-joined:

  ```
  ${n} red log(s) record no sella: ${names.join(", ")}
  ```

  One condition, one finding — not one per file. `lesson.recurrent` became
  noise by reporting per-instance; do not repeat it.

**Advise, not block, and this is the load-bearing judgment.** A blocking
rule here can never be cleared: the six reds cannot be re-recorded, so the
only escapes are hand-editing the headers (forgery) or deleting the
evidence. A block whose only exits are forgery and deletion is worse than
the gap it closes. Piece 1 is what makes the count stop growing; the
advisory is the permanent, honest record that six once did.

Expect the advisory to report a **fixed set of two opera, six logs**. If
that count ever grows, piece 1 has a hole — say so in the brief's own
acceptance rather than in a comment nobody re-reads.

## Relationship to W-035

W-035 ships `RULE_IDS` (`packages/cli/src/rules/ids.ts`) and behaviour 7,
a drift guard asserting the registry equals a live harvest of every rule id
in `check.ts` + `rules/*.ts`. Either landing order works:

- **W-039 first** — W-035's harvest picks `opus.red_sella` up on its own;
  its builder adds one literal to a set it is already writing.
- **W-035 first** — this builder adds `"opus.red_sella"` to `ids.ts` in the
  **same commit** as the rule, or `npm test` fails on behaviour 7.

This opus does **not** wait for W-035. The only coupling is one sorted
string literal, and the guard names the failure precisely if it is missed.

## Behaviours to test

1. `red` with neither `--sella` nor `$BISELLIUM_SELLA` exits 2, runs no
   command, and writes no log
2. `red --sella guest` records, and the log header reads `# sella: guest`
3. `opus.red_sella` advises once for an opus with two headerless reds,
   naming both basenames
4. `opus.red_sella` advises for `# sella: guest`, and is silent for a named
   sella
5. `opus.red_sella` ignores off-contract `*.log` files in the reds
   directory
6. `opus.red_sella` never blocks — it is absent from a `--level block` run

Reds via `bisellium red W-039 --behaviour <n> --sella <id>` (this opus's
own reds will be the first that cannot be recorded anonymously), one per
behaviour, assertion-level. Behaviour 1 needs `$BISELLIUM_SELLA` unset in
the child environment; set it explicitly rather than relying on the
harness's. Every behaviour builds its own officina under `$TMPDIR`.

   officina.
4. The handoff's backlog item 11 is deleted in the same commit. A rule that
   exists and a prose reminder that it exists are one item too many.

## Out of scope

- **Rewriting the six existing headers.** That is the forgery this opus
  exists to make unnecessary.
- **Widening the refusal to `ready`/`done`/`review`.** Reasoned above.
- **A hook that sets `$BISELLIUM_SELLA` for every dispatch.** The hook
  layer already defaults it to `guest` (`.claude/settings.json`); making
  the hook guess an identity is the same anonymity with a better disguise.
- **`# sella:` on gates or receipts.** Different artifacts, different rule.
