# W-039 — red logs must name the sella that recorded them

Spec of record, signed by the architect, 2026-09-24. This revalidates the
cascade-22 filing (commit 3e2ccb3) against today's tree. The ruling still
stands: **advise, not block**, and fix the root cause at the source. Four
facts in the filing were wrong or stale, and they are corrected below: the
count, the reach of the reds walk, the empty-string hole, and the handoff
item. Sol red-teams this brief (D-020) as input, not authority. The `ready`
gate is signed on `opus/W-039` after `bisellium branch` (D-021). Greenlight
is the Patron's (commit 0d9a269).

## Intent

`resolveSella` (`packages/commands/src/lifecycle.ts:41`) is
`flag ?? $BISELLIUM_SELLA ?? "guest"`. `runRed` calls it at line 540 and
writes the result into the log's `# sella:` header at line 595. It never
refuses. When a dispatch sets neither the flag nor the env var, the
evidence is written and nobody knows who made it.

**The count, recounted from the tree on 2026-09-24:** 16 red logs carry
`# sella: guest`, across three opera:

| Opus | State | Logs |
|---|---|---|
| W-028 | halted | `17, 18, 19, 21` |
| W-031 | done | `01`–`10` |
| W-036 | done | `01, 02` |

The filing said "six across two opera" because it missed W-031. That was a
miscount, not a regression. The newest guest `# at:` is
2026-09-20T06:08Z, from W-036, and it predates the filing. Every red
recorded since then names a sella: 132 are `builder-a` and 32 are
`builder-b`. None of the 16 can be fixed. `red` refuses a command that exits
0, so once a behaviour is implemented its red can never be recorded again.
Rewriting the header by hand would be forging evidence. **The 16 are
permanent history.**

## Two pieces

### 1. `red` refuses an unattributed recording (the root cause)

The code path today (line numbers as of 0d9a269):
`main.ts:98` passes `rest` unchanged to `runRed`
(`packages/commands/src/lifecycle.ts:485`). That function parses its own
flags, then calls `openStudio` (527) and `safeRedsDir` (534), and then
**`const sella = resolveSella(values.get("--sella"))` (540)**. After that
it hashes the tree (570–578), runs the command through `runCapture` (580),
creates the directory with `mkdirSync` (587) and writes the log with
`writeFileSync` (598). Sella is resolved in `runRed` and nowhere else.
`main.ts` adds nothing for `red`. Its own `?? "guest"` chain at line 177
serves `hook-event` and is out of scope.

The change:

- Add a sibling helper next to `resolveSella`, called `namedSella(flag)`.
  It returns the first of `--sella` and `$BISELLIUM_SELLA` whose value is
  **non-empty after trim**, or `undefined`. It reads `process.env` once.
  Do not export it. The tests reach it through `runRed`, and an import of
  an internal helper that isn't exported would make the red a module-load
  failure.
- At line 540, `runRed` calls `namedSella` instead of `resolveSella`. When
  the result is `undefined`, it exits 2 with this message:

  ```
  red: no sella — pass --sella <id> or set $BISELLIUM_SELLA (use --sella guest to record as guest deliberately)
  ```

  The refusal stays **after** `safeRedsDir` and **before** the tree hash,
  `runCapture` and `mkdirSync`. That way no command runs, nothing is
  written, and the existing usage refusals (lifecycle.test behaviour 11:
  bad `--behaviour`, missing `--`, `..` ids) keep their own messages.
- **`resolveSella` stays byte-identical.** `ready`, `done`, `review`,
  `halt` and `waive` (lines 127, 269, 374, 685, 825) keep the silent
  fallback, including its empty-string case. See Out of scope.

**Empty is not a sella.** Under `??`, `BISELLIUM_SELLA=` (set but empty)
and `--sella ""` both count as values today. `parseFlags` accepts an empty
value, because its only check is `v === undefined`. Both record
`# sella: ` (empty), which is anonymity in a different form. The filing's
own acceptance demo, `BISELLIUM_SELLA= bisellium red …`, would have
**recorded** under a naive `=== undefined` check. `namedSella` closes this
hole. An empty flag falls through to the env var, and an empty env var
falls through to `undefined`.

**The resolution matrix, pinned by behaviours 1–3.** "Empty" means empty
after trim, so whitespace-only counts as empty. `parseFlags` keeps the
**last** value of a repeated flag (`packages/commands/src/writes.ts:56`),
and `namedSella` inherits that: it sees only the last `--sella`. It does
not scan for the first non-empty value, and it does not refuse a
repeated flag. Last-wins is how every other verb behaves, and changing it
for `red` alone would split the CLI's flag contract.

| `--sella` (last value) | `$BISELLIUM_SELLA` | Result |
|---|---|---|
| absent | unset | exit 2 |
| absent | `""` or whitespace | exit 2 |
| `""` or whitespace | unset | exit 2 |
| `builder-a --sella ""` | unset | exit 2 |
| absent | `builder-b` | records `builder-b` |
| `""` | `builder-b` | records `builder-b` |
| `"" --sella builder-a` | unset | records `builder-a` |
| `builder-a` | `builder-b` | records `builder-a` |
| `guest` | unset | records `guest` |

An explicit `--sella guest` or `BISELLIUM_SELLA=guest` is **accepted**.
The manifest declares `guest` as a human sella. The refusal targets
anonymity, not the name guest.

### 2. `opus.red_sella` (advise): active opera only

The rule is folded into `checkRedEvidence`
(`packages/cli/src/rules/evidence.ts:156`). It reads the same `logTexts`
map the loop already fills (lines 196–214) and uses the existing
`parseLogHeader(...).get("sella")`. It adds no new directory read and no
new parser.

- **Reach.** The loop walks only opera in
  `ACTIVE = {building, verifying, review}` (line 25). Those are exactly the
  opera whose reds can still be recorded again legitimately while the
  behaviour still fails. The filing asked for this walk and also expected
  the advisory to fire on the historical logs. Those two cannot both hold:
  W-028 is halted, and W-031 and W-036 are done, so on today's tree the
  rule reports **zero**. This brief resolves the contradiction in favour of
  the walk. An advisory that fires forever on three closed opera clears
  only by forgery or deletion. It is the `lesson.recurrent` noise class in
  a new place. The 16 headers are their own honest record, and a rule does
  not need to repeat them. If W-028 resumes to `building`, the rule fires
  on its four logs. That is the moment someone can act on it.
- **Scope within an opus.** Only the `<NN>.log` files for behaviours
  `1..N` that `opus.red_evidence` already resolves. `close-bugs-red.log`
  and similar files are off-contract, and a missing sella header is not a
  finding about a file that was never a red log.
- **Fires** when a log's header has no `sella` key, or has one whose
  trimmed value is empty or `guest`.
- **One finding per opus**, written as an object literal
  `{ rule: "opus.red_sella", level: "advise", where: "ci/reds/<id>/", message }`
  in the same shape as the other findings in this file. Behaviour 7's
  harvest reads that `rule: "..."` shape. The message:

  ```
  ${n} red log(s) record no sella: ${names.join(", ")}
  ```

  `names` are the basenames, sorted and comma-joined. One finding per
  condition, never one per file.

**Advise, not block. This is the load-bearing judgment.** Even on an active
opus, a guest red for a behaviour that is already implemented can never be
recorded again. A block there would leave only two exits, forgery or
deletion. Piece 1 stops the count from growing. The advisory flags the
cases piece 1 cannot see: an explicit `--sella guest`, a log written by a
pre-W-039 binary on a stale worktree, or a hand-made log.

## Behaviours to test

**Proving that a refusal writes nothing.** Behaviours 1 and 2 preseed
`ci/reds/<id>/` with a `01.log` (the target the call names) and a sibling
`02.log`, each holding known bytes. Before every refused call, the test
snapshots the directory's sorted listing and each file's bytes. After the
call, it asserts that the listing and every file's bytes are identical,
and that the marker file the command would have written does not exist.
Checking only that the directory is absent would miss a refusal that
overwrote an existing log.

1. With `$BISELLIUM_SELLA` deleted and no `--sella` (matrix row 1),
   `runRed` exits 2 and leaves the preseeded directory byte-identical
   with no marker. The same invocation with `--sella guest` (row 9) then
   records, and `01.log`'s header reads `# sella: guest`.
2. Every other refusal row of the matrix exits 2 and leaves the preseeded
   directory byte-identical with no marker. The rows are: env var set to
   `""`; env var set to `"  "`; `--sella ""` with the env var deleted;
   `--sella "  "` with the env var deleted; and
   `--sella builder-a --sella ""` with the env var deleted.
3. Every other recording row of the matrix writes the named sella into
   the header: env var `builder-b` alone gives `builder-b`; `--sella ""`
   with env var `builder-b` gives `builder-b`;
   `--sella "" --sella builder-a` gives `builder-a`; and
   `--sella builder-a` with env var `builder-b` gives `builder-a`.
4. `opus.red_sella` returns exactly one finding for a `building` opus
   whose `01.log` and `02.log` headers have no `sella` line:
   `level: "advise"`, `where: "ci/reds/<id>/"`, and message
   `2 red log(s) record no sella: 01.log, 02.log`.
5. `opus.red_sella` fires for a `# sella: guest` log and for an empty
   `# sella:` log, naming both. On the same fixture, it does not name a
   third log whose header reads `# sella: builder-a`.
6. `opus.red_sella` ignores off-contract logs. With a headerless `01.log`
   and a headerless `close-bugs-red.log` present, the message names
   `01.log` only, with count 1.
7. `opus.red_sella` reaches active opera only. It fires for a `building`
   opus with a guest red, and is silent for a `done` opus and a `halted`
   opus whose reds are byte-identical.

Every behaviour builds its own officina under `$TMPDIR`. Each assertion is
**positive**: it tests that a finding or refusal is present, with exact
content. A test that only asserts absence ("is silent", "never blocks")
passes before the code exists and cannot produce a red. That is why
"never blocks" is part of behaviour 4's exact-shape assertion rather than
a separate behaviour, and why behaviours 1, 5 and 7 pair their absence
checks with a presence check on the same fixture.

## Out of scope (pointers, not work)

- **Rewriting the 16 existing headers.** That is the forgery this opus
  exists to make unnecessary.
- **Surfacing the 16 through a rule over done or halted opera.** This
  brief declines it; see Reach. If the Patron wants it, the change is one
  state gate in this loop, and it needs its own decision.
- **Widening the refusal, or the empty-string fix, to
  `ready`/`done`/`review`/`halt`/`waive`.** A red log is permanent and
  cannot be recorded again. A gate can be re-signed (W-040). Refusing the
  common lifecycle verbs in a fresh officina is a regression for adopters.
  Widen it when an anonymous gate shows up on a real officina.
- **A state and ownership guard on `red`.** Today `runRed` will write into
  a `done` or `halted` opus's reds directory, including an explicit guest
  red that `opus.red_sella` never sees. W-033 left `red` out of its guard
  on purpose, so adding one is a contract change. It is filed as **W-058**
  under P-010.
- **Checking the `# sella:` value against the manifest's roster.** The
  rule reads `# sella:` and nothing else.
- **Other header classes.** `# command:` provenance and scratch-path
  operands are covered by W-048. `# tree: dirty:` headers and the
  tree-hash self-reference class (W-037 round 2) belong to the certificate
  rules. Reds recorded again in place (the W-037/W-041/W-044/W-049
  precedents) change nothing here: the rule reads whatever header is on
  disk now, and git keeps the previous one.
- **A hook that sets `$BISELLIUM_SELLA`.** The manifest's
  `hooks.default_sella: guest` already fills in guest for hook events.
  A hook that picked an identity would be the same anonymity with a
  better disguise.
