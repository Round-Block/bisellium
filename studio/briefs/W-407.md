## Intent

The shipped Inbox is a 320px selector and reading pane wide, but at 390px it stacks list and answer content into one long page. Its three actions are approve, decline and follow up, with `1`/`2`/`3` bound in that order. W-407 changes that mechanism in place; it adds no second queue, keyboard listener or write route.

The Patron's 2026-10-27 capture review rules Microsoft Outlook as the interaction reference on desktop and phone. At 840px and wider, a 320px needs-you list sits left of an independently scrolling reading/decision pane. The list does not move when long reading content scrolls. Below 840px the list fills the main pane; click or Enter opens the selected petitio as full-screen reading/decision content below W-415's shell row, and a visible Back control or Escape restores the same selected, focused row. The 840px boundary is the producer's call: after the existing gutters, it leaves 320px for the list and about 470px for legible reading; 640px would leave two panes under 300px each. Both list and reading panes use `overflow-y: scroll`, a stable scrollbar gutter and styled track/thumb so the vertical scrollbar remains visible rather than appearing only during scroll.

This opus amends DIRECTION §6 and its Arbitrium row to that Outlook layout. It explicitly supersedes the agent-written single-column/no-preview rationale and amber-row text from 5e5efd88. The amendment also records the Patron's 2026-10-28 rulings: first-notified dates, selected shade alone for focus, no Inbox colophon and the shared visible refresh. Inbox rows never use amber: every needs-you row already waits on the Patron, so an amber rule or date adds no distinction. Amber remains on the sidebar Inbox count. Severity colours are excluded until a separate producer-filed opus defines an authoritative severity source.

Rows are 68px Outlook-style summaries with adequate padding and a hairline divider. Line one puts the asker's mono sella id left and fixed en-GB/UTC first-notified date right; line two safely wraps an arbitrary subject to at most two 13/18 lines, then clips with an ellipsis. Missing or malformed time is `Date unavailable`. The selected row's lighter `wash` background alone marks selected-and-keyboard-focused; there is no underline, box or outline. Measured sRGB contrast is 1.21:1 between `wash` (`#343746`) and `surface` (`#282a36`), 11.06:1 between selected-row text (`#f8f8f2`) and `wash`, and 13.36:1 between text and `surface`. The full-row wash is visible and not obscured for WCAG 2.4.7/2.4.11, but its 1.21:1 state contrast does **not** meet WCAG 1.4.11's 3:1 non-text contrast threshold; this is the explicit trade-off the Patron accepted with the revision-f screens. A two-pixel verdigris left rule means unread only and disappears when the petitio is opened. Read state is a browser-local presentation fact, not an officina write.

The reading pane repeats the complete wrapping subject before the ask and caps reading text at 72ch. Subject, ask and Evidence scroll in `.inbox__reading-scroll`; a separate bottom action bar pins ratio, approve/defer/decline, disabled delegate and its note, and the key hint, at desktop and in narrow full-screen detail. The list remains still. A roughly 2,500-character ask with four paragraphs, bulleted and numbered lists and two evidence references proves the reading scrollbar and pinned bar.

The constrained safe-Markdown renderer turns consecutive `-`, `*` or `+` items into `<ul>` and `1.` or `1)` items into `<ol>`. Paragraphs remain prose, React escapes raw HTML, and every other Markdown construct remains inert text. Markdown links render as label text only in the ask, so raw `[label](target)` syntax never appears twice. The Evidence line contains each admitted target once. HTTP(S) evidence is an actionable anchor. Anchor and repository-relative forms render as selectable plain text containing their target and `Not available in this console`; they have no navigation action. Unsupported forms stay out of Evidence.

The queue remains one roving-tabindex listbox. `j` and `k` clamp, move selection and DOM focus, and call native `scrollIntoView({ block: "nearest" })`: there is no position marker, stable offset or smooth whole-queue slide. Wide reading follows selection. Narrow click or Enter opens detail; Back or Escape returns to the row. W-415 overlay Escape remains owned by the sidebar and does not close Inbox detail. After a successful answer, the clamped current index owns selection, reading content and ratio, and nearest reveal keeps that row visible.

`Store.api.needsYou()` keeps the producer's oldest-waiting-first call: dated rows sort by strict normalized opening instant ascending, equal instants retain native lexicographic filename order, and missing/malformed instants follow dated rows in that same order. Filtering and normalization already live in this response builder, so the adapter retains filename order and the view performs no second sort.

`1`, `2` and `3` remain approve, defer and decline. Approve and decline use today's sole `POST /api/answer` body `{ petitio, reply: "<verb>: <ratio>" }`; defer uses its existing ask-back shape `{ petitio, reply: "defer: <ratio>", askBack: true }`. Delegate remains visible, unkeyed, disabled and non-writing with `Delegation is not available yet` tied through `aria-describedby`. Until authoritative reads exist, `You asked` and `For information` are non-interactive labels with `Not available yet`, never invented numeric counts. Zero petitiones renders only `Nothing waiting on you`; the Inbox renders no source, generated-at, timestamp or “as of” colophon. W-406's Board and W-415's sidebar, 960 boundary, 640 zoom reflow and 390 shell row remain unchanged.

`useVisibleRefresh(refresh, intervalMs?)` is the one shared freshness mechanism and W-408's predecessor. Its 30-second default performs an immediate read only on a visible mount, reads on visible intervals, window focus and visibility change, skips hidden intervals, and cleans up all registrations on unmount. Inbox passes one stable `fetchInbox()` callback and admits only one in-flight read: simultaneous focus/visibility events coalesce, while an explicit post-answer refresh queues behind an existing read. After the first successful load, a failed background read retains the last response, selected id, open detail, DOM focus, both pane scroll positions and petition-keyed drafts; it changes only the read-failure notice, and recovery removes only that notice. Only a failed first load renders the empty read-failure state. A new id is absent from the local read set and therefore arrives unread. If an ordinary successful refresh removes the selected petitio, its reading snapshot and draft remain on screen with `This petitio no longer needs a decision.` and disabled submission until the Patron selects another row. Only a successful explicit answer advances automatically.

## Interfaces

The prototype is twelve commits after 27e39d31, paired `test(W-407): row b1, red` / `feat(W-407): behaviour 1` through b6, with non-numbered patch subjects and `ui-architect` co-author trailers. `/home/edckt/.bisellium-evidence/W-407-spec/rebuild-prototype.py` reconstructs it; `reds-host.sh` replays six assertion reds, predecessor-on-later-red greens and cumulative greens.

`Petitio.openedAt?: string` maps to optional `petitiones[].opened?: number` through strict `instant()`. `Store.api.needsYou()` sorts defined epochs ascending, breaks equal epochs by original snapshot index, and puts undefined epochs last by that index. Native snapshot index is lexicographic Markdown filename order. `datePresentation()` formats a finite epoch as day plus short month with `Intl.DateTimeFormat("en-GB", { timeZone: "UTC" })`; missing/non-finite is `Date unavailable`. No raw browser `Date.parse`, route, enumeration or package edge is added. `InboxResponse` gains only `opened?`; its top-level remains exactly `opera` and `petitiones`, with no absolute `studio` field.

`useVisibleRefresh(refresh, intervalMs = 30_000)` keeps the latest callback in a ref, invokes it on visible mount, visible interval, window `focus` and document `visibilitychange`, makes every hidden event a no-op, and clears its interval and both listeners on unmount. `Inbox.refreshInbox` is `useCallback`-stable, reuses `fetchInbox()` and holds an in-flight guard. A second ordinary event during a read coalesces; an explicit answer intent queues one follow-up read. The intent is captured when a request starts, so a stale in-flight ordinary read cannot consume a later answer reconciliation.

The first successful response becomes the retained snapshot. A later read failure mutates only `readFailed`; it never clears data, selection, detail, focus, scroll or keyed reasons, and the next successful read clears the notice. Before any successful response, failure sets `EMPTY` and renders the empty read-failure. An ordinary success retains selection by id without `focusRequest`. If that id is absent, `detachedPetition` retains its last reading snapshot and reason, `aria-selected` is removed from the live rows, the exact withdrawn notice is shown and every submit control is disabled. Selecting another live row clears the snapshot. Only post-answer intent uses same-index/reopen/nearest-reveal advancement.

`askText(body)` replaces lexical Markdown-link forms with label text. `askBlocks(body)` recognises blank-line paragraphs, unordered markers `-`, `*`, `+`, and ordered decimal markers ending `.` or `)`; it emits only escaped React text, `<p>`, `<ul>`, `<ol>` and `<li>`. Raw HTML is never interpreted. `evidenceLinks(body)` recognises HTTP(S), hash, `./`, `../` and `docs/`, `studio/`, `ci/`, `opera/`, `petitiones/`; it returns an `actionable` discriminator. Only HTTP(S) becomes `<a href>`. Every admitted non-HTTP form becomes selectable text with its literal target and exact unavailable note. Duplicate target keeps the first label. This is rendering only; no repository-serving interface is invented.

`INBOX_READ_STORAGE_KEY` is exactly `bisellium.inbox.read`; its value is a JSON array of non-empty petitio-id strings. `decodeInboxReadSet()` rejects missing, malformed, non-array or mixed/empty values to an empty set and deduplicates valid ids; `encodeInboxReadSet()` sorts ids for a stable value. `Inbox` wraps both `localStorage.getItem` and `setItem` in `try/catch`. A denied read or write renders all current rows unread. Opening means wide selection/read, narrow click or Enter; it adds that id locally and removes only its unread left mark. It never calls an officina route.

`Inbox` remains the only `submitAnswer` caller. Enabled verbs keep the same `petitio`, `reply` and optional `askBack` record shape. Delegate never calls it.
