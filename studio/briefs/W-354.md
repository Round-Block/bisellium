## Intent

High under D-039. W-339's PR #651 reached merge-group certify run 39546843889. Master's `scripts/ci-certify.mjs` selected the opus head, rebased it and invoked `bisellium run --sella builder`; the host runner discovered `/home/runner/.cache/ms-playwright` and logged that it was bound read-only at `/browsers`, but 43 of 44 served tests then failed before starting with `browserType.launch: Executable doesn't exist at /home/builder/.cache/ms-playwright/...`.

The log was true only about cache discovery and the descriptor returned by `browserMounts`; it did not identify the cell that later ran the gate. The complete hop is:

1. `.github/workflows/ci.yml` runs master's `scripts/ci-certify.mjs` from the tooling checkout.
2. `certify` calls master's `bisellium run`, which reaches `runBuilderCommand` and then `scripts/run-builder-host.mjs` with an absolute host browser path forwarded when one is set, or the runner's host-home fallback otherwise.
3. The builder cell and every red replay use `builderCell` or `replayCell`; both already apply `browserMounts`, so both carry the read-only bind and `PLAYWRIGHT_BROWSERS_PATH=/browsers`.
4. After red replay, the **producer CI/verify/check recomputation** does not use either descriptor. It hand-builds a third cell at `run-builder-host.mjs:818-850`: candidate/home/tmp binds, tooling and private-etc read-only binds, and eight environment names including `NODE_PATH`, but no `/browsers` bind and no `PLAYWRIGHT_BROWSERS_PATH`. This is the loss.
5. That cell runs master's `bisellium ci --offline --opus W-339`. `runVerify` adds the reserved `served-e2e` gate for a `kind: ui` opus; `localPipeline`'s `filterEnv` removes secret-shaped names only, so it would preserve `PLAYWRIGHT_BROWSERS_PATH`; `runWatched` passes the filtered environment to the gate shell.
6. `scripts/served-e2e.mjs` spawns `npm --workspace @bisellium/web run test:serve` with `{ ...process.env, BISELLIUM_SHOTS_DIR }`; npm starts `playwright test`; `playwright.serve.config.ts` does not replace the browser path. The served harness's later Node spawns are web servers, not the browser launcher. No spawn after the producer cell drops the name.
7. The installed `@playwright/test` and `playwright-core` are both 1.63.0. Their `browsers.json` requests Chromium and chromium-headless-shell revision 1243, and the inspected host cache holds revision 1243 plus ffmpeg 1011. There is no measured revision mismatch in this checkout.

After this opus, the producer-gates descriptor is built by new pure `producerCell`: it derives the whole `replayCell` descriptor, then adds only the immutable `/tooling` read-only bind and `NODE_PATH=/tooling/node_modules`. Thus every current host-runner candidate-code cell routes through a browser-aware builder: `builderCell` for the builder, `replayCell` for replay preparation/replay, and `producerCell` through `replayCell` for the final gates. A cache that resolved on the host is mounted read-only and selected in the producer gate; an absent cache still adds neither.

This fix belongs at the cell construction boundary, not in `ci-certify`, `bisellium ci`, the `served-e2e` gate or Playwright config: those are later callers, and changing one would leave the hand-built producer cell capable of drifting again. It is a host-runner fix and lands alone before W-339 is requeued, because certify executes master's tooling (W-178/W-323).

Threat model: mistakes and descriptor drift, not adversaries (D-045). The cache remains read-only and no namespace, egress, writable bind or candidate-selected host path changes.

2. Producer gate construction (`run-builder-host.mjs`, narrowed). The removed inline descriptor has no second copy of binds or environment names.

3. Downstream environment hand-off (inspected, unchanged). `filterEnv(process.env)` preserves `PLAYWRIGHT_BROWSERS_PATH`; `runWatched` passes it; `served-e2e.mjs` spreads it into npm; npm/Playwright inherit it; neither Playwright config nor its global setup constructs a replacement environment. This trace explains why no second production edit is needed. It is unchanged code and therefore a stated limit under D-076 E, not a new guarantee.

4. Browser revision (inspected, unchanged). `playwright-core` 1.63.0 requests revision 1243 and the inspected cache carries `chromium-1243` and `chromium_headless_shell-1243`. Selection of the correct executable is Playwright's contract once it receives `/browsers`; installation, cache completeness and future dependency revisions are outside this change.

Promise producer-browser-pair: whenever the host runner resolves a browser cache, the producer CI/verify/check `sandboxArgs` receives both its read-only bind at `/browsers` and `PLAYWRIGHT_BROWSERS_PATH=/browsers` from one descriptor — limit: whether the directory contains every executable the installed Playwright revision needs is not inferred from directory existence.

Promise producer-reuses-replay: producer gates inherit the replay cell's candidate/home/tmp binds, private-etc read-only binds, working directory and seven base environment names, then add only immutable tooling and `NODE_PATH` — limit: `sandboxArgs`, bwrap, system mounts and the existing replay descriptor are reused unchanged and are stated limits, not re-proved here (D-076 E).

Promise cache-absent-unchanged: when host cache discovery returns `undefined`, `producerCell` adds no `/browsers` bind and no Playwright browser-path name, while every non-browser producer descriptor field remains present — limit: the resulting served gate is expected to fail normally; this opus adds no install, fallback or new diagnostic.

Promise one-producer-builder: the producer recomputation has one descriptor construction in the host-owned module and the runner spreads that complete descriptor into its one bwrap launch — limit: source-level wiring proves construction and use without launching bwrap; the merge queue's certify run on the landed fix proves the real host mount, environment and browser launch together.
