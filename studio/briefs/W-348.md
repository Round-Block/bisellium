## Intent

D-091 changes only the UI lane's spec pair: Codex `gpt-5.6-sol` drafts, prototypes and signs with the ui-lead's Astra input, and Claude `claude-opus-5-5` reviews. Engineering keeps the design magister's signature and Codex Sol review; every build review stays a fresh Codex Sol session. Today the signer is inferred from the design magister in next's signature readers, writer ledger check, retro and brief-stale, while the reviewer and its model are fixed by `spec_reviewer` and `REVIEWER_MODEL`.

The design adds one atomic UI override to the manifest: `ui_spec_signer` and `ui_spec_reviewer`. Both absent preserve the existing pair for adopters; once either is present, both must name distinct live agent seats. The signer is exactly Codex `gpt-5.6-sol` on `codex`; the reviewer is exactly Claude `claude-opus-5-5` on `claude-code`. The real studio declares `ui-architect` and `ui-spec-reviewer`. This is configuration rather than a `kind === "ui"` model hard-code, so all readers share the same seat ids and D-091 is visible in the studio contract.

Next uses the selected signer for every signature reader, re-sign order, ready attribution, prototype-red attribution and later class-loop signature, and uses the selected reviewer and model for review. Verdict, retro and brief-stale select through the same atomic classifier in the studio each already inspects. Next keeps today's record and manifest selection for kind and pairing; making both come from the record that owns spec evidence and failing closed on an absent, unreadable, malformed or non-mapping owner record is W-355, not a promise of this cut.

Threat model: mistakes, not adversaries (D-045).

## Interfaces

1. `readUiSpecPairing(manifest)` (verdict, new export) returns `{ pairing: undefined }` when both UI keys are absent; otherwise it returns `{ signer, reviewer: { sella, model, design: signer } }` or one `error` prefixed `bisellium.yml#ui_spec_signer/ui_spec_reviewer:`. It counts every matching `sellae` row, and requires distinct, live `kind: agent` seats: signer model/harness `gpt-5.6-sol`/`codex`, reviewer `claude-opus-5-5`/`claude-code`.
2. `readSpecReviewer(manifest, record)` (next, extended) returns `{ signer, reviewer }`. It recognises `record.kind === "ui"` exactly and a present UI pair; every other kind, and a UI record with both override keys absent, uses the design magister plus `spec_reviewer`. Gate-state handling is unchanged: `greenlit` takes the reviewer; a past-ready trunk state returns the selected signer and no reviewer. The caller's current manifest/record selection is unchanged and is only a stated limit; W-355 owns evidence-owner selection and its fail-closed record read.
3. Next's spec sequence uses that selected signer wherever it formerly used the design magister: `readSpecSignature`, `signedSpec`, `reviewedSpec`, `failedSpecReviews`, the initial and failed-review dispatches, ready attribution, `signedAfter`, `classLoop` and the replayed-red sella. The selected reviewer carries its own string model into `readSpecReview`, the order's `model` line and record command. The ui-lead input remains outside this strict sequence as W-338 defines.
4. `runVerdict` (verdict, extended) still validates the design row for every plain spec verdict, then selects the UI signer through `readUiSpecPairing` on `kind: ui`; only that sella is checked by `promiseLedgerProblems`. The design magister and reviewer remain plain verdict writers but owe no signer ledger.
5. `readOpusVerdicts` and `reviewRounds` (retro, extended) skip the selected signer's spec log as a signature. `readOpusVerdicts` fails on an unreadable requested record; `reviewRounds` preserves its historical limit by falling back to the design magister when an old measured log has no readable opus record.
6. `checkBriefStale` (extended) selects the UI signer before it searches passed spec logs. An invalid atomic pair emits one blocking `brief.stale` finding at the UI opus record; a valid pair keeps the rule advisory.

The forms the pairing classifier recognises, one per line:

- `kind: ui` exactly selects the UI override when present — as pinned by `W-348-b1` "kind ui selects the configured UI signer and reviewer"
- every other `kind` text, including absent, differently cased and unknown values, is a limit and selects the existing design-magister/`spec_reviewer` pair — as pinned by `W-348-b1` "every other kind keeps the design magister and spec_reviewer"
- both UI keys absent preserve the existing pair — as pinned by `W-348-b1` "both UI keys absent preserve the existing pair"
- both keys present as non-empty strings name the exact seats described above — as pinned by `W-348-b1` "kind ui selects the configured UI signer and reviewer"
- every other key form is rejected: only one key, a non-string or empty value, no seat, duplicate seat, retired seat, non-agent seat, wrong harness, wrong model, or the same seat for both roles — as pinned by `W-348-b1` "the refusal names the cause"

Promise pair-route: a `kind: ui` opus is signed and re-signed only by the Codex UI signer selected by the caller's existing manifest and record inputs and reviewed only by its configured Claude UI reviewer; every other kind keeps the design magister and engineering reviewer — limit: next's existing source selection for those inputs is unchanged; W-355 will make it follow the record that owns spec evidence and fail closed on a bad owner record. A caller's `# sella:` and `# model:` headers are claims, not proof of the process that produced them.

Promise atomic: a partial or unsuitable UI pair never falls back after either key is present: next and verdict refuse, and brief-stale blocks — limit: other commands that do not read spec roles may accept unknown manifest keys; this opus changes only the named consumers.

Promise history: retro never treats the configured signer's notes as review findings or a review round, and brief-stale anchors on that signer — limit: `reviewRounds` keeps the design-magister fallback for a historical log whose opus record is absent or unreadable, because record validity was not previously in that measurement's domain.

Promise engineering: non-UI signature and review selection is unchanged — limit: unchanged parsing and sequence code is a stated dependency, not a guarantee (D-076 E): `parseVerdictLog`, `parseLogHeader`, `readSequence`, `readSpecSignature`, `readSpecReview`, `promiseLedgerProblems`, `readOpus` and `readContainedRegularFile`.
