## Intent

On 11-09 Codex 0.167.0 could not start its read-only shell inside our sandbox, and a reviewer that read no file wrote `VERDICT: PASS`; `verdict` recorded it. A fix check from the same failure wrote "Unable to census" and `next` counted its `Not determined` line as an open path. This opus makes every path that records a Codex review prove, from Codex's own structured record, that the turn which gave the review ran a command: a turn that did not is failed-to-run, never a verdict and never a fix check.

1. **The review and fix-check performs judge their own turn (behaviour 1).** Each reads the `codex exec --json` stream it already holds (`turn.raw.stdout`); with no command run to exit 0 it writes `failed-to-run.json` in its packet and holds, recording nothing. The fix check also holds on a census that names itself unrun.
2. **`verdict` judges the session it is given (behaviour 2).** A verdict with `--session` whose `--model` the manifest seats on the codex harness reads that session's rollout under Codex's home; with no command run to exit 0 in its last turn, or with no single readable rollout, it refuses (exit 2) and writes nothing. The performs pass their own judgment instead (`VerdictOptions.turnRan`).
3. **The verdict boundary's own inputs are judged or stated (behaviour 3, revision 2).** A manifest whose `sellae` is not a list of mappings, has a non-string `harness` or a codex row with no model (a harness string other than exactly `codex` is not judged: W-568), a caller's turn judgment in any form but `TurnRan`'s two, and a Codex home that is empty or relative are each refused (exit 2) before anything is written; every other input the new code reads is closed or a stated limit (`census-inputs.out`).

**The closed signal, read from real logs** (`signal.out`, `judge-real.out`). Codex writes two structured records of a turn, and both name each command it ran as an item with a status and an exit code; the prompt, the reply and a command's output are string fields inside other items, so no quote in them can add or remove one. In the `codex exec --json` stream (the performs'): a top-level `item.completed` event whose `item.type` is `command_execution`, `item.status` `completed`, `item.exit_code` 0. In the rollout `<CODEX_HOME>/sessions/YYYY/MM/DD/rollout-<time>-<session>.jsonl` (written for every `codex exec`, text or JSON mode, start or resume; the by-hand reviews' only structured record): an `event_msg` whose `payload.type` is `item_completed`, `payload.turn_id` the last `task_started`'s, and `payload.item` a `CommandExecution` with `status` `completed` and `exit_code` 0. "Shell failed" and "ran no repository command" are one signal: Codex 0.167.0's sandbox failure never starts the command, so the turn holds shell calls and no command item (W-558 r4's last turn: 11 calls, 0 commands; fix-2: 14 and 0; smoke A: 2 and 0; smoke B: 1 and 0), while every passing round holds commands (pin smoke 2, r8's last turn 6, fix-1 30, fix-2 rerun 23). The last turn, not the session, is judged: r4 resumed round 2's session, whose first turn ran 12 commands.

**Every site that turns a Codex review into a pass** (`census.py` at master 498077fa, `census.out`): Codex runs in the review perform (`next.ts:2810`), the fix-check perform (`next.ts:2941`) and `scripts/censor.sh` (text mode, recorded by `scripts/record-review.sh` through `verdict`); every other Codex run is a kept evidence script that reaches the officina only through `verdict` (776 scripts under `~/.bisellium-evidence`, none writing a record). Records are written by `runVerdict` (the perform's in-process call, `next.ts:2822`, and the CLI, `main.ts:130`) and by `runReview` (`next.ts:2851`, `main.ts:129`), which records only beside a verdict log `verdict` wrote. Fix checks are written by the fix-check perform (`check.json`, `next.ts:2952`) and read by `readFixCheck` (`next.ts:1947`). So the refusal sits in `verdict` (every by-hand and perform verdict) and in the two performs (their own turn, and the fix check, which writes no verdict).
