## Survey: what is already true, measured 2026-09-25

### What the SSE stream actually carries

Measured in `packages/core/src/differ.ts`, `packages/core/src/store.ts` and
`apps/server/src/http.ts`:

- `GET /api/live` writes `data: ${JSON.stringify(e)}\n\n` per event the
  server's own `Store.ingest` emits, plus `: connected` once and `: heartbeat`
  every 15s. Comment frames never surface through `EventSource`.
- A frame is a `GantryEvent`: `{ id, name, ts, projectId, attrs }`. The names
  the differ can produce are `workflow.item_appeared`, `workflow.state_changed`,
  `workflow.gate_evaluated`, `workflow.actor_assigned`, `workflow.item_removed`,
  `workflow.attention`, `workflow.digest`, `provider.status`.
- **The attrs are identifiers, not a payload.** A `state_changed` frame carries
  `workflow.item.id`, `state.from`, `state.to`, `department`, `source`,
  `source.seq`, `time.derived`. There is **no title, no sella, no tokens, no
  traditio, no gate name** on any frame.
- **`workflow.time.derived` is `true` on every differ event** and `ts` is the
  poll's observation time.
- **The stream fires only on the poll** (`setInterval(pollMs)`, default 5000).
- `store.api.*` re-reads the studio's files per call and caches nothing.

### What the stream does NOT invalidate (ui-lead finding 2, verified)

`diffSnapshots` emits on exactly four opus conditions: the item appearing, its
`state` changing, a gate's **status or `certifies`** changing
(`differ.ts:41`, `gateChanged`), and `sella` becoming a **new non-undefined**
value (`differ.ts:113`). Therefore the following change on disk and produce
**no frame at all**:

| Change | Displayed where | Why no frame |
|---|---|---|
| `title` edited | every card, drawer header | not diffed |
| `tokens` edited | drawer record slot | not diffed |
| `traditio.next` / `blocked_on` edited | drawer record slot | not diffed |
| a gate's `evidence` **href** changes, verdict unchanged | drawer gate row | `gateChanged` deliberately ignores href-only changes |
| `sella` **removed** (set to undefined) | card third line | `differ.ts:113` requires `nextSella !== undefined` |

A disconnected client additionally misses every frame in the gap: **SSE has no
replay** — `handleLive` writes `: connected` and then only live frames
(`http.ts:492-504`), with no `Last-Event-ID` handling and no backlog. And
revision 1 fetched the drawer's events **only on selection**, so an open drawer
never refreshed.

**Consequence: refetch-on-frame is necessary and not sufficient.** The brief no
longer claims otherwise. See *Liveness: what is actually guaranteed*.

### `/api/events` semantics, corrected (ui-lead finding 4, verified)

Revision 1's survey was wrong on both counts. Measured:

- `clampedLimit` returns `undefined` when the parameter is **absent**
  (`http.ts:538`), and `store.api.events` then passes
  `Number.MAX_SAFE_INTEGER` (`store.ts:396`). **An omitted `limit` is
  unlimited**, not 500. The `[1,500]` clamp applies only to a *supplied*
  value.
- `Index.events(since, limit)` selects `ORDER BY seq` **ascending** and
  `break`s at `out.length >= limit` (`index-db.ts:535-552`). **A supplied
  limit returns the earliest matching rows**, not the latest. Revision 1's
  "X's last two" contradicted the route it claimed to preserve.
- `/api/events` reads **the Index**, and the Index is fed by
  `apply(this.log)` at Store **construction** plus each `ingest()`'s own
  diffed events (`core/store.ts:175`, `:225`). An event appended to
  `events.jsonl` by any other writer — `bisellium emit --usage`, and every
  `writes.ts` `emitEvent` including the ones the server's own POST routes
  run in-process — **never enters a running Index**. `rebuildIndex()` exists
  and nothing outside `packages/core/src/index.test.ts` calls it.
  Measured: `studio/.bisellium/events.jsonl` holds **48 `gen_ai.usage`
  events**, so this is live, not hypothetical.
- **`since` over HTTP is numeric only**, and revision 2 got this wrong in the
  other direction — it promised "numeric seq or ISO string". The route passes
  the raw value through `num()` (`http.ts:638`, `num` at `:545`), which returns
  `undefined` for anything not finite, so **an ISO-string `since` is silently
  discarded and the response starts from the beginning of the log.**
  `Index.events` does accept an ISO string (`index-db.ts:546`) and compares it
  lexicographically, but **Index support is not HTTP support** — nothing threads
  a string through the route. Corrected in *Interfaces* and pinned by
  behaviour 10 so the real behaviour is written down instead of inferred.

This is why the item-filtered path below reads the log fresh instead of the
Index, and why *Drawer data sources* qualifies the token split.

### What the Board needs that the server does not yet give

1. **The state → phase mapping is server-side only.** `adapters/native/src/index.ts:38`
   declares `STATES` (`backlog→backlog`, `greenlit→planned`, `building→in_progress`,
   `verifying→verifying`, `review→awaiting_review`, `done→done`, `halted→halted`);
   `describeLifecycles()` returns it; **no route exposes it**. `apps/web`
   depends on neither `@bisellium/schema` nor `@bisellium/adapter-native`
   (measured in `apps/web/package.json`), and hand-copying seven state ids into
   the web tree is W-041's lesson and CLAUDE.md's "never by hand".
   → `/api/officina` gains `lifecycle`.
2. **`/api/events` cannot be asked for one item**, and what it can be asked
   for is Index-backed and therefore stale for externally-appended events.
   → `/api/events?item=`, served from a fresh log read.
3. **The web's own types are wrong against the wire.** `OpusEntry.probationes`
   is `Record<string, { status: string; evidence?: string }>`; the wire carries

   `{ id, kind }[]`; the wire carries `name` too. See *Not "append-only"*.

Nothing else is missing. `/api/opera` already returns `title`, `kind`,
`collegium`, `sella`, `state`, `tokens`, `probationes`, `traditio` per row, so
**this opus never calls `/api/opus/:id`**. `/api/inbox` already returns
`petitiones: [{ id, opus, from, subject }]` — the join the drawer's banner
needs.

## Liveness: what is actually guaranteed

Three mechanisms, each doing one job. Together they are the invalidation
contract; separately none of them is enough, which is the finding-2 correction.

**(1) Reconciliation — a full refetch of `/api/officina`, `/api/opera`,
`/api/inbox`, **and the selected item's events when the drawer is open**.** It
runs on **initial subscription** and on **every (re)connect** of the
`EventSource`. This is what covers the no-replay gap: a client that was
disconnected does not ask what it missed, it re-reads the world. `EventSource`
reconnects on its own; the Board does not suppress or re-implement that, it
hooks `onopen`.

**The drawer is part of the reconciliation set, not just of mechanism (2)**
(ui-lead closure, finding 2 reopened). Revision 2 refreshed the drawer only on a
**matching frame**, so a drawer left open across a disconnect missed every event
emitted while the client was gone and stayed wrong after reconnect — the exact
gap reconciliation exists to close, reintroduced one level down. The
reconciliation set is therefore a function of the selection, not a constant:
`reconcileTargets(selected)`, specified in *Interfaces* and asserted in
behaviour 3, so a builder cannot drop the fourth fetch without a red.

**(2) Frame-driven refetch.** A frame passing `boardNeedsRefetch` schedules the
same refetch through a **single trailing timer**, so one poll delivering fifty
frames issues one refetch. **And when the drawer is open, a frame naming the
selected item also refetches that item's events** — revision 1's open drawer
never refreshed.

**(3) The stated policy for fields with no invalidation.** The five rows in
*What the stream does NOT invalidate* update on the **next reconciliation**,
i.e. on the next (re)connect, and **not before**. This brief says so plainly
rather than implying they are live. It is not fixed by lowering `--poll-ms`,
because the poll produces no frame for them at all. Fixing it properly means
either diffing those fields in `packages/core/src/differ.ts` — a change to the
shared wire contract, not this opus's to make — or a client heartbeat refetch,
which is a poll by another name and is deliberately not built (it would also
destroy behaviour 7's ability to prove transport dependence). **Named as an
unfiled gap** in *Out of scope*; revision 2 said "filed as a follow-on" here and
"unfiled" there, which the ui-lead caught. **Unfiled** is the true one: no opus
exists.

**What the brief therefore claims, and no more:** state changes, gate verdicts,
owner assignment, item appearance/removal and attention changes reach the Board
within one poll interval; everything else reaches it on the next reconnect;
nothing displayed is ever older than the last reconciliation, and the liveness
label reports **both** the connection state and the last successful refresh so
the operator can tell the two apart (ruling 10).

## Composition: desktop and phone

The Patron rules from a phone. This section is a specification, not a
consequence.

**Desktop (≥900px).** Columns are a fixed 288px (§3) in a horizontally
scrolling row. The needs-you column is **sticky-left** against that scroll
(ruling 7: "first" alone does not satisfy "pinned"). Fixed width is chosen over
flex because §3 states a density target, not because it is required for ladder
alignment — the ui-lead is right that alignment comes from the ladder's own
fixed mark geometry, so the false binary in revision 1 is withdrawn. The
drawer is 540px, right-aligned, over a board that stays mounted and live.

**Tablet (600–899px).** Columns keep 288px and keep scrolling; the needs-you
column **unpins** (sticky at 288px of an 800px viewport costs more than it
returns) and simply leads the track. The drawer is `min(540px, 100vw - 72px)`,
leaving the rail's 72px visible.

**Phone (≤599px).** The existing `w025.css` breakpoint, where the rail already
becomes a top row.

- The board is a **horizontal scroll-snap track of full-width columns** — one
  column at a time, `scroll-snap-align: start`, so a swipe lands on a column
  and never between two. A 288px pinned column on a 390px phone would consume
  74% of the width, so **nothing is pinned here**.
- **Initial visible content** is the needs-you column **when it has cards**,
  and the `in_progress` column otherwise. An empty attention column is never
  the first thing the Patron sees ("empty on a good day" must not mean "a good
  day shows you nothing").
- **Later columns** are reached by swiping the track, and by a **column-name
  strip** above it: one tappable name-and-count per column that scrolls its
  column into view. Swipe alone is not discoverable, and the strip doubles as
  the board's overview on a 390px screen.
- The **drawer is full-width** (the canvas's 540px exceeds the viewport), and
  its **close control sits in the header at a ≥44px hit target, reachable
  without scrolling** — the header is the drawer's first element and does not
  scroll away.
- **No information is hover-only** (ruling 17): every gate's status is printed
  as a word in the drawer's gate rows. The ladder's `title` attribute is a
  desktop convenience, never the only carrier.

Behaviour 9 asserts all of this from a real 390×844 viewport, following W-065
behaviour 15's precedent.

## Keyboard (DIRECTION §5, ui-lead finding 7)

Revision 1 deferred this to a follow-on. That was a deletion of an explicit
contract, so it is withdrawn and specified.

- Each column is a `role="listbox"`; each card is a `role="option"` with
  **roving tabindex** (exactly one `tabIndex=0` per column).
- **`j` / `ArrowDown` and `k` / `ArrowUp`** move focus within the focused
  column. They **stop at the ends** — no wrap, because a wrap on a
  seven-column board is indistinguishable from a jump.
- **`ArrowRight` / `ArrowLeft`** move to the nearest card in the next /
  previous **non-empty** column, preserving the row index where one exists.
  `Tab` continues to move between columns natively.
- **`Enter`** opens the drawer for the focused card. **`Esc`** closes it and
  **returns focus to that card**.
- **Focus restoration on removal.** If the selected card is removed or changes
  column while the drawer is open, the drawer closes and focus lands on the
  nearest remaining card in that column, or on the column head when the column
  is now empty. **Never `document.body`.** This is the case the ui-lead named
  and it is the one a naive implementation always drops.

Board scroll offset is snapshotted on open and restored on close (§5, "Drawer,
never modal").

## Drawer data sources (ui-lead finding 5)

Revision 1 promised a petitio subject no type carried and no fetch provided,
and a token split that could be silently stale. Both are now sourced.

- **The needs-you banner** joins `/api/inbox`'s `petitiones` on
  `petitio.opus === opus.id`. When a petitio exists, the banner shows its
  `subject` and `from` and links to that thread. When a human gate is pending
  with **no** petitio, the banner shows the gate's name alone and says so —
  it does not invent a question. `/api/inbox` is fetched with the other two on
  every reconciliation, so the join is as fresh as the rest.
- **The event list and the token split** come from `/api/events?item=<id>`,
  which is served from a **fresh read of `events.jsonl`**, not from the Index
  (see the survey). This is what makes the 48 existing `gen_ai.usage` events —
  and any appended while the server runs — actually reachable.
- **The token split is labelled event-derived** and carries the item's
  front-matter `tokens` total beside it. When the two disagree, **both are
  shown with their sources named**; the split is never presented as the
  authority, because a sella that never emitted a usage event contributes
  nothing to it. Ruling 14's "qualify incomplete event-derived totals".
- **Dollar cost is omitted** — no price table exists.

### `GET /api/events` — unfiltered path unchanged, filtered path specified

**Unchanged, and documented as it actually is** (finding 4): an **omitted**
`limit` is **unlimited**; a **supplied** limit is clamped into `[1,500]` and
returns the **earliest** matching rows in ascending `seq` order; `since` is an
exclusive **numeric** seq.

**`since` stays numeric-only, and the brief is corrected rather than the route
widened** (ui-lead closure, finding 3 reopened). Revision 2 wrote "numeric seq
or ISO string", which is true of `Index.events` and false of the route: `num()`
discards any non-finite value, so **`?since=2026-09-25T00:00:00Z` is silently
treated as absent and the response starts from the beginning of the log.**

Chosen deliberately, and it is the smaller of the two honest options. Widening
the route to thread a string would change a route this opus has promised to
leave byte-for-byte alone, for a capability **no caller wants** — the Board
resumes nothing, and the drawer's path refuses `since` outright. Refusing a
non-numeric `since` with a `400` would be the better contract, but it is equally
a behaviour change to an existing route and it belongs with whoever needs it.

**The ceiling, named rather than smoothed over:** silently discarding a
malformed `since` is a real if minor defect — a caller who passes a timestamp
gets the whole log and no error. Behaviour 10 **pins that behaviour as it is**,
so the defect is written down and a future opus that fixes it has a test to
change on purpose rather than discovering it. Listed in *Out of scope* as an
unfiled gap.

**New, `?item=<id>`:**

- **Source: a fresh read of `<studio>/.bisellium/events.jsonl`**, not the
  Index — because the Index misses every externally-appended event for the life
  of the process (survey). `readLog` from `@bisellium/core` is reused;
  `apps/server` already depends on it. **Side-effect free**: it touches neither
  the Index nor any `Store` state, so a read route stays a read route.
  `ponytail:` a full log read per item query; tail incrementally if the log
  ever outgrows a single read (614 lines today).
- **Ordering: ascending**, same as the unfiltered route, so one route never
  returns two orderings. Display reversal is the client's, in `drawerDetail`.
- **`limit` on this path means the LAST N**, then returned ascending — the
  in-house precedent is `Index.timeline`'s own
  `out.slice(Math.max(0, out.length - limit))` (`index-db.ts:523`), five lines
  above `events()` in the same file. A drawer wants an item's recent history,
  never its oldest. An **omitted** limit returns all of that item's events.
- **`item` combined with `since` is refused `400`.** `since` exists for
  resuming the whole stream by the Index's `seq`; this path does not read the
  Index, so its rows carry **no `seq`** and there is nothing to resume from.
  Refusing is the honest answer and removes the footgun of a positional index
  masquerading as a resumable cursor.
- An unknown or unsafe `item` answers `200 []` — never a 404, never a throw.

## Recording the reds

Pinned before any evidence is produced. **D-024 exists because a builder
deviated from a prescribed recording state on W-071, and P-012 — the
working-tree-identity mechanism — has not landed. Prescription is therefore the
only guard, and this section is binding.** Revision 1's prescription was
internally inconsistent and overclaimed; the ui-lead's finding 8 is accepted in
full and it is rewritten here.

### The exact sequence, in the working tree

Per module group, and **not** per behaviour:

1. Write the module(s) into the **working tree** as skeletons. Do not commit
   anything for the sake of the red — the sequence below is about the working
   tree, which is what the test actually runs against.
2. Write the test file with **every** assertion for **every** behaviour that
   module group backs.
3. Record **all** of that group's reds against that one skeleton state, with
   `bisellium red`, before implementing any of them.
4. Only then implement, and commit.

The groups, stated so shared-module ordering is unambiguous (finding 8):
`lib/board.ts` backs behaviours **1–4** — all four reds are recorded against
the one skeleton state. `BoardView.tsx` + `BoardDrawer.tsx` back **5–6**.
`tests-serve/board.spec.ts` backs **7–9**. `apps/server/test/board.test.ts`
backs **10**. `usage.test.ts` backs **11**.

### Skeletons return wrong values; they never throw

A `throw new Error("not implemented")` produces a **stack trace**, not an
assertion failure, and `opus.red_content` wants assertion-level evidence. So
every skeleton export returns a well-typed zero value — `[]`, `""`,
`undefined`, an object with its required fields at their zero values — and the
test's own `check(...)` lines report `FAIL`.

**Consequence a builder must honour:** a behaviour whose assertions are all
*negative* (an emptiness or absence check) would **pass** against a zero-valued
skeleton and produce no red. Behaviour 5's "no `<img` tag", "no `box-shadow`",
"no 999px" family is exactly that class. Every behaviour must therefore contain
at least one **presence** assertion — a column head, a card, a gate row, a
count — which a zero-valued skeleton fails. Check this before recording, not
after.

### What the artifacts can show, and what they cannot

`bisellium red` records `# exit`, `# at`, `# sella` and `# tree` (a
`dirty:<sha>` when the tree is not clean — see `studio/ci/reds/W-065/09.log`).
The check rules verify: the log exists, its `exit` is non-zero, it is not an
`ERR_MODULE_NOT_FOUND`-class module-load failure, it is not byte-identical to
another behaviour's log after header strip, and it names a sella.

**Revision 1's claim "each `at` earlier than the first commit touching the
corresponding source file" is struck.** It is unenforced by any rule, and it
contradicted step 1 above: a skeleton that has been committed makes every red's
`at` *later* than a commit touching that file. Replaced by what the artifacts
genuinely show, and nothing beyond:

- non-zero exit, assertion-level (a `FAIL` line, not a stack, not a
  module-load error)
- eleven distinct bodies
- a named sella per log
- the `tree` header's recorded base identity

**Stated plainly: these artifacts cannot prove that an implementation was never
written and then removed.** That is precisely P-012's gap and D-024's kill
condition, and this brief does not pretend otherwise. What remains is the
prescription above, which is binding as spec: implementing a behaviour,
verifying it green, stubbing it back and recording the red against the stub is
**forbidden here whether or not it is detectable**. A builder who has already
done it **discloses it** rather than recording it — disclosure is what made
D-024 a waiver instead of a lesson in deception.

### Argv slots

`apps/web/src/lib/*.test.ts` take the repo path at `argv[2]` and the behaviour
at `argv[3]`. `apps/web/test/*.test.ts` take the behaviour at `argv[2]` and no
repo path (hence `--cwd apps/web`). `apps/server/test/board.test.ts` follows
`argv[2]` repo + `argv[3]` behaviour. Playwright specs select by title with
`-g`, never argv. **A red through the wrong slot runs the whole file and is
void.** Behaviours 5 and 6 share one file and 7–9 share another, so a red
recorded without its selector covers two behaviours at once and is void twice
over.

Behaviours 7–9 need `apps/web/dist` **built** before their reds are recorded,
or the failure is "no dist" — one environment failure, not an assertion-level
red. Build first; the red then fails on the missing Board route.
