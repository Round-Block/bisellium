A spec's "stale handover" hold can mask an invalid architect signature (W-275): sign with findings lines `n. advisory — … — check: …` or `No findings`, since `verdict` accepts prose findings on a passed spec but `next` refuses them. Uncommitted tracked edits in the main checkout stop the spec and merge performs from fast-forwarding master: set them aside with a tagged `git stash push -m <tag> -- <paths>`, rerun the perform, `git stash apply <sha>`, drop by tag. A merge perform that prints `QUEUE_TIMEOUT` while the PR is still queued is rerun with `--poll-ms 20000 --max-polls 150`. Code-owner review gates only PRs touching `.github/`, `.claude/`, `studio/leges/`, `studio/decisions/`, `studio/bisellium.yml`, `studio/prompts/`, `docs/ADOPTION.md`, `scripts/ci-certify.mjs` (auto-merge is always safe; pushing dismisses an approval). The Status page's live version carries edits the build lacks, so its republish needs the Patron until W-283 serves the page. A red's selector must hold no whitespace (`red` refuses it; use `'^W-<id>-b<n>\s'`). A red must fail by assertion, never ENOENT or module-not-found (the host replay refuses it). The mint runs from the opus worktree with `--studio studio --repo .`. After pushing to a code-owner PR, re-request the Patron's review (`gh pr edit <n> --add-reviewer edckt`). Never merge master into an opus branch: certify replays the branch onto master and a merge commit re-conflicts; rebase instead (`pr` refuses it). A queued PR shows no auto-merge request: check `isInMergeQueue` (gh api graphql) before touching it. If an approved PR sits CLEAN and `isInMergeQueue` is false, toggle `gh pr merge <n> --disable-auto` then `--auto`; records PRs use `gh pr merge --auto` without `--squash`.
