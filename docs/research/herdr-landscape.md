# Herdr landscape

**Watch the Herdr orchestration platform; adapt the separate Herdr multiplexer’s local socket shape for W-046, but integrate neither product now.** Herdr-platform names useful runtime concerns, especially fleet visibility, but it does not replace Bisellium’s organization, authority, or evidence semantics. The multiplexer is the narrower and more actionable comparison: its agent start/prompt/read API is a candidate dispatch transport, not a control plane entitled to decide models, gates, or acceptance.

## Positioning: plumbing below the officina

The name covers two unrelated projects. **Herdr-platform** is presented as an AI-agent orchestration control plane: it routes work by context, cost, policy, and urgency; shares workflow state and prior decisions; inserts human approval gates; and traces decisions and handoffs across a managed fleet. It coordinates existing specialist agents rather than doing their work. Every capability in this sentence is **unverified-vendor-copy** from herdr.org. **Herdr-multiplexer** is separately reported by Better Stack, BitDoze, and daily.dev as an open-source Rust/Ratatui terminal multiplexer for roughly twenty agent CLIs, with four displayed states (`working`, `blocked`, `idle`, `done`) and a CLI plus local socket API for pane split, agent start, prompt-with-wait, and read; those reports say it requires no account, telemetry, or network. The platform matters to the question “what runtime coordination could sit under an officina?”; the multiplexer matters to W-046’s concrete transport seam.

Neither occupies Bisellium’s primary layer. Bisellium defines an officina as a file-backed organization: roles and delegated authority live in the manifest and collegium leges; lifecycle is fixed and evidence-constrained; greenlight remains the Patron’s decision; and checks reject unsupported state (`docs/ADOPTION.md`, “Manifest” and “Lifecycle (fixed)”; `studio/leges/production.md`; `studio/leges/design.md`; `studio/leges/engineering.md`; `studio/leges/qa.md`). D-014 makes the Censor the single review and QA gate and preserves independence by keeping that role read-only (`studio/decisions/D-014.md`). D-021 gives each opus record one writer and enforces ownership as a pre-write CLI refusal, not a reconciliation convention (`studio/decisions/D-021.md`). These are authority semantics, not scheduling features.

The useful distinction is therefore sharper than “audit trail versus certificate.” Herdr-platform claims after-the-fact tracing and approval gates (**unverified-vendor-copy**); Bisellium also has after-the-fact telemetry in append-only, gitignored `events.jsonl`, receipts, timelines, and a rebuildable SQLite projection (`docs/ADOPTION.md`, “The `.bisellium/` directory”). Its stronger distinction is *prospective refusal plus tree-bound proof*: `verify` refuses a dirty source tree unless explicitly told to record a `dirty:` claim, runs declared automated gates, and records `certifies: tree:<hash>`; `done` and `merge` refuse evidence that cannot support the transition or no longer names the source tree being shipped (`docs/ADOPTION.md`, “The SOURCE tree hash,” “Running run and verify,” and “Lifecycle (fixed)”). Red evidence likewise must be produced before implementation and retained per behavior, not reconstructed later (`studio/leges/engineering.md`, §§2 and 7). A runtime trace can explain what agents did; it cannot mint these certificates, reorder their production, or waive the gate that checks them.

## W-046: dispatch transport, not transferred authority

An officina could run on Herdr-shaped plumbing if the adapter boundary stays at dispatch. W-046 asks for one opus end-to-end on both harnesses with model and policy passed; the standing landscape already finds that `talk` has Claude and Codex profiles but does not yet pass the requested model, capability, or equivalent command policy, while hooks remain Claude-only (`studio/opera/W-046.md`; `docs/research/agent-studio-landscape-2026-09-21.md`, “Proposed Bisellium direction”). Today `talk` selects a configured harness and maintains a harness-scoped session; `run` separately owns worktree execution (`docs/ADOPTION.md`, “Running talk” and “Running run and verify”). D-020 explicitly calls direct `codex exec` an interim transport and assigns model tiers by decree, with Codex output remaining input rather than a gate (`studio/decisions/D-020.md`).

The adapter should consequently accept a Bisellium-created dispatch envelope — sella, chosen model/tier, permission policy, bounded task, working directory or worktree, and context — and return transport facts: session identity, output, exit/limit state, usage, and liveness. Bisellium must still choose the sella and decreed tier, construct policy, own the opus branch, write through its CLI, compute certificates, and admit transitions. Authority never transits a model or dispatcher. Herdr-platform could implement that envelope behind a harness profile, but its claimed context/cost/policy router (**unverified-vendor-copy**) must not override D-020 or choose a gate.

The multiplexer already offers the smaller experimental surface W-046 needs: local agent start, prompt-with-wait, and read operations are exactly a dispatch transport, while pane state can supply liveness. Its four states must remain adapter-local rather than being mapped onto Bisellium’s fixed lifecycle: `blocked` in a terminal is not an opus state, and `done` in a pane is not accepted delivery. A narrow adapter or test double around that socket shape would exercise provider-neutral dispatch without adopting a second workflow authority.

## Steal, ignore, watch

**Steal the observability question, not the claimed semantic memory.** Bisellium’s server already exposes opera, events, live SSE, receipts, timelines, providers, health, and derived budget posture (`docs/ADOPTION.md`, “Running serve”; `apps/server/src/store.ts`). The shipped web application, however, routes only Inbox and Officina (`apps/web/src/App.tsx`); Officina shows budget posture, engine due items, and integrity findings, but no live agent fleet, handoff trace, session failure, or per-opus execution timeline (`apps/web/src/screens/Officina.tsx`). The standing landscape correctly says Board and evidence-ledger views are direction rather than shipped UI (`docs/research/agent-studio-landscape-2026-09-21.md`). A read-only fleet projection that joins receipts/events to durable opus and gate records is a real gap. It must visibly distinguish ephemeral liveness from authoritative file-backed state.

**Defend decree-over-router for authority; watch routing only as advice.** D-020 deliberately maps fast, mid, high, and escalation tiers to bounded job classes, keeps the Opus-tier Censor as sole judge, and supplies kill conditions for revisiting the mapping (`studio/decisions/D-020.md`). That is a strength: costs remain subordinate to role, evidence, and independence. A cost-aware router could later recommend among equivalent providers inside a decreed tier or stop dispatch at a quota boundary, but it should not silently downgrade a builder, substitute the Censor, or decide urgency. Bisellium already derives burn from recorded usage and exposes provider posture (`docs/ADOPTION.md`, “Running emit” and “Running serve”); the missing evidence is that adaptive selection improves accepted outcomes after review, not that routing exists.

**Ignore shared “prior decisions” as runtime truth and duplicate approval gates.** Decisions and leges are committed, reviewable authority loaded into context; chatter and runtime telemetry bind nothing unless promoted through defined records (`docs/ADOPTION.md`, “Running talk”). Herdr-platform’s shared workflow memory and human approval gates (**unverified-vendor-copy**) may aid execution, but treating them as authoritative would create a second record and a second gate beside D-014. Similarly, ignore the multiplexer’s pane labels as lifecycle truth; retain only its transport and liveness affordances.

## Recommendation

**Recommendation: watch Herdr-platform; adapt the multiplexer API shape as a W-046 transport experiment; do not integrate either implementation.** First prove W-046 with Bisellium-owned model/policy envelopes and identical gate semantics across Claude and Codex. Then add a read-only fleet view from existing events, receipts, sessions, and opus records before buying a new control plane. This preserves the standing landscape’s rule that dispatchers may own leases, retries, quotas, and recovery while files, decisions, checks, and certificates remain authority (`docs/research/agent-studio-landscape-2026-09-21.md`).

`kill_when`: revisit platform integration if one complete dual-harness opus proves the local adapter cannot provide bounded retries, cross-provider session recovery, and fleet tracing without duplicating substantial control-plane machinery, or if two consecutive retros show dispatch/recovery failures or routing cost dominating accepted-opus cost; abandon even the socket-shape adaptation if W-046 proves the existing harness profile sufficient with no material recovery or observability deficit.

**Standing-landscape disposition:** Herdr warrants one disambiguated comparison row at the next scheduled update, not a standalone section: platform as runtime control-plane reference, multiplexer as local dispatch-transport reference.
