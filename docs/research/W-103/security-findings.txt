1. **Blocking — scan work is unbounded.** File/character *output* budgets do not bound filesystem traversal or bytes read. Define separate deterministic limits for directories visited, candidate files examined, files opened, and source bytes read. Specify the searchable corpus (regular files only, exclusions such as `.git`, binary detection, extension/size policy) and report which limit caused incomplete coverage. Excerpts must not conceal scan-budget exhaustion.

2. **Blocking — repository identity is ambiguous.** The dataset apparently identifies projects but not repositories, while a project may bind to multiple roots. Require each binding to assign a stable repository ID. Define whether search runs across every repository bound to the case’s project. Curated references must be explicitly mapped to a repository ID by the binding; reject ambiguous/unmapped references rather than selecting by path match or ordering. Output both project ID and binding-supplied repository ID.

3. **Search independence is underspecified.** In `search` mode, make only the case ID, project ID, and question available to retrieval logic. It must not inspect curated references, captured hashes, expected-answer fields, or route-mode results. Add a test that poisons/changes those fields and proves byte-identical search results and metrics. Route mode may consume curated references but must not fall back to search.

4. **Symlink containment needs an operational rule.** Canonicalize the bound root once, resolve each candidate with `realpath`, and verify it is the root or has the root-plus-separator prefix before opening. Reject absolute paths, traversal components, dangling links, non-regular files, and any intermediate or final symlink resolving outside. State whether concurrent filesystem mutation is excluded; otherwise path-check-then-open remains raceable and requires descriptor-based verification.

5. **Git observation could violate read-only intent.** Specify an allowlist of non-mutating commands and flags, with argument arrays and no shell: e.g. `git --no-optional-locks rev-parse HEAD`, `symbolic-ref --short -q HEAD`, and a scoped porcelain-status command. Set `GIT_OPTIONAL_LOCKS=0`, disable repository-configured filesystem monitors/hooks where applicable, never run fetch, checkout, reset, clean, update-index, or configuration writes, and pass explicit pathspecs after `--`. Timeouts and bounded stdout/stderr are also required. If safe scoped dirty-state collection fails, report identity as partial/unknown rather than broadening commands.
