# Approved targeted-read implementation and evaluation plan

Authority: Patron approved the proposed plan and requested implementation, 2026-09-28. Targeted reads first; 30% minimum reduction. This records the accepted scope, not a signed spec or review gate.

## Decision
YES only if all gates pass. Otherwise NO, classified implementation failure, insufficient savings, or invalid evidence. Invalid evidence never passes. Keep opt-in until decision. Integrate capability inside Bisellium for multiple projects; epoch0 and Yan Mo read-only. Earlier 93% candidate-packet result does not count.

## Capability
Locate compact paths/headings/ranges; read exact bounded source sections with heading ancestry, project/repository/worktree identity, source hash and range; expand adjacent or referenced material. Preserve common task orientation (objective, project, state, applicable instructions); never silently drop mandatory instructions. Explicit truncation, omitted ranges and unresolved references. Read bounded sections of oversized files. Prevent project confusion and out-of-root/symlink escapes; refresh changed identities. Fresh and repeated reads return bodies; repeat suppression, semantic databases and automatic summaries excluded. Ordinary read fallbacks allowed and counted.

## Frozen evaluation
Six read-only tasks, two per project (Bisellium, epoch0, Yan Mo): a local-context question with a qualification/exception, and a cross-document question needing a rule/dependency/state record. Include an oversized document and a plausible outdated source across the sample. Separate draft/architect contexts prepare exact questions, frozen source snapshots, required facts and qualifications, source ranges, acceptable answers/failure conditions and common orientation. Mechanically validate source hashes/ranges/quotes before execution. Builder gets development fixtures and specification, never held-out keys. Freeze implementation before held-out execution; no post-result tuning.

## Gate A
Recorded genuine red before implementation. Deterministic checks: exact source plus heading ancestry; boundaries/Unicode/empty/oversized content; explicit omissions/budgets; correct expansion; changed identities; cross-project paths; out-of-root and symlink safety; fresh context returns content; logs include responses/errors/fallbacks. All must pass before model trials.

## Gate B
12 fresh isolated Luna-low runs: baseline and candidate for each of six tasks. Same questions/orientation/sources/model/effort. Baseline uses competent existing search and bounded reads, not forced whole files. Candidate locate/read/expand plus logged ordinary fallback. Maximum 12 source-access calls each; one call may return multiple bounded locations/sections. Alternate arm order; no answer-key or opposite-arm access. Concise cited qualified answers. No silent model changes; incomplete runs recorded.

Capture every actual delivered source response including orientation/discovery/expansion/errors/fallbacks, UTF-8 bytes, available provider tokens, calls/status/answers. Development/evaluation overhead reported separately. Never represent disk packets as actual model delivery or byte savings as subscription savings. Censor receives anonymised answers and frozen source-backed requirements; span checks assist but do not substitute for answer review.

## All required acceptance gates
All deterministic checks pass. Candidate and baseline each complete all six tasks correctly with all required qualifications. No candidate-only error/unsupported claim/missing context. Candidate aggregate read bytes <=70% baseline; no project's aggregate increases. Frozen inputs, complete logs, valid keys and replayable measurements. Independent Sol-high censor PASS on completed opus. Failure/invalidity yields NO for this version.

## Workflow and stop rules
Separate Sol draft, Astra-medium architect spec, Sol security, Sol build, Terra prereview, Sol-high sole censor; Luna clerical work. Compact briefs and file pointers. No selective reruns/replacement tasks/additional variants after observing results. Only infrastructure failures may rerun with original failure retained and identical frozen inputs. Correctness or efficiency failure requires a separately declared evaluation for any revision. Keep sources/manifests/exact commands/revisions/raw logs/decision linked from handover. Source edits require signed spec and recorded reds; bookkeeping only owning CLI.
