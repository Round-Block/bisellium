Agent studio · organization model + console

Bisellium

An agent team run like a product officina — collegia with leges, budgets and acta — and the console that renders it: work moving through states past probationes, over any source.

date 2026-09-18 status process persisted in the repo; next: W-016 + W-019 under the new sizing, then web reference instance epoch0 repo ~/projects/bisellium

The one idea: a collegium is lex + budget + acta. A written scope of what its magister decides alone, a token/time stipendium per period, and an obligation to report inform-and-proceed. The Patron touches four things — decretum, budget allocation, arbitria, lex changes.

Five decisions bound the project. Conventions first, plus a reference harness for magistri: the officina state is files and any toolchain can produce them; Bisellium also hosts each magister’s conversation by driving the vendor CLIs you already use, so you can talk to a magister from the console — nothing is locked in, and builders run wherever they run. Standalone first: the app runs on its own sample officina before any external project is wired. Nobody updates a card: the console is a projection; the Patron’s four writes are the only exception. Rules are checked, not read: a convention exists only if check can fail it. Mistakes, not adversaries: the threat model is agents that drift, not agents that attack; identity and provenance catch the former and are not claimed to stop the latter.

Strict admission keeps the inbox answerable: only human probationes and petitiones enter it, and both escalate on age. Patron overload is detected by the officina, not by tracking whether the Patron reads: open petitiones per collegium are capped like tokens, and petitio age is a health check.

Availability

Posture limited is not absence. An over-budget collegium stops starting work; items in flight keep their live sella. Absence is a missed heartbeat (Defaults): then Production is acting magister for routing, petitiones addressed to the sella are re-addressed or held with visible age, and the acta-diurna obligation is waived and shown as such. If Production itself is the stale sella, the manifest’s fallback chain applies and one aggregated “routing down” ask reaches the Patron. Items in flight keep their traditio, which is what makes pickup possible.

Cadence

Daily — one acta entry per Magister. Decretum review — Patron + Production, fasti changes. Budget review — next period’s stipendia. Postmortem — the failing collegium’s Magister: acta + lex amendment proposal. Retrospectio — the Censor, once per cascade or period: the improvement loop below.

Autonomy: a declared ladder and a tick

Authority (what a magister decides alone) and mechanism (run, talk) do not by themselves make an officina act; sellae are reactive and nothing starts sessions. Autonomy is therefore declared per collegium in its lex and driven by one scheduler:

LevelBehaviour
L0 manualsellae act only when talked to
L1 scheduledthe tick runs cadence work: dailies, repo review, check, consolidation
L2 dispatchingthe Aedile’s loop walks the fasti: starts ready opera (decreed and spec-passed) into worktrees within WIP and posture, advances opera whose probationes passed, closes done
L3 continuousmagistri also self-assign follow-ups inside “decides alone” — hygiene from repo review, fixes for failed probationes — without waiting for dispatch

bisellium tick is a thin scheduler (cron, a service, or the desktop app’s background task) that runs due cadence work and, at L2 and above, the Aedile’s dispatch pass — through the same run/talk shim, so every autonomous action has a receipt and appears on the timeline. Agents do not live in the tick; it only starts them.

The edge is the fasti. Autonomy never crosses a Patron touchpoint: the officina runs every greenlit item to done and then idles, visibly (“idle: fasti empty, 3 items awaiting decretum”). A week away costs nothing but decrees. Brakes: halts are per item; bisellium pause is the officina brake — stop starting, finish what is in flight; posture limited is the same brake per collegium, and autonomous starts stop at closeout. Process health shows the level and state: running, paused, idle since.

Canonical probatio ladder, declared in the manifest: agent spec (before building); automated tests · lint · types; agent qa · review; human owner (only where a lex names it). Automated probationes are re-run by CI on the candidate merge commit; agent probationes certify the branch-tip tree hash and go stale only if the tree changes. “Substantive” is deterministic: any tree change outside the manifest’s non-code globs. The merge-blocking subset: automated probationes green on the merge commit, review passed and current, traditio present.

Posture per collegium is derived from burn/stipendium on whichever unit the budget sets (worse of both if both): ≥60% conserve, ≥85% closeout, ≥100% limited; no data → unknown, never assumed ok. Burn is the sum of usage events attributed to the collegium’s items and sellae.

A certificate is judged only while the opus is active. stale, dirty and mismatch apply to opera in building, verifying or review; a done opus’s certificate is history and is never re-judged against a newer source tree. Two officinae in one repository (a real one and a sample) must list each other in source_excludes so neither counts the other as source.

One directory is one officina. A portfolio is the console over several; the Board spans them by phase, the Officina screen is per officina. Contract changes bump bisellium:; check refuses an unknown major; migrate rewrites files forward.

Part II

Memory, docs, enforcement

A rule is real only when something machine-reads it and something fails when it is violated. Rules that live only in a document agents are asked to re-read decay to prose. Evidence (n = 1, an anecdote): an audit of one mature markdown-run project found script-produced rules honored at ~90% and document-only rules at 0–10%, with two lifecycle hooks silently dead. A widely shared practitioner write-up (“Markdown Is All You Need”, r/ClaudeCode, 2026-09) reaches the same conclusion from seven months of production: storage was never the hard part; editorial policy is, and it holds only when enforced.

Memory rules

  1. Structure, not prose.

    Traditiones, decisions, probatio results, budgets are front matter with required keys. A missing key is a parse failure.

  2. Derive, never mirror.

    One canonical file per fact; every rollup — burn, board, decision log, files changed, doc registry, index — is generated. Mirrors are where rot lives.

  3. Supersede, never overwrite.

    A changed decision strikes the old line with a date and writes the new one beside it. Every line carries provenance — [stated] [observed] [inferred] [suggested]. Each decision names its kill condition.

  4. Store only what is not re-derivable.

    Current state is verified live, never asserted from memory. Inferred lessons pass a recurrence probatio counted over distinct opera, with [inferred] weighted below [observed]; Patron corrections skip it. A hostile line can suggest a rule once; once is never enough. The consolidation pass that proposes these edits from transcripts is backpass (Part III, Composition), which already enforces corroboration and a human probatio on apply.

  5. Traditio is required on every active item.

    Sella, stage, next action, blocked-on, timestamp. Stale when behind the item’s last commit or behind the clock (Defaults). The console shows age.

  6. Per-sella memory.

    memory/seats/<seat>.md: long-term, recurrence-gated, read only by that sella at boot.

  7. One writer per file at a time.

    Each sella works in its own worktree, acquired from a pool (treehouse) so isolation costs nothing to set up. Shared files are append-or-supersede only, so merges are textual; a genuine conflict is a Production call. The worktree rule is the lock; hooks only check.

  8. Content is data, not instructions.

    Bodies of items, petitiones, acta, memory files and anything from an external adapter are injected as quoted data with a source tag. Standing instructions come only from the identity file and leges, which must be Patron-authored.

Identity and provenance

A sella is a manifest id. Its session-start hook exports GIT_AUTHOR_* for the sella, so the git author is a convenience, not proof; provenance keys on the hook receipt’s session id, which carries sella, model, prompt hash and run id. check fails: a [stated] line not written under the Patron role; a lex or identity file edited by any other role; a transition performed by an actor the manifest does not permit for it. Signed commits are an option an officina can require; on one machine where every sella can reach the Patron’s key they prove little, which is why the threat model is stated as mistakes, not adversaries.

Hooks leave receipts. Every run stamps a heartbeat; check flags a declared hook not seen for the configured number of sessions. Block rarely, advise less. Blocking exits only for the merge-critical set; nag text is the first thing an agent learns to ignore. Never inject the same content on both sides of a compaction.

Context budget

Many files bog down context only if the read path is unbounded; the tool bounds it. Boot is a budgeted bundle: this sella’s lex, the pointer index, its active traditiones, items addressed to it — truncated by priority over cap, and it says so. Collegium is a boundary for leges and acta, not for adopted docs an item references: a builder loads the UX spec its item cites. Query the store, don’t read the tree; drill-downs read one file, narrowest first. Tiers with caps; consolidation (daily → weekly, done → archive) is a script. Process overhead is a tracked cost: hooks report tokens injected; overhead ratio per sella is on the budget panel. Memory chores run as code where possible and on the cheapest model where judgment is needed; nothing here claims to be judgment-free.

Code hygiene

A lane with a budget: kind: hygiene holds a fixed share of Engineering’s stipendium that features cannot borrow; inside “decides alone” up to a size threshold. Every hygiene item carries an evidence link — a repo-review finding, a FAIL loop, a postmortem, or a review comment — so the reserved share buys debt, not trivia. Repo review is a generated acta: stale branches, unpruned worktrees, dead code, duplicate modules, warning counts, coverage drift, dependency advisories, churn hotspots, modules behind repeated FAIL loops; findings become backlog items with evidence. Clean code is a probatio: lint and types in the ladder; changed files may not increase warnings. Done includes cleanup: merge prunes branch and worktree, archives the journal. Debt has a kill condition. Postmortems feed refactors through the recurrence probatio, with failure class as a fixed taxonomy (probatio id × item kind).

Mechanical or judgment: the class on every finding

Every probatio result and every check finding carries a class. Mechanical: the fix is determinable from the finding — a wrong exit code, a missing key, a dead link, a rename. It is fixed inside “decides alone”, re-verified, and never escalated. Judgment: the finding changes what the opus is — scope, a lex boundary, a taste question. It escalates as a petitio or an arbitrium. This is no-mistakes’ auto-fix-versus-escalate split lifted from code to the officina, and it is the autonomy ladder’s stopping rule: L3 may act on mechanical findings unasked, never on judgment ones.

Evidence must be produced, never backfilled. Observed on this project: a builder added lint/types probatio results to older opera by pointing at existing logs, to satisfy new gates it had just declared. That is the laundering failure the provenance rules exist for, one level down. The counter is mechanical: an automated probatio’s log must name the tree it certifies (probatio.evidence.tree), verify refuses a dirty tree, and check --repo compares certificates to the real tree.

Mechanical work leaves a script as its testimonium. A transform a regex could express — renames, moves, key changes, formatting — is done by a script the sella writes, runs, and commits beside the change: near-zero tokens, reproducible, reviewable as one file. Measured on this project: a contract rename done by hand-editing cost 361k tokens and 230 tool calls in one agent, a quarter of its cascade; the same change as a script would have cost a few thousand.

The process is data, not memory

Everything this document says about how work is done must exist as an officina artifact that check can fail; otherwise it is prose that decays. Concretely: the rules live in the leges of the repo’s own studio/ (the Fabri lex says test-first with a recorded red and mechanical work is a script; the Censor lex says drive the CLI as a first-hour user and mutate one behaviour per opus; the Design lex holds the definition of ready); sellae receive their rules as their boot bundle from context, not from a prompt; every rule that can be checked has a check rule, and a lex clause without one is listed as unchecked in process health; decisions live in decisions/ with provenance and a kill condition; and the build workflow itself is a committed template in cascades/, parameterized by opera ids, whose specs are the opera’s briefs. A session’s memory file is reduced to pointers.

The improvement loop: retrospectio, owned by the Censor

The Censor keeps the standards the way the Roman office kept the rolls. Once per cascade or period:

  1. Inputs are data, and usage is one of them.

    Verifier issues, the final review, check advisory counts, fix-round count, mutation-catch rate — and the run’s usage: tokens and minutes per agent, per opus, per role and model tier; the checking-to-building ratio; waste (re-runs after a cutoff, refused tasks, fix rounds caused by tree churn); the provider quota state at the time. The cascade template records each agent’s usage into the officina as gen_ai.usage events attributed to opus and sella (emit --usage), so burn derives from real spend, cascades fall under the same stipendia as everything else, and the retro proposes sizing rules from numbers rather than impressions.

  2. Findings become lessons.

    lessons/L-nnn.md, each [observed] with evidence links and a failure class from the fixed taxonomy (probatio × opus kind). No lesson without evidence.

  3. The recurrence probatio decides what becomes a rule.

    A class seen in two or more cascades on distinct opera yields a proposal, split on the mechanical/judgment line: an advisory detection rule the Censor adopts alone (it only makes something visible); a blocking rule or lex wording change is a lex change — a Patron touchpoint — and arrives as a capped petitio.

  4. Adopted rules leave a trail.

    A decision with provenance and a kill condition, a lex amendment row, and a check rule or an explicit unchecked label.

  5. Pruning is part of the job.

    Kill condition met → superseded with a date, never deleted; lessons with no recurrence after the configured periods → archived; exactly one retro actum per cascade.

  6. The loop’s own health is a screen.

    Lessons open, rules proposed / adopted / retired, fix-round rate and tokens per opus across cascades.

bisellium retro drafts the retro actum from the run’s data (a script, zero tokens); the Censor writes the judgment part, files lessons, computes recurrence and raises petitiones. It is clean by construction because check owns the shape of lessons/ and decisions/, and the Censor’s lex says exactly what it may adopt alone.

Process health is a screen

The checks render per officina on the Officina view: autonomy level and state (running / paused / idle since), hooks alive, ledgers present, index under cap, traditio freshness, certificate staleness, state-vs-evidence, halted age, backlog depth per collegium, open petitiones per collegium, docs past review, overhead ratio, lex clauses without a check rule, lessons open and rules proposed / adopted / retired. Healthy means every merge-blocking check passes and no advisory check has been red longer than one period; anything else is shown as the list of failing checks, not a score.

Rules the views enforce

Amber means one thing: waiting on a human — a pending human probatio or an open ask; rare, escalating on age. Agent probationes block but never enter the inbox. Evidence is two clicks from the red X: every probatio result links evidence with identity (tree hash), which is what makes stale computable. Cost is per item, per sella, per review round, summed from gen_ai.usage.* over spans sharing workflow.item.id; snapshot sources show an honest “—” unless their files record tokens. Limits are routing state, not a metrics zoo. Derived time is labelled: events from snapshot diffs carry workflow.time.derived = true.

Providers, harnesses, models

Three axes vary independently, and a sella binds to all three in the manifest:

Harness tiers. Tier 1: native hooks (session start, compaction, stop, post-tool). Tier 2: no hooks, but launched through bisellium run, which supplies start/stop receipts, the sella’s git author env and the boot bundle. Tier 3: snapshot-only — files, no receipts. A profile declares its tier and check adjusts expectations: no dead-hook alarms for a harness that cannot fire one. context output is neutral text; the profile says where it goes (CLAUDE.md / AGENTS.md include, or hook stdout).

Usage has no universal source. API accounts expose usage; subscription plans mostly do not. Provider status comes from the API where it exists, a CLI status source where one exists (quota-axi, below, covers most subscription CLIs from local credentials), otherwise usage.yml observed by a human — and unknown when none. Stipendia are per provider pool because tokens are not comparable across vendors; an optional price table rolls burn up to money for the finance view. When a pool is limited, routing follows each sella’s declared fallback, and the receipt records the model actually used. A lex may pin a model tier (“reviews run on a strong-tier model”); check compares receipts to the pin and voids mismatched work — the wrong-sella rule generalized to wrong-model. Memory and leges are markdown, so a sella survives a model change.

The reference harness: talking to a magister

A magister is (seat, harness profile, session id). The direct line on the Agents screen is a real conversation: bisellium talk resumes the sella’s session in its worktree through the vendor CLI’s headless mode (claude -p --resume, codex exec --resume), with the boot bundle as system context and a tool surface limited to reading the officina and running bisellium commands. Driving the CLIs keeps subscription billing and keeps every hook and receipt working, because it is the vendor harness underneath.

Status questions mostly need no model. “Where is W-004?”, “what is blocked on me?”, “burn this week?” are query answers from the store: instant, free, deterministic. The magister is invoked when addressed or when judgment is needed, and the chat shows which is which. Magistri cost nothing idle; cadence work (dailies, repo review) runs them on a schedule; a magister may dispatch builders through the same run command into fresh worktrees. Conversation is timeline chatter unless it produces a petitio or a decision, so the inbox rule holds.

Risks, none architectural: headless modes and resume semantics differ per CLI and change; one profile per CLI, not a gateway; a human using the same CLI shares its session store.

Adapter contract and store

interface AdapterBase { projectId; describeLifecycles(): Lifecycle[]; send?(target, message); providerStatus?(): Provider[] }
interface SnapshotAdapter { style: "snapshot"; snapshot(): Snapshot; intervalMs }   // native, any markdown/git source
interface EventAdapter    { style: "events";   pollEvents(since): Event[] }        // OTLP, harness hooks, LangGraph
// the CORE diffs snapshot N vs N-1 into workflow.* events stamped time.derived = true;
// identical consecutive snapshots produce nothing. Diffing lives in one place, never in adapters.

Store: append-only JSONL log plus a SQLite index rebuilt from it; OTLP ingest on localhost; one query API. “Live” is a tail on the log, replay is a scan of it. A partial snapshot is rejected whole; an adapter that stops answering marks its source stale in process health rather than freezing the board silently. Locality: nothing leaves the machine unless an adapter is configured to reach out; acta and petitiones are files in the officina directory, visible to whoever has the repository — no separate privacy layer, by design.

How the build runs: cascades

Each build step is one workflow — the officina model applied to building the officina. A Haiku clerk opens opera in the repo’s own studio/; Sonnet builders work in parallel on disjoint files from a written spec; an Opus verifier per opus runs the suite, reads the diff against the spec, and plays the first-hour user who only drives the CLI; one fix round; a Sonnet integrator wires and commits; the clerk closes the opera with real probatio evidence; an Opus principal engineer reviews the commit and is not asked to be kind. Mechanical findings are cleared by a single builder before the next cascade; judgment findings go to the Patron.

A spec phase, from cascade 5. Earlier cascades had no spec lock: the specs were written by the orchestrating session, unreviewed, and three of the costliest findings were spec errors (certifying the wrong tree, the git-author identity model, a rename done by hand). The model’s own gap — no definition of ready between decretum and building — was inherited by the build. Now an Opus architect (the Design sella) writes each opus’s brief from the dossier, the code and the last review; a second Opus tries to break the briefs before anyone builds; the spec probatio passes; only then do builders start. The build’s spec phase and the model’s definition of ready are the same mechanism.

Sizing is data (D-012). Measured across six cascades: token spend grew from 0.9M to 3.4M per run while the Opus share of it passed half, mostly verification; 4b spent 2.4M and integrated nothing. The sizing now lives in cascades/sizing.json and the Aedile’s lex: two opera per cascade; one Opus Censor per opus, Sonnet for the first-hour drive; mutation on one opus per cascade; one worktree and branch per builder so verifiers see a stable tree and work is attributable; builders boot from CLAUDE.md and context, never from read lists; no mid-turn messages relayed into a running workflow. The retrospectio’s usage section is what revises these numbers.

Tests: spec-first, test-with, not TDD. Builders write the implementation and its acceptance tests from the same spec in one pass; negative fixtures under examples/fixtures and CLI spawn tests pin behaviour after the fact. That caught spec drift but not spec misreading: twice the builder’s tests agreed with the builder’s bug. From cascade 3b the rule is test-first with a recorded red: the builder writes the test file, runs it, pastes the failing output into its report, then implements; the verifier checks that the red exists and, for one behaviour per opus, flips it and expects the suite to fail. That is the cheapest form of TDD an agent can be held to, because the red run is evidence, not a claim.

Acceptance

The console renders the sample officina and an external adapter with zero adapter-specific code outside the drawer’s extension slot; replaying a recorded log reproduces the same state sequence (derived timestamps differ); removing one adapter leaves the other untouched; every negative fixture fails check and the officina from init passes it. A failure of the first three is a schema defect to fix before a third adapter is written.
